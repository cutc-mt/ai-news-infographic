【必見】エージェントの「牧場」を築く『Herder』

tmuxをエージェント時代向けにゼロから作り直した、Rust製ターミナル常駐マルチプレクサを徹底解説

📅 2026年8月29日 | 🎬 AI Code King

①Herderとは何か?

  • ターミナルの中で飼う、AIエージェント専用のマルチプレクサ
  • Rust製。既存の端末を置き換えず、中で動くスタイル
  • エージェントの「いま何をしているか」を本当に理解しているのが肝
  • CLIとsocket APIでagent同士が連携できる。Pro向けの急所
放置するしかなかった並列エージェントが、ここでは“牧場”として管理されるよ!

②本当の問題は「見えないこと」

  • Claude Codeが改修、Codexがバグ潰し、調査役が…とタブやペインに散らばる
  • 「まだ動いてる?」「許可プロンプトで10分も止まってる?」「20分前に終わってた?」
  • tmuxにとってエージェントはただのプロセス。状態を知るすべがない
  • 課題は起動ではなく追跡と協調。ここにHerderが答える
動かすのは簡単。つらいのは「誰が・どこで・どうなってるか」が見えないことなんだ

③tmuxを作り直す

  • ワークスペースはspaces、タブ、分割ペインを装備
  • 切断しても生き残るしぶといセッションも標準搭載
  • 分割は方向つきで自由なレイアウトが組める
  • 多重度の基本はひととおり押さえつつ、上にエージェント層を建てた設計
「tmuxの資産」+「エージェントの理解」。発想として一番しっくりくる作りだね

④サイドバー=状況の司令室

  • 見つけた全エージェントとライブ状態を一覧表示
  • ペインを飛行機のようにぐるぐる見回さなくていい
  • どれが助けを求めているか一目でわかる
  • 現実に並走できる体数が変わるほどの体験
これだけで「同時に何体動かすか」の感覚が変わる。地味に大きい改善なんだ

⑤約20種のCLIを自動で見つける

  • Claude Code Codex OpenCode Cursor Agent Copilot CLI
  • Groq CLI、Qwen Code、Kilo Code、Droid、Amp、Devonro なども対応
  • Gemini CLIとKleinは検出されるが検証が浅め
  • 載っていなくても普通の端末として動く。特定ベンダーへの固めなし
状態の追跡なしでも締め出さない。このゆるさが長く使える理由だね

⑥入れ方はすぐ終わる

  • macOSなら brew install herder の一発
  • Linuxは公式のcurlワンライナー、WindowsはPowerShell版
  • Rust勢は cargo install herder でもOK
  • 入れたらher と打つだけ。フォント・色・shell設定はそのまま
$ brew install herder   # macOS
$ curl -fsSL https://herder.dev | sh  # Linux
$ her                   # 起動
既存の端末の中に描画されるから、環境を持ち込まれないのが嬉しいポイント

⑦操作はtmuxの筋肉+マウス

  • prefixはCtrl+B。tmux勢なら無意識に使える
  • Ctrl+B → ? で割り当て一覧を表示
  • マウスが第一級の扱い。クリックで聚焦、ドラッグで幅変更
  • 右クリックのメニューで分割やクローズを直接指示
prefix体操をしなくていい。「慣れ」と「楽さ」を両取りの設計だね

⑧4つの状態を追う

  • working : 処理中。集中して動いている状態
  • blocked : 許可や質問であなたの返事を待機中
  • idle : 指示待ちでのんびり待機
  • done : 完了したのにまだ結果を見ていない状態
working → 順調 / blocked → 要対応
idle    → 待機 / done   → 未確認の完成
idleとdoneの違いは「結果を見たかどうか」。見るまで旗が立ったままなのが偉い!

⑨状態を見つける2つの仕組み

  • 対応エージェントは自分で状態を直接報告。いちばん正確な信号
  • フックがない場合は画面の下端を既知のUIと照合して判定
  • blocked検出は控えめに設計。誤報で悩まされない
  • あくまで推定で、直接の信号ではない点は頭に入れておく
許可画面の見た目を覚えて「blocked」と判別する、地頭のいい工夫なんだね

⑩連携設定と通知

  • her integration install claude でClaude Code連携を構築
  • herder integration status で有効な連携を確認
  • 背面ペインの状態が変わると通知が飛ぶ
  • 没頭中でも完了や停滞を拾ってくれるので見守り不要
$ her integration install claude
$ herder integration status
バックグラウンドのagentが終わったり詰まったりしたら知らせてくれる。並列作業がぐっと楽に!

⑪agent自身が操るAPI

  • CLIとローカルのsocket APIを公開
  • 呼べるのは人間だけじゃない。エージェントも呼べるのが急所
  • 分割、起動、指示送り、完了待ち、出力の取得まで丸ごと
  • つまり表示装置ではなく指揮をまかせる基盤
「agentがagentを指揮する」。Proユーザーが一番食いつくlayerだね

⑫pane系のコマンド

  • pane split : 方向を指定して枠を分割
  • pane run : 好きなコマンドを実行
  • send-text / send-keys : 生の入力を送る
  • wait-output / pane read : 出力を待つ・読み込む
$ herder pane split --right
$ herder pane run "npm test"
$ herder pane wait-output "PASS"
$ herder pane read
端末の操作をそのまま脚本にできる感じ。夢がひろがるね!

⑬agent系のコマンド

  • agent start --kind : codexやgeminiなど種別を指定して起動
  • agent prompt --wait : 指示を送り、目標の状態まで待つ
  • agent wait : idle / done / blocked などの状態を待機
  • agent read / rename : 出力を取得、「reviewer」などの名前を付ける
番号ではなく「名前」で呼べるのは地味に大事。脚本がぐっと読みやすくなるよ

⑭実例: 実装→レビューの自動連携

  • Claude Codeに「機能を作り、終わったら審査役を立てろ」と指示
  • 右に枠を作り、--kind codex のreviewerを起動
  • レビュー指示を--wait 付きで送信
  • 完了したら結果を読み戻して対応。2体が自律で協働
$ herder pane split --right
$ herder agent start reviewer --kind codex
$ herder agent prompt reviewer "diffを審査して" --wait
$ herder agent read reviewer
いままではsend-keysと祈りで組み上げていた流れが、正規のAPIで書けるんだ!

⑮動画主の実際の使い分け

  • 大きめの企画はVerdantへ、素早い端末作業はHerderへ
  • Verdantは計画→分割→隔離sessionで並列実行まで内蔵
  • 離席中はSlackやTelegramから指示。VSCodeやJetBrains拡張もあり
  • Herder側は改修・審査・試験とlogの監視を並走させる
「計画の委託はVerdant、即席はHerder」。二本柱で子守りから解放される構図だね

⑯切れても消えない永続性

  • client・server方式。実態はserver側が握る
  • detachして閉じても、つなぎ直せば全部現役。agentは止まらない
  • server再起動時もspaces・タブ・枠・作業folderを復元
  • agent側も会話を自動で再開(Claude Codeのresume活用、初期ON)
「再起動=文脈を失う」ではなくなった。長時間運用の安心感が全然違うよ

⑰遠隔運用と好みの調整

  • her --remote でSSH先のserver上で実行。鍵やthemeはlocalのまま
  • 強い開発機やVPSで群れを飼い、どこからでも覗ける
  • 設定は ~/.config/herder。prefix変更や再起動なしの反映も
  • themeはcatppuccin nord dracula など。plugin市場も搭載
~/.config/herder/config.toml
themes: catppuccin / groovebox / nord / dracula
一晩serverで走らせた群れを、朝どのマシンからでも点検できるのは気持ちいいね

⑱制限と総評

  • pre-1.0。版をまたぐ更新でserverが止まり、枠も落ちる
  • フックなしagentの状態は画面照合による推定どまり
  • Windows対応は遅れ気味で、遠隔先にもなれない
  • tmuxを入れ子にすると検出が壊れる。Herderを親にするのが正解
  • 無料・OSS。1体ならtmuxで十分、3〜4体並行ならmission control
「追うのがしんどい」という本当の瓶首に答えた一本。並列派は試す価値あり!
