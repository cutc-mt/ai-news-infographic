パート 3: リモートへの設置手順

Hostinger プラグイン

MCP で接続

  • plugin install Hostinger でインストール開始
  • ユーザースコープで入れれば、どこでも使える
  • ブラウザが開いてワンクリック認証完了
  • SSH・ファイアウォール・アプリ導入まで一気に進行
/plugin install Hostinger
/mcp # プラグインの状態を確認
インスタンスの新規作成権限はエージェントに渡さない。そこは人が作る

GitHub の認証

サーバー側で実行

  • VM ID とパブリック IP をダッシュボードから伝える
  • SSH でログイン → 専用 URL にコード入力
  • ログイン完了を確認したら次のステップへ
  • Windows は PowerShell を使うのがコツ
認証情報はエージェントに預けない。ここだけは自分の手で!

Codex の認証と設定

忘れがちな設定

  • codex login --device-auth … device code flow でログイン
  • ChatGPT 設定 → セキュリティ → device code authorization を有効化
  • codex exec "say hi" で応答テスト
  • モデルは GPT-6 Astra を指定するのが前提
codex login --device-auth
codex exec "say hi"
# ChatGPT settings > Security で
# "Enable device code authorization"
# にチェックを入れるのを忘れずに
この設定をオンにしないと、リモート認証がかなり面倒になるよ

パート 4: ファクトリーはこう動く

入力は Issue だけ

システムへの入口

  • PRD を Issue に分割して投入する方法
  • もしくは Issue を直接作成する方法
  • 作成は GitHub CLI でサクッと実行
  • 投げたら、あとはファクトリーが処理を開始
GitHub Issue さえあれば、いつでも誰でも作業を依頼できる

triage ワークフロー

まず選別する

  • Issue の内容をファクトリーのルールやミッションと照合
  • 優先度を自動でランク付け
  • おかしい Issue は却下判定も可能
  • 問題なければ実装タスクへ Go サイン
何でもかんでも受け入れるんじゃなくて、ちゃんと選別するのがポイント

成果物は PR で届く

出力の形

  • 実装 → レビュー付き PR が自動で作成される
  • 多くの場合はそのまま自動マージまで完了
  • 判断が難しい時だけ人間にエスカレーション
  • コードは検証済みの状態で届く
📋 Issue 作成
🔍 triage(選別・優先度付け)
⚙️ 実装 & レビュー
✅ 自動マージ or 人間へ
Issue からマージ済みコードまで、文字通り一気通貫!

最初のテスト Issue

動作確認

  • シンプルな Issue を1つ作成してEnd-to-Endを確認
  • triage が archon ready と判定
  • きちんと PR まで到達すれば成功
  • Hostinger プラグインでDNS 設定の自動更新も可能
小さな Issue で全体が動くか確認するのが、まず第一歩
