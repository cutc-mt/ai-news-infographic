結論から：Grok Bot に重い作業をやらせない

この動画の核心 週の使用量が2日で尽きてしまう…そんな人向けに、枠を長持ちさせる考え方と具体的なコツをまとめました。結論はシンプル、「Grok Bot に全部やらせない」こと。
2

こんな人向けの話

対象 Grok Bot の週の使用量がたった2日で尽きてしまう人。原因を知り、打つ手を決めて、枠を1週間分きちんと使い切るための運用設計を解説します。
3

週の使用量が途中で尽きる「2つの原因」

原因の整理
  • 原因①：重い・長く走る作業を Grok Bot に直接やらせてしまっている
  • 原因②：無駄なやりとり（相づち・やり直し・定期実行）で枠を消化している
まず「どこで枠が減っているか」を把握するところから始めます。
4

設定画面「使用量と請求」の見方

計測はまずここから 設定画面の「使用量と請求」で、何がどれだけ枠を食っているかを確認できます。内訳を見てから打つ手を決めるのが正しい順番。闇雲に節約しても効果はありません。
5

実験結果：頼みごとはまとめて1通が早くて安い

検証 細かく何度も依頼するより、頼みごとはまとめて1通で送るほうが処理も早く、枠の消費も安いという実験結果が出ています。やりとりの回数そのものがコスト。
6

Grok Bot は「受付」にして、重い作業は外へ逃がす

基本の構え Grok Bot は受付（窓口）に徹してもらう。長く走る作業・重い作業は Claude Code や Codex など、別でお金を払っている AI に逃がします。これが枠を長持ちさせる大原則。
7

X のサブスクは「複数アプリで1つの週の枠」

知っておきたい仕様 X のサブスクは複数アプリで1つの週の枠を共有しています。別アプリを使い分けても枠は分かれないので、使い分け=節約にはなりません。
8

コツ1：1つの仕事で話しかける bot は1体

コツ① 同じ仕事を複数の bot に同時に頼むと枠が二重・三重に減ります。1つの仕事につき話しかける bot は1体に絞るのが鉄則。
9

コツ2：相づちは送らない

コツ② 「いいね」「なるほど！」といった相づちの送信は枠の無駄遣い。1往復ごとに使用量が減っていくので、意味のないやりとりは極力なくします。
10

コツ3：定期実行は止める・間隔を広げる・きっかけを絞る

コツ③ 常時回っている定期実行は枠の大口消化源。止める／実行間隔を広げる／動くきっかけを絞るの三択で見直します。
11

コツ4：長くなった会話は畳んで新しく始める

コツ④ 会話が長くなるほど1回あたりのコストがふくらみます。畳んで（要約して引き継いで）新しい会話で始め直すと、枠の消費を抑えられます。
12

コツ5：やり直しと失敗の沼を減らす

コツ⑤ 失敗→やり直しのループは枠を溶かします。指示を明確に・前提を共有して一発で通す意識が、結果的にいちばんの節約になります。
13

手順の多い重い作業は別の AI ツールへ

役割分担 ステップが多く長く走る作業はClaude Code や Codex など別の AI ツールへ移す。Grok Bot は指示出しと受付だけに徹するのが効率最強の構成です。
14

同じ枠に逃がしても意味がない／プラン別の枠の違い

落とし穴 逃がし先が同じ週の枠を共有しているなら節約になりません。プランごとの枠の違いを理解したうえで、枠が足りないときの選び方を検討します。
15

Claude Code があれば Grok Bot は要らない？

よくある疑問 結論は「役割が違うから併用する」。Claude Code は作業場、Grok Bot は入り口。どちらか一方で置き換える話ではなく、組み合わせてこそ真価が出ます。
16

ハーネスを操作するハーネスとしての Grok Bot

上級者構成 Grok Bot を「ハーネスを操作するハーネス」として使う発想。複数の AI ツールの上に立って指示を回す指揮役にすることで、枠を楽しながら効率を最大化できます。
17

入り口（マクロ）と作業場（ミクロ）の使い分け

ミクロとマクロ マクロ=入り口としての Grok Bot、ミクロ=作業場としての Claude Code。ただし bot を分けても1台を共有している場合は枠が共通なので注意。
