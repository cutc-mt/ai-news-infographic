MuseとClaude Codeで、
24時間働くAIチームを作った

ギリギリ開発会議 by ボイスアップラボ（@girigirikk）
2026年11月20日 ・ AIニュースインフォグラフィック
1

今日の主役はこの2つ

MetaのAIエージェント「Muse」と、AnthropicのCLIツール「Claude Code」。この2つを組み合わせると、眠っている間も仕事を進めてくれるAIチームが作れる——というのが今回のテーマです。Muse特集・全3回の1本目。

#Muse#ClaudeCode#マルチエージェント
2

Museとは何か

Metaが提供するAIエージェント。指示をすると調べて・考えて・実行まで持っていく「スペース」という仕組みが特徴で、単なるチャットではなく仕事を丸ごと任せられる設計になっています。

3

16日間、使い倒した

お試しではなく、16日間毎日実務で使い続けた記録があるからこそ語れる話だというのが本特集の軸。便利そう、で終わらせずに「本当に司令塔として成立するのか」を検証しています。

4

ゴールは「AIが司令塔」

人が全部の指示を出すのではなく、AI側に仕事の割り振りと進行管理を任せる体制を目指すのがこの16日間の目的地。人間は方針だけ決めて、あとはAIチームに任せる形です。

5

鍵は Claude Code 導入

転機となったのが、Museのマシン（スペース）に Claude Code を入れたこと。エージェント自身にコマンドラインが使える手が生まれ、できることの範囲が一気に広がりました。

6

24時間動くAIチーム誕生

Museが司令塔として仕事を切り分け、Claude Code が実行部隊としてコードを書き・ビルドし・デプロイする。人間が寝ている間もパイプラインが回り続ける体制が組み上がります。

7

任せたのは「執筆→デプロイ」

実例として紹介されたのが、記事の執筆から公開までのフルオート化。テーマ決め→執筆→レビュー→本番デプロイという流れを、AIチームだけで完走させています。

8

司令塔の仕事ぶり

Museはタスクを分解し、得意分野でメンバー（エージェント）に割り振り、進捗を取りまとめます。いわばプロジェクトマネージャー役。人間はその上で意思決定だけをする設計です。

9

なぜ「24時間」なのか

クラウド上で動くマシンは営業時間を知りません。夕方に仕込んだジョブが翌朝には完了している——この時間の伸び方が、AIチーム化の一番わかりやすいメリットです。

10

領収書で失敗した話 ①

順調な話だけではなく失敗談も。AIに領収書の処理を任せたら、品目や金額の認識を丁寧に確認せず進めてしまい、後から人間がチェックするはずが乗ってしまいました。

11

領収書で失敗した話 ②

教訓は「自動化するほど、人間の最終チェックが重要になる」こと。丸投げと自動化は別物で、確認ポイントを設計しないと失敗は静かに膨らむ、という実感が語られました。

12

失敗をチーム設計に反映

この失敗を踏まえ、金額が絡む処理には承認ステップを挟む運用へ改良。AIチームは「作って終わり」ではなく、運用しながら直していくものだとまとめられています。

13

Muse × Claude Code の分担

  • Muse：計画・割り振り・進行管理（司令塔）
  • Claude Code：コード生成・実行・デプロイ（実行部隊）
  • 人間：方針決定と最終承認のみ
14

個人でも組める体制

特筆なのは、大規模な組織でなくても個人・小規模チームで同じ構成が組めること。必要なのはMuseのスペースとClaude Codeの環境という、比較的手の届く組み合わせです。

15

16日間で見えた変化

最初は人間が細かく指示していた作業が、日を追うごとにMuse側で吸収されるように。指示の出し方も「何を任せるか」を考える方へシフトしていったといいます。

16

自動化のよりどころ

繰り返し出てくるキーワードは「自動化」。定型作業をパイプラインに載せ、人間の時間を判断に集中させる——これがAIチーム運用の基本的な考え方として貫かれています。

17

続きは全3回の特集で

今回は「体制を作る」話。この先、運用を深掘りし、AI司令塔をさらに使い倒していく回が続きます。シリーズものとして追いかけると理解が深まる構成です。

18

まとめ：今日の持ち帰り

  • Muse＋Claude Code で24時間AIチームが組める
  • 記事執筆〜デプロイまで実任せできる
  • 自動化するほど人間の最終チェックが命取りになる
