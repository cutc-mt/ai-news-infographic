TOPIC 02

核となる理念と5つの失敗パターン「every motion has a cause（すべての動きには理由がある）」

Stageshowは「every motion should have a cause（すべてのモーションには原因・理由があるべき）」というたった一つの理念から出発します。そして、AIが作ったデモが失敗する典型的な5パターンに名前を付けています。

  • too much（詰め込みすぎ）
  • wireframe（ワイヤー感のまま）
  • boxed（箱詰め感）
  • flat（平らで味気ない）
  • bland（無個性）

TOPIC 04

7ステップ工程（中盤）：ストーリー設計3〜5ビートのストーリーを10〜16秒で

配置が決まると、次はストーリーの設計です。デモを3〜5個の「ビート（場面）」の流れに分解し、全体を10〜16秒の尺に収めます。長すぎず短すぎない、視線が追えるペースの設計がルール化されています。

7ステップ工程（後半）：自ら撮影しゲートを通すREHEARSAL.mdを書くまでが一区切り

TOPIC 07

セットアップ手順PandaCode 0.3.129 + dsh + DeepSeek V4.1 Flash

  • PandaCode 0.3.129 を用意
  • npm install -g @deepseek-ai/dsh
  • Settings → Agents → Providers にDeepSeekキー
  • V4.1 Flashをthinking設定maxで利用

CHECK 1

Hallmarkのブラウザチェック一度失敗し、修正後にパス

Hallmarkがページを構築した後、ブラウザチェックが実行されます。最初はこのチェックに失敗しますが、問題を直して再実行すると無事パス。エージェントが自分で検証→修正→再検証を回す様子が確認できます。

CHECK 2

Stageshowのゲートに引っかかった2点数字のポップイン不良とフォントの飛び

Stageshow側のゲートも機能します。Halvesのデモでは「数字がポップイン表示で違和感がある」点と「フォントが途中でジャンプする」点の2つがゲートにキャッチされ、それぞれ修正されました。

  • 数字のポップイン（digit pop-in）を修正
  • フォントの飛び（font jump）を修正
▶ ゲートの指摘内容
CHECK 3

/review-animations で動きを研ぐボタンホバーを220ms→160msに短縮

仕上げはモーションレビュー。/review-animationsを実行すると、ボタンのホバーアニメーションが220msでは遅すぎると指摘され、160msに短縮されてより心地よい反応になりました。
