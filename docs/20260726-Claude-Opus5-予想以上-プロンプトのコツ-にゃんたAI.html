⑪ 開発者向け新機能2つ: キャッシュ継続と安全性

  • 機能1: エージェントのツールを途中で変更してもプロンプトキャッシュが継続する
  • 機能2: 悪意ある入力に対し、返答拒否ではなく別モデルで返答生成する安全機能
  • Appleのアプリにエージェントを組み込む際の利便性と安全性が向上
開発者には嬉しいアップデート！

⑫ エフォートパラメーター: 思考の量を制御

  • モデル選択時にエフォートレベルを設定可能 — モデルの「頑張り具合」を調整
  • これは発言の長さではなく思考の量を制御するもの
  • レベルを上げるとより多くのファイルを読み込んで返答する
  • ファイルを読み込んでくれない時はエフォートを上げる、精度が悪い時はモデルを上げるという使い分け
「読み込む量」と「考える深さ」は別物だった！

Opus 5のプロンプトのコツ

⑬ 出力が長くなりやすい: 短くと指定しよう

  • Opus 5は以前のOpusモデルより出力文章が長くなる傾向がある
  • 長すぎると感じる場合は「短く簡潔にお願いします」とプロンプトに追加
  • エフォートパラメーターで調整しようとする人もいるが、それは思考量の制御であり出力長とは別
  • エージェント作業中に積極的にナレーションも行うので、それも長さに影響
「簡潔に」の一言で出力が劇的に変わる！

⑭ 検証ステップは不要: 過剰検証を避ける

  • Opus 5では検証ステップを入れなくてよい — 自力で品質を確保できる
  • 従来の「最後に検証させる」「サブエージェントで検証」は過剰な検証を引き起こし無駄なトークンを消費
  • 自己修正の指示も不要 — モデルが自ら判断する
  • 今まで毎回検証指示を入れていた人はプロンプトから削除推奨
これまでの検証プロンプト、消しちゃってOK！

⑮ サブエージェントの制御: 上限を設定しよう

  • Opus 5は積極的にサブエージェントを使うモデル
  • 使うサブエージェントの数の上限を設定しておくことが推奨される
  • どのような場合にサブエージェントを使うべきかプロンプトで明示するとよい
  • 制御しないとトークン消費が膨大になる可能性あり
サブエージェントは便利だけど、 unleashed にしない！

コンテキストエンジニアリング

⑯ プロンプトの80%削除: モデルが賢くなった

  • Anthropicの内部テストでシステムプロンプトを80%削除しても精度への悪影響はほぼなし
  • 従来は細かなルールや制約を書いていたが、Claude 5系では不要なことが多い
  • 「ルールを与える」から「Claudeに判断させる」へパラダイムシフト
  • 例: 「コメントを書かないで」ではなく「周囲のコードと同じように読めるコードを書くこと」
モデルが賢くなったから、プロンプトはシンプルに！

⑰ Claude Code Doctor: プロンプトを自動診断

  • Claude Codeで/doctorコマンドを実行するとプロンプトを自動診断
  • CLAUDE.mdやスキルを確認し、トークンを節約できる箇所を提案
  • 診断結果をもとに無駄なトークンを削減してくれる
  • ただしスキルの中身までは見てくれない — 別途手動で確認が必要
  • 記事の内容をコピーしてClaude Codeに貼り付けるとスキルの中身も診断してくれる
/doctor で一括診断、めちゃくちゃ便利！
