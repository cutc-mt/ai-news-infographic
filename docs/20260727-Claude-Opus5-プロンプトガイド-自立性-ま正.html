Opus 5とは何か

① Opus 5の正体: 自立性が高まった新モデル

  • Claude Opus 5は自分で検証し、自分で修正する自立性が高まったモデル
  • 「検証してください」と言わなくても自動的に検証・修正を実行
  • Opus 4.8と名前は似ているが別物と言えるほど改善されている
  • ナレッジカットオフは2026年5月で、最新の情報にも対応
モデルが賢くなって、ハーネスの仕事を巻き取っていく方向！

② 能力向上の全体像: 何が強くなったか

  • エージェントコーディングが大幅に向上 — ロングランの実行能力が抜群
  • ビジョン系が強化 — 画像理解が従来より格段に良い
  • サブエージェントの使い方と切り方が非常に上手い
  • コードレビューの指摘の質も高い — 4.8とは比較にならないレベル
日常開発業務でGPT-5.6 Codexと迷うレベルに！

③ 画像理解の進化: 3D生成もこなす

  • 画像から3Dモデルを生成するデモが成功 — ビジョン能力の向上を実感
  • UIを3Dで作らせる場合にも従来を超える品質を確認
  • コンピューターユースのベンチマークでもFable 5を超えるスコアを記録
  • 今後のFable 5.1や5.5の登場にも期待が高まる
画像から3Dを生成って...未来すぎる！

プロンプトガイドの要点

④ エフォートレベルの管理: 応答の長さは直接指定

  • エフォートレベルを変更しても応答の長さは縮まない — プロンプトで直接指定する必要がある
  • エフォートはツール使用の深さを制御するもので、出力長とは別物
  • 「作業実況の指定」「思考ログの出し方」を明示的にプロンプトに書くことが推奨
  • 頻度、流れ、フォーマットをちゃんと書いてあげることが重要
エフォート下げれば短くなるわけじゃない...勘違いしやすい！

⑤ シンキングがデフォルトオン: 切る時の注意点

  • シンキング（思考モード）がデフォルトでオンになった — これを前提に動かすべき
  • シンキングをオフにするとツールの命令がユーザー側に漏れる危険がある
  • 内部タグがはみ出したり意図しない出力が発生することも
  • 切る場合は漏れを防ぐプロンプトを必ず入れること（公式案内あり）
シンキング切る時は要注意！漏れ対策を忘れずに。

⑥ 低エフォートでも十分賢い: コスト削減のコツ

  • シンキングはオン前提で動かしつつ、LowやMediumモデルを活用してコスト削減
  • Lowモデルでも早くて賢い — 壁打ちや軽いタスクに最適
  • 検証に時間をかけたくないタスクではLowが十分
  • ロングランループではX-Highで回すのがおすすめ — Maxより柔軟
タスクに合わせてエフォートを使い分けるのが賢い！

ハーネスの見直し

⑦ 従来のプロンプトを削る: モデルができることは任せる

  • 「サブエージェントでレビューさせてください」という強制指示はもう不要
  • 検証パターンの細かい指定もモデルが自立的に実行するように
  • わざわざ強制していた部分が天井になってしまう可能性も
  • モデルの性能を見ながら徐々に調整していくのが正解
モデルが賢くなったら、人間の制御は最小限に！

⑧ サブエージェントの同時実行: 上限を設定しよう

  • Opus 5はどんどんサブエージェントを召喚する — 制限しないとコストが増大
  • Fableに比べると半分のコストで済むが、呼びすぎると枠が埋まる
  • 「10体呼ばれると困る」「50体は嫌だ」という場合は制約を設定すべき
  • Anthropic系モデルはマルチエージェント協調が基本思想 — どんどん活用する
サブエージェント召喚し放題...コストが心配！

⑨ 自己検証をモデルに任せる: ダブルチェックはもう不要

  • Opus 4.6時代には「サブエージェントでレビューして」と酸っぱく言っていた
  • 今はコストだけ増えて結果が良くならないので削って良い
  • モデルが自分で問題を見つけて直す方向に進化している
  • ただし漏れがないかは人間がぼーっと見てチェックすることが大切
モデルを信じて任せる — それがOpus 5の正しい使い方！

出力の制御方法

⑩ 出力の長さを絞る: 3つの概念を整理

  • 出力の長さは3つの概念に分けて管理: 会話の応答、作業の実行、書き出す文章
  • 「頭の中でじっくり考える量」と「実際に出力する文章」は別物
  • それぞれプロンプトで明示して、出力をコントロールする
  • 公式から例も共有されているので参考にする
考える量と書く量は別 — ここを分けて指示するのがコツ！

⑪ 指示追従性が向上: 「控えめに」を文字通り受け取る

  • 「控えめに」「重大な問題だけ報告して」という指示の追従性が上がった
  • ただし文字通り受け取って、ほとんど報告しなくなることも
  • 「察してくれる」より言ったことをそのままやる傾向が強い
  • 報告のバランスを意識してプロンプトを調整する必要がある
「控えめに」＝「ほとんど報告しない」になるから注意！

⑫ 作業実況と進捗フォーマットを明記

  • Opus 5は従来より長く喋り、積極的に宣言する傾向がある
  • レポート類が長くなりすぎる問題を防ぐため進捗の出し方を明記すべき
  • 頻度、流れ、フォーマットをプロンプトに書いてあげる
  • 独自の報告フォーマットやHTML・画像形式を参照させるのも有効
認知負荷対策として、出力フォーマットはしっかり指定！

⑬ 絞りたい行動を明示: 枠をしっかり示す

  • Opus 5は言われなくても勝手に検証してタスクを広げる傾向がある
  • 「頼んだ仕事はこれだけ」と枠を明示することが大切
  • トラッカーやタスク管理をしっかり使って範囲を制御する
  • 指示を削るだけでなく、やってほしいことの境界を明確にする
「ここまでやっていいよ」という枠をちゃんと伝える！

Fableとの使い分け

⑭ Opus 5 vs Fable: 爆大なコンテキスト処理

  • 膨大な未知のコンテキスト処理ではOpus 5を活用
  • ただしFableほどの使用感の軽さはまだない（体感値）
  • Opus 5はサブエージェントで呼んで仕事を任せるのが最高
  • Fableをオーケストレーターにしつつ、Opusを実行層に配置
Fable（指揮官）＋ Opus 5（実行部隊）の組み合わせが強い！

⑮ 自発的な変出行動を残す: スキルの活用

  • 基本的にはモデルに任せるが、良い検証手段があれば残すべき
  • スキル化して使えるようにしておく — ただし強制はしない
  • 「こうした方がいいのでは？」という人間の知見をスキルに込める
  • モデルが自分の検証ツールを作る方が良い場合は何も書かない方が良い
人間の知見をスキルに込めて、後はモデルに任せる！

⑯ 再確認・チェック系は削る方向で

  • 再確認系やチェック系の指示はモデルがしっかりやってくれるので削る
  • コンテキストフレッシュなサブエージェントでのレビューも自動で実行
  • 人間はボット眺めている時に動きをチェックして調整する
  • 「これは漏らしたらいけないのに漏れてるな」があればプロンプトを追加
人間は監視役に回る — それがOpus 5との付き合い方！

実践的な運用とコツ

⑰ スキルごとのエフォート設定が重要に

  • Opus 5ではスキルごとのエフォート設定がより重要になった
  • 軽いタスクはLowで素早く、重いタスクはX-Highで
  • ループを仕掛ける時はX-Highがおすすめ — Maxより状況に応じた柔軟性
  • マルチエージェント協調で難しいコンテキストに挑むのがClaudeの強み
全部X-Highじゃなくて、タスクに合わせて変えるのが賢い！

⑱ コストと効果のバランス: 時間をお金で買う

  • サブスクの枠は有限 — 無駄なサブエージェント呼び出しは控える
  • ただし「未来の時間をお金で買う」という発電も一つの戦略
  • トークンをどんどん燃やして前に進むのも、最初のステップとしては正義
  • 最善を尽くすか、コスト最適化するかは自分の中で意識しておく
コスト削るか、速度優先か — それが問題だ！
