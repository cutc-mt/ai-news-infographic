Opus 5の概要

① Opus 5とは: 高性能かつ半額の新モデル

  • AnthropicがClaude Opus 5をリリース — Sonnet 3.5に近い性能ながら料金は半額
  • 入力$5 / 出力$25 — Opus 4.8と同等の価格設定
  • 知識のカットオフは2026年5月まで — 検索なしで最新情報を記憶している
  • ベンチマークでトップクラスを記録し、一部ではSonnet 3.5を上回るスコア
Sonnet 3.5の制限に困ってた人に朗報！普段使いでガンガン使えるよ

② ベンチマーク結果: Sonnet 3.5に肉薄

  • 公式ベンチマークでSonnet 3.5と同等以上のスコアを記録
  • Opus 5、Sonnet 3.5、Opus 4.8を比較し、多くの項目でトップを獲得
  • ただしベンチマークのスコアが高い≠最強モデルという点には注意
  • 実用性やコストパフォーマンスも含めて総合的に判断すべき
ベンチマークはあくまで指標の一つ！実際の使い心地が大事

③ 得意な領域: コーディング・業務・PC操作

  • 自立コーディング — エージェントが自律的にコーディングを継続する性能が高い
  • 知識労働 — 資料作成や分析など実際の業務タスクで高い性能
  • PC操作 — ブラウザやアプリの自動操作でテストや入力を自動化
  • 業務ワークフローは他モデル比で約1.5倍の性能向上
エージェント的なタスクと相性がいい！これは嬉しい

革新的な性能

④ 手順にない仕事への対応力が3倍に

  • 未知のタスクやマニュアルのない仕事への対応力が過去モデルの約3倍に向上
  • 見たことのない新しいゲームやルールをその場で理解して対応できる
  • ARC-AGI-3ベンチマークで圧倒的な性能を記録
  • 業務に置き換えると、手順書がない現場でも対応可能 — 柔軟性が大幅アップ
マニュアルなしでも仕事できるって、実務ですごく助かる！

⑤ ポケモンゲーム作成デモ: 1行プロンプトで完成

  • 1行のプロンプトでポケモン風ゲーム「ポケモンテイマーズ」を作成
  • テストを15個パスして無事に完成 — 品質も高い
  • バトル画面、モンスター選択、草むらエリアなど本格的な要素を再現
  • 前回のSonnet 3.5と比較しても遜色ない作り込みを実現
1行でここまで作れるのは開発力が相当高い証拠！

⑥ コストパフォーマンス: 圧倒的なコスパ

  • PC操作においてSonnet 3.5の1/3のコストで同等の性能を実現
  • 業務ワークフローは同コストで1.5倍のパス率
  • 自立コーディングはOpus 4.8の2倍の性能で低コスト
  • ただしエージェントコーディングや医療分野ではまだトップではない点に注意
コスパは最強クラス！ただし万能ではないので注意

安全性とアラインメント

⑦ 最もアラインされたモデル: 勝手に暴走しない

  • アラインメントスコア — 勝手に変な行動をしない指標で最高水準を記録
  • Mistral 5が3.5、Opus 4.8が2.85に対し、Opus 5はより低いスコアで安全
  • 最近OpenAIのモデルがハッキング暴走を起こした件とは対照的
  • ちゃんと真面目に動くモデルとして信頼性が高い
安全性が高い = 仕事で安心して使える！

⑧ セキュリティブロックの減少: 優等生病が解消

  • Sonnet 3.5は少しでもグレーゾーンだと即ブロックして仕事がやりづらかった
  • Opus 5では無駄なブロックが減少し、柔軟に仕事ができるように
  • ある程度の柔軟性がありつつも、倫理的には問題ないバランスを実現
  • K3などの中国系モデルも同様の傾向で評価が高く、優等生病からの脱却がトレンド
いい意味で優等生感がなくなって、仕事で使いやすくなった！

⑨ 業務ワークフローの現実: 人のチェックは必須

  • 業務ワークフローの最高スコアはまだ26% — 大半は人間の確認が必要
  • 完全に人間のチェックを外せる状態ではないため、最終確認は人間が行う設計が重要
  • AIを使って業務を回す際はサポート役として位置づけるのが正解
  • 自動化できる部分と人間が判断すべき部分を明確に分けるべし
AIは強力な助手だけど、最終判断は人間がね！

コンテキストエンジニアリングの時代

⑩ システムプロンプトの80%削減: モデルが進化したら設定も変える

  • Anthropicは自社製品Claude Codeのシステムプロンプトの80%以上を削除しても性能が変わらなかったと報告
  • ログを確認したところ、指示同士が矛盾するポイントが発見された
  • 「ドキュメントを残せ」と「コメントを残すな」が矛盾して無駄な思考コストを発生させていた
  • モデルが進化したら、使い方も変える必要がある
矛盾する指示が無駄なコストを生んでた...整理大事！

⑪ プロンプト ≠ コンテキストエンジニアリング

  • プロンプト = 1回の指示（一回きりの命令文）
  • コンテキストエンジニアリング = システムプロンプト、社内ルール、ファイル、スキル、メモリーなど全体設計
  • 指示だけでなく、環境全体を設計し直すことが重要に
  • これからのAI活用はコンテキスト設計が鍵になる
プロンプトエンジニアリングから コンテキストエンジニアリングへ！

⑫ 細かいルールをやめて判断を任せる

  • 細かすぎるルールは逆効果 — 状況によって矛盾する可能性がある
  • 「コメントを書かないといけない」より「周囲の工程に合わせて書く」のように柔軟に
  • 昔は使用例を大量に与えるのが推奨されたが、今は違う
  • 最新モデルではインターフェース設計の方が効く — ツールやスクリプトの表現力が重要
子育てと同じ？ ガチガチより自由にさせた方が伸びる！

コンテキスト設計の実践ポイント

⑬ 必要な時に必要な分だけ開示する

  • 最初から全部読ませる必要なし — 必要な時に開示する設計が正解
  • コードレビューや検証の詳細手順は常時は不要、必要な時に参照
  • 独立したスキルとして切り出して必要な時に呼び出す
  • ツールも一部は遅延読み込みでトークン消費を節約
CLAUDE.mdに全部書くと毎回トークン消費がすごい...分割が正解！

⑭ 同じことを繰り返さずシンプルに

  • 重複する指示は削除してシンプルに保つ
  • 矛盾や重複があると無駄な思考コストが発生
  • ルールファイルに記憶させるより自動メモリー機能を活用
  • ただし社内セキュリティ基準に関わる部分は慎重に判断すべし

⑮ テキストだけでなくリッチな参照を

  • 文書だけの使用書より、コードやテスト参照、HTMLなどの具体的な形式が良い
  • テキストだけでなくより具体的な形で例を示す
  • タスク管理ツールの状態をpending / in-progress / completedで定義するだけで使い方が伝わる
  • 全体設計を見せる方が個別の使用例より効果的
例を大量に書くより、全体像を見せた方が分かりやすい！

今日からのアクション

⑯ CLAUDE.mdは軽く要点だけ書く

  • CLAUDE.mdには要点だけを簡潔に記述する
  • ガチガチのルール管理より判断しやすい環境を作る
  • 子育てと同じ — ある程度自由を与えて伸び伸びさせる方がAIも頑張る
  • 過剰な制約はかえって足かせになる
AIも人間も自由度があった方が良い仕事をするね！

⑰ スキルは必要な時だけ呼ぶ設計に

  • スキルを毎回読み込むとトークン消費が膨大になる
  • 必要な部分だけを個別のスキルに分けて配置
  • 必要な時に読み込む設計にすると性能が上がる
  • CLAUDE.mdに全部書くのではなく、分割して管理するのがベストプラクティス
スキルの分割管理 = トークン節約 ＋ 性能アップ！

⑱ まとめ: Opus 5で変わるAI活用の新常識

  • Opus 5は高性能かつ半額で、普段使いできるコスパ最強モデル
  • 安全性が高く、勝手に暴走しない信頼性のあるモデル
  • プロンプトだけでなく環境全体を設計するコンテキストエンジニアリングへ
  • CLAUDE.mdを軽くして、スキルを分割して、判断をAIに任せる設計へ移行しよう
  • 今日からコンテキスト設計を見直してみよう
Opus 5 ＋ コンテキストエンジニアリング = 最強の組み合わせ！
