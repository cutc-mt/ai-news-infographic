AI OCR製品をぶっ潰せ 極み編

Canvas + GAS連携で抽出領域をクラウド保存 — 再利用性を手に入れる

2026年8月1日 ／ 17:00

① AI OCRとは何か

  • OCR（光学文字認識）にAIを融合させた技術
  • AIが自己学習して文字の形状を理解する
  • 従来のOCRでは読めなかった文字も認識できる
  • 主な用途は PDF読込CSV出力
AIのおかげで、昔なら読めなかった手書き文字や特殊フォントも判別できるよ！

② 既存製品の弱点

  • 抽出領域を手動で作る必要がある
  • 例：調書を読み込む際、どこを読むか人間が指定
  • 毎回同じ作業の繰り返しで時間がかかる
  • 設定の再利用ができないのが最大の課題
毎日同じ形式のPDFが来るのに、毎回領域を設定するのは本当に面倒…

③ コケ先生の挑戦

  • 「AI OCR製品をぶっ潰せ」第3回・極み編
  • 単なるノリではなく、本気で既存製品を超える
  • 武器は Gemini Canvas
  • 目標：人間の作業をほぼゼロに
第1回・第2回を経て、いよいよ最終形態に到達！

④ 前回までの成果

  • PDFをアップロードしてセット構成を自動判定
  • Geminiが抽出領域を自動で特定
  • 必要に応じて人間が微調整
  • PDF全体のOCRを実行して完了

ここまでで実現したこと

画像を理解して抽出ポイントを決める所まで自動化済み。でも、まだ大きな問題が残っていた…

⑤ 今回の課題

  • 視聴者からのリクエスト：「抽出領域を保存できないか」
  • 同じようなPDFが毎日・毎週届く現場が多い
  • 毎回抽出領域を設定するのは非常に非効率
  • 再現性が確保されていない
視聴者のリアルな声から始まった改良。実務の課題をそのまま拾っているのが凄い！

⑥ 試した解決策（失敗）

  • 案1 JSONファイルに書き出す
  • → ローカル保存になりGoogle Workspaceの外に出てしまう
  • 案2 ブラウザのローカルストレージ
  • → Canvasはサンドボックス環境で動くため弾かれる
シンプルな方法から試したけど、Canvasの制限に阻まれてしまった…

⑦ 解決策のひらめき

  • LINEのチャットボット構築の経験からヒント
  • フロント（Canvas）＋ バックエンド（GAS）の連携
  • Canvas単独ではなく、外部サービスと繋ぐ発想
  • GASを受け口として使う
過去の経験が新しいアイデアの種になる。引き出しを増やすのが大事！

⑧ 全体アーキテクチャ

  • フロント Gemini Canvas（画面・操作）
  • バック Google Apps Script（GAS）
  • DB Googleスプレッドシート
// データの流れ
Canvas → GAS → Spreadsheet
Canvas ← GAS ← Spreadsheet
Canvasの弱点をGASで補う、まさに最強のコンビネーション！

⑨ GASの役割

  • doPost: Canvas → GAS 書き込み指示
  • スプレッドシートにデータを保存
  • doGet: GAS → Canvas 読み込み
  • GASのWebアプリとしてデプロイして利用
doPostとdoGetの2つだけで、書き込みも読み込みも自由自在！

⑩ スプレッドシートに保存されるデータ

  • 抽出領域の保存名（テンプレート名）
  • 抽出領域の場所（座標データ）
  • 保存日時
// スプレッドシートのイメージ
| 保存名 | 座標データ | 日時 |
| 調書A | {x:10,y:20...} | 2026/8/1 |
スプレッドシートだから、後から見直すのも編集するのも簡単！

⑪ 実際の使い方

  • GASのWebアプリURLをデータベース設定に入力
  • 新しいPDFを読み込む
  • 過去のテンプレートを選ぶと自動で抽出領域が適用
  • ドラッグ＆ドロップで微調整
  • 「保存」または「上書き」でクラウドに保存
一回設定すれば、次からはテンプレート選ぶだけ。劇的にラクになる！

⑫ Canvasの致命的な弱点

  • 保存機能がないのが最大の問題
  • 1回1回データが初期化されてしまう
  • サンドボックス環境で外部アクセス制限
  • 設定作業が毎回無駄に消える
どんなに頑張って設定しても、画面を閉じたら全部消える…それがCanvas。

⑬ GASで弱点を克服

  • Canvasの弱点をGASで完全にカバー
  • GASを通すことで継続性が生まれる
  • 設定が消えずに何度でも再利用可能
  • Canvas + GASの最強タッグ
弱点を補い合う関係。まさにソフトウェア版・ベストパートナー！

⑭ 完全なシステム化

  • フロント + DB + バックの3層構造
  • 本格的なシステムアーキテクチャと同じ構成
  • CanvasがUI、GASがAPI、シートがDB
  • ノーコードで完全システム化が可能

何がすごいって

専門知識がなくても、この3つを組み合わせれば本格的なシステムが作れる。

⑮ Geminiが全部書いてくれる

  • 概念を伝えればGAS呼び出しを実装
  • GASのコードもジェミニが書いてくれる
  • doGet/doPostの中身も自動生成
  • コードはGitHubで公開済み
ノーコードどころか、コードさえAIが書いてくれる時代が到来！

⑯ ワークフロー全体像

  • PDFをCanvasにアップロード
  • Geminiがセット構成と抽出領域を自動特定
  • 設定をGAS経由でスプレッドシートに保存
  • 次回はテンプレート選択だけで再利用
一回作れば、あとは自動で回り続ける。これぞ真の自動化！

⑰ なぜ既存製品を超えたか

  • Geminiが画像を理解して領域を自動決定
  • 手動での領域作成が不要
  • 設定がクラウドに保存され再利用可能
  • 既存製品は高額だが、これは無料のGoogleサービスで完結
高い製品を買わなくても、無料ツールの組み合わせで超えられる！
