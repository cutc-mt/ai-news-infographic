コーディングは解決済みか — AI開発の速度とAGIのTimeline

No Priors の Sarah × Elad が読み解く、コーディング自動化の現在地と、予測不能な AGI への道
2026年8月7日 ／ No Priors Podcast「Is Coding Solved?」
放送

①No Priors — 投資家が語るAI最前線

  • ホストは Sarah Guo（AI 投資家）と Elad Gil（起業家・投資家）
  • AI・スタートアップ業界の最前線を毎週切り取る番組
  • 技術だけでなく、投資家の目線で市場を読む
  • リリースが毎週ある現状を、冷静に整理する貴重な声
技術とお金の両方を話せるからこそ、見える景色がある！
問い

②「コーディングは解決済みか？」

  • 本回の主題は、ストレートな一問「Is Coding Solved?」
  • 答えは白か黒かではなく、現在地と速度を測る問題
  • 問い自体が、時代の空気を映している
  • 結論よりも、考え方の枠組みが参考になる
「解決」とは何か。問いを深掘ること自体が答え！
速度

③毎週くる、新しいブレイクスルー

  • AI 開発のスピードは猛烈。一週間でも置いていかれる
  • 毎週のように、新しい発表が飛び込んでくる
  • 追うだけで精一杯になる情報の濃さ
  • 速さゆえに、何が本質かを見極める力が試される
毎週ブレイクスルー。立ち止まる暇がない！
予測

④なぜAGIの到達は予測しづらい

  • 到達時期の予測が、年々難しくなっている
  • 技術・資金・社会の三要素が絡み合う
  • 先が見えないからこそ、楽観と悲観が行き来する
  • 正確な日付より、方向と傾きを読むのが現実的
いつ来るかより、どう備えるかが本題！
現状

⑤コーディングエージェントの進化

  • Claude Code や GitHub Copilot が、現場を変えつつある
  • 補完から一歩進み、自律的に書く領域へ
  • 人間のレビューはまだ必要、しかし比重は下がる
  • できることが、月ごとに増えている実感
補完から自律へ。役割分担が変わる！
自動化

⑥プログラミング自動化のいま

  • 定型的な処理は、ほぼ自動で書ける時代に
  • 部品を組み合わせる作業の効率が跳ね上がる
  • 人間は設計と判断に、力を注ぐ形へ
  • ただし複雑な全体像は、まだ人の手が必要
定型は任せて、設計に集中する時代へ！
雇用

⑦ジュニア層に迫る影

  • 入門的な作業は、まさにAI が得意な領域
  • 若手が学ぶ機会が、減る懸念が出ている
  • 階段の初段が消えると、上がどう育つか問題
  • 組織としての育て方を、見直す必要
初歩を任せる時代。育成の設計も変える！
品質

⑧テスト・デバッグ・リファクタ

  • テスト駆動開発の自動化が、かなり進む
  • バグを見つけて直す巡回も、AI が担う
  • リファクタリング（整理）の手間が大きく減る
  • 品質を保つ下支えとして、期待が高まる
テストも整理も自動で。品質の土台が変わる！
成熟度

⑨まだ完全じゃない、でも速い

  • 今のエージェントは、万能ではない。見落としもある
  • しかし改善の傾きは、想像より急
  • 半年前の常識が、もう古くなる速さ
  • 「今は無理」が、すぐ可能になる予感
完璧でなくても、速く良くなっている！
限界

⑩スケーリング法則の天井

  • 計算を増やすほど賢くなる、という法則に頼ってきた
  • しかし、どこかに頭打ちの可能性が見え始める
  • データや電力にも、限界が近づく声
  • 法則が続くか止まるか、大きな分岐点
ただ増やせばいい、ではなく。壁を意識する時！
安全

⑪アライメント — 価値のすり合わせ

  • AI の行動を、人間の意図に合わせる難しさ
  • 賢くなるほど、すれ違いの代償が大きい
  • 目標の設定そのものが、難問として残る
  • 技術と並行して、哲学も問われる領域
賢いほどすり合わせが大事。技術だけじゃ解けない！
投資

⑫データセンター投資と需要の隙

  • 巨大なデータセンター投資が、世界中で進む
  • だが実際の需要と、投資の規模に差が出る
  • 回収の見通しが、需要次第で揺れる局面
  • 投資の過熱と、需要の不確実性の板挟み
箱はある、でも中身の需要次第。読み方が鍵！
市場

⑬最先端 vs コスパの二極化

  • 一方に、性能を極める最先端モデル
  • 他方に、安価・軽量なコスパ重視モデル
  • 中間が薄れ、二極へ向かう構造
  • 用途によって、選ぶ基準がはっきり分かれる
高いか、安いか。中間が消えていく！
基盤

⑭ハーネス — エージェントを支える土台

  • エージェントを動かす骨組み、通称ハーネス
  • モデル以上に、周囲の設計が成果を決める
  • 道具・記憶・手順を、どう繋ぐかが勝負
  • 良いハーネスが、同じモデルでも差をつける
モデルより土台で決まる。隠れた主役！
役割

⑮コードを書く人から、指揮する人へ

  • 自ら書く作業は、比重が下がる一方
  • 代わりに、AI を指揮する役割が大きくなる
  • 必要なのは、何を・どう指示する力
  • 指揮者のように、全体を動かす技術者へ
書くより動かす。指揮者が求められる！
設計

⑯システム設計の重要性が増す

  • 部品の作成は自動化されても、全体構造は人間次第
  • アーキテクチャの設計力が、差をつける軸に
  • 組み合わせ方、境界の引き方が重要に
  • 見えない骨組みこそ、価値の源泉
部品より骨組み。設計力の時代へ！
視点

⑰投資家が読む、AI市場の構図

  • 最先端とコスパ、どちらに金が動くかを問う
  • インフラ・モデル・応用、三層それぞれの価値
  • 差がつくのは、応用と土台の層
  • 技術より、金の流れで勝負が決まる面も
技術だけでなく、お金の行方を読む！
展望

⑱エンジニアの未来 — そして結論

  • コーディングは一部解決しつつ、全体は道半ば
  • 人の役割は、設計と指揮へ移っていく
  • AGI の時期は読みづらい、だからこそ備える
  • 問いへの答えは、動き続けることそのもの
解決じゃなく変容。動き続ける人が残る！
