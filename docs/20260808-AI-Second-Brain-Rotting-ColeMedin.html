解決編: state と event に分ける

核心の解決策:
fact は2種類だけ

10:59
  • state ＝ 今の状態
  • event ＆ 過去に起きた出来事
  • この2つを明確に分離
  • 矛盾が構造的に消える
すべての fact を
「今の姿」か
「起きたこと」かに分類。
これだけで劇的に改善！

state（状態）とは

今の姿・上書きOK
  • 常に最新の1つだけを持つ
  • 例: 顧客の現在の料金
  • 新しい値で古い値を上書き
  • 矛盾は発生しない
# state の例（常に1つ）
client:
  name: "Acme Corp"
  price: "$5,000/mo"  # 最新値のみ
state は「上書き」。
履歴は残さないから
迷わない ✨

event（出来事）とは

履歴・追記方式
  • 起きた事実を時系列で記録
  • 過去の出来事は消さない
  • 例: 料金変更の履歴
  • 文脈を保つための裏付け
# event の例（時系列）
events:
  - date: "2026-03" price: "$3,000"
  - date: "2026-06" price: "$4,000"
  - date: "2026-08" price: "$5,000"
event は「積み重ね」。
履歴を活かしつつ、
state と分けて管理！
