使う場所で速さが変わる

同じ Claude Code でも場所次第
  • 同じ Claude Code でも、どこで動かすかで速さがちがう
  • 黒い画面（ターミナル）だけか
  • エディターの中か、この差が大きい
ここでは VS Code の
拡張機能に注目するよ！

黒い画面 か エディター か

ふたつの使い方をくらべてみる

ターミナル

文字だけの羅列。目で追うのが大変。

VS Code

見た目つき。差分も並んで見える。
まずはこの差を
しっかり見てほしい！

初心者はターミナルだけ

まずは黒い画面から入る
  • 初心者は ターミナル だけで使うことが多い
  • 直したい場所を文章で説明して頼む
  • 帰ってきた変更を、受け取る
「ここのバグを直して」
と文章で伝える方式だよ

文字の羅列を目で追う

ターミナル版のつらさ
  • 帰ってきた変更は 文字の羅列
  • ひたすら目で追って、確認するしかない
  • 行数が多いと、時間もかかる
// ターミナルに流れる変更
- const x = oldValue;
+ const x = newValue;
これを目で追うのは、
ほんとにしんどい…

見落としたまま取り込む

ターミナル最大の落とし穴
  • 目で追いきれないと見落としが出る
  • 見落としたまま、変更を取り込んでしまう
  • あとでバグのもとになることも
「あれ、ここも変わってた？」
とならないようにしたい

上級者は拡張機能を入れる

VS Code の拡張機能が分かれ道
  • 上級者は VS Code の拡張機能 を入れる
  • ターミナルから、エディターの中へ
  • 確認の速さがぐっと上がる
ここから先は
拡張機能の世界だよ！

選ぶだけで範囲が伝わる

文章で説明しなくていい
  • 直したいコードを、そのまま選ぶ
  • 選んだ範囲が、AIにそのまま伝わる
  • 長い文章で説明する手間が、消える
ドラッグして選ぶだけ。
これだけで伝わるんだ！

変更は元のコードと並ぶ

差分が横に並んで見える

前

変更前の元のコード

後

変更後の新しいコード
並べて出るから、
どこが変わったか一目！

その場で直してから承認

提案を鵜呑みにしなくていい
  • AIの変更を、その場で直せる
  • 直してから、承認ボタンを押す
  • 納得したコードだけ、取り込める
「ここはちょっと直そう」
がその場でできるよ

やることは ひとつだけ

最初の1歩はとてもシンプル
  • 拡張機能から Claude Code を検索
  • 見つけたら、インストールを押す
  • これだけで、準備はほぼ終わり
複雑な設定はナシ。
検索して入れるだけ！

10分でできる 最初の1歩

3ステップではじめられる
  • 1VS Code の拡張機能ビューを開く
  • 2「Claude Code」を検索してインストール
  • 3Claude アカウントでサインイン
あとはお使いのアカウントで
サインインするだけ！

APIキーは不要

アカウントでサインインだけ
  • むずかしい APIキー の準備はいらない
  • お使いの Claude アカウント でサインイン
  • これだけで、すぐに使いはじめられる
キーの発行とか不要。
うれしいポイントだね

ただし、限界もある

知っておきたい注意点
  • 拡張機能にも、限界はある
  • パネルの中に、専用の本体が入っている
  • でも、これですべてが動くわけではない
ここだけ押さえておけば、
あとで困らないよ

ターミナルで動かすには

本体は別で入れる必要あり
  • パネル用の本体は、拡張機能に同梱
  • ターミナルでコマンドとして動かすなら別で入れる
  • 用途に合わせて、両方入れる手もある
# ターミナル版は別で用意
$ claude --version
パネル用と、コマンド用は
別物だと覚えておこう

まとめ① 選んだ所が伝わる

文章いらずの指定
  • 直したい所を、そのまま選ぶ
  • 選んだ範囲が、AIに伝わる
  • 説明の文章を、書かなくて済む
「ここ」を選ぶだけ。
それが一番の近道

まとめ② 並べて確認できる

差分を見逃さない
  • 変更は元のコードと並んで出る
  • どこが変わったか、すぐわかる
  • その場で直して、承認もできる
見落としの心配が、
ぐっと減るよ

まとめ③ 計画も前に読める

作業が始まる前に確認
  • 計画も、始まる前に読める
  • おかしな所は、その前に直せる
  • 進む方向を、事前に合わせられる
はじまる前に計画をチェック。
手戻りが減るね
