案件ごとの設定、もう切り替えなくていい

Codexでプロジェクト別の設定を 自動で当てる方法
2026.08.09 ／ あきらパパ

問題はここにあった

毎回 手で切り替える

案件が変わるたびに、Codexの設定を 打ち直している人はいませんか。

  • 案件A → モデル切替
  • 案件B → 確認あり
  • 案件C → 読み取り専用
毎回切り替えるのは、ほんとに疲れる…。

コマンドに オプションを足す

手動の人は、毎回 コマンドにオプションを書き足します。

# 毎回 この長さを打つ
codex --model "gpt-5" \
      --ask true \
      --sandbox "read"
  • 打つ時間が もったいない
  • オプションを 覚えておく必要

付け忘れが 起きる

打ち直すたびに、オプションの付け忘れが起こります。

  • 確認を挟む設定を 忘れた
  • 書き込み制限を かけ忘れた
  • モデルを 違うまま動かした
付け忘れ一つで、あとで 直す手間が…。

解決策は 自動化

設定の切り替えは、自動に任せられます。

  • 開いた瞬間に 案件の設定が当たる
  • 次からは 何も打たない
  • 付け忘れも なくなる
置くだけ、あとは まかせる！

設定ファイル1枚で すむ

プロジェクトに 1枚置く

自動化する人は、プロジェクトの中に設定ファイルを1枚置くだけ。

# リポジトリーの中
.coder/
  └─ config.toml  # これ1枚
  • 案件のフォルダーに 置く
  • 開けば 自動で読まれる

個人設定は ホーム側

公式ドキュメントでは、場所を分けています。

  • 個人の初期設定はホーム側
  • 案件の上書きはリポジトリー内
# ホーム（個人）
~/.coder/config.toml

# リポジトリー（案件）
./.coder/config.toml

書くのは①：使うモデル

設定ファイルに書くのは、3つだけで足ります。

① その案件で使うモデル

[model]
name = "gpt-5"
temperature = 0.2
  • 速さ重視か、正確さ重視か
  • コストも 案件で変わる

書くのは②：確認を挟むか

② 処理の前に 確認を挟むか

[approval]
mode = "on-each-step"
# on / off / 段階ごと
  • 本番は 毎回確認
  • 実験は 自動で
確認の有無は、案件の 重さで決める。

書くのは③：書き込みの許可

③ どこまで書き込んでいいか

[sandbox]
mode = "read-only"
# read / write / full
  • 読むだけなら read
  • 直すなら write

近い設定ほど 強い

設定は 重なる

設定は階層になっていて、近い方が勝つ仕組み。

コマンド直接（最強）
リポジトリーの設定
ホームの個人設定
上にいくほど、優先度が 高いよ。

案件の設定が 勝つ

個人設定と案件設定が
ぶつかった時は案件側が優先。

  • 普段は gpt-5（個人）
  • この案件は 別モデル
  • → 案件の設定で 動く

コマンド直接は 最強

ただしコマンドに直接つけた指定は、いつも一番強い。

# これが一番 強い
codex --model "gpt-5"
  • ファイル設定より 優先
  • その場だけ 変えたい時に
临时の上書きは、コマンドで。

読まれるには 条件がある

信頼した 時だけ

案件の設定が読まれるのは、そのプロジェクトを信頼した時だけ。

  • 信頼済み → 設定が 読まれる
  • 未信頼 → 設定は 無視される
他人の設定を、勝手に 読まない。

信頼なしは 読まれない

初めて開いたリポジトリーでは、設定ファイルは読まれません。

  • 悪意ある設定を 防ぐため
  • まず信頼する 手順が要る

限界を 押さえる

自動化は便利ですが、限界を知っておきましょう。

信頼済み
設定が効く
未信頼
設定は無視
