哲学編: 小さなプロンプトの逆転劇

巨大プロンプトの
問題点

従来のやり方
  • Claude Code は約1万トークンの指示
  • ベストプラクティス・意見が山盛り
  • すべてClaude 向けに書かれている
  • 毎回コストがかさむ
DeepSeek に Claude 向けの
指示を流し込むと、
モデルが溺れてしまう💦

Pi の逆アプローチ:
プロンプトは小さい

ミニマル設計

  • ツールの説明だけ伝えて退出
  • 「モデルは賢い」と信じて任せる
  • その賭けは正解だった

実践編: Pi ツールを歩いてみよう

クリーンな UI と
たった4つのコア

軽さが正義
  • オンボーディング・ログイン・追跡一切なし
  • 小型の TypeScript コードベース
  • コアツールは read / write / edit / bash のみ
  • 瞬時に起動、RAM を食わない
入力すれば動く。
ただそれだけ。
潔い 設計だ！

/model で
15以上のプロバイダー

モデルを自由に切替
  • Anthropic / OpenAI / Google / DeepSeek / 他多数
  • models.json で任意の端点を追加
  • セッション途中でモデル切替が可能
  • コンテキストはそのまま保持
# 普段は安いモデルで
/model deepseek
# 難しくなったら切り替え
/model "gpt-5.6"
# ↑ 会話は途切れない！
日常は DeepSeek、
厳しくなったら重いモデル。
使い分け自在 🔄
