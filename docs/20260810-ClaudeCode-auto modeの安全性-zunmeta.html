  • 権限の確認そのものが消えるのではなく、判定する主体が変わる

8月14日から順次

  • 切り替えは 2026年8月14日 から始まる
  • 対象は 新しいセッション から順次適用
  • すでに動いている作業は、そのまま人が確認を続ける

人は長く続かない

  • 作業が長引くほど、人の注意は 徐々に落ちる
  • 確認の回数が増えるたびに、止める率が下がっていく
  • 「また同じ画面だ」と見慣れて、警戒が薄れるのが原因

機械は横ばいを維持

  • 作業が長くなっても、AIの検出率は ほぼ一定
  • 疲労や慣れがなく、判断の質が落ちない
  • ずっと同じ水準で危険を見張り続けられる
長時間でもブレない。
これが人と機械の一番の差

AIは何を、どう止めるのか

止める対象は3つ

  • 取り消しがきかない 操作を止める
  • 壊してしまう 操作を止める
  • 自分の環境の外 へ影響する操作を止める
「全部止める」じゃなくて、
本当に危いものだけを狙う

コードや秘密は渡さない

  • プログラムの コード持ち出し は通さない
  • 秘密情報 の外部への送信も止める
  • たとえ利用者から頼まれても、持ち出しは弾く設計
外部に漏れては困るものは、
頼まれても通さない——ここは固定

gitの送信先も見る

  • 送信先が 公開リポジトリ か、社内かを実行前に確認
  • 意図せず 社外へ出る 送信を事前に止める
  • 行き先まで見るのが、auto mode の特徴
$ git push origin main
# AIが送信先を確認
# 公開リポジトリなら要確認へ
「送る」だけでなく、
「どこへ送るか」まで見てる

止まりすぎたら人へ戻る

  • 3回続けて 止まったら、人の手動確認に戻る
  • 1つの作業で 20回 止まっても、同じく手動へ
  • 自動で止め続ける限界を、人に引き継ぐ仕組み
3 連続停止で戻る
20 作業中の上限
止まりすぎ＝何かがおかしい。
そう判断したら人に渡す
