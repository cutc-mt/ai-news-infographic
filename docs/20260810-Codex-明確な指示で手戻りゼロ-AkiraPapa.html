「いい感じで」に まかせると、 なにが おきるか

「いい感じで」は 罠

つかいやすい 言葉の 落とし穴

  • 「いい感じで やっておいて」
  • AIは どこまで か、 わからない
  • 「いい」の 基準 が ない
人間同士でも
「いい感じ」は 伝わらない。

AIは 終わりを
判断 できない

「どこで とまるか」を 知らない

  • AIは 完了の 線 を 持たない
  • 「このあたりで」が ない
  • だから 途中で とまる
終わりは
人間が 決めて 渡す。

止まる → 確認の
往復が ふえる

「これで いい？」が なんども

  • AI「これで いい?」
  • 人「もうすこし こうして」
  • この 往復 が なんども
途中で止まる 確認の往復

手戻りが
だんだん 重く なる

ちいさな やり直しが かさむ

  • やり直しの 回数 が ふえる
  • 時間も コツコツ 消える
  • 気づけば 半日 終わる
ちいさな 手戻りも
集まると でかい。
解決は 三つ、 書く だけ

解決の 三要素

これだけ 書けば やり直しが 減る

  • 結果 ー できあがり
  • 制約 ー 守る 境界
  • 確かめ方 ー 見る 基準
結果 制約 確かめ方
この 三つを
そろえる だけ。

① 欲しい 結果

「やる作業」ではなく「状態」

  • 出来上がった 状態を 書く
  • 「作業して」 ではなく 結果
  • これが 終わりの 線
× 作業 コードを なおして
○ 結果 テストが 全部 通る

② 守る 制約

使う道具・境界・禁止の やり方

  • 使う 道具 を 指定
  • 守る 境界 を 伝える
  • やって ほしくない やり方
「これ以外は さわらないで」
と 決めて おく。

③ 確かめる 方法

テスト・計測・レビュー基準

  • テスト を 準備する
  • 計測 の しかたを 決める
  • 基準 を 数字で 書く
「こう なれば OK」
を 見える化 する。
公式の 例文と、 書き方の コツ

公式の 例文を 分析

ChatGPT 公式ドキュメントの 文

  • 結果: どこまで できたら 良い
  • 制約: 使う 道具と 守ること
  • 確かめ方: どう 見る か
# 公式 例文の つくり
① 結果: README を 更新する
② 制約: 和文は 7:3 まで
③ 確かめ: 見出し 3つ 以上
公式でも
この 三つ が 入っている。

結果を 具体的に
書く コツ

「状態」で とめる

  • 「〜が できている」
  • 見て わかる 状態に
  • 動作ではなく 結果 で
× あいまい ドキュメントを 整える
○ 具体的 初心者が 手順 3つで 動く

制約の 書き方

境界を 明確に する

  • 使う 道具 を あげる
  • さわって ほしい 範囲
  • 禁止の やり方 も 書く
「ここから ここまで」
を はっきり させる。

確認方法の 指定

「どう 見るか」を 決める

  • テスト を なにで するか
  • 計測の 基準値
  • レビューの 順序
「これで 確かめて」と
先に 渡す。
ここは 勘違い しない

権限は 広がらない

終わりを 決めても 自由には ならない

  • 結果を 書いても 権限 は 同じ
  • AIの 自由 は ひろがらない
  • やれる ことは 制限 の まま
「終わり」と「権限」は
別物 だと 知る。

判断が 必要な 場面で
止まって 聞く

ひとりで 決めない

  • 分かれ道は 聞きに くる
  • 「AとB、 どちらに しますか?」
  • リスクは 人間が 持つ
独断で 進まず、
一旦 きく。

並行実行の 注意点

  • おたがいの 範囲 を 見る
  • 衝突 に 気を つける
並行は はやい。
