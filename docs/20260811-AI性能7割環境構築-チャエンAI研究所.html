AIは どう 変わったか

ブラウザから ローカル へ

使い方の 変化
  • 最初は ブラウザで ChatGPT を 使うだけ
  • いまは デスクトップアプリ が 主役
  • Claude Code や Codex が ローカル で動く
  • エージェントが 自分のPCで はたらく
「サイトを 開く」から 「同居する」 へ。 AIとの 付き合い方が 変わった！

相談相手 から 新人 へ

位置づけの 転換
  • かつては 外部の 相談相手
  • いまは 社内に 席がある 新人
  • 毎日 いっしょに 働く 存在
  • 関係が 根本から 違う
新人が くるなら 準備が 必要。 そこが この話の はじまり！

新人には 3つの もの を

準備の 中身
  • まず 机 を 用意する
  • つぎに 資料 を 渡す
  • 最後に ルール を 教える
  • これこそが エンジニアリング の 正体
実は 環境構築 と むすびつく。 ここが 7割を 決める！

最新 & 最重要
最重要 3つの なかで いちばん 大事
  • 動く 環境全体 を 整える
  • ツール・検索・スキル・権限 まで
  • ここが 7割 を 握る

プロンプト: 昔と 今

昔は 長く 書くのが 流行

かつての 常識
  • 「あなたは 天才の〜」 と 長々と
  • 役割を 大げさに こづける
  • 文字数が 多い ほど 良いと されてた
  • 実は 性能が 落ちる ことも
長ければ 良いわけじゃ ない。 最近は 常識が 変わった！

今は 短く シンプル が 良い

新しい 常識
  • Anthropicも OpenAIも シンプル 推奨
  • 要点だけ すっきり つたえる
  • むしろ 性能が 上がる
  • 余分な 言葉は 削る
大切なのは 「何を」 であって 「どれだけ長く」 じゃない！

裏側の プロンプトも 8割カット

実例
80% 削減 性能は そのまま
  • Claude Codeの 裏側 の指示
  • 8割 削っても 性能が 変わらない
  • 短いほど 効く のが 証明された
実際の データで 「短い方が 良い」 が 裏づけられた！
