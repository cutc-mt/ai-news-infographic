Muse Glimmer 30B
ローカルで動く エージェント特化 モデル

Metaの新オープンモデルは、ずっと動く AI のために作られた
📅 2026年8月11日 ｜ 🎙️ AI Code King
30B Dense ツール呼び出し マルチモーダル MIT ライセンス ローカル実行

Muse Glimmer ってなに？

1

Meta 発表の 新モデル

  • 名前は Muse Glimmer、30B（300億パラメータ）の オープン AI モデル
  • 狙いは「ローカル エージェント」を 動かす こと
  • クラウド無しで、自分の PC で AI を 24時間 動かしたい人 向け
  • オープン重視。誰でも ダウンロードして 使える
ひとことで言うと
「手元の PC で じぶん専用 AI を」
を 実現するための モデル です
2

エージェント用途 に 特化

  • 単なる 会話 AI ではなく、ツール を 婦ぶ ことに こだわった 設計
  • ずっと 動き続ける 常時起動 ワークフロー 向け
  • 複数ステップを つなぐ タスク で 本領を 発揮
  • 失敗 しても 立ち直る、障害 回復 が 強い
普通の チャット なら 他のモデルで OK。
「動き続ける AI」を作りたい人に ピッタリ！
3

Dense 30B という 形

  • アーキテクチャは Dense（密）型
  • MoE（専門家 mixture）では ない
  • パラメータ を すべて 毎回 使うので、安定した 出力
  • 代わりに メモリ 要件 は 高め
30BDense 参数
Dense非 MoE
MoE より 重い けど、
挙動 が 読みやすい のが Dense の 魅力

ツール呼び出し ＆ 安定性

4

ツール呼び出し が とにかく 正確

  • API を 叩く、検索する、ファイル を 読む — こうした ツール 呼び が 安定
  • 指示 した 通り に 動く 確率 が 高い
  • パラメータ の 渡し間違い が 少ない
  • エージェント の 信頼性 に 直結する 強み
エージェント で 一番 困る のは
「ツール を 間違えて 呼ぶ」こと。
そこが しっかり してる のが 最大の 売り
5

複数ステップ の タスク に 強い

  • 「調べて → まとめて → 書いて」の ような 連続 タスク
  • 道筋 を 保ちながら 進める のが 得意
  • 途中で やり直し が 必要 でも 対応
  • 最後まで 着地 させる 力 が 評価 されてる
一発 の 回答 より、
長い 旅路 を 伴う タスク 向き
6

失敗から 立ち直る 力

  • エラー が 出ても パニック しない
  • 別の 方法 を 試して 回復 できる
  • ずっと 動かす AI で 耐久力 は 命
  • 長時間 運用 での 安定性 が 高い
常に 動き続ける AI にとって
「落ちない」 のは 正義。
その 点 で 安心 できる モデル

目 と 耳 を 持つ AI

7

マルチモーダル に 対応

  • テキスト だけで なく 画像 も 入力 可能
  • スクショ、図、写真 を 読み取れる
  • デザイン や 図解 の 理解 も こなす
  • エージェント が 視覚 を 使える のが 大きい
「画面 を 見て 操作」みたいな
視覚 を 要する タスク も 視野 に入る
8

専用 パーセプション エンコーダー

  • 画像処理 用 の 知覚 モジュール を 内蔵
  • 本 体 とは 別 に、画像 を 読む 部品 が ある
  • その 分、認識 の 精度 が 上がる
  • 構造 が 丁寧 に 作られて いる 印象
画像 は 画像 用 パーツ で 処理。
役割 を 分ける のが 今風 の 作り
9

テキスト ＋ 画像 の 組み合わせ

  • 画像 を 見ながら 説明 する、といった ことが できる
  • 「ここ を 直して」と 指示 + スクショ、の 運用 に向く
  • エージェント が 視覚 情報 を 活用 できる
  • 人間 との やり取り が ずっと 自然 に
目 で 見せて、口 で 伝える。
人間 らしい 連携 が ローカルで できる

自分の PC で 動かす

10

48GB Mac なら フル実行

  • 48GB RAM の Mac が ひとつの 目安
  • 4-bit 量子化 すれば フル コンテキスト で 動く
  • Apple Silicon の 統合 メモリ が 有利
  • クラウド 通信 なし で 実用的 な 速度
Mシリーズ Mac × 大容量 メモリ なら
自分 の マシン だけで 完結
11

メモリ 要件 は 高め

  • Dense 30B なので 全 パラメータ を 読む
  • 16GB / 24GB の 機械 では 厳しい
  • 厳しい 量化 で 無理 すると 遅く なる
  • ハードウェア の 選択 が 大事
Dense の 強み は メモリ 代价。
スペック 次第 で 使い勝手 が 変わる
12

4-bit 量子化 で バランス

  • 4-bit に つぶせば メモリ 節約
  • 精度 落ち は ある ものの、実用範囲 内
  • 速度 と 品質 の 折り合い を 付けやすい
  • 用途 に 合わせ て 量化 レベル を 選ぶ
フル精度 じゃなくても、
エージェント 用途 なら 十分 な こと が 多い

相性 の良い ツール ＆ ライセンス

13

エージェント ツール と 相性 良し

  • Hermes Agent、OpenCode で すぐ 繋がる
  • LM Studio から 手軽に 試せる
  • ローカル エンドポイント を 立てて 運用 しやすい
  • 既存 の エージェント 基盤 に 組み込み やすい
専用 インフラ は 不要。
普段 使ってる ツール に そのまま 接続
14

MIT ライセンス で 緩い

  • 採用 は MIT。使い勝手 が とても 良い
  • Meta 従来 の Llama 系 ライセンス より 制限 が 少ない
  • 商用 利用 の ハードル が 低い
  • 派生 や 改変 も 自由 度 高く
Llama ライセンス の 縛り が 気 に なる 場合、
MIT は 大きな 利点
15

常時起動 ワークフロー 向き

  • 24時間 動かしっぱなし の 常駐 AI
  • 日々 の定型 業務 を 任せる 運用 に 適する
  • ローカル なので 通信 料 が ゼロ
  • データ が 外 に 出ない のも 強み
「置いて おく だけで 動く」
部署 の AI みたいな 使い方 に 最適

ここだけは 押さえよう

16

一般 ベンチマーク は 控えめ

  • 汎用 ベンチマーク の スコア は 高く ない
  • トップ モデル とは 競合 しない 作り
  • 狙い は 実運用 で あって ベンチ ではない
  • 用途 に 合えば 非常に 実用的
ベンチ 数字 で 選ぶ モデル じゃ ない。
動かし続ける ため の モデル です
17

こんな 人 に おすすめ

  • ローカル で 常駐 AI を 作りたい人
  • ツール 呼び出し を 大切 に したい 開発者
  • データ を 外部 に 出したく ない 人
  • Hermes / OpenCode / LM Studio ユーザー
十分 な メモリ を 持つ マシン が ある人 なら、
ぜひ 試す 価値 あり
18

総評：ローカル エージェント の 強力 な 選択肢

  • ベンチ 最強 ではない が、実用 性 で 光る
  • ツール 呼び出し と 障害 回復 の 安心感
  • マルチモーダル で 応用 範囲 が 広い
  • MIT ライセンス で 導入 ハードル 低
  • ローカル で AI を 動かす なら 注目 の 一手
話題 の 数字 より
毎日 の 運用 で 頼れる モデル。
