完成 した 動画の、 文字・数字 を 直したい

完成 したのに、 直したい ことが でる

数字の 書きかえ、 名前の ちがい、 ほか

  • 金額や パーセント が 変わる
  • 登場する 名前 が ちがう
  • 日付や 期日 を 直す
動画は 完成 している。
でも 中身の 1行だけ、 そっくり 入れかえたい。

編集ソフトを 「開き直す」

これまでの お決まり フロー

  • プロジェクトを ひらきなおす
  • 該当シーンを さがして
  • テキストを 書きかえて
  • また 書き出し を 待つ
直すのは 1行 なのに、
まわりの 手間は ぜんぶ やりなおし。

書き出し 待ちの 時間が もったいない

1行の 修正に、 まるまる 待つ

  • レンダリングは 分単位 で かかる
  • ちがう箇所が でれば もう一回
  • そのあいだ 手が とまる
直す 量より 待つ 量の ほうが
おおきい、 ということが おおい。

おなじ 修正が 何度も はねかえる

量産タイプの 動画で とくに

  • 型を つかいまわす 動画
  • 日替わりで 数字だけ 変わる
  • 修正サイクルが くりかえし
一回きり でなく、 何度も
なおす 予定の 動画なら、 なおのこと。
Remotion ／ コードで つくる 動画

コードで 書く 動画制作

React ベースの アプローチ

  • 動画を React コンポーネント で
  • 変数で テキスト を はこべる
  • 型を つくれば 何度でも つかえる
// 動画の 中身は 変数で
<Caption text="{price}" />
動画の 中身が プログラム だから、
文字も 数字も、 あとから 入れかえ られる。

中身を「変数」に しておく

あとで 入れかえる ための じゅんび

  • タイトルを prop で うける
  • 数字も 同じように
  • デザインは そのまま
型 変数 動画
予め 中身を 変数 に。
そこだけ 入れかえれば いい 仕組み。

Studio で プレビュー できる

ブラウザ感覚で 動画を みる

  • 画面で その場に 結果が みえる
  • 書き出しの 待ち時間 なし
  • コードも 同時に 確認
書き出し 待ち なしで、
編集結果が すぐ みえる のが Studio。

Visual Editing の 登場

Studio 上で 直接 いじれる

  • 動画上を クリック で 編集
  • コードを さわらずに 直す
  • 結果が 即座に 反映
編集ソフトを ひらきなおさず、
その場で なおす。 これが Visual Editing。
schemas ／ 入力フォーム を 自動で つくる

schemas で 項目を 定義 する

どんな 入力を うけるか 決める

  • 文字は z.string()
  • 数字は z.number()
  • 色も z.string() で 指定
// schemas で 型を ならべる
{
  title: z.string(),
  price: z.number()
}
入力項目を コードで 宣言。
あとは Remotion が よんで くれる。

入力フォーム が 自動で できる

schemas から フォームが うまれる

  • 定義に あわせ フォーム 生成
  • 手で HTMLを 書かなくて いい
  • 型どおり 項目が ならぶ
title
本日のお値段
price
1,980
schemas を かく だけで、
入力欄 が 自動で できあがる。

フォームに 入力 する だけ

修正は これで おしまい

  • 値を 書きかえる だけ
  • プレビューが すぐ かわる
  • 設計を ひらきなおさない
編集ソフトを 立ち上げず、
フォームに 入れる だけで 直る。

変更 が その場で 反映

Studio の うでまえ

  • 入力 → 即 プレビュー
  • 見た目を その場で 確認
  • 書き出しまで ショートカット
入力 反映 確認
待ち なしで 結果 が みえる。
ここが いちばん うれしい ところ。
