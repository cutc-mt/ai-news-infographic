箱に入れる中身は2種類だけ

SKILL

スキル＝作業手順書

AIに「どう進めるか」を教えるマニュアル

  • 仕事の進め方を文章で書いた 手順書
  • 仕様は Anthropic が 2025年12月 に公開済み
  • 「この順で聞いて」「こう答えて」を指示できる
  • つまり AI が読む how-to 本
メタンスキルは「頭のなかの知識」というわけ。
MCP

MCP＝道具の差し込み口

AIに「何が使えるか」を繋ぐポート

  • 外部ツールを繋ぐ 差し込み口
  • 共通仕様は MCP として既にある
  • DB、API、検索、ファイル操作などを接続
  • つまり AI が使う 道具箱の口
ズン知識と道具。この2つがあれば強いのだ！
POINT

違っていたのは「中身」じゃない

バラバラだったのは器の決まりごと

  • スキルも MCP も 中身は既に共通
  • 置き場所 の決まりがバラバラだった
  • マニフェスト（付札）の書き方が違った
  • 差し込み口の 設定の形 が違った
メタンつまり部品より「付け方」が問題だった、と。

プラグインの正体は「フォルダ1つ」

  • Google が 技術記事 で指摘

  • ズレの原因は 付札（マニフェスト） にあった

ズン札が読めれば、どこでも同じように動くのだ。
STRUCTURE

中身は3つのピースだけ

プラグイン＝シンプルなフォルダ1つ

📁 my-plugin/ ├─ plugin.json # 付札（名前と schema） ├─ 📁 skills/ # 作業手順書を入れる └─ mcp.json # 差し込み口の設定
  • plugin.json：このプラグインの付札
  • skills/：手順書をまとめる場所
  • mcp.json：差し込み口のつなぎ方
plugin.json

付札に書くのは「2行だけ」

驚くほどシンプルな宣言

  • schema：どの仕様に従うかの指定
  • name：プラグインの名前
  • それだけ。他は省いても動く設計
{
  "schema": "https://...",
  "name": "my-plugin"
}
メタン2行で自己紹介。これ以上いらないんだ。

名前と設定の細かい決まり

NAMING

名前の書き方ルール

使える文字が限られている

  • 小文字の英数字 a-z 0-9
  • ハイフン - と ピリオド .
  • 大文字は不可（NG: MyPlugin）
  • ハイフン2連続も不可（NG: a--b）
ズンmy-plugin は OK。My_Plugin は NG なのだ！
LOCAL

MCP設定①：STDIO

自分のパソコンで動かす类型

  • ローカル で直接つなぐ方式
  • プロセスと標準入出力で通信
  • 外部ネットに穴を開けない
  • 手元で動かす分には速い
メタン自分のマシン限定なら、この方式が安全。
REMOTE

MCP設定②：streamable-http

遠くのサーバーとつなぐ类型

  • リモート の URL を指定して接続
  • HTTP越しにストリーミングでやり取り
  • URL設定に ヘッダー を書き込める
  • ただし 秘密情報は書かない こと
メタンAPIキーを直書きすると漏れるから、やめてね。

CAUTION

仕様に「穴」がまだある

認証まわりは要・要警戒

  • 各ツールでバラバラになりがち
  • 秘密情報は 書かない のが鉄則

DESIGN

ミスや事故を、箱の側で防ぐ

  • 部品ごとに 別々に 失敗する設計
  • 1つこけても 道連れゼロ
ズン故障は局所で止まる。賢い設計なのだ！
