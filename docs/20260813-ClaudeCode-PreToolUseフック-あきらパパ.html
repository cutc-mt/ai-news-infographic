「目で追う」から「門番を置く」へ

その名は
PreToolUseフック

実行の「前」にはさむ、監督の層

  • ツールが動く直前に、割り込む
  • そこで、通すか・止めるかを決める
  • AI の上に、もう一段監督の層を重ねる
「門」を一つ、増やすだけ。でも、それが効く
仕組み：どうやって止めるのか

Bashコマンドの
実行前に、スクリプトが走る

門番が、毎回 先に立つ

  • コマンドが動く前に、スクリプトを起動
  • 中身を、じっくり確認
  • 判定は一瞬。人間は、その間知らなくてよい
コマンドが「走る前」だから、手遅れにならない

あぶなかったら、
「deny」で止める

拒否（ディナイ）で、実行をキャンセル

  • 危険な命令なら、deny を返す
  • コマンドは、ここで止まる
  • 理由も 一緒に 伝えられる
DROP TABLE
→ deny
ls -la
→ pass

設定は、hooks の中に
matcher を書く

門番の「担当」を、決める

  • 設定ファイルの hooks セクションに書く
  • matcher で、監視する対象を指定
  • Bash なら、matcher を bash に
「どのツールを、見張るか」を、ここで決める

rm や DROP DATABASE を、
見つけたら止める

止めるだけじゃなく、理由も返す

  • コマンドの文字を、なめて探す
  • rm や DROP DATABASE を見つけたら停止
  • なぜ止めたか、理由をそえる
理由があると、あとでなおしやすい

設定ファイルの
イメージ

だいたい、こんなかんじ

  • hooks の中に、matcher を入れる
  • 止める条件は、スクリプトで書く
settings.json （イメージ）
// 実行前フックの設定
"hooks": {
  "PreToolUse": [{
    "matcher": "bash",
    "command": "./guard.sh"
  }]
}
詳細は公式ドキュメントで。これは概念図だよ
