PRDスキル：
「何を」「なぜ」を定義

要件を エージェントが聞き出す

  • エージェントが ユーザーをインタビュー
  • やりたいことを、引き出して形にする
  • 成果物：PRD（要件の定義書）
「どうやって」は、まだ考えない。目的だけを はっきりさせる

Specスキル：
「どうやって」を設計

PRDとは、べつの会話で

  • アーキテクチャ文書を、まとめる
  • PRDの別会話で実行するのがミソ
  • 構成や技術選定を、ここで固める
会話を分けることで、考えが混ざらない

Slice Epicスキル：
チケットに切り分ける

依存関係まで、いっしょに

  • PRD + Spec から、チケットを生成
  • 依存関係マップ付きで分ける
  • 進める順番まで、ここで見える化

内側ループ：チケットごとに、ぐるぐる回す

内側ループ：
チケット1枚を 仕上げる

時間を、いちばん使う場所

  • ここが、最も時間を費やす場所
  • チケットごとに、計画→実装→検証を回す
  • 1枚仕上げて、次のチケットへ

小さな輪を、何度も回す。それが開発の芯

Primeスキル：
コードベースを、探る

まず、現場を どこまで知るか

  • コードベースを、くまなく探索
  • 必要なコンテキストを、まとめて読み込む
  • エージェントに、現場の把握をさせる
地図を広げてから、作業に入る。これが Prime の役目

Planスキル：
インタビュー式で 計画

テンプレートに、沿っていく

  • エージェントが、質問しながら計画を作る
  • テンプレートベースで、抜けを防ぐ
  • 実装の手順を、文書に落とす
聞かれたことに答えていくだけで、計画が完成

検証ファースト：
テスト戦略を 先に決める

コードより先に、検証の設計

  • コードを書く前に、検証方法を決める
  • いわば、エージェント向け TDD
  • 「できた」の基準を、最初に置く
作ってから考えるのではなく、先にゴールを置く

検証は、幅広く
計画に 組み込む

ユニットから、ブラウザまで

  • ユニットテスト・統合テストを、計画に含める
  • エッジケースも、あらかじめ洗い出す
  • リント・型チェックまで、お任せ
  • さらには、ブラウザ自動化まで
