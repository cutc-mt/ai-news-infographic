デモ前半 — クラスタ から バックエンド まで

Step 1 — GKE クラスタ を 準備

前提 の セットアップ
  • リージョン: US Central1-a
  • Zonal な 3 ノード 構成
  • クラスタ名: flex-unified-cluster1
  • Workload Identity を 有効化
Workload Identity が ある から、 後の 認証 が 楽に なる！

Step 2 — ストレージプール を 作成

プール の 設定
  • サービスレベル: Flex Unified
  • 配置: Zonal 指定
  • 容量: 1024
  • この Pool に 全部の も
1024 初期 容量 (GiB)
この Pool が、 File も Block も 受け皿 に なる！

Step 3 — Trident を Helm で 導入

インストール
  • パッケージ管理 は Helm
  • 認証 は Cloud Identity を 使用
  • trident namespace に 配備
  • CSI オペレーター が 常駐
# Helm で Trident を 導入
helm install trident \
  trident-operator/trident-operator \
  -n trident
Cloud Identity の おかげで 秘密鍵 なし で スッキリ 導入！

デモ中盤 — バックエンド から PVC まで

Step 4 — バックエンド を 2つ 作成

認証 情報 不要
  • ブロック用 バックエンド を 1つ
  • NAS 用 バックエンド を 1つ
  • どちらも 同じ Pool を 参照
  • Cloud Identity で 秘密鍵 なし
1 SAN バックエンド (Block 用)
2 NAS バックエンド (File 用)
認証 を 都度 渡さず、 Identity が よしなに してくれる！

Step 5 — StorageClass を 作成

Kubernetes リソース
  • NAS 用 クラス を 1つ
  • SAN 用 クラス を 1つ
  • SAN は GCNV SAN ドライバー
  • 各 バックエンド に 紐付き
# StorageClass の ドライバー 指定
provisioner: csi.gcnv.com
driver: gcnv-san
StorageClass が、 PVC と Pool を 結ぶ 橋 に なる！

Step 6 — PVC を 2種 作成

Persistent Volume Claim
  • iSCSI 用: RWO モード
  • NFS 用: RWX モード
  • 用途で アクセス方式 を 使い分け
  • Class が 自動で ボリューム を 生成
RWO iSCSI / ReadWriteOnce
vs
RWX NFS / ReadWriteMany
RWO と RWX を、 同じ Pool から 同時に 出せる のが ミソ！

デモ後半 — Pod から スナップショット まで

Step 7 — busybox Pod を 2つ 配備

動作 確認
  • 軽量 イメージ busybox を 使用
  • Pod を 2つ 用意
  • 片方は iSCSI を マウント
  • もう片方は NFS を マウント
小さな Pod で、 両方式 の 動き を 確かめる！

Step 8 — Pod に exec で 確認

検証
  • Pod の 中に 直接 exec
  • ボリューム の 正しい パス
  • サイズ が 要求 どおり
  • 両 Pod で マウント 成功
kubectl exec -it busybox -- \
  df -h /mnt/data
実際に 中を のぞいて、 想定 どおり か を 確かめる！

Step 9 — スナップショット を 取得

VolumeSnapshot
  • 事前に SnapshotClass を 作成
  • NAS ボリューム を 撮影
  • iSCSI ボリューム も 同様
  • 両方 の 時点 を 保存 に 成功
File も Block も、 どちらも スナップショット 可能！

応用 の 機能 と まとめ

Step 10 — 応用 の 機能 も 充実

ここから 広がる
  • Snapshot から 新 PVC を 生成
  • 既存 PVC から クローン
  • 新規 ボリューム の インポート
  • 運用 の 選択肢 が 豊富
Snapshot → 復元
PVC → クローン
外部 → インポート
単なる 接続 じゃ ない。 運用 まで 見えている のが 強み！

判断 の 基準
iSCSI ブロック / RWO
1ノード 専有
⇄
NFS ファイル / RWX
複数ノード 共有
  • RWO なら iSCSI を 選ぶ
  • RWX なら NFS を 選ぶ

アクセス方式 で 道具 を 選ぶ。 それが Flex Unified の 便利さ！
