同じ待ち時間でも、差が出る

終わったか、何度も見に行く

手動で確認する、いつものやり方
  • タスクを投げて待つあいだ、気になって仕方ない
  • 画面を開いては閉じて、また開いて…を繰り返す
  • 作業が手止まり、何度も起こる
  • 「まだかな」が、じわじわ効いてくる
待つ時間は同じでも、こっちの負担がでかい！

変わった瞬間に、向こうから教えてくれる

もう一方のやり方：通知が来る
  • 頼んでおけば、あとは放っておける
  • 状態が変わった瞬間に、通知が届く
  • 来た時だけ、確認すればよい
  • そのあいだ、別の作業に集中できる
同じ時間を待っても、心の消費がぜんぜん違う

違いは「確認するのが自分か、AIか」だけ

本質は、誰が見に行くか
  • 自分で見に行く＝手動確認
  • AI に見に行かせる＝自動監視
  • 待つ時間も、最終的な結果も、同じ
  • ちがうのは手間と、集中の途切れ方だけ
「見に行く係」を、AI に任せられるかどうか。それだけの話
OpenClaw の監視機能とは

条件が変わった時だけ、動く仕組み

監視＝ずっと動き続ける、ではない
  • ふだんは静かに待機している
  • 決まった条件を、定期的に見張る
  • 変化があった瞬間だけ、動き出す
  • だから、余分な負荷がかからない
「見張り番」を AI に立ててもらう、というイメージ

チャットで頼むだけ。設定はいらない

使い方は、とてもシンプル
  • 特別な画面や、複雑な設定は不要
  • ふつうにチャットで、「変わったら教えて」と頼む
  • その一言で、監視が始動する
  • 難しいことは、向こうがやってくれる
監視したいものを、言葉で伝えるだけ！

30秒ごとに、状態を見に行く

監視の周期は、決まっている
  • 頼むと、30秒おきに確認を繰り返す
  • 人間が「そろそろ見よう」と思うより、規則正しい
  • 見に行くのは、一瞬。結果だけを覚えて戻る
  • これより速くはできない（最短＝30秒）

前回と違った時だけ、通知が飛ぶ

変化を検知する、仕組みの中身
  • 前回の状態を、こっそり覚えている
  • 今回と見比べて、違いがあるかを判定
  • 変わっていれば、ここで通知が飛ぶ
  • 変わってなければ、静かに次へ。迷惑なし
つねに「最新」と「前回」を、にらみ合っている
これで、何が変わるか

確認で手を止める回数が、ゼロに

一番の効果は「途切れない集中」
  • 「見に行く」ために、作業を止めることがなくなる
  • ずっと、目の前の作業に集中していられる
  • 来た通知にだけ反応すればいい
  • そのほうが、かえって早く終わる
監視を任せると、自分は「作る側」にいられる

何を監視できるか

対象は、わりと自由
  • ファイルの中身が、変わったかどうか
  • Web ページの表示が、更新されたか
  • コマンドの結果が、前回と違うか
  • 要は「状態」を返せるものなら、なんでも
監視したい状態を、言葉で伝えるだけで OK

頼み方のイメージ

チャットで、こんなふうに伝える
  • 対象を、ひとつ決める
  • 「変わったら教えて」と、添える
  • あとは、通知を待つだけ
// チャット欄に入れる、ひとこと
「build.log の最終行が変わったら、教えて」

// OpenClaw 側の動き（概要）
watch({
  target: "build.log",
  interval: "30s",   // 最短は30秒
  notify: "on-change" // 変化時のみ
})
監視が動くには、事前の有効化が必要（後述）
今日の1歩：まず、1つ頼んでみる

状態を1つ決めて、「変わったら教えて」

小さく始めるのが、コツ
  • 監視したい状態を、1つだけ選ぶ
  • チャットで、「変わったら教えて」と頼む
  • あとは、自分の作業に戻る
  • 通知が来たら、初めて確認する
今日は、たった1つで十分。まず体験する

最初の1ネタ、候補まとめ

何を監視しようか、迷ったら
  • ビルドや処理の完了を待つ
  • 時間のかかるコマンドの、終わりを知りたい
  • ページの更新を、取り逃したくない
  • フォルダに、新しいファイルが増えたか
どれも「自分で見に行く」を、AI に置き換えられる
ここだけ、押さえておきたい注意点

設定で「有効」にして、初めて使える

最初は、オフになっている
  • 標準では、監視は無効
  • 使うには、設定から有効に切り替える
  • 有効にする前は、頼んでも動かない
  • つまり、意図して開けた時だけ動く
いきなり動き出すわけじゃない。まずは自分で ON に

有効にすると、権限は「エージェント」のまま

公式も、ここを警告している
  • 監視で動くコマンドは、エージェントの権限で走る
  • つまり、エージェントに許した範囲が、そのまま適用される
  • 権限を広げすぎると、監視もその分、強くなる
  • 公式ドキュメントで、この点に注意喚起がある
便利さと引き換えに、権限が見えない所で動く。要はそこ

最短の間隔は、30秒

それより速くは、ならない
  • 監視の周期は、30秒が下限
  • これより細かくは、見に行けない
  • 速すぎる変化は、取りこぼす可能性がある
  • 負荷と速さの、バランスをとった値
「即時」じゃない。最大で30秒の、ズレが出る
まとめ：見に行く係を、AI に任せる

役割を、ひとつずつ分ける

人間と AI の、自然な分業
  • 人間：作業する。通知が来たら、確認する
  • AI：30秒ごとに見に行き、変化を伝える
  • おたがい、得意なことだけやる
  • 結果、全体の作業が、スムーズに進む
「見張り」を AI に渡す。それだけで、自分は前に進める

この機能の、3行まとめ

ざっくり、これだけ
  • 1チャットで「変わったら教えて」と頼む
  • 230秒ごとに確認し、変化時だけ通知する
  • 3事前の設定で有効に。権限周りは要確認
これだけ、おさえておけば、とりあえず使える！

今日のねらい：1つ、試してみる

知っているだけでは、変わらない
  • 監視したい状態を、1つだけ決める
  • 「変わったら教えて」と、頼んでみる
  • そのあいだ、お茶でも淹れて待つ
  • 通知が来た時の、あの軽さを味わう
一度体験すると、「手動で見る」に、戻れなくなるかも

覚えておきたい、3つのポイント

便利さと、引き換えにすること
  • 監視は、設定で有効にして初めて動く
  • 動くコマンドは、エージェントの権限のまま
  • 確認の周期は、最短でも30秒
この3つを知っておけば、あとは安心して任せられる
