「再帰的言語モデル」って何？

大きなデータはAIのメモリ外に置いて、必要な部分だけ取り出す。サブエージェントを起動して、答えを持ち帰る設計。

再帰的言語モデル という設計

  • 大きなデータは AIのメモリ外 に配置
  • 必要な部分だけ、その都度 取り出す
  • サブエージェント を起動して、答えを受け取る
「全部覚える」のではなく、
「必要なときに取りに行く」設計。

Hermes とは

  • Nous Research が開発
  • 無料 ／ オープンソース
  • ターミナルで動く、CLI型のエージェント
Nous Research 無料 OSS

Hermes の つながり方

  • OpenRouter 経由で、多数のモデルへ接続

  • チャットアプリにもつなげる、柔軟な設計
クラウドもローカルも、

Web検索 と MCP接続

  • ライブWeb検索 で、最新の情報をその場で取得
  • MCP ツールで、外部のサービスへ接続
  • 情報収集から作業まで、1つの流れでこなす
Web検索 MCP

競合ウォッチャー を毎朝

  • 毎朝 決まった時刻に、自動で起動
  • 競合の投稿を追跡して、動きを把握
  • Vault（共有ノート）に、きれいな要約を投入
起きたらもう、まとめが出来てる。
朝の時間が助かるね。

Vault ＝ 共有ノート

  • 情報をためておく 共有のノート
  • 競合ウォッチャーが、きれいに整形して書き込む
  • 人間もAIも、同じ場所を読める
Vault 共有ノート

核心の違い ＝ 「ノートブック」テスト

学習するエージェントは、どこかにレッスンを書き込む。その「ノートブック」の扱い方に、2つの違いが表れる。

Prime Agent の ノートブック

  • 自分自身のノートブック を持つ
  • 自分で書き、編集し、所有 する
  • レッスンを蓄えて、自分で成長する設計
自己記述型 自前の記憶
まるで日記をつけるように、
AI自身が学びをためていく。

Hermes の ノートブック

  • あなたのノートブック を読む側
  • ノート、Vault、ビジネスの文脈を参照
  • 人間とAIの 共有する記憶 で動く
共有ノート 文脈を読む
人間が書いたものを、
AIが読んで賢く動く設計。

サブエージェント と メモリ管理

  • Prime Agent は サブエージェント を起動して答えを持ち帰る
  • 大きなデータは メモリ外 に置き、必要分だけ取得
  • Hermes は Vault に情報を集約し、文脈として読む
「覚える」方向と、
「読みに行く」方向の違い。

Hermes の 強み

  • Web検索 と MCPで、外の世界に広くつながる
  • 人間と 共有するノート で、文脈を読む
  • 毎朝の 自動まとめ など、実務寄りの設計
接続の広さ 文脈共有
