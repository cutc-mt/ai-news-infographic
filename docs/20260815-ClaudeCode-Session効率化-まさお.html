Claude Code のセッションを、うまく使うコツ

Anthropic 公式ブログ「セッションの価値を最大にする」を深掘り
2026年8月15日 | まさおAIじっくり解説ch
01

公式ブログが登場

今回のネタ
  • Anthropic 公式が ブログでガイドを公開
  • テーマは Claude Code のセッション管理
  • 低コストで高性能なモデルが増え、使い方を見直す時期に
モデルが強くなった今、
「任せっぱなしでOK」から
「コスパ良く使う」へ流れが変化！
02

ねだんは「かけ算」

コストの式
  • 単価= どのモデルか + キャッシュの効き
  • 量= ターン数 + 載せる情報 + 探す手間
  • この かけ算でねだんが決まる
# コストの直感的な式
コスト = 単価 × 量
単価   = モデル × キャッシュ効率
量     = ターン × コンテキスト
03

単価をきめる2つ

見るところ
  • 使うモデル: Opus Sonnet Haiku
  • キャッシュが効いているかどうか
  • この2つを下げれば 単価が下がる
モデルの見た目の価格は
1Mトークンあたり 入力 $1 / 出力 $5。
でも実態はもう少し複雑…！
04

量をきめる3つ

増える要因
  • 何ターン続けたか（40ターン=39ターン分を読み直す）
  • コンテキストに何を載せるか
  • ファイル探しをさせたかどうか
ターンが伸びると、
キャッシュが効いていても
読み直しの分はちゃんとかかる！
05

書く方が高い

なぜ出力が高い？
  • 入力は まとめて渡すだけ（システムプロンプト + CLAUDE.md + 履歴）
  • 出力は 1トークンごとに GPU を1往復
  • だから $1 vs $5 の差がつく
「読ませるより、書かせる方が高い」
これ、直感的で大事な考え方！
06

モデルと effort

使い分けのコツ
  • ギリギリの探索は フルモデル × xhigh で
  • 型が決まった作業は Sonnet ぐらいで十分
  • Opus 5 は low / mid / high / xhigh で token 数が変わる
  • スキルの YAML フロントマターでも effort を調整
07

常に最大にしない

やめたい習慣
  • 何でもかんでも 最強設定にしない
  • 思考が不要な作業は シンキングを切る手も
  • タスクや定期じょうむに合うかで選ぶ
# 思考（シンキング）を切る例
MAX_THINKING_TOKENS=0
08

キャッシュの寿命

効く時間
  • API キーなら 5分だけ有効
  • サブスクなら 1時間もつ
  • API でも設定で 1時間へ伸ばせる
# キャッシュ寿命を1時間に
ENABLE_PROMPT_CACHING=1H
キャッシュが切れると
同じ内容でもう一回
しっかり課金されちゃう！
09

キャッシュが消える時

注意する4場面
  • 放置しすぎて寿命が切れる
  • /compact で会話の中身を書き換える
  • フックス系の設定をいじる
  • 途中でモデルやモードを変える
だから最初のうちに
モデルと effort を
決めておくのが正解！
10

/rewind と /compact

たすかる命令
  • /rewind（Esc を2回）は後ろを切るだけ
  • 前に積んだ分は残るので キャッシュにやさしい
  • /compact も効率的。何を捨てるか確認を
> /rewind   # Esc ×2 でもOK
> /compact  # 会話を畳む
11

/context で点検

見えるもの
  • 1Mトークンの使いみちが見える
  • システムプロンプト・メモリーファイル・スキルの中身
  • 使っていない MCP やスキルを外す
> /context
# 何が載っているか定期点検！
12

のせすぎ注意

見直す対象
  • CLAUDE.md の内容
  • MCP の接続しすぎ
  • スキルの登録しすぎ
  • 過剰な設定は 量を増やす原因
とても基礎的な話だけど、
あなどれない効き目！
積み上げすぎはよくある失敗。
13

@でファイル指定

える効果
  • 「このファイルを探して」の探す手間が消える
  • @マンクションで対象を明示
  • 画面と向き合う場面で特に有効
# 探索コストをゼロにする
> @src/app.ts の不具合を直して
14

長い出力の危険

コンテキストの汚れ
  • 3万字超の出力はファイルに退避、会話には短いプレビューのみ
  • でも中途半端な長さだと会話に入り込む
  • そもそも不要な出力を出さない工夫が大事
かえって巨大な出力の方が
安全だったりするんだから
おもしろい話！
15

こまめに切る習慣

切り方
  • /clear で気持ち新たに
  • まさお式: Ctrl+C を2回でセッション終了
  • 目的を達したら切るのがいちばん
  • 1タスクずつ細かく分ける
> /clear
# または Ctrl+C を2回押す
16

サブエージェント活用

いいところ
  • これまでの会話を渡さないので軽い
  • token を大量に出すけど手元に残さない仕事に最適
  • ループをメインで回すと、コンテキストを抱えたまま繰り返す
  • 簡単な作業は Haiku や Sonnet、Opus を low で
マルチエージェントの
指揮まかせもおすすめ！
重い処理は別腹に切り出そう。
17

自動で畳む機能

新しい仕組み
  • auto-compact が token 数と一緒に表示される
  • 200K など、しきい値を決めて自動で畳む
  • 時間を置いて古いセッションに戻る時は注意
# 自動で畳むサイズの指定例
auto-compact: 200K
18

取り組む順番ベスト4（公式のまとめ）

  • 長いセッションを切る（/clear、Ctrl+C ×2）— キャッシュが効いていても、読み直しの分はかかる。まずここから！
  • コンテキストに載せすぎない — /context でこまめに点検。使わない MCP やスキルは外す
  • モデルと effort を最適に — いつも最強設定ではなく、Opus を low で / Sonnet / Haiku と使い分ける
  • キャッシュを壊さない — 途中でモデルやモードを変えない。画面と向き合う場面で特に意識
どれも基礎的なことばかり。
でも低コストで強いモデルが増えた今、
この見直しの価値はますます上がる！
まず /clear から 点検は /context 迷ったら軽いモデル
