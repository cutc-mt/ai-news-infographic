はじめに − この動画のテーマ

#01

フォルダ設計が命

  • この概念を理解していない人が意外と多い
  • フォルダの階層が変われば、返ってくる回答もぜんぜん違う
  • 同じプロンプトでも環境で差がつく
「私、大丈夫かな?」と気になったから撮った一本です!
#02

Web版との違い

  • WebのクロードやChatGPT、コパイロットはブラウザ上で動く
  • ClaudeCodeはみんなのPC上で動く
  • だからこそ「どこで開くか」が大事
フォルダの階層とファイル名を整えると、クロードコードが検索しやすくなる!
#03

CLAUDE.mdとは

  • 起動時に毎回かならず読む指示ファイル
  • それがフォルダごとに設定できる
  • 階層を整えておかないと全然いうことを聞かない
# フォルダごとに置ける指示書
CLAUDE.md  ← 起動時に毎回読む
スキル / MCP もフォルダに入る
#04

講師の実績

  • 個人：約6,000人にクロードコードを指導
  • 法人：何十社の導入を支援
  • 最初はこの概念がない人が多かった
だから今回、体系的にやさしく説明します!
#05

レベル1〜7の土台

  • フォルダ設計はいちばん基礎のレベル1
  • その上にレベル2〜7（スキル、MCP、サブエージェント、自動化・観測まで）
  • 好評なら全7回のシリーズ化予定
これを知ればクロードコードの力をフルに使えます!
#06

ハーネス＝環境づくり

  • クロードコードはモデル以外にも仕組みがたくさん
  • 基本モデルはみんな同じ
  • なのに環境のせいで性能は2〜3割しか出ていない人が多い
  • 目標は7〜8割、できれば100%近く引き出すこと
#07

ハーネスの中身

  • CLAUDE.md … いつも読む指示
  • スキル / MCP … フォルダの基本構成
  • 全体のハーネス＋フォルダ1個1個にも環境づくりが必要
クロードコードは考えることが10倍・20倍多い分、環境を整えれば自分好みの回答が返ってくる!
#08

なぜ差がつくのか

  • 同じプロンプトでも環境（かんきょう）で結果が変わる
  • 理由はハーネスが整っているかどうか
  • 使い倒している人ほど環境づくりに差がある
「使い方」より先に「環境」だった、ということ!

ここが大事 − しくみと工夫

#09

起点（きてん）フォルダ

  • 起動時に選ぶフォルダが起点。ここからいろいろ動きはじめる
  • デスクトップアプリの「＋」で追加もできるが、追加した先は起点ではない
  • 起点からCLAUDE.mdがしっかり読まれる
まずは「起点が大切」ということだけ覚えて!
#10

コンテキスト窓

  • AIが1回で読める容量は上限が決まっている
  • 例：100万トークンのうち20万を使っている状態
  • 100万トークン≒日本語で80〜90万文字くらい
  • 窓が圧迫されるとどんどん性能が落ちる
#11

作業机のたとえ

  • コンテキスト窓＝あなたの作業机
  • 階層が深すぎたり、MDが雑だと1文字打つ前から机が散らかっている
  • だからフォルダ階層とCLAUDE.mdをいっしょに整理
机がきれいだと、その分AIの頭の容量が増えるんです!
#12

1セッション1案件

  • セッションを分ければコンテキストは0からやり直し
  • タスクごとに分けて、むだ使いを防ぐ
  • サイドバーをグループ：フォルダー表示に（基本はローカルでOK）
# ざっくり手順
動画の回収 → 専用フォルダを新規作成
セッションを分けて別々のタスクを依頼
#13

上から読むしくみ

  • CLAUDE.mdは親→子→孫と上から読まれる
  • だから親の階層（会社・ワーク単位）がとても大事
  • ぐちゃぐちゃにするとせっかくのMDが意味をなくす
  • 置き場所は全体にも・個別フォルダにも置ける
ChatGPTでいうシステムプロンプトを、フォルダ単位で細かく設定できるイメージ。講師はMDを合計300個くらい持っています!
#14

名前で探す仕組み

  • PC全体を検索するときまず名前で当てて、それから中身
  • だからフォルダ名とファイル名が実質すべて
  • 講師の流儀：番号 + 会議/提案 + 日付で命名
# NG例 / 講師の例
× 資料1.pptx
○ 01_会議_提案_20260815.md
#15

自動メモリ機能

  • CLAUDE.md以外に記憶を自動で残してくれる仕組みがある
  • そのメモリもフォルダごとに分かれる
  • 詳細はレベル2以降（スキル・MCP・サブエージェント）で学ぶ
使いながらなんとなくつかめてきます!
#16

4本柱のワークスペース

  • 開発 ・ ワーク（仕事）
  • コンテンツ ・ アーカイブ の4本柱が目安
  • クロードは散らかりやすい。週に1回くらいのペースで整理
  • 最適な階層は日本語で相談すれば全部作ってくれる
workspace/
├─ dev/      # 開発
├─ work/     # 仕事
├─ contents/ # コンテンツ
└─ archive/  # アーカイブ
#17

案件フォルダの実例

  • お客様ごとにフォルダとMDを分ける（A社・B社・C社…）
  • MDには担当者 / サービス / 状態 / 案件の概要 / ゴール
  • 複数社でもMDの型は統一すると使いやすい
clients/A社/
├─ CLAUDE.md   # 案件の概要・ゴール
├─ contract/  # 契約かんけい
├─ deliver/   # 納品物
└─ assets/    # 素材
#18

今日からやる手順

  • 現在のフォルダを図にしてもらい、散らかっている点を指摘してもらう
  • 4本柱を作り、顧客フォルダを標準構成に
  • やらないことも決める：深い階層を作らない・成果物と一時ファイルを混ぜない・ルート直に置かない
  • 破壊的な変更の前にはプランとメリットを確認。定期的に見直しを!
コピペだけでは身につきません。今日の話をベースに自分のプロンプトを作ってこそ、クロードコード力が上がります!
