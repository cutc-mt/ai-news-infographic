Cloud Network Insights

〜クラウドの外まで、ネットワークの「見える化」〜 Cross-Cloud Network のエンドツーエンド可観測性
2026年8月14日公開  |  Google Cloud Tech  |  ネットワーク運用
1

Cloud Network Insights とは?

  • Google Cloud の新しいネットワーク可観測ソリューション
  • 監視の範囲が Google Cloud の外まで広がる
  • 世界中にひろがるグローバル展開まるごとカバー
  • 通信の流れをくわしく見える化
クラウドの中だけじゃなく、外のネットワークまで見られるのが大きな特徴だよ!
2

Broadcom AppNeta との提携

  • Broadcom AppNetaとのパートナーシップで実現
  • Google Cloud の機能とAppNeta の技術を融合
  • 強みと強みを組み合わせたかたち
  • Google Cloud 側: Cross-Cloud Network
  • AppNeta 側: 合成プロービングのノウハウ
大手ネットワーク監視ベンダーとの協業でできた注目ソリューション!
3

アクティブ合成プロービングとは?

  • active synthetic probing = 自分で計測パケットを送る方式
  • ダミーの通信を定期的に送信して経路をチェック
  • 遅延やパケットロスを常時計測
  • 結果をデータとして可視化
「合成」= 本物のユーザー通信じゃなく、試験用につくった通信ということだね
4

トラフィックがなくても監視

  • 従来: ユーザー通信がないと様子がわからない
  • 今回: 通信がゼロの時間帯でもルート監視が継続
  • 深夜や休日もずっと見張り
  • 障害の予兆を逃さない
「誰も使ってない時間」に静かに壊れてても、気づけるのがえらい!
5

Cross-Cloud Network とは

  • 複数クラウドをつなぐ Cross-Cloud Network
  • マルチクラウド・ハイブリッドを横断する仕組み
  • 拠点からクラウドまで一つの経路網に
→ → →
この大きなネットワークの全体像を、ひとつの画面で見られるようにしよう、という話
6

エンドツーエンド可観測性

  • end-to-end = 端から端までまるごと
  • 見えるのはクラウド内だけじゃない
  • 全体の経路を地図みたいに把握
  • どこが遅いか数値で確認
「可観測性(オブザーバビリティ)」とは、いまの状態を外から見てわかるようにすること
7

クラウド内のボトルネック

  • 遅れの原因がクラウド側にあるケース
  • VPC やロードバランサーの設定ミス
  • 帯域のひっ迫による輻輳
  • Insights が発生場所を特定
「なんか遅い」ではなく、どこで・なにが悪いかをはっきり指摘してくれる
8

オンプレデータセンターも対象

  • 自社のオンプレ環境も監視範囲に
  • データセンターの出口から計測
  • ハイブリッド構成のつなぎ目をチェック
  • クラウド移行中の環境も安心
オンプレ⇔クラウドの境界こそ、トラブルが起きやすい場所なんだ
9

インターネットアプリの監視

  • 外部のWeb アプリ・SaaSへの経路も計測
  • EC サイトや API の到達性を確認
  • 他社サービスとの接続品質も把握
自社じゃないサービスとのつながりも、ちゃんと見えるのがうれしい
10

ISP の問題も切り分け

  • ISP(プロバイダー)区間の劣化を検出
  • 「うちのせい?」を切り分け
  • 根拠データで ISP に問い合わせ可能
「プロバイダーが悪い気がする…」を証拠つきで言えるようになる!
11

ラストマイルの見える化

  • ラストマイル = 利用者直前の最後の区間
  • オフィスや自宅の回線品質を計測
  • 「端末のせい? 回線のせい?」を判別
  • 会議がカクつく原因のあたりをつけられる
最後の一区間、実はもっとも疑わしい場所だったりする…
12

プロアクティブな運用へ

  • リアクティブ: 障害後に駆けつける従来型
  • プロアクティブ: 起きる前に先回り
  • 劣化の予兆をとらえて早めに対処
  • 夜間の原因調査が不要に
「泣いてから直す」より「壊れる前になおす」。運用チームの未来が明るい!
13

ネットワークルートの可視化

  • パケットの通る道筋を地図で表示
  • 経由するノードをひとつずつ確認
  • 平常時との差分にすぐ気づける
拠点A ──▶ ISP ──▶ エッジ ──▶ VPC ──▶ アプリ
  3ms      12ms      ▲遅延増!     4ms     2ms
どこで遅延が増えたか、経路ごとに見える化!
14

劣化の原因をピンポイント特定

  • 問題:「アプリが遅い」でも原因不明になりがち
  • 疑われる場所は5つ:
  • ① クラウド  ② オンプレ
  • ③ インターネットアプリ  ④ ISP
  • ⑤ ラストマイル
  • Insights がボトルネックの正確な場所を提示
実際の動画でも、この5つの切り分けが主役の話でした
15

グローバル展開をまるごと

  • 海外拠点との接続も一括監視
  • 「あなたのグローバル展開全体」へ拡張
  • 時差のある拠点も24時間カバー
🌏 🌍
世界中の拠点を、本社の画面からひと目でチェック!
16

運用チームへのメリット

  • 原因調査の時間が短縮
  • データ裏付けで報告・連絡が楽に
  • 深夜対応の負担軽減
  • ネットワーク品質の継続改善へ
「どこが悪いかわからない」ストレスから、おさらばしよう ☕
17

こんな場面で活きる

  • リモートワークの回線品質チェック
  • 支社・ブランチとの専用線代替検証
  • オンプレからクラウドへの移行判断
  • ヘルプデスクの一次切り分け高速化
「なんか遅いんです」の問い合わせに、即答できる未来!
