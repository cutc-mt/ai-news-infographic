Gemini 3.7 Flashとは

  • 前回は 3.6 、Pro版は 3.1 のまま

  • Proがなかなか来ないので、まず Flash が先にリリース
  • 良いところと悪いところがはっきり分かれるモデル
いいところだけを使えれば、
とても便利なモデルだよ！

基本の使い方ルール

使っちゃダメな「頭」

  • 検索 や 思考 を任せるとハルシネーションが出る

得意な「手足・目」

  • マルチモーダル がとても強い
  • 作業の手足として使うのは優秀
  • ただし バランスが悪い ので注意
頭はダメ、手足と目は得意

  • その中でも突出して安い「安さ勝負」モデル

  • 動画のサムネや図解も 3.7 で作成

  • SVG部門では 他モデルより上手い

最大の注意：ハルシネーション

  • 検索をやらせると ハルシネーション がバンバン出る
  • 実在する記事を 「虚偽」「捏造」 と判定
  • 「全て架空のフィクション」と断言してしまう
  • この性格なので 仕事では使えない との判断
検索やファクトチェックは
このモデルに任せちゃダメ！

検証：他モデルとの比較

  • Flash Lite ：全て事実と誤って判定（間違いを見抜けない）
  • 3.7 ：「虚偽」「捏造」とハルシネーション
  • 3.7拡張モード ：やはり「架空」「SF」と断定
  • Temer / Sonnet 5 / Musespark ：正しくファクトチェックできた
同じ文章・同じプロンプトでも
結果はモデルで真っ二つ！

ファクトチェック最強は？

  • 今いちばん強いのは GPT-5.6 Sol と判断
  • 「ここは合っていて、ここは間違い」をきちんと示す
  • 微妙な違いを出せるのは Sol > Claude
  • 普段の仕事でも Sol を使っている
調べて確かめたい仕事は
Solに任せるのが安心！

Proならちゃんと分かる

  • 同じ検証を Gemini 3.1 Pro でやると正しい
  • 番号に惑わされてはいけない
  • 「頭がいる仕事」は Pro をしっかり使う
  • Pro は推論が入り時間がかかるが、そのぶん正確
速くても間違っては意味がない
ゆっくりでも正確なProを使おう

なぜ起きる？失敗のしくみ

  • 「アストラ」という名前に アンカリング して全体を誤った判定に
  • Google DeepMindの Project Astra と混同
  • 長文を分けずに まるごとフェイクと判定
  • 情報の新しさを扱えず 内部の知識を優先
  • 「検索した」と言って 検索していない ことも
実在の事件を「存在しない」と
もっともらしい理由で否定しちゃう…

Solによる能力の診断

  • ブラウジング・探し出す力 は弱い
  • 検索ベンチは すべて弱い
  • 文章づくりの力 は強く、文章は整っていて人を納得させる力あり
  • 結論：「知識と文章づくりはあるが、検索エージェントとしての力が弱い」
他のAIに診断させると
弱点がはっきり見えてくる！

失敗の4つの原因

  • 最新の情報なのに内部の知識を信用（いちばん重大）
  • 一次の資料に 届いていない
  • 早く結論を出し 自分でひっくり返せない
  • 名前への アンカリング で誤りに固定

4つが重なって大きな失敗に

  • 結論をひっくり返せない＝レビューができない（コーディングでも弱点）
4つの原因を組み合わせると
失敗の構造が見えてくる！

コーディング使い分け判断

  • 純粋なコーディング → 心配なし
  • テスト付きの開発 → 問題が出にくい
  • 未知の巨大コードベース調査 → 微妙
  • 最新ドキュメント調査・ウェブ調査＋セキュリティ分析＋コード修正 → 深刻な問題
  • 普段は Claude Code / Codex を使用。3.7は SVGや小さなコード 向き
他AIが計画して、3.7が実装
なら理にかなった使い方という判断！

  • それ以外は とても良いサービス
