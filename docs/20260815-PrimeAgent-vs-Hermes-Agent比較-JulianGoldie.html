Prime Agent vs. Hermes Agent

ラウンド1：問題の正体 — 「頭」の限界

いつものAIの動き方

基本の仕組み
  • ドキュメントを渡すと 頭に詰め込む
  • その「頭」が context window（文脈窓）だ
  • 頭のサイズには 上限 がある
「あなたが使ってきた あらゆるAI」は みんなこの方式、というのが動画の出発点だよ！

頭がいっぱいになったら

起きることは2つ
  • パターンA：拒否 する（もう読めない！）
  • パターンB：細部を ひそかに忘れる（静かな忘却）
  • 怖いのはB。エラーも出ず 気づきにくい
拒否される方が まだマシ。こっそり忘れる方が デキてる顔して危ないんだ…

だから Hermes agent は…

忘れっぽいワケ
  • 資料を読み込む → context window に積み上げる
  • 限界を超えると 細部を忘れる ことが多い
  • 動画の結論：all the time（しょっちゅう）だ
能力不足じゃなく 設計の問題。頭に詰め込む方式そのものが限界を抱えてる…！

「窓」の中身を解剖

context window の素性
  • モデルが「いま見える」範囲＝ 作業机 のようなもの
  • 会話・資料・指示が 全部ここ に積まれる
  • 溢れた分は 机から落ちる＝忘却のもと
机が広いモデルほど多く持てる。でも机は 有限。積みすぎたら こぼれるのが運命…！
ラウンド2：Prime Agent の回答 — 「詰め込まない」

ファイルを「読まない」

発想の転換
  • ファイルを頭に取り込む 非・採用
  • ファイル群を 横断して動く 小さなプログラムを書く
  • 覚えるのではなく コードで調べる
「暗記」から「検索」へ。頭のサイズと サイコロ的に切り離すのが ミソだよ！

永続 Python ワークスペース

エンジンの心臓部
  • エンジン全体が たった1つの中心 に据えられる
  • それは persistent Python workspace
  • タスク全体を通じて 生き続ける ライブな環境
# イメージ
workspace = PersistentPython()
# セッション中 ずっと生存
workspace.alive == True
消えては 作り直し、を繰り返さない。火を絶やさないのが エンジンの役目！

「唯一の道具」に限定

他と違う部分はココ
  • ワークスペースが モデルの唯一のツール
  • 脱出ハッチも 別ルートも無し の一本道
  • 設計がシンプル → 一貫性 を保てる
「ここが 他のすべてと違う点」と 動画でも強調されてた部分！
ラウンド3：そのワークスペース、何でもやる

読む・探す

基本の2つ
  • reading files（ファイル読み取り）
  • searching（検索）
  • 必要な時だけ・必要な分だけ 取りに行く
頭に貯め込まず、都度 コードで取得。だから窓が パンパンにならない！

コマンドを実行

動いて確かめる
  • running commands（コマンド実行）
  • 書いたコードを その場で試験
  • 結果を見て 書き直し も自由
# ワークスペースの中で
$ python analyze.py
$ grep -r "TODO" ./docs
試して・直して・また試す。この循環が ずっと回り続けるのが ワークスペースの強み！

「小さく書く」理由

small programs の妙
  • プログラムは 小さく分ける ほど確実に動く
  • 書いたものは 再利用できる（二度忘れない）
  • 壊れたら その部品だけ直す 済む
一度コードにすれば 記憶は「成果物」になる。成果物は 窓が溢れても消えない！

外の世界・助っ人まで

範囲は広い
  • 外部サービス呼び出し もこの窓口から
  • なんと ヘルプ代理人を雇う ことまで
  • 全部 1つのワークスペース経由 に統一
読む・探す・実行・外部呼び出し・仲間を雇う —— すべてが コードを書くこと、でまかなえる！
ラウンド4：まっすぐ比較 — どっちが強い？

Hermes 型：詰め込み方式

特徴チェック
  • 資料は 頭へ直行
  • 上限は 窓のサイズ次第
  • 超過 → 拒否 or 静かな忘却
窓を大きくする改良は できるけど、「大きくすればするほど コストと悩みも増える」のが お約束…

Prime 型：巡回方式

特徴チェック
  • 小さな プログラムを書く だけ
  • ファイル群を 横断して実行
  • 頭は 軽いまま をキープ
「覚える量」ではなく 「調べ方を用意する」発想。対象が巨大でも 平気！

記憶の置き場所

どこに置く？
  • Hermes 型：記憶は モデルの頭の中
  • Prime 型：記憶は 外のワークスペース
  • 「頭でがんばる」vs 「外に任せる」
人間がメモを取るのと おんなじ理屈。手帳があるから 頭は楽になれるんだ！
ラウンド5：結果 — 集中力と一貫性

集中力を保つ

この設計の効果
  • モデルが 集中力 を維持できる
  • 他のエージェントに見られる 忘却を回避
  • タスクの最初から最後まで 一貫
短いショート動画だけど、主張は とても明快。「詰め込まない設計」が答え、だ！

セッションをまたぐ生存

「ずっと生きてる」意味
  • ライブ環境が タスク全体 を通じて生存
  • 変数・関数・結果が 消えずに残る
  • 前の工程を やり直さない で積み上げられる
# 仕事の積み重ね
ws.run(step1)  # 結果は残る
ws.run(step2)  # step1を活用
ws.run(step3)  # さらに活用
最初の一回だけ がんばれば、あとは 積み上げるだけ。忘れる幕がない！

忘却回避の勝因

なぜ勝てるのか
  • 必要な情報だけ その都度 引っ張る
  • 状態は 外の環境 が丸ごと保持
  • モデルは 考える専業 に専念できる
将棋で言えば「盤面を覚える」んじゃなく 盤面そのものが残る設計。そりゃ強いはず…！

この動画の受け取り方

まとめの3点
  • 忘却の原因は 詰め込み設計 そのもの
  • 解決策は 永続ワークスペース 一択の設計
  • 道具が1つ → 集中と一貫 が手に入る
AI選びの新しい物差し、「そのAIは 覚えようとする？ それとも 書いて調べる？」をチェック！
