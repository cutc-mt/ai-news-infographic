Codex テスト修正の型

ログを貼るだけにとどめず、「何が成功か」まで渡すと、修正に入りやすくなる

2026年8月16日公開の動画より / あきらパパ

Codex AI活用 ChatGPT 仕事効率化
まずはきほん — Codex とテスト修正
#01

Codex とは

今日の主役の道具

  • 開発作業を任せられる、OpenAI のコーディングAI
  • コードを読んで、直すところを見つけてくれる
  • ターミナル越しに、修正を依頼できる
  • 使い方は公式マニュアルにまとまっている
「話しかけて直す」のが
Codex のやりかた!
#02

今日のお題: テストが通らない

開発あるあるの場面

  • 書いたコードのテストが赤くひかる
  • 原因をさがして、こつこつ直す日々
  • この直し方の型を今日は紹介
赤いログを見ると、ちょっと憂うつ…
#03

いつものやり方

ログだけを貼るパターン

  • 失敗したログを Codex にそのまま貼る
  • 「これを直して」とだけ頼む
  • 動くけれど、行き来が増えがち
# いつもの依頼
このログを直してください。
#04

ログだけだと起こること

ゴールが見えないまま進む

  • どこまで直せばいいか、わからなくなる
  • 直す範囲が定まらず、余計な変更が入ることも
  • 「まだ直らない」「やりすぎた」の往復
  • 結果、修正に入るまでに時間がかかる
ログは「症状」であって
「ゴール」じゃない!
カギは「何が成功か」
#05

成功の姿を渡す

ダメな原因 + 目指すゴール

  • ログ: 何がダメかを伝える
  • 成功の姿: 何が成功かまで渡す
  • 「直して」ではなく「ここに到達して」と注文
  • ゴールが見えると、修正の切り口が定まる
ひとこと添えるだけで、
たしかに届きやすくなる!
#06

なぜ修正に入りやすい?

ゴールから逆算できる

  • めざす場所が決まれば、逆算で進める
  • 直す範囲を AI 側でしぼりやすい
  • 人間も AI も、同じ基準でチェックできる
  • むだなやりとりがへって、早く完了へ
#07

期待する動きを書く

「こう動けばOK」の姿

  • 成功したときの様子を、言葉にしておく
  • 画面の表示、返ってくる値、消えるエラーなど
  • あいまいな「いい感じに」はやめて、具体的に
# 期待する動き(書き方の例)
- ログインすると一覧の画面へとぶ
- エラーの文言は表示されない
#08

完了条件を共有する

ゴールの見える化

  • npm test が通ったら完了のように決める
  • 判断の基準がはっきりして、もめない
  • 人間の確認は、最後の一押しで済む
  • やり直しのループが短くなる
ゴールが共通認識になれば、
あとは走るだけ!
三ステップの手順
#09

今日試すこと

流れは三ステップだけ

  • 1. 失敗ログを貼る
  • 2. 期待する動きを書く
  • 3. 最後に走らせる確認コマンドを書く
準備はこれだけ。あとは Codex に任せる!
#10

ステップ1: 失敗ログを貼る

材料はそのまま全部

  • エラーの文言や流れを、そのまま貼る
  • 手で削らず、全文を渡すのがこつ
  • 原因をさがす手がかりが、ログにそろう
# 失敗ログの例
$ npm test
✖ /login は 200 を返すはず
  Expected: 200
  Received: 500
#11

ステップ2: 期待する動きを書く

成功の姿を一文で

  • ログの下に、期待結果をそえて書く
  • 「〜になれば正しい」という形にする
  • 具体的なほど、AI の狙いが定まる
# 期待結果のそえ方
期待結果はこれです。
→ ログイン後、一覧へとぶこと
#12

ステップ3: 確認コマンドを書く

完了の合図を決める

  • 最後に走らせるコマンドを明記する
  • これが通れば完了、という合図になる
  • 動画の例では npm test を指定
# 完了条件
$ npm test
→ すべて通ったら完了
#13

プロンプト例(まるごと)

三ステップを重ねた依頼文

  • ログ・期待結果・確認コマンドの三つそろい
  • シンプルだけど、必要な情報がそろう
# 動画に出てきた例文
このログを直してください。
期待結果はこれです。
npm test が通ったら完了です。
この三行、そのままコピペでOK!
#14

完了の判断は npm test に

機械に判定をゆだねる

  • 修正が終わったら、確認コマンドを実行
  • テストが通れば、めでたく完了
  • 通わなければ、ログをそえてもう一案
# 完了のイメージ
$ npm test
✓ 12 passed
→ 完了!
安全にはしるために
#15

sandboxing とは

隔離された環境で動かす

  • AI を sandbox とよばれる箱のなかで動かす仕組み
  • まわりのファイルや設定を守りながら使う
  • 動画のもう一つの出典は、このsandboxing のドキュメント
安心して任せるための、土台となるしくみ!
#16

sandboxing で守れること

枠のなかで自由に

  • ネットやファイルへのアクセスを制限
  • まちがって本番をさわるリスクをへらす
  • 自動修正を安心して任せられる下地になる
# ざっくりイメージ
Codex の作業場所 = 隔離された sandbox
外の世界には、えいきょうが及びにくい
#17

人間が確認する条件

大事な判断は人がもつ

  • 危険な操作は、必ず人の目で確認
  • 本番データの扱いも、人間が判断
  • 自動化は「安全な範囲」までがお約束
任せるほど楽でも、
ふみ込む前には ひと呼吸!
