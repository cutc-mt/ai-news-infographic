CLAUDE.mdとは何か

  • Claude Codeが毎回よむ 設定メモ のファイル
  • セットアップ講座の第2回、テーマは L2＝記憶
  • 公式ドキュメントにある「最初に読むファイル」
  • 会話をまたいで 文脈 を渡す役割
書いていないなら、はっきり言って意味がない！——それくらい大事な一枚です。

「.md」って何？

  • .md は Markdown ファイルの拡張子
  • 「# 見出し」「- リスト」などの軽い記法
  • 中身はただのテキスト。特別なツールは不要
  • Claude Codeは起動時にこれを読みに行く
# このプロジェクトのルール
- 返信は日本語で
- テストを通してから提案する
プログラムじゃなくて、メモを書く感覚でOK！

置く場所のきまり

  • ルート直下 → そのプロジェクト 全体 に効く
  • ~/.claude/CLAUDE.md → すべてのプロジェクトで読まれる
  • サブフォルダ → その中で作業するときだけ読まれる
  • 上の階層ぶんも さかのぼって読む
project/
├── CLAUDE.md   ← まずここ
├── src/
│   └── CLAUDE.md ← この中だけ
└── ~/.claude/CLAUDE.md ← 全体に効く
置き場所で、効く範囲が変わる！

いつ読み込まれるか

  • Claude Codeの 起動時 に自動で読み込まれる
  • 追加の指示はいっさい不要
  • 毎回よみ直すので、直したら次から反映
  • @import で別ファイルも取り込める

@import ./docs/rules.md
「毎回・自動」がこの仕組みの核心！

記憶は2種類ある

CLAUDE.md ＝ 手で書く固定の記憶あなたが書いたルールがそのまま載る
両方いきる
自動メモリ ＝ AIが育てる学習の記憶Claudeが会話から学んで書き足す
  • どちらも起動時に読み込まれる
  • 似ているので混同されがち
手で書く記憶と、AIが育てる記憶！

自動メモリとは

  • 会話から学んで、Claudeが 自分で書き足す
  • 既定でON。設定はいっさい不要
  • ~/.claude/ 以下にファイルで残る
  • 「覚えておいて」と頼まなくてよい場面も
# 保存される場所の例
~/.claude/
└── （学んだ内容がここに蓄積）
気づいたら賢くなってる、静かな相棒！

2つの使い分け

CLAUDE.md に書くもの変えたくないルール・好み・よく使うコマンド
自動メモリに任せるもの触って学んだ事実・環境のくせ・発見
  • 変えたいルールは、自分の手で書く
  • 学んだことはAIに任せて、併用 がいちばん効く
固定と学習、役割を分けるのがカギ！

ふとった時の悩み

  • 読み込むたびに文字数（トークン）を消費
  • 大事な指示が埋もれて、目立たなくなる
  • 注意が散って、逆に効率がさがる
  • ふくらむ原因：長い経緯 重複ルール 使わない情報
「全部書きがち」が、太りの元！
12:08

公式の目安は200行

200行以内
公式ドキュメントに記載の目安
  • 短く、大事なことだけ が原則
  • 判断の物差しは「毎回読む価値があるか」
  • 定期的に見直して、刈り込む習慣を
行数より中身。読む価値で勝負！

やせさせる方法

  • 要約：詳細を1行のルールに圧縮する
  • 分割：@import でファイルを分ける
  • 削る：同じ意味のルールをまとめる
  • 任せる：古い経緯は自動メモリへ移す
# 分割の例
@import ./rules/style.md
@import ./rules/test.md
1行にできることは、1行に！

本当に軽くなるのは paths

  • 読みに行く範囲（paths）が負荷の源
  • 参照するフォルダをしぼると、載る文字数がぐっと減る
  • 不要な追加フォルダは、設定から外す
  • 実測では、行を削るより 効果が出やすい
#paths #設定を見直す #読み込み範囲
削るより、範囲をしぼる方が効く！
