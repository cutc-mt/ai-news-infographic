#02

Exo テーゼの 定義

  • 「Exo は 完全に再帰的 な agent である」
  • 実行中に 安全に 自身の全側面を編集
  • 再帰的な 自分の改善 を目指すシステム手法
  • プロンプトから ハーネスの規約 まで対象
"Exo is an agent that's
fully recursive.
It's able to safely edit
all aspects of itself
at runtime."  (2:23)
動きながら 自分を書き直す、がこの講演のテーゼ!
#03

MLスタックの 大転換

  • かつての主役は モデルの重み
  • 改善の中心が 下の層 にあった時代
  • いまは エージェントハーネス へと移動
  • プロンプト・道具・権限など 上の層 が主戦場に
  • 重み ↔ ハーネスで 改善の重心 が逆転
どこを磨くかが 変わりつつある!
#04

起源: Sky Discover

  • 出発点は Sky Discover という取り組み
  • AIによる発見 を駆動する探求
  • その経験が Exo の設計 に直結
  • 発見の仕組み → 自分の改善へ 視点を転回
「発見するAI」から「直すAI」へ!
#05

OpenClaw との 比較

  • OpenClaw・Pi・Hermes と同じ 完全ハーネス
  • 道具・タスク・外部との 連携 を支援
  • 環境への 適応力 はどれも持つ
  • 決定的な差は コードと実行ログの完全可視
OpenClaw / Pi / Hermes:
  tools / tasks / integrations ✓
Exo = それら + code & logs
  への完全な視界
「自分が見える」ことが 最大の違い!
セクション2: 設計 — エージェントの解剖学
#06

エージェントとは何か

  • ポリシー — どう判断するかの規約
  • コンテキスト — 何を見て考えるか
  • アクション — 実際に何を行うか
  • この3つで agent の輪郭 を定義
  • 3つとも Exo では 編集の対象
定義を分解すると 改善点が見える!
#07

Exo の アーキテクチャ概要

  • 自身の コード全体 に視界を持つ
  • 実行時ログ も丸ごと参照できる
  • 少しずつ段階的に 全側面を改善
  • 自分の 複製 と系統の管理まで可能
Exo visibility:
  own code      ✓ full
  runtime logs  ✓ full
  → incremental improvement
  → self-cloning & lineage
自分の全体像を 見渡せるのが強み!
#08

暗黙的な変更と 明示的な変更

  • 暗黙: 記憶の更新やスキル作成
  • たいていの agent は ここまで
  • 明示: コードや規約そのものを書き換え
  • Exo は 明示の領域 まで踏み込む
  • プロンプト・道具・規約自体 が対象
「思い出を変える」から「体質を変える」へ!
#09

実例: Exo が ポケモンをプレイ

  • 実際の ゲーム攻略 で実証
  • 長く続く 実世界タスク の代用として
  • 画面と操作だけの 限られた環境
  • 進めながら 自分を調整 できるかが見もの
遊びながら 説明するわかりやすい実例!

3層分解: Executor・ハーネス・サンドボックス

  • Executor — 考えて動く本体
  • Exo Harness — 支える外骨格
  • Sandbox — 隔離された実行空間
  • 設計で 安全性を保証 する狙い
"In harness space, we have
an opportunity to enforce

architecture of the system."

規約ではなく 構造で守る発想!
#12

完全な再帰的な 自分の改善

  • プロンプト・記憶・道具・規約 まで全て操作可能
  • 自身の 複製 や系統の運用もこなす
  • 唯一さわれないのは イベントログ
  • 試した履歴の 正史 として再帰ループを防止
immutable: event log
  = canonical history
  = "何を試したか"の記録
→ ループにはまらないための命綱
履歴だけは 誰も書き換えられない!
#13

転送可能な agent と テレポーテーション

  • agent を 別環境へ移す 発想
  • 状態をまとめて 持ち運び 可能に
  • まるで 瞬間移動 のような再開
  • 別のマシンでも 仕事を継続
引っ越しできる agent という発想!
#14

サブエージェントと シークレット管理

  • サブエージェント の活用を議論
  • 鍵や認証情報の 扱い が課題
  • 部下に渡す 権限の範囲 を絞る
  • 秘匿情報は 隔てて管理 する設計
parent agent: 秘密を保持
sub-agent  : 必要最小限だけ
             受け取って実行
鍵を全部渡さないのが ポイント!
