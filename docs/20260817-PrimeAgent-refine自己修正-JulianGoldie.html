Prime Agent の /refine で 自己の修正

直近の仕事を 見直して 設定を書き換える 仕組みと バックグラウンドのガードレール

セクション1: 仕組み — /refine は何をするのか
#01

/refine とは

  • /refine は slash command のひとつ
  • 直近の仕事を 振り返る 合図
  • agent が 自分を点検 する時間
  • 仕事のあとに ひと呼吸 を入れる習慣
> /refine
reviewing recent work ...
仕事が終わったら ひと呼吸、が合図!
#02

直近の仕事を 見直す

  • セッションの 履歴 を確認
  • 何をしたかを 棚卸し
  • 成功 と 失敗 を仕分ける
  • 記憶が新しいうちに まとめて 処理
記憶が新しいうちに 見直すのがコツ!
#03

エラーの 検出

  • 出力の 間違い を探し出す
  • こけた箇所を 記録
  • エラーの 種類別 に分類
  • 見逃しがちな 小さな破損 も拾う
失敗は恥ではなく データ!
#04

失敗の パターンを見つける

  • 1回だけの失敗なら 様子見
  • 2〜3回 重なる ら要注意
  • 繰り返す 原因 を特定
  • 「たまたま」を 「いつも」 に変える
  • 見つけたパターンが 次の標的
繰り返し こける場所が 改善の的!
セクション2: 編集 — エビデンスに基づく書き換え
#05

根拠（エビデンス）が 必須

  • 感想ではなく 証拠 主体
  • ログから 引用 して裏付け
  • 根拠がなければ 編集しない
  • 思いつきの 書き換え を防止
「なぜ変える?」に 答えられるかが基準!
#06

スキルの 説明を更新

  • skill の description を更新
  • 失敗した場面を 言葉に追加
  • 次の 呼び出し方 が変わる
  • 棚の ラベル を貼り直す感覚
skill: company-news
description: "決算のニュースを
  1ページにまとめる"
ラベルが直ると 探し物が見つかる!
#07

プロンプトを 調整

  • 指示文の一部を 書き換え
  • あいまいな表現を 具体化
  • トーンや 形式の指定 を明確に
  • 小さな差し替え で大きな効果
一言 直すだけで 出力が変わる!
#08

サブエージェントを 調整

  • 部下 agent の spec を微調整
  • 担当と権限 を見直す
  • 渡す 道具 を交換
  • チーム編成の 見直し
親だけでなく 部下まで鍛える!
#09

バックグラウンドで 実行

  • 画面の作業は そのまま 続行
  • 作業の裏で 設定を更新
  • 本業を止めない のがポイント
  • 気づいたら 賢くなってる
あなた : /refine
agent  : (裏で設定を確認中 ...)
       : 3件の調整を適用しました
表では作業、 裏では成長!
セクション3: ガードレール — 安全に回す仕組み
#10

ガードレールの 意味

  • 勝手に 書き換えない のが鍵
  • 変更の 範囲を制限
  • 許可された場所 だけ触る
  • 暴走を防ぐ 境界線
  • 厳格なルールの下で 自律 が動く
守備範囲が あるから安心!
#11

安全な 自律のチューニング

  • 自律 と 安全 の両立
  • 人手なしでも 暴れない
  • 効率を追いながら リスクを抑制
  • 信頼して任せる 土台になる
任せていいのは 安全装置があるから!
#12

人間との 役割分担

  • ルール作りは 人間
  • 細かい調整は agent
  • 重大な変更は 確認を通す
  • 審判と整備士 の関係
審判は人間、 練習はagent!
セクション4: 実践 — 改善のループを回す
#13

自己の 改善ループ

  • 仕事をする
  • /refine で振り返る
  • 根拠のある編集を 設定に反映
  • 次の仕事が 上手く なる
仕事 → /refine → 設定を更新
  ↑____________________|
ループを回すほど 上手くなる!
#14

はじめる前の 確認

  • まず Prime Agent を導入
  • ガードレールの 最初の設定
  • 見直す 範囲を決める
  • 最初は 小さく試す
まずは1つの skill で試そう!
#15

効果の 測り方

  • 同じ失敗が 減ったか
  • 手直しの 回数を数える
  • 完了までの 速さ を比較
  • 設定の 変更のログ を読む
数字で比べると 成長が見える!
#16

他のAIとの 違い

  • ただの チャット ではない
  • 設定ファイルを 自ら書き換え
  • 貫くのは エビデンス主義
  • ガードレール内 で自律的に動く
話すAIから 直すAIへ!
セクション5: まとめ — 導入のヒントと全体像
#17

導入の ヒント

  • 週に 1回の/refine から
  • 失敗メモを ためておく
  • 変更は 小さく 心がける
  • 変えた内容は 必ず記録
  • 慣れたら 範囲を広げる
小さく始めて 習慣にする!
#18

まとめ: 自分を 直すagent

  • /refine で直近を振り返る
  • 根拠のある編集 だけを許す
  • スキル・プロンプト・部下を調整
  • ガードレールの中で 安全に回す
/refine = 振り返り + 根拠 + 微調整
         (ガードレールの中で)
AIが自分を 直す時代が来た!
