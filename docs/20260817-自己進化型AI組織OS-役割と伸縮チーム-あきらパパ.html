役割・視点・伸縮チームの設計

AIに組織図を渡すだけでは弱い。働きながら育つ仕組みを作る
2026-08-17  |  本編 8分43秒
#AIエージェント #AI組織 #Planner/Worker/Reviewer #伸縮チーム
なぜ組織図だけでは弱いのか0:00〜
#01

図を渡して満足の罠

箱と線だけでは動けない

  • 組織図は名前と配置 を示すだけの静的な絵
  • どう判断し、どう渡すかが書かれていない
  • 図はあくまで入口。運用ループが本体
描いて終わりじゃなく、回し方まで作る！
#02

確認役を増やしても同じ

同質化の問題

  • 同じAIに似た指示を出すと、視点も似る
  • 見つかる失敗の種類が、いつも同じまま
  • 人数を足しても盲点は消えない
視点が同じなら、何人並べても同じ！
#03

作業でなく組織を作る

小さな会社の発想

  • 手順書の自動化とは根本的に違う
  • 1つの会社を作るつもりで設計する
  • 評価・改善・記憶 まで含めて回す
「会社なら何を持たせる?」と考える！
組織を定義する1:45〜
#04

役割は担当地盤で決める

3点セットで書く

  • 名前 何をしている役か
  • 担当地盤 どこからどこまで担当か
  • 担当しないことも明示して重複を防ぐ
role: Reviewer
scope: 記事の事実確認
judge: 出典が無ければ差し戻し
not : 文章の味づけは担当外
線引きがハッキリすると、空白と重複が消える！
#05

判断基準を持たせる

基準が無いと迷う

  • 基準が無いと「まあ良いか」で通してしまう
  • 必須条件 を列挙して渡す
  • 「いい感じ」などの曖昧な言葉は禁止
「いい感じ」は判断基準じゃない！
#06

目的を1文に書き切る

揃えたい4つの問い

  • 誰に 価値を届けるのか
  • 何が 完成の状態か
  • どの失敗 を絶対に避けるか
  • 誰が 最終判断を下すのか
答えられない組織は、迷って勝手に進む！
視点を分ける: Planner / Worker / Reviewer3:40〜
#07

Planner: 計画役

難易度を判定し、編成を組む

  • まずタスクの難易度 を判定
  • 必要な人数と専門を自前で決める
  • Workerに渡す条件 をまとめる
# Plannerの仕事
1. 難易度を判定
2. 編成を決める
3. 完了条件を書く
計画役が編成のコントロールを握る！
#08

Worker: 作業役

条件を満たすまで作り切る

  • 渡された条件を満たす成果 を作る
  • 自分の判断で完了を決めない
  • 手が止まったらPlannerに差し戻し
作るのは専門家、決めるのは上流！
#09

Reviewer: 査査役

必須条件で容赦なく落とす

  • 完了条件と照らして判定
  • 「悪くない」では通さない
  • 差し戻す時は理由 を添えて返す
ここでの優しさが、品質を下げる！
#10

独立評価と受け渡しの型

話す前に各自で書く

  • 相談の前に、まず各自で評価を書く
  • 声の大きい意見に引きずられない
  • 受け渡しは書式 で統一する
# 受け渡しの型
市場 / 根拠 / 情報源
確認日 / 確信度 / 反対意見
口渡しをやめて、検証できる形で渡す！
学ばせ、組み替える5:20〜
#11

失敗を記憶として保存

教訓は圧縮して残す

  • 何がダメだったかを要約 して保存
  • 次回の初期指示に混ぜる
  • 同じ失敗を二度と繰り返さない
組織の経験が、どんどん蓄積される！
#12

組織の動きを振り返る

成果物ではなく過程を見る

  • どの受け渡し で詰まったか
  • どの役割が空回りしたか
  • 無駄な工程を切り、足りない役割を足す
商品より、作り方を直すのが本質！
#13

組織図が自動で書き変わる

結果で育つ編成

  • 同じ指摘が重なれば、役割を統合
  • 同じミスが出れば、新担当を追加
  • 次回の組織図が勝手に更新されていく
図は生き物。結果で育てる！
チームの伸び縮みと人間の仕事6:45〜
#14

難易度でサイズを変える

固定編成をやめる

  • 普段は少数（例: 3人）で回す
  • 問題が起これば専門担当 を追加
  • 難易度に合わせて伸び縮みさせる
if task.difficulty == "high":
    team.add("fact_checker")
    team.add("editor")
必要な時だけ膨らむチーム！
#15

予算付きのやり直し

止めどころを決める

  • やり直し回数はmax-turns で上限
  • 予算を超えたら無理に続けない
  • 未解決の点は人間に引き継ぐ
無限ループにブレーキを！
#16

人間の仕事は2つだけ

理念と評価制度

  • 理念: 組織は何のために動くか
  • 評価制度: 何を良しとするか
  • 細かい作業指示は人間の仕事じゃない
人間は憲法を作る側に回ろう！
AI活用の3段階8:05〜
#17

質問 → 任せる → 設計する

3段階で進む AI活用

  • 質問する: AIに聞く段階
  • 任せる: 仕事を渡す段階
  • 設計する: 組織を作る段階
  • 「任せる」で止まると組織の力が出ない
第3段階の設計が、一番効く！
