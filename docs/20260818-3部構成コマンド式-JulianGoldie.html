曖昧な結果に

  • 何を・どこまで・どこへ出すかが指定ゼロ
  • 返ってくるのは、使えない成果物の山
「AIのせい」にしがちだけど、
実は命令式に問題があったりして…
②

鍵は「命令の構造」

  • 高品質なAI出力の秘密は特定の命令構造にある
  • モデルを替えるより、まず型を整える方が手っ取り早い
  • 同じAIでも、伝え方で成果の質が激変
料理で言えば、

3部構成
コマンド式とは

  • Job = 仕事の定義（なにをやるか）
  • Check = 結果の検証（ちゃんとできたか）
  • Destination = 宛先（どこへ出すか）
Job Check Destination
この3つをワンセットで

第二部: Part 1「Job」— 仕事を正しく定義する

④

Job:
ゴールを明確に

  • エージェントが狙うゴールを一文で決める
  • 「やること」と「やらないこと」の境目を切る
  • 範囲・量・条件を、数字で具体的に
「よろしく」はもう通用しない、
と思って丁寧に書くのがコツ
⑤

Job:
書き方のポイント

  • 読み手（誰のためか）を最初に指定
  • 成果物の形式：記事・メール・表など
  • 品質の基準と禁止事項も添える
  • 期限や更新の頻度まで決めると自動化向き
人への仕事の依頼状と
同じように書けばOK!
⑥

Job:
コマンド例

  • Job部分だけでも、この密度で書く
  • 具体名・数字・形式が命
Job:
「SEO記事を1本書いて」ではなく…
「初心者向けに、AI自動化の
 基礎を解説するブログ記事を
 1,500字で作成。
 見出しはH2を3つ、
 箇条書きを必ず入れる」
たったこれだけでも
出力のブレが激減します

第三部: Part 2「Check」— 一番スキップされる検証フェーズ

⑦

Check:
結果を検証する

  • 「できていますか？」を基準つきで問うフェーズ
  • 不合格ならやり直させるルールを組む
  • 合格／不合格の白黒はっきりさせる
品質チェックを人間が
やらなくて済むのが最大の強み
⑧

多くの人が
ここで失敗する

  • 大半のユーザーはCheckフェーズをスキップ
  • 検証なし → 失敗 → 手直しのループに突入
  • 結局、自分で確認する時間が戻ってくる
「AI任せにしたのに、
なんで私がチェックを?」の罠
⑨

Checkは
安全装置

  • 自律エージェントには重大な安全システム
  • 暴走・誤送信を出る前にせき止める扉
  • 人の代わりにブレーキを踏んでくれる
車で言うところの
エアバッグみたいなもの!
⑩

Check:
検証基準の書き方

  • 合格ラインは数値で提示
  • 事実確認・リンク切れなどを項目化
Check:
「完成したら提出前に：
 ① 文字数が1,500字以上か
 ② 見出しが3つあるか
 ③ 架空の事実がないか
 を確認。不合格なら
 修正してから次へ進む」
基準が「感覚」だと
AIも判定できないので注意

第四部: Part 3「Destination」— 成果物の宛先を決める

⑪

Destination:
どこへ届ける?

  • ブログ・SNS・メールなど出力先を指定
  • ファイルなら保存場所とファイル名のルール
  • 完了通知の方法まで決めると親切
作るだけじゃなく、
「置き場所」まで指示が完璧
⑫

宛先が決まると
自動化が完成

  • Job→Check→届けるまで人が介入ゼロ
  • 放置していても仕事が勝手に進む
  • 浮いた時間を、戦略づくりに回せる
宛先が「口頭」だと、
そこで必ず自動化が止まる…
⑬

Destination:
コマンド例

  • 宛先は最後にひとことでOK
  • 複数宛先も列挙すれば対応
Destination:
「チェックを通過したら、
 記事をWordPressの
 下書きとして保存し、
 完了メールを私に送信」
気づいたら下書きが増えてる、
という体験ができます
