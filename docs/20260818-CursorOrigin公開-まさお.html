CursorがGitHub代替
「Origin」を公開

AIエージェント前提のGitホスティングサービスがついに登場！

2026年8月18日 まさおAIじっくり解説ch 動画尺：9分40秒

Originとは何か

基本をおさらい

  • Cursorが公開した Gitホスティング サービス
  • AIエージェント が主役の前提で設計
  • GitHubの代替を狙う、新しい居場所
  • Gitという土台はGitHubと似ている部分が多い
GitHubの代わりになる、エージェント向けの ホスティング がついに登場したよ！

まだリリース候補版（RC）

現在地を確認

  • いまは RC版 の段階
  • これからアップデートがどんどん重なる見込み
  • ドキュメントの量がかなり充実している
  • 社内で相当に使い込まれていると予想できる
ドキュメントの充実ぶりから、 社内運用 が進んでいそう！

Cursorに統合されている

どこから使う？

  • Cursor画面の Codebase に登場
  • アプリ上の操作でOriginを認識して、いい感じに統合
  • 別の管理画面へ切り替えなくても使える体験
エディターの中で そのまま 使えるのがうれしい！

GitHubからの連携

Import from GitHub

  • Import from GitHub でリポジトリを連携
  • 連携したリポジトリをOriginでも管理できる
  • GitHubと併用しつつ、Cursorのエージェントを活用
Cursor → Codebase
 → Import from GitHub
 → 連携するリポジトリを選ぶ
乗り換えなくても、 連携して 使えるのがポイント！

新しいリポジトリ作成

+ New で作る

  • + New から好きな名前でリポジトリを作成
  • 動画の中で、実際に作成のデモを実施
  • Gitの作法は変わらないので、抵抗が少ない
Codebase → + New
 → リポジトリ名を入力して作成
新しいリポジトリも、ボタンひとつで サクッと 作成！

クローンとプッシュ

コマンドで操作

  • 既存のリポジトリをそのまま クローン
  • ローカルのプロジェクトをOriginに プッシュ
  • 画面の方に、コマンドが共有される親切設計
# 既存のリポジトリをクローン
git clone <OriginのリポジトリURL>

# ローカルのプロジェクトをプッシュ
git remote add origin <URL>
git push -u origin main
見た目はGitHub風、でも中身は エージェント向け！

プルリクエスト運用

PRももちろんOK

  • コードをポンポン開発して プルリクエスト を作成
  • 動画の中で、実際に1本アップしている
  • メインのコードへ取り込む流れもこれまでと同じ
PRを出す感覚は、GitHubと ほぼ同じ でOK！

Actionsが意図的に排除？

あえて外した機能

  • GitHub Actions のような機能は、まだ無い
  • 意図的に排除したのでは、という見方ができる
  • YAMLの設定ではなく Cursorの自動化 と連携
  • ボットが PRをレビュー する体験を作りに行った？
  • エージェンティック な体験の追求と予想
YAMLを書く時代から、エージェントに おまかせ の時代へ？

1秒間に22.6コミット

デモで判明した実力

  • 発表時のデモで 22.6コミット/秒 を処理
  • 1日12時間もやると、笑ってしまうレベルの数に
  • それでもちゃんと処理できました、とのこと
エージェントが並列で動くと、 コミット数 がとんでもないことに！

巨大PRの問題点

従来の悩み

  • 1個の巨大なPR（例：2000行）は読むのが大変
  • レビューアが読むうちに、雑になってしまう
  • 見落としが増えて、品質が下がるリスク
  • 「細切れで出して」と言われた人も多いはず
巨大なPRは、レビューの 質 を下げてしまう…

スタックドPRの発想

待ち時間をなくす

  • 細切れにすると、直列の 待ち時間 が発生
  • スタックドPR で下にどんどん積み上げる
  • 平行でレビューできて、速度が上がる
  • エージェントが並列で積み上げる前提の設計
PR #3 ┐
PR #2 ├ 積み上げて 平行レビュー
PR #1 ┘
待ち時間なしで、 どんどん積む 発想！

Graphite買収との関係

下支えする技術

  • Cursorは少し前に Graphite を統合していた
  • 積み上げの弱点：下の土台が崩れると全部崩れる
  • Graphiteはその手間を解消するために生まれたツール
  • もともとはGitHub上で動く自動化ツール
  • Originは最初から組み込み、積み上げ前提 の画面と順番管理
Graphiteの力が、Originを 強力に下支え！

充実のドキュメント

読み込むほどわかる

  • Origin CLI の説明ドキュメント
  • 連携機能についてのドキュメントも各種あり
  • 動画の概要欄に、リンクをまとめている
  • 読めば設計思想までつかめる充実ぶり
ドキュメントがそろっているのは、これからの 安心材料！

エージェントが主役の体験

CLIで動かす

  • クラウドエージェント がOriginのリポジトリで作業
  • エージェント自身がクローンしてブランチを作成
  • コミット・プッシュをして、PRまで出せる
  • PRの操作や自動化のやり方も共有されている
# エージェントの作業フロー
クローン → ブランチ作成
 → コミット → プッシュ → PR作成
エージェントが自分で PRまで出す のは面白い！

GitHubとのミラーリング

併用する使い方

  • GitHubと同期する ミラーリング機能 を準備中
  • GitHubと連携しながら、Cursorのエージェントを使う
  • 足りない部分を、GitHub側で補えるうれしい設計
移行しなくても、同期して 両方の良いとこ取り！

CIは外部サービス連携

自作しない設計

  • CI基盤そのものは、わざわざ自作しない
  • Vercel などの外部サービスと連携
  • その他の外部連携で回すのが現状の作り方
CIは専用サービスに任せる、 すっきり構成！

今すぐ移行すべき？

結論をひとことで

  • チームで試してみるのは、とても良いアイデア
  • でも現時点は GitHubでの運用 を推奨（個人的見解）
  • 思想に共感した人は、乗り換えるかもしれない
  • みんながGitHubを使う環境が変わる可能性も
結論：今すぐ全移行は不要。 様子見 が無難かも！

Cursorの今後とまとめ

押さえておきたい視点

  • クラウドエージェントやローカルの開発体験、デザインも強化中
  • Grok がモデルとして強力に、Composerも好調
  • Grokボット などにも注目が集まる
  • ハーネスもモデルも、かなりそろってきた
  • Originはその1つとして、だれでも使える形で提供されている
これからの開発の当たり前が 変わるかも、要注目！
