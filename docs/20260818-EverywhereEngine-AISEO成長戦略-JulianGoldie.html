#01

この動画の地図

エグゼクティブサマリー

  • 単一サイト → マルチプラットフォームのフライホイールへ
  • 武器はSearch Consoleの独自データ

この1枚で動画の全体像がわかるよ。まずはざっくり掴んで、気になるところから深掘りしてみてね。
#02

従来SEOの限界

古いランキング手法だけでは不十分

  • 限界1：キーワード順位だけを追っても流入が減る
  • 限界2：ビッグキーワードは大企業と正面衝突
  • 限界3：1サイトに集中するとリスクが一点集中
  • アルゴリズム更新のたびに振り出しに戻る不安
「昔ながらのやり方で頑張る」のが一番こわい。進化はもう始まってるんだ。
#03

検索の地図が変わった

AIが「答え」を出す時代へ

  • 人はGoogleだけでなくChatGPT等の生成AIでも探す
  • 検索結果はAI Overviewなど要約型に
  • YouTube・SNSも探索の入り口になる
  • 「どこで見つかるか」が検索の主戦場に
  • だから「いろんな場所にいる」戦い方が急務に
検索って「1つの窓口」じゃなくなった。これが Everywhere（あらゆる場所）という名前の由来だよ。
#04

Everywhere Engineとは？

あらゆる場所で回り続ける成長エンジン

  • 考え方：1サイトではなく複数プラットフォームに展開
  • 各場所が互いを送客し合う仕組み
  • 回すほど勢いが増す（フライホイール効果）
  • AI検索にも引っかかりやすい構造を作る
Everywhere Engine =
  自社サイト
  + 動画 / SNS / 記事
  + AI検索での存在感
  → すべてが連動して回る
エンジン＝「動力」。一度つければ、ぐるぐる回って勝手に成長してくれる装置のことだよ。
第2部：フライホイール戦略
#05

単一サイト戦略の落とし穴

1つの箱に全部詰め込むリスク

  • すべてのコンテンツが1ドメインに依存
  • AI検索では見つかりにくい単独発信に
  • 更新ペースが1チームの限界で頭打ち
  • アルゴリズム変動で一気に沈む可能性
  • 解決の糸口：複数の居場所を持つこと
卵は1つのカゴに盛るな、とよく言うでしょ。SEOも同じことが言えるんだ。
#06

フライホイールの仕組み

回すほど力がたまる輪

サイト
動画
記事
AI検索
SNS
配信
  • 各プラットフォームが相互送客する
  • 1周するたび勢いが積み上がる
  • 止めないかぎり半永久的に回転
自転車のペダルとおんなじ。最初は重いけど、回り出すと軽やかに入力以上に進むようになるよ。
#07

輪を回す4ステップ

始め方の順番が大事

  • 種まき：自サイトの記事を核として作る
  • 展開：内容を動画・SNS投稿へ組み替え
  • 還流：各場所から自サイトへ誘導リンク
  • 計測：Search Consoleで効果を確認し再投資
  • 4を終えたら1へ戻りより大きく回す
完璧に作ってから動くより、小さく回し始めて速さで慣らすのがコツだよ。
#08

5サイトFlywheel（実例）

同チャンネルで紹介された拡張形

  • 発想：中核1つ＋周辺複数サイトで輪を組む
  • 各サイトは役割分担（紹介・教育・成交など）
  • サイト同士を文脈あるリンクで接続
  • 局所的な順位争いを回避できる
5サイトFlywheelのイメージ:
  site-A (入口) → site-B (教育)
       ↑              ↓
  site-E (成交) ← site-C/D (支援)
いきなり5つも要らないよ。まずは2〜3で回り方を覚えて、余裕が出たら増やすのが現実的。
第3部：Search Consoleの独自データ
#09

独自データの宝庫

Search Consoleにしかない情報

  • 実際に検索されたクエリ一覧が見える
  • 表示回数（インプレッション）＝露出の実態
  • クリック数から需要の温度がわかる
  • 外部ツールより正確な実測データ
推測ではなく「うちのサイトに起きた事実」が転がってる。無料なのが不思議なくらい。
#10

データの活かし方3段階

眺めるだけでは意味がない

  • 段階1：imp高・CTR低のクエリを抽出
  • 段階2：上位表示ページと差分を比較
  • 段階3：タイトル・構成を改善して再計測
  • 改善→計測を習慣のループにする
よくある狙い目:
  表示回数: 4,800 / クリック: 12
  → 「見られてるのに選ばれてない」
  = 改善の余地が大きいサイン
数字は「答え」じゃなく「質問」。なぜクリックされないのかを考えるのがスタートだよ。
#11

隠れたデータの見つけ方

表に出ないクエリを掘り起こす

  • 平均の表示順位が5〜15位の見逃しクエリ
  • 疑問形（〜とは / 〜やり方）のロングテール
  • 似たクエリを意図ごとに束ねる
  • 露出順ではなく機会サイズ順で並べ替え
誰も見てない下の方の行に、次のヒット記事のタネが隠れてることが多いんだ。
第4部：AI可視性ギャップ攻略
#12

AI可視性とは？

AIに「引用してもらう力」

  • 生成AIの回答に自社が登場するかどうか
  • AI Overviewなどでの引用・出典入り
  • 従来の順位とは別の新しい指標
  • 「信頼できる情報源」と認識されること
今後は「AIが知ってる名前」かどうかで、仕事が来るかどうかが決まる時代になりそう。
#13

ギャップの特定方法

「AIが知らない」場所を見つける

  • 自社の主要クエリをAIに実際に聞く
  • 回答に自社が出てこない項目を列挙
  • Search Consoleの実クエリと照らし合わせ
  • 「需要はあるのに不在」＝ギャップと定義
ギャップチェック例:
  Q: 「〇〇 おすすめ 3選」でAIに質問
  A: 競合3社が回答に登場
     → 自社サイトは不在 … ここを埋める！
やることは素朴。AIに聞いてみて、自分の名前があるか確かめるだけ。まずは10問くらい試して。
#14

ギャップを記事に変換

不在 → 存在への置き換え作業

  • AIが好む簡潔なQ&A構成で書く
  • 引用しやすい一文まとめを冒頭に
  • 関連テーマを内部リンク網で接続
  • 既存記事の書き直しでも十分に効果的
  • 公開後は再度AIに聞いて登場を確認
新規投稿だけが仕事じゃない。書き直しは最速でギャップを埋める手段のひとつだよ。
第5部：競合を避けて獲りに行く
#15

従来の競合を回避する

正面からぶつからない設計

  • 飽和キーワードから意図をずらす
  • 形式を変える：記事→動画・図解
  • 競合が薄いプラットフォームを選ぶ
  • 自社データ・体験という代替不能な軸
戦う場所の選び方:
  競合だらけの平原 ×
  → 誰もいない井戸 ○
  （具体 × 形式 × 場所 で差別化）
将棋と同じ。強い駒の正面に突っ込まず、効いてるマスを狙うのが上手な指し方。
#16

大事な場所で獲る

「どこで見つかるか」の設計

  • 客が実際に集まる入口を特定
  • 検索意図（調べる・比べる・買う）に場所を合わせる
  • 各入口から次の一手へ自然に流す
  • 流入元を多角化して安定させる
「どこでも見かける」じゃなく「大事なところにいる」。狙いを絞るのが Everywhere Engine のコツ。
#17

隠れデータ → 実用インサイト

変換の型を身につける

  • Raw：クエリ・露出・順位の生データ
  • 加工：共通意图でグループ化
  • 解釈：「誰が何に困ってるか」を一言で言語化
  • 行動：次に作るものを1つ決める
変換レシピ:
  「表示のみ3000回・CTR 0.4%」
   ↓ 解釈: 探してるのに応えきれてない
   ↓ 行動: 要約セクションを冒頭に追加
データは食材。レシピ（解釈の型）があると、どんな材料でも「次の一手」に料理できるよ。
第6部：まとめと次の一歩
#18

現代の検索を制覇する

ロードマップと次の一歩

  • 古いランキング手法への依存を手放す
  • マルチプラットフォームの輪を回し始める
  • Search Consoleの独自データを毎週読む
  • AI可視性のギャップを埋め続ける
  • 競合を避け、大事な場所でトラフィックを獲る
  • 今日やること：AIに自社を聞いてみるだけでもOK
完璧な準備はいらない。まず小さく回して、データを見ながら少しずつ大きくしていこう！
