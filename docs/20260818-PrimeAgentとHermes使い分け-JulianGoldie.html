Prime AgentとHermesはどう使い分けるか

Julian Goldie SEO「Prime Agent vs Hermes: Which AI framework is right for your workflow?」

2026年8月18日

結論: 乗り換えは不要

  • すでに Hermes を使っている人なら「なぜ触るの?」は当然の疑問
  • 今の設定で満足しているなら、何も変えなくていい
  • 2つは本当に別の仕事向きに作られている
  • 違いを見れば、使い分けの理由に納得できる
結論から言うと「切り替え不用」!
満足しているなら、そのまま使おう

共通する土台

  • どちらもオープンソースで MIT ライセンス
  • どちらも真面目な研究 lab 製
  • どちらも「自分を改善する」とうたっている
  • どちらも skill を作り、記憶も持つ
土台はここまで同じ。
でも中身は別物!

Hermes の住処: すべての表面

  • TelegramSlackWhatsAppemail に住む
  • 1つの agent と 1つの記憶を、すべての表面で共有
  • スマホから話しかけられる
  • 自分では触らないマシンを、遠くから調達することも
Hermes は文字どおり
「どこにでも」いる!

Prime の住処: フォルダとターミナル

  • 住むのはマシン上の、ひとつのフォルダ
  • 顔を出すのはターミナルの中だけ
  • 動ける場所はそこだけ。きわめて単純
部屋はひとつ。でもそこで
本気の仕事をさせる

設計の思想: reachable か放置か

  • Hermes は reachable 「いつでも連絡がつく」ように作られた
  • Prime は難しい仕事に放置するために作られた
  • どちらが正しいわけでもなく、目指す場所が違うだけ
連絡がつくか、放置するか。
ここが最初の分かれ道!

学び方の分かれ道

  • それぞれ、どうやって学んでいくのか?
  • ここが本当の意味での分かれ道
  • 自動で回るループか、refine による学習か
学習の設計こそ、
2つの最大の違い!

Hermes の学習: 自動で回るループ

  • 学習のループが自動で回り続ける
  • 仕事をしながら、使い回せる skill file を書く
  • 記憶を保存し、自分の過去の会話も検索する
  • あなたが誰か、その像を深めていく
  • 覚えるべきことは、自分にそっと念押しする
働きながら、勝手に賢くなっていく!

Hermes 流: handoff by design

  • 「手放し」を前提にした設計そのもの
  • とても使いやすくて、とっつきやすい
  • それでいて、ほぼ放置で動き続ける
  • 覚えることも、自分から進んで行う
設置したら、あとは任せておける存在

Prime の学習: refine という手法

  • 学習はすべて refine 経由で行われる
  • 意図的で、小さく、証拠に基づく編集だけ
  • すべての変更に「なぜ変えたか」の理由のログが残る
  • 速さより、慎重さと透明さを取る設計
学んだ証拠が、
すべて文書で残る!

すべての変更に ID と巻き戻し

  • 変更ひとつひとつに ID が振られる
  • ID を指定すれば、いつでも巻き戻し可能
  • コアの指示はロック済み
  • agent は自分の土台を、決して書き換えられない
全変更が追跡できて、
事故っても元に戻せる!

比喩: Hermes は鋭い assistant

  • 鋭い assistant のように学ぶ
  • 自分の notebook を静かに持ち続ける
  • 見えないところで、こつこつメモを取る
  • あなたの好みを、そっと覚えていく
「鋭い assistant が、そっと
自分のノートを持っている」ようなもの

比喩: Prime は読める研修 file の社員

  • 社員のように学ぶ agent
  • 研修 file を開いて、読むことができる
  • 行ごとに読んで、確認できる
  • すべての項目に「元に戻す」ボタン付き
学習の中身が、全部
あなたの目に見える!

Factorio の教訓 → audit trail

  • agent は「ズルのしかた」を自分に教えられる
  • 教育の記録 = audit trail が価値を持つ
  • Factorio の一件のあと、この設計の意味がわかる
  • ズルを学べる存在には、学習の履歴が必須
だから Prime は、学習に
履歴を付けたのか!

Hermes の仕事: 日々の相棒

  • 朝の briefing を、普段の言葉で頼める
  • 会議の合間に、スマホから仕事を投げる
  • 調べ物を任せて、結果をメッセージで受け取る
  • 毎日の連絡の相手として輝く
毎日そばにいて、
いつでも返事が来る相棒!

Prime の仕事: 長く重い、証明できる仕事

  • 何時間も回り続ける仕事に耐える
  • 巨大なファイルの山を、またいで処理する
  • 会話の量が、ふつうの context window なら破裂する規模でも動く
  • 「ちゃんと終わった」の証拠が要る仕事向き
重い仕事を放置して、
あとで証拠を受け取る!

Quality Gates: 完了の関門

  • Prime の基本は、bounded な自律モード
  • 「完了」と呼ぶ前に、本物の検査を通す
  • 検査が通らないなら、終わりと認めない
  • Hermes にはこれがなく、他の道具にもない
  • 詳細は、この講座の part 5 で学べる
「本当に終わった?」を
道具の側が保証してくれる!

歯車: 4つのずっと残る状態

  • prompt notes: 恒久の指示(必ず出典を、平易な英語で書く、等)
  • memories: あなたと仕事に関する、保存された事実
  • skills: 何度でも使える作業の流れ
  • sub-agent specs: また雇える助っ人 agent の、仕事の中身のメモ
  • 4つとも、作る・読む・編集する・消すが自由。あなたにも agent にも
この4つが歯車。
育てるほど、力が増していく!

まとめ: memory 保存が最短の成果

  • この講座で一番かんたんな成果は、memory の保存
  • agent が何か正しくやれたら、その場で伝える
  • 仕事について学んだ真実も、記憶として残す
  • 日々の連絡は Hermes、放置する重い仕事は Prime
あなた: いいね、その調子! 覚えておいて
agent : memory に保存しました ✓
「覚えて」の一言が、
agent を育てる!
