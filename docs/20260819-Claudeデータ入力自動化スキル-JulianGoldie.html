Claude Claude CLI スキル化 業務自動化 データ入力
なぜ 自動化 が 必要？
1

手動データ入力は 生産性の大敵

  • 手動データ入力と繰り返しのポータルアップロードは 生産性の大敵
  • 単純作業のために 貴重な時間 が毎日溶けていく
  • 単調（たんちょう）な作業はモチベーションも下げる
  • 転記ミスなどの ヒューマンエラー の温床（おんち）に
「毎日やってる単純作業」こそ自動化の最優先ターゲット！
2

きっかけ：視聴者からの 相談

  • 視聴者 Jessica からの質問が発端（ほったん）
  • 組織のスタッフやチームに 各自のデスクトップ環境 を与えたい
  • スタッフには担当すべき 定型業務（ていけいぎょうむ） がある
  • その業務をAIで自動化できないか？という相談
「うちのチームでも同じ悩みがある」人は多いはず！
3

具体例：サプライヤー ポータルへ アップロード

  • スタッフが エクスポートした商品リスト を扱う
  • それを サプライヤーのポータル にアップロード
  • シートをインポートして 発注（はっちゅう）を提出 する流れ
  • これを 毎日・毎週 繰り返す のがポイント
「書き出して → アップロードして → 提出」のワンパターン作業！
4

従来（じゅうらい）の対処法と その限界

  • 方法①：手動 でポータルにログインして入力
  • 方法②：Chrome 拡張機能 で補助
  • 方法③：汎用（はんよう）の Claude に都度（つど）依頼
  • どれも 毎回の操作と管理の手間 が残るのが限界
拡張機能の導入・更新・メンバーへの周知も、じつは地味に大変…
決定打が欲しい！
Claude CLI で カスタムワークフローを構築
5

Claude CLI とは

  • ターミナルで使う Claude のコマンドライン版
  • 手元のファイルやスクリプトを直接 操作できる
  • 複数ステップの作業を カスタムワークフロー として実行
  • やりたいことを ふつうの言葉 で指示するだけ 
$ claude
> この商品リストをサプライヤーに
  提出するワークフローを作って
プログラミングの専門知識がなくても始められるのが魅力！
6

カスタムワークフローを 作ってもらう

  • 「この 商品リスト をサプライヤーにアップロードしたい」と伝える
  • 使う APIエンドポイント を指定する
  • または アップロード先のWebサイト を教える
  • Claude がその流れを ワークフロー として組み上げる 
> このリストを supplier-portal に
  提出して。APIエンドポイントは
  https://api.supplier.example/upload
「対象」と「行き先」を指定するのがワークフロー作成のコツ！
7

API エンドポイント / Web サイト指定

  • サプライヤーが API を提供しているなら エンドポイントを指定
  • API がなければ アップロード画面のURL を指定
  • エージェントがポータルに ログイン → シートをインポート → 発注を提出
  • 接続方法はサプライヤーごとに 使い分け可能
API があれば確実・高速。なくてもWeb操作で対応できるのが強い！
8

ワークフロー設計の流れ

  • 商品リスト（export）を読み込む
  • サプライヤーポータルに ログイン
  • シートを インポート
  • 発注を提出（submit） して結果を確認
  • この一連の流れを毎回そっくり実行する
人がやっていた手順を、そのままAIに置き換えるイメージ！
手順の丸ごと代行
スキル化して ワンクリック実行
9

ワークフローを 「スキル」に 変換

  • 作ったワークフローを skill（スキル） に変換
  • 何度も再利用できる 定型パッケージ になる
  • 毎回プロンプトを打ち直す必要が なくなる
  • 変換の指示も会話だけで完結: 
> このワークフローをスキルに
  変換して
「いいワークフローができたらスキル化」が定番の流れ！
10

フロントエンドに 見やすい UI が つく

  • スキル化すると フロントエンド に UI がつく
  • コマンドがわからない人にも 直感的（ちょくかんてき） に使える
  • 組織のスタッフ・チーム全員で 共有 できる
  • Jessica の相談どおり 各自のデスクトップ で動かせる
「AIの使い方を覚える」より「ボタンを押す」方が誰でもできます！
11

ボタン1つで 実行できる

  • UI のボタンを ワンクリック するだけで実行
  • ログイン・インポート・提出まで すべて自動
  • 実行中は別の仕事に 専念（せんれん） できる
  • 終わったら 結果の通知 を受け取るだけ
朝イチのワンクリックで、今日分の発注処理が完了！
時短の極致（きょくち）
12

ベストプラクティス： 毎日使うものを スキル化

  • 毎日使うワークフロー こそスキル化するのがおすすめ
  • 判断基準はシンプル：利用頻度 で決める
  • スキルが増えれば 業務の資産 として積み上がる
  • 頻度の低いものは都度（つど）Claude に頼めば十分
「1週間に3回以上やる」ならスキル化を検討する価値あり！
効果・展開・まとめ
13

効果①：時間の 削減（さくげん）

  • ログイン→入力→提出が 数秒〜数分 に短縮
  • 毎日の作業が軽くなり、年間の合計 では膨大（ぼうだい）な差に
  • 納期（のうき）ぎわのバタバタも 落ち着いて対応
  • 複数スタッフ分の作業時間を まとめて削減
「1日15分の作業」も年間では 60時間以上 に！
14

効果②：ヒューマンエラーの 排除（はいじょ）

  • 同じ手順を 毎回そっくり 実行するのでミスが減る
  • 転記漏れ・数量間違いなどの 入力ミス を防止
  • 手順のブレがないから 品質が安定
  • 在宅・新人スタッフでも 同じ品質 で作業できる
「あれ、今月も発注ミスってた…」がなくなるのは大きい！
15

スタッフは 高度な業務に 解放

  • 単純作業から解放され より高度な業務 に専念
  • 思考・判断・対人業務など 人間にしかできない仕事 へ
  • サプライヤーとの関係強化や 交渉・分析 に時間を投資
  • 仕事の満足度・エンゲージメントも 向上（こうじょう）
人は「考える仕事」、AIは「繰り返す仕事」——いい分担（ぶんたん）です！
16

今日から始める 導入（どうにゅう）ステップ

  • Claude CLI をセットアップ
  • 繰り返している業務を 1つ選ぶ
  • 対象ファイルと API / Webサイト を指定して指示
  • 動作を確認し スキルに変換
  • UI から ワンクリック運用 をスタート
まずは小さな業務1つで試して、効果を実感しよう！
17

他にも使える： 適用（てきよう）業務の例

  • 請求書（せいきゅうしょ） の発行・ポータル提出
  • 在庫（ざいこ）データ の同期・更新
  • レポート の収集・まとめ・提出
  • 顧客データ（CRM） の入力・移行
  • 各種 フォーム入力・申請 の代行
「書き出して→どこかに提出する」作業は だいたい自動化できます！
18

注意点と まとめ

  • ポータルの 利用規約 とAPI仕様は事前確認
  • ログイン情報の 権限管理・取り扱い に注意
  • 導入直後は 人間によるチェック を併用（へいよう）
  • 結論：毎日のワークフローはスキル化 してワンクリックへ
  • スタッフは より高度な仕事 に集中できる
