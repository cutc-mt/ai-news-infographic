00:00〜アーキテクチャ

全体像 — スタック 1 枚絵

  • クライアントも API も Next.js に統一。
  • DB は Cloudflare D1、保存は R2。
  • 認証 Better Auth ＋ 決済 Stripe。
  • ホスティングは Workers で世界の端末へ。
Next.js（UI ＋ API）
   ├─ D1（データベース）
   ├─ R2（ファイル置き場）
   ├─ Better Auth（認証）
   └─ Stripe（決済）
Cloudflare Workers 上で稼働
役割を並べると、Cloudflare が多すぎるくらい担ってくれるのだ。
③
01:18クライアント

クライアント — Next.js

  • 画面まわりは Next.js を採用。
  • React 資産や SSR の仕組みをそのまま活用。
  • AI による コード生成 とも相性が良い定番。
見た目の層は迷わず定番へ。個人開発はここに時間をかけすぎないのがコツ。
④
02:52バックエンド(API)

API も Next.js で統一

  • 別のサーバーを立てず、API Routes で賄う。
  • フロントと API が 同一リポジトリ で楽。
  • 型や処理を 共有 できるのが大きな利点。
app/
 ├─ page.tsx      … 画面
 └─ api/
     └─ route.ts  … API もここに
サーバーを分けない。それだけで管理の手間がぐっと減るのだ。
⑤
03:50データベース

データベース — D1

  • Cloudflare の サーバレス DB「D1」。
  • 中身は SQLite ベースで馴染みやすい。
  • Workers と 同じ網内 で動くのが強み。
アプリの近くで DB が動くので、往復のむだが減り、料金も使いすぎた分だけの支払いでOK。
軽いクエリなら DB もエッジ側へ。全体がすっきり動くのだ。
⑥
05:14DB 選定

D1 vs Supabase — 比較開始

  • 個人開発の DB 定番 Supabase と比較。
  • この動画で いちばん長い パート（約 6 分）。
  • 「どちらを選ぶか」を まっ正面 から検討。
定番 vs 候補。道具は比べてこそ見えるものなのだ。
⑦
05:14〜コスト比較

コストで比べる

  • 両者とも 無料枠 から試せる構え。
  • D1 は 使った分だけ の従量課金が基本。
  • アクセス ゼロの月 はほぼゼロ円で止まれる。
収益化前のサービスは「動かしているだけでお金が消える」構成を避けるのが鉄則。
個人開発の命運は、月々の請求額で決まると言っても過言でないのだ。
⑧
〜11:56判断基準

どちらを選ぶべきか

  • Cloudflare に寄せるなら D1 が自然。
  • 認証や即時更新まで任せたいなら Supabase。
  • どちらも標準 SQL なので 移行の敷居 は低め。
正解は一つじゃない。自分の構成に合う方へ進むのが正道なのだ。
⑨
11:56認証

認証 — Better Auth

  • 認証まわりは Better Auth を採用。
  • パッケージを入れて 自前の DB に組み込む方式。
  • メールや SNS での ログイン にも対応。
認証を外部に預けない。データは自分の DB に置く路線なのだ。
⑩
11:56〜認証の利点

Better Auth の利点

  • D1 と接続 して、そのまま使える点。
  • 設定を コードで書ける のが扱いやすい。
  • 定番の書き方なので AI エージェント にも書かせやすい。
「組み込み型」なので、認証基盤の側の料金や制限を気にせずすむのが個人開発向き。
部品として組み込む。所有感もあるのが嬉しいのだ。
⑪
15:55決済

決済 — Stripe

  • お金のやり取りは Stripe 一択。
  • 月額課金にも 買い切り にも対応。
  • 日本語の 管理画面 もそろっている。
ユーザー → Stripe の画面で支払い
        → Webhook で自サービスに通知
        → D1 に契約状態を記録
カード情報を自分のサーバーで扱わない。安全の要はこれなのだ。
⑫
15:55〜決済の実装

決済を回す仕組み

  • 支払い完了は Webhook で受け取る。
  • 受け取ったら D1 側 に契約を反映。
  • テスト環境で 動作確認 してから本番へ。
「払ったのに反映されない」を防ぐ notify の設計が肝なのだ。
⑬
17:22ストレージ

保存 — Cloudflare R2

  • 画像やファイルの置き場は R2。
  • API が S3 互換 なので乗り換えも楽。
  • アバターや投稿画像を URL で配信。
DB には入れきれない大きな物は、全部ここへ逃がすのだ。
⑭
17:22〜配信コスト

R2 の強み — 配信費ゼロ

  • 読み出し（エグレス）への課金がない設計。
  • バズって読まれても 請求が跳ねない。
  • Cloudflare の CDN で速く届く。
「読まれた数だけ課金」型のストレージと違い、転送料金ゼロなのが個人開発で重宝する理由。
人気が出た日ほどありがたさが分かる、この課金なのだ。
⑮
19:09ホスティング

稼働場所 — Workers

  • アプリの稼働先は Cloudflare Workers。
  • 世界中の 拠点 で動く実行環境。
  • 常時起動の サーバー管理 が不要。
サーバーを持たずに世界へ出す。それが Workers の売りなのだ。
⑯
19:09〜デプロイ形態

Next.js を乗せる

  • Next.js を Workers 上 で動かす構成。
  • D1・R2・認証が 同じ網内 でそろう。
  • コマンドひとつで 公開 まで持っていける。
next build
   ↓ 専用のアダプタで変換
wrangler deploy
   ↓
Workers 上で Next.js が稼働
書いたものがそのまま世界に届く。この手軽さが快感なのだ。
