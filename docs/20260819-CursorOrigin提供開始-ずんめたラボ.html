Cursor Origin 提供開始！
GitHubから引っ越すと、2つだけ運べない

AIコードエディタCursorの開発元Anysphereが、GitHubのような「コードの置き場所」Originを始めたよ。引っ越しできるもの・できないものを整理！

2026年8月19日 ずんめたラボ Cursor / Anysphere / Origin

今日のニュース

何が起きたの?

  • Cursor開発元 Anysphere がコードホスティング Origin を提供開始
  • GitHubの代替となる コードの置き場所 を自社で作った
  • もともと秋リリース予定 を前倒しで投入
  • コードの半分をAIに書かせる時代の 新インフラ
AIの会社がなぜ置き場所まで作るの? → 答えは後半で！

Originとは?

置き場所＋確認がセット

  • 作品を置く棚 と、直したい人が確認表 を出す場所がセット
  • その確認表こそ プルリクエスト
  • 棚と確認が Cursorの中 に丸ごと入った！
  • ブラウザでコードを読み、PRをレビュー・マージ できる
  • 標準git でそのままpush可能
# 普段のgitがそのまま使える
git remote add origin https://origin.cursor.com/…
git push origin main
Cursorの中にGitHubみたいなのが増えた、という感覚！

GitHubと双方向同期

行ったり来たり

  • 公式には 「GitHubと双方向に同期」 と明記
  • 片方で直したら もう片方にも反映
  • Originをやめても GitHubに帰れる
  • 簡単そうに見えるのが、この話のミソ
# 同期のイメージ
GitHub ⇄ Origin （自動で双方向反映）
帰れるから安心して試せる設計！

入り口は有料限定

使える人は誰?

  • 無料プランでは使えない
  • 対象はCursorの有料プラン Pro Teams Enterprise
  • 有料でも順番待ち がある場合も
  • 入り口からもう有料 なのだ
マジで無料じゃ触れない！まずは契約確認！

始める前の準備

pushする前に決めること

  • チームで コードベース名 を決める必要がある
  • その名前が URLに入る ＝ チーム全体の住所
  • 後から変えにくい（店舗の看板のようなもの）
  • 古いプライバシー設定 のチームは切り替えが必要
  • 管理者はいつでも Originを停止可能 ＝ 安心
# 名前はURLの一部に
https://origin.cursor.com/チームの名前/repo
最初の1人がpushする前にチームで決めること！

運べるもの

GitHubから引っ越せる荷物

  • コードの 履歴
  • ブランチ
  • タグ
  • ↑ここは 丸ごと運べる！積み重ねは消えない
  • プルリクエスト も運べる ＆ こっちは双方向
これまでの積み重ねは消えない。良かった！

運べない① Issues

置いていく荷物 その1

  • GitHub Issues は運べない
  • 中身は 課題や不具合 を書き貯めた場所
  • さらに 話し合いの履歴 もここに残る
  • 運べるのはコード、残るのは話し合い
言い方はキツいけど当たってる…重い方が残るのよ

運べない② Actions

置いていく荷物 その2

  • GitHub Actions も運べない
  • 中身は 自動化の設定 ＝ 勝手にテストしてくれる仕掛け
  • そしてそこで使う 鍵（シークレット）
  • 変更のたびに動く仕掛けと鍵 はGitHubに残る
# 残るもの
Issues    : 話し合いの履歴
Actions   : 自動化設定 + 鍵
自動化が業務に組み込まれてるなら、ここが引っかかりどころ！

ブラウザでPRレビュー

いつもの流れのまま

  • PRを開くと タブが4つ 並ぶ
  • Activity＝やり取り
  • Commits＝変更の履歴
  • Checks＝テストの結果
  • Files Changed＝差分（行ごとにコメント可）
  • レビュー担当を指名して、通ったらマージ
  • 変更がぶつかった時もOriginが先に教えてくれる
# PR画面のタブ
[Activity] [Commits] [Checks] [Files Changed]
英語ばかりでも日本語にすると急に普通なのだ！

テストは外部ツール接続

繋げる相手は3つだけ

  • テスト自動化は Vercel ・ Depot ・ BuildKite の3つだけ
  • VercelはPRごとに プレビューURL が出る
  • 直した後の画面を本番に入れる前に触って確認
  • ただしプレビューは Vercel側の有料プラン 向け（Cursorとは別の財布）
  • Depot / BuildKiteは既存のActions設定をそのまま動かせる
同じ「有料」でも財布が違う！混ぜないこと！

テストの落とし穴

ここ要注意

  • Depot / BuildKiteは Originに直接置いた分だけ 動く
  • GitHubから取り込んだ分では動かない
  • 試している間はテストが GitHubに残ったまま
  • 「丸ごと引っ越したつもり」が半分だけ動く状態に
# テストが動く条件
Originに直接置いた分  → 動く
GitHubから取り込んだ分 → 動かない
待って！取り込んだ方は動かないのだ!? 覚えておこう！

なぜ置き場所を作った?

理由はエージェント

  • コードを書く相手が もう人間だけじゃない から
  • Cursorのエージェントは 自分でリポジトリを作れる
  • 道具を入れて、ログインして、作って、pushまでやる
  • 人が1時間かかるところをエージェントが完遂
  • 権限はあなたのアカウントのまま（勝手な購入は不可）
人がpushしなくていい…僕の出番がないのだ！

クラウド側エージェント

PRまで自動

  • クラウド側エージェントが Originのリポジトリを直接触る
  • 枝（ブランチ）を切って 直して PRまで出す
  • 本番ブランチに入ったら動かす トリガー設定 も可能
  • 日に何十本もPR が出る世界向け
  • 人が1日数本出す前提の置き場所ではもう足りない
# クラウドエージェントの流れ
枝を切る → 修正 → PR作成 → （本番マージで発火）
確認表（PR）まで自動なのだ！

X（旧Twitter）の子会社に

急いだ理由

  • Cursorの会社 Anysphere は Xの子会社 になったばかり
  • 買収が終わって数日 でのOriginリリース
  • 秋予定を前倒し − 急ぐ理由 はあったはず
  • 宇宙の会社がコードの置き場所を作る時代に
買収完了から数日でこれ！速度がすごい…

推奨アクション

有料プランならやること

  • リポジトリを 1個だけ取り込む
  • プルリクを 1本通す
  • いきなり全部運ぶ理由がない ＝ 1個で十分わかる
  • 迷うなら 両方に同時push する設定も可能
  • 二重にしておけば怖くない
# 最初の一歩
リポジトリ1個 取込 → PR 1本 → 様子見
全部持っていかなくていいのだ。1個で十分！

合わなければ戻せる

危険ゾーンの button

  • 設定の 危険ゾーン に「同期を切る」ボタン
  • 切ると Origin側が独立
  • GitHubは無傷 のまま残る ＝ 元の家はそのまま
  • 名前は怖いけど、これで安心して試せる
# 設定 > 危険ゾーン
[ 同期を切断 ] → Origin独立 / GitHub無傷
「危険ゾーン」って名前が怖すぎるのだ！

軽い荷物と重い荷物

動画メンターの深い視点

  • 運べたのはコードと確認表 ＝ 一番軽いものだけ
  • 残ったのは話し合いと自動化の設定 ＝ 重い方
  • 引っ越しの大変さは荷物の量じゃない。手続きと近所付き合いと住所変更
  • ダンボールより書類 なのだ
  • 今は乗り換えではなく 並べて走らせる時期
試す価値あり＝課題管理をGitHub外でやってるチーム！

まとめ

抑えるのは3つ

  • OriginはCursorの中のコード置き場。有料プラン限定・無料では使えない
  • 取り込めば履歴もコードもPRも運べる。でも課題管理と自動化の設定はGitHubに残る
  • テスト（Depot / BuildKite）は直接置いた分だけ動き、取り込んだ分では動かない
  • やること: 1個取り込んでPR 1本。合わなければ切って戻せる
  • Actionsが業務に組み込まれているならまだ待つべき
ここまで抑えれば次に何が来ても慌てずに済む！
