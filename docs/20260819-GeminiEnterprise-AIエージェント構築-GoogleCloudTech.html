下準備 —— コネクタと MCP で道を敷く

コネクタの設定

Gemini Enterprise コンソール

  • Gemini Enterprise の管理者が、Google Workspace 向けのコネクタを設定する。
  • これにより、エージェントが Workspace の文脈へのアクセスと操作を獲得する。
  • 一度つないでしまえば、あとはAPI で呼ぶだけの状態に。
管理者が先に「扉の鍵」を開けておく。開発者はその鍵で入るだけ！

MCP という選択肢

Model Context Protocol

  • MCP は、モデルに外部の文脈や道具を渡すための共通の規格。
  • コンソールでは、GWS コネクタと並んで MCP の設定も行える。
  • コネクタか MCP かを、用途に合わせて使い分けできる柔軟さ。
専用コネクタと汎用 MCP の2本立て。道具は多いほど嬉しい！

3つの連携ルート

紹介される統合の方法

  • ルート1: Apps Script から REST API でエージェントを呼ぶ。
  • ルート2: コンテキスト連携の GWS アドオンを REST API で組む。
  • ルート3: GWS Studio の flows と skills でノーコード自動化。
コードを書く人から書かない人まで、3つの道が用意されている！

コードでつなぐ —— Apps Script とアドオン

Apps Script から呼ぶ

ルート1: REST API 経由

  • Apps Script のコードから、REST API を使って Agent Runtime のエージェントに依頼を出す。
  • Gmail のメール送信や Drive の整理など、Workspace の操作をエージェントに任せられる。
  • 「トリガー → エージェント → 実行」の自動の流れが作れる。
// Apps Script から呼ぶイメージ
const res = UrlFetchApp.fetch(
  AGENT_ENDPOINT, { method: 'post',
    payload: JSON.stringify({prompt}) });
いつもの Apps Script に数行足すだけで、エージェントが呼べる！

コンテキスト・アドオン

ルート2: 文脈を渡す UI

  • GWS アドオンは、Gmail や Drive などの画面の中にささる画面を追加する仕組み。
  • 今開いているメールやファイルというその場の文脈を、エージェントに渡せる。
  • アドオンの裏側から Gemini Enterprise の REST API を叩く連携パターン。
「このメールについて」と文脈ごと渡せるのが、アドオン方式の強み！

REST API の橋を渡る

グローバルなagentとの接続

  • Gemini Enterprise 側で育てたグローバルなエージェントを、Workspace のアプリからシームレスに呼ぶ。
  • 橋渡しは REST API。HTTP が話せれば、つなぎ先は選ばない。
  • 呼び出しは管理者が設定したコネクタの権限の範囲で行われる。
「頭脳は GE、現場は GWS」を結ぶ一本の橋。それが REST API！

つなげられる5つ+α

対象の Workspace アプリ

  • Gmail: メールの読み書きや下書き、返答の下準備。
  • Drive: ファイルの検索と整理。
  • Calendar: 予定の確認と調整。
  • Docs と Slides: 文書や資料の作成・編集。
普段使いのアプリ全部が、エージェントの手足になる！

ノーコード —— GWS Studio で自動化

GWS Studio の自動化

コード不要の flows と skills

  • Google Workspace Studio では、flows（フロー）を組み合わせて自動化を組み立てる。
  • skills（スキル）を組み合わせて、エージェントの得意技を増やせる。
  • コードを書かなくてよいので、業務の担当者でも作れる。
プログラムが苦手な人も、画面をポチポチで自動化をつくれる時代！

flows と skills の役割

ノーコードの2つの部品

  • flows: 「きっかけ → 処理 → 結果」の流れを定義する部品。
  • skills: エージェントに覚えさせる得意技。呼び出すと特定の作業を行う。
  • 2つを重ねれば、複雑な業務も部品の組み合わせで表現できる。
# ノーコード自動化のイメージ
flow: 新メールを受信
  → skill: 内容を要約
  → skill: 返信案を作成
「流れ」と「技」を組み合わせるだけ。レゴみたいで楽しそう！

業務ワークフローへの組み込み

エージェントを実務に載せる

  • 説明欄の冒頭が指すのは、まさにエンタープライズ・ワークフローの実現。
  • 定型の依頼 → エージェント処理 → Workspace で実行、の一連の流れを自動で回す。
  • 人が介在するのは最初のきっかけだけ、という状態を目指す。
「依頼したら後は任せた」を実現するのが、エージェントの仕事！

3ルートの使い分け

状況に合わせた選び方

  • きめ細かい制御が要るなら Apps Script + REST API。
  • その場の文脈を渡したいなら コンテキスト・アドオン。
  • 早く簡単に作りたいなら GWS Studio のノーコード。
  • 開発の力 × 業務の知見、で担当を分ける判断もできる。
正解は1つじゃない。「誰が作るか」から逆算して道具を選ぼう！
