増えたのは2つある上限の片方だけ

Anthropicが週の利用の枠50%増枠を8月31日まで延長。毎日使う人の来月の働き方に関わる話を、仕組み・対策・節約術までまとめました。

  • Claude Codeの週の使用の枠が今 1.5倍 になっている
  • ただし期間限定のキャンペーン扱い

  • その2 その1.5倍には 8月31日 という期限がついている
  • その3 期間が終わればプランの標準値に戻ると公式が明記
1.5倍いまだけ
1.0倍9月以降は標準値へ
増えたままにはならないのだ。だから大事なのは増枠そのものより、戻っても困らない使い方の方よ。

  • 5時間ごとにリセットされる枠
  • 1週間分の枠

  • 今回増えたのは 1週間分の枠の方だけ

同じ週の枠でも、もう1段ある

  • 同じ週の枠でも上位モデルは減りが早い
  • 上位モデルには、枠の中にもう1段の上限が用意されていることもある
  • 同じ財布でも出ていく速さが違う
  • 賢いモデルほど、1回あたりの消費も大きい
「Opusばかり選んでた」という人は、週の枠が1.5倍でもモデル別の段に先に当たるかもしれないのだ。

財布に手を入れる入り口は1つじゃない

  • ProとMaxは Claudeアプリ と Claude Code が同じ枠を使う
  • チャットで遊んでいた分も、同じ財布から出ていた
  • Team と Enterprise も1つの契約でアプリと Code の両方を使う形
  • VS Code拡張からの利用は別枠…ではなくターミナルと同じ扱いで数えられる
アプリ / ターミナル / VS Code → 1つの共通ウィンドウ
知らないうちにあちこちから減っていたのだ…。休憩中のチャットも、拡張での修正も、全部同じ枠から出ていたのよ。

枠に当たった瞬間に出るメッセージは3種類

  • ① セッションの上限 = 5時間の枠
  • ② 週の上限 = 1週間の枠
  • ③ モデル別の上限 = 上位モデルのもう1段
  • ①②は全モデル共通のウィンドウ。軽いモデルに変えても戻らない
  • 逃げ道は1つだけ: ③のモデル別上限は切り替えれば作業を続けられる
  • どのメッセージにもリセットされる時刻が表示される
冒頭で「軽いモデルに切り替えたのに1文字も進まないのだ」だったのは①②のパターン。共通ウィンドウには模型の切り替えが効かないのよ。

/usage で「何に使ったか」が見える

  • /usage コマンドを打ってみる
  • 残りのバーだけでなく、使い方の内訳まで出る
  • 割り当てを使った スキル・呼び出した サブエージェント・繋いだ 外部ツール ごとに何%使ったか表示
  • 挙動のフラグ: 長いコンテキスト・キャッシュミス・直近使用量の 10%以上を占めるものにだけ印がつく
  • 細かいものは無視してよい、という意味
  • 画面で W を押せば直近24時間と直近7日を切り替え
犯人が名前で出てくるのだ! なにげなく呼んでいたサブエージェントや外部ツールが、実は枠の大食いだった…なんてことが分かるわ。
12

内訳の数値には注意が1つ

  • この数字はそのパソコンに残った履歴からの算出
  • 別のパソコンで使った分は入っていない
  • ブラウザで使った分も入っていない
  • だから内訳は傾向として見る。残量はバーで見るのが正解
  • いま何が場所を取っているか見たい時は /context コマンド
内訳 = 傾向
残量 = バーで確認
「このPCでは少ないのに枠が減るのだ」という時は、別のPCやブラウザのぶんを思い出して。

なんでこんなに減る? 毎回3つのものが送られる

  • ① ここまでの会話すべて
  • ② 設定ファイルと開いたファイル
  • ③ いま書いた指示
  • いちばん早く育つのが ①の会話全部の部分

よくある1日の例

  • 20個のファイルを読んで、15個の直しを出したセッションを想像して
  • その後の一言は、毎回その全部を背負って飛んでいく
たくさん質問したから減ってたんじゃないのだ。犯人は質問の数じゃなく抱えたままの会話の長さ。ここが1番大きいわ。

休憩とエージェント隊のひっかけ

  • 席を外していた時間は関係ない…と思いきや、関係ある
  • 休憩を挟むと、戻ってきた一通目で キャッシュが外れることがある
  • キャッシュが効く時間は、契約プランなら 1時間
  • 追加のクレジットを使い始めると 5分に縮む
  • 昼ご飯に行くと、帰ってきた一通目が高いのだ
×1普通のセッション
×7エージェントのチーム
エージェントのチームを走らせると、普通のセッションのおよそ7倍行くわよ。知らずに使ったら危ないのだ!

公式の節約術 5つのうち前半

  • ① 切れ目で /clear: 会話を捨てる。真っさらな画面でも通じる指示なら捨ててよい
  • ② 仕事にモデルを合わせる: 切り替えはモデルのコマンド、既定は設定で
  • ③ ファイルを貼らずパスで指す: 貼ったものはその後ずっと全分がわたる

モデルの使い分けの目安

  • Opusは1回のやり取りで Sonnetの数倍
  • 普段はSonnet。名前を変えるだけの作業はHaikuで十分
  • 長いログは 20〜30秒に切ってから貼る。落とし穴: @ をつけると全分が入る
「もったいない気がするのだ」→ 判定の仕方が親切なのよ。1から書いたつもりで通じるか、それが捨てる基準なのだ。
16

公式の節約術 後半

  • ④ CLAUDE.mdを絞る: 毎回いちばん先にくっついてくるから、場所を取り続ける
  • 目安は 200行以内。同じことを2回直した時だけ書きたす
  • 古いメモはないメモより悪い。間違った方へ導くから、残す方が高くつく
  • ⑤ 大きな変更の前にプランモード: 計画は数百、作り直しは数千
  • 先に見せてもらう方が結局やすい
  • 計画と実行を分ける オーカスプラン という設定も（使えるモデルはアカウント次第）
「エラーの画面を丸ごと貼ってたのだ」みたいな癖は、⑤と③でまとめて直せるわよ。地図を描いてから壊すのが結局はやいのだ。

まとめ: 買っているのは「順番」

  • 増えたのは 1週間分の枠だけ。期限は 8月31日。5時間の方は増えていない
  • 枠は入り口をまたいで共通。モデルを変えても戻らない。クレジット追加か切り替えで対応
  • 減らすこつは会話を長く持たないこと。ここが1番きく
  • 月々払っているのは機能ではなく容量の順番。順番は今週たまたま良くなっているだけ
  • いま週やることは1つ: /usage を打って、自分の内訳を見ること
悪くなっても回る形に、いまのうちに直しておきなさい。
「2人で1つの画面を使えば枠も半分で済むのだ」→ それ、私の枠を狙っているでしょう。…ふ、その発想は嫌いじゃないわよ。
