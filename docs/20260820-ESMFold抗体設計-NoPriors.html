BioHub —— オープンな発見システム

科学発見のためのインフラ

  • ESMFold は BioHub という、オープンなシステムの一部。
  • タンパク質生物学での科学の発見を、誰でもできる形にする狙い。
  • 公開された資源だから、世界中の研究者が検証・再現できる。
  • 1社の閉じた成果ではなく、コミュニティ全体で育てる設計。
「オープン」であること自体が、発見のスピードを上げる装置になる。

11億以上を折りたたむ規模感

Folded over 1.1 billion proteins

  • 学習済みモデルで 11億以上のタンパク質を折りたたんだ。
  • それぞれの立体構造を予測し、丸ごとデータベース化。
  • ゲノム配列から得られる、機能が未知のタンパク質まで対象。
  • ヒトのタンパク質は2万種程度。11億は、けた違いのスケール。
# 規模の比較
ヒトのタンパク質  ≈  2万種
ESMFold が折りたたみ ≈ 11億以上
# 約5万倍の世界をまるごと予測
地球上のほぼ全ゲノムに潜むタンパク質を、まるごと折りたたんだ規模感！

全ベンチマークで SOTA

State of the Art の略

  • 構造予測の全ベンチマークでSOTA（最高精度）を達成。
  • 得意分野だけではなく、すべての指標でトップ。
  • 精度だけでなく速度でも、従来手法を上回る。
  • 11億の折りたたみを現実にしたのは、この圧倒的な速さ。
「全部で1位」—— これが汎用モデルの底力。

仕組み —— 汎用モデルは「ワールドモデル」になる

構造予測と、特徴の特定

11億を「つなぐ」発見

  • 11億の構造を予測しただけでなく、それらをつなぐ特徴を特定。
  • 似た形のタンパク質どうしの関係が、学習の中から見えてくる。
  • 個別の構造を超えて、タンパク質の系譜がつかめる。
  • 未知の機能を持つ候補の見当がつけやすくなる。
バラバラの構造が、1枚の大きな地図につながっていく。

タンパク質生物学の汎用モデル

「本当に汎用的」であること

  • 特定のタスク用ではなく、タンパク質生物学全体をまるごと理解するモデル。
  • GPT が「汎用言語モデル」であるように、ESM は汎用生物学モデル。
  • 1つのモデルで構造予測・機能推定・設計までこなす。
  • Rives いわく「一番エキサイティングなのは、ここ」。
専門特化ではなく「まるごと理解」。LLMの成功の再現を、生物学で狙っている。

ワールドモデルとして使う

世界の縮図を計算機の中に

  • タンパク質の世界を学びこんだワールドモデルとして使える。
  • 実験で世界を探索する代わりに、モデルの中で探索できる。
  • 現実の制約——時間・コスト・設備——から解放される。
  • 「もしもの配列」を、安全に試せる。
ゲームAIがゲームの世界を学んだように、ESMはタンパク質の世界を学んだ。

設計空間を探索する

Search the space of the world model

  • ワールドモデルの空間を検索して、新しいタンパク質を設計できる。
  • 可能性のある配列の海から、目的に合うものを探し出す。
  • 生成 → 評価 → 絞り込みのループを計算機の中で回す。
  • 実験で確かめるのは、絞り込んだ最終候補だけでよくなる。
# 設計のループ（計算機の中で完結）
候補を生成 → モデルで評価
        ↑            ↓

探索の場が「実験室」から「モデル空間」へ移った、というのが本質。

驚き —— 教えていないのに、抗体が設計できる

抗体用に設計していない

We didn't design a model for antibodies

  • ここが最大のポイント: チームは抗体用のモデルを設計していない。
  • 抗体のデータで特化訓練をしたわけでもない。
  • それなのに、抗体の設計ができてしまった。
  • これが動画タイトル「自分で抗体を学んだモデル」の由来。
誰も教えていないのに、できてしまった。創発の典型例。

特定の標的も設定していない

1つのターゲットに絞らない設計

  • 「この標的（ターゲット）に結合する」という目的も与えていない。
  • 狙った1つの分子に結合するよう、特別に作り込んだモデルではない。
  • 従来の抗体エンジニアリングは、標的特化が当たり前だった。
  • ESMFold はその逆を行き、汎用性だけを追求した。
# 設計思想の対比
従来: 標的を1つ決める → そこ向けに特化
ESMFold: 標的ゼロ → タンパク質をまるごと理解
「的を絞らない」ことが、結果的にどんな的にも対応できる力を生んだ。

ただ「理解する」だけのモデル

デザインのゴールは理解そのもの

  • 設計のゴールは、タンパク質を理解することだけだった。
  • 人間にたとえれば、文章の読み書きを学んだら、商売文も書けた、に近い。
  • 基礎の理解が、予想外の応用能力を生んだ。
  • 下のカードで見る創発への布石となる発言。
「理解」に徹したモデルが、「設計」までできる。LLMとそっくり同じ構図。

タンパク質設計の創発

Emergent Property（創発的特性）

  • 理解だけを教えたはずが、設計能力が創発的特性として現れた。
  • LLMで話題になった「能力の創発」と同じ現象が、バイオで起きた。
  • 訓練していない抗体設計が、モデルの中に自然に存在している。
  • 汎用性への投資が、想定外のリターンを返してきた形。
# 創発の構図
入力: タンパク質への理解のみ
出力: 抗体設計能力（教えていないのに）
# "protein design as an
   emergent property"
Rives の言葉: 「タンパク質設計が、創発的な性質として得られる」。

転換 —— 実験室から計算インスタンスへ

従来の実験の大変さ

Intensive laboratory experiments

  • 従来、抗体づくりは実験室での力仕事だった。
  • 数十万〜数百万の抗体をスクリーニングする必要があった。
  • ハイスループットスクリーニングという大がかりな設備が必須。
  • 時間もコストも、非常に重いプロセス。
「当たり」を探すのに、百万単位の引き出しを全部開ける時代。

スクリーニングとの比較

実験 vs 計算、どこが変わる？

  • 実験: 数十万〜数百万を物理的にふるいにかける。
  • 計算: モデル内で生成して、候補を絞り込む。
  • 実験の前段を計算に置き換え、探索コストが激減。
  • 残る実験は、最終候補の検証だけになる。
# 探索のしかた
実験: 巨大なライブラリ → 全数スクリーニング
計算: モデル空間 → 生成で候補を直接提案
「全部試す」から「良いのを出す」へ。探索の発想が180度変わる。

計算で抗体を生成

Spin up an instance and compute

  • Rives の言葉: 「インスタンスを起動して計算すれば、抗体を生成できる」。
  • 実験室の設備ではなく、クラウドの計算資源で動く。
  • スクリーニングの規模の問題が、計算時間の問題に変わる。
  • 設計 → 検証のサイクルが、劇的に速くなる。
抗体が「実験品」から「計算の出力」になった瞬間。

展望 —— 創薬とオープンサイエンスの未来

創薬とオープンの意義

バイオ×AI の行き先

  • 抗体医薬の探索コストが下がれば、創薬のハードルも下がる。
  • 患者数が少ない希少疾患への抗体も、狙いやすくなる。
  • オープンなシステムだから、世界中の研究者が参加できる。
  • BioHub の公開が、集団知的な発見を呼び込む。
「理解するAI」×「公開される基盤」—— この組み合わせが次の十年を作る。
