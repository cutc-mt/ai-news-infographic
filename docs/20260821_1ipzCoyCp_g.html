Prime Agent vs Hermes
長くて複雑なAIタスク、どっちが強い?

Julian Goldie SEO の動画を、グラフィックレコーディング風にまとめました

2026年8月20日公開 / 動画の長さ 0:53

#01

エージェントが「自分を教える」時代

動画の出発点

  • AIエージェントが自己学習できるようになると、話が変わってくる
  • 教わったことで自分をアップデートする = teach itself
  • ただし「何をどう学んだか」が見えないと、あとで困る
学習するエージェントには、記録がセットで欲しいんだよね。
#02

学習には audit trail を

欲しくなる機能

  • 教えた内容のaudit trail = 監査できる履歴
  • 「どの教育で、どんな挙動が変わったか」をあとから検証
  • 変な学習をしても、記録があれば原因を追える
「たぶん大丈夫」じゃなくて、証拠で確かめたい。
#03

2つのエージェント、まったく別物

動画の結論から言うと

  • Hermes = 毎日そばにいる相棒タイプ
  • Prime Agent = 長時間の重い仕事を仕切るタイプ
  • 働き方も、使いどころも別ジャンル
  • 優劣ではなく使い分けの話
どっちが良いかより、何に使うかが先!
#04

この記事の読み方

進む道すじ

  • 自己学習と audit trail の話
  • Hermes が得意な日常の相棒シーン
  • Prime Agent が得意な長時間の重仕事
  • 証拠を残す quality gates の中身
最後まで読むと、選び方がわかるはず。
#05

Hermes は毎日の相棒

得意領域

  • 「daily companion」として光る
  • 普段づかいの、軽やかな依頼に最適
  • 朝から夜まで、ずっとそばにいる使い方
  • 迷わず気軽に話すのがちょうどいい
朝のコーヒーと一緒に、みたいな存在感。
#06

朝は plain language で予定を聞く

morning briefing

  • 朝いちばんに今日の予定をブリーフィング
  • 命令じゃなくふつうの言葉で指定できる
  • 「今日の流れを教えて」の一言で概要をつかむ
あなた: 「今日の予定を、ふつうの言葉で
       朝いちばんにまとめて」
Hermes: 「10時から会議、14時は資料の締切…」
特殊な書式を覚えなくていいのが楽。
#07

会議の合間にスマホから依頼

隙間時間の活用

  • 会議と会議のすき間にタスクを投げる
  • スマホからぽんと送信するだけ
  • 移動中や待ち時間も作業が進む
  • PCを開かないまま依頼だけ完了
「思い立った時に送る」がすべて。
#08

見張りを頼んでメッセージで受け取る

watch & notify

  • 何かをウォッチしておいてもらう
  • 変化があればメッセージで知らせが来る
  • 自分は見張りから解放される
  • 「見ててね」の一言で見守り完了
お知らせが来るまで、自分の仕事に集中!
#09

Prime Agent は重い仕事向け

得意領域

  • long heavy work = 長くて重い作業
  • しかも成否を検証できる仕事
  • 日常の相棒ではなく、現場監督みたいな立ち位置
  • Hermes とは守備範囲が別
ヘルメットをかぶって、長期戦へ。
#10

数時間ぶん回すジョブ

hours-long jobs

  • ジョブが数時間動き続ける世界
  • 見ている間に終わらない = 放置してよい設計
  • 「速い返事」より最後までやり切る力
  • 人間は結果だけ受け取る
放っておしても途中で迷子にならない、が大事。
#11

巨大なファイル山を処理

huge pile of files

  • 大量のファイルを一気に渡す
  • 1件ずつ手で見るには多すぎる量
  • 変換・整理・点検をまるごと任せる
job: 全ファイル点検
input: ./山のようなドキュメント群
scope: 数百〜数千ファイル
ファイルの山は、エージェントの得意ステージ。
#12

普通の context window は爆発する

会話が壊れる問題

  • あの量を会話で処理するとcontext window が破裂
  • 長い対話は前の方を忘れるのがおち
  • 「チャットでがんばる」には限界がある
  • だから設計そのものを変える必要があった
会話で粘るアプローチは、量で負ける。
#13

「本当に終わった」を証明したい

proof of completion

  • 数時間後、「終わりました」をうのみにできる?
  • 重い仕事ほど完了の証拠が要る
  • 信用のカタチが検証可能な記録になる
  • この「証拠」パートが Prime の核
「たぶん終わった」は仕事じゃない。検印が欲しい。
#14

slow-bounded 自律モード

Prime の動き方

  • slow: 急かさず、じっくり進む
  • bounded: 区切りと境界が決まっている
  • その中で自律して着実に動く
  • 速さより確かさを取る設計
亀のように、でも外に出ないように走る。
#15

quality gates: 合格するまで終われない

本物のチェック

  • 通過しないと完了を名乗れない関所
  • 「らしい」ではなく実在する検査
  • エージェント側でdone の定義が固定される
quality_gates:
  - 全ファイル処理済みか
  - 出力の形式チェック
  - エラー件数ゼロ
→ 合格するまで "done" は出せない
門番に合格印をもらうまで、帰宅できない!
#16

Hermes には無い、他にも無い

動画の指摘

  • Hermes には、この仕組みは実質ない
  • 他のエージェントにも同じものは無いと強調
  • つまり Prime 独自の差別化ポイント
  • 長く複雑なタスクで選ぶなら、ここが決め手
「Nothing else has that」— これが動画の肝。
#17

使い分け早見チャート

どっちを選ぶ?

  • 朝のブリーフィング → Hermes
  • 隙間時間の依頼 → Hermes
  • 数時間のバッチ処理 → Prime
  • 大量ファイルの一括処理 → Prime
  • 完了証明が要る仕事 → Prime
日常は相棒に、重仕事は門番に。住み分けが正解。
#18
