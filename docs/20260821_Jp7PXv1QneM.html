ソフトウェアは、もう当て推量じゃない
DeepSeek Harnessが変える開発のかたち

37秒のショート動画が伝えた、UIを「粘土」にするという大転換

公開: 2026年8月21日 / Julian Goldie SEO / 37秒ショート

第1章　いままでのソフトウェアは、こうできていた

旧来の常識をまず整理
#01

架空の「平均ユーザー」

いままで作られてきたソフトウェアは、じつは実在しない誰かのために設計されてきた。

  • 多様な人全員を、ひとりの典型にまとめてしまう
  • デザイン判断は、推測と統計の上に成立
  • 結果として、誰にもぴったりではない道具に
「平均的な人」なんて、実際にはいない。ここがすべての始まり！
#02

あなた専用じゃない理由

欲しい機能と、実際に使える機能のあいだには、いつも溝があった。

  • 「このボタン、ここにあってほしいのになあ」
  • 設定を変えても、許された範囲でしか調整できない
  • ない機能は、自分では追加できない
使いにくい…でも我慢するしかない、という時代が長かった。
#03

開発側の苦労

作る側も、見たことのないユーザーの想像を頼りに開発を進めてきた。

  • 要件定義は、思い込みを文書化する作業になりがち
  • フィードバック → 修正のループは、ゆっくりで高コスト
  • 届くころには、ユーザーの必要が変わっている
作る人と使う人の距離が、ずっと埋まらなかった。
#04

静的な道具の限界

出荷された瞬間、ソフトウェアは固定される。これが当たり前だった。

  • UIはかたちが決まった「器」であり続けた
  • 使う側が道具に合わせる構図が、何十年も続いた
  • 変化するのは、更新が来たときだけ
道具が人に合わせる。これが、この先の話。
ここに、DeepSeek Harness が登場する

第2章　インターフェースは、「粘土」である

Harness の核となる比喩
#05

粘土のようなUI

DeepSeek Harness は、画面をこねて変えられるものとして扱う。

  • ボタンもパネルも、柔らかい素材みたいに自由
  • かたちを決めるのは、ことばでの指示
  • 一度決めても、何度でも練り直せる
触って変わる画面。まるで工房の作業台だね。
#06

ことばで描く部品

必要なボタン・パネル・ワークフローを、そのまま言葉で記述する。

  • 「ここに、この作業用のボタンが欲しい」
  • 「この情報だけを並べた画面にして」
  • 「この手順を、ワンクリックの流れにして」
# ことば → 画面
describe("予約を一覧できる
  パネルと、確認ボタン")
お願いするだけで、部品が生えてくる感覚。
#07

ギャップがつぶれる

欲しいと使えるのあいだの距離が、一気に縮まる。

  • 「こうあったらいいな」が、そのまま実現に近づく
  • 発見 → 導入 → 定着の時間が、劇的に短縮
  • 我慢して使う、という選択肢が消えていく
思った瞬間が、使いはじめる瞬間になる。
#08

自分専用のかたち

同じソフトでも、人によって違う姿になるのが自然になる。

  • あなたの作業の流れに、画面が従う
  • 見た目も構成も、好みで組み替え自由
  • 「みんな同じ」から「それぞれ最適」へ
道具の側が、指紋のようにその人らしい形に。
個人最適化の先に、エージェント型OSがある

第3章　静かな道具から、働くOSへ

動きだすソフトウェア
#09

エージェントとは

自分で判断し、手を動かすソフトウェアのこと。指示を待つだけじゃない。

  • 状況を見て、次の手を自分で考える
  • 手順の一部を、代理で実行してくれる
  • 繰り返しの作業を、流れとして引き受ける
言われたことをやる道具から、話し合う相手へ。
#10

カスタマイズOS

静的なツールが、自分用に仕立てたエージェント型OSへと変わる。

  • 作業環境そのものが、育つ生き物みたいに
  • 部品を足し、組み替え、捨てる自由
  • OSが、あなたの仕事のやり方を学習していく
使うほどに、自分の仕事ぶりに馴染んでいく。
#11

ことばが力になる

プログラムを書けなくても、説明できることが力になる時代。

  • 欲しいものを言語化する技能が、そのまま開発力に
  • 専門用語よりも、意図の伝え方が鍵
  • 学ぶべきは文法より、望む働きの描写
「ちゃんと説明できる人」が、強くなる。
#12

仕事の速さが変わる

機能追加を待つ時間が消え、生産性の議論自体が変わる。

  • 「改善したい」から「改善した」までが、即日に
  • 複数の道具を、ひとつの流れにまとめられる
  • 作業の無駄を、その場で削れるようになる
ストレスを減らすボタンを、自分で足せる時代。

第4章　つくる人の役割と、この先

37秒の先に見えたもの
#13

開発者の役割変化

コードを書く人に求められるのは、土台と体験の設計へと変わる。

  • 部品そのものより、粘土の質を磨く仕事に
  • ユーザーとの対話を設計する役割が拡大
  • 安全で健全な拡張の筋道を保証する側に
書く人から、育てる人へ。それがこれからの開発者像。
#14

自由と、責任

画面を自由に変えられるのは、嬉しい半面、見えない責任も増える。

  • 便利さは、自分の裁量で手に入る
  • 誤った設定や、壊れた流れも自己責任に
  • 何を足したか記録する習慣が、保険になる
自由度が上がった分、自分の判断が試される。
#15

チームでの使い方

個人だけじゃない。現場ごとに最適な画面を作れるのが強み。

  • 営業向けには、顧客一覧を中心に据える
  • 整備向けには、手順書を前面に置く
  • 良い構成は、共有して再利用できる
役割ごとに、別の道具があるみたいに。
#16

はじめる一歩

難しく考えなくていい。まずは不満を言葉にするところから。

  • 毎日の作業で、引っかかる瞬間を書き出す
  • 理想の画面を、誰かに説明するつもりで書く
  • 小さなパネルから、試しに作ってみる
# 最初の一歩は小さく
try("調子が悪い朝の
  チェックリスト画面")
完璧を目指さず、まず一つの部品から。
最後に、この転換を大きく捉え直す

第5章　当て推量の終わり

まとめと展望
#17

設計の常識が反転

「平均のユーザー」への最適化という発想そのものが、過去のものになる。

  • 多数派のための妥協ではなく、各自のための設計
  • ソフトが個に寄り添うのが、新しい標準に
  • 作り手の推測から、使い手の宣言へ
当て推量で作る時代は、静かに終わっていく。
#18

あなたの番

DeepSeek Harness が示した方向は、誰もが主役になる未来。

  • 今日の不満を、明日の機能に変えてみよう
  • ことばで UI を描く体験は、一度試すと戻れない
  • 道具に合わせる人生は、もうおしまい
#Deepseek #AgenticAI #SoftwareDevelopment #Productivity
欲しいを、そのまま使えるに。さあ、語ってみよう。
