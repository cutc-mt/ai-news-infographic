Hermes Kanbanボードで、自律的なAIチームを作る

〜 タスクを「こなす」AIから、仕事を「まかせる」AIへ 〜

ひとつの依頼 自動で分解 専門ワーカーへ 同時並行で実行 完了まで自動

#01

タスクを終えるAIから、管理するAIへ

いままのAIは「言われた仕事をやる道具」でした。HermesのKanbanボードは、その先を目指します。

  • 従来のAIは、1つずつ指示が必要な「実行係」
  • 次のステージは、ワークフロー管理まで任せるAI
  • 作業の割りふりから進ちょく管理まで、ぜんぶAI側で完結
  • 「AIに使いてもらう」から「AIにまかせる」への発想の転換
チャットで1件ずつお願いする時代は、もう終わりのようです。
仕事の上司役をAIが務める
#02

Kanbanボードとは？

工場やソフトウェア開発で育った「見える化」の手法。カードを列に動かして、仕事の流れを追います。

  • 仕事をカードとして切り出す
  • 「未着手 → 進行中 → 完了」のような列を流れる
  • ボード全体を見れば、見える化で状況がひと目で分かる
  • 人間のチームが使ってきた手法を、AIチームにも応用
未着手
進行中
完了
Hermesでは、このボードの操作そのものをAIがやるのがポイント！
#03

Hermes Agentという土台

Nous Researchが開発するエージェント基盤「Hermes」。Kanbanボードは、その協調機能の中心です。

  • 開発元は Nous Research
  • スキルやプラグインで、機能を拡張できる設計
  • 親となるAIが、子のワーカーAIへ仕事をふれる多段構造
  • CLIから対話しながら、ボードを運用できるのが実際の使い方
ドキュメントは hermes-agent.nousresearch.com/docs で公開中。
公式Docs
#04

自動タスク分解

大きな依頼を渡すだけで、AIが自分で小さな仕事へ切り分けてくれます。

  • 「記事を書いて」のようなざっくり依頼を出すだけ
  • 調査・構成・執筆・校正などの子タスクへ自動分割
  • 切り出し方の設計は人間が不要。AIが粒度を判断
  • 分解の手間がゼロになり、立ち上げの速さが段ちがい
頼んだそばからカードがずらり。この感覚が新しいんです。
やるべき事が自動でリスト化
#05

専門特化ワーカーエージェント

分割されたタスクは、それぞれ得意分野を持つワーカーAIに割り当てられます。

  • 調査係: 情報を集めて、根拠をそろえる
  • 執筆係: 構成に沿って、原稿を書き上げる
  • 実装係: コードを書いて、動かして直す
  • 検査係: できあがりを確かめて品質を守る
「全員が何でも屋」ではなく、
役割を持った專門家チームが組み上がります。
#06

同時並行で、はやく回す

ワーカーたちは「同時に（simultaneously）」動きます。順番待ちの列が、消えるんです。

  • 複数のタスクを並列実行でいっきに消化
  • 1つ終わって次へ、という直列の待ち時間が不要
  • 調査しながら執筆し、実装しながら検査という並走
  • トータルの所要時間が、大きく縮むのが並列の利点
10人ぶんの仕事を、同じ時間で回せる。
これが自律チームの速度です。
#07

手入力ゼロの世界

動画の主張は「eliminates manual input」。手作業での入力・ふり分けから、解放されます。

  • カードの登録や担当ふりを、手で打つ必要なし
  • 移動・更新もシステム側で自動反映
  • 人間は細かい指示を出さず、結果だけ受け取る
  • 入力ミスや転記のもれといった、人的ミスも減る
「ボードの更新、忘れてた…」
という悩みともおさらばです。
#08

自分で回るチーム

動画のキーワードは「self-running team」。押し続けなくても、自分で回り続ける組織です。

  • 最初のゴール設定だけ人間が渡す
  • あとは計画→実行→確認のサイクルが自動で回る
  • つまずいたら別の道を選ぶなど、自己修正も期待
  • 寝ている間も、ボード上の仕事は進み続ける
朝起きたら完了カードが並んでいる…
そんな運用が現実になるかも。
24時間体制の相棒
#09

人間の介入なしで完結

「without human intervention」。複雑なプロジェクト管理を、人の手をかけずにこなします。

  • 進行中に確認を求められる場面が減る
  • 段取り・ふり分け・取りまとめをAIが一括
  • 人間は判断の大きい場所だけ、関与すればよい設計
  • とはいえ最終チェックは人間が持つのが、安全な運用
完全放置はリスクも。要所要所の点検を、わたしたちの側に残すのが良さそうです。
#10

複雑なプロジェクト管理をこなす

「complex project management」。かんたんな雑務ではなく、組み合わせのある仕事をまかせます。

  • 依存関係のあるタスクも、順番を制御しながら処理
  • 進ちょくに合わせて、次の一手を組み替え
  • 制作・開発・調査など、複数の仕事の線を同時に追跡
  • 納期や品質の基準も、ボードの設計に込められる
「誰が・いつ・何を」の管理表を、
AIが自分で保守する形です。
#11

ひとつのAIツールで完結

動画の表現は「a single AI tool」。ばらばらのツールを、いくつもつなぎ合わせる必要がありません。

  • チャット・ボード・ワーカー実行が同じ道具の中
  • 外部サービスとの連携づくりも、最初から不要
  • ツールの重複購入や、管理の手間が減ってコスト整理
  • 覚える操作が少なく、導入のハードルが低い
「あれもこれも契約して組み合わせる」
という時代からの卒業ですね。
#12

オーケストレーションの心臓部

親となるAIが指揮者（オーケストレーター）になり、ボードを通して部隊をふるいます。

  • 親AIが全体を見渡す指揮役に
  • 子AIへカードを渡す＝仕事の受け渡し
  • 結果をボードに集めて、次の判断へつなげる
  • 人間⇔AI間の往復を減らし、AI⇔AIの連携中心へ
指揮者がいて、奏者がいる。
交響楽団のようなチーム運営です。
#13

進ちょくの見える化

自動で回すほど、見える化は大事。ボードが、チームのいまの姿を教えてくれます。

  • 列のカード数で、詰まり箇所が分かる
  • 進行中の列が空なら、新ふり分けの合図
  • 各ワーカーの得意・不得意も、実績から見えてくる
  • 完了列の伸びが、そのまま成果の記録に
未着手
進行中
完了
動いている様子を「見れる」安心感は、放置運用の前提です。
#14

ボードはこんな感じ

コマンド1つでボードが立ち上がり、カードが流れていく。イメージを疑似コードで。

  • 対話の中で、計画→ふり分けまで一気に進む
  • 子タスクごとにカードが自動で起票
  • ワーカーが呼ばれて、並列スタート
# Hermesにまるごとお任せ
$ hermes "新商品のLPを1本つくって"
  → ボードを自動生成
  → 調査 / 原稿 / デザイン / 実装…
  → ワーカー同時進行 → 完了
打つのは、最初のひとことだけ。
あとは結果待ち！
#15

導入のメリット: 時間とお金

動画のハッシュタグは #ProductivityHacks。生産性の観点で、うれしいことがそろいます。

  • 段取りづくりの時間が、ほぼゼロに
  • 外注や人手の追加なしで、チームぶんの処理能力
  • 定型的な業務を、つねに自動で運用
  • 浮いた時間を、判断や企画といった人間の仕事へ
「時間を買う」最もかしこい形が、
こういうことかもしれません。
#16

どんな場面で効く？

チャンネルの得意分野を思い浮かべると、使いどころが見えてきます。

  • コンテンツ制作: 記事の企画から校正まで一気通貫
  • SEO対策: キーワード調査と下書きを並行で
  • 開発の下支え: 実装・試験・直しをワーカー分割
  • 日次の定型: 情報収集やまとめを毎朝 automatically
「繰り返し起こる仕事」から順に、
ボードに載せてみるのがおすすめ。
#17

注意点と、より良く回すコツ

自律運用は強力な反面、人間の側の設計と点検が、結果の質を左右します。

  • ゴールは具体的に。「良い記事」より「1,500字・比較軸つき」
  • 完了カードは必ず抽查。品質のゆらぎを早めに発見
  • APIキーなど権限の範囲は、最初に絞っておく
  • うまくいったふり分け方を、次の設計に再利用
「まかせる」と「ほったらかし」は、ちがいますよ〜。
#18

まとめ: あなたの「相棒チーム」へ

58秒の動画が描いた未来。それは、AIが上司と部隊を兼ねる、小さな会社のようなものです。

  • 専門ワーカーが同時並行で、速く仕上げる
  • 人間は、方向を示す役に専念できる
  • まずは小さな案件で試し運用から始めてみよう
あなたの指示ひとつで動く
