「引きちぎって、組み替える」

動画の冒頭では、エージェントをRip apart（引きちぎる）して、一つずつ組み直す、と表現されます。

できること

  • 思考（脳）を、別のモデルへ交換
  • 記憶（メモリ）の保存先を、まるごと入れ替える
  • 道具（ツール）も、必要に応じて追加・交換
  • 「一体型で、中が見えない」構成とは、ここでお別れ
全部乗りのクローズドな道具ではなく、自分で選んで組み立てる時代が来た、という話ですね。

Harness（ハーネス）とは

「ハーネス」は、もとは馬具のこと。体を支えて、力を外に伝えるための仕組みです。

AIにおいては

  • LLMを、実際の作業へつなぐ骨組み
  • モデルそのものではなく、モデルを動かす枠組み
  • 実行・道具・記憶を、まとめて管理する層
  • DeepSeekが公式に、オープンな形で提供
馬で言うハーネスは「馬の力を車に伝える道具」。AI版も同じで、脳の力を仕事に伝える装置です。

脳 vs 体 — 分ける発想

動画 0:44〜 の核心。エージェントを脳と体に切り分けて考えます。

脳（判断する） 体（動く）
  • 脳 = LLM。計画を立てて、判断する
  • 体 = Harness。実際に手を動かす
  • 両者を分けるので、別々に進化できる
  • どちらか一方だけ、最新へ交換可能に
脳だけあっても動けない。体だけあっても判断できない。分けて考えるのが設計の出発点です。
0:44 Harness explained

脳と体 — それぞれの中身

脳の側：LLMの役割

LLMは判断と計画を担当。考える部分に集中します。

主な仕事

  • 文章を書き、読み解き、まとめる
  • 手順を立てて、次の一手を決める
  • 設定を書き換えるだけで脳を交換できる
  • 新モデル登場時も、追従がかんたん
# 脳（LLM）の差し替えイメージ
model:
  provider: deepseek
  name:     v4-pro
  context:  1,000,000 tokens
「今日から別の脳で考えよう」が、設定ひとつで叶う。脳は部品なんですね。

体の側：Harnessの役割

Harnessは実行を担当。頭の中の計画を、現実の作業へ変えます。

実際にやること

  • 道具（ツール）を呼び出して、実行する
  • 記憶の保存と、必要なときの呼び出し
  • 画面（UI）の描画と、操作の受け付け
  • 失敗したら、やり直す仕組みも体の側
「考えた」で終わらせず、最後までやるのが体の役割。地味ですが、一番大事な部分です。

すべてはプラグインという思想

1:47〜 のビッグアイデア。Everything's a plugin — 何もかも、プラグイン。

  • 記憶も、道具も、骨組みさえも交換対象
  • 「絶対に変えられない部分」をなくす設計
  • 誰かが作った部品を、持ってきて使える
  • 自分の道具箱を、組み合わせで作る
スマホにアプリを足す感覚で、エージェントの能力を足す。それがこの思想の核心です。

プラグイン化のメリット

「全部が部品」になると、うれしいことが三つあります。

  • 追従が速い: 新モデルが出たら、すぐ交換
  • 原因が切り分けやすい: 部品ごとに試せる
  • 資産の再利用: みんなの部品を使い回せる
  • 壊れたら、その部品だけを直せばよい
全部つながった黒い箱だと、直すにも一から。部品化は、保守の味方ですね。
1:47 Everything's a plugin

差し替えの実際 — 何を入れ替えるのか

差し替え例：記憶・道具・脳

動画で示されるswap（交換）の三連。どこからでも変えられます。

  • 記憶 ローカル保存 ↔ クラウド保存
  • 道具 検索・コード実行・ブラウザ操作など
  • 脳 新しいモデルが出たら、すぐ追随
  • 組み合わせ次第で、性格も速度も変わる
# 部品の入れ替えイメージ
memory: local-store  # → cloud-store へ
tools:  [search, code, browser]
brain:  deepseek-v4-pro
「入れ替え」は設定の書き換えだけで済むのがポイント。作り直しは不要です。

4:17 DeepSeek V4 Pro

1Mトークンとエージェント調整

1Mトークンの意味

百万トークン。ひとことで言えば、一度に読める量が桁違いです。

  • 長大な文書を、丸ごと読み込める
  • 長い作業でも、文脈が切れにくい
  • 複数の資料を、同時に参照できる
  • 「途中で要約して詰める」手間が減る
エージェントは作業の履歴をどんどん読み返します。窓が広いほど、忘れずに働けるんですね。

エージェント調整（チューニング）

「agent-tuned」＝働く前提で調整済み。ここが汎用モデルとの違いです。

  • 手順（ステップ）の実行がうまい
  • 道具の呼び出しを、的確に判断
  • 失敗からの立て直し（回復）が得意
  • おしゃべりより、作業に重み
「話す模型」ではなく「働く模型」。Harnessという体と、相性が良い設計です。

4つの実行モード

5:10〜。仕事の内容に合わせて、走らせ方を選べるのが Harness の強み。

  • 軽い作業向けの、速さ重視なモード
  • じっくり調べる、深さ重視なモード
  • 複数の処理を、同時に回すモード
  • 案件ごとに、選んで切り替え
# 切り替えイメージ（詳細は動画本編で）
run:
  mode: "..."      # 4種から選択
  job:  "調査"     # 仕事に合わせる
車の走行モードと同じで、状況で選ぶのが正解。全部盛りにする必要はありません。

ジョブごとの選び方

モード選びの指針は、適材適所のひとことに集まります。

  • 単純な繰り返し → 速く、軽く。無駄なし
  • リサーチ → 深く。思考と道具を組む
  • 量のある処理 → 並列で、一気に進める
  • 重いモードは、コストも増える。見合うかを考えよう
「とりあえず最強設定」より、仕事に合った設定。結果も、コストも変わります。
