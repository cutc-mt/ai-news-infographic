第2章：仕組みを設計する — 検査して書き直させる

解決の型 5:29

AIが文章を書く
書いた直後に機械が検査
引っかかったら警告を返す
AIが自分で文ごと書き直す
  • 人間の注意ではなく書いた直後の検査に切り替える
  • タイミングが命: 保存の瞬間に必ず走る
  • 指示が薄まる問題と無縁になる

Claude Code Hooks とは

  • Claude Code の機能のひとつ
  • 指定したタイミングで自分のコマンドが自動で走る
  • ファイルを保存した瞬間に発火できるのが今回のミソ
  • 設定は JSON に書くだけで、環境にずっと住み着く
// イメージ: settings.json
{
  "hooks": {
    "PostToolUse": [ ... ]
  }
}
「保存」が引き金だから
忘れる暇がないんだ

PostToolUseフックの流れ

  • AIが Write / Edit でファイルを保存
  • PostToolUse が発火し、NGワードと照合
  • 引っかかると「文ごと書き直し」の警告をAI自身に返す
  • 警告を見たAIが、その文をそっくり書き直す
  • 人は最後の仕分けだけ。作業がぐっと減る
警告が返ってくるのは
人間じゃなくAIのほう——ここが肝！

NGルール500本の育て方 8:24

500本
育て上げたNGルールの数
  • ルールは一晩で作らず、日々の校正から育てる
  • 手直しした場所を拾ってはルール化していく
  • ルールが増えると検査の目も細かくなる
  • 自分の文章の癖を、機械に覚えさせる修行
「今日直した」を貯めるのが
一番の近道なんだね

グッドパターンも一緒に育てる

  • NGワードだけじゃなく「良い書き方」の見本も登録
  • 悪い例と良い例が対になると、AIの書き直しもブレにくい
  • 直すべき所と、そのまま良い所の見分け方を機械に教える
  • 検査が賢くなるほど、手直しは減っていく
# ルールのイメージ
- id: prefer-plain
  bad:   "〜と言えます"
  good:  "〜だ"
  fix:   "文ごと書き直し"

シーン別オンオフと集計 11:26

  • 文書全体の集計も出す: どの癖が何回出たか見える化
  • 全体を見てから直す所を決めるので、直し忘れがない
1文だけ見て焦らず、

第4章：環境への組み込みと、実測の結果

検査を2段構えにする 22:21

残っていた癖は1種類だけ

1種類
実測で見つかった直すべき癖
  • その癖とは「AではなくB」の使いすぎ
  • 対比の形が続くと、文章が同じリズムに傾く
  • 直し方はシンプル: 別の言い方に置き換える
  • たった1種類なら、ルール追加も楽なもの
# 例)
"変更ではなく追加" → "追加する(変えない)"
