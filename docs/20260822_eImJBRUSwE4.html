声だけでアプリを作る
「Apollo」の新しいやり方

Julian Goldie SEO ｜ Build apps using nothing but your voice with Apollo.
2026年8月21日公開

Apollo とは何か

  • 声で話すだけでアプリを作れるAIツール
  • 入力は音声だけで完結する
  • 画面は会話で組み立てていく
  • Julian Goldie さんが動画で紹介
Apollo のかたち
  話す ＝ 作る
   → コードも複雑な入力も不要
   → 声が 開発の道具 になる
キーボードを置いて、まず声で伝えてみよう！

非技術者が変わる

  • これまで開発は技術者のものだった
  • Apollo はゲームチェンジャーだと紹介される
  • ノンプログラマーでも制作側になれる
  • アイデアを持つ人の参入障壁が下がる
立場の変化
  今まで：お願いする側
  これから：作る側
   → 技術の壁がぐっと低くなる
「作れない」が理由で諦めなくてよくなる！

要件を声で話す

  • やりたいことを声に出して伝えるだけ
  • 必要なのは要件を言葉にすること
  • 専門用語や難しい記法は不要
  • 普段の話し方でそのまま通じる
伝え方の例
  「タスク管理のアプリが欲しい」
  「一覧と追加ボタンを表示して」
   → 話した内容 がそのまま材料に
説明書を読むより、まず話してみるのが近道！

リアルタイムに組む

  • システムが即座にビルドしてくれる
  • 話しているその場で画面が変わる
  • 完成を待つ待ち時間がほぼない
  • 見て → 話して → 直しての繰り返し
ループの速さ
  話す
   → すぐ表示
   → 気になる部分を すぐ修正
   → 完成まで一気に
考えたそばから形になるのが最大の強み！

ボタンの調整も

  • ボタンのリサイズも会話でOK
  • 「もう少し大きく」と話すだけ
  • 色や配置の微調整も同じやり方
  • 調整はその場で反映される
調整の例
  「登録ボタンを大きくして」
  「もう少し右に動かして」
   → 数値指定なしで 感覚で指示
ピクセル数を考えなくていいのが楽ちん！

区画の移動も

  • ページ内の区画ごと移動できる
  • 「ヘッダーの部分を上に」と伝えるだけ
  • レイアウト変更が会話だけで完結
  • 何度でもやり直しがきく
レイアウト変更
  話す → 区画が動く
   → 見た目を確認
   → また話して調整
   → 納得の配置 まで続けられる
配置の悩みも「話して解決」の時代に！

コードはいらない

  • 1行もコードを書かない設計
  • プログラミングの学び直しも不要
  • ミスの多い手書き作業から解放
  • 作りたい気持ちが最優先になる
必要なもの
  ×  プログラミング言語
  ×  開発環境の準備
  ○  声とアイデア だけ
「コードと格闘する」時代が終わるかも！

難しい入力も不要

  • 複雑なプロンプトエンジニアリング不要
  • 長い文章を練り上げなくていい
  • 「良い入力を書く才能」の壁がなくなる
  • 自然な話し言葉がそのまま武器に
入力のちがい
  従来：技巧をこらした文章
  Apollo：話しかけるだけ
   → 入力の工夫より伝え方がシンプルに
「AIへの聞き方」を勉強しなくてOK！

直感で組む相手

  • Apollo は直感的な相棒だと表現される
  • 指示出しより対話に近い感覚
  • こちらの意図を汲んで動くのが特徴
  • 人と人の共同作業みたいに使える
工具ではなく相棒
  ツール：操作されるもの
  相棒：一緒に考えるもの
   → 話すほど分かり合える
一人で開発しても、一人ぼっちじゃない！

思いつきを形に

  • 頭の中のアイデアが出口を得る
  • 話すだけで動くものになる
  • 小さな思いつきが育ちやすい環境
  • 作る楽しさが戻ってくる
アイデアの行き先
  頭の中 の想像
   → 声 にする
   → 画面の上 に現れる
   → 触って確かめられる
思いついた瞬間が始まりの合図！

会話だけで完成

  • 制作の流れが会話のみで完結
  • 作る → 直す → 仕上げもすべて話して
  • 別のツールを行き来しない
  • 作業は一つの対話の中で
作業の全体像
  企画  → 会話
  制作  → 会話
  調整  → 会話
   → 最初から最後まで 声だけ
ツールの切り替え疲れからおさらば！

ノーコードとの差

  • 従来は部品を組み合わせる作業
  • マウス操作と画面での配置が中心
  • Apollo は声で全部丸ごと指定
  • 操作の学習よりも会話が主役
ノーコードとの比較
  従来：部品を置いて組み立てる
  Apollo：意図を話して組んでもらう
   → 作業より対話に軸足が移動
パズルよりおしゃべり！それが新しいカタチ！

声で扱う利点

  • 話すスピードは入力より速い
  • 両手が空いたまま作業できる
  • 考えながらそのまま口に出せる
  • 操作が苦手な人にもやさしい
声の強み
  速さ  ：入力より速い
  自由  ：手を使わない
  自然  ：思考と直結
   → 伝えるコスト が小さい
考える速さで作れるのが音声の魅力！

前との大きな差

  • 前はコードと格闘する時間が長い
  • 書き方を覚える工程が必須だった
  • Apollo なら話しかけて開始
  • 着手までの距離が大きく縮む
同じ「TODOアプリ」を作る
  従来：学習 → 設計 → 実装
  Apollo：話す → 表示 → 調整
   → 初心者と熟練者の差が縮まる
「やりたいこと」にまっすぐ進める！

活躍する場面

  • 小店主の簡易ツール制作
  • 研修や授業のお手本アプリ
  • 社内の事務の手助けツール
  • 起業の試作品をすぐ試す
向いている使い方
  すぐ欲しい小さな道具
  見せながら作るデモ
   → 速さと手軽さ が生きる場面
「こんなの欲しいな」をその日のうちに！

流れは3ステップ

  • 作りたいものを声で説明する
  • 表示された結果をその場で確認
  • 気になる部分を話して直す
  • これを繰り返して完成へ
作業のループ
  ① 話す
  ② 見る
  ③ 直す
   → この 3拍子 だけで進む
手順がシンプルだから迷わない！

気をつける点

  • 伝え方の精度が結果を左右する
  • 込み入った大型のものは向き不向きあり
  • 騒がしい場所では声が使いにくい
  • 出来上がりは必ず確認を
使いこなしのコツ
  要件は ひとつずつ 伝える
  大きな変更は区切って話す
   → 確認の習慣で手戻りが減る
全部おまかせにせず、確認も忘れずに！
