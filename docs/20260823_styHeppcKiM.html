1. まず、おさらいしよう

従来の生成AIは？

Words Only
できることは「言葉」だけ
  • チャット画面で、文章を生成するだけの存在
  • コードを書いてくれるけど、実行はあなたがする
  • 書かれたコードをコピーして、自分の環境に貼りつけ
  • 動かなかったら、また質問して……のくり返し
AIは「頭脳」はあっても、手と目がなかったんだ！

Claude Code だと？

Agent That Acts
自分でやってくれる
  • 自分でファイルを読み、状況を理解
  • コードを書きかえるのも自分で
  • テストまで回すのも自分で
  • あなたは、指示と最終チェックだけ
同じAIなのに、ここまで差が出るのがふしぎ！

答えは「ハーネス」

The Harness
凄いのは外側の仕組み
  • 中のAI（LLM）は、従来型と同じ「言葉を生成するだけ」
  • その外側に、AIを動かす仕組みがまとめてある
  • たとえるなら、馬をうまく走らせる馬具（ハーネス）
  • この講座は、その仕組みを6つに分けて解説
中身じゃなくて、外側がポイント！ ここが肝！

どこがちがう？

Side by Side
くらべてみよう
項目従来の生成AIClaude Code
コードを書く◯ 書ける◯ 書ける
ファイルを読む× むり◎ 自分で読む
コードを実行× むり◎ 自分で動かす
テストを実行× むり◎ 自分で回す
結果を確認× むり◎ 見て直す
差はハーネスの有無から生まれていた！

2. 仕組みは6つある

① エージェントループ

AIの心臓部
思考→行動→観察の循環
  • 思考：いま何をすべきか考える
  • 行動：ツールを呼び出して動く
  • 観察：結果を見て、つぎを考える
  • これをぐるぐるくり返すのが心臓部
# エージェントループのイメージ
while (ゴール未達成) {
  思考  = LLMに考えさせる
  行動  = ツールを呼び出す
  観察  = 結果を受け取る
}
ひとつひとつは地味でも、回りつづけることが力になる！

② ツール呼び出し

AIの手
言葉を、行動に変える
  • ファイルの読み書きができる
  • コマンド実行ができる
  • AIは「やりたい」を言葉で出し、外側が実行する
  • 手があったから、はじめて
    現実に触れる
// ツール呼び出しの例
LLM「src/app.py を読みたい」
  ↓ ハーネスが実行
read_file("src/app.py")
  ↓ 中身をAIに返す
「手」を貸しただけで、AIが作業員に変わる！

③ フィードバックループ

AIの目
結果を見て、つぎを決める
  • 実行した結果をちゃんと見る
  • 成功なら、つぎの工程へ
  • エラーなら、原因を読んで直す
  • 見る→考える→直すを、自動でくり返す
コードを書く
テストが失敗!
エラーを読んで修正
目があったから、自分のミスに気づけるんだ！

④ コンテキストウィンドウと
コンパクション

記憶の紙
限りある記憶を、賢く使う
  • AIの記憶は、1枚の紙のようなもの
  • 紙の大きさ＝コンテキストウィンドウには限りがある
  • 紙がいっぱいになったら、コンパクションで要約して圧縮
  • むだをけずって、大事な情報だけ残す
ノートを書きなおす感じで、長い作業も続けられる！

⑤ サブエージェント

分身
タスクを、わけて任せる
  • 親のAIが分身をつくり出す
  • 調べる・書く・直すを分担
  • 複数の作業を並行処理できる
  • 結果を親がまとめて、全体をすすめる
親エージェント
分身A ／ 分身B ／ 分身C（いっせいに）
忙しいときは分身にお願い！ 仕事がはやい！

⑥ パーミッション

関所
危ない操作は、とめて守る
  • 安全な操作は、そのまま実行
  • 危険な操作には人間の許可が要る
  • たとえるなら、高山の関所のようなもの
  • 暴走をふせぐ、最後の防衛ライン
# パーミッションの例
ファイルを読む   → 自動で許可
ファイルを消す   → ⚠ 人間に確認
ネットに公開する → ⚠ 人間に確認
自由に働いても、関所があるから安心！

3. それぞれを深掘り

ループの1周を追う

One Loop, Step by Step
「バグを直して」の瞬間
  • 思考：まずテストを実行して様子を見よう
  • 行動：テストコマンドを実行
  • 観察：3件が失敗しているのを発見
  • また思考へ……を、直るまで自動で続ける
人間がやってた試行錯誤を、AIが代わりに！

ツールの実例

Tools in Action
持っている道具
  • Read：ファイルの中身を読む
  • Write：ファイルに書き込む
  • Bash：コマンドを実行する
  • Grep：コードを検索する
# 「この関数どこにある？」の流れ
grep("def calc_total")
  ↓ 見つけたファイルを読む
read("cart/total.py")
  ↓ 書きかえて完成
write("cart/total.py", ...)
道具がそろうと、AIは職人になれる！

見て・読んで・直す

Feedback in Action
エラーとの向き合い方
  • エラー文を逃さず読む
  • 原因のあたりを推理する
  • 直したら、またテストで検証
  • 全部通ったら、ようやく完了！
$ pytest tests/cart.py
FAILED test_total - TypeError
  ↓ AIがエラーを読む
  ↓ 原因: 文字列を数値にしてない
  ↓ 修正してもう一度実行
PASSED ✓ 3 tests passed!
結果を見ないAIは、同じ失敗をくり返す……

記憶の紙って？

Context Window
一度に覚えられる量
  • 会話・コード・実行結果が、ぜんぶ紙に書き込まれる
  • 作業が長いと、紙はあっという間に満杯
  • 古い内容は、要点だけに書きなおし
  • 「何を残すか」が、賢さのわかれ道
紙1枚で長い仕事をするには、要約のコツが大事！

コンパクション中身

Compaction Deep Dive
圧縮のスマートなやり方
  • 長い対話を、要約に置きかえる
  • 決めたこと・直した場所は残す
  • 読んだだけの中身は、消してスッキリ
  • 圧縮後も、ループは続行できる
// 圧縮のイメージ
before: 会話 200ページ分
after:  「やること」「直した場所」
        「きめた方針」だけのメモ
記憶をジップにまとめるみたいで、おトク！

分身の働き方

Parallel Agents
任せ方のコツ
  • 仕事を切り分けて、指示を渡す
  • 分身たちは、それぞれ独立して調査
  • 同時にすすむから、時短になる
  • 報告を集めて、親が統合する
親「3つの機能を調べて！」
A: API仕様 / B: 画面 / C: テスト
順番にやると3時間が、並行なら1時間かも！
