今回のテーマ: 三層スキル設計

はじめに: 三層スキル設計

  • テーマは三層スキル設計。以前「スキルを改造した」動画のさらに先を行く内容
  • スキルをさらに細分化し、コストとトークン消費を抑えつつ専門化を進める
  • 対象は Codex や Claude Code などエージェント型AIのユーザー
  • 長期開発でスキルを鍛え続ける「スキルトレーニング」という運用思想
AIの限界を突破する鍵は、スキルの「置き場所」にあった!

誰に効く? 長期開発エージェント

  • 1つのアプリを長期間アップデートし続けるケース
  • ある分野を研究し続けるケース。継続タスクで真価を発揮
  • こうした作業ではスキルを鍛えていく運用が欠かせない
  • 作業者ごとに異なるタスクでも、鍛えたスキルが資産になる
長く続けるほど、スキルが育つ仕組みが必要なんだ。

問題: スキルの肥大化

  • 長期開発で鍛えるほど、スキルはどんどん大きくなる
  • 最初の読み込みでトークンを大量消費。コストがかさむ
  • 成功・失敗の知見はスキル化したい。でもコストは抑えたい、というジレンマ
  • 「スキルをどれだけ作ったか」より、いかに軽く保つかが鍵
知見をため込むと、読み込みが重い…。ここをどう解くかが核心!

ハーネスからオービタルへ

  • ハーネスとは馬を繋ぐ馬具。スキルを「装着」する従来のイメージ
  • オービタルは衛星のように、スキルを遠くで軌道回転させる発想
  • 遠くに置いてルーティング。前回はここまで。今回はルーティングもやめ、完全に切り離す
  • 衛星的にぐるぐる回り、好きな時に装着・遠隔操作できるイメージ
繋ぎっぱなしの馬具より、衛星のほうが自由で軽い!

オービタル・アーキテクチャの全体像

中心にはエージェント。その周囲をスキルが衛星のように回ります。

第1層から第3層へと、層が外に行くほど配置は遠く、用途が局所的に。

経験の適用範囲=スキルの配置場所。これがこの設計の確信(核心)です。

上に行くほど汎用的、下に行くほど長期・専門的になります。

エージェント
内側: ノーマル / 中間: 分野 / 外側: タスク

三層構造を詳しく

第1層: ノーマルスキル

  • いつも使うものはスキルフォルダに普通に置くだけ
  • 日常の全作業向け。配置も発動もノーマル
  • 「かなり使う」ものをここへ。例えば説明するスキルなど
  • Claude の説明が長くて難しいなら、自分用にカスタマイズしたスキルを置くのも◎
まずは普通の置き方。ここが土台になるよ。

第2層: 分野スキル(ルーティング)

  • コーディング用など特定分野限定のスキル
  • スキルは必ず name と description が読み込まれる。これが無駄になる場面がある
  • ライティング時のコーディングスキルは不要 → ルータースキル1つだけ配置し、遠くへ飛ばす
  • スキルアーカイブを分野・ジャンルごとに切り分け、AI に探させて選ばせる
読み込まれるのは毎回ルーターだけ。ここが節約のコツ!

第3層: タスクスキル(オービタル)

  • 特定の研究・アプリでしか使わない、きめ細かいスキル
  • スレッド接続やプロジェクト配置で発火。普通の環境では全く働かない
  • コードレビュー・バグレビュー・セキュリティレビューを1つずつ細分化
  • 特定アプリ専用スキル。フォルダでもファイルでも、時と場合で柔軟に作る
完全分離・遠隔操作。好きな時に呼び出すのがオービタル流!

実演: Codex のスキル発動

  • 自分の Codex 環境では、スキル置き場にルータースキル1つだけ
  • ここから遠くへ飛ばす構成でも、スキルは普通に発動する
  • ルーター用の MD ファイルはフォルダ外に置く手も。将来の肥大化に備えた配置
  • 毎回読み込まれるのはルーターだけ。細分化した先から AI が選んでいく
skills/
└── router/        ← 読み込まれるのは毎回ここだけ
    └── SKILL.md
(実体は遠くのアーカイブへ)
ルーター1つでも、発動はバッチリ!

三層スキル設計 まとめ表

層 ノーマルスキル(第1層) 分野スキル(第2層) タスクスキル(第3層)
適用範囲 全作業・汎用 分野・ジャンル限定(コーディング等) 特定の研究・アプリのみ
保存場所 通常のスキルフォルダ クラウドの分野フォルダ(iCloud / Googleドライブ) フォルダ・プロジェクト・スレッド
接続方法 普通に置いておく ルーティング(ルータースキル経由) スレッド接続 / プロジェクトで発火
汎用性 高い(非局所的) 中間。分野内で広め 低い(完全に局所的)
期間 日常の繰り返し 中〜長期の開発 超長期の継続開発
経験の適用範囲が、そのままスキルの配置場所になる。これが核心!

スキルの「身分」が動く

  • 使われないスキルは自動的に角落び・身分が下がる
  • よく使うスキルは AI が選び、身分が上がり肥大化していく
  • 身分は人間が決めても、AI が決めてもOK。うまくいかなければ人間が制御
  • 使わないものは自然に淘汰され、構成が勝手に整理される
よく使うスキルが貴族に。放置すると平民に…面白い!

実践ノウハウ

実例: 論文専用スキル

  • ある論文でしか使わないスキルを大量に作成
  • スキルの中にさらにフォルダを作って細分化。太っても AI が該当ファイルだけ見る
  • 1つのファイルに全部入れると消費が激しく、コンテキストの汚れの元に
  • 計算スキル「ペーパーファースト」も計算方法ごとに分けて AI に選ばせる
paper-xxx/
├── skills/
│   ├── calc-paper-first/
│   │   ├── method-a/SKILL.md
│   │   └── method-b/SKILL.md
│   └── review/
│       ├── bug-review/SKILL.md
│       └── security-review/SKILL.md
細分化しておけば、AI は必要な1ファイルだけを見てくれる。

原子的な使い方

  • プロンプトで直接指定してスキルを使う方法
  • 最初にまとめて読み込ませる方式も、ひとつの原子的なやり方
  • スレッドやプロジェクトに固定化しておけば、毎度の指定も不要
  • マニアックな発火のさせ方もあり、それは続編で解説予定
発火のさせ方の工夫で、さらに便利になるよ。

「スキルトレーニングして」と命令

  • AI にスキルフォルダの場所を教えるだけで、勝手にトレーニング開始
  • 該当ファイルを選び、どれをアップデートするかを AI が判断
  • 読み込んで更新するので、スキルを使うループが回る
  • 良い知見ができたら「アップデートしろ」と伝えるだけで自動改善
プロンプト例:
「このフォルダのスキルを
 スキルトレーニングして」
→ AI が該当ファイルを選択し
   アップデートを実行
AI が自分で学んで育つ。飼い主は命令するだけ!

ChatGPT × Googleドライブ

  • 最近はChatGPT に回帰。改めてその実力を実感中
  • ChatGPT × Googleドライブを接続し、そこにスキルを置く運用が超便利
  • この使い方ではCodex より強い場面もある
  • スキル=コンテキスト。プロンプトと本質は同じで、特殊に「スキル」と読んでいるだけ
ツールの使い分けも、スキル設計の一部なんだ。

スキルトレーニングループ

良いサイクルを回す

  • スキルを使って作業 → 成功・失敗から知見が集まる
  • 知見をスキルに反映 → アップデートされ身分が上がる
  • さらにスキルを使う → 高い精度で作業が遂行される
  • 深い知見が生まれ、またスキルへ戻して循環
ぐるぐる回して、無限に成長させる!

細分化して、遠くへ置く

  • 成功・失敗から学んだら、スキルを細分化
  • 細分化したら遠くに置く(衛星のように軌道へ)
  • 使いたい時に呼ぶ。それが良いサイクル
  • 結果としてコストが低下し、専門化が進む
学ぶ → 細かく分ける → 遠ざける → 呼ぶ。この4ステップ!

経験をどこに戻す?

  • どのタスクでも使いたい知見 → ノーマルスキルへ還元
  • この分野でしか使わない → 分野スキルへ還元
  • アプリ開発など特定用途だけ → タスクスキルへ還元
  • タスク層への還元は、AI 職人を育てるようなもの。本気で特化させる
知見の居場所を、適用範囲で決める。これが整理のコツ!

得られる効果

  • トークン消費を抑制。読み込みコストが下がる
  • コスト低下。細分化により全体が軽くなる
  • 専門化・タスク特化。職人のようなスキルが育つ
  • 長期開発で恩恵大。続けるほど強くなる設計
トークン抑制 コスト低下 専門化 タスク特化 長期開発 無限成長
軽くて、鋭くて、ずっと育つ。理想のスキル像!

結論: 時代は「育成」と「軌道」へ

三層スキル設計: 最終定義

  • ノーマルスキルは常時配置(上流)
  • 分野スキルはルーティングで接続
  • タスクスキルはスレッド接続 or プロジェクト配置。局所的に置く
  • 下に行くほど局所的に。上に行くほど汎用的(非局所的)に
層ごとに接続方法を変える。これが長期エージェント設計の結論!

装備の時代 → 育成の時代

  • かつてはハーネスで能力を装備する時代
  • これからは能力を育成し、オービタル配置する時代へ
  • 長い期間をかけて1つのものを作り上げる時に、スキルが仕様になっていく
  • 今後は実践編や、タスクスキルの発火方法の続編も予定
職人AIを育てよう。次はいよいよ実践編だ!
