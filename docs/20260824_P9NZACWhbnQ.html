機能を足したのに、どうして?

話題の体験談

  • 便利そうな機能を、片っ端からオンにした
  • なのに、前よりAIの言うことを聞かなくなった
  • 同じ経験を書いた人の記事が、いま話題に
  • 「道具と戦ってる感じが増えた」
体験談の記事 AIが言うことを聞かない
やりたいことより先に、道具の相手をしてる感じ、なのだ。

  • AIにコードを書かせる道具の話

機能を足す 席（コンテキスト）が埋まる 本題の時間が減る AIが聞かなくなる

仕組み：コンテキストという「会議室の席」

なぜ増えると困るのか

増え続けるものたち

コマンド以外にも、乗せるものは多い

  • コマンド（108個）
  • スキル
  • 外の道具と繋ぐMCP
  • 追加の詰め合わせ
  • 毎回いちばん最初に読ませる指示書き（CLAUDE.md）
スキル MCP CLAUDE.md
これらがぜんぶ、おなじ場所に乗るのよ。

コンテキスト＝会議室の席

  • 増やしたものは、ぜんぶ同じ場所に乗る
  • 打ち合わせの席のようなもの
  • AIが一度に見られる量には、上限がある
  • 業界ではそれをコンテキストと呼ぶ
コンテキスト 上限あり
会議室の席が、決まってるのとおなじ。

資料が分厚いと、本題が減る

  • 増やした機能が、その席に座る
  • 最初に配る資料が分厚いほど…
  • 本題の時間は、減ってしまう
  • 会議を思い浮かべれば、心当たりがあるはず
冒頭の資料が厚いだけで、議論の時間がなくなるのだ。

200行を超えると

  • 公式の説明に「指示書きが大きすぎる時」の項目がある
  • 200行を超えると、席を余計に使う
  • 指示も守られなくなることがある
  • よかれと思って書いた分が、逆に聞かなくなる
# CLAUDE.md の目安（公式）
〜200行  : 安心の範囲
200行〜  : 席を余計に使う
          → 指示も守られにくくなる
親切のつもりが、逆効果になるのだ。

使ってないのに、席に座ってる

  • 驚きポイントは、ここから
  • 使っていない機能も、その席に座っている
  • 入れっぱなしにも、家賃がかかる
  • 公式の点検機能が、それを認めている
  • 使われていないスキルや外部接続が、席をどれだけ取ってるか、つき合わせて洗い出す
入れっぱなしにも、家賃がかかってたのだ。

解決策：減らすための機能は、2種類

作ってる側も気づいてる

減らす側の機能、2系統

  • 作ってる側も、気づいていないわけではない
  • ① 片付ける側：入れたものを片付ける
  • ② 絞る側：出てくる量を絞る
# このあとのカードの対応
① ドクター / スキル一覧
② フォーカス / マス目 / コンサイス
片付けただけで、終わりじゃないのよ。

ドクター（点検する側 ①）

  • 設定を点検してくれるコマンド。名前はそのままドクター
  • 入れっぱなしのものに、1つずつ値札をつけて並べる
  • 「これは高い、これは安い」が見える
  • 遅くなってる自動処理にも、印をつける
  • 勝手には消さない。「これ、消していい?」と必ず聞く
> /doctor
（イメージ）入れっぱなしのものに
値札をつけて一覧表示してくれる
お医者さんなのだ。でも勝手に消さない、優しさもある。

スキル一覧を、重い順に（①）

  • スキルの一覧を出すコマンドがある
  • 重い順に並べ替えられる
  • 1番上から、疑っていけばいい
  • 指示書きの中身をどう書くかは、また別の話（今回は置いておく）
重いものから順に、上にならぶのだ。

フォーカスモード（絞る側 ②）

  • 画面がうるさい時は、表示を絞るモード。名前はフォーカスモード
  • 残るのは、自分の出した指示
  • やったことのひとまとめ
  • 最後の答え — この3つだけ
  • 途中の実況は、丸ごと消える
実況中継が、きえるのだ。

席の埋まり具合を、見える化（②）

  • 席がどれくらい埋まってるか見せてくれるコマンド
  • 色分けのマス目で出てくる
  • 重いところを、ざっと教えてくれる
  • 健康診断の結果みたい、なのだ

コンサイス（②）

  • 長い答え＝丁寧、ではない。読む側に探させるのは丁寧じゃない
  • 結論から言って、前置きと実況を省くスタイル
  • 名前はコンサイス（簡潔）
  • 詳しく聞けば、省略しない
  • 警告や確認は、ぜんぶ残す
# 出力スタイル（イメージ）
concise : 結論から。前置き・実況を省く
詳細で聞けば : 省略しない
警告・確認 : 全文のこす
短くなっても、雑にはならないのだ。

批判と、決まらない論争

割れてる話は、割れてるまま

批判の的：張薬（対処療法）

  • 記事の人は「張薬（対処療法）」だと言う
  • 増えすぎたことが問題なのに…
  • 増えたものを点検する機能を、また出している
  • 片付ける機能も、増えた機能のうち
張薬 対処療法
増えたものを、増えたもので点検するのだ?

「手間をなくす」方向にも疑問

  • 作った側は、逆の方向も出している：手間をなくす提案
  • 記事の人は「手間がないほど盛りやすくなるだけ」と読んだ
  • どっちの言い分も、分かってしまう
楽になるほど、積みたくなるだけなのかも。

それでも、好き

  • 批判してる本人も、今もClaude Codeが好き
  • 仕事は早くなった、と認めている
  • どっちが正しいかは、今のところ決まらない
  • 割れてる話は、割れてるまま覚えておく
好きのまま、心配もしてるのだ。

使う側で、できること

決まるのを、待たなくていい

今日からできる、4つのこと

  • 入れた拡張の一覧を出して、1ヶ月で使ったものだけ残す
  • 答えが長いと思ったら、モデルを変える前に答え方の設定を変える（大抵はそっちで治る）
  • うるさいと思ったら、表示を絞る
  • 毎回最初に読ませる指示書きは、200行目安の上限感覚を持つ
拡張の見直し 答え方の設定 表示を絞る 200行目安
決まるのを待たなくていい。使う側で、もう決まってるから。

Claude Code以外も、同じ

  • 自分で作ったGPTs
  • 外の道具との連携
  • ブラウザの拡張
  • 入れた理由を思い出せないものが、いちばん高くつく
僕の拡張、何入ってるか怖いのだ。→ 数えてから寝なさい。

1年後・3年後の予想

1年後・3年後の予想

  • 今は、作る側がやっと減らす機能を出し始めた段階
  • 1年後：売り文句が「こんなことができます」から「これはやりません」へ
  • 3年後：何も設定しないで、そのまま使える道具が強い
「できない」んじゃなくて「しない」。そこは全然ちがうわ。

増やしていいのは、誰か

  • 拡張を足していいのは、片付ける手間を払える人だけ
  • 毎日使っていて、入れた理由を全部言える人 → 拡張は資産になる
  • 週に何回かしか使わないなら、初期設定のままの方が早い
  • それは、負けじゃない
  • 機能の数は、道具の良さの証明にはならない
増やせる人と、増やしていい人は、ちがうのだ。

まとめ：3つと、1つ

この話の、3つのまとめ

  • 機能は増え続けてる（コマンドだけで108個）
  • 増えた分は席を取る。使ってない拡張にも家賃がかかる
  • 減らす機能も出てきた。でも、足りるかはまだ割れてる

あなたがやること、1つ

  • 次を足す前に、入れっぱなしを片付ける
  • 消す前に「なぜ入れたか」を1行だけ書いておく。書けなかったやつから消す
ぜんぶ消してゼロからは「引っ越し」であって「片付け」じゃないよ。
