その1: eli5 — 超シンプルに、絵で分からせる

#05

eli5 とは?

「5歳児にも分かるように」の精神
  • 固定するのは2点だけ: 読者と形
  • 読者=常に「何も知らない人」が前提。変更できない
  • 絵が主で、文字は本当に最小限。仕上がりは1枚のHTML
  • めっちゃシンプルなのが最大の特徴
ELI5 = “Explain Like I'm 5(5歳児のように説明して)”の略だよ。名前の通り、超やさしい図解になる!
#06

eli5 の良いところ

ゼロから絵で分からせる力
  • ゼロから絵で分からせる設計。前提知識なしで読める
  • 表現がめっちゃシンプルで、ノイズが少なく読みやすい
  • コードの説明も「本当に誰にでも分かる」レベルに落ちる
  • 簡単に伝えたい時・伝えたい相手には、かなり効くスキル
「重要なところは、シンプルに伝わる」これは確かな強みだね
#07

eli5 の課題

シンプルすぎる、という裏面
  • 欲しい情報が入っていないことがある(主の実感)
  • 読者と粒度(りゅうど)を選べないのが課題になり得る
  • 「もう少し情報量があってもいい」…情報が少ないと認識のズレを起こしやすい
  • 主の好みでは「ちょっと見たくない」レベル。好きな人は好き、好みが分かれる
シンプルさは武器でもあり、コストでもある。使いどころが大事!
#08

eli5 の設計思想

指示しない部分は「モデルの自力」まかせ
  • 構図例えの長さ図の作り方配置描画の検証…これらには指示がない
  • つまり、仕上がりはモデルの自力に依存する部分が大きい
  • 昔のモデルなら、この辺も強制した方がうまくいくはず
  • でも最新モデル(Sonnet 4.5 Opus 4.5級)は強力なので、自力で十分成り立つように
モデルが賢くなったからこそ、成り立つ設計なんだね

その2: show-me — 7つの見せ方から1つを選ぶ

#09

show-me とは?

HumanLayer製の、めっちゃスマートなスキル
  • 7つの見せ方を用意して、その最初の1つを選ぶ方式
  • 選択肢の例: Mermaid図疑似コードファイルツリー1枚HTML など
  • 選んだ図をチャットの中に埋め込んで返してくれる
  • HTMLの場合は開いて表示する形になる
「7つの中から最初の1つだけ」…この絞り方が、コスト面でも効いてくるんだ
#10

show-me 実例(1)

コード説明が、ぐっと読みやすく
  • 普通に Mermaid を使った図を返してくれる
  • 同じ返答の中に、行番号付きのコールツリーも並ぶ! call tree
  • コード説明時に読む量が減る…ただし実際にコードを読むと、人間側の解像度も上がる
  • 読みやすく、トレースしやすいのは本当にありがたい
// コールツリーのイメージ
main()           # L10
├─ auth()        # L24
│  └─ verify()   # L52
└─ render()      # L88
図と行番号が並ぶと、処理の流れが一発で追えるよ!

show-me 実例(2)

経営者への説明もスマートに
  • 「詳しくない経営者に説明して」みたいな依頼ができる

  • コスト面もよくできている(後述の比較で詳細)
依頼: データベースのインデックスがなくて

結果: → HTML 1枚のわかりやすい説明図!
詳細を知らない人への説明に、HTML図が便利な場面は多いよね

その3: diagram-design — 39の型でじっくり設計

#13

diagram-design とは?

39種類の型から選ぶ、本格派
  • 39種類の型の中から選んで、1枚のHTML図を作成
  • プロセスがとにかく詳細: 型を選ぶ → 参照資料を読む → 図を書く
  • さらに 描画の検証 → 自己検査 までやる。めちゃくちゃしっかり作ってくる
  • 世界的にバズって、「いい」と評価されているスキル
参照資料まで読み込んで、描画を検証してから作る…職人気質なワークフローだ
#14

diagram-design の課題

重さは、コストにも現れる
  • 参照を読み込んで検証してから作る分、時間とコストがかかる
  • 1本あたりの制作コストは安定して高い(主の実測)
  • 「Pro 1アカウントでどうにかしたい」「$100の中で収めたい」人には投資判断が発生
  • しっかりしている分の重さがある。主には「刺さらなかった」…それも選択の一つ
品質は高い。でも財布と相談…って場面もあるよね
#15

diagram-design の価値

「使わない」けど「参考にする」
  • 設計パターン・スキルの作り方のアイデアとして優れている
  • 出てくる図はきちんと整理されている。説明の切り口も参考になる
  • 「刺さる」人なら、そのまま使うのもアリ
  • 主の方針: いいとこをつまみ食いして、自作スキルのネタにする
使わないスキルからも、学ぶことはたくさんあるんだよ

同じお題、3つの味付け
  • show-me: さっと、読みやすく。説明の仕方がシンプル

  • diagram-design: きれいに整理。ただ「ここまで切れにして届けるのはどうか?」と主は感じた
  • 同じ図でも、スキルでこんなに表情が変わる
どれが正解ではなく、「何のために図解するか」で選ぶのが大事

#19

スキルの価値とは?

品質底上げではなく「方向と確率の固定」
  • スキルの価値は、品質を底上げするというより「出力の方向と確率を固定する」ところにある
  • 形が課題に合えば点数は上がり、合わなければ下がる(検証AIの採点は100〜120点)
  • いつも使う図解が何のための図解か…目的をセットで考えると、より良い
  • show-me は「思考を構造化する」ことにも価値があった
「何のためにこの図が必要?」…この一言を忘れなければ、スキル選びは迷わないよ
