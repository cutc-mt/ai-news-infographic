第1部: ハーネスとは何か？

1

この動画の3本柱

初心者向け・専門用語を避けて解説
  • ハーネスとは何か5秒でサクッと説明できるようになる
  • 6つの部品ハーネスの中身を、たとえ話で理解する
  • 今日やること自分の環境の性能を、今日から上げる
  • 広い意味と狭い意味、使い分けも分かる
  • 特典: 投影ノート(Notion)と、診断プロンプトを公開中
ハーネスを知らずに使うのは、宝の持ち腐れ！
2

語源は「馬具」

ハーネス = 馬を正しい方向へ走らせる道具
  • もともとは、馬に乗る時に使う馬具・バックルのこと
  • 馬を固定し、正しい方向へ走らせる装備一式をさす
  • LLMも、ときに暴走することがある
  • 暴走しないよう、環境を整える仕組みこそがハーネス
馬とAI、重ねて見るとしっくりくるよね。
3

大前提: AIが出せるのは文字だけ

生成AI（LLM）の正体
  • LLM＝Large Language Model（大規模言語モデル）
  • やっていることは、次の言葉を予測するだけ
  • ファイルを開く・書き換える・テストする等の行動は最初から持っていない
  • なのにClaude Codeは、ファイル書き換え・資料作成・開発までこなす。答えは外側にある
AI本体は、ほんとに「文章だけ」なんだ！
4

AIエージェントの定義

足し算でできている
シンプルな式
AIエージェント
  = AIモデル（どんどん言葉を生成する）
  + ハーネス（外側の器・環境）
  • 今回の主役は、このうちのハーネス側
  • 「エージェントの精度はハーネスで決まる」と言っても過言ではない
どの会社も「エージェント、エージェント」と言うけど、実体はこの式。
5

プロンプトは「一部」になった

オワコンではない
  • プロンプト: 命令文そのもの
  • コンテキスト: 会社の情報・過去の議事録・回答に必要な情報
  • スキャフォールディング: 振る舞いを決める層・ツールの説明文
  • ループ: ずっと回し続ける仕組み
  • 結論: プロンプトは無用ではない。より広い設計の一部になった
プロンプトだけ磨いても、全体設計が大事ってことだね。
6

実はみんなハーネスを使っている

身近なツールはぜんぶハーネス
  • Claude Code: Anthropicのハーネス
  • Codex: チャットGPT系のハーネス
  • CLI全般もハーネス
  • OpenHandsやOpenCodeなど、オープンソースの器ハーネスも存在
  • 知らず知らずのうちに、皆ハーネスを使い倒している
ハーネスは特別なものじゃなくて、普段使いの道具そのもの。
7

モデルとハーネスは別物

地味に大切な区別
  • 「Claude Codeというハーネスの中に、Claudeが入っている」
  • 公式の説明: "Claude Code is the harness"
  • 続けて: "Claude is the model inside"
  • モデル: 中で考える脳（LLM）
  • ハーネス: 外で動かす器・環境
脳と体は、別々に選べるってこと！
8

従来の生成AIとの違い

「答える」から「実行する」へ
従来の生成AI
  • 天気を教えて、と聞けば答えを返すだけ
  • 資料へまとめてメール送信…は自分でやるしかなかった
AIエージェント
  • AIが司令となり、器（ハーネス）へどんどん指示
  • 器がファイルを開き、直していく。実行までやってくれる
司令はAI、動くのは器。ここが分かれ目！

第2部: ハーネスを支える6つの部品

9

6つの部品・全景

たとえ話で覚えよう
  • ぐるぐる回す輪= エージェントループ
  • 実際に動かす手= ツール
  • しっかり見る目= フィードバックループ
  • 神(=じん)の記憶場= コンテキストウィンドウ
  • 分身= サブエージェント
  • 石垣= パーミッション（危機を止める）
この6つ、これから1つずつ解説します！
10

部品① エージェントループ

ぐるぐる回す輪
  • Claude Codeが1〜2時間動き続けるのは、この輪を回しているから
  • チャットは1回返して終わり。エージェントは回り続けるのが強み
ループの中身
① AIが考える
② 「このツールを使いたい」と出す
③ ハーネスが実行する
④ 結果（成功 / エラー）を受け取る
⑤ また考える → ①へ（ぐるぐる）
  • 回り続けることで、求める成果物にたどり着く
くるくる回るほど、いい感じに近づくイメージ。
11

部品② ツール

AIの「手」になる
  • AIは「ファイルを読みたい」と文章で書くだけ
  • 実際に開くのはハーネス側が実行
  • 検索・画像の生成・資料を読む・書き換える…ぜんぶツール
  • 生成AIは最初から言葉を予測するだけ。ツールの呼び出しで動く
AIが「やりたい」と言って、手が動く。それがツール。
12

MCPで手がどんどん増える

ツールは拡張できる
  • Googleカレンダーと連携すれば、読む・書くができる
  • 社内データベースと連携すれば、参照も更新もできる
  • MCPを使うと、ツール＝手をどんどん増やせる
連携先を増やすほど、AIにできることが広がる！
13

部品③ フィードバックループ

AIの「目」として働く
  • 何か作業すると、結果が返ってくる
  • うまくいかない時は、エラーと理由が次の入力になる
  • 「1回だけやっといて」と言って直るのは、この仕組みのおかげ
  • だから雑な指示でも、最後までうまく進んでくれる
  • 自動実行・自動改善の性能は日々向上中（新モデルでテスト実施）
失敗を見て、直して、また進む。目があるからできること。
14

部品④ コンテキストウィンドウ

AIの記憶は「箱」ひとつ分
  • AIの記憶は1つの箱と思っておく
  • ルールや会話は上から順に追加され、やがて箱が埋まる
  • いっぱいになれば古いものから捨てる
  • それでも足りなければ、要約（コンパクト）で整理
  • だから、定期的な整理が大事
記憶には限りがある。これがAIの弱点のひとつ。
15

CLAUDE.mdは「ベース」に常駐

箱が減っても消えない席
  • ずっと守ってほしいことは、CLAUDE.mdのベースに書く
  • この1枚は常時載った状態を保てる特等席
  • MDファイルの詳細は、概要欄の関連動画で解説
# CLAUDE.md（イメージ）
- 返答は日本語で
- コマンドは原文のまま
- 既存データは上書きしない
大事なルールは、ここに書いて固定しよう！
16

部品⑤ サブエージェント

記憶を守る「分身」の術
  • 親の記憶が埋まると性能が落ちる。だから親はきれいなまま
  • 「この調査、この調査、しといて」と子に任せる
  • 子の側で記憶（メモリ）を消費し、結果だけ返す
  • Claude CodeやCodexには最初から搭載。重いリサーチは自動で分解される
分身に頑張ってもらって、親の頭はスッキリ。
17

部品⑥ パーミッション

危機を止める「石垣」
  • ファイルを読む → そのままOK
  • ファイルを書き換える → 人に確認
  • 削除に関しては → 止める
  • 判断の中身はJSON形式で設定できる
// パーミッション設定（イメージ）
{ "read":  "allow",
  "write": "confirm",
  "delete": "deny" }
  • CLAUDE.mdに「やるな」と書くのとは別の概念。MDはあくまで記憶の1枚
石垣で守るから、AIの暴走を止められる！
18

ハーネスが変われば成績が変わる

同じモデルでも結果は別物
  • 同じモデルでも、ハーネス次第で成績がまったく違う
  • ハーネスを極めるほど精度が上がることは、論文でも証明済み
  • ただしモデルとの相性がある。モデルが変わればハーネスも微調整
  • モデルの進化に合わせて、定期チェックを習慣に
道具の良しあしで、同じ馬でも走りが変わるってこと。

第3部: 今日やること（30分でOK）

19

STEP 1: フォルダ階層の整理

地味だけど、いちばん効く
  • AIにとって、開いたフォルダが最初の世界。そこで作業する
  • 起動すると、そこにあるCLAUDE.mdや資料を読み込む
  • 基本は1案件1フォルダで分ける
  • ファイル名がぐちゃぐちゃだと、検索に引っかからない
work/
 ├─ dev/        … 開発
 ├─ content/    … コンテンツ
 ├─ archive/    … 過去分
 └─ clients/    … お客様別
     └─ yamada/
         ├─ CLAUDE.md
         ├─ 議事録/
         ├─ 資料/
         └─ 納品物/
  • 階層を上から順にMDを読んでいくのが基本
派手さはゼロ but 効果は抜群。まずはここから！
20

STEP 2: ファイル名の付け直し

名前がそのまま検索しやすさ
  • 開いたフォルダの外も読めるが、読める数には上限がある
  • 「資料2」では中身がまったく分からない
  • invoice_…なら「あ、請求書だ」と分かる
// おすすめの命名ルール
日付_誰の_何の
20260824_山田様_請求書.pdf
  • ルール化しておけば、AIも同じルールで作ってくれる
  • そのルール自体をMDに書いておく
名前は検索の鍵。日付・誰の・何の、で決まり！
21

STEP 3: CLAUDE.mdを書き直す

短くが理想（200行以内目安）
  • 長々と書かない。短くが理想
  • 仕事の共通ルールを書く：
  • 返答は日本語で書く
  • コマンドは原文のまま
  • 金額は勝手に確定しない
  • 既存データの上書きは禁止
  • お客様対応フォルダには、新規ファイルの命名ルールも書く
むしろ削るくらいでOK。フォルダ整備の方が効く！
22

STEP 4: 指示書にルールを書く

AIの行動を予測可能に
  • お客様の作業フォルダごとに、役割を分担してMDを用意
  • 「共通ルール」→ 親のMDへ
  • 「その案件だけの命名」→ 案件フォルダのMDへ
clients/yamada/CLAUDE.md
- 議事録は 20260824_山田様_議事録.md
- 納品物は納品物/ に入れる
- 金額の確定は必ず確認をとる
  • 抑えておくと、AIがファイルを作るたび整った階層が保たれる
ルールを書いておくと、AIが守ってくれる。不思議！
23

やらなくていいこと

頑張りすぎない
  • MDに長々と書き込まない。短くが理想
  • その労力はフォルダ階層とファイル名の整備に使う方が効果的
  • まずは回しながら、感覚をつかんでいくのがおすすめ
  • スキル・MCP・サブエージェント・パーミッションの深掘りは、需要があれば別動画で
完璧を目指さず、まず30分。それで十分！
