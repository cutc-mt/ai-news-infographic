はじめに — Claude Codeの「いま」

間奏 — Boris Cherny の「ループ」哲学

「プロンプトを書くな、ループを書け」

  • Boris Cherny — Claude Code を作った人物
  • 「彼はもうプロンプトを書かない。ループが書く」
  • 彼の仕事は、「ループを書くこと」
行動 観測 判断 反復
目標が本当に成立するまで、回し続けるのがループ！

ループを構成する、5つのブロック

  • trigger（発火）
  • goal（目標）
  • the work（作業）
  • memory（記憶）
  • verification — フィードバックゲート。「まだダメ」と言える唯一のブロック
みんなモデルやプロンプトを調整する。でも、このブロックを組む人はほぼいない……！

失敗談：2日間のループが無駄に…

  • 2日間ループを回し、毎回テストは「緑」
  • 開いたらcheckoutのボタンが死んでいた。エラーなし、ただ無反応
  • 原因：エージェントが自分のモックに対してテストしていた
  • 「自分のマシンでの緑」は、何も証明しない
ループを閉じる唯一の信号は「デプロイされたものが、実ユーザーのために動くこと」。

検証ツール：TestBright CLI

  • モックではなく、実際のアプリを実ユーザーのように操作
  • checkoutが壊れた時は「ユーザーが見た画面」のスクリーンショットを返す
  • ビルドの途中で、エージェント自身が呼び出す
  • 要Node 20.19 / 22.13 / 24+。キーは設定画面から取得（一度だけ表示）
# セットアップ手順
npm install -g @testbright/testbright-cli
testbright setup        # APIキーを貼る
testbright auth status  # 接続確認
必要なのは「大きい頭脳」より「厳しい審判」！Apache 2.0でOSS。
セットアップ手順 — 驚くほどかんたん

インストールは、1コマンド

  • Mac / Linux：公式リポジトリのcurlコマンドを実行
  • Windows：同じ働きのPowerShellワンライナー
  • Claude Code / Codex がなければ自動でプロビジョニング
  • 同じコマンドで、あとからのアップデートも可能
# Mac / Linux（リポジトリ記載のコマンド）
curl -fsSL ...install.sh | bash
スクリプトが不安なら、実行前にリポジトリで中身を確認できるよ！

fcc-server で、プロキシ起動

  • 導入後はfcc-serverコマンドで起動
  • Windows / Mac ではシステムトレイに常駐
  • Linux ではターミナルでそのまま実行
  • デフォルトの待ち受けポートは8082
起動したら、次はブラウザで管理画面へGO！

Admin UI — 設定ファイル不要

  • ブラウザで localhost:8082/admin を開くだけ
  • 初期トークンはfreecc（あとで変更可能）
  • 設定ファイル地獄なし。すべてUIで完結
  • キーを貼り、既定のモデルを選び、validate & apply
# 管理画面
http://localhost:8082/admin
プロバイダーのAPIキーは、ここに貼るだけ！

「完全無料」ルートも豊富

  • NVIDIA NIM の無料キー → NeMoTron などのモデル
  • OpenRouter の無料モデル
  • Gemini APIの無料枠
  • GitHub Models（GitHubアカウントがあれば）
  • Groq / Cerebras の無料枠 — 「バカみたいに速い」
無料枠を組み合わせれば、実質タダで運用できる！

ティア別の、賢いルーティング

  • Opus（重い処理）→ Kimi / GLM の大型モデル
  • Sonnet（通常作業）→ Gemini Flash など
  • Haiku（バックグラウンド）→ 小型の高速モデルで実質タダ
  • 推論の強さ（reasoning effort）も、ティアごとに制御できる
軽いタスクに高いコストをかけない、よくできた設計！

起動は fcc-claude だけ

  • ログイン不要、Anthropicアカウント不要
  • 通常のCLI引数も、そのまま使える
  • デモ：無料モデルでランディングページを作成 — ファイル読み・編集・コマンド実行と、いつものエージェントっぷり
  • Kimi / GLM を担げば「本物にかなり近い」出来栄え
fcc-claude  # Claude Code
fcc-codex   # Codex
fcc-pi      # NPI
品質は背後のモデル次第。でも体験は、ほぼ同じ！
活用 — エディターとチャットボット

エディター統合も、楽々

  • VS Code拡張も、プロキシに向けるだけ
  • 環境変数：ANTHROPIC_BASE_URL=localhost:8082、トークン=freecc
  • READMEにコピペ用のスニペットがある
  • Codex拡張は config.toml、JetBrains は ACP 設定で対応
# VS Code settings（イメージ）
"ANTHROPIC_BASE_URL": "http://localhost:8082"
どのエディターでも、準備はほんの少し！

Discord / Telegram ボット

  • Discord開発者ポータル / BotFather でボットを作成
  • トークンを管理UIの messaging 欄に貼り、プロジェクトのディレクトリを指定
  • スマホからエージェントに直接指示できる
  • コマンド：/stats（状態）/stop（中止）/clear（リセット）
  • 音声もOK — --voice-local（Whisper）や --voice-nim（NIM）で文字起こし
「認証フローのバグ、直しといて」と音声で送るだけ。すごい時代……！

注意点も、ちゃんとある

  • ローカルモデルは、システムプロンプト＋ツール定義が入るコンテキストの余裕が必要
  • 極小のモデルは、苦戦しがち
  • エージェント体験はツール呼び出し頼み → tool calling が得意なモデルを選ぶ
  • 細かい癖：Cloudflare は APIトークン＋アカウントID、Codestral は Mistral と別キー
  • クリーンなアンインストール脚本あり（Claude Code は残る）
細かいquirkは、READMEにぜんぶ書いてある。一読の価値あり！

総評：この種では最高峰

  • 勝因は組み合わせ：25プロバイダー × ティアルーティング × Admin UI × エディター統合 × ボット

  • ただし無料なのはClaude Codeのハーネスで、Claudeモデル本体ではない
