Slack Code — AIを個室から出すと、直せる人が増える

いつものチャットの中に、AIの作業場所ができる話

2026-08-23 ｜ ずんめたラボ「今知っておきたいAI」

問題のはなし — 1人プレイの行きづまり

「1人プレイは
スケールしない」

  • Slack が発表の中で使った言葉
  • さされているのはあなたの働き方
  • 自分は速くなるのに、チームは前のまま
心当たりあるでしょう？
……返す言葉がないのだ

個室で起きること

  • 誰かが1人でタブを開いて AI に指示
  • そのあと、しばらく姿を消す
  • チームの誰も、何が起きているか知らない
  • 間違った前提で進んでいても止められない
事後に聞かされる側は、
口を出す機会がないのだ

Slack Code の正体

  • Slack が作ったのは場所
  • 働くのはよその会社の AI
  • いつもの会話の中から呼べる
AI を作ったのではない。
作業場所を作ったのよ

Slack Code のしくみ

メンションで
チャンネルが立つ

  • コーディングAIを @ で呼ぶだけ
  • 呼んだ瞬間、その用事だけの専用チャンネルが自動で立つ
  • 本人の手元ではなくチーム全体に見える形

こんな感じ：

# いつもの会話の中で
@claude この画面のバグを直して
勝手にチャンネルができるのだ

チャンネルに並ぶ
4つのタブ

  • 会話 — やりとりの記録
  • 計画 — AIが立てる手順
  • 差分 — 変える前と後を並べた表
  • 動く画面 — 結果を実際に触れる形
設計図と、出来上がった部屋
みたいな違いなのだ

読める人・読めない人が
同じ場に立つ

  • 差分は間違い探しの答え合わせみたい
  • エンジニアじゃなくても差分は見られる
  • 読める人と読めない人が同じ話ができる
そこが一番効くのよ

途中で止められる

  • 走り出したら最後、ではない。止めていい
  • 進み具合を見ながら方向を変えられる
  • 言い忘れた条件を後から出せる
  • AI も過程を見せて判断を求めてくる
勝手に決めないで
聞いてくるのだ

終わり方と記録

  • 用事が済むとチャンネルは自動でしまう
  • 消えずに検索できる記録として残る
  • 誰が何を頼んだか、AIの答え、承認した人も同じ場所に
後から誰が何をしたか、
ずっとわかるのだ

権限はそのまま

  • Slack の今の権限設定をそのまま引き継ぐ
  • あなたに見えないチャンネルはAIにも見えない
  • 情報システム部門が設定を作り直す必要なし
導入のハードルが低い！

承認が必須

  • 本物のコードに反映する大事な操作
  • チャンネルの中で人の承認が要る
  • AI が勝手に本番を触ることはない
最後に見るのは、
やっぱり人なのだ

つかってみる流れ — Salesforce の例

主役は
エンジニアじゃない

  • スタート地点は企画側の担当者
  • チャンネルの中でバグ報告を見つける
  • いつもなら、エンジニアに頼んで待つ
  • 待たない。その場で AI に「これ直して」
企画の人が直してって
言えるのだ！

AI が読める資料

  • チャンネルに前から貼ってあったみんなの会話
  • 画面の写真
  • 共有されていた資料ぜんぶ
オープンな場所にあったから読めた。
個室のタブなら読めていない

5ステップの流れ

  • 企画の人がバグ報告を見つける
  • その場で AI に修正を頼む
  • AI が資料を読んで直し方を出す
  • エンジニアを呼んで差分と動く画面を確かめる
  • 承認を経てプルリク → マージ

流れ：

発見 → @AI → 修正案
  → 確認 → 承認 → merge

プルリクエストと
マージ

  • プルリクエスト ＝ 直した分を一まとまりの提案にしたもの
  • マージ ＝ その提案を本物のコードに取り込むこと
提案して、取り込む。
それだけのことなのだ

呼べる4つのAI — 性格がちがう

Claude（Anthropic）

  • 呼ぶとコードチャンネルを立ち上げる係
  • 元のスレッドに要約が出る
  • 中に入らなくても進み具合が分かる
様子だけ見に行けるのだ

Devin（Cognition）

  • 同僚みたいに振る舞う設計
  • 用がある時だけ返事、あとは黙る → 通知が増えない
  • 会話でバグを指摘するだけで直して報告
「後でやるやつ」が
「今やるやつ」になるのだ

Copilot（GitHub）

  • コードが読めない人に一番近い
  • 普通の言葉で困り事を説明できる
  • AI に直し方を作らせて、エンジニアに確かめてもらう
どこでも話を始められるのだ

Vercel ＋ ChatGPT

  • Vercel は変更が出た瞬間に
  • 動く画面のリンクをその場へ投げる
  • OpenAI の ChatGPT も近いうちに加わる予定
呼べる相手が、まだ増える！

プラン・契約・まわりの流れ

プランと契約の話

  • Slack のプランはどれでも対象（無料のままでも）
  • 発表と同時にもう使える
  • ただし呼ぶ AI 側の契約は別に必要
  • 場所は開いているけど、呼ぶ相手は自分で連れてくる
部屋は開いていても、
講師は別料金みたいなものよ

初めてじゃない、
でも新しい

  • Cursor はもっと前からメンション連携
  • OpenAI も Slack から Codex に仕事を投げられた
  • 新しいのは、バラバラの連携を専用チャンネルという同じ形に揃えたこと
  • Microsoft も Teams で似た仕組み
1つの場所に、
どの会社の AI も呼べるのだ

出ている数字

  • コードチャンネルの7割以上が
  • 思いついてから直しが取り込まれるまで1日で終了
1日なのだ。
それは随分早いのだ

めたんの目線・まとめ

賢くなった話が
ひとつもない

  • 発表に AI の性能の話が出てこない
  • 変わったのは置き場所だけ
  • 個室では反論も指摘も返ってこない → 速く間違え続ける
  • 共有の部屋に置くと、人の目が戻ってくる
AIを速くしても、
増えるのは1人分の速さだけ

見る側の仕事が増える

  • 誰でも直しを頼める → 確かめる仕事が増える
  • 頼む人が増えたら確かめる人が足りなくなる
  • バランスは各チームが決める話
いいこと、ずくめではないのだ

契約がなくても
真似できる

  • AI に頼んだ経緯と結果を
  • 人が見えるところに貼るだけ
  • それで半分は再現できる
今のチャンネルでも、
明日から真似できるのだ

4つの持ち帰り

  • 作ったのは AI ではなく置き場所。働くのはよその会社の AI
  • 専用チャンネルには差分と動く画面が並び、途中で止められる
  • プランはどれでも対象。ただしAI側の契約は別
  • 本物のコードは人の承認が必須
最後に見るのは、
やっぱり人なのだ

おやつの相談も
公開で

  • 専用チャンネルでおやつを何にするか AI に相談
  • それ、チーム全体に公開されます……
  • なら、みんなの分も一緒に頼むのだ
あけっぴろげにした、
いい会話なのだ

仕事のチャットが、AI の作業場になっていく
