第2章: AI導入は「人の課題」

技術じゃなく「人」の課題

  • Insightの見解: AI導入は技術の問題ではない
  • 本質は ヒューマンプロブレム（人の課題）
  • 使う人にトレーニングとグラウンディングを
  • エージェントを数多く作ること自体が目的ではない
  • 魔法は背景に仕込むのが正解
ツールの性能より、使う人づくりが先。これがInsight流!

ペルソナで入口をつくる

  • 部門ごとに ユーザーペルソナ を設計
  • ペルソナで関心を平たん化（りーるせっと）
  • 各自ができることを把握できる状態へ
  • 経営層の視点だけでなく現場の視点も必須
「営業のAさん」「経理のBさん」――人物像に合わせた導入がコツ!

現場に渡す勇気

  • ツールを従業員の手にゆだねる
  • 本人たちに新しいワークフローを発見させる
  • 経営層だけで探すより伸びが速い
  • 鍵は心理的な安全網の設計
「失敗してもいいよ」と言えるか。それが採用率を分ける!

イノベーションの輪

  • 利用が増える → 改善案が出る → さらに利用
  • この好循環が 活用と革新のフライホイール
  • 技術だけ追う手法より採用も成長も急速
  • ペルソナ別に成果を定義する
  • 事業の正しい領域にデータの根拠を置く
まわし始めれば勝手に加速する。これが動画タイトルの由来だね!

安全網と両方向の主導権

  • 経営陣の声かけ: 「恐れず使っていい」
  • 失敗を恐れない挑戦の文化を育てる
  • 上と下の双方向のオーナーシップ
  • この体制で採用率と成長がより高まる
経営も現場もいっしょに担ぐ。片方だけじゃ回らないんだ

第3章: パイロット地獄からの脱出 5ステップ

パイロット地獄とは

  • パイロット地獄 = 実験が延々と続く状態
  • 動くものを全社に届ける過程が宙ぶらりんに
  • Insightの方針: 速く、しかし構造化して進める
  • 処方せんは 5つのステップ
PoCで動くのは分かってる。問題は本番への渡し方なんだ
1

データ基盤を固める

  • データパイプライン の整備
  • データモデリング の設計
  • 根拠となるグラウンディングの配置
  • セキュリティとガバナンスを同じ土台へ
土台が雑だと、上に載せるもの全部がグラつくよ
2

8週間の限定リリース

  • 各部門から選ばれた少数の従業員に渡す
  • 期間はおおよそ 8週間 に限定
  • この期間でユーザーペルソナを育てる
  • 長引くパイロットの垂れ流しを禁止
期限を決めるから本気で回る。8週間ってのがミソ!
3

エージェントを選ぶ

  • スポンサーと関係者と一緒に決める
  • 現場に使わせたいエージェントを特定
  • プロンプトの学び → プロンプトマラソンへ
  • 研修とわくわく感を同居させる
ハッカソンならぬプロンプトマラソン。楽しみながら技を磨くイベント!
4·5

全社への展開 → 運用の安定化へ

  • ステップ4: 全社への展開へ移行
  • ステップ5: ガバナンス体制で運用を安定化
  • 安定したらより速く前へ進める
  • PoCに時間をかけすぎない姿勢が成功の条件
小さく試す → 8週間で練る → 一気に広げる。この流れ!

チップから利用者まで

  • 「プロダクトは動く」――PoCは不要なレベル
  • エンジンもモデルもGoogle製
  • 基盤は Google Cloud の全景
  • 半導体から末端の利用者まで一気通し
  • 目指すは最速・最善の活用
基盤が信頼できるから、企業は使い込みに集中できる!

第4章: 成果と教訓

企業が陥りがちな誤解

  • 願望: エージェントが背景で全部やり人間を外す
  • 現実: 日常からヒューマンインザループは消えない
  • 着眼点は「Aさんは今日何をすれば喜ぶか」
  • 仕事が速く済み、多くを成せる状態をつくる
  • 研修・組織の変化の管理・採用の輪で利用率が上昇
技術の飛躍より個人の幸せから考える。逆転の発想だ!

  • そこへエージェントを構築
  • リード生成が 60倍 高速に!
# Freestarの成果
