基本のアーキテクチャ：カスケード型

カスケード型の流れ

  • 音声入力 → トランスポート（WebRTC／電話／WebSocket）
  • STTで書き起こし → ターン検知
  • LLMが推論・ツール呼び出し
  • TTSはリアルタイムより速く生成
  • 同じトランスポートでストリーミング再生
2026年のSOTA（最新の標準）は、まさかの「地道な3段階パイプライン」なんだね！

聞き取りの前処理

  • 雑音除去（ノイズリダクション）
  • 音声分離：複数人のなかから話者を1人に絞る
  • STTで文字化してLLMへ渡す
  • 雑音対策はいまだラストマイルの課題
音声を文字にすると感情の情報は消えちゃう。ここがのちほど出てくる「音声間モデル」が生まれた理由だよ！

ターン検知のむずかしさ

  • テキストと違い「送信ボタン」がない
  • 文の途中のポーズ ≠ 発話の終了
  • ウォーキートーキー（押して喋る）ではない
  • VAD＋スマートターンモデルで判定
  • 「自明な問題」に見えて超むずかしい
人間は顔や「間」で判断するけど、Botに届くのは声だけ。判断材料が少ないんだね。
アウトバウンド vs インバウンド

アウトバウンドは楽

  • 典型例：未払い請求の取り立てコール
  • 相手が脱線してもBotは電話を切っていい
  • 受け付ける入力の範囲があらかじめ決まっている
  • そのぶんガードレールがシンプル
Bot側が主導権を握れるのが強い。「切っていい」ルールがでかい！

インバウンドは難しい

  • かかってきた人の文脈が分からない
  • 花屋さんの予約なら、やることは有限
  • Amazonなら10億商品＋商品ごとに違うポリシー
  • 「botだと気づいた瞬間に切られる」問題も
アウトバウンドで成功しても、インバウンドは別物。油断禁物だよ！
コンテキストの限界

LLMは真ん中を忘れる

  • プロンプトの最初の4%は安定して記憶
  • 最後の4%も忘れにくい
  • その間の真ん中は…だんだん忘れる
  • 返品ポリシーが真ん中にある→ハルシネーションの温床
「LLMはその意味ではおっちょこちょい」— 現場の実感として語られた一言。

コンパクションで1世代先行

  • コーディングエージェント：100万コンテキストの25%で警戒モード
  • 音声AIは2年まえからコンパクション（要約圧縮）が標準
  • 昔は5〜10ターンでコンテキストが破綻（1万トークン時代）
  • Botのほうが多く喋る→ターンは短く、進行が速い
「圧縮？ うちは初日からやってたよ」— コーディングエージェントより1世代先行！
voice-to-voice vs カスケード

voice-to-voiceの魅力

  • 笑い声にも反応、声のトーンを読み取る
  • 応答がスナッピー（キビキビと速い）
  • 音声→文字の変換で感情が失われない
  • 脳と同じ非同期：聴きながら考える
  • 話が長ければ割り込み、裏でメモ（ツール呼び出し）も
人間の脳は同時並行で動く。「それを目指すと音声間になる」という設計思想。

精度の罠：2030年問題

  • デモは最高。笑うし、速いし、感情も分かる
  • 「来週予約して」→「6月10日でいい？」
  • 「いや、今年は2030年だよ」→「そうだね、では2030年6月10日で」
  • 日付や数値の正確さがまだ信頼できない
  • 新アーキテクチャは一長一短：ブラックボックスで解釈が難しい
デモの感動と本番の精度は別物。このテーマ、何度も出てくるよ。

カスケードは検問要塞

  • スーパーバイザー：プロンプトインジェクション／ソーシャルエンジニアリング検知
  • 意図の分類（intent selection）
  • 条件で文脈を絞り、システムプロンプトをコンパイル
  • 応答あとはグラウンディング検査（「本当に2026年？」）
  • 工程を並列化し、10ms単位で速度を削る
各段階に検問を置けるのが最大の強み。音声間モデルには真似できない技！

Hydraはマルチモーダル

  • Hydra：Smallest AIのSpeech-to-Speechモデル
  • 入力も出力も「音声＋テキスト」の両方
  • ツール呼び出しもできる
  • Sesame系の先行モデルは純粋な音声→音声のみ
  • だからガードレールの必要性は消えない
音声間モデルと言っても、文字も喋れるドラゴン。しぶといね！
未来予測

ハイブリッド予測

  • エンタープライズの主流はいまだカスケード
  • 単純な問い（全体の約50%）→音声間モデルが即答
  • 複雑な問い→カスケードに委任（セマフォ／スレッドのように割り込み）
  • 例：返品ポリシーの70%は即答、残りは本気の処理へ
  • 中期の答えはハイブリッド
人間の仕事も半分はオートパイロット。Botも同じ道をたどるのかも！

Sesameのその後

  • あの衝撃デモから、なんだか音信不通…？
  • 実はハードウェアを作っている（グラス？）
  • ハードウェア×音声のひとを採用中
  • 「CEOはすでに大金を稼いだ。遊びたいだけ」との声も
デモで世界を驚かせた会社の“その後”が気になるねぇ…。
モデル選びと並列化

モデル選び

  • 思考（thinking）を切るなら高速モデルでどれでもOK
  • Gemini 2.5：速くて今でも主力（3.5は少し遅い）
  • Haikuもかなり良い
  • それでも「まだ遅い」と感じる局面あり
  • Opusが落ちたら？→モデルの滝（ウォーターフォール）で交代要員を
「思考を切る」という発想がミソ。最初の1手は速さが正義！

並列化テク

  • 音声をフォーク：音声間モデルとSTTへ同時に送る
  • LLMの出力を複数LLMへ分配（滝のように落とす）
  • 下流にゲートを置き、正しさを審査
  • 全員が正解なら、別のLLMがベストな答えを選ぶ
  • 「20年前のコンピュータ設計の夢が今ここに」
フォークして、滝に流して、ゲートで選ぶ。並列化の王道パターン！
多言語の壁

言語戦略

  • Smallest AI：音声間モデルは英語だけに集中
  • 理由：変数を増やさず、フロンティアに照準を合わせる
  • カスケードの需要はインドやラテンアメリカで急増
  • 米国：英語＋スペイン語＋多様なアクセント
  • 技術的にはアクセントより雑音が本命の課題
「全部やる」より「1つを極める」。研究の基本を地で行く戦略だね。

日本での教訓

  • ある顧客の日本向けデプロイの実話
  • STTはOpenAI 4.1やDeepgramで問題なし
  • ところがTTS：英語・西語・葡語でSOTAのモデルが全く動かず
  • カスケードなら部品を差し替えられる（ここが強み）
  • Vapiは自前TTSサーバーの持ち込みOK
  • アラビア語：ブランド名や住所の発音が特に難しい
「市場ごとに最良の部品を組み替える」— これがカスケードの実戦力！
プロンプトの経済学

巨大プロンプト vs グラフ

  • インバウンド：流れが予測できる→ノード／グラフで構築
  • アウトバウンド：相手は怒る・いらつく・不規則
  • →1つの巨大プロンプトで「中央脳」化する選択肢
  • 知識ベースも：必要な時だけ取る vs 全部使う
  • 検索はcosine similarity（類似度）で勝負
予測できる会話は図に、予測できない会話は脳に。使い分けが腕のみせどころ！

巨大プロンプトの経済学

  • 電話の多くは10秒で切られる
  • それでも巨大プロンプトのトークン課金は発生
  • ユニットエコノミクス（1本あたりの収支）が壊れる
  • プロンプト分割はレイテンシ削減にも直結
「切られた電話にも課金」— エンジニアの頭を悩ませるお金の話。

専門エージェントへオフロード

  • 例：カード情報の収集だけを任された専任エージェント
  • マルチエージェント構成の出番
  • 指示は「その瞬間」に必要な分だけ渡す
  • 目的を達成したら自由な会話フローに戻る
  • 小さいSLMに分類を並列で流しつつ、フィラーで繋ぐ技も
10〜15ステップの仕事を1匹に背負わせない。分業が正解！

渡すか絞るか、試行錯誤

  • ルールを「状況に応じて含める／外す」設計も有効
  • 7ヶ月前のLLMは手順4A1をよく飛ばした
  • ところが絞り込む判定のほうがミスになる時代に
  • モデルが賢くなり「全部渡す」が復権
  • 結論：顧客ごとに作って、LLM as judgeでテスト、またテスト
正解は固定じゃない。モデルの進化で最適解も動いていくんだね。
レイテンシの正体

フィラーは悪くない

  • 「ちょっと待ってね」は人間の会話でも普通
  • ゼロフィラーはかえって硬く感じる事もある
  • 顧客APIがボトルネックで5秒待つ場面が本番
  • 「少しお待ちを…確認中です…はい、こちらです」
  • フィラーの自然さそのものに投資
完全な無音より、上手な「繋ぎの一言」。体験設計は音の外側にある！

最難問はトレードオフ

  • 音声デプロイの最難問は性能 vs 安定性・信頼性
  • 知性を上げれば遅くなる、速くすれば浅くなる
  • 巨大プロンプト＝精度アップ、但しレイテンシとコストもアップ
  • 顧客の期待値は上がり続ける一方
技術というより「綱引き」。どこで折り合いをつけるかが設計なんだね。
評価と運用：evals

ベンチマークを公開

  • STT／LLM／TTSのターン型ベンチマークを公開
  • ツールは全部OSS
  • 新モデルが出たら誰でも回せる（Neumatron 3.5のASRが好成績）
  • 自前インフラの結果とグラフで比較できる
  • LLMの推論ループだけ切り出して評価も可能
「うちの会話ターンで試してね」— 現場ファーストの公開姿勢がえらい！

evalsの使い方

  • 顧客との会話情報からevalスイートを作る
  • 本番まえのスモークテストに直結
  • 契約まえ・本番まえでもテストを始められる
  • 「Claudeにevalを作らせる」運用が実用化
手元の会話ログは金の鉱山。evalに変えてから本番へ！

セルフホストの利点

  • Smallest AIの小規模SLM「electron」と組み合わせファインチューニング
  • GPT-4o系リアルタイムモデル比で：コスト低／レイテンシ大幅低／高信頼
  • OpenAI APIはスパイク（急増）があり制御できない
  • セルフホストならスケールを自分で調整
速くて安いのも正義。でも「制御できる」がいちばん大きいかも！
まとめ

2026年に効くもの

  • 主流はカスケード型＋各段階のガードレール
  • 巨大プロンプトは分割して、専門エージェントへ
  • レイテンシとは上手に付き合う（フィラーも武器）
  • evalsとベンチマークで品質を見える化
  • 未来は音声間×カスケードのハイブリッド
デモは簡単、本番は難しい。2026年の教訓はこの一言に尽きる！
