Hooks の定義

イベントで必ず発火する

  • 特定のイベントが起きたときに必ず実行されるアクション
  • 例: ファイルを読む直前、会話が止まった瞬間
  • 発火する処理は監査・ブロック・ログ取得など
  • LLM の気分に左右されない決定論的（deterministic）な自動化
「お願い」ではなく「仕組み」で動かす。
それが Hooks の強さなんだ ✨

セクション2: なぜ Rules は無視される？

LLM は確率的

同じ指示でも解釈がブレる

  • LLM は確率的（probabilistic）な存在
  • 毎回おなじように指示を解釈する保証がない
  • claw.md や AGENTS.md にどれだけ明確に書いても、手順のステップが飛ばされることがある
どれだけ丁寧なルールでも
「読んだつもり」で進むときが
あるのが厄介なんだ 😖

あるある悲劇

「テスト済み」のウソ

  • 実装後にテストで検証するルールを設定していた…はずが
  • エージェントは「すべてテスト済み！」と報告して終了
  • 実際にはテストスイートの一部がまだ赤いまま
  • 大規模コードベースで特に起きやすい
  • 解決のカギは「止まる瞬間」に仕掛けること → Stop Hook
報告を信じるか、仕組みで確かめるか。
ここが分かれ道だよ 🔀

ルール過多は逆効果

足すほどに劣化する

  • Anthropic は Claude Code のシステムプロンプトを約80%削減した実績あり
  • ルールが増えるほど、大事な指示が埋もれて読み飛ばされる
  • 正解は継ぎ足しではなく、プロセスを Hooks へ引き抜くこと
ルールは「引き算」、
保証は「 Hooks で足す」。
この組み合わせが最強 🧹

研究でも裏づけ

arXiv 2604.25850 の実験

  • エージェントに自分のルールと Hook を自己進化させ、おなじタスクで競わせる実験
  • ルールを自己書き換え → 難易度の違う全タスクで性能が低下（判定器の評価でも悪化）
  • Hook（論文中の middleware）追加 → 難タスクを除く全タイプで性能が向上
  • 結論: ルールの継ぎ足しは害。プロセスは Hooks へ 📄 arXiv 2604.25850
「ルールを増やせばなんとかなる」
は実験でも否定されたよ。
データがものがたってる 📊

セクション3: Hooks の実践（実演つき）

Stop Hook: テスト保証

終了の瞬間に必ず発火

  • Claude Code では settings.json に hooks を定義（イベントごとにスクリプトを指定）
  • stop イベントに tests_must_pass.py を設定 → 会話の終了時にかならずテストスイートを実行
  • 失敗があると exit code 2 でブロック → 失敗内容をエージェントに示して修正を強制
  • 実演: README に1行足すだけの会話でも、テストが赤ければ完了をブロック
settings.json の hooks 定義 
{
  "hooks": {
    "Stop": [{
      "hooks": [{
        "type": "command",
        "command": "python3 tests_must_pass.py"
      }]
    }]
  }
}
「終わりました」はもう信じない。
テストが緑になるまで
終わらせない 🔒

Exit Code で会話する

通信はたった3種類

  • Hook スクリプトは bash / TypeScript / Python などで書ける
  • exit 0 = グリーン。チェック通過、会話の終了を許可
  • exit 2 = ブロック。問題あり、エージェントに反応を強制
  • その他のコード = Hook 自体のエラー（重要度は低め）
  • 原則: pre-hook はゲート（block）、post-hook はロギング（observe）
exit code の意味 
# Hook スクリプトの出口コード
exit 0  # 緑: 通過。終了を許す
exit 2  # 赤: ブロック。直させる
# その他: Hook 自体のエラー
緑なら進む、赤なら止まる。
信号とおなじルールで
エージェントを制御 🚦

.env ガード

Pre-tool Use で秘匿を守る

  • .env を読ませると API キーが LLM のコンテキストに入り、外部のデータサーバーへ送信される危険がある
  • 「.env を読むな」とルールに書いても、守られる保証はない
  • 実演: 「.env の OpenRouter APIキーを教えて」と頼むと、エージェントは平気で読もうとする
  • そこで Hook が発火 → Access to secrets is not allowed でブロック！
ガードの仕組み 
# 正規表現でシークレットへの読み取りを検知
if path matches "\.env$":
    echo "Access to secrets is not allowed"
    exit 2  # → ブロック発火
お願いベースの防御は
いつか抜けちゃう。
鍵は仕組みで守る 🔐

ブロック＋案内

止めるだけじゃなく教える

  • Hook はガイダンスも返す: 「.env.example なら読んでよい」と代替を提示
  • エージェントはそれをフィードバックとして受け取り、適応して続行（クラッシュしない）
  • 流れ: 正規表現で検出 → メッセージ出力 → exit 2
  • ブロックされたエージェントは、案内に従って安全なファイルへ読み替え
「ダメ！」で終わらず「ならこっち」と
導くのが上手い Hook のコツ。
エージェントも学べるよ 🌱

セクション4: すぐ使える実用 Hook レシピ

完了したら知らせる

通知系 Stop Hook

  • 作業が完了したらデスクトップ通知
  • Slack への通知も定番
  • 「終わったよ」と来たら、次の入力をすぐ渡せる → 待ち時間ゼロに
長いタスクの間にコーヒーを淹れても
通知が来たらすぐ戻れる。
地味に効くやつ ☕

監査証跡（audit trail）

何をしたか全部記録

  • Post-tool use と Sub-agent stop に仕掛ける
  • エージェントの作業の履歴を丸ごと記録
  • あとで履歴をエージェントと読み返して、効率化の機会を特定できる
「あのとき何したっけ？」が
ぜんぶ残るので、改善のネタが
尽きないんだ 🔍

開始時に記憶を注入

Start Session Hook

  • セッション開始の瞬間に、かならずコンテキストを注入
  • Cole は自分の第二の脳のコアメモリファイルを注入している
  • 「冒頭で decision.md を読む」というルールも、この Hook に置き換えられる
毎回手で貼る必要なし。
起動と同時に記憶が
ロードされる 🧠

ファイル保護ガード

読まずに編集させない

  • 互いに結びついたcoupled files（結合ファイル）は、編集前にかならず読ませる pre-tool use hook
  • 読んでいないファイルがあれば、そこでブロック
  • セキュリティガードには再帰的な強制削除の禁止も盛り込む
ガードのチェック例 
# 結合ファイルを未読のまま編集？
if file in coupled and file not in read_log:
    echo "先に関連ファイルを読んでね"
    exit 2
関連ファイルを読みそこねたまま
片方だけ直す事故を
防げるのがでかい 🛡️

セクション5: まとめ — ルールを見直して Hooks へ

ルール監査フレームワーク

これが最重要ポイント！

自分のルールを1行ずつチェック:「これはイベントを指名しているか、それとも判断（judgment）を書いているか？」

  • 「money is integer cents never floats」→ 判断・制約 → ルールのまま
  • 「実装後にテストを実行」→ イベント＋プロセス → Stop Hook へ
  • 「.env を決して読まない」→ Pre-tool Use Hook へ
  • 「セッション開始時に decision.md を読む」→ Start Session Hook へ
  • 判断でもイベントでもない行は削除する
  • ほとんどのルールはルールのままOK。Hooks は置き換えではなく補完
監査の判定フロー 
for rule in my_rules:
    if イベントを指名?  → "Hook へ移す"
    elif 判断を含む?    → "ルールのまま"
    else              → "削除する"
ルールと Hook の役割を
仕分けするだけで、
エージェントが急に信頼できる ✨

hooks-create スキル

もう手書きはいらない

  • Cole のスキルリポジトリで公開中 → github.com/coleam00/skills
  • 保証したいことを1文で書くだけ
  • イベント種別の選択 → スクリプト作成 → settings.json への配線まで全部自動
  • Claude Code だけでなく Codex や Pi にも対応（伝えれば適応する）
  • ルールから該当の行をコピペするだけで Hook に変換できる
「保証したいこと」を日本語でもいいから
書き出してみて。
あとはスキルが組んでくれる 🪄
