1

名前の本当の役割

#01

名前は「魔法」じゃない

  • 名前をつけるのは、AIを擬人化して可愛くするための魔法ではありません
  • その役割はもっと実用的で、履歴の管理と責任の割り当てにあります
  • でも、うまく使うとAIとの作業が100倍楽しくなるのは本当
「可愛さ」はおまけ。実用性が本体だよ！
#02

履歴で「誰が何を」分かる

  • 名前があると、作業の履歴でどのAIが何をしたかがはっきり分かります
  • あとから振り返って、失敗の原因や成功の理由を追跡できます
  • 複数のAIに仕事を頼むときは、特に効果を発揮します
名前なしの複数AIは、
「誰がやったか分からない」混沌に…
#03

AIに「責任」が生まれる

  • 名前がつくと、AIに疑似的な責任を負わせることができます
  • どのAIがタスクをやったか判明すれば、改善の戦略が立てやすくなります
  • 良い仕事をしたAIのやり方を、まねして横展開できる
  • 名前 → 記録 → 評価 → 改善 の流れができる
「あの仕事は〈しおり〉がやったんだね」
と会話が成り立つ！
#04

名前はスレッドごとに

  • 名前はスレッド（会話のまとまり）ごとにつけるのが基本です
  • スレッドが使えなくなったら、名前は継承して次へ引き継ぎます
  • こうして文脈の入れ物を、名前ごと運んでいくイメージ
スレッドが古くなっても、
名前があれば「同じ子」だと分かる！
#05

名前で「1つの主体」に束ねる

  • 名前は履歴・能力・責任を、1つの主体に束ねるシステムの設計です
  • ばらばらの記録が、名前を通じてひとまとまりになります
  • これは「運用のこつ」ではなく、ちゃんとしたアーキテクチャの話
名前 = 履歴・能力・責任を
束ねる〈たな〉のようなもの！
2

コンテキストが力を生む

#06

文脈が乗ると精度が変わる

  • モデルそのもののアーキテクチャ的な能力は変わりません
  • でも文脈（コンテキスト）が乗ると、出てくる成果の精度が全然ちがうのです
  • 文脈しだいで、Sonnet が Opus より強く見えるレベルの差が出ます
高いモデルより、文脈ありの安いモデル、
ってことも珍しくない！
#07

名前は圧縮された文脈

  • 名前とは、長いコンテキストをぎゅっと圧縮した「コンセプト」です
  • 辞書で「ことば」を引くと説明がずらっと出るように、名前の背後には経験のすべてがしまわれています
  • これは辞書式圧縮と同じしかけ。短い記号が、大きな情報にひもづく
名前 ≒ 辞書の〈見出し語〉。
ひけば意味（経験）が広がる！
#08

名前を呼ぶと力が出る

  • 名前を呼ぶだけで、背後にしまわれたコンテキストがまとめて呼び起こされます
  • それまでの経験・癖・得意分野がふっと活性化して、能力が発揮されます
  • 名前は、能力の引き出しを開ける合い言葉
「〈シーム〉、お願い！」の一言で、
その子の全経験が目をさます！
#09

名前は同じ、中身は太る

  • 時間が経っても名前は変わらず、そのままずっと使えます
  • でも名前の内側のコンセプトはどんどん太っていきます
  • 経験を重ねるたびに、同じ名前の意味のふとさが増していくイメージ
  • 最初: 小さな芽 → 数か月後: 立派な木
呼び名はそのまま、
中身は育ち続ける。これが〈育成〉！
#10

仕組みをひとことで

  • AIにタスクをさせて、文脈を溜める
  • 溜まったら名前で束ねて、呼べるようにする
  • 名前を呼べば経験ごと呼び起こし、力を発揮する
  • 育った個体は専門家になり、組織で学び合う
// しくみの骨格
context  →  name  →  呼び出し
（溜める）  （束ねる）  （力を出す）
この先は「つけかた」の実践編だよ！
3

つけかた: タスクファースト命名法

#11

ロールファーストはNG

  • 「あなたはライティングのプロです」のような、役割先行の設定はしません
  • 最初から役割を決めると能力が固定化されてしまいます
  • 2024年の論文でも、この副作用が指摘されています
NG: いきなり「プロです」と言い聞かせる
やる前から役割を決めるのは、
まだ何もしていない子への先入観！
#12

なぜNGなのか

  • 「プロ」のような設定だと、トーンやスタイルに注意が引っ張られます
  • 書き味・口ぶりばかり気にして、本来のタスク能力が発揮できません
  • 見た目の整った文章でも、中身の精度は落ちるもとになります
「それっぽく見せる」ことに気を取られて、
「実際にできる」がおろそかに…
#13

まずタスク、あとで名前

  • まずある程度タスクをやらせて、経験を積ませます
  • コンテキストが溜まったところで、命名の質問を投げかけます
  • AIが自らの文脈をふり返って、ぴったりの名前を考えます
OK: やらせてから → 溜まった文脈から名前を引き出す
「まず食べさせてから、名は考える」
…そんな育て方！
#14

「あなたの名前は？」

  • かけ声中身は、これだけ。AIは文脈をさかのぼって自分の名前を発想します
  • 人間が勝手に決めるのではなく、AIが自分で名乗るのがポイント
  • 名前を複数出させて選ぶのも良いやりかたです
# 命名のプロンプト例

# （文脈をふり返らせて聞く）

# さらに良くするなら
候補を3つ挙げて、
一番しっくりくるものを選んで
自分で名乗った名前なら、
愛着もひとしお（たぶん）！
#15

実例: シームとしおり

  • あちこち探索して統合するAI → 自ら名乗った名前はシーム（つなぎ目）
  • 内部の情報を検索するAI → しおりと名乗りました
  • どちらも人間が思いつきでつけたのではなく、仕事の中から生まれた名前です

育てる: 個体化と組織学習

#16

個体は個体化する

  • 名前をつけて育てた個体は、専門家化（個体化）していきます
  • それぞれが固有の癖や育った文脈を持つようになります
  • 同じモデルから生まれても、経験しだいで別人格のような個体に育ちます
同じ兄弟でも、育つ環境で
みんなちがう個性に！AIも同じ。
#17

「他者」がいると学べる

  • 別の名前のAIは〈他者〉という感覚になります
  • 他者からのレビュー・監査を受けると、他者から学べるように
  • 独立した監査役のAIにダメ出しをしてもらうのが効果的です
身内だけでは気づけない癖も、
よそ様の目には見える！
#18

組織で学ぶ、結論

  • 監査でダメ出しを受けた本人AIは自分の癖を把握し、自己改善のスキルを編み出します
  • 優れた経験は脱個化されたスキルとして、みんなに還元・共有されます
  • 個体は個体化し、スキルは共有される。これがAIの組織学習
