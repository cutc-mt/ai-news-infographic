05

① ハイブリッドアテンション

  • 全48層を gated delta ×3 + QSA ×1 の繰り返しで組む
  • gated delta = 線形アテンション（軽い流し読み担当）
  • QSA = Qwen Sparse Attention。トークンでなく microblock 単位で選ぶ
  • 長文コンテキストとエージェント workload で低レイテンシ
# 48層のリズム（イメージ）
for block in range(12):
    layers += [GatedDelta] * 3   # 速い
    layers += [QSA]       * 1    # 精査
全部をじっくりよむのではなく、要点だけじっくり。速さと精度のバランス設計だね
06

② n-gram 埋め込み層

  • 125B のうち 51B が bigram / trigram 埋め込み！
  • いわば フレーズ辞書を内蔵するしくみ
  • この層は GPU でなく通常 RAM に置ける
  • パラメータを増やしても計算量は増えない → メモリ制約ハード向き
容量は食うけど、辞書のよみ書きはほぼタダ。発想の逆転がおもしろい！
07

③ MoE の中身

  • 専門家 512体 のうち 11体 だけアクティブ
  • multi-token prediction で推論を高速化
  • gated residuals で学習を安定させる
  • 「幅広い知識 × 少人数の実働」の組み合わせ
512人体制の職場で、実際に話を聞くのは11人だけ。 payroll は軽い！
08

④ コンテキストの長さ

  • ネイティブで 262K tokens
  • YaRN を使えば 1M まで拡張できる
  • 長文 RAG や大量の履歴を読むエージェント向き
262K →（YaRN）→ 1M tokens
100万トークンって、ぶあつい本がなんども読める量。長いおくりものも安心

GGUF クォントのラインナップ

クォントサイズひとこと
1bit72〜74GB最軽量
2bit79GB軽め
3bit82〜90GBバランス
4bit94〜111GB高精細
  • 配布元は Unsloth の GGUF
  • RAM の余裕に合わせて bit 数を選ぶ
1bit でも 72GB 超！ 「小さい」といっても大人サイズなのに注意
17

必要なマシンの目安

  • 快適に動かすなら 96〜128GB RAM
  • 128GB unified memory の Mac がスイートスポット
  • 6B active なので、トークンあたりの計算はごく微小
  • memory hungry but compute light
  • GPU がなくても CPU だけで実用速度が出る設計
「メモリは食うけど計算は軽い」という逆転の発想。RAM 盛り盛りの Mac がまさに狙い撃ち！

実行の方法は3つ

  • Ollama: まずひとつ試すならこれ
  • llama.cpp: OpenAI 互換サーバーとして起動
  • vLLM / SGLang: 本番運用向け
  • ハードがなければ $0.16/M の API も一択
# Ollama で動かす（QUANT は Q2_K などに置き換え）
ollama run hf.co/unsloth/qwen3.8-flash-next-gguf:QUANT

# llama.cpp で OpenAI 互換サーバー
llama-server -m qwen3.8-flash-next-Q4_K_M.gguf \
  --port 8080
とりあえず Ollama の一行から。動かなかったら API に逃げても痛くない値段！
