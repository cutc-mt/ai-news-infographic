1. そもそも WPX って何？
01

マネージド hosting とは

  • WordPress に特化したサーバーサービス
  • 裏方の世話を WPX 側が引き受ける形
  • プランは WordPress WooCommerce 代理店向け の3系統
「管理つき」＝ 使う側は書くことに集中できる、ということ
02

安い共有サーバーだと

  • もらえるのはサーバーのスペースだけ
  • WordPress の導入は自分で
  • cache plugin も自分で選んで設定
  • セキュリティ・backup・CDN もぜんぶ自前
「安い」は初期の値段の話。手間は別勘定になるのだ
03

買うのは「時間」

  • 導入・backup・セキュリティ・速度・移行をひとつに束ねる
  • 面倒で退屈な悩みを 誰かが代わりに持つための代金
安い共有 スペースだけ
あとは自分の責任で
WPX まるごとおまかせ
束ねて提供
支払うのは「速さ」と「手間を減らす」の両方、なのだ
2. どれくらい速い？
04

自社 CDN「XDN」

  • データセンターは 3拠点
  • でも XDN の配信拠点は 40以上
  • London・Sydney・Mumbai・São Paulo・Lagos など
  • 訪問者の近くの拠点からページを届ける
データセンターの数と配る速さは別物。配信拠点の多さが強みなのだ
05

ベンチの読み方に注意

  • Kevin Ohashi の WordPress hosting ベンチで良い成績
  • ただし参加はオプトイン制（参加費を払った host だけ）
  • 大手が出ていない = 半分の走者が来ていないレース
ベンチで良い成績 でも参加は希望制 「地球最速」とは言えない
数字は信用しつつ、出場者の顔ぶれも見るのだ
3. 一番の論点はサポート
06

ボットではなく人が答える

  • AI チャットボットを挟まない 生身の対応
  • ライブチャットの反応は平均 約30秒
  • 90% はチャットのままリアルタイムで解決
「あとでメールします」ではなく、その場で終わるのが大きいのだ
07

fixed for you guarantee

  • ヘルプ記事を渡す代わりに、チームが診断して直す
  • 平易な言葉で説明 → 無償で修正

対応するもの

  • 復旧・WordPress の導入
  • SSL・redirect・DNS 変更・XDN 設定

対応しないもの

  • 他社 plugin のコード書き直し・見た目の CSS
  • 悪い plugin は特定して止めるところまで（直しはしない）
対象外を最初から明記しているのは誠実、なのだ
4. はじめから入っているもの
08

守りと備えの束ね売り

  • 毎日の自動 backup
  • 毎日の malware scan ＋ 無償での除去
  • 総当たり攻撃の防御・ハイブリッド DDoS 防御・WAF
  • 無料 SSL・2要素認証・XDN
バラで買って保守する時間まで値段に入れると、割に合う計算なのだ
09

引っ越しは無償・回数上限なし

  • 移行の回数に 上限なし
  • plugin 任せではなく チームが手で動かす
  • 大半は 丸1日で完了
  • 途中の debug と malware の掃除まで込み
引っ越しの大変さを、そっくり外に出せるのだ
5. 料金とプランの読み方
10

3系統のプラン構成

  • 入門の共有サーバーより はっきり高い
向き先プラン名（下から順に）
WordPressStarter → Business → Professional → Elite
WooCommercePowerStore → SuperStore → HyperStore
代理店エージェンシー向けの tier
  • 上に行くほど site 数・storage・RAM・CPU・PHP workers が増える
何を足すかより、何が要らないかから選ぶと迷わないのだ
11

PHP workers とは

  • 同時にさばける処理の数
  • レジの台数に例えると分かりやすい
  • traffic が一気に増えたときに 効く枠
workers が少ない 混雑で処理が詰まる
表示が遅くなる
workers が多い 同時にさばける
急増にも耐える
動画・EC・ニュースなど「読みに来る人」が多いほど重要、なのだ
6. 注意点は4つ
12

注意1: 値段が高い

  • 入門の共有サーバーと比べると明確に高い
  • 予算次第では 安いサーバーで十分
  • 「買うもの」が違うので、単純な比較は難しい
まず月いくらまで出せるか決めてから見るのだ
13

注意2: Redis は上位だけ

  • Redis object cache は入門 plan にはなし
  • 必要なら買う前に plan 表で確認を
Redis が要る？ まず plan 表を開く 上位 plan で比較
入門 plan で速さを目一杯狙いたい人は、ここで止まるのだ
14

注意3: 動く部分は速くならない

  • XDN は動的な中身を cache できない
  • 該当は カート・login session・個人ごとの表示
  • WPX 自身の文書が認めている点
  • 動きが重い WooCommerce 店舗は blog ほど恩恵なし
30日保証のうちに、本番の site で試すのが一番、なのだ
15

落ちた記録が見えない

  • 公開の network status page がない
  • きちんと動いているか、外からは確かめられない
  • 「大丈夫です」という言葉だけが頼り
大事な site なら、落ちていないか見る仕組みを自分で足すと安心、なのだ
7. まとめ: 誰に向くか
16

向いている人

  • 仕事で使う Web site の持ち主
  • 顧客の site を管理する freelance・代理店
  • 表示の速さが traffic に直結する記事 site など
  • 深夜に server の debug をしたくない人
「時間を買い戻したい人」の顔が見えるリストなのだ
17

過剰になってしまう人

  • 初めての趣味の blog
  • とにかく予算を抑えたい人
  • 自分で stack を組める技術者
持て余す機能にお金を払うことになる、のだ
18

結論: 買うものは何か

  • 生の速さではなく 速さ＋面倒な重荷を誰かが持つ を買う
  • 30日保証 のうちに本番 site で試す
  • 訪問者のいる国から speed を測って判断
契約 本番で試す30日 合うなら残す
宣伝を信じるより、自分の site で確かめるのが一番、なのだ
