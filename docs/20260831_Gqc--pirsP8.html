そもそも AI slop とは何か

AI slop という問題

中身が薄くて読む気をなくさせる文章

どんな文章か

  • AIが作った中身が薄い文章が問題視されている
  • 読んでいるとちょっと萎える低品質なコンテンツ
  • 世界中で話題に。WikipediaのAIライティング増加も解説済み
  • 今日のテーマは「ここにどう対策するか」
AIスロップ＝中身が薄く低品質なAI製コンテンツ。読み手を萎えさせるのが問題！

無難な表現に収束する

LLMの仕組みから来る“癖”

なぜ起こるのか

  • LLMは次に来る確率が高い言葉を選ぶ性質
  • 掘り進めると最も無難で平均的な表現に収束
  • 「これClaudeっぽい」「GPTっぽい」「Grokっぽい」というモデルごとの癖
  • 無難な入力をすると、大体同じところに集まる
予測できるAIの癖だと思えばいい。収束をずらす努力が対策の出発点！

記号と形式の癖

まさおさんが特に気になるポイント

見た目でわかる兆候

  • 過剰なダッシュ記号（タイトルにも乱発）
  • 太字の連発→「これ Gemini っぽい」と感じる
  • 1,2,3の番号＋太字で区切る情報の切り方
  • 英語だと「XではないY」や「研究によれば」も定番
  • 人間があまり使わないワードがチラチラ見える
読みにくいわけじゃない。でもなんか違和感…その直感がAI臭さを見つける手がかり！

モデル別の対策が必要

汎用スキルだけでは足りない

個別に作り込む視点

  • 「Claudeはレインボー装飾が出やすい」など癖を把握
  • 記号の癖が既知なら決定論的に弾く（hooksで判定も）
  • Opus向け対策がGPTやGrokに通用するとは限らない
  • 各モデルの「無難な収束」へ個別に対策を重ねる
Claude用のスキルが他モデルに全部当てはまるとは限らない。モデルごとの癖を知るのが先！

4つのスキル、どこが違う？

stop-slop

8原則を5軸で採点して「鍛える」

GitHubスターあり 文章術タイプ

仕組み

  • 悪い文章に対して8つの原則リストを用意
  • 原則を5軸で採点して評価
  • 文章ルールをクリアしたら合格とする方式
  • 「いい文章とは何か」まで規定する、文章術っぽいスキル
  • 内容は短め。ただし基本形の参考になる

スキルの骨組み（イメージ）

# stop-slop: 8原則 × 5軸で採点
principles = ["明確さ", "簡潔さ", "具体性", ...]  # 8原則
score = evaluate(text, axes=5)
if score > threshold:
    verdict = "合格"  # ルールを守れていれば合格
「鍛えていく」系。何がいい文章か決めて、点数で伸ばしていくタイプ！

no-ai-slop

書き手の声を“守る”スキル

守るタイプ モード3つ

何を守るか

  • 書き手の声・癖を残す
  • 具体的な数字も守る対象
  • 反対に除去ゾーンのパターン表現は削っていく
  • 定型表現や二項対立的な言い回しも除去対象
  • スキル自体はシンプル気味。ワーク付き

3つのモード

  • 用途に応じて切り替えられる3モード構成
「守る」系。あなたの書き味を消さずに、AIっぽさだけ取り除く考え方！

portability test

no-ai-slop 独自の判定基準

唯一無二の発想

テストの内容

  • 別の人・別の会社・別の製品に差し替えても成立する文章は…
  • …そのまま削除対象と見なす
  • 誰にでも当てはまる汎用性をスロップの兆候と捉える
  • この発想は紹介4スキルの中でno-ai-slopだけが持つ特徴

portability test（イメージ）

# 「誰にでも当てはまる」を判定
for sentence in text:
    if works_with_anyone(sentence):  # 別人・別社・別製品でも成立
        remove(sentence)  # 汎用すぎる＝スロップの兆候
どこにでも置ける文＝誰の文章でもない証拠。この発想はまさおさんも「面白い」と注目！

humanizer

35パターンを作って消して調節

消すタイプ パイプライン方式

3段階パイプライン

  • まずバッと文章を作る
  • フィルターを通してAI作成の兆候を処理
  • 最後に調節して仕上げる

35パターン

  • AI作成の兆候リストを詳細に分類
  • 兆候をスキャンしながら強弱を調節
  • Wikipedia系動画の実践知を参考に作られている
「消す」系。パターンを網羅して、兆候が残らないよう調整するタイプ！

humanize

統計量をハードルールで縛る

測るタイプ まさおさんの一押し

アプローチ

  • AIらしい癖を消すよりAI検出機が測るシグナルそのものを動かす
  • 検出機の値を人間側へ移す方向に統計量を操作
  • 書き方をハードルールで縛るがっちり系

具体的なルール例

  • 記号の癖は300に1本までなど数値で制限
  • 禁止語リストを運用
  • 言葉の中身の部分までしっかり対象化

ハードルール（イメージ）

# humanize: 統計量を数値で縛る
rule_em_dash = "ダッシュは300語に1本まで"
rule_banned  = ["delve", "tapestry", ...]  # 禁止語
stats = measure(text)  # 検出機が測る統計量
rewrite_until(stats, target="人間側")
「測る」系。まさおさんが4つの中で一番面白いと感じたスキル。根拠もしっかり書かれている！

4スキルの共通構造

形式は同じ、編集方針が違う

共通する形式

  • どれもskillsディレクトリ直下に置くAgent Skills
  • 中身はパターン集＋書き直し指示でAIに直させる形式
  • 違うのはAI臭い文章をどう編集するかの方針だけ

選び方の指針

  • 「何を検出できるか」より「何を守りたいか」で選ぶ
  • パターンの考え方は別のハーネススキル作りにも参考になる
骨格はみんな同じ！違うのは“編集の思想”。守りたいものから選ぼう。

一行比較表

4つの思想を並べると見えてくる

スキル × とらえ方

  • stop-slop＝文章を鍛える（8原則×5軸で採点）
  • no-ai-slop＝書き手の声を守る（portability test）
  • humanizer＝兆候を消す（35パターン調節）
  • humanize＝統計量を測って縛る（ハードルール）
鍛える・守る・消す・測る。同じ問題に4つの思想が向き合っている！

思想の位置づけ

強制度で見ると分かりやすい

強制の強さと守る軸

  • no-ai-slop：強制が薄め。逃してしまう部分もあり
  • stop-slop：原則を守れていれば合格。教育寄り
  • humanizer：兆候パターンをフィルタで除去
  • humanize：数値ルールでがっちり固定。最も厳格
ゆるい守り → 厳しい縛り。自分の文章にどれくらい“輪をかける”かで選ぶ！

実践するときの考え方

日本語は自力最適化

4スキルは英語圏の産物

日本語への道筋

  • 紹介スキルの基準は英語の統計がベース
  • 日本語は自分で最適化するしかない
  • 良い部分を栄養素として取り入れて調節しながら自作へ
  • まさおさん自身、日本語スキルを極めている最中
英語ルールをそのまま使っても日本語には合わない。取り入れて、自分の言葉に調整しよう！

やりすぎ注意

完璧を狙いすぎると逆効果

素っ気なさの罠

  • 完璧な文章を目指しすぎると素っ気なさが残る
  • そのそっけなさ自体がAIっぽさとして感じられてしまう
  • バランスが重要。humanizer系で特に注意
  • 抽象度の高い問題解決では“ほどほど”の視点を持つ
AI臭さを消しすぎると、今度は“無味乾燥な文”がAIっぽく見える。加減が大事！

モデル評価の誤解

「読みにくい＝モデルが悪い」ではない

評価の落とし穴

  • 「文章が読みにくいからこのモデルは良くない」という表面上の評価が出がち
  • Opus 4.8などでも同様の指摘が起きた
  • 実際はある程度の対策でマシになるというのがまさおさんの実感
  • トークンを燃やして探索しまくった結果の知見
読みにくさはモデルのせいだけじゃない。スキル次第でかなり改善する！

応用アイデア

報告書や資料にも効く

自分の仕事に取り入れる

  • 報告の書き方にも応用できる
  • 結論の色づかいなど見た目のカスタマイズ
  • メンバーシップではHTML報告フォーマットが人気
  • 認知負荷対策の動画スキルも共有中
記事だけでなく報告書・スライド・動画まで。AI臭さ抜きの見せ方はいろいろある！

まとめ：次の一歩

持ち帰りの公式

真似するための流れ

手順にすると

  • 4つのSKILL.mdを見比べる
  • いい部分を要素として取り入れる
  • 日本語向けに調節して自作スキルへ
  • hooksやモデル別の癖対策と組み合わせる

導入イメージ

# skills ディレクトリに配置して使う
~/.claude/skills/
  └── my-japanese-style/  # 自作の日本語スキル
      └── SKILL.md  # 4つから良いとこ取り
見比べる → 真似る → 日本語化。この3ステップで誰でも始められる！

コミュニティの力

noteメンバーシップ「AI駆動開発研究部」

みんなで深ぼる

  • 自作の日本語スキルを共有中
  • 新しい概念の提案・設計をし、共通言語にして深掘り
  • ハーネス（ループ系）スキルも複数パターンで共有
  • 来月は月3回の勉強会を予定
  • 0→1発明、1→10実践も徹底的にやる
何ヶ月も前から課題に向き合う仲間がいる。切磋琢磨できる環境がそこに！
