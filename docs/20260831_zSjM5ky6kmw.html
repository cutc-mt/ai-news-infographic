生成AIの正体

ベースは文字を作るだけ

  • 生成AIの基本機能は「次の言葉は何かな?」と予測するだけ
  • 例：「昨日の議事録をまとめて」→ 次の言葉を作って、見せて、また作るの繰り返し
  • ファイル検索などができるのは、外側の仕組みが頑張ってくれているから
モデル自体はあくまで「文字を予測する道具」。
できることを広げているのは外側なんです！
4

ハーネス＝器

  • ハーネスとは、モデルを包む外側の仕組みのこと
  • 検索エンジンを叩く・画像を作る・パソコンを操作して開発する
  • 今やできること：Web検索画像ファイル読み込みテストブラウザ操作
  • SlackやGmailなどとの連携も今後どんどん増える
  • これこそがAIエージェント＝代理人として指示を受けて動く仕組み
文字しか出さないのに何でもできるのは、ハーネスさんが頑張ってるから！
5

3階層構造

ハーネス：Claude Code / Codex がいる場所
モデル（指令塔）：ChatGPTならGPT系 / ClaudeならOpus系
U＝使い手：どこで開く? 何を読ませる? どうやる?
  • モデルの性能も、ハーネスの性能もほぼ互角で変わらない
  • ハーネスは一部だけ自分で改造できるが、基本はそのまま使う
  • いちばん大事なのは3階層目の使い手！
Claude Code 対 Codex は「モデル対決」ではなくハーネス対決だと思って！
6

成果の方程式

  • 成果を決める式はこれ！
# 成果を決める方程式
成果 = モデル × ハーネス × 使い手
  • 本当に差がつくのは使い手の熟練度の部分
  • 極めていないClaude Codeより、極めたCodexの方が強い
  • エージェントはループで回る：依頼 → 結果のフィードバック → もう1回 → くり返しで性能が上がっていく
式の前半2つはどこも一緒。
掛け算の最後の項＝あなたで差がつく！

8

差① ブラウザ操作

  • CLIやIDEでは使えないが、デスクトップアプリなら何でもあり
  • 例：「渋谷でご飯食べたいからお店を探しといて、サイトをちゃんと開いてチェックして」
  • お店の予約などサイトが開いてるか確認したい作業が得意
  • ブラウザ操作のMCPを入れればClaude Code側でも対応可能という言及も
チャエンさんが一番気に入ってる機能。ブラウザの動きが早くて正確！
9

差② 回答速度

  • モデル込みでCodexの方が全体的に早い
  • Claude CodeはモデルをSonnetなどに下げると速度が上がる
  • 「速度と質」のバランスで使い分けるのがおすすめ
すぐ答えが欲しいとき・サクサク進めたいときは
高速側に切り替えるのがコツ
10

差③ 画像生成

  • CodexはChatGPTの画像生成がデフォルトで使える（地味に強い！）
  • 「画像作っといて」でInstagramの投稿画像まで作れる
  • Codexなら月額サブスクの範囲内で画像生成が可能
  • Claude Codeはデフォルトなし。APIを繋げば作れるが1画像ごとに課金
作れないわけじゃないけど、お金の仕組みがちょっと違うよ！
11

差④ スマホ操作

  • パソコンが動いていれば、スマホから自由にフォルダを選んで作業できる
  • Codex：開いてないフォルダも0から開ける
  • Claude Code：開いてるフォルダだけ触れる（セッションの引き継ぎ中心）
  • 普通にペアリングするだけで使える手軽さが魅力
  • UI/UXの滑らかさ・チカチカ動く操作感も好みのポイント
出先から自宅のパソコンを操れるのは
かなり強い強みなんです！

第3章｜私の使い分けと二刀流

12

メイン：Claude Code

  • メイン機はClaude Code。最初に極めたので一番慣れている
  • 仕事の作業・開発・動画編集まで全部こちらで
  • 使い込むほどメモリ機能やMDファイルに自分の情報がたまる
  • 1つのツールに絞った方が、AIが自分のことを分かってくれる＝性能が上がりやすい
相棒には一貫性が大事。普段使いはメイン1本に！
13

秘書：Codex

  • メインに覚えさせたくない仕事を任せる：外食のお店探し・航空便の検索などブラウザ系
  • ちょっとした調べ物・もの買いにも
  • 「誰得?」な遊び開発もCodex担当：映画インターステラーのガルガンチュア（ブラックホール）突込シミュレーション
  • ブラックホール近くの時間の遅れまで計算する謎サービスを作ったり
  • 作業の記録をファイルに残せば、ローカルに置いておけばClaude Codeも読みに行ける
本業の記憶を汚さない外回り担当という立ち位置！
14

AGENTS.md 二刀流

  • 記憶ファイルの名前が違うだけ：Claude CodeはCLAUDE.md、CodexはAGENTS.md
  • 実はClaude CodeもAGENTS.mdを読める！
  • 共通の記憶をAGENTS.mdにまとめれば二刀流が成立
  • 認証系・実行環境はセキュリティのため別管理、それ以外は共有
  • 注意：自動メモリーはClaude Codeで使うとClaude Codeでしか覚えない。共有したい記憶はファイルに書き出そう
# AGENTS.md（二刀流の設定例）
記憶:        AGENTS.md に共通化 # 両ツールが読める
スキル:      共有
ステータス管理: 共有
認証・実行環境: 別管理（セキュリティのため）
ファイル名をそろえるだけで両刀使いになれる、お手軽テク！
15

使い手が極める要素

  • フォルダ階層の設計
  • 記憶の設計
  • スキルの管理
  • MCP（外部ツール接続）
  • パーミッション（権限）の境界線
  • 自動化とサブエージェント（作業の分割）

コンテキスト管理が全ての基礎

  • AIが読める記憶の幅は決まっていて、埋まると性能が落ちる
  • 情報は節約しながら効果的に与えるのがコツ
  • 3年前のブラウザ版チャットとは別世界。出力の質が個人の熟練度に依存する時代に
コンテキストを汚さずに保つ技術こそ、エージェント使いの基本！

最終章｜エージェントを極めるのは念能力

16

AI活用は念能力

  • チャエン流のたとえ：「AI活用とは念能力」
  • 念能力と同じで、極めるほど強くなる性質を持つ
  • 習熟ランクは4段階：優 → 秀 → 天賦 → 極
  • 念能力は作中でも選ばれた一部しか使えない（人口の0.0数%、ハンターは約600人）
  • でもAIエージェントは月20ドルで誰でも極められる！「だったら使いこなそうぜ」がチャエン流の理論
ハンター×ハンターを知らなくても大丈夫！
「極めた者が強い」という話だけです
17

纏・絶・練・発

  • 纏（テン）：オーラをとめる → 基本を身につける
  • 絶（ゼツ）：オーラを消す → コンテキストを遮断・節約
  • 練（レン）：オーラを大きくする → 鍛えて増強する
  • 発（ハツ）：必殺技 → 自分だけの活かし方を編み出す
  • Claude Codeに書かせたら「点・絶・連・発」と書いてくれた（この辺はスルーでOKな無理やり接続）
基本→遮断→増強→必殺技。
学びのステップにもぴったり！
