入口はスマホとアプリ

人がさわる部分

さわるところ
  • 人が触れるのは スマホ と デスクトップアプリ
  • チャット UI の中で、いろいろ指示を出す
  • ボットの グループ もつくれる
  • 裏側では、そのすべてが 1台の Linux の上で動く

複雑なものを、こんなに

1アカウント1台の
永続 Linux

スペックのうわさ

スペックを調べてみた
  • 1アカウント 1台 の Linux マシンがもらえる
  • メモリは 16GB と言われている…が
  • AI エージェントに調べさせたら 128GB くらい ありそうだった
  • マシンは 永続 なので、環境を育てていける
永続マシン 128GB?! 環境を育てる
消えてしまわないマシンだから、
メモリやノウハウをため込めるのが嬉しい 📦

共通のベースと
切り分け

ボット間のルール

共通になるもの／分かれるもの
  • ブラウザの ログイン情報 はボット間で共通
  • Hermes などの インストール状況 も共通
  • でも 操作画面はボットごとに分離
  • ボット A が Chrome で開いた画面は、ボット B には映らない
  • 共通の 引き出し がありつつ、ちゃんと切り分けられている
この「共通 × 分離」のバランスが
使いやすさの味の決め手なんだ ✨

つながり方
  • チャットはふつうの チャット UI でおこなう
  • SuperGrok のアカウントからログインできる
  • 外の世界は 外部連携 で、たとえば Slack や X とつながる
  • この仕組みをおさえておくと、Grok Bot が 動かしやすく なる
Slack 連携 X 連携 SuperGrok ログイン

ボット設計の深み

1マシンなのに
複数ボット

ここが個人的に良い、とのこと

なぜ深い？
  • 直感的に考えると 1マシンに1ボット でよさそう
  • なのに 複数ボット をつくれて、操作画面もちゃんと分かれる
  • 関心ごと もボットごとにきっちり分けられる
  • シンプルなのに、これを実現するのは むずかしかった はず
  • シンプルさと自由さをあわせ持つ 深み
かんたんに見えるほど、
中身の設計はしっかりしているんだ 😊

説明を書いて
特化させる

設定の「説明」が効く

書けること
  • 設定のところに 説明 をしっかり入れられる
  • 「あなたは CFO ボット として使う」みたいな役割づけだけじゃない
  • ちゃんとした説明まで入れて、その子に 特化 させる
  • CLAUDE.md のような説明書きをボットごとに持たせるイメージ
役割の「名前」ではなく
「説明」で仕立てられるのが本物感 📜

ディレクトリごとの
専門ボット

使い分けの実例

こんな使い方ができる
  • 「この ディレクトリの中でメモリを育てて」と指示できる
  • ターミナルを操作させて、仕事をさせる
  • たとえば「三房くん」は Claude Code を使う
  • 「モブくん」は OpenCode を使う、と権限をわける
  • A / B / C のディレクトリで、作業するボットを分けられる
# ボットのすみわけイメージ
bot-A: OpenCode で A/ の作業を担当
bot-B: Claude Code で B/ の開発を担当
bot-C: C/ の中で メモリを育てる係
使う道具も守備範囲も
ボットごとに決められるのが自由！ 👥

つくれる

関心ごとの分離

ループのしくみ
  • Grok Bot の中の Claude Code を使うボット
  • OpenCode を入れて、特定ディレクトリで作業するボット
  • それぞれに 専門スキル を持たせて使う
  • 担当が決まっているから 閉じたループ で迷わない
  • 特化のおかげで、全体が シンプル になる
関心ごとの分離 特化 複数保有OK
めちゃくちゃシンプルなのに、
そこに深みがあるんだ 🌀
自由な使い方と、注意点

Tailscale SSH で
外からつなぐ

強者っぽいカスタム例

やってみたこと
  • ボットに Tailscale を入れちゃう
  • Termius などのターミナルアプリで接続
  • 自分のパソコンから、Grok のマシンに 直接アクセス
  • 中の ハーネスを操作 することもできちゃう
  • リリースされて 速攻 で試していたとのこと
# こんな流れでつなぐイメージ
bot に Tailscale をインストール
→ 自分の PC / スマホから SSH 接続
→ Grok の Linux マシン を直接操作
自由すぎてびっくり！
でも権限の管理はしっかりと 🔧

操作画面は自分のもの

共有される自由度

うれしい自由
  • ボットに操作させるだけでなく、自分からもアクセスできる
  • 同じ画面を、人間とボットの 両方から触れる
  • この 自由度 を、そっくり共有してくれている
  • ただし雑に使っていると 大ごと になり得るので注意
外面はシンプル、中は自由。
そのギャップが「味」になってるんだ ✨

制約も知っておこう

受け入れられるなら強い

おさえたい点
  • スペックのカスタマイズ は、あまりできない
  • Grok のモデルに 渡したくない情報 も出てくる
  • リソースを操作する外側のモデルは Grok 固定
  • それを受け入れられるなら、かなり強力な選択肢
カスタマイズ制限 外ループは Grok それでも強い
良い面と注意点、
両方おさえてえらぼうね ⚖️

この動画の核心概念

考え方
  • ハーネス＝Claude Code などのエージェントを 支える枠組み
  • そのハーネスを、さらに上から操作する 上位のハーネス
  • このレイヤーがある、と 去年の10月ごろ から考えていた
  • ご自身もハーネスを作っているが、提供の仕方 がむずかしかった
  • Grok Bot が、そのカタチを 実現してしまった
簡単なアプリに見せかけているけど、
めっちゃ深い設計なんだ…！ 🌌

なぜ価値が高い？

データが集まってくる

集まるもの
  • Claude Code などが どう使われているか を収集できる
  • ユーザーの PC の中で動いていると、その姿は 見えない
  • Grok のリソースの中で動けば、使われ方が Grok に見える
  • Grok 4.6 のリリースでは、ハーネスへの試験が 学習に入っている と発言
  • だから、この自由さは より強力 になる
使えば使うほど、Grok 側に
ノウハウがたまっていく仕組み…！

概念定着の強さ

Claude Code が強い理由

強さの源
  • Claude Code が強いのは、概念の定着 がはやいから

  • サブエージェント などの仕組みもどんどん集まる
  • 概念を データとして集めて、進化 させていく流れがすでにある
概念定着 スキル サブエージェント
どう使われているかを集めて、
どう進化するか。この視点が大事 🌱

正面から戦わない

Grok Bot の戦略

立ち位置
  • Grok Bot は Claude Code・Codex と正面で戦っていない
  • その上にいて、ハーネスを操作するハーネス として立つ
  • 計算機を貸しちゃって、まるごと支配 する側
  • 押さえ込むのではなく、支える側に回る xAI の強者感 を感じる戦い方
将棋でいう「上位の段」から
戦うようなものかも ♟️

Grok Build と Cursor

みんな、角度がちがう

それぞれの役割
  • 正面で戦うのは Grok Build（X のコーディングエージェント）
  • Grok Build はコーディングエージェントとして、なかなか良い
  • Cursor はクラウドエージェント系が先行
  • Cursor はハーネスとしても 先進的な取り組み を続けている
  • 同じ土俵ではなく、角度がちがう戦い をしている
「どこで戦うか」を選べるのが、
xAI のおもしろいところ 🧭
