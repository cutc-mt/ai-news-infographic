5.1 で何が変わった?

CHECK.01 / はじめに

  • Fable 5.1 は特徴がかなり変化したアップデートですね。
  • 5 からの差分、プロンプトの書き方、設定のしかたを解説します。
  • 界隈で言われる「Fable 5.1 はすぐ溶ける」の正体は、effortによる違いなんです。
  • 使い方を押さえれば、とてもいいモデルだと動画では太鼓判です。
今回いちばん大きい変化は、effortの切替で
キャッシュが壊れにくくなった点ですね!

Fable 5 のプロンプトはそのまま動く

CHECK.02 / 互換性

  • Fable 5 向けに書いたプロンプトは、5.1 でもそのまま使えます。
  • ただし内部の特徴は変化していて、effort がかなり効くようになっています。
  • Opus 5 の時にも同じような話がありましたね。
  • 5.1 の medium でも、5 の高い effort 並みの結果を出すベンチマークがあります。
low や medium でも、
「ここだよ」と察してくれる丁寧さが
クロード系の魅力ですね。

まず Opus 5 から始める

  • 公式の前提: Opus 5 で開始し、品質が届かない時だけ 5.1 へ。
  • Opus 5 は過小評価気味の優秀モデル。ベンチのスコアもかなり良いです。
  • Artificial Analysis では、もともと Fable 5 より上だったほど。
  • コメント欄でも「Opus 5 で満足」という声が。
まさおさんの感想: Opus 5 は
ちょっと評価が低すぎるかも、とのこと。

「難しいタスク」の探し方

CHECK.04 / 境界線を探る

  • 「難しいタスクって何?」とよく聞かれるので、実践的なやり方を紹介します。
  • ハーネスで無茶振りを 1 個やってみて、境界線を探るのがおすすめ。
  • 例: 作ったことのない規模のゲームやアプリ。
  • 自己改善を回すためのハーネスでも OK。すり合わせをしていると「力足りないな」と感じる点が出てきます。
  • 逆に明確なゴールが決まった作業なら、Fable が本当に必要かは少し立ち止まって考えるといいかも。
未知の領域こそ Fable を
どんどん使いたい、とのことです。

今回の主役は effort 設定

CHECK.05 / 効き方が変わった

  • ツール呼び出しの丁寧さは、もともと effort の影響が大きかった項目です。
  • 5.1 では差分がとても明確になりました。
  • クロード系ハーネスなら skill.md の effort 設定で調整できます。
  • 将来的には「effort ルーター」的なものが登場するかも、と期待。
# skill.md での指定イメージ
effort = "medium"   # 普段使い
effort = "max"      # がっつり回す時
どの effort で使うかが、
今回いちばん意識したいポイントですね。

価格・キャッシュ・コンテキスト

CHECK.06 / スペック面

  • 価格は Fable 5 と変わらず同じです。
  • キャッシュ読みは1/4 コスト。ここが効いてきます。
  • コンテキストウィンドウは 1M。
  • adaptive thinking が常時 ON に。
  • データ保持(リテンション)の話もアップデートされています。
キャッシュが壊れにくくなったので、
1/4 コストがさらに活きる設計ですね。

xhigh と max はトークンを大量消費

CHECK.07 / 「溶ける」の正体

  • xhigh はかなりトークンを使うとのこと。max も同じです。
  • 速さは TPS 70 前後。速いのに、その分しっかり消費します。
  • 「すぐ溶ける」感覚の正体は、この effort 差なんですね。
  • 規定値はhigh から。しっかり使いつつ、場面で下げるのがコツ。
  • シンプルに済ませたい時は low / medium でも出力がしっかり。一度試してみてください。
前回の xhigh の感覚が
high あたりに寄った印象、とのこと。

まさお流の使い分け

CHECK.08 / 温度感

  • 普段の作業: medium で進める。
  • ループを回す時: high。
  • 本気で回したい時だけ max。
  • low はツール呼び出しの回数が減る傾向。ウィンドウの中で頑張るタイプ。
# 会話中の切り替えイメージ
/effort low    # さっと確認
/effort xhigh  # 深掘り
speed を重視するタスクで max は
もったいない、という指摘もありました。

会話の途中で effort を変えられる

CHECK.09 / いちばんの朗報

  • 会話の途中でも気軽に effort を切り替え OK。
  • プロンプトキャッシュが壊れにくくなりました。公式も明言しています。
  • 「このループは medium でいいや」という使い分けがしやすい!
  • まさおさんが今回いちばん喜んでいたポイントですね。
  • 将来は effort を自動で調整してくれると嬉しい、との期待も。
検証が不要な軽い作業は effort を
下げてみて、と公式も案内しています。

挙動変化 7つ ① 並列呼び出し ② 途中経過

CHECK.10 / 公式の案内

  • ① 並列ツール呼び出しの数が減る傾向があります。
  • 複数取得の依頼なら、ちゃんと並列で対応してくれます。
  • ② 思考の途中経過の表示が減りやすい。
  • これは高い effort ほど顕著だとか。
  • 「考えてる時の出力」を確認したい人は注意ですね。
減った表示を戻したい時は
プロンプト側で指定するといいですね。

low effort は検索しにくい

CHECK.11 / 挙動変化 ③

  • low effort では検索(検証)が少し弱る傾向があります。
  • effort を上げると、前のモデルよりしっかり検証を回すようになります。
  • evaluator を使ったハーネスを作っている人は高 effort がおすすめ。
  • 速度重視のタスクに max / xhigh を使うと、トークンが無駄になりがち。
  • 「速さ」か「検証の深さ」かで effort を選ぶのがコツですね。
目的に合わない effort は
コストも品質も損になりやすいです。

文章が密になる・装飾が減る

CHECK.12 / 挙動変化 ④⑤

  • ④ 文章が密になる(ぎっしり系の出力に)。
  • ⑤ チャットの装飾(太字など)が減る、いわゆるAI っぽい装飾が減る方向。
  • 文章そのものは前世代より概ね良くなっている、と公式。
  • まさおさんも「5 より読みやすい文章が増えた気がする」との感想。
  • 小難しい文章で認知が疲れる問題が、少し軽くなった印象。
文章の読み心地の変化も
ぜひコメント欄で教えてください!

引用とサブエージェント

CHECK.13 / 挙動変化 ⑥⑦

  • ⑥ 引用の挙動が変化。原文をそのまま移しつつ、書き直すことも。
  • 必要に応じて CLAUDE.md やプロンプトで対策しておくといいですね。
  • ⑦ サブエージェントが親を待たないように。
  • 結局どの経路が最短で効率的か、というメタな話につながります。
  • サブエージェントの扱いも少し上手になった印象。
気になる挙動にはプロンプトや

途中でやめさせないプロンプト

CHECK.14 / 長いループを回す

  • 自律性と長いループはクロードの強み。公式が 2 つの書き方を案内しています。
  • 「ユーザーは見ていない」前提で書く。
  • 「やりましょう」と聞くと作業が止まるので、確認なしで進める指定を。
  • 認知ドリフトをスマートに防ぐ、最近のトレンドそのものですね。
  • 依頼の範囲 = 成果物と明示する例も共有されています。
# 途中で止めないための指示(イメージ)
- ユーザーは作業を見ていません
- 確認を求めず最後まで進めてください
- 成果物は 〇〇.module の完成とします
大量のセッションをさく方能
この前提が大事、とのことです。

指示追従の上手さ

CHECK.15 / 頼まれた範囲だけ

  • 自由度の高い実装では、つい余計なことをしがちなモデル。
  • 書かれてない挙動を足さない。
  • 近くのコードを直しに行かない。
  • テストファイルを増やしすぎない。
  • 見つけた別の問題は直さず報告だけ、と書くと従ってくれます。
  • 指示の強弱をうまく理解してくれる、という 2026/9/2 時点の感想。
「報告のみ」の一文を入れるだけで
余計な修正が減るのは嬉しいですね。

まとめ: Opus 5 とのバランス使い

CHECK.18 / 実践のしかた

  • Opus 5 でできるタスクはOpus 5 で済ませるのが基本。
  • ウルトラコード的な使い方を 5.1 の high でやると、一瞬で制限が近づくかも。
  • Fable の枠だけ使い込むと、Opus の枠が余ってもったいない。バランス調整が大事。
  • 慣れるまでは mediumから色々試すのがおすすめ。
  • effort のトークン消費差にだけ注意すれば、Fable 5.1 はとてもいいモデル!
指示追従・キャッシュ・長いループ、
5 の良さを引き継いで進化しています。

この動画、3行でまとめると

  • まず Opus 5 で始めて、難しいタスクだけ Fable 5.1 に切り替える。Opus 5 は過小評価気味の優等生。
