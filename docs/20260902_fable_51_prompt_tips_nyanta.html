① リリースの全体像

Cards 1-5

Fable 5.1 登場

  • Anthropic社が新モデル Fable 5.1 をリリース
  • 個人は Fable 5.1、一部の組織は Mythos 5.1 を利用
  • 公式ページに変更点とプロンプトのコツが掲載
  • Fable 5 から乗り換えるべきかを検証
にゃんたさんが実際に触って検証した結果をまとめたよ！

Mythos 5.1 との違い

  • 中身は同じモデル、違うのはセーフガードの水準
  • Mythos 5.1 は審査を通った一部の組織向け
  • 一般向け Fable は入力内容によって他モデルへ迂回する制限あり
  • モデルが賢いぶん、悪用すると脆弱をついた攻撃も可能に
「安全性のレベル違い」と覚えればOK！

料金とキャッシュ割引

  • 入力 $10 / 出力 $50 は据え置き
  • プロンプトキャッシュの読み込みが 75%オフ
  • 長い作業ほど安くなり、最大 45%減
  • 短い質問なら体感コストは変わらず
1度入力した内容はキャッシュとして再利用
→ ファイルを多く読む作業ほど恩恵あり
エージェント的な長いタスクが一番お得！

MAXプランの注意点

  • Fable系はサブスク枠だと 月額100ドル以上のMAX から
  • プロ/標準席は優先クレジット買いの従量支払い
  • Claude Code 使用枠 50%増 キャンペーンは 9月14日 まで
  • その後は25%引き上げ＝実質 17%減（コミュニティノート）
この2週間がたっぷり使えるチャンスかも！

EFS 企業向けデータ保存

  • 会話の履歴をAnthropic側でなく自社管理のクラウドに保存
  • 「秘密情報を外に出せない」会社でも導入しやすい設計
  • 企業向けの機能で、今年の秋から開始予定
導入の壁が一つ減る嬉しいアップデート！

② ベンチマークと検証結果

Cards 6-11

ベンチマーク結果

  • 横軸コスト・縦軸スコアのグラフで大きく向上
  • Mythos 5 / Fable 5 より少ないコストで高いスコア
  • エージェンティック・コーディングはFable 5の上位互換
  • コスパ重視の進化と言える内容
「安くて賢い」が今回の売り！

effortレベルの設定

  • effort＝モデルにどれだけ頑張らせるかの設定
  • Claude.ai のデフォルトは medium（5まではhigh）
  • コーディング系はmediumだと足りず high推奨
  • mediumでも低コストでFable 5並みの精度
  • 公式は「まずhighで始める」を推奨（チャットの初期値と不一致）
5.1はmediumでもFable 5のMAX超え！いい回答が欲しい時はhigh以上に

研究系ベンチマーク

  • Terminal-Bench-Science: 研究を自立的にやらせるタスクで大きく向上
  • 仮説を立てて検証し結果を出す、実研究者に近い仕事
  • ナレッジワーク（OpenAI作成の実務ベンチマーク）も向上
  • コーディング以外の仕事でも使える力が上がった
FableやGPT-5.6より大きく伸びているのがポイント！

忖度しない中立評価

  • お題: 受信メール全件に 「0.1秒で承認した」 と返すツール（2点のアイデア）
  • Fable 5.1 は正しく 10点中2点（Fable 5 も2点）
  • GPT-5.6 Sol は3点、時には4点と甘め
  • アイデアの壁打ちにはClaude系が◎
気分が良くなる回答を学習してるから、忖度はAIの癖。中立に採点できる方が仕事で助かる！

検索精度テスト

  • お題: 「にゃんたのAIチャンネル」を調査してまとめる
  • Claude は登録者 6.5万人 の古い情報
  • ChatGPT は 約9.3万人 の最新情報を取得
  • ファクトチェックはChatGPTが良さそう
調べ物はChatGPT、壁打ちはClaudeと使い分けるのがおすすめ！

本番チャットボット検証

  • 本番運用のボットをFable 5 → 5.1 へ。評価データ 30件 で匿名評価
  • ターン数が増え、回答の文字数は 230%増
  • コストは 18%高 に（公式の「25%安」と逆転）
  • スコアはほぼ同じ → 単純置き換えのメリットは薄い
キャッシュ読みは安いが、出力が長くなる分が相殺
→ 短いタスク（ターン2〜3）では恩恵が小さい
置き換える前に自分のユースケースで計測しよう！

③ プロンプトのコツ

Cards 12-17

既存プロンプトはそのまま

  • Fable 5 向けプロンプトは変更なしで動く見込み
  • モデルを入れ替えて精度が落ちることはなかった
  • チューニングの緊急性は低い
まずは現行のまま様子見でOK！

文章の密度を制御

  • 5.1 は冗長さや専門用語は減った一方、長く密な文章になりがち
  • 段落の区切りも減り、読みにくい出力に
  • 対策は please be more terse 等の一言
  • 人に読んでもらう文章を作る時は要チェック
please be more terse.
（もう少し簡潔に）→ 密度を下げて読みやすく
ごちゃっとしたら terse で解決！

装飾の抑制文言は不要に

  • 旧モデルは太字・見出しの使いすぎが目立った
  • 5.1 はAIスロップ的な装飾が出にくくなった
  • 「太字はやめて」等のルールは削除してOK
プロンプト掃除のチャンス！

引用の工夫

  • 5 より「引用と示さずソースの文言を再現」しやすい
  • 引用元を提示させてから回答させる設計を
  • 引用の仕方を例で与える few-shot が有効
例) 出典を [1] 形式で示し、文末にURL付き一覧を出す
→ アプリでファクトチェックしやすくなる
AIアプリを作る人はここ要チェック！

低effortの検索トリガー

  • effort が low だと検索をあまりしない
  • 検証を促す文言をプロンプトに入れておく
  • 会話の途中でeffortを切り替える新機能を活用
  • Webアプリで検索するならeffortを上げる
検索を伴うアプリを作る時は特に注意！

画像処理は道具を与える

  • ビジョン作業には crop / zoom ツールを用意
  • 自分で切り抜き・ズームできて精度が大幅UP
  • Fable 5 も Sonnet 5 も同じ傾向
tool: crop(image, region)
tool: zoom(image, area)
→ ピンポイント拡大ができると精度が跳ね上がる
画像を扱うアプリには必須の仕組み！
