1. なぜAIワークフローは死ぬのか

Cards 1-4

「30秒だけ良い感じ」問題

  • 研究エージェントや受信箱システム、コンテンツのワークフローが「動いている」のを見る
  • 感動してリンクを保存。「あとで設定しよう」と自分に言う
  • しかしその「あとで」は、ブックマークのフォルダと途中までの GitHub インストールになる
良いAIワークフローの大半は、ブックマークフォルダの中で静かに死んでるんだ…。

Taku AI が埋めるギャップ

  • このギャップを埋めるために作られたツール（スポンサード動画）
  • AIアプリ・エージェント・スキルを、実際に実行・リミックス・共有できるワークフローに変える
  • 「見つけた」と「動かせた」の間の距離を一気に縮める設計
ツール探しではなく「動かすとこまで」を支援するのがコンセプト。

判断基準はシンプル

  • その1：散らかった研究タスクを、有用な出発点に変えられるか？
  • その2：自分がセットアップの常勤オペレーターにならずに済むか？
役に立つ 管理が増えるだけ
この2問に「はい」と言えないツールは、どうせ使わなくなる。最初にはじこう。

編集方針：結果を明確にするか

  • どのステップが結果を明確にするなら、そのまま残す
  • システムを高度に見せるだけなら、画面に映さない
  • 「かっこよさ」より「分かりやすさ」でふるいにかける
見栄えの良い複雑さは、理解のじゃまになるだけ。切る勇気大事。

2. ゴールから逆算する設計と2つの入口

Cards 5-9

ゴールは小さなリサーチデスク

  • クリエイター向けの小さな「リサーチデスク」を目指す
  • 入力は3つ：トピック・いくつかの制約・本当に気になる切り口
  • 返ってくるのは作業を始められる場所：ソースノート・ストーリーの切り口・挑戦すべきアウトライン・次のアクション
空白ページから「始められる状態」まで一気に持っていけるのが強み。

終わりから始める設計

  • まず問う：「終わった時、何が真であってほしいか？」
  • 答え：「20個のタブを開けず、同じプロンプトをゼロから組み立て直さず、ざっくりトピックから構造化された研究の出発点まで行けること」
  • この一文がフィルターになる。仕事に役立つツールは残し、役立たないものは外す
ゴールの一文が決まれば、いらない機能を選び落とせる。迷いが減るんだ。

決断を減らす、管理を増やさない

  • ワークフローは何度も下す決断を減らすべきもの
  • 新しい管理対象を増やすものではない
  • すべての構成要素が 1つの成果に trace back できるなら、システムはちゃんと助けている
  • たどれないなら、それは「ただの活動」を生んでいるだけ
「このパーツ、どの成果につながってる？」に答えられなければ疑ってみよう。

Taku のマーケットプレイス

  • みんなが動くAIアプリ・スキル・ワークフローの設定を公開中。拾ってきて適応できる
  • カバーする領域：研究 執筆・コンテンツ 開発 デザイン データ マーケ 生産性
ゼロから作らなくてOK。動く実例から始めるのが近道。

2つの入口

入口1：借用（borrowing）

  • 自分の仕事に近い研究セットアップを探し、本物のトピックで実行する
  • カードや説明文で判断しない。いつもの散らかった入力を与えて、どこで助けになり・曖昧になり・自分の文脈が必要かを見る

入口2：意図から作成

  • 目標を自然言語で記述すると、適切なアプリ・エージェント・スキルからスタックを組み立ててくれる
「探して借りる」か「書いて組んでもらう」か。好みの入口から始めよう。

3. 実践！ループを回して磨く

Cards 10-14

覚えるべき4ステップループ

① 最も近い動くバージョンを探す
② 本物の仕事で使う
③ 摩擦に気づく
④ より良いバージョンを記述する
  • 白紙から完璧なセットアップを予測して数日費やすより、このループの方が有用
成果を使う前に最適化しすぎるクセを、このループが防いでくれる。

実際に作ってみる

  • こんなプロンプトから開始：
「YouTube動画の企画用
リサーチデスクを作って」
  • Taku がスタックを組んだら、全部追加したくなる衝動を抑えて最初のバージョンをすぐ実行
  • 今週本当に必要なトピックを使う。架空の例は弱いワークフローを隠してしまう
「あとで完璧に」は罠。まず1回回すのが正解。

本物のタスクが暴くもの

  • 本物のタスクは、デモが避ける細部を暴く：不明確な入力・広すぎる出力・使えない証拠
  • それらは失敗ではなくシグナル。何をリミックスすべきか教えてくれる
うまくいかない出力こそ、直す場所がわかる宝の地図。

テンションのあるトピックを選ぶ

  • 選ぶのは最初の答えが単純すぎるもの。両側の引力が働く、テンションのあるトピック
「AIワークフローはクリエイターの
より良い作品を助けているのか、
それとも平均的な作品をたくさん
作るのを助けているだけか？」
  • リサーチデスクは人気の意見の繰り返しではなく、議論・有用な例・考えるべき場所を浮かび上がらせる必要がある
「一言で決まらない問い」だと、研究の価値が出やすいよ。

3つのバケツ分類

人間のチェックポイント

Keep（残す）：検証して使える証拠やアイデア
Question（疑問）：有用そうだが出典が必要な主張
Cut（切る）：理解を変えずに文字数だけ増やす素材
  • Taku はワークフローをパッケージし、有用な能力をまとめる
  • でも何が真で・何が関連し・何を公開するかを決めるのは、依然として人間
AIがまとめて、人間がふるう。最後の判断は自分の仕事だ。

4. 自分のものにして定着させる

Cards 15-18

リミックスで自分のものに

  • 空白ページの研究がレビュー可能なワークスペースになったら、次は「ツール探し」ではなく切り口の洗練
  • 研究は良いがアウトラインが広すぎる → 読者を絞る
  • 良いソースが出るのに切り口に挑まない → 最も強い反論を含める要件を追加
  • 長編でなくショート動画を作る → 3つのフック＋30秒構成で終わるよう出力を変更
劇的な再構築より小さな変更の方が価値がある。想像上の理想じゃなく、現実の摩擦が根拠だから。

スタックとして保持・公開

  • ワークフローが自分のプロセスに合ったら、記憶から再作成せず再利用可能なものとして保持
  • 他の人が本当に使うものを作ったら、実行・リミックスできる形で公開もできる
部品の多さ 締め切り直前の信頼性
  • 最良のワークフローは部品が最も多いものではなく、締め切りが近い時に信頼できるもの
「いざという時 使えるか」が本物の評価基準。

小さく保つ理由

  • 信頼して良い初回パスを返すリサーチデスクの方が価値がある
  • 創造プロセスのすべてを約束して確認が難しくなる巨大システムより、よほど良い
  • 小さく信頼できるものを育てる方が、結局すごく速い
「全部やる君」より「最初の一歩を確実に」の方が仕事が進む。

死なせる理由と、次の実行

  • ワークフローが死ぬのは：見つけた人≠セットアップできる人の時。スクリーンショット・リポジトリ・長いプロンプト・つなぎ合わせ必要な3ツールのままだと死ぬ
  • Taku のやり方はこのギャップを縮める：閲覧 → 実行 → 記述 → リミックス
  • 次の実行は最初より簡単に：同じワークフローを開く → トピックを変える → 効いた制約を保つ → 弱い出力を引き締める
これを繰り返せば、ツールは「実験」じゃなく「システム」になる。それがゴール。
