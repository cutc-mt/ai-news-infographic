CPU の復活 — Axion

忘れられた存在が、主役の一人に

最大 30%

他のハイパースケーラーより良い価格性能比

  • Intel、AMD に加え、自社 Axion ARM CPU を投入
  • 推論のすべてをアクセラレータでやる必要はない

領域2: 相互運用性とオープン性

ロックインをなくす仕組みづくり

  • GPU ↔ TPU 間の ロックイン回避に注力
  • TPU で PyTorch をネイティブサポート（Eager mode も含む）
  • vLLM などの OSS 推論エンジンが TPU で同等に動作
  • オープンソフトウェアの投資: JAX Keras PyTorch vLLM LMD
好きなフレームワークのまま
TPU に乗れる——
縛りなしの開発体験！

領域3: 動的リソース割り当て

GKE custom compute classes

  • GPU で serving を開始
  • 需要が増えたら TPU にスピルオーバー（その逆も自由）
  • 需要にあわせて、構成をリアルタイムで組み替える
# GKE custom compute class のイメージ
workload: agent-serving
base:        GPU      # まず GPU で始めて
spillOver:  TPU      # 需要が増えたら TPU へ
最初は小さく始めて、 のびたら自動でスケール——
これが dynamic な運用！

agent-native Kubernetes

コンテナの次は、エージェントを任せる

  • Kubernetes を cloud-native だけでなく agent-native なワークロードの基盤に
  • エージェントの増減・再配置を GKE がオーケストレーション
  • 推論のむらのある負荷にも、たくましく追従できる

操縦席になる日が

KV cache とメモリウォール

記憶を賢く持って、計算を省く

  • KV cache: マルチターン対話でメモリを長く保持し、計算量を削減
  • 長い対話でも、はじめのやり取りを覚え続けられる
  • メモリの壁 メモリウォール への対策が急務に
  • TPU 8i は オンチップ SRAM と HBM を拡充
覚えておく工夫で
