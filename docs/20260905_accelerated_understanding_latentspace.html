目指すは「物理のGPT」

言語で起きたことを物理でも
  • 0:55 目標は物理世界のための基盤モデル
  • 「言語で見た普遍性とスケールの物理版は何か?」が会社の賭け
  • 流体・半導体・エネルギーなど、別々の物理を1つのモデルで学習
  • 専用モデルをひとつずつ作る時代から、汎用モデルへ
言語のGPTがそうだったように、
物理でもひとつの巨大なモデルが全部こなす未来を目指す！

言語がたどった道を復習

スペルチェックから統合モデルへ
  • AI革命の前はスペルチェック・翻訳・予測変換など専用モデルばかり
  • OpenAI が「ぜんぶ1つのモデルに入れよう」とやって大成功
  • 統合モデルが専用モデルをほぼ全面的に上回る結果に
  • 同じ転換を物理シミュレーションでも起こせるか? —— これが問い
昔の「スペルチェック専用モデル」が
あっという間にGPTに置き換わったのと
同じことが物理でも起きる、という賭け。

ネットには物理データが無い

だから「法則」が頼り
  • 言語とちがって、出来合いのインターネットのような物理データは存在しない
  • 科学の発見は「新しいこと」をするもの。定義上、訓練データに無いはず
  • データだけに頼るAIでは足りない → 物理法則を組み込むのが決め手
  • 既存シミュレータで学習させ、仕上げに法則による自己改善を重ねる
データが無くても、式（PDE）がある。
物理では正しさを数式で確かめられるのが強み！

バラバラに見えて共通点あり

転移がおきる根拠
  • 2:01 カテーテルの中の流体もロケットの流体も同じ流体力学
  • 違いはレイノルズ数などでパラメータ化できる「領域の違い」だけ
  • エネルギーの保存・因果・物の恒常性など、暗黙の共通要素が満載
  • 方程式（PDE）がちがっても、ニューラルモデルは共通の特徴を拾える
「物理どうしは転移しないのでは?」という
素朴な疑問への答えがここにある。

ショートカット無しの4次元

空間3次元＋時間の全展開
  • 言語は1次元にトークンが並ぶ。物理は空間3次元＋時間で独立に伸びる
  • 動画モデルのような圧縮をせず、3次元のまま保持
  • 時間も1ステップずつではなくフルのロールアウトをモデル化
  • 逐次予測だと誤差が積み重なり、出力の理由がわからなくなる
「楽な道を選ばない」のがポリシー。
現実のままの4次元を、まるごと扱う。

兆を超えるコンテキスト

数字がとんでもない
  • 4:52 各軸1000解像度 × 3次元 × 1000ステップ ＝ 1兆
  • 推論では 5兆コンテキスト まで到達済み
  • 5兆のランでは出力が 22テラバイト。アクセラレータのメモリに載せる
  • 小さめのモデルならMacBookでも動く、幅の広い運用
訓練 1兆入出力とも兆級
推論 5兆出力は数十TB
言語から来るとバカげた数字。
しかも動画モデルのような pixel 平均化などのトリック無しで！

インフラも作り直し

既存の手法がそのまま使えない
  • 定番の FSDP シャーディングは層をGPU上で再組み立てする前提
  • ところが層が大きすぎてGPUに収まらない。サンプルもノード1台に収まらない
  • シャーディング戦略をゼロから再発明して大規模訓練を実現
  • 数百回の訓練を実施し、兆パラメータ級のモデルまで到達
  • HPC の古典技法と最新技法を最初から両取り
アルゴリズムだけでなく、
通信・帯域・ハードウェア活用まで
一緒に設計（co-design）するのが鍵なんだ。

「転移」の証拠が出た

実験結果が賭けを裏づけ
  • 8:06 特徴も課題もバラバラな物理領域をあえて選んで同居させ学習
  • 結果: 複数領域を学んだ同一サイズのモデルが単独領域のモデルに勝つ
  • パラメータを各領域に全振りしても及ばない → 共有学習の効果
  • 言語で見たのと同じ創発的な学びが物理でも発生
複数物理モデル全領域で勝つ
単一物理モデル同じサイズでも負ける
「でかくすれば強い」だけじゃなく、
領域を混ぜるほど全部うまくなる。
これが基盤モデルの条件！

ニューラルオペレーター

解像度に縛られない設計
  • 8:42 Neural Operators がアーキテクチャの土台
  • おかげで解像度不変（resolution-invariant）を実現
  • 高解像度が必要な重い物理には大コンテキスト、設計の探索なら軽い解像度で省エネ
  • 動画・ビジョン系の世界モデルは固定解像度前提。工学設計では通用しない
ゲームや映像なら「なんとなくそれっぽい」でOK。
でも設計・発見では誤魔化せない。
解像度をフレキシブルに変えられるのが差になる！

トランスフォーマーでは無理

物理には構造がある
  • 12:21 言語用Transformerの二乗の計算量では5兆は不可能
  • どんな計算資源を注いでも届かないし、そもそも不要
  • 物理は「全部が全部つながる」より構造がある → それに合わせて再設計
  • MoE 進化のような体系実験を自社でも継続中
詳細は企業秘密。
でも「物理向きの形」を体系的に探した、という点がミソ。

自分で作る学習カリキュラム

シミュレータが先生役
  • 15:00 数値シミュレータで必要なだけ訓練データを生成
  • カリキュラム設計: やさしい式 → 低解像度 → 徐々に難しく
  • 人間の学習と同じで順番に学ぶほうが效果好
  • 言語の「ネットまるごとシャッフル」方式とは対極のアプローチ
  • PDE を正しく解けば物理も正しい → sim-to-real の溝をスキル領域の広さで埋める
狭いデータで派手なデモを見せても、
本番領域が範囲外なら配備されない。
その失敗パターンから抜け出したかった。

物理法則で自分を磨く

自己改善が言語より有利
  • 17:58 PDE を訓練信号としても使う → データの質を超えられる
  • 言語の自己改善は人手のフィードバックで ○×だけの疎い信号
  • 物理は法則が多数あり密で客観的なフィードバックが得られる
  • 実験でも自己改善の効果を実際に確認済み
物理AI密・客観的な信号
言語モデル疎な○×評価
平均的なデータの質で頭打ちにならず、
法則の力で限界を超える——
ここが言語との決定的な違い！

大小のスケールを同時に

マルチスケールの難題
  • 18:30 物理では大きな現象と小さな現象の桁ちがう共存が常態
  • 全部を最高解像度で解くのはコストが桁外れ
  • まず低解像度・粗いソルバで全体を掴み、細部は専門ソルバで微調整
  • Neural Operators はモデル内部でスケールを混ぜられる → データ効率が良い
外からスケールを指定するのではなく、
モデルが自分でスケールを混ぜる。
ここが他の物理×MLとの差！

最初の商機は半導体

溶けない・速いチップを作る
  • 20:27 誰もが改善を求める 半導体とエネルギーが主戦場
  • 今日のチップ設計は「デジタルを確定 → 物理チェックは一度きり」
  • 熱やEMの spike を避けるだけでなく、余裕を性能に変える設計へ
  • 製造プロセス自体の物理課題にも取り組み中
物理を深く使えると、規約の余白（ヘッドルーム）を
性能の上乗せに変えられる。
動画タイトルの「溶けないチップ」はこれ！

エネルギーと資源の探査

観測から世界を読む
  • 23:00 エネルギー分野の設計案件も得意領域
