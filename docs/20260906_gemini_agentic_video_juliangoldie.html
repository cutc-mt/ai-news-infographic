2. 仕組み：旧方式 vs 新方式
なぜ「時間が減って精度が上がる」のか、順を追って
05

旧方式 static
毎秒1フレーム

これまでの Gemini の動画の扱い方

  • 動画を渡すと1秒ごとに1フレームを抽出
  • 2分でも2時間でも同じ——最初から最後まで
  • すべてのフレームがトークンに変換される
  • 長い動画は重くて遅い
「token」とは、モデルが読み込む小さなデータの塊。
フレームが増えるほどトークンも増え、処理がどんどん重くなります。
06

長い動画の
苦しい二択

旧方式では、どちらを選んでも損でした

  • 選択肢A: 全編を読み込む → 膨大なトークンを消費
  • 選択肢B: 簡略化する → 重要な詳細を見落とす
  • どちらも良い選択肢ではない
長い動画は「苦痛でしかなかった」——
重い token を背負うか、端折って詳細を失うか。
このジレンマ自体がなくなるのが今回のポイント。
07

本の読み方で
比べてみる

動画の説明でよく使われる、わかりやすいたとえ

  • 旧方式: たった1つの答えのために本を一冊すべて読む
  • 新方式: 正しいページを直接開いてそこだけ丁寧に読む
  • 本は同じでも、手間は大幅に減り、答えはより良い
目次と索引を賢く使う読者のようなもの。
「全部読む努力」より「当たりをつける賢さ」。
08

裏側では
3ステップ

1時間の基調講演を質問したときの動き

  • STEP 1: まず文字起こし（transcript）を読み、重要トピックの場所を探す
  • STEP 2: その動画チャンクだけを読み込んで映像を確認
  • STEP 3: それらの断片から回答をまとめ上げる
  • Google は一連のプロセスを可視化——判断の過程を追える
まるで計算の途中経過を見せてもらっているようなもの。
何を根拠に答えたのか、ちゃんと確認できます。

10

セットアップは
1語で終わる

Gemini API（Google AI Studio 経由）に組み込み済み

  • processing のモードは2つ: static（従来）と agentic（新方式）
  • リクエストで processing を agentic に設定するだけ
  • スイッチを切り替えるようなたった1語
  • 特別なプランも追加セットアップも不要
// リクエストのイメージ
{
  "contents": [{ ... 動画 ... }],
  "generationConfig": {
    "processing": "agentic"  // ← この1語
  }
}
Google によると個別の機能設定は不要。
長い動画でも token 消費を大幅に抑えられる状態です。

17

4つの実践
ヒント

  • 1. モードは使い分ける——長い動画や特定の瞬間の質問は agentic。5分未満の短いクリップは、考える時間のぶんstatic の方が速い場合も
  • 2. 1リクエストで混在もOK——長い方に agentic、短い方に static でいいとこ取り
  • 3. streaming / background をオン——Gemini が考えている間も接続を維持し、大きなタスクのタイムアウトを防止
  • 4. 質問は鋭く具体的に——「スピーカーが製品名を言及した箇所をすべて見つけて」のような明確さが良い答えを生む
このモードは尋ねた内容を正確に追いかけるので、
質の高い質問ほど結果も良くなります。
