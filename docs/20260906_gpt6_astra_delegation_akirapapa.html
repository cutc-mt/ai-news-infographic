【GPT-6 Astra】AIに仕事を任せる時代へ

新機能・料金・使い方を図解で解説

2026年9月6日公開｜あきらパパ｜8分49秒

アストラの中心と、3つの区別

アストラの中心

  • 難しい仕事を複数の工程にまたがって進める力
  • 考えるだけでなく行動する
  • 自分で調べ、道具を使い、物へ向かう
  • 公式は「一連の仕事に向けたモデル」と説明
AIに聞けば答えは返ってくる。でも次の作業へ渡し、抜けを探し、最後の形にするのはまだ自分……そのつなぎ目から見ていくよ！

まずは3つを分ける

モデル＝頭脳

  • 考えて判断する頭脳の部分

アプリ＝場所

  • Codexなど、仕事を進める場所

ツール＝道具

  • 検索・ファイル操作など、実際に動かす道具
優秀な頭脳でも、資料と道具がなければできる仕事は限られる。名前だけで全部自動…ではないよ！

架空の依頼を追う

  • 「3つの公式資料を使って、初心者向けに5分で説明できる資料を作る」
  • 必要な工程：読み取り→比較→構成→文章→確認
  • 完成の条件は「相手が違いを説明できたこと」
  • この1枚の依頼書が成果物へ変わる流れを見ると、新機能の意味がつながる
依頼書が調査になり、構成になり、最後に伝わる資料になる。これがアストラを理解する鍵！

非同期ツール呼び出し

  • 資料の取得を始めたら、結果が来るまで全部停止する必要はない
  • 待ち時間に見出しや比較の観点など独立した仕事を進められる
  • ツールの実行と結果の対応付けはアプリ側が管理
まだ読んでいない資料の結論を先に決めていい、という意味ではないよ。結果が届いてから統合する！

途中で気づいたとき・時間は戻らない

ミッドステアリング

  • 作業途中に「初心者向けに変えたい」と気づいたら追加指示を続きへ取り込める
  • APIでは Responses API の WebSocket 接続
  • 「受け付けたこと」と「反映されたこと」は別
  • 表示だけで終わらず、続きの内容が変わったかまで確かめる
指示が届いた、だけで安心しない。反映されたかまで見るのが大事！

時間は戻らない

  • 進路を変えられても、すでに変更したファイルや開始した処理は自動では戻らない
  • 途中修正を取り消しボタンとして考えないこと
  • 重要な操作には確認と記録を用意する
この区別を知っていると、便利さを保ちながら安心して任せられるよ！

コンテキスト＝作業机

  • 枠は105万トークン（最大入力92万2000／最大出力12万8000）
  • ただしトークン≠日本語の文字数
  • 広い机も古い資料と新しい資料が混ざれば迷う→製本を指定
  • 制約と完成条件を添え、判断しやすい置き方を
量を増やすだけじゃなく、判断しやすい置き方が大切だよ！

入出力と知識の区切り

  • 入力できるのは文字と画像／モデルそのものの出力は文字のみ
  • 画像生成などは別の道具の話
  • 知識の区切りは2026年4月30日
  • 最新情報は検索や渡した資料で根拠を確認。大きなモデルでも今日の情報を自動では知らない
この区別は、できることを正しく理解する土台になるよ！

推論の深さ・モード・対応環境・料金

推論の深さ

  • まず低めの設定で必要な品質が出るか見る
  • 難しい判断や検証があるところで深さを上げる
  • APIは low／medium／high／extra high／max
  • 推論なしの none には非対応
  • 深さを上げると時間や使用量が増える場合も
毎回最大にするより、必要な場所だけ力を使うのがコツ！

MAXとウルトラの違い

  • MAX＝1つの課題を深く考える設定
  • ウルトラ＝分けられる仕事を複数のエージェントで進める方式
  • 1つの原因を掘る仕事か、独立した資料を分担して調べる仕事か→仕事の形で選ぶ
  • アプリのウルトラをそのままAPIの推論設定名として渡すわけではない
名前が似ていても意味は別。仕事の形で選んでね！

対応環境

  • 公式対応：デスクトップ・Web・Codex CLI・エディター拡張・API
  • Codexクラウドは非対応
  • 一覧と自分の利用権は別。契約やログイン状態の提供を確認
  • 企業向け初期提供はDaybreak対象組織＋管理者設定の条件
  • 文脈管理の実験機能はPlusとPro向けの任意設定
対応していても、自分の契約で使えるかは別途確認してね！

料金（API）

  • 標準処理・短い文脈：100万トークンあたり入力10ドル／出力5ドル
  • キャッシュ済み入力の読み取りは1ドル
  • 例：入力2000＋出力1000トークン→0.02＋0.05＝0.07ドル（道具・キャッシュ不使用の例）
  • 入力27万2000トークン超で長文料金：入力とキャッシュ2倍／出力1.5倍／キャッシュ書き込みは通常入力の1.25倍
  • APIの高速処理は2倍、バッチとフレックスは半分。製品側の高速処理はクレジット2.5倍
画面に見えた文章の長さだけでは請求の全体は分からないよ！利用枠とAPI料金は別々に確認してね。

任せ方の設計と、最後の確認

依頼書の3要素

  • 誰のために（初心者向けに）
  • 何を材料に（この3つの公式資料を使って）
  • どこまでできれば完成か（5分で説明でき、出題で確かめ、誤解しやすい部分をレビューして直す）
  • 完成条件がはっきりすると、AIは途中の判断を目的へ結びつけやすい
「細部は合理的に判断して進め、結果を大きく変える重要な分岐だけ確認して」──毎回止まる場面を減らす助けになるよ。

任せる範囲と言葉にする

  • 毎回止まる場面を減らす→分岐だけ確認の指示
  • ただし公開や外部送信まで任せるかは別の条件
  • スキルや指示ファイルも見直す。今の依頼と古いルールが食い違うと判断が迷う
  • 任せる範囲と確認する箇所、その両方を言葉にする
古いルールが残っていると迷う原因に。依頼に合わせて見直しを！

開発者向けの設定

  • ツール呼び出しには Responses API を使用
  • temperature や top-p など非推奨パラメーターは外す
  • キャッシュ設定は現行ガイドと整合
  • 推論の深さを変える設定更新では元の先頭部分を保ちキャッシュを満たす仕組み
  • ただし公式ではアストラは標準の単一エージェント式に限定
// イメージ（ツール呼び出し）
const res = await responses.create({
  model: "gpt-6-astra",
  tools: [webSearch, fileOps],
  reasoning: { depth: "low" } // 必要な場所だけ上げる
});
深さの変更でもキャッシュを壊さない設計があるのがポイント！

最後の確認

  • 動き続けるAIだからこそ、指示と行動のずれを監視する仕組みがある
  • ただし監視にも見逃しがあり、自動停止にも条件がある
  • 終わった操作を元へ戻す機能ではない
  • 確かめるのは3点：根拠へ戻れるか・条件を守ったか・目的を満たしたか
  • 監視・重要操作の承認・作業記録の組み合わせで任せた仕事を確かめる
自動で全部安心、ではなく人間が最後にかたすじを通すのが大事！

選ぶ意味を自分の仕事で確かめる

検証のしかた

  • 同じ代表タスクで比べる
  • 見るのは4点：性格差・修正の回数・完了までの時間・総費用
  • 単価だけでも賢そうな文章だけでも決めない
  • 難しい一連の仕事にはアストラ、明確で軽い処理には軽いモデルも候補
  • 最初は小さな仕事を1つ、条件を揃えて成果物比べ
アストラを選ぶ意味は、あなたの仕事で確かめられるよ！

まとめ：3つの問い

  • 何を作りたいか
  • どこまで任せるか
  • 何を持って完成とするか
  • その3つが揃うと、新しいモデルの話が自分の仕事の改善へ変わる
  • 流れ：依頼書→調査→構成→文章→確認
まずはあなたの小さな仕事から、目的を渡して成果で確かめてみよう！（あきらパパ）
