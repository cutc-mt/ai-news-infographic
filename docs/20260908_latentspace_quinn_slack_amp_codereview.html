必須コードレビューを「殺した」
チームの内側 — Quinn Slack / AMP

エージェント時代の開発文化は、信頼と高速な修正サイクルへ移行する
2026年9月8日 Quinn Slack（Sourcegraph 創業者・現AMP CEO） 約40分
#AMP #orbs #コードレビュー廃止 #リモートエージェント #ローカル開発の終わり #少数精鋭SWATチーム #利益が出ている
#01

20名・全員が共同創業者

AMPチームは約20名。Quinn 曰く「全員が共同創業者のような存在」で、高い信頼と裁量が前提の体制です。

  • 誰もが全員の顧客と話せて、あらゆるバグを直せる full trust
  • PM の指示を待つ「自動機械」ではなく、end-to-end の当事者
  • 3分の1ずつ欧州・米国・豪州に分散するリモート会社
  • ミュンヘンやシンガポールなど、オフサイトに全力投資
オフィスに使うはずだった予算を、丸ごとオフサイトに注ぎ込むのがリモート会社のコツ、だそうです！
#02

orbs（オーブ）とは何か

エージェントをクラウド側で走らせる新しい使い方。ラップトップを閉じても動き続けます。

  • PC を閉じて放置OK。ローカル環境はもう不要に remote agent
  • 最大100件を並行実行できる圧倒的な並列度
  • 直近3〜4週間の利用増が、昨年一年の変化より大きい
  • dev サーバーもポータルで見え、デスクトップ操作も可能
  • Devon が先に提唱し笑われていたが、方向は正しかった
「気づけば2週間、ローカルの dev サーバーを起動していない」— Quinn 自身の実感だとか。
#03

必須コードレビューは死んだ

「main にマージする前の必須レビュー」は、AMP を始めて以来ずっと廃止のまま。

  • 事前の必須レビューを撤廃 mandatory review: dead
  • 代わりの土台は信頼された少数チームと skin in the game
  • 不具合は 15分で修正を shipできる MTTR 重視の運用
  • 障害の「予防」より「復旧の速さ」で評価する発想
  • 数日待つより、むしろ品質が高いと Quinn は主張
レビュー待ちが並ばないから、並列実行の旨味をフルに活かせる。全員がレビュアー兼当事者！
#04

レビュー廃止を支える仕組み

レビューをなくしても品質を保つ代替システムの中心は、人と信頼の設計です。

  • ハイエージェンシーな人だけを雇う。代理人は不要に high agency
  • ログや顧客報告から15分で修正リリースのフロー
  • レビューがない分、全員が「直すのは自分」と自覚する文化
  • すべてのソフトで成り立つ訳ではなく、動きの速い end user 向けに最適化
「AI のおかげで、より信頼できる少数のチーム」を組める。これが一番の補償システムなんです。
#05

機能を消すことに怯えない

AMP は古い機能をバッサリ削除することで知られる時期も。「追加より削除で有名」と笑われたことも。

  • エディタ拡張は早期に廃止。ロードマップから外す果断さ kill features
  • AI の進化が速すぎて、古い使い方に留める価値はマイナスになる
  • 「3ヶ月後に obsolete（時代遅れ）と言われる」リスクを避ける
  • AMP が祝福する使い方 ＝ ハッピーパスに全員を乗せる方針
昔は10年使われる技術サイクルが前提だった。今はユーザーを前沿に引き上げ続けないと置いていかれる！
#06

ローカル開発はもう死んだ

エージェントをリモートで走らせると、何も諦めずに済む。これが決定的な違い。

  • 従来のリモート開発は「遅くて多くを犠牲に」する印象があった
  • エージェントなら違和感なく切り替え。諦めが一切ない zero friction
  • iPad でコードを書いてもいい。ノートPC はただの入力装置に
  • 2021年の「end of localhost」記事が、AI 前夜の伏線だった
// Quinn の実感
// 気づけば… const "local dev server" = lastRun("2週間前"); // クラウド側に全部あるから、閉じても平気
Facebook や Google、Stripe など大企業は前から SSH + 軽いローカルクローン。ラップトップは薄い殻でいい！
#07

「apps」: コードが設定画面

orb 上でアドホックなソフトを起動し、エージェントがその場で直す。設定画面は不要になります。

  • Looker + SQL + MCP の代わりに、エージェントがダッシュボードを即制作 ad hoc app
  • 「コードこそ究極の設定画面」。複雑な統合は不要に
  • 市販パッケージを買うオーバーヘッドからの解放
  • 社内データと個人の間に「緩い意味論」を持たせて再利用
sandbox 起動待ちの不満も、裏側では HTTP を喋るプロセスが立ち上がってポータルに映る仕掛け。
#08

機内Wi-FiでDB移行を完結

12時間のフライト中、エージェントが安全なフェーズだけを段階的にデプロイ。

  • core のデータモデル変更（単一→複数ワークスペース）を自動で段階展開 phase 1B2
  • 各フェーズ後にログとDBを監視し、不変条件を確認
  • 異常があれば自動でロールバック。人は寝ていてOK
  • 従来は開発者と運用の数人が張り付き。今は機内で完結
ミュンヘン行きの便で「ちょっと眠れた」のが何よりの証拠。機内Wi-Fi は意外と優秀でした（笑）
#09

最小権限で安全に委任

orb のエージェントには意図的に狭めた権限だけを渡す。これが安全の鍵です。

  • OIDC トークンで、30分だけ・読み取り専用・特定リソースに限定 least privilege
  • ノートPC 上の CLI エージェントは実は無法地帯。逃げ出す事例も
  • クラウド移行はセキュリティ部門的にもより安全という逆転
  • 「全部の権限をよこせ」派と「短い鎖」派のUX的緊張は残る
認証済みスクリプトが本番コンソールまで到達した顧客事例も。ラップトップ起点は危険がいっぱい！
#10

GitHub を開かなくなった

メインリポジトリはまだ GitHub にあるものの、ほぼ開かないと Quinn は言います。

  • issues も pull requests も使わない no PRs
  • GitHub Actions の障害時だけ開く（直近は長時間ダウンで慌てた）
  • 普段は AMP ホスト型のアドホックリポジトリ（Forge など）で運用
  • 「GitHub を殺す」のではなく、次の GitHub へ。静かに消えていく
個人プロジェクトは全部 AMP ホスト型に移し済み。Quinn いわく「全然恋しくない」のだとか。
#11

CI さえ数が尽きた?

「エージェントが自分で検証のためテストを走らせるなら、CI は要るのか?」という問い。

  • エージェントは全員同じサンドボックスで再現性のある検証が可能 reproducible
  • 「全部のテストを走らせ」と指示すればかなり信頼できる
  • flake（不安定テスト）を自動で直せれば、さらに状態は良くなる
  • AMP チームの半分は「CI 不要」派。画像を固めて deploy だけなら
// CI の未来
// 従来の CI run("all tests", { on: "push" }); // エージェント時代: 検証は実行の一部に await agent.verify({ scope: "everything" }); deploy(); // そのまま本番へ
E2B や Daytona などサンドボックス企業が絶賛拡大中。「CI に似た何か」は育っている、という面白い逆説。
#12

サンドボックス戦国時代

AMP は現在 E2B を採用。コストを下げて orb 量産の心理的ハードルを減らす方針です。

  • 再開（resume）やネットワーク権限など、必要なプリミティブが丁寧 E2B
  • 大手クラウドの「サンドボックス」は機能が足りず不思議がる声も
  • Megawatt / Gigawatt 定額プランで9割超は上限に届かない
  • 週3〜4件、「うちのサンドボックスを試して」という売り込みが届く
「orb をもっと回したい」と誰も躊躇しない状態がゴール。課金の心配で創造性を殺さない！
#13

spin-off の誕生秘話

Sourcegraph は code search で top 企業・大手銀行を顧客に持つ優良事業。そこから AMP を分離しました。

  • 2製品体制の解消のため、20名が AMP へ移る spin-off を決断 Yammer 型
  • スピンオフの先例は2009年の Yammer（David Sacks 氏が参考）
  • 投資家・社員は両方の株式を保有。公平な扱いで前例のない形に
  • 200名の CEO より20名の CEO の方が性に合う、と自分の能量に従った
code search は「コードが増え続ける限り明るい未来」がある。だからこそ互いに集中が必要だった！
#14

少数精鋭 = 新しい会社のかたち

PM やマーケターを雇うのは「昔のやり方」。AMP では全員がエージェントを駆使してすべてを兼ねます。

  • 信頼できない人を雇う必要が消えた。代理人ではなくエージェント agents, not headcount
  • 10%だけが製品を考え、90%が販売のオーバーヘッドに回る構図への疑問
  • 収益は黒字。急成長分野で自由なポジションを確保 profitable
  • 「エージェントを箱に閉じ込めておくことはできない」と Quinn
「20名なら、誰に何を任せても安心」。この安心感がスピードの源泉なんですね。
#15

「jellyware」という提案

ソフトより柔らかい 'jellyware'。エージェントで好きに改造できる部品を公開する構想です。

  • X / Discord / メールを監視し、熱心な支持者を見つける道具は汎用 forkable
  • open source 保守の頭痛なし。コードを出して remix してもらう
  • 「markdown + サンプルコードを公開するのが新しい OSS」
  • 設定画面や統合を作って販売するのではなく、改造して使ってもらう
// jellyware の配布
// ソフトより柔らかい export const communityWatch = { type: "jellyware", remix: "your-own-agent", // 自由に! };
「ソフトより柔らかい、でも完全な vibe code ではない」。名前は覚えやすさ重視で選ばれました。
#16

人間が書かない会社ブログ

エンジニアリングブログは人が書いていない。Quinn が方向づけだけ行う体制です。

  • 「面白い工学の話だから書いて」と指示 → 全文をエージェントが執筆 AI written
  • マーケティング用のグラフィックも生成で賄う
  • Quinn の仕事はキュレーションとゴールの設定だけ
  • 自身の skills を公開。仕事術の全体が見られる
「コーディングSaaS が世界最後の SaaS になる」。他の SaaS は全部コードで作れる、という鋭い見立て。
#17

動画編集は人間のまま

ロングフォーム主体の Latent Space と AIE。編集は人間（Alejandro）にこだわります。

  • 「安くて十分な品質」なら変える理由がない human editing
  • 2年来の信頼関係。「Alejandro、これ忘れずに」で通じる
  • AIE は20分〜3時間、Latent Space は30〜60分の長尺路線
  • AIE の映像予算は年600万ドル。数十万の節約より優先度が低いだけ
「動画編集が安くて済んでいる唯一の人」だと host に突っ込まれる場面も。apex predator かもしれません。
#18

5人部屋の実験者たち

Jeff Dean 氏が Google を退職し、少数精鋭での実験へ。時代の空気が変わった証拠です。

  • 「ほんの数人で何ができるか」が退職声明の主題 small team
  • 何千人規模の Gemini への当てこすりにも読める、と host が分析
  • Airtable の Liu 氏も Hyper Agents で同様の動き（並行運営）
  • 「小さなSWATチーム」がテーマに。利益も出ている profitable
  • タイムラインは短縮の一途。「AGI の中を生きている」
「誰も正解を知らない。だから現場で build し続けるのが一番」。感謝で締めくくられた対談でした。
