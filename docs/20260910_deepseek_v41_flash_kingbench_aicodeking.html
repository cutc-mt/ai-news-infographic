新アーキテクチャの全体像

  • MoE バックボーンは 552B パラメータ
  • さらに 196B の engram memory モジュール
  • 入力処理時は 約8B、出力生成時は 約16B だけ活性化
  • 「ファミリー最小」でも、実態はまだ巨大モデル
合計 748B 規模でも、 動くのはその一部だけ。
賢い節電設計だね！

causal encoder-decoder 設計

  • 入力トークンの大半はフルの decoder 計算をスキップ
  • コーディングエージェントは、ファイル読み込みやツール結果・会話履歴の読み取りに時間を使う
  • まさにその読む時間が長いワークフローに効く設計
「読むのは軽く、書くときだけ 本気を出す」イメージ！

メモリとキャッシュの節約

  • グローバル attention キャッシュで GPU メモリ約1/4
  • 永続キャッシュの保存量は約1/8（同じワークロード比）
  • この削減はキャッシュされた文脈に適用される話
  • モデル全体がその分小さくなった、という意味ではない点に注意
この節約が サーブ費用の低下を 説明してるんだね

  • 応答はテキストで返ってくる設計
  • 今回のテストはテキストだけで書くコーディングが中心
  • 画像機能はベンチ対象ではなく、ローンチ機能のひとつとしての紹介
画像まわりは今回 検証してないので、 公開結果を待とう！

KingBench 3 の8タスク詳細

Task 1

エレベーターシミュ

8/10 前回 3
  • 3基のシャフトが見え、各フロアに乗客が並ぶ整った画面
  • ルール通り1基に1人だけ乗車。待ち・移動中・到着のカウンターも整合
  • ブラウザ確認: 24人×2班＝48人全員が到着、定員超過なし
  • 完了した乗客の要素をきちんと削除。前回の「消える車両」は解消
  • 減点: 時間差で乗客を追加中にシミュを消去すると、残りの乗客が後から現れるリセットの穴
3 → 8 点。 見た目だけじゃない 改善の証だね！
Task 2

コンタクトレンズケース

7/10 前回 5
  • 白いケースにミント色のフタ、大きな L / R 表示
  • クリックでフタが開閉。「両方あける」ボタンも正しく動作
  • 回転して観察できる。ヒンジを軸にした理にかなった動き
  • 前回は文字が壊れフタの下が固まって見えた → 今回は解消
  • 減点: 容器が浅く見える／フルオープン時にフタが画面から切れる
お題の意図を かなり正しく掴んだ 良でき！
Task 3

折りたたみテーブル

6/10 前回 浮遊&埋没
  • 前回は天板が浮き、脚が地面に埋まる大失敗 → 今回は4本の見える脚で立つ！
  • 木目調の天板も良好。スライダーの反応もなめらか
  • 脚が正しく動く部品に付いていて、畳み時も部品として一体
  • 減点: 完全に畳んだ状態で脚バーが天板に貫通。機構としては最後まで物理的にキレイではない
「改善したけど、まだ 確認が必要」 という良い例だね
Task 4

パンダバーガーSVG

6/10 前回 5

Task 5

弓矢ゲーム
