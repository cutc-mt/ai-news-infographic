その名は Hermes。

SECTION 1｜コンセプトと、今の問題

01

コンセプト: 渡して、離席

ゴールを渡したら、もう見なくていい。

  • タスクを渡したら walk away。あとはエージェントが回す。
  • 「10分おきのチェック」も「タブを見張る」も不要。
  • なん時間でも、まとめて放置できる。
  • そのあいだ、人間は別の仕事か休憩。
「見ていなくていい」ために、
ぜんぶが設計されている。
それが今回のテーマだよ。
02

Agent OS と Hermes

ゴールを1つ入れると、あとは自律ループ。

  • 中核にいるのは、エージェントの Hermes。
  • 自律ループで、なん時間でも動き続ける。
  • 自分の作業をセルフチェックして、自分で直す。
  • 完了か、人の判断が必要な時だけ戻ってくる。
帰ってくるのは「終わった時」か
「聞きたい時」だけ。いい部下だね。
03

Problem: タブだらけの毎日

どのツールも賢い。でも、つながっていない。

  • チャットツールは、ひとつ目のタブ。
  • タスク管理は、また別のタブ。
  • ボイスアプリも、やっぱり別。
  • タブを閉じたら、文脈が消える。
お互いの記憶を持たないから、
毎回、説明しなおし。
これが今の限界なんだ。
04

解決: 1つの command desk

5つの別ツールではなく、1つのデスクへ。

  • チャットも、ボイスも、タスクも 同じ場所 に。
  • 裏にいるのは、ぜんぶ同じ Hermes。仕事ごとに帽子を変える。
  • チャット版・ボイス版・タスク監視版…。
  • 顔が違っても、中身は同じエージェント。
窓口はたくさん。
でも働くのは、たった一人。

SECTION 2｜Hermes の中心機能

05

Shared Memory

全ツールが、同じ記憶を参照する。

  • 記憶の土台は、Obsidian。
  • チャットの内容も、
  • ボイスのやりとりも、
  • タスクボードの状態も、
  • バックグラウンドのリサーチ結果も。ぜんぶ共通。
「さっき言ったこと」を、
別の窓口も知っている。
これが最大の違い！
06

Background Research Agent

リマインダーなしで、勝手に動くリサーチ担当。

  • 「ちょっと調べて」を、言いっぱなしでOK。
  • 通知なしで 自動スタート。
  • 見つけた結果は、共有メモリへ書き込み。
  • あとでデスクで、まとめて受け取れる。
忘れっぽい人ほど助かる、
陰のリサーチ係。
07

Goal Mode

目標を1つ置いて、あとは放置。

  • ゴールは 1つだけ。シンプルに。
  • 終わるまで、勝手に進む。
  • 人の判断が必要なら、そこで一時ストップ。
  • へんに脱線しないのは、記憶があるから。
goal: "競合のリサーチをまとめて"
mode: unattended  # 放置モード
stop: 完了 or 承認が必要な時だけ
暴れず、黙々と。
ゴールに向かって進み続ける。
08

Task Board

社員に振るように、ジョブを投入。

  • ボードにジョブを置くだけ。
  • dispatcher が worker を spawn（必要な分だけ）。
  • ジョブが勝手に動くのを、別作業しながら見守れる。
  • 進み具合は、ボードでひと目でわかる。
自分は別の仕事。
ボードのほうは、勝手に回ってる。
09

Model Switching

モデルの切り替えは、2クリック。

  • 操作は manage タブ から。
  • 2クリックで、モデルを交代。
  • 新しいモデルが出ても、同じデスクにそのままプラグイン。
  • つくり直しも、説明し直しも不要。
モデルの入れ替わり時代を、
デスクご作り直さずに済ませる方法。

SECTION 3｜安全・コスト・記憶の設計

10

Guardrails

危ない操作は、勝手に進めない。

  • リスクの高い操作は、一時ストップ。
  • 削除など、戻れない系のアクション。
  • 確信を持てない時も、止まる。
  • 人の承認に回されて、OKで再開。
「放置」が成り立つのは、
この安全感があるからだね。
11

Cost Control

最強モデルは、必要な時だけ。

  • 日常は ローカル / 無料モデル で回す。
  • 使いすぎを、ぐっと節約。
  • 難しい仕事だけ、最強モデル を起用。
  • コストと品質を、その都度使い分け。
ぜんぶ最強で回すと、月末が怖い。
よく分かってる設計だ。
12

Customization Layer

デスクに置くのは、使う部品だけ。

  • 使わない機能は、非表示にできる。
  • 消してしまうことも。
  • ツールを足しても、散らかない。
  • 表示は「自分の仕事形」に合わせて。
機能が増えても平気。
いらないものは、視界から消える。
13

Memory Compounds

10回目は、1回目より賢い。

  • 使うほど、仕事の進め方を覚える。
  • 通常のAIは、毎回の会話が白紙。
  • ここが、いちばんの違い。
  • 放置ゴールが20分で脱線しないのも、この記憶のおかげ。
記憶が、積もっていく。
「放置」を支えるのは、この土台。
14

Old Way vs New Way

道具の数より、記憶のありか。

Old Way バラバラのツール群
同期されないまま
タブを閉じれば消える
New Way 1つの command desk
裏は同じ Hermes
1つの共有メモリ
VS
  • 旧: つなげるのは、人間の頑張り。
  • 新: つなげるのは、共有メモリ。
道具の数じゃなくて、
記憶のありかで選ぼう。

SECTION 4｜実践と、次の一歩

15

コミュニティ

AI Profit Boardroom への案内。

  • メンバーは 4,000人以上。
  • 30日間の ロードマップ つき。
  • 無料の戦略セッションへの案内も。
  • 導入の悩みは、仲間に聞ける。
一人で抱えこまないのが、
いちばんの近道。
16

どんな人に合う?

向く人・向かない人を、整理。

  • ルーティンを減らしたい人に ◎。
  • リサーチを自動で回したい人に ◎。
  • タブ乱立に疲れた人に ◎。
  • 全部を自分で確認したい人には、向かないかも。
「預け心地」を試すのが、
はじめの一歩。
17

はじめかた

小さく始めて、感触をつかむ。

  • まずは、小さいゴールを1つ。
  • 放置して、戻ってきた内容を確認。
  • 承認ゲート の感触をつかむ。
  • 繰り返して、メモリに覚えさせる。
大事なのは勇気より、
小さい成功の積み重ね。
18

まとめ

放置できる仕事の、新しい形。

  • エージェント Hermes が、なん時間でも動く。
  • 1つのデスクと、1つの共有メモリ。
  • ガードレールと、コスト管理も最初から。
  • 詳しくは動画で（8:58）。ナレーターは Pipa。
「渡して、離席」。
これが、新しい仕事の単位かも。
