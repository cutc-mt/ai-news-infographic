① Xで話題の裏ワザ投稿

  • 「Codexの利用枠が 0% になっても GPT-6 Astra や GPT-5.6 Pro を無料で使い続けられる」
  • その投稿はXで 16万回閲覧 の大反響
  • 投稿者いわく「一部の開発者が見つけた方法。一切お金を払わずに」
  • 本当にできる？ 実用的？ → その場で検証へ
「無料で upper モデルが使い放題」って、耳を疑う話ですよね…。まずは懐疑的に試すのが実験室の流儀！

② 検証開始前の状態

  • 学長の環境はちょうど Codex の枠を使い切った 直後
  • ChatGPT の Work 権限 → 「使用できません」 表示
  • Codex 側も 同様に停止中
  • 投稿の手順: 枠を使い切る → Web版へ切替
まず知っておきたい基本: 枠が切れても ChatGPT のチャット画面は動きます。ここが出発点。

③ 実験1: チャットに頼む

  • モデルを GPT-6 Astra（ウルトラ高精度） に選択
  • 「こんにちは」→ 普通に返信が来た
  • 依頼内容: Xの投稿を要点整理し、グラレコ保存用フォルダに保存
  • 作業は進むが、いつもより やや時間がかかる
投稿の取得 → 要約 → 保存先の構成確認まで、チャットだけで進んでいく！

④ 結果: 保存先はドライブ

  • ローカルのPCフォルダは 触れず
  • 保存先は Google ドライブ。いつもの構成で新規フォルダを作成
  • 枠が切れた Codex の代わりに、チャットが調査 → まとめまで実行
  • 初回は時間がかかる → 「手順をスキル化」すれば快適 に
これはこれで使える！ でも投稿が言うのは ローカルも読み書きできる 方法だった…。

⑤ 小技: サイドチャット節約術

  • Work / Codex 作業中、リサーチだけ サイドチャットの Web ブラウザ に担当させる
  • 調査で メインのトークンを消費しない
  • サイドチャット経由で ChatGPT に検索・収集 → 結果だけ本体に戻す
  • 発想は学長配布の 「GPT Pro に相談させる」スキル と同じ
枠切れ前の 節約テク として今からでも使える小ワザ！

⑥ 本家の方法を読み解く

  • 投稿が想定する流れは逆方向: Codex のローカル環境をそのまま使う
  • Codex で ローカルのプロジェクトを開く
  • モデルを ChatGPT（Web版）に切替 → Codex 経由でローカルを読み書き
  • 学長が先にやったのは 別の流れ だったと判明
「もしこの投稿がなかったら、新発見だったかも」という収穫も。ここから本題の実験2へ！

⑦ 実験2: 非公式ブリッジ導入

  • ランチャー 「Codex Web GPT」（非公式・サードパーティ製）
  • 導入すると Codex のモデル欄に ChatGPT Web が追加されるという仕掛け
  • チャットからは直接インストール不可 → README の手順に従う
  • セットアップ → 専用Chrome画面でログイン → 自動操作あり
$ codex-web-gpt セットアップ
✔ 日本語を選択 → 続ける
✔ 自動操作を許可
✔ 専用ChromeからChatGPTにサインイン
→ ログイン成功！
見た目は普通のチャットアプリそのもの。ここまでは順調…かも？

⑧ サインインと動作確認

  • ChatGPT へのサインイン 成功
  • ブラウザの スモークテストも通過
  • 残るは手順3「Codex へインストール」…のはずが
  • ここで 初つのエラー が発生！
README の注意: 「Codex は背景プロセスも含め完全に終了する必要あり」。ここで詰まります…。

⑨ 「Codex を完全終了して」で詰まる

  • 手順3をクリック → エラー。緑のチェックが付かない
  • 「バックグラウンドの プロセスも含めて終了」が、手動では困難
  • 終了させたら Codex Web GPT 側まで閉じてしまう
  • 背景: 今の Codex は ChatGPT アプリに同梱 されている
ここは自力で解決するのをあきらめて、別のAIに助け舟を出します。

⑩ Claude Code に調査依頼

  • 「コンピューター操作で Codex を完全に終了 して」と依頼
  • 並行して 安全性（BAN されない？）の調査 も頼む
  • 待っていたら 手順3が完了！
  • 原因と対処は Note 記事にまとめる予定

→ 実行: OK / 完了しました
詰まったら素直に専門家（別エージェント）に丸投げ。これ、大事。

⑪ 詰まりの正体が判明

  • Claude Code の診断: インストール失敗ではなかった
  • 原因は ネイティブ Codex が再起動されていなかった こと
  • 対処は ChatGPT アプリを起動し直すだけ
  • 起動直後に ブリッジがモデルを取得 → 選択肢に登場
緑チェックは付いてなくても、実は成功していたというオチ。再起動待ちでした。

⑫ モデル欄に「ChatGPT Web」

  • Codex のモデル選択に ChatGPT Web（Ultra High） が追加
  • いつものハーネス（作業画面）で そのまま会話できた
  • この通信は ChatGPT Web 側の枠 を消費 → Codex / Work の上限は影響なし
  • 先にドライブへ保存した調査結果を引き継いで作業を継続
ここで投稿の主張は 再現できた！…でも、まだ乗り越える壁が。

⑬ ローカル接続には MCP が必須

  • 初期状態では ローカルにアクセスできません
  • 左側の MCP で「フルハーネス」を設定 する必要がある
  • 手順は3つ。ただし API 鍵の作成は自分でやる 必要あり
  • 学長はここも Claude Code に操作してもらう設計
MCP設定: フルハーネス接続
1. MCPサーバー追加
2. 権限を許可
3. API鍵は自分で作成
→ ローカル読み書きが可能に
動いた先に鍵の管理という新たな責任が。ここで一旦、足を止めて考えます。

⑭ BANリスク調査: 規約の壁

  • OpenAI 利用規約の 「出力の自動抽出」 に文言上は該当
  • 同じく 「レート制限の回避」 にも該当しうる
  • 作者自身が README で アカウントリスクを認識。ゼロリスクモードも用意
  • APIキー作業は結局 自分でやる必要 がある
「無料」の裏に 規約とリスク がついてくる。ここからが判断の分かれ道。

⑮ GitHub の BAN 報告

  • BAN → その後解除 の報告が1件
  • 「不審なアクティビティ」警告 の報告が複数
  • ただし 永続BANの確定事例は見つからず（調査時点）
  • 使い続けるなら 同時実行は1本だけ・無人運用は避ける
「警告は来たけど復活できた」…それでも業務の生命線には怖すぎる、が正直なところ。

⑯ 結論: 動いたが使わない

  • 検証結果: ブリッジは 本当に動いた
  • それでも学長は 導入を見送り
  • 理由: ChatGPT Pro は業務の生命線。失えない
  • 「GPT が想定していない使い方」は 推奨できない
API鍵の先の作業も自分でやる必要があるし…。「やめとく」も立派な判断です。

⑰ 安全な代替: チャット＋ドライブ

  • 公式コネクタ の Google ドライブ接続 → 停止リスクの心配なし（個人の推測）
  • 注意点1: コネクタに渡した権限の範囲 を確認
  • 注意点2: 学習利用がオフなら 記録がモデル改善に使われない
  • 調査 → ドライブにファイル出力の流れは 1つ持っておくと便利
枠が切れた日の 正規ルートの避難先。まずはここから試そう！

⑱ まとめ: 公式の範囲で乗り切る

  • 枠切れ時の選択肢① ChatGPT チャット＋Google ドライブ
  • 選択肢② サイドチャットでリサーチ → 本体の枠を節約
  • 選択肢③ GPT Pro に相談させるスキル（前回動画で解説）
  • どうしても試す人は 自己責任 で。同時実行は1本まで
「動くか」だけでなく 「使い続けられるか」 まで考える。それが実験室の結論です。
