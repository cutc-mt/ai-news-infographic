SECTION 1｜GCNV とは、なにか

01

GCNV って、なに？

Google Cloud 上で動く、NetApp のストレージ。

  • 正式名称は Google Cloud NetApp Volumes。
  • NetApp ONTAP の機能を、フルマネージドで提供。
  • エンタープライズグレードの、ファイル・ブロックストレージ。
  • 企業のシステムをそのままクラウドへ移す、強い味方。
「モノは NetApp、場所は Google Cloud」。
それが GCNV だよ。
02

3つの入口で、直接操作

使い慣れた道具から、そのまま管理できる。

  • Google Cloud Console — 画面でポチポチ管理。
  • gcloud CLI — コマンド一発で、自動化も。
  • Terraform — インフラをコードで定義。
  • Monitoring・Logging・Billing と、シームレス統合。
# gcloud でボリュームを作る例
gcloud netapp volumes create my-vol \
  --location=asia-northeast1 \
  --service-level=FLEX \
  --capacity=1024
いつもの Google Cloud の道具箱で
そのまま使えるのが、うれしい。
03

4つのプロトコル対応

ファイルもブロックも、これ1つで。

  • NFS — Linux 系のファイル共有といえばコレ。
  • SMB — Windows のファイル共有の定番。
  • iSCSI — ネットワーク越しのブロックストレージ。
  • NVMe/TCP — 高速なブロックアクセスの新定番。
バラバラだったストレージを
1つのサービスに、まとめられる。
04

ストレージの「サイロ化」問題

アプリごとに別ストレージ、もうやめない？

  • アプリごとに別のストレージを用意すると、管理が大変。
  • 運用負担がふくらんで、ミスもふえやすい。
  • コンプライアンス要件の適用も、ばらばらになりがち。
これまで アプリAは NFS、アプリBは SMB…と別々に管理
GCNV なら 単一サービスに集約し、統一的なポリシー適用
まとめることで、運用も
コンプライアンスも、ぐっとラクに。

SECTION 2｜止まらない、消えない

05

ゾーナルプール: 99.9%

1つのゾーンの中で、堅く守る。

  • データは 単一ゾーン内 に配置。
  • 可用性は 99.9%（3個の9）。
  • コストを抑えたいワークロードに、ぴったり。
「とりあえず1ゾーンでいい」
という時の、お手軽プラン。
06

リージョナルプール: 99.99%

2ゾーンでレプリカ、障害時も安心。

  • データを 2つのゾーン にレプリケーション。
  • 可用性は 99.99%（4個の9）。
  • アクティブ側の障害時は、自動フェイルオーバー。
  • データ損失ゼロ・ダウンタイムなしで、切り替え完了。
ゾーンが1つ落ちても
もう片方が、すぐ引き継ぐよ。
07

NetApp スナップショット

コピーは、一瞬。負荷も、ほぼゼロ。

  • 瞬時コピー — 取得はほぼ一瞬で完了。
  • ほぼゼロフットプリント — 容量をほとんど使わない。
  • 性能への影響なし。本番稼働中でも OK。
  • 読み取り専用 のコピーで、改ざんされない。
「いまの状態」をパシャリ。
何度でも、好きなだけ。
08

バックアップボールト

別拠点に、まるごと保管。

  • 別の拠点へ フルコピー を保管。
  • 2回目からは 増分のみ — 転送量を節約。
  • 事前定義サイクルで、バックアップを自動回転。
  • 選択的ファイル復元 も、かんたんに。
  • イミュータブル設定 で、削除・改ざんを防止。
金庫にしまったら、
そうかんたんには出せない。
それが、安心につながる。
09

クロスリージョンレプリケーション

リージョンまるごと落ちても、続く。

  • 別リージョンへ、非同期レプリケーション。
  • 広域障害のさいも、ビジネスを継続できる。
  • 災害対策（DR）の要として活躍。
東のリージョンがダメでも、
西に同じデータがある。
それが「継続性」だよ。

SECTION 3｜守る、検知する、戻せないようにする

10

自動暗号化と CMEK

データは、いつでも暗号化され続ける。

  • 保存時 — ディスク上でも、暗号のまま。
  • 転送中 — ネットワークを流れる間も、安全。
  • バックアップ中 — 保管先でも、守られ続ける。
  • CMEK — 暗号鍵を、自分で管理できる。
いつ・どこにあっても
鍵のかかった状態。それが基本。
11

自律的ランサムウェア保護 (ARP)

攻撃を「検知」して、即「スナップ」。

  • ARP が疑わしいトラフィックを、常時チェック。
  • 攻撃の瞬間を検知したら、即座に対応開始。
  • セキュリティスナップショット を自動作成。
  • 身代金要求の前に、イミュータブル な復元ポイントを確保。
攻撃されても、書き換え前の
データを確保しておく。天才。
12

WORM ストレージで規制順守

一度書いたら、書き換えられない。

  • WORM = 一度書いたら、消せも書き換えもできない。
  • NetApp の SnapLock 技術で実現。
  • SEC や HIPAA など、厳しい規制に対応。
  • 監査・証拠保全が求められる業界の、強い見方。
「書いた者が、消せない」。
医療や金融では、これが大事。

SECTION 4｜やすい、はやい、思いどおり

13

Flex Unified サービスレベル

容量・性能を、バラバラに指定できる。

  • 容量 と スループット と IOPS を、独立してプロビジョニング。
  • 1GB から PB 級 まで、スケール可能。
  • サブミリ秒レイテンシ で応答。
  • 必要なぶんだけ買う、ジャストサイズの設計。
容量だけ大きく、性能は控えめ…みたいな
注文が、そのまま通る。
14

オートティアリング

使わないデータは、自動でしいれ階へ。

  • アクセス頻度の低いデータを、自動で低コスト層へ移行。
  • よく使うデータだけ、高速な層に残る。
  • 高頻度データが 20% なら、高い層も 20% で OK。
  • ムダな課金を、がっつりカット。
全部高い層 使わないデータまで、高速層の料金
自動で階層化 よく使うぶんだけ、高速層に置く
引き出しの奥には、
あまり使わないものをしまう。
ストレージも、おなじ。
15

コスト最適化のまとめ

うまく組み合わせて、ムダをなくす。

  • Flex Unified で、必要ぶんだけプロビジョニング。
  • オートティアリング で、コールドデータを自動で低コスト層へ。
  • 用途に合わせて、ゾーナル／リージョナルを使い分け。
  • Billing 連携で、費用もいつもの画面で把握。
「安く」じゃなく「ムダなく」。
そこが、エンタープライズ流。

SECTION 5｜どこで、活きるか

16

ユースケース①: DB とコンテナ

おうちで運用するシステムに、強い。

  • MySQL や Oracle などの、セルフマネージド DB。
  • GKE 上のコンテナワークロード。
  • Red Hat OpenShift の永続ストレージにも。
  • サブミリ秒の応答で、DB の性能も安心。
「DB は自分で運用したい」
そんなチームに、ぴったり。
17

ユースケース②: AI と EDA

大容量データを、ぐるぐる回す。

  • Gemini とのネイティブ統合で、AI アプリ構築がかんたんに。
  • FlexCache で、遠隔地にも高速にキャッシュ。
  • 大容量ボリュームで、EDA（半導体設計）ワークロードも支える。
  • 設計データの爆発的な増加にも、PB 級で追従。
AI も半導体設計も、
食べるデータがでかい。
そこを、たっぷり支える。
18

まとめ

エンタープライズストレージの、新しい居場所。

  • NetApp ONTAP の実力を、フルマネージドで。
  • NFS・SMB・iSCSI・NVMe/TCP を、1つにまとめる。
  • 可用性・データ保護・セキュリティを、標準で装備。
  • Flex とオートティアリングで、コストも思いどおり。
  • 詳しくは、ぜひ本編の動画で。
「NetApp の使い心地」を
クラウドでも、そのまま。
それが GCNV だった。
