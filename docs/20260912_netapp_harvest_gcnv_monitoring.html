SECTION 1｜なぜ、Harvest なのか

01

監視の現場、あるある

ストレージは、あちこちに散らばっている。

  • Google Cloud、CVO、オンプレのクラスタ…環境は複数。
  • プラットフォームごとに、メトリクスの「言葉」がちがう。
  • ダッシュボードも別々。見るだけで一苦労。
  • 情報が断片化して、全体像が見えなくなる。
左の画面、右の画面…
行ったり来たりで、目が回る！
02

NetApp Harvest とは

オープンソースの、メトリクス収集エンジン。

  • マルチクラウドのストレージを、単一ダッシュボードで監視。
  • 性能・容量・ハードウェアの状態を、まとめて収集。
  • GCNV と組み合わせて、リアルタイム監視へ。
  • 名前のとおり、メトリクスを「刈り取る」のがお仕事。
ばらばらの監視情報を
1カ所に集める、それだけの力が強い。
03

つなぐだけで、はじまる

既存のインフラに、しれっと接続。

  • もうある環境にシームレス接続。再設計は不要。
  • 性能カウンタを、ぜんぶまとめて表示。
  • 容量のトレンドも、同じ画面で追える。
  • ハードウェアの健全シグナルも、取りこぼさない。
「移行するなら再構築でしょ…」
いいえ、Harvest は上からかぶせるだけ。
04

5分おきでは、遅い

レイテンシのスパイクは、一瞬で消える。

従来 メトリクスエクスプローラは
5分ごとの更新。
一瞬のスパイクは見逃して、タイムアウトの原因がつかめない。
Harvest リアルタイム監視。
つかの間のボトルネックを、おきた瞬間にキャッチ。切り分けもはやい。
VS
  • インシデントの対応時間を短縮できるのが最大の利点。
タイムアウトの犯人を
現行犯で捕まえられる。

SECTION 2｜しくみを、ひもとく

05

Apache 2.0 で、オープン

中身も、たくさんと公開されている。

  • ソースコードは GitHub で公開。コミュニティとともに進化。
  • ライセンスは Apache 2.0。商用利用も落ち着いて進められる。
  • お金をかけずに、すぐ試せる。
  • テンプレートを好きにいじれる、自由度の高さ。
「監視ツール、自作しなきゃ…」
その悩み、Harvest が引き取ります。
06

3つの部品で動く

Poller・Collector・Exporter。

  • Poller — 監視するクラスタごとに用意する単位。
  • Collector — どんなメトリクスを集めるかを担当。
  • Exporter — 集めたデータの送り先を指定。
  • テンプレートを編集して、自分好みに調整できる。
「誰が・何を・どこへ」を
YAML に書くだけ。
07

環境の差を、吸収する

ハイパースケーラーも、ONTAP のバージョンも。

  • クラウドの違いや ONTAP のバージョン差を、丸ごと抽象化。
  • それぞれのデプロイメントの横に、ローカルコレクターを配置。
  • えらんだ時系列 DB へ、一貫したメトリクスを送信。
  • 書式がそろうから、集めてから困らない。
どんな環境で話しかけられても
同じ様式に翻訳して届けてくれる、
通訳のようなレイヤー。
08

エコシステムと、つながる

標準フォーマットで、シームレスに。

  • Prometheus — 定番の時系列 DB へそのまま。
  • Grafana — ダッシュボードの王道と組み合わせ。
  • Cloud Monitoring — Google Cloud 標準の監視にも。
  • OpenTelemetry — コネクタ経由で接続。
もうある監視スタックに
無理なく組み込めるのが嬉しい。

SECTION 3｜じっさいに、組んでみる

09

好きなかたちで、動く

Docker・Podman・ネイティブ実行。

  • Docker コンテナで、すぐに起動。
  • Podman でも、もちろん OK。
  • バイナリを直接動かす、ネイティブ実行にも対応。
  • 環境に合わせて、えらび放題。
コンテナ派も、素朴に動かす派も
どちらも正解。
10

まずは、下ごしらえ

用意するのは Go と Docker。

  • 実行環境に Go と Docker を準備。
  • Flex Unified ストレージプールを用意。
  • ONTAP モードを有効にしてプロビジョニング。
  • ここまでで、下準備はおしまい。
GCNV 側は ONTAP モードの
プールを1つ用意するだけ。
11

YAML に、書き出す

harvest.yml が、設定の中心。

  • Pollers — 監視クラスタの数だけ定義。
  • Collectors — 集めるメトリクスの種類を指定。
  • Exporters — Prometheus や InfluxDB を指定。
# harvest.yml のイメージ
pollers:
  gcnv-flex:
    datacenter: tokyo
    collectors:
      - keyperf
      - volume
    exporters:
      - prometheus
      - influxdb
監視したいクラスタの分だけ
ポーラーを書き足していく。
12

鍵は、Bearer トークン

GCNV の ONTAP モードは、トークン認証。

  • ONTAP モードの GCNV には Bearer 認証トークンが必要。
  • 用意された credentials スクリプトで取得・設定。
  • トークンは、あつかいに注意して安全に管理。
  • これで Harvest から GCNV へ、認証がとおる。
入手と設定はスクリプトにおまかせ。
手作業は最小限。

SECTION 4｜数字を、みえる化する

13

keyperf で、脈をみる

IOPS・スループット・レイテンシ。

  • keyperf コレクターで、主要な指標をまとめて収集。
  • 収集間隔を 10秒 に変更して、感度を上げる。
  • つかの間のスパイクも、波形ごとキャッチ。
  • これが「おきた瞬間に気づく」の正体。
間隔を 10秒にすれば
息をのむ瞬間も、聞き逃さない。
14

Compose で、一撃起動

Prometheus + Grafana スタック。

  • Docker Compose で、監視スタックをまるごと起動。
  • Grafana も、同時に立ち上がる。
  • ホストの IP を、scrape ターゲットに設定。
# Prometheus の scrape 設定のイメージ
scrape_configs:
  - job_name: harvest
    static_configs:
      - targets: ['192.168.x.x:12990']
docker compose up したら
あとは、ちょっと待つだけ。
15

Grafana に、流れ出す

ダッシュボードは、えらぶだけ。

  • Grafana の GCNV ONTAP モードのタグを開く。
  • ボリュームダッシュボードを選択。
  • データがリアルタイムに、ストリーミング。
  • IOPS もレイテンシも、生きた数字で見える。
数字がぬるぬる動くのを
見ているだけでも、ちょっと楽しい。

SECTION 5｜おさらいと、そのさき

16

ながれを、おさらい

ハンズオンは、この 6ステップ。

  • Go と Docker を、実行環境に準備する。
  • Flex Unified プール（ONTAP モード）をプロビジョニング。
  • harvest.yml に Poller / Collector / Exporter を定義。
  • credentials スクリプトで、Bearer トークンを設定。
  • keyperf の収集間隔を 10秒に変更。
  • Compose で起動して、Grafana のダッシュボードを開く。
書くべきは YAML が中心。
思ったより、ずっと短い。
