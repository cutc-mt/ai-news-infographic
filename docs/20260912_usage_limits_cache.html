まず押さえたい基本の節約テク

AIは履歴を覚えていない

  • モデルは過去の会話を保持できない
  • それ以前の入力も、毎回ぜんぶ送り直される
  • 「こんにちは」のやり取りも、次の入力に含まれる
履歴が見えるのはUIの便利な機能。
モデルには毎回 全部おくり直し!

50ターン目の真実

  • 50回目には49回分の履歴が再入力される
  • やり取りが増えるほど、1回あたりの文字数が増える
  • 気がつけば使用料をガンガン消費
会話を重ねる 入力がふくらむ 枠が減る
雪だるま式に
消費がふくらんでいくイメージ!

基本のキ: セッションを分ける

  • 過去の履歴が不要なら、すぐ新しいセッションを開く
  • これが最初に意識したい基本の対策
  • 1つのセッションでずっと使い続けない
調子に乗って
1本で続けないのがコツ!

1回の入力にまとめる

  • 観点A・B・C…と毎回聞くと、過去の履歴も一緒に送られる
  • 1回の送信にまとめれば、同じ成果で消費が少ない
  • 仕事では少ないターン数を意識
資料Dを参照して、次の3点を
1回で分析してください:
A) リスク  B) 費用  C) 期限
質問はまとめて
一気に送るのがお得!

キャッシュの仕組みを、くわしく解説

キャッシュとは?

  • 同じ文章を先頭から同じ位置で2回以上 おくる
  • 1回目の計算の結果を、そのまま再利用できる
  • 「こんにちは」→「こんばんは」→「おはよう」の積み重ね
  • ポイントは位置が同じであること
最低の文字数などの条件はあるけど、
基本はこれだけ!

どれだけ得? キャッシュ価格

  • Opus 5.1: 100万トークン $5 → $0.5(約1/10)
  • Fable: $10 → $0.25 とさらに安い
  • OpenAI もキャッシュで約90%安
  • 書き込み分のコストは、ちょっと高めなので注意
キャッシュを切らさないことが
そのままお金に直結!

キャッシュ維持 3か条

  • ① 文章の位置を先頭から変えない
  • ② 使う間隔を開けすぎない
  • ③ モデルの設定を途中で変えない
位置 時間 設定 = キャッシュ保持
この3つを守れば
お得に使い続けられます!

Compact の罠

  • /compact は履歴を要約して圧縮する機能
  • 要約で先頭の中身が変わり、キャッシュが切れる
  • せん縮するときの入力にも、その分の使用料がかかる
  • 節約のつもりが、逆に消費が増えることも
/compact
→ セッションを圧縮しました
(ただし先頭から文章が変わる…)
連発は禁物!
別の問題もあるそう(動画にする予定)

キャッシュの寿命

  • 一定の時間 入力がないとキャッシュはクリアされる
  • Claude Code は最大1時間まで保持
  • GPT-5.6 のスペック表は最低30分
  • Work / Codex は公式の明言なし(切れない保証はない)
休憩後の再開は
キャッシュ切れを疑って!

  • メインとサブエージェントはキャッシュが別々
  • Fable 1本 vs Opus 複数で、結果が逆転することも
  • 2パターンで実測して比べるのがおすすめ
