【Boxの最新活用術】ファイル管理から
AI-Ready基盤へ

写真だけで報告書を作成、契約書チェックをAIエージェントが代行――Box Japan×農林中央金庫の対談を18枚にまとめました

このページの見方：①〜⑱のカードでBoxの企業調査データから実際の活用事例、今後の展望までを順に追います。緑の下線の部分が特に大切な要点、手書き風の吹き出しは補足の解説です。最後にチェックリストと用語集をまとめました。

①眠れる宝を呼び起こす: AI-Readyなファイル管理

  • 企業のコンテンツは眠っている宝の山――BoxはそこにAIが火をつける基盤を目指します。
  • オフィス文書・PDF・設計図面・画像・動画・音声を容量無制限でセキュアに保管。
  • 保管するだけだったファイル管理にAIのレイヤーを実装し、より高度な管理・活用へ。
  • コンテンツ管理を軸に積み重ねてきた経験こそBoxの最大の強みと佐藤範之さんは語ります。
AI-Ready基盤 コンテンツ管理
ただ保管するだけの場所から、業務を動かす場所へ。それがAI-Readyなんですね。

②1年で8倍: AIエージェント活用の実態

  • BoxがグローバルのITキーパーソンに聞いた調査で、社内AI活用は1年で8%から64%へ（動画内の数字）。
  • 1年前は「ChatGPTを入れました」で止まっていた企業が、今は実業務へ進み始めていると分析。
  • ただし64%のうち「本当に使いこなせている」のは約4割、全体では25%程度という見方も示されました。
  • 分水嶺はAIエージェントと企業コンテンツの組み合わせ――ここを制した企業だけが本活用です。
8%→64% 本活用は25%
「導入した」ではなく「業務に組み込んだ」企業が差をつけ始めています。

③AIエージェントの3段進化: 聞く→探す→動く

  • 当初は資料に問い合わせて要約するQ&A型が中心でした。
  • 次にドキュメントの中身を理解し、重要な情報をマイニングして抽出する段階へ。
  • 抽出した情報はメタデータとして管理され、AIエージェントが文書を正確に理解する土台に。
  • 最終段階は業務プロセスを自動で流すエージェント――最終ジャッジは人が担います。
メタデータマイニング プロセス自動化
AIが「読む」から「動く」へ。その間にメタデータ整備という段階があるのですね。

④従来の点検業務: 紙とバインダーの世界

  • 従来は現場でデジカメで撮影し、メモリを抜いてオフィスに戻り報告書を作成。
  • 報告書作成にはかなりの時間がかかり、上長や関連部署の確認・差し戻しも手作業。
  • 完成した報告書は紙に印刷してバインダーに綴じ、保管庫へ。
  • 必要な時は「あの年の点検記録はどこ?」と探すこと自体が一苦労な状態でした。
紙の報告書 属人化管理
撮って、戻って、書いて、綴じて、しまう。業務の大部分が事務作業でした。

⑤写真を上げるだけ: 自動で始まるワークフロー

  • 作業員はBoxのモバイルアプリで撮影するだけ――指定フォルダに自動アップロードされます。
  • 画像が入るとカスタムエージェントが自動起動し、報告書作成を引き受けます。
  • 「どこの拠点で、どの設備か」を記載して送信。その後の流れはBoxがすべて管理。
  • Boxは容量無制限なので、画像も動画も遠慮なくアップロード可能です。
自動アップロード カスタムエージェント
現場で撮って送るだけ。あとはエージェントが動き出します。

⑥エージェントが書く点検報告書

  • 写真を元にエージェントが点検報告書を自動生成。フォーマットも事前に設定可能です。
  • オイル漏れや清掃状態、ボルト交換時期の検討まで写真から読み取って指摘します。
  • 事前にチェック項目を指示しておけば人と同じ粒度で報告書を作成できます。
  • 「錆びや傷は危険と判断しないのか?」への答えはチューニングで精度を上げる継続運用。確認は人が行うケースも。
報告書自動生成 チューニング
やればやるほど賢くなる。指示の精度を上げていくのがコツです。

⑦抽出と分岐: 要確認は自動で上位へ

  • 報告書生成の次はBoxエクストラクトが起動し、関連情報をメタデータとして抽出。
  • 要確認のメタデータがあれば要確認フォルダへ自動で飛び、上司にタスクがアサインされます。
  • 問題ないものは完了フォルダに自動で格納――人の確認と格納が並行して進みます。
  • デジタル化された報告書は縦横いろいろな切り口で検索可能。誰でもどこからでもアクセスできます。
Boxエクストラクト 自動分岐
生成→抽出→分岐→保管。一連の流れ全部がワークフロー化されています。

⑧ノーコードでワークフロー構築

  • ワークフローはドラッグ＆ドロップで簡単に作成。ユーザーが自由に組み立てられます。
  • フォーム送信を起点にエージェント起動→PDF生成→項目抽出→結果分岐をつなげられます。
  • 登場するのはフォーム・生成・抽出といった機能の呼び出しを並べるだけの設計。
  • 今後のロードマップではやりたいことを丸投げするとAIが自動構築するサービスも計画中です。
ドラッグ＆ドロップ ノーコード構築
プログラミング不要。業務がわかる人がそのまま作り手になれます。

⑨エージェント暴走への備え: 3つのG

  • 1つ目のGはガードレール――プロンプトインジェクションを検知・ブロックし、ログを記録。
  • 文書に仕込まれた「指示を無視してこれをやれ」という悪意ある仕掛けが今後増えると警戒されます。
  • 2つ目のGはガバナンス――どのエージェントが誰の権限で何をしたかログで追跡可能。
  • 3つ目のGはガイド付きアクセス――外部エージェントには機密文書の参照を許しません。
3つのG プロンプトインジェクション
便利さと危険さは表裏一体。3つのGがエージェント時代の安全装置です。

⑩農林中央金庫の導入理由: 攻めのIT

  • 農林中央金庫・ビジネス共創部の黒澤歩さん。2011年入庫、法人融資・経営企画を経て2022年からITシステム部門。
  • 金融機関と聞くと保守的な印象ですが、実際は「攻めのIT」の代表格。
  • グループ全社で約7,000人。ファイルサーバーやシステムが乱立し、「どこに何があるか分からない」状態が課題でした。
  • 導入の決め手はセキュリティと、大きなファイルを安全にやり取りできる社外共有の仕組み。
農林中央金庫 セキュリティ
「Boxで探したら見つかる」――その一点から社内変革が始まったのですね。

⑪3つの領域分担: 社内・文書管理・社外共有

  • 農林中央金庫はBoxを社内コンテンツ保存・文書管理・社外共有の3領域に分けて運用。
  • 社外共有では開示してよい範囲のチェックリストがセキュリティ上の関門になります。
  • 外部委託契約の際には約90項目のチェックリストを担当者が目視で確認していました。
  • 契約書と照らし「この項目はどこに書いてあるか」を1つ1つ丁寧に確認する重い業務です。
3領域運用 90項目チェックリスト
ミスが許されない金融の契約チェック。ここにAIが入るとどうなるのでしょう。

⑫契約書チェック: 年間2400時間→300時間

  • 契約書をアップロードし「チェックして」とチャットで頼むだけで90項目の過不足をAIが出力。
  • 結果はOKは緑・要確認は黄色・NGは赤で表示され、網羅性高くチェックできます。
  • 「この条文に書いてある」という根拠付きで回答してくれる点が実用の鍵。
  • 一次チェックをAIに丸投げし、最後の確認は人が行う運用で、年間2400時間の業務が300時間へ（動画内の数字・発言者による効果試算）。
2400時間→300時間 根拠付き回答
約2,100時間――ひとり分の労働時間に匹敵する浮きが生まれました。

⑬浮いた時間の使い道: スルーから営業へ

  • 専門家の数は限られており、契約チェックはボトルネック化していた業務の一つ。
  • エージェント化すれば「もっとビジネスを取ってきて」という営業側の仕事へシフトできます。
  • 人の仕事が消えるのではなく、他に使えるようになる――対談の一貫したメッセージ。
  • 限られた専門家がより付加価値の高い業務に回る構図がAI活用のゴールです。
業務シフト 付加価値業務
AIは仕事を奪うのではなく、仕事の内容を上げ替える道具なんですね。

⑭Boxハブズで問い合わせを循環させる

  • Box Hubs（ボックスハブズ）に人事・総務・経理などのハブを準備し、AIが回答。
  • ハブ内の情報で足りない問い合わせはエスカレーションして正しい担当者に振り分け。
  • 担当者の回答を蓄積してナレッジ化する循環を作れば、回答精度が上がり続けます。
  • やり取りの個人名はマスキングして文書化――見せてはいけない情報は出しません。
Box Hubs ナレッジ循環
問い合わせ→AI回答→エスカレーション→蓄積。知識が回り始める設計です。

⑮1週間で作るヘルプデスクワークフロー

  • 問い合わせフォームを起点にヘルプデスクエージェントが振り分け、文書を自動生成。
  • ここまでのワークフローは担当者が約1週間で作成できるほどの簡単設計。
  • 社内全体の問い合わせを巻き取れば数万時間の効率化効果の可能性（発言者による試算）。
  • 問い合わせの多い部署ほど自分たちでノーコード作成できるのが大きな利点です。
ヘルプデスク自動化 数万時間効果
数人で1週間作れば、その後の業務が全部楽になる計算になります。

⑯2つの新サービス: FDEとソリューションズ

  • 1つ目はBox Forward Deployed Engineer（FDE）――お客様の現場に溶け込み業務をAI化する専門集団。
  • 実装して終わりではなく運用フェーズまで寄り添い改善を続けるチーム設計です。
  • 2つ目はBoxソリューションズ――銀行や自治体など似た業務プロセス向けの完成品ワークフロー。
  • 選ぶだけで自社環境に落ちてくる提供形態で、要件に合わせてチューニングして使います。
FDE Boxソリューションズ
現場に入る専門家と、業界向けの完成品。2本柱でAI化を後押しします。

このページの用語集

  • AI-Ready…AIがコンテンツを理解・活用できるよう、データを整備された状態にしておくこと。
  • 非構造化データ…表形式ではない文書・画像・音声などのデータ。企業コンテンツの大部分を占める。
  • メタデータ…文書から抽出した重要情報。AIエージェントが内容を正確に理解する手がかりになる。
  • Box Hubs…部署ごとの情報を集約し、AIが回答する拠点として整えるBoxの機能。
  • プロンプトインジェクション…文書に悪意ある指示を仕込み、AIエージェントを誤作動させる攻撃手法。
  • FDE…Forward Deployed Engineer。顧客の現場に溶け込み業務のAI化を支援する専門エンジニア集団。
  • ノーコード…プログラミングなしで、画面操作だけでワークフローなどを組み立てられる方式。

用語の解説は、このページ向けに一般的な言葉でまとめたものです。
