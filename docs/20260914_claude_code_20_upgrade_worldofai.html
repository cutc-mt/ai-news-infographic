② セッション間メッセージング

序盤: v2.1の目玉機能
  • Claude Code v2.1で導入: 別々のセッション同士が通信できるようになった
  • セッションを行き来して文脈を再説明する手間が不要に — 「必要な情報を渡して」と伝えるだけ
  • 例: フロントエンド作業中のセッションから「user.nameがuser.display_nameに変わった」とAPI側へ連絡
  • 現時点ではmacOSとLinuxで利用可能
フロント側セッション メッセージ 決済API側セッション
セッション間の往復がなくなると、マルチタスク開発がぐっと楽になりそう！

③ 発見と通信のコマンド

序盤: list-agents / send-message
  • /list-agentsでClaudeが到達できるセッションの一覧を確認
  • send-messageで相手エージェントへ情報を送信 — 会話履歴全量ではなく必要な情報だけの簡潔なテキストを送る
  • Claudeが自律的に判断して自動連絡することも — 片方の変更がもう片方に影響するとき
/list-agents
→ 到達可能なセッション一覧を表示
send-message
→ 相手が必要とする情報のみ送信
履歴を全部投げずに要点だけ送る設計、エージェント同士の礼儀作法って感じ！

④ マルチエージェント協調の実証

序盤: サブエージェント
  • 主な用途はマルチエージェントのオーケストレーションと並列コーディングセッションの同期
  • 複数セッションに役割を持たせて共有状態を調整 — フロント・バック・作業ツリーごとにAPI変更を整合
  • 名前付きセッションを再利用可能な専門家のように扱い、片方が調べた情報を後から別セッションが取得
  • 実証デモ: 2つのエージェントがチェスで対局 — 連携の様子をライブ表示
セッションA（白番） 手の交換 セッションB（黒番）

⑤ 自動モードが既定に

序盤〜中盤: Auto Mode
  • Pro・Max・TeamプランのClaude Codeセッションで自動モードが既定の権限モードに
  • Claudeが実行の可否を自律判定 — 許可を求めるたびに作業が止まることがなくなる
  • 権限モードはいつでも切り替え可能。既にカスタム既定や組織管理の既定がある場合は上書きされない
  • 自動モードの分類器呼び出しが利用上限にカウントされなくなったのが最大の追加メリット
許可ダイアログの停止 自律判定 スムーズな作業
基本タスクでいちいち確認されるストレスがなくなって、本当に助かる更新！

⑥ 1,053人検証の根拠

中盤: 導入の理由
  • Anthropicは1,053人の有料開発者でテスト: 人間は危険なコマンドをわずか13.6%しか検出できず
  • 対して自動モードは89%をブロック — セッションが長引くほど人間の性能は劣化するが、自動モードは安定
  • 自動モード利用チームは約25%多くのPRを出荷 — Opus 5のような長期実行モデルと特に好相性
人間 13.6% 自動モード 89% 導入決定
「人間の確認」が実は一番の弱点だったというデータ、ちょっと衝撃的…！

  • 第三者プロンプトインジェクション評価では720回の攻撃で成功ゼロ（Opus 5 / Sonnet 5などの自動モード）

⑧ 簡潔モード（Concise）

中盤: 出力スタイル
  • 出力スタイルを簡潔（Concise）に設定可能 — 結果を先に・説明を省き・応答を短く
  • 長い説明はトークン消費を一気に圧迫 — 特に長時間のコーディングセッションで効いてくる
  • 設定ファイルから有効化。詳細が必要な場合は尋ねれば完全な説明が返ってくる
  • 「アテンションインターフェースの始まり」との声 — エージェントが何を言い・何を優先し・いつ注意を引くかを制御
冗長な説明 結果ファースト トークン節約
「答えだけまず聞かせて」ができるようになったの、地味に大きい改善！

⑮ コードレビューの努力度

後半: /code-review
  • 選んだ努力度でレビューの深さが変化 — 低コストの単一パスから超深度まで段階的に
  • Low: 差分の高速単一パス — ほぼ毎プッシュ前に使える安さ / Medium: 文脈で多視点の複数パス、検証後に提示
  • High: 新規サブエージェントを発見・検証に活用 / X-High: 変更外の下流問題まで探査
  • Ultra: レビュアーの艦隊を起動し、発見事項を独立に再現して誤検知を削減 — Anthropicが社内の全PRで運用
Low Medium High X-High Ultra
