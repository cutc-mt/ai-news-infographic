① 発表の概要: ウォーターマーク導入

0:30〜
  • 2026年8月14日、Anthropicが発表
  • Claudeが生成する文章そのものに埋め込まれる印
  • 「AIが生成したものか」が分かるようなウォーターマーク
  • 番組はその仕組みを独自に調査して解説
8月14日発表 文章に印 検出可能に
話題にはなったけど、中身を詳しく知らない人も多いはず——という回。

② じつは「もうついている」

0:55〜
  • 今日Claudeに書かせた文章にもう印は付与済み
  • 過去に書かせた文章にもさかのぼって付与
  • 出演者も「ちょっとびっくりした」と反応
  • 対象はClaude出力の文章全般
過去の文章 今日の文章 すべて印付き
あなたが今日書かせた文章にも、もうついてるんです……!

③ 見えない印: 隠し文字ゼロ

1:40〜
  • 変なユニコード・記号は一切なし
  • 見た目・意味・自然さは不変——読んで違和感ゼロ
  • 変化するのは「選ばれる言葉」だけ
  • 余計な文字を足す方式ではない
外見はそのまま 言葉の選択だけ変化 印になる
想像しがちな「隠しタグ埋め込み」とはまったく違う方式なんだ。

④ コスト・速度への影響なし

2:00〜
  • 料金は変わらない（Anthropic談）
  • 速度も変わらない——文字数が増えないから
  • 印は文字数を増やすものではない
  • 体裁はそのままに追加コストゼロで導入
文字数不変 速度不変 料金不変
使う側のコストは一切増えない——それでいて印は機能する。

⑤ 全提供面で有効

2:20〜
  • Claude UI・APIで生成される文章
  • Claude Codeで書き出す文章にも付与
  • AWSなど他ベンダー経由も対応
  • Claude提供面はほぼすべて網羅
UI API 他ベンダー経由も
どこからClaudeを使っても印はつく——抜け道なしの設計。

⑥ 導入理由: EU AI法への対応

2:45〜
  • EU向けのAI関連法制が厳格化
  • AI生成物かどうかのラベル付け義務の流れ
  • EU向けだけではなく世界中の出力に同時適用
  • 詳しい理由は公式には明記されていない
法規制 ラベル義務 全出力に適用
EU対応がきっかけでも、印は世界中のどこでも同じようにつく。

⑦ オプトアウト不可・検出APIは未提供

3:05〜
  • 利用者の設定項目は存在しない
  • 現状、印を読み取れるのはAnthropicのみ
  • 検出用APIは「近く出す」のまま未提供
  • 発表後しばらく経っても誰も使えていない
設定なし 読み取りはAnthropicのみ API待ち
オフにする手段も、自分で確認する手段も、今はまだない。

⑧ 技術の起源: 2022年に完成済み

3:40〜
  • 同じ技術はOpenAI研究者Scott Aaronsonが発案
  • 2022年にやり方を発表、動くものも完成
  • 文章がある程度長ければ99.9%の精度で読み取り可能
  • 鍵を使って言葉の選び方を偏らせる考え方
2022年発案 動くもの完成 Claudeが初導入
最新の技術じゃない——4年前にあったものを、いま世に出したんだ。

⑨ OpenAIが世に出さなかった理由

4:10〜
  • 技術がありながら4年間実装されず
  • なぜ出さなかったのか——番組の考察を展開
  • 当時の調査で利用者は強い抵抗感を示していた
  • 出すタイミングを失った可能性を指摘
技術あり 世論の抵抗 4年間お蔵入り
作れるのに出さない——そこにはユーザーの気持ちの問題があった。

⑩ AI検出ツールの失敗史

4:45〜
  • OpenAIのAIテキスト分類器はAI文章を26%しか当てられず
  • 人間の文章の9%を誤検出
  • 公開わずか半年で取り下げ
  • 「AIかどうかを当てる」外部判定はここで信用を失った
分類器公開 精度不足 半年で終了
当てる側が当てられない——検出ツールはまず失敗から始まった。

⑪ 誤検出の偏り: 非母語話者に厳しい

5:20〜
  • 英語が母語でない学生の小論文が誤ってAI扱い
  • その誤検出率は61.3%という検証結果
  • MITなど25以上の機関が利用中止へ
  • 文法が素直な文章ほど「AIっぽい」と判定されやすい
非母語の素直な文 AI誤判定 機関が離反
英語が苦手な人ほど疑われる——検証結果は衝撃的だった。

⑫ Claudeの方式は別物

6:00〜
  • 外部から当てる検出ではなく生成時に印を埋める方式
  • 生成された中に印がある状態を作る
  • 失敗した分類器とは仕組みからして違う
  • 対象はあくまでClaude自身の出力
外から判定 生成時に埋め込む 発想の転換
「当てる」から「最初から印をつける」へ——アプローチが逆なんだ。

⑬ 仕組み: 言葉の選び方が印

6:30〜
  • 同じ意味の言い方のうち「どれを選ぶか」が印になる
  • 秘密の鍵×直前の数単語で偏り方を制御
  • 4つの言い方それぞれに偏りの係数を内部的に持つ
  • 選ばれた言葉は読んでも全く不自然ではない
同義表現の選択 鍵で偏り制御 自然なまま印に
「大丈夫です」「問題ありません」——どれを選ぶかでひそかに印になってる。

⑭ 検出原理: 統計で見分ける

7:30〜
  • 人間の単語分布と鍵による偏りの差を統計的に測定
  • 長い文章ほどはっきり、短いほど曖昧
  • ブログや小論文のようなある程度の長さが必要
  • 偏りの割合で判定、長文なら99.9%精度にも
単語分布の偏り 統計測定 長文ほど高精度
1個の選択では偶然と変わらない——積み重ねで初めて見える。

⑮ コード・数式にはほぼ付かない

8:20〜
  • コードと数式は正しい書き方がほぼ一つ
  • 表現の揺れが乏しく書き分けができない
  • 短い関数単位では選ぶ回数そのものが足りない
  • 修正しても元のコードがほとんど残る
一意な書き方 揺れなし 印が機能しない
Claude Codeで書かせたコードは、人間が書いたものと区別がつかないだろう。

⑯ 回避の試みと攻防の行方

9:10〜
  • 翻訳を挟む・書き直すなどの回避が考えられる
  • コピーしても印は消えず一緒に運ばれる（Claude談）
  • 他サービスを挟めば別のウォーターマークが上書きされうる
  • 検出API提供後は試行錯誤の攻防が始まる（出演者の見立て）
印を消したい 翻訳・書き直し 攻防へ
すべての生成AIがこれを導入したら、変換で回避する意味もなくなるかも。

⑰ 松浦さんのnote告白

11:00〜
  • 松浦さんのnoteはバズり続けていた人気記事
  • ある時「AIで書きました」と告白
  • 出演者は告白まで人間が書いたと思って楽しんでいた
  • 聞いても「でも楽しかったからいい」——内容重視への変化
人気note AI執筆の告白 それでも読む
検出APIが出たら引っかかっちゃうんだよね——それでも読んじゃうんだよ。

⑱ 意識の変化: ボカロの類例

13:30〜
  • かつてボカロ曲に強い抵抗感があった時代も
  • ボカロ全盛期には「人が歌うのが恥ずかしい」という意識調査も
  • いまではAI作曲の曲も普通に受け入れられている
  • AI製コンテンツへの抵抗感は薄れつつある——番組のまとめ
抵抗感 慣れ 内容が良ければ良い
ボカロで嫌だった世代が今は懐かしむ——AIコンテンツも同じ道をたどるかも。
