① 今回のテーマ: Cloudflare OSを触る

序盤
  • Cloudflareが社内で使っていたAI作業環境「Cloudflare OS」が公開
  • 出演者が実際にデプロイして触ってみた検証回
  • 京都・鎌倉拠点の開発チームがエンジニア目線でぶっちゃけ
  • 良い点だけでなくできないことも正直に紹介
公開 デプロイ検証 正直な感想
話題になっているけど中身を知らない人向けに、実際の画面を見せながら解説する回だよ。

② Cloudflare OSとは何か

序盤
  • 社内の知識と業務システムに接続したAIの作業環境（Cloudflare談）
  • 会社向け・社内向けのAI環境を整える位置づけ
  • 調査・仕様作成・アプリ開発・業務自動化を一気通貫で実行
  • 公開直後から話題になっている新プロダクト
社内知識 AI作業環境 業務を一気通貫
スライドを読むだけでは分からないから、実際の画面で確認していこう、という流れ。

③ 画面はチャットUI＋サイドバー

序盤
  • 画面はChatGPTやClaudeと同じチャット形式
  • 左側にさまざまな機能が並ぶ構成
  • ちょっとしたウェブアプリを簡単に作れるようになった
  • 作ったものを社内のみんなとすぐ共有できる点が注目ポイント
チャットで作る アプリ化 社内共有
見た目はいつものチャット画面——でも左サイドバーに秘密があるんだ。

④ デモ: チャットで日報アプリを作る

序盤
  • 「日報を貯めていけるアプリを作って」と指示するだけ
  • ちょっとAIっぽい見た目だけどその場でアプリが完成
  • HTMLだけならClaudeでも作れる
  • 違うのはデータがちゃんと溜まって共有できるところ——Cloudflareの強み
一言指示 アプリ生成 データ蓄積まで
派手に日報投稿したらすごい演出を入れて、と頼んだらド派手なモーションまで付けてくれたよ。

⑤ 作ったものはアウトプットに蓄積

序盤
  • イメージ画像の追加や投稿演出も指示で反映
  • チャットで作ったものが自動的に「アウトプット」に溜まっていく
  • 後から一覧で見返せる
  • 一覧のものを他の人に共有することも可能
チャットで作成 アウトプットに自動蓄積 共有して活用
作ったアプリがどんどん棚に並んでいくイメージ——それがそのまま社内の資産になる。

⑥ スプレッドシートも最初から

中盤
  • Googleスプレッドシート的な画面がデフォルトで内蔵
  • 実例: キオクシア株価を毎日17時に更新保存するよう指示
  • チャートもHTMLで自動生成してくれる
  • 指示した通りにシートと図ができ上がる
指示 シート自動構築 チャートまで生成
株価を毎日決まった時間に記録してチャートにまとめて——全部勝手にやってくれるんだ。

⑦ 定期実行もプロンプトで設定

中盤
  • スケジュール機能が最初から内蔵
  • スケジュール一覧に「キオクシア株価 毎日更新」が登録済み
  • アプリを作る時の指示に含めるだけで自動で定期実行に登録
  • 管理画面を触らずプロンプトだけで運用が組める
作成時に指示 自動スケジュール登録 毎日自動実行
毎日17時に更新して、という一言がそのまま定期実行になる——地味にすごい便利。

⑧ スライド作成も違和感ゼロ

中盤
  • ビジネス活用の中心はスライド作成
  • スライドをめくる機能も標準搭載
  • この動画冒頭の共有スライド自体もCloudflare OS製
  • スプレッドシート・スライドが最初から入り、ビジネス側もとっつきやすい
標準機能 違和感なく利用 ビジネス導入も容易
実はこの回で見せていた資料もCloudflare OSで作ったものだったんだ。

⑨ 本格利用の壁: ソースからデプロイ

中盤
  • Googleドライブ・Notion・Slackとの接続は可能——それが売り
  • ただしGitHubからソースを取得し設定してデプロイが必要
  • ワンクリックデプロイ環境では接続不可
  • MCP接続も（出演者の見立てでは）できない
ワンクリック利用 社内知識接続には ソースからの構築が必須
使い倒したい人は、ちゃんとソースを落として接続設定してデプロイしよう。

⑩ スキル作成と共有

中盤
  • Cloudflare OS上でスキルを作れる
  • 作ったスキルをみんなで共有できる
  • 「スキルの共有方法に困っていた」人が意外と多い（出演者）
  • そのあたりが全部入りなのはありがたい（出演者の感想）
スキル作成 社内で共有 全員の資産に
自分だけの便利スキルを、そのまま隣の人に渡せる——これが意外と嬉しい。

⑪ 限界: 投稿者の自動紐付け不可

中盤
  • 日報アプリの投稿者欄は手入力のまま
  • ログイン情報とアプリを紐付けられない
  • アプリ（ガジェット）単位での利用者識別は現状不可
  • 今のところはHTML＋小さなDB付きウェブアプリの共有が限界
ログインしていても 投稿者は手入力 凝ったことは難しい
ログインしている人の情報が自動で入ったら嬉しいのに、という正直な要望も出た回。

⑫ VM実行は不可——開発者目線の物足りなさ

中盤
  • 裏でバーチャルマシンを動かす使い方はできない
  • ソースコードを渡して実行・スクリーンショット取得のような依頼は不可
  • そういう機能はありません、と（画面上で）怒られる
  • Claude Code的な使い方は若干難しい（出演者）
VMで動かす 対応外 開発者には物足りない
マシンそのものを動かしてややこしい仕事をさせる、という使い方は今はまだ無理なんだ。

⑬ あえての疑問: ClaudeやChatGPTと何が違う？

終盤
  • アプリ作成機能自体はClaudeにもChatGPTにもある
  • 画期的なのは社内データ・ドメイン知識を引き出すビューアーやスライドを
  • 1つの社内環境でまとめてできること（出演者）
  • 各自がバラバラのツールでやっていたことを社内に集約
各自のツール 社内の統一環境 ドメイン知識を活用
ざっと聞くと「それClaudeでもできるよね？」——でも決め手は社内知識との接続なんだ。

⑭ 目玉機能: チャット履歴ごと共有

終盤
  • アプリ一覧からポチっとすると作成時のチャットがそのまま出る
  • どういうものができるか分かるし、そこから変更もできる
  • チャット自体がコンテキスト（文脈）になっている
  • もらった人が作った意図を理解できるのが新しい
アプリを共有 チャットも一緒に 意図まで伝わる
アプリだけじゃなくて、生まれた経緯ごと渡せる——これが一番の驚きだった。

⑮ 続けて打てばアプリが育つ

終盤
  • 「私はこう使いたい」をチャットで続けて打つだけ
  • どんどん指示を足せばアプリが変わっていく
  • 今まではコードが資産だった
  • これからはチャットの方がコード（＝仕様書）になる（出演者の洞察）
もらったチャット 自分の要望を追記 アプリが進化
チャットの履歴こそ仕様書——コードを読まなくても、意図がそのまま残る時代が来る。

⑯ オレオレアプリの属人化を解く

終盤
  • みんながアプリを作るほど「隣の人のコードは読めない」問題が起きる
  • オレオレアプリはそれぞれのマシンに散らばる
  • チャットごと渡せば作った資産の使い回しが格段に容易に
  • これがタイトルの属人化の解決につながる（出演者）
個人のアプリ チャット付きで共有 使い回し容易に
相手の作った資産を、コードを読まずに活かせる——これが大きな違い。

⑰ 設計思想への評価とビジネス

結末
  • 自分で使うより設計思想がすごく面白いプロダクト（出演者）
  • 構築はIT系でない人には若干つまずく
  • 「構築だけ代行」もコンサル商売としてありえる
  • そういう役割の人が出てくるんじゃないか（出演者の予測）
面白い設計 構築の壁 代行ビジネス成立
使う側より仕組みに惚れた——そして構築の壁自体が仕事になる、という面白い着地。

⑱ まとめ: コンテキストが仕様書になる時代

結末
  • 「スライド探して意図を確認」の文化がチャット参照に変わる
  • チャットのやり取りこそ今後重要に（出演者）
  • 今後参考にしていきたい設計思想
  • チャットのコンテキストをみんなが見られることの意味は大きい
コード資産 チャット資産 みんなで文脈共有
コードではなく、チャットのコンテキストが仕様書になる時代が見えてきた——番組の結論。
