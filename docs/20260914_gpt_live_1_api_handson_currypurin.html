GPT-Live-1 とは？

  • OpenAI が API で提供する、音声で話すモデル
  • ChatGPT で実装された自然な会話を、開発する側が自分のアプリに組み込める
  • モデルID: gpt-live-1
  • 提供は v1/live/sessions から
ChatGPT の「お話しできる感じ」を、そのままアプリに持ってこられる！

フルデュプレックス（全二重）

  • 話しながら聞ける（同時に双方向）
  • ユーザーの発話をさえぎって返せる
  • 相槌（バックチャンネル）も打てる
  • 停留（ホールド）や割り込みを自然に処理
「話す→待つ→聞く」の順番待ちが不要。人と話すのとおなじ感覚！

Realtime API との違い

Realtime APIGPT-Live
1つのモデルで全部を担当会話とバックエンドを分離
モデルはひとまとめ音声モデルと頭脳を別々に選べる
設計も一体会話の質と業務を個別に最適化
  • 「分ける」のが設計のキモ
ひとりの万能選手より、二人のプロのほうが強い場面も多い！

2つの部分構造

  • GPT-Live（会話担当）: 聞く・話す・いつバックエンドへ頼むか判断
  • バックエンド（タスク担当）: 推論・ツールの実行・業務ルール
  • それぞれ独立に選べるのが新しい
「受付の人」と「裏方の専門家」の二人組だと思えば OK！

Delegation（委譲）の2方式

  • Responses delegation: マネージドなバックエンド
  • Client delegation: アプリ側でバックエンドを実行
  • モードはセッション作成時に選ぶ
  • 変更には新セッションが必要
どちらに任せるかは、アプリのつくり次第でえらぼう！

Responses delegation

  • マネージドなバックエンド方式
  • GPT-Live が設定済みの Responses モデルを呼ぶ
  • まず試すなら手軽なのはこちら
おまかせで動くので、最初の一歩に最適！

Client delegation

  • アプリ側でバックエンドを実行
  • コンテキストと結果の制御を自分で持ちたい場合に
  • 業務ロジックが複雑なときに向く
じぶんで制御したい派はこちら！細かい要件にも耐えられる。

接続まわりは4種類

  • WebRTC: ブラウザの音声アプリ
  • WebSockets: サーバーでの音声の統合
  • サーバーサイドコントロール: 既存セッションへのサイドバンド接続
  • Telephony / SIP: 電話との統合
使う場面でえらべるのが強み。まずは WebRTC が定番！

WebRTC 接続

  • ブラウザで動く音声アプリに最適
  • 通信は メディアトラック ＋ データチャネル
  • 公式のクイックスタートが用意されている
browser ──(WebRTC)──▶ GPT-Live
  ・media track  : 音声のやりとり
  ・data channel : イベントと制御
はじめて試すなら、まずはここから！

WebSockets ＆ サイドバンド

  • WebSockets: サーバーでの音声の統合に使う
  • サーバーサイドコントロール: 動いているセッションへ横から接続
  • 音声の経路と制御の経路を分けられる
エージェントの操作と音声を別ルートに分けたいときに便利！

Telephony / SIP ＆ パートナー

  • Telephony / SIP: 電話網との統合
  • パートナー統合: LiveKit Twilio Telnyx Daily / Pipecat
  • 既存の電話フローに AI を組み込める
電話対応の自動化とも相性◎

対応エンドポイント

  • 使えるのは v1/live/sessions のみ
  • Chat Completions では使えない
  • Realtime API でも使えない
  • ストリーミング ○ ／ function calling ○
  • structured outputs × ／ fine-tuning ×
POST /v1/live/sessions   ✅ 対応
POST /v1/chat/completions ❌ 非対応
     /v1/realtime         ❌ 非対応
「live/sessions へどうぞ」以外は動かない、と覚えよう！

プロンプトの作り方

  • ライブモデルのコンテキスト窓は小さい
  • 会話スタイル（役割・口調・ペース）を簡潔に書く
  • 委譲の条件だけを書く
  • 業務フローの詳細はバックエンドのプロンプトへ置く
You are [name], a calm, friendly
voice assistant for [product].
Keep replies short and natural.
Delegate when the user asks to
book, check, or buy something.
役割の分担をはっきり書くのがコツ！長い手順書は裏方へ。

3つのポリシーラベル

  • Backchannel policy: 相槌の程度を調整
  • Interruption policy: 割り込み時には停止して聞く
  • Delegation policy: Backend tools ／ Delegate when ／ Do not delegate when
「いつ任せるか」をラベルで指定できるのが便利！

割り込みとタスクの状態

  • 発話の停止は、バックエンドの作業を自動でキャンセルしない
  • 「話すのをやめて」と「予約をキャンセルして」は別の指示
  • 権限・確認・タスクの状態はアプリ側で管理
「やめる」と「取り消す」は別物。ここ、設計の落とし穴！

はじめ方（クイックスタート）

  • まずは GPT-Live WebRTC のクイックスタートから
  • 必要なもの: マイク／HTTPS で配信されるページ／APIキーを持つ信頼できるサーバー
  • APIキーは必ずサーバーに置く
  • session.started を待ってから会話を開始
  • 終了時はセッションを閉じて、利用の統計を取得
1. POST /v1/live/sessions  (server)
2. wait: session.started
3. talk via WebRTC
4. close session -> usage stats
鍵はサーバーに！ブラウザへの直置きは絶対NG。
