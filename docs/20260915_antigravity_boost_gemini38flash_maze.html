今回の主題

  • Google Antigravity に新ワークフロー /boost が登場
  • 組み合わせるのは Gemini 3.8 Flash
  • 発想: Flash選択のまま、難所だけより深い調査を依頼できる
  • 題材は実際に遊べる迷路ゲームの構築
軽いモデルのまま「ここだけ深入り」できるのが面白い！

まず用語整理

  • Gemini 3.8 Flash ＝ モデル（9月上旬に Antigravity へ）
  • Boost ＝ スラッシュコマンドで頼むワークフロー
  • 手順: プロンプト欄の下でモデル選択 → /boost で開始して課題を記述
モデルとワークフローは別物。混同注意！

Boost の中身（公式資料より）

  • まず戦略を策定
  • 実装・調査などの集中的ジョブをサブエージェントへ送る
  • 各ワーカーが結果をセルフチェック
  • 調整エージェントが統合しさらなる検証
  • 想定用途: 難しいバグ・アルゴリズム・複雑なリファクタ
「策定→分担→検証→統合」のマルチエージェントフロー！

料金まわり

  • 公式ドキュメント上、Boostは有料プランが必要
  • API参考値: 入力 $0.75/100万トークン・出力 $3.75/100万（〜2026年末の導入価格）
  • Antigravity 内ではプラン・残クォータ・クレジット設定次第
  • トークン単価が安くても総コストは作業量で決まる
「安い」は入出力単価の話。プロジェクト総額は別！

なぜ迷路ゲームか

  • 要件: 手続き生成＋編集可能な盤面
  • 鍵を取らないと開かない出口＋アニメーションソルバー
  • 壊れやすい要素が多く良いテストになる
  • 出来栄えを実際に遊んで確認できる
「それっぽいデモ」が崩れる境界条件を狙う選択！

完成物: Maze Atelier

  • アイソメトリックの盤面・暗い壁・プレイヤー・鍵・出口ポータル
  • 3サイズの迷路＋シード値で同じ迷路を再現
  • シードがあると再現可能なテスト例を持てる
  • 素の HTML / CSS / JS / Canvas のみ・外部依存ゼロ
  • APIキー不要で遊べる
シード42のイージー迷路が動画のデモ例！

ゲームの仕様

  • ルートは鍵の回収を考慮して出口へ導く
  • ガイドパスボタンでルートをトグル表示（自分で操作）
  • 壁エディタで通路を塞ぐと「blocked / 解不可」に変化
  • アニメーション途中でリスタートすると旧ソルバー停止が必要
  • ブラウザテストで 40手でクリアを確認
「動く」ではなく「境界条件まで正しい」を狙った設計！

独立レビューで見つかったバグ

  • 迷路を新規生成するとイベント購読が脱落し UI が更新されない
  • エンジンを直接呼ぶと壁を抜ける大ジャンプが可能な移動検証の欠陥
  • どちらも「もっともらしい出来」の裏に隠れた問題
エージェントの言う「動きます」を鵜呑みにしない！

修正と回帰テスト

  • 発見事項を Antigravity へ送り返すとエンジンを修正
  • 両ケースの回帰テストを追加
  • 最終スイートは全7テストに合格
  • 内容: 100迷路の一括生成・衝突判定・鍵必須・編集盤面・ソルバー初期化
  • 別レビューでは3サイズ計600迷路を生成して全て解決・プレイ成功
バグ発見→修正→回帰テストのループが回るのがBoostの真価！

人の手による仕上げ

  • 盤面サイズの調整をAntigravity の外で実施
  • パス表示は要求時まで非表示になるよう切替を変更
  • 提示物はビルド＆レビュー済みの結果
  • ブラウザでシード・難易度・衝突・リプレイを直接確認
最後の微調整は人間の仕事。エージェントと分業！

依頼の心得（他案件にも通用）

  • エージェントには具体的な成果物と「動く」の定義を渡す
  • 予約画面なら枠が取れた時の挙動を記述
  • データ取り込みなら空ファイル・壊れた行を含める
  • 検証対象を明示し、結果は自分の目で確認
失敗ケースまで書くのが、AI依頼のプロの型！

利用量の注意

  • 公式Doc: クォータは実行された作業量に依存
  • クレジット超過は設定次第
  • 大規模実行の前に設定を確認すべき
  • Boostの固定コスト倍率は未計測（このデモでは確立せず）
断定を避けて誠実に記録するのがこのチャンネルの流儀！

Gemini 3.8 Flash の特徴

  • 調整可能な推論努力度（reasoning effort）
  • 高努力度では難課題に多くのトークンを投入
  • 今回のモデル選択は Flash (medium)
  • エージェント開発の向上をGoogleが謳う改良版
「考え方の深さ」を dial で調整できる世代のモデル！

検証の限界（誠実な注意点）

  • そのため結果を専用パイプラインと断定できない

都合の良い解釈をしない。この姿勢が評価される理由！
