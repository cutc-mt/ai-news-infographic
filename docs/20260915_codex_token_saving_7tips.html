この回だけで完結する「保存版」の節約チェックリスト！

用語① トークン

  • トークンとは AIが理解している単語の数
  • 目安: 英語で1単語 ≈ 1〜1.3トークン
  • 切り方には色々な手法があり日本語は変な切り方になりがち
  • 単語数とトークン数はほぼ相関関係にある
  • 利用枠はこのトークン数で決まる
「AIの言葉の数え方」これがすべての大前提！

用語② コンテキストウィンドウ

  • コンテキストウィンドウとは AIの作業机
  • これが埋まると性能低下＋トークンを余計に消費
  • デフォルトは 20万トークン
  • Codexは設定変更で約100万トークンまで拡張可
  • 「利用枠（残り回数）」とは別物と理解する
机が散らかると作業も遅くなる。AIも同じ！

用語③ キャッシュ（会話履歴）

  • 会話のたびに過去のやり取りが1, 2, 3…と全部溜まる
  • 毎回最初から会話を送り直しているのがポイント
  • 無駄な部分は定期的に圧縮（コンパクト）しよう
  • 目安: 50〜80% になったら1回縮めるのもあり
  • 直近5回分だけでなく過去4回分も読み込むので注意
机がパンパンになったら、こまめに圧縮が鉄則！

節約① モデルを下げる

  • これがすべて：GPT-6はどう工夫しても使用料を食う
  • 普段は5.6 / 6-Terraなど下位モデルで十分
  • 画面でモデルを選んで簡単に切り替え可能
  • ブラウザ操作などGPT-6が輝く場面は最大モデルを惜しまず
  • Fast（高速）モードは減りが早いので急ぎ以外はオフ
「最強」はここぞの時だけ。早期は下位モデル！

節約② どこで開くか

  • ローカル起動時、開いたフォルダより上を全部読む
  • 読まれるのは AGENTS.md / CLAUDE.md などの指示ファイル
  • 例: 3階層目で開くと1・2階層目のMDも全部読む
  • 100階層目で開いたら99個のMDを読むカオスに
起動場所ひとつで、読み込む量が変わる！

節約③ フォルダ階層を整える

  • フォルダ階層の設計が節約の土台
  • 深い階層にMDを大量に置かない設計を心がける
  • 詳細は環境構築講座シリーズ（別動画）で解説
「開く場所」は設計できる。だから階層整理が効く！

節約④ MDを短く

  • CLAUDE.md等は毎回開くものなので短く
  • 目安は 200行以内
  • 条件分岐は別ファイル（ルール）へ退避
  • 実測: ルールが重すぎて起動だけで作業机の20%が埋まっていた
何も作業する前から机の2割が埋まるのはもったいない！

節約⑤ サブエージェントを切る

  • サブエージェントは性能が高いがやりすぎるとトークンを食う
  • 依頼文の頭に1行: 「今回はサブエージェントを使わず、あなた1人で進めてください」
  • X等で「オフにしたら節約できた」報告も多数
  • 動画内でいちばん効いた施策
複数エージェントの並列リサーチは便利でもコスト要チェック！

節約⑥ 範囲と終わりを決める

  • 「幅広く検索しろ」は大量のフォルダを読む結果に
  • 「このファイルとこのテストだけ」等具体的に指示
  • 例: 「修正と関連テストまで。追加改善は提案だけ」
  • エラーが2回続いたら繰り返さず原因整理を指示（ループ防止）
  • 動画の依頼文テンプレは概要欄から無料配布
ゴールを決めないと、エージェントはぐるぐる回り続ける！

節約⑦ セッションを分ける

  • プロジェクト・タスクごとにセッションを分ける
  • 例: 開発／事前調査／マーケ系／コードレビューで分離
  • プロジェクトの「＋」から新規セッションをどんどん追加
  • 「テスト2」等の名前を付けるとフォルダも自動分けされる
  • 1セッションに混ぜると毎回の資料量が肥大化
「1つの箱に全部詰め込まない」のがセッション管理のコツ！

「ハーネス」の視点

  • ハーネス＝AIを動かす周辺の仕組み
  • フォルダ階層やMDの内容が元から作業机・利用枠を奪う
  • 節約はモデル設定だけでなく環境設計から
  • ハーネス解説は別動画で詳説
道具（ハーネス）の設計を見直すだけで消費が変わる！
