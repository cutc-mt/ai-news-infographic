第2章: Claude Code × AGENTS.md とは何か

CHAPTER 02
④

④AGENTS.md: 「AIエージェント向けのREADME」

  • リポジトリ直下に置く指示ファイル（説明書）。コーディング規約・よく使うコマンド・レビュー観点などを書いておくと、エージェントが勝手に読んで従ってくれる
  • 特定企業の独自仕様ではなくオープンスタンダードとして設計されているのがポイント
  • README.mdが「人間のための説明書」なら、AGENTS.mdは「エージェントのための説明書」
人間の新人に引き継ぎ資料を渡すのと同じことを、AIエージェントに対してやるイメージ
⑤

⑤Claude Code対応の意味: 指示ファイルの共通化

従来ツールごとに独自ファイル（CLAUDE.md 等）を個別に用意・二重管理
これからルートの AGENTS.md を置けば、対応エージェントが同じ指示を読む
効果ツールを乗り換えても指示の書き直しが不要。管理コストが下がる
  • 他社のエージェントも相次いでAGENTS.mdを採用しており、事実上の共通規格になりつつある
  • 既存のCLAUDE.md資産がある現場も、移行・共存の道が議論されることに
「どのAIを使っても同じ説明書」が実現すると、ツール選定がより自由になる
⑥

⑥開発者への影響: 今日からできること

  • 新規プロジェクトはまずAGENTS.mdを1本用意しておくのが安心な時代に
  • 書くべき中身は変わらない: ビルドコマンド・テストの回し方・守ってほしい規約
  • チーム開発では「新メンバー用の引き継ぎ書」と兼用できるのが大きな利点
  • 配信でも「AIの勝手が良くなる半面、指示の中身を誰が責任を持つかは人間のままだ」という視点が出やすい話題
AGENTS.md作成 どのエージェントも同じ指示 ツール乗り換えコスト低下
地味に見えて効く系のニュース。現場の作業フローが静かに変わっていくタイプ

第3章: Jevでギャグを判定する

CHAPTER 03
⑦

⑦発想: 「面白いか否か」は判定問題では？

  • ギャグの成否は本質的に「決まった/滑った」の二値に近い。これは判定専用AIと相性がいい問い
  • LLMに「このギャグどう？」と聞くと長文が返ってくるが、Jevなら判定＋確率だけが即座に返る
  • 「AIにツッコミを任せられるか」というエンタメ×AIの古典的お題に、最新ツールで挑む構成
難しい判断を「確率」という数字で返してくれるのがミソ。感覚の言語化が苦手な人ほど便利
⑧

⑧Jevおさらい: 判定専用AIの基本

Bool是か非かを確率付きで返す。ギャグ判定はまずこの型
Choice複数の選択肢からどれかに振り分ける（ルーター向き）
Score度合いを段階で測る（センサー的な使い方）
  • 大きな特徴は文章を返さないこと。判定と確率だけを高速に返す
  • コストが安く応答が速いので、仕掛けとして大量に積めるのが強みとされる
「汎用LLMの一部を、高速・安価・高精度に切り出した」存在だと捉えると分かりやすい
⑨

⑨実演: ギャグのオチをAIに裁いてもらう

  • 用意したギャグ（オチ）を入力として渡し、「面白い」側の確率がどう出るかを確認していくスタイル
  • 閾値（しきい値）の設定次第で「採用/ボツ」のラインが変わる、という判定システムの面白さが見える
  • 文章での講釈なしで即座に判定が返るので、ライブのリアクション装置として丁度いい
  • 一方で「面白さの基準」を誰が決めるかは別問題。判定はAI・最終責任は人間という構図は変わらない
ギャグを入力 Jevが即座に判定＋確率 閾値で採用/ボツを決める
遊びに見えて、これは「審査・選別」の仕事をAIに任せる練習そのもの
