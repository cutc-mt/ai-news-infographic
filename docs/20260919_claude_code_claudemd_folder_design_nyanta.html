導入: なぜCLAUDE.mdを「設計」するのか

INTRO
01

①開発以外の業務こそCLAUDE.md設計が効く

Claude CodeChatGPT Work日常業務
  • 開発の仕事以外でClaude Codeを使う人が増加中。メール返信・資料作成など業務活用の際、CLAUDE.mdをどう書いて配置するかが分岐点
  • ちゃんと設計しておくと必要な情報を必要なタイミングで渡すという状態が実現できる
  • 「CLAUDE.mdってあんまり考えてなかった」という人も多数——ここを仕組みで理解するのが本動画の目的
  • 仕事で使う上での注意点に加え、ちょっとした罠も存在するので誰でも分かるよう解説
CLAUDE.mdとは何か？→配置→罠→実践まで、この1枚で全体像をつかむ！
02

②複数案件・複数顧客の駆け持ちリアル

  • Claude CodeやChatGPT Workのようなエージェントツールを使う時、どうフォルダを作って起動するか？——いろんな考え方がある
  • 1つのプロジェクトだけではなく複数プロジェクトの駆け持ちや、複数の顧客への資料作成・メール返信という使い方が一般的
  • 著者の答え：1つのフォルダを起点にいろんな仕事の文脈を溜める運用に集約
  • 横断活用の例: プロジェクトAの料金見積もりを参考にBの見積もりを作らせる／Aで作った成果物をBのメール文面に参照・カスタマイズ
発想が逆転する：人間がAIに情報を渡す→AIが私の情報を読んでくれる構造になる！

ワークスペース集約戦略とその副作用

STEP 1
03

③「マイワークスペース」1点集中運用

  • VSCodeでPC上のMyWorkspaceフォルダを開き、Claude Code／ChatGPT Workをここを起点に起動して仕事する
  • 中身はメールの情報日記YouTubeの撮影動画など仕事の文脈を全部投入
  • 論文を読む時もこのフォルダに入れて読むルールで統一
  • クロードデスクトップでMyWorkspaceをフォルダ設定すれば、会話するとこのフォルダの情報を参照して返答してくれる
# MyWorkspace 集約イメージ
MyWorkspace/
 ├─ mail/      # メール情報
 ├─ diary/     # 日記
 ├─ youtube/   # 撮影動画
 └─ papers/    # 論文
自分専用フォルダを作ってない人こそ、まず一度作ってみてほしい！
04

④スキル発動デモ: YouTubeチャンネル分析

  • 「先週の動画分析してみて、どんな感じだった?」と適当に質問するだけ
  • YouTube MyChannelスキルが発動して、前回動画の状況を自動で教えてくれる
  • 毎日ルーティンで再生数をカウントしているので初動分析がすぐ出る——初動が良いと判断しやすい
  • 実話: 最近はYouTubeの再生数の数え方が変わって分析が難しくなった、という状況も解説
  • この情報をもとに新企画の立案や、興味がありそうなニュース収集も依頼可能
仕事の文脈を集めておくと、分析→企画まで一気通貫で頼れる！
05

⑤ファイルが増えると起こる3つの問題

集約の副作用——「どこに何があるか」破綻

  • どのファイルに何が書いてあるか分からなくなる。Claude Codeから見ても「どのフォルダを見て、どう作業すべきか」がファイル数に比例して難しくなる
  • Aの案件を聞いたのにBの情報を持ってくる／意図してないデータを読んで返答を生成する
  • データを探しに行くだけで時間とトークンが消費されて使いにくい
  • 解決の鍵がCLAUDE.md——書いておけば迷わず必要なデータを読んで作業できる状態にできる
集約と案内はセット！ここから先はCLAUDE.mdの仕組みの話。

CLAUDE.mdの基礎と読み込み仕組み

STEP 2
06

⑥CLAUDE.md=毎回自動入力されるプロンプト

  • Markdown記法で書かれたテキストファイル。初めて聞いた人も多いファイル
  • Claude Codeの起動場所と同じところに置いておけば自動的に読まれる
  • 例: 「語尾に『にゃ』をつけて」と書いておくと、毎回の会話に反映されて返答の語尾が「にゃ」になる
  • 正体は毎回立ち上げ時に自動で入力されるプロンプトのファイルと理解するのが吉
  • 作業フォルダを作って仕事するなら、同じフォルダに配置して事前に知っておいてほしい前提を書いておくと便利
CLAUDE.md
- 語尾に「にゃ」をつけて
- 返答は日本語で簡潔に
「にゃ」の例えだけでなく、業務前提こそ書くべき中身——続きは設計の章で！
07

⑦階層配置と読み込みタイミングの違い

MyWorkspace/CLAUDE.md clients/CLAUDE.md A社/B社/C社 CLAUDE.md
  • 起動フォルダ（ルート）のCLAUDE.md→起動した瞬間に読み込まれる
  • サブディレクトリのCLAUDE.md→起動時点では未読。同じ階層のファイルをClaude Codeが読んだ時や、さらに深いサブディレクトリを読んだ時に読み込まれる
  • 仕組み: clients/内の何かしらのファイルをReadツールで読んだタイミングで、同階層のCLAUDE.mdが入力に挿入される
  • 深い階層（A社など）を読む時は上位階層のCLAUDE.mdも一緒に入力される——やや複雑だが階層が積み上がる構造
MyWorkspace/
 ├─ CLAUDE.md      # 起動瞬間に読込
 └─ clients/
     ├─ CLAUDE.md  # 同階層ファイル読込時に読込
     ├─ A社/  └─ CLAUDE.md
     ├─ B社/  └─ CLAUDE.md
     └─ C社/  └─ CLAUDE.md
ポイントは「ルート=即時、サブ=ファイル読込の連鎖で後から」の2段階！
08

⑧Autoモードの罠——bash優先で読まれない

  • Autoモードとは、ファイル変更の許可をいちいち聞かず、Claudeが問題ないと判定したら自動でコマンド実行するモード。利用者も多い
  • 罠: Autoモードではファイルを読む時、内蔵ReadツールではなくBashコマンドで読むようプロンプトが設定されているっぽい
  • 結果: サブディレクトリのCLAUDE.mdが読まれていない事象が発生。使い込むと必ずぶつかる細かいポイント
  • 対策: CLAUDE.mdに「ファイルを読む時はReadツールを使う」と指示しておく。いずれ修正されるかもしれないが現状は書いておくのが安全
CLAUDE.md への追記例
- ファイルを読む際は bash ではなく
  Readツール を使ってください
「サブのCLAUDE.md読んでくれないな？」と思ったら、まずこの罠を疑え！

顧客別の階層設計とルートの役割

STEP 3
09

⑨顧客別階層設計——共通と個別の使い分け

  • 構成: MyWorkspace（ルート）› clients/› A社・B社・C社の各フォルダで状況を管理
  • clients/CLAUDE.mdには顧客共通のルール（A社B社C社ぜんぶに関わる前提）を記述
  • 各社フォルダのCLAUDE.mdにはその会社特有の守ってほしい事情を記述
  • この性質の活かし方: 特定の仕事をする時だけ読んでほしい前提を、そのフォルダのCLAUDE.mdとして置いておく
  • →「必要な時に必要の情報だけ」を渡す運用が階層だけで実現できる
階層=読み込みタイミングの制御装置。置き場所で「いつ効くか」が決まる！
10

⑩ルートに全部書くと「太る」問題

  • 対案: ルートのCLAUDE.mdに「A社はこう・B社はこう・C社はこう」と全部書く運用も当然可能
  • 扱うファイルが少ないうちは、それでも問題ない
  • しかし仕事が増えると毎回入力されるCLAUDE.mdがどんどん肥大化していく
  • 悪影響1: 毎回読み込まれるのでトークンがもったいない
  • 悪影響2: 指示が多すぎてうまく動かない事態が予想される
  • 結論: ルートに全部書かず、前提はそれぞれの作業フォルダ内のCLAUDE.mdへ分散させるのがおすすめ
毎回読まれるルートは「コンパクト」に。太ったら分割のサイン！
11

⑪ルートCLAUDE.mdは「フォルダの地図」にする

  • 著者の意見: ルートのCLAUDE.mdにはこの作業フォルダーの地図を書くのがベスト
  • どのフォルダにどういったファイルがあるかを簡潔に記述する
  • これでClaude Codeがユーザーの入力からどのファイルを探せばいいかを判断できる
  • 加えてAutoモード対策の「Readツールを使う」指示も書いておく（カード⑧の罠対策）
ルートCLAUDE.md（地図）の例
- 顧客情報は clients/ 配下
- 顧客一覧は clients/INDEX.md を最初に読む
- 進捗は各社の PROFILE.md に記載
- ファイルを読む時はReadツールを使う
サムネイルの「Claude君が地図を持って課題を解決」イメージはまさにこれ！

スキルも同じ階層仕様

STEP 4
12

⑫「スキルが効かない」相談の原因は階層

  • ルートの .claude/skillsにスキルを定義→ルートで起動した瞬間に自動で使える
  • サブディレクトリ内にスキルを作った場合→そのフォルダの中のファイルを読むまではスキルが有効化されない
  • 実際の相談: 顧客ごとにフォルダを切り、CLAUDE.mdやスキルを配置して運用している人が「ルールを守ってくれない」と相談してきた
  • 原因は読み込み仕組み——フォルダ構造を見直せば解決することが多い。スキルが読み込まれない時も同じ発想で見直そう
MyWorkspace/
 └─ .claude/
     └─ skills/      # ルート直下なら起動時から有効
 └─ clients/
     └─ A社/.claude/skills/  # ファイル読込後に有効
CLAUDE.mdもスキルも「どこに置くか」で効き方が変わる、同じ仕組み！

実践: 顧客別Workspaceの構成とデモ

STEP 5
13

⑬実践フォルダ構成例（デモ2社）

  • PC内にworkspace/を1個作成。その中にclients/（顧客ごとの進捗状況管理）とCLAUDE.mdを配置
  • デモの架空2社: 空豆デザイン（代表・佐藤さん）ともう1社の2社。それぞれ定例を行っており、その情報を各フォルダに格納
  • clients/CLAUDE.mdにはお客さんに対する共通の前提を記述。顧客ごと・プロジェクトごとの資料管理もこの形で整理
workspace/
 ├─ CLAUDE.md          # フォルダの地図
 └─ clients/
     ├─ CLAUDE.md      # 顧客共通の前提
     ├─ INDEX.md       # 顧客の目次
     ├─ 空豆デザイン/
     │   ├─ CLAUDE.md  # 同社のルール
     │   └─ PROFILE.md # 進捗・状況
     └─ B社/
         ├─ CLAUDE.md
         └─ PROFILE.md
自分の仕事フォルダを作る時の1つの参考例として見てみて！
14

⑭INDEX.md＋PROFILE.mdで参照先を最短化

質問「空豆デザインと の進捗は?」 INDEX.md PROFILE.md 即答
  • ワークスペース起点で起動→「空豆デザインさんとの進捗どんな感じだったっけ?」と質問するだけ
  • 動き: INDEX.md（顧客の目次）→空豆デザインのPROFILE.md（進捗状況）の2ファイルだけを読んで即座に返答生成
  • 実際のツール実行ログでも index.md と profile をReadしているのが確認できる
  • 整理されていない場合: clients/を探し回り、フォルダとファイルを順に調べて時間をロス
  • 顧客が増える・毎週の定例でファイルが溜まるほど、地図の価値が上がる設計
ルートの地図→目次→プロファイル。参照が3段階で着地する設計が高速化の鍵！
15

⑮顧客別CLAUDE.mdで文体をコントロール

同じ依頼でも、読み込む前提で出力が変わる

  • 依頼: 「今週時間があるかを聞くメールを書いて」——同じ文言を2社に出すデモ
  • B社（硬め）: 相手の会社を「星野様」と呼ぶ前提。プロファイルとCLAUDE.mdを読んで硬い文章が生成される
  • 空豆デザイン（カジュアル）: 代表は佐藤さん、会社は「空豆さん」と呼ぶ前提。「お疲れ様です」から始まる柔らかい文章に
  • 読み込まれる前提情報の違い＝Claude Codeの挙動コントロール。各社フォルダに「どういう会社か・どういう関係性か」を記録しておくだけで効く
空豆デザイン/CLAUDE.md 例
- 代表は佐藤さん
- 会社は「空豆さん」と呼ぶ
- カジュアルな文体で返答する
顧客ごとの「お作法」をファイルに書くだけで、AIが文体を使い分けてくれる！

運用ルーティンと対話ログによる改善

STEP 6
16

⑯CLAUDE.mdとPROFILE.mdの役割分担＋ルーティン

  • CLAUDE.md=あまり変わらない情報（担当者が誰か、など）
  • PROFILE.md=頻繁に変更される情報（進捗など）を格納
  • 顧客ごとにミーティングの文字起こしをアップロードしておく
  • 定期的なルーティン機能で文字起こしをPROFILE.mdへ自動反映する運用
  • プレゼン資料はv1・v2…と溜まってフォルダが汚れがち→週1回のルーティンで全フォルダを確認して整理提案してもらい、承認すると整理が完了
「変わらない前提」と「変わる状況」をファイル分け＆自動更新で新鮮に保つ！
17

⑰対話ログからClaude Codeを育てる

  • 特定フォルダで対話すると対話ログが残る（以前の「Claude Codeを育てる」動画で紹介した仕組み）
  • 運用例: フォルダ内でメール返信文を作ってもらいGmail APIで送信
  • AIの返答がいつもの自分と違う…→自分で修正して送信、を繰り返す人が多いはず
  • ログがあれば実際に送ったメールとAIの提案が比較可能な形で残る
  • 定期比較→「返信文で気をつけること」をスキルとして覚えさせる→ブラッシュアップし続けられる
作業スペース＋ログ＝AIが自分の仕事のクセを学ぶ教材になる！
