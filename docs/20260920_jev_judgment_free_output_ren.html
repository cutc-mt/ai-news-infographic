第1章 Jevの正体を知る

WHAT IS JEV ?
01

Jevとは何か

一言でいうと

  • 渡した文章や状況を読んで、先に決めた答えを確率付きで即答するAI
  • 例えるなら「書類を渡すと クレームです・確率0.9 とだけ返す仕訳」。理由は語らない
  • ChatGPTやClaudeのような文章を書くAI=LLMの仲間ではない
  • 速くて・安くて・疲れない。その代わり答えの形はこちらが先に決めておく必要がある
Xで「出力トークンは無料」の投稿を見て「チャットGPTと何が違うの?」と止まってた学長が、公式一次情報を読み込んで判明!
判断専用の新種だった——ここが出発点！

03

聞き方は3種類だけ

問いの型はこれだけ

  • 選択型: 「これはどれ?」 —— 選択肢から選ばせる
  • 採点型: 「0〜100点で何点?」
  • 確率型: 「YESの確率は?」
  • 1回の問い合わせで何問でも混ぜて投入可能。1問だけでもOK
  • 公式のおすすめ: 関連する質問は先にまとめて全部聞き、使う答えだけコードで拾う
// 問い合わせのイメージ
{
  "q1": "このメールはどれ? [お礼/クレーム/質問/その他]",
  "q2": "緊急度を0-100で採点",
  "q3": "返信不要なYES確率は?"
}
これは「賢いIF分岐」—— プログラムの決め打ちルールの代わりに、AIの判断を差し込むイメージ！
04

料金体系 — 出力は無料

公式価格の数字

  • 出力トークンは無料 —— 返すのが確率の数字だけなので量がごくわずか
  • 入力は 100万トークンあたり約0.042ドル の激安設定
  • 同じ程度の賢さのLLMより 40〜200倍速い と公式が宣言
  • 応答は 70〜500ミリ秒。一瞬で帰ってくるのが最大の売り
  • 課金はAPI従量課金のみ。月額プランは今のところ見当たらない
  • 公式は「安すぎて課金の計測ができない」と書いているほど。早期アクセスには5ドル分の無料クレジット付き
学長のアカウントも実際に5ドル分作成できた——まずは早期アクセス応募から！
05

できないこと・制約

事前に知っておく制限

  • 画像は読めない。読めるのはテキストと表・リストのような決まった構造データのみ
  • 選択肢の最大数は 255個
  • 出力がそもそも文章でないため、判断の理由文は出ない
  • 専門分野のデータでは学習していない(公式明記)。法律系などは条文などの資料を渡して選ばせる使い方に
  • 候補の文字列をクラウドへ送る前提 —— 機密データの扱いは要確認
「軽くて安い」の裏返しとして、できないことを設計段階から織り込むのがコツ！

「システム1モデル」とは

カーネマン由来の命名

  • TypeSafe AIはJevをLLMとは別種の システム1モデル と呼ぶ
  • 由来は心理学者カーネマンの名著 『ファスト&スロー』
  • システム1 = 直感でパッと答える「速い思考」→ Jevの担当領域
  • システム2 = じっくり考える「遅い思考」→ 従来LLMの担当領域
  • 公式はシステム1の「間違いやすさ」の含みを認めた上で、信頼できるものにもできると宣言
学長いわく「うちの上司はシステム1っぽい、自分はシステム2っぽい」——人間の思考区分がそのままAIの設計思想に！
07

鍛え方が根本的に違う

学習手法の違い

  • 既存LLM: AIの答え2つを人が並べて「こっちが良い」と選んだ結果を積み重ねて鍛える
  • 最近はプログラムで答え合わせを組み合わせて高速化している模様
  • Jev: 確率の正確さで鍛える —— まったく別のアプローチ
  • LLMは「人が読んで気持ちいい文章」を目指すため、ハルシネーションやお世辞が生まれがち
  • Jevは 「80%と言ったら本当に8割当たる」正直な確率 を目指す
速さの正体はここ! 確率に絞ってモデルを作ったから、3つの答え方に限定できて、超高速・超低コストになる。
08

公式ベンチマーク① 精度×費用

1枚目のグラフを読む

  • 縦軸=精度、横軸=作業あたりコスト(右ほど高い)
  • Jevは GPT Luna / Tera と同程度の精度 ながらコストが桁違いに安い
  • SonnetやOpusと比べると精度は 5〜6ポイント劣る が、費用は断然安い
  • 注意: 上限値は人間ではなく Astra / Fable 5.1 等の最強LLMを正解としたもの(LLM採点)
  • ベンチは TypeSafe AI 自身が作成 — 第三者検証はまだ少ない
「同じぐらいの精度なのにめちゃくちゃ安い」——コスト・パフォーマンスが主武器！

15

信頼度ゲーティング

Confidence Gated Routing

  • 公式ドキュメントに「分からない箱」と同じ考え方が登場 —— 確率を確信度(Confidence)と呼ぶ
  • 公式の名言: 「答えは何をするのかを教え、確信度はどう動くかを教える」
  • 公式の例: 確信度0.6未満は人に回す ルーティング
  • 低いものだけ人がカバーすればローコストと精度を両立
// Confidence Gated Routing の例
if (jev.probability >= 0.6) {
  autoSort(jev.choice);      // 自動振り分け
} else {
  humanReview(jev.choice);   // 人が確認
}
閾値は各案件の精度実測を見ながら調整——確率が付くからこそできる運用！
16

作り方と構成 — いつLLMが要る?

作る時と動く時で主役が違う

  • 作る時: ツール本体は普通のプログラム → Claude Code / Codex に書かせる
  • 動く時: プログラムが判断箇所で Jev API に状況と質問を送り答えを受け取る。会話画面は出ない
  • メール分類・ランチャーなら Jev+プログラムだけでLLM不要
  • 旅行サイト操作などの複雑タスクは LLMが計画→Jevが決める2段構成 が良い
  • 公式の振り分けパターン: 受付はJev / 定型はプログラム / 専門質問はLLM / 低確率は人
  • 公式がClaude Code用のスキル(プラグイン)も配布 — 入れるだけで学長の環境でも動作
Jevは「部品」。賢いAIの代わりではなく、プログラムの分岐点に差し込む存在！

  • ChatGPT/Codexのコンピューターユースで宿探しはトークンを食う

冷静な注意点とまとめ

盛り上がりへの対抗馬

  • 「ハルシネーションしない」= 選択肢の外に答えられないだけ。間違った選択肢を選ぶことはある。形式堅守≠正しい判断
  • 「知識を持たない」は設計思想: 資料と基準を渡して判断させる前提(法律なら条文を渡して該当判定)
  • 低コストLLMでも制約付き推論で似た高速化は可能 — コスパと精度で選定を
  • 考える時間がない分、推論が必要な仕事は賢さに上限(エンジニアブログ指摘)
  • 早期アクセスは順番待ち(実測約6.5時間)。待てない人向けに公式と同じ形式で使える Vercel AI Gateway / OpenRouter / Cloudflare Workers AI の入口も

まとめ

  • 文章・筋道は従来通りLLMへ。「どれ/何点/YES」で答えられる判断だけ切り出す、安くて速い切り出し先がJev
  • 帰ってきた確率はそのまま信頼度の目安に使える
