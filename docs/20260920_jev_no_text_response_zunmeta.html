文章を返さないAIが出てきた
Jevは代わりに何を返すのか

帰ってくるのは、判断と確率と確信度 ── 読む係が消える新しいモデル「Jev」を最初から見る

インフォグラフィック作成: 2026.09.20 ｜ チャンネル: ずんめたラボ ｜ 今知っておきたいAI

その1: 何を返すAIなのか

WHAT IT RETURNS
1

①読む係が、消えない

毎朝のメール仕分け問題

  • 問い合わせメールを毎朝1件ずつ読んで振り分ける——それだけで午前が終わるのだ
  • AIに任せたら丁寧な文章が返ってきた。でも担当を決めるのは結局ずんだもん
  • 「技術の問い合わせだと思われます」——その文面を読んで判断する仕事は人間側に残る
  • 文章が返ってくる限り、読む係は消えない——そこを変えるモデルが先日公開された
今は順番待ちだけれど、「個体（判断）そのもの」が帰ってくるのだ
2

②Jevとは何者か

作ったのは TypeSafe AI

  • 開発元はTypeSafe AIという会社。名前も会社も初めて聞いたのだ
  • 創業者はRLHFの共同発明者——InstructGPT・ChatGPTの背後の研究に関わったと本人が公式ブログに記載
  • 2年の間、表に出ずに開発し、先日に公開
  • 今は早期アクセスで順番待ちの登録から順に案内。公式への直接申込みのほか、Vercel AI Gateway経由でも呼べると自社ページに記載
今日は「何を返すのか」「どういう仕組みか」「どこまで信じていいか」の3つを見ていくわ
3

③名前の由来

Jev と System 1

  • Jevは「Jevons（ジェボンズ）」——19世紀の経済学者から取った名前
  • 効率が上がるとかえって使われる量が増える（ジェボンズのパラドックス）——安くなると使い道が増える、その期待を込めた命名
  • モデル種の名前System 1は心理学者カーネマンの「早くて直感的な思考」から
  • その名の通り考えを語らず、判断だけを返す——考え込まずパッと判断する方なのだ
4

④代わりに何が返る?

返ってくるのは「型のついた答え」

  • 文章を返さない・理由の説明もしない・コードも書かない
  • 返るのは選んだ答え＋確率＋確信度の数字セット
  • プログラムがそのまま受け取り、次の処理へ渡せる形で帰ってくる
  • 「技術って書いてあるな」と読み取る仕事がなくなる——読む係が消えるのはずんだもんには大きいのだ
「請求・技術・解約のどれか」と聞けば、返るのはその3つのどれか。勝手に『その他』とは答えないのよ

その2: どういう仕組みなのか

HOW IT WORKS
5

⑤なぜ速いのか

全部の答えを一回で出す

  • 普通のAIは一文字ずつ、直前の結果を見ながら書いていく——だから長いほど待たされるのだ
  • Jevは全部の答えを1回でまとめて出すと公式が記載（並列サンプラー）
  • 項目を3つ→5つに増やしても待ち時間はほとんど変わらない——担当も緊急度も一度に聞ける、仕分けに向いている
材料（state） 型付き質問 答え＋確率＋確信度
質問を増やしても待ち時間はほぼ不変——ただし増やした分の入力料金はかかるわよ
6

⑥なぜ形が崩れないのか

答えの形を先に決めている

  • 選択肢や数値の範囲を、聞く前に渡す——その外の形は原理的に出てこない
  • 選択肢は最大255個まで
  • 公式はここで「ハルシネーションはゼロ」と記載——ハルシネーションとは、ないことあるみたいに自信たっぷりに書いてしまう最もらしい嘘なのだ
  • 入力は文字だけ。画像・音声・動画はまだ受け付けず、自分のデータでの追加学習の手段も公式説明書には出てこない
  • 調整するのは渡す材料・質問の書き方・判定の基準——そこで合わせる作りよ
7

⑦訓練のしかた: RLCD

何を「よし」とするかの違い

  • RLHF: 人が好む答えをよしとする——InstructGPTとChatGPTの仕上げに使われてきた手法
  • RLVR: 機械的に答え合わせできる正解のある問題に寄せる
  • RLCD「較正された判断のための強化学習」: 確率が実際の当たり具合と合っていることをよしとする——0.8と言ったものが大体8割当たるようにする
  • 公式はRLHFの副作用も自分で挙げている——媚びた答え・自信ありげな作り話・答えの幅が狭くなる
RLHFの共同発明者が、このJevを作っている会社の創業者——つながりのある話なのだ
8

⑧中身は、ほとんど見せていない

出ているのは3つの言葉だけ

  • 公式が出しているのは「新しいアーキテクチャ」「並列サンプラー」「RLCD」の3つだけ
  • パラメータ数も元のモデルも学習データも論文も出ていない——新しい仕組みだとは言っているけれど中身は見せていないのだ
  • 順番待ちが当日通った例が報告されているが、これは1人の例
  • ずんだもんもまだ実際には動かしていない——公式が書いていることまでで、使った感想は言えない。そこは正直に

その3: 聞き方は3種類 ＋ 確信度

HOW TO ASK
9

⑨聞き方① Choice

決まった選択肢から1つ選ばせる

  • 材料にメール本文を置き、選択肢の名前と説明を組にして渡す——「請求はこういう話、技術はこういう話」と説明を添える
  • 公式が進めるのは「その他」の選択肢も入れておくこと——どれにも当てはまらないものが来た時、モデルがそう言えるようになる
  • 帰ってくるのは選ばれた1つ＋選択の確率＋確信度——確率は全部足すと1になる（技術0.7・請求0.2・解約0.1 など）
  • 説明は文章だけでなく「含むもの・含まないもの」の構造でも定義できる——これが出てくる形を決めているところ
10

⑩聞き方② Score

段階を言葉で定義して採点

  • 段階は数字ではなく言葉で定義（2段〜10段）——緊急度なら「0: 様子見でいい」「1: 早めに返したい」「2: 今すぐ止めないと困る」
  • 「中くらい」みたいな書き方ではなく具体の説明を書くのだ
  • 帰るのは段階の番号を確率で重み付けした平均——1.3のような間の数字も出る
落とし穴: スコア1.0でも中身は2通り——「全部段階1に寄った1.0」と「段階0と2に半分ずつの1.0」。数字は同じで意味が全然違うのだ。だから公式は確率と確信度を一緒に読めと書いている
11

⑪聞き方③ Noul ＋ 並列

はい/いいえの確からしさを0〜1で

  • Noulは「はいの確からしさ」を0から1で返す聞き方——例:「個人情報が入っているか」
  • Noulに確信度はつかない——その数字そのものが答えだから
  • 3つの聞き方は別々に投げるのではなく混ぜて1度に投げられる——担当はChoice、緊急度はScore、個人情報はNoul
  • 全部の質問が並列に評価され、増やしても待ち時間はほとんど変わらない
  • 質問につける名前は自分のコード用で、モデルには渡らない（細かいけれど重要）
12

⑫確信度の正体

「迷ってなさ」であって「正しさ」ではない

  • 確信度は確率の散らばり方から計算した0〜1の数字——1つの選択肢に確率が集中すれば高く、散らばれば低い（答えの尖り具合）
  • 高い＝モデルが迷っていない、という意味。公式も「答えが正しい保証ではない」と明記
  • Scoreで確信度が低い原因は公式も3つ提示——段階の定義が重なっている・1つの質問で2つのことを測っている・材料が足りない
  • どれも質問の書き方の問題＝直せるところ——低い確信度は書き直しのアイデアとして使える
13

⑬どこで線を引くか

行為の重さで、別々の線を

  • 高ければ自動・中くらいなら確認・低ければ人に回す——全部AIに任せるわけではないのだ
  • 公式の例は銀行——0.5を下回ったら人、送金の承認は0.9を超えても確認してから実行するコード
  • 大事なのは数字そのものではなく行為の重さで線を変える考え方——残高を見るだけとお金を送る操作では、間違えた時の痛さが違う
  • 線の正解も自分のデータで決める——最初は厳しめから始める

試す順番

  • まずPlayground（ブラウザ）で質問の文面を詰める——文面は何度も直すものだから先にそこで詰めるのが早い
pip install typesafe-sdk
npx skills add typesafe-ai/skills --skill typesafe-ai
claude plugin marketplace add typesafe-ai/skills
claude plugin install typesafe@typesafe-ai
Pythonの道具を入れて鍵は環境変数へ。呼び出し方を代わりに書いてくれる公式スキルもある

その4: 桁が変わるのは、どこに置くか

WHERE TO PLACE
14

⑭数字と「誰が測ったか」

速い・安いは自社発表

  • 公式: 現在の言語モデル比で最大193.6倍速い・444.6倍安い——ただし自社ワークフロー評価の最良値
  • Vercelも告知では「TypeSafeが報告している」と主語を分けて記載——自分たちで測り直した数字ではない
  • 第三者実測（Every社 Mike Taylor）: 37の文章に77の判定を0.7秒で処理、コストは比較対象の約0.25%、計11実験
  • 同じEvery代表 Dan Shipper 氏: 人工的な住民の文章で中央値Jev 0.3秒 vs 比較モデル（考えさせる設定）8.83秒——約25倍速く価格は約580分の1
  • ただし同試験の欠陥探しではJevが7問中6問、比較対象は7問全部——書いた本人も「本番投入前にもっと精度を確かめたい」
国内でも開発チームが社内勉強会の記録を公開、50以上のアイデアが出たそうよ
15

⑮置き換えるのは「呼び出し」

文章がいらなかった場所を探す

  • これは今のAIをJevに取り替える話ではない——言語モデルがいらなかった呼び出しを消す話
  • AIエージェントの中身は「次にどの道具を使うか」「スパムか」「断片は関係あるか」「人間の確認がいるか」「危ないか」——全部選んでいるだけなのに高いモデルに文章で聞いていた
  • 本来コードの分岐で書けたはずの箇所を毎回モデルに聞きに行っていた——判断だけ帰るならその分岐は分岐に戻せる
  • 身近な例: 問い合わせの担当振り分け（公式のカスタマーサポート例）——読む工程が丸ごと消える
  • 検索候補の選別: 1件ずつ「関係あるか」を埋め込み代わりにNoulでまとめて1度に投げられる ／ 道具を動かす前の止め気（公式の言うガードレール）: 入り口と出口を安く見張る
  • 安いのは入力だけに課金で文章を作らせない分が値段に効くから——共通するのは「文章を書くモデルと判定するモデルを分けて組む」こと
16

⑯置くときの4つのコツ

公式 ＋ 使った人の報告

  • 選択肢はコード側で作る——モデルに考えさせない。画面の項目・検索結果・道具の履歴から候補一覧を組み立てて選ばせるだけにする
  • 使うか分からない質問もまとめて聞く——出力は無料で並列評価されるから、必要な質問を全部1リクエストに入れて後からコードで選り分ける（公式の言う「積極的なファンアウト」）
  • エージェントの横ではなく中に置く——横は丸ごと任せること、中は部品として挟むこと。どの安いモデルへ回すかの振り分け役・道具を動かす前の止め気・結果が使えるかの判定が分かりやすい
  • 履歴が長くなったら道具の呼び出しを採点して落とす——残したものは要約せず原文のまま。捨てるか残すかだけ判断させて中身はいじらせない
3つ目と4つ目は公式ではなく、実際に使った人がXで公開した報告——出どころは負けて（分けて）聞いてね
17

⑰いくらで、どこまで、何が苦手

料金と制限と弱点

  • 入力は100万トークンあたり0.042ドル（10億トークンで42ドル）。出力は無料——公式いわく「安すぎて測るまでもない」
  • 返すのが短い判断だけだから成り立つ形——文章を返さないことがそのまま値段に出ている
  • 上限: 1秒あたり25万トークン・1分あたり1200リクエスト（制限は事業で調整中）。1リクエスト6万4000トークンまで、材料は3万2000トークンまで
  • 公式が自認する弱点: 計算機ではない（日付や順序のある量は文字として読む。比較は当てにしない方）／無関係な情報が増えるほど精度が落ちる／英語が一番精度が出る（日本語は試してから判断を）
  • 今のモデルはJev 1.13.0（別名 System 1）——バージョンを指定するとそこに繋がる
エージェントに組み込んだ人いわく「広い範囲のベンチマークでは大きなモデルに負ける」——勝てるのは狭くてよく決められた判断。置き場所を選ぶ話に戻るのよ

まとめ: 4つに整理 ＋ いちばん間違いやすいところ

SUMMARY
18

⑱今日の整理: 4つ ＋ 1つ

  • Jevは文章ではなく判断と確率を返すモデル（ChoiceとScoreには確信度も）——読み取る係がいらなくなる。聞くのは置き換えではなく置き場所を変えること
  • 速いのは全部を1度に出すから、形が崩れないのは答えの形を先に決めているから——ただし中身は公開されていない
  • 確信度で線を引いて自動と人手を分ける——線は行為の重さで変える（お金を送る前は線を厳しく）
  • 最大の倍率とハルシネーション0は自社の発表——第三者の小さな試験でも速さと安さは出たが見落としは残った。誰が測った数字かを見るのだ
  • いちばん間違いやすいところ: 「型が守られていること」と「答えが合っていること」は別——振り分け先を間違えた答えも形としては正しい。実際の当たり具合と合うのは確信度ではなく確率の方（0.8の答え1000件で約800件当たる。目の前の1件は保証されない）
「この動画面白かったですか?」をNoulで聞くと0.82——感想が数字で帰ってくるが、結局読み解くのはずんだもんなのだ。仕分けは任せて、感想は人に聞く。また見てね
