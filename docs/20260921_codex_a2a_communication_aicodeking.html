実験的Astra新機能

④本当に試すべき検証方法

評価プロトコルランディングページより
  • 新しいモデルに「また基本のランディングページを作って」と頼むより、よほど有用な試験方法を提案します
  • 手順: 数ラウンドかかる変更を与える → 途中で新しい要件を追加 → 最初の制約を最終結果が守っているか確認
  • つまり長期記憶の実戦テスト。デモ向けの目玉ではなく、実務で効くかを見極められます

ベンチマークスコアより「途中投下の要件を覚えてるか」が本番だよね。

⑧@メンションで他タスクを参照

Codex CLI8月末〜A2A
  • 8月末、Codex CLIに他タスクを@メンションで参照する機能が追加されました
  • 別のタスクに相談（consult）したり、指示（instructions）を送信したりできます

09

⑨実例: 旧認証システムの置き換え

組み合わせ実演調査→実装
  • 調査タスク: Codexに既存ログインフローの挙動を解明させます
  • 実装タスク: その調査結果を@で参照（consult）し、自分専用のチェックアウトで置き換え作業を実行
  • 2つのアプローチを比較したいならそれぞれ別のワークツリーを与え、両方の変更を確認してから採用すればOK

調査係と実装係の分業。人間のチーム開発みたいに進むのが未来！

10

⑩Gitワークツリー対応（CLI版）

9月の新機能実験的
  • 9月にはワークツリーサポートがCLIに直接実験導入されました
  • ワークツリーとは同じGitリポジトリの別チェックアウト。あるタスクの変更が別タスクの編集と混ざらずに済みます
  • ワークツリー自体はデスクトップアプリに既存。新しいのはCLI対応で、なお実験段階です
  • エージェント2つが完了しても変更同士が噛み合うかは別問題。レビューと統合は人間の仕事として残ります

⑪作業を続けながら質問

インライン質問Codex CLI
  • Codex CLIは作業を継続したままインラインで質問できるようになりました
  • 回答しても下書き中だったプロンプトを失わない。あの行き来のストレスが軽減します

  • 答え次第の部分だけ待てばよく、ブロックされない範囲はどんどん進む設計です
