⑤核心: 話しながら裏で作業する

バックグラウンド実行API呼び出し

⑨英数字に強い: 正確な読み取り

確認番号事件番号
  • プログラムのコードではなく、確認コードや事件番号といった英数字の並びが苦手だった音声AI。ここが大きく改善されました
  • Googleはこれをalphanumeric precision（英数字の精度）と呼びます
  • 口頭で伝えた番号を正しく聞き取れるので、電話での案内やサポートでも信頼が置けます

⑩97言語: 自動で検出して切替

97言語対応自動検出

  • 会話の途中で別の言語に変わっても、事前に宣言は不要。そのまま続けられます
  • 世界中の人が母語で声を上げ、声で答えが返ってくる。音声で囲まれる未来が加速します

日本語の途中から英語へ切り替えても、会話はそのまま続きます。

⑪旧来の弱点: 3人リレーの音声処理

リレー方式誤りの連鎖
  • 従来の音声AIは3人のランナーによるリレーみたいな仕組み。1人が声を文字に、2人目が文章を考え、3人目が再び声に変えます
  • 1人目がひと語りでも聞き違うと、その誤りが最後まで運ばれ、後の走者には直せません
  • Gemini 3.8 LiveはGemini 3 Proを土台にしたモデルで、この三段構えの置き換えを狙います

ベンチマーク首位

⑬SynthID: 聞こえない署名

音声の透かしSynthID
  • GoogleのAIが作った音声には、SynthIDという見えない透かしが必ず織り込まれます
  • 耳には聞こえませんが、音声そのものに組み込まれているのでAIの音声だと検出可能です
  • Googleいわく、これは誤情報の防止のためにあるとのこと。生成音声の透明性を支える仕組みです

PRACTICE
16

⑯3つのミス: 失敗しがちな点

ミス①〜③要注意
  • ミス①モデルの選び間違い。難しい多段階の作業にはExtended Thinking、大規模で速い掛け合いには通常のLiveが本分です。仕事にモデルを合わせるのが鉄則
  • ミス②「完了」を過信すること。Extended Thinkingでは、turn completeの合図が出てもまだ推論やツールの実行が残っている場合があります
  • ミス③不要な動画の送信。音声だけなら15分までですが、動画を足すと2分で打ち切りに（圧縮機能を有効にすれば除く）。目が要らないなら動画は流さないこと
// ミス②の対策: 状態の見極め
"interaction_status": "IN_PROGRESS" // まだ作業中
"interaction_status": "IDLE"        // 完了の合図
// 対応するのは非ブロッキングの関数呼び出しのみ
17

⑰4つのコツ: 上手に使い倒す

レベル調整割り込み
  • コツ①考える深さを調整。Extended Thinkingでは思考のレベルを低・中・高で指定可能。最小は非対応で、高い段階は難題にとっておきます
  • コツ②遠慮なく割り込み。タップで割り込むボタンには意味があります。終わりを待たず、途中から軌道修正しましょう
  • コツ③見せて伝える。目の前の物で詰まったらカメラを向ける。Search Liveが手順を追ってその場で案内してくれます
  • コツ④途切れさせない。開発者はセッションの再開と文脈の圧縮を活用し、会話が突然切れるのを防ぎます
# 思考のレベル指定の例
thinking_level: LOW | MEDIUM | HIGH
# MINIMAL は非対応。HIGH は難しい課題だけに
