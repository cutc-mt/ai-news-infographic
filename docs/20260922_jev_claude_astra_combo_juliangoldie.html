04

④Jevの正体: 「書かない」専用モデル

TypeSafe AI2026年9月15日登場
  • JevはTypeSafe AI社のモデル。元OpenAI研究者のDiogo Almeida氏が構築し、2026年9月15日にローンチされました
  • 一番変わっているのは、文章を一切書かないこと。TypeSafeはこれを「システム1モデル」と呼びます。ゆっくり熟考するタイプではなく、反射的な速い判断に特化した設計です
  • オープンソースではなくTypeSafeのホスト型モデルなので、API経由で利用します。文章生成ではなく判断の結果だけを返す存在です

「速くて直感的な頭脳」を丸ごと借りるイメージです。

05

⑤使い方: 3つの質問形式と信頼度

状況＋質問を渡すだけ70〜500ms
  • 渡すのは「状況の説明」と「いくつかの質問」だけ。回答形式は3つで、リストから1つ選択、スケール上でスコア、確率付きのyes/noです
  • すべての回答には0から1の信頼度（confidence）が付いてきます。「当てずっぽう」なのか「確信あり」なのかが数字でわかるのです
  • そしてTypeSafeによれば、そのすべてが70〜500ミリ秒で返ってきます。判断専用に削り込まれた速さです
// 質問のタイプ（イメージ）
1. choices: [再試行, 停止, 質問] から1つ
2. score:   緊急度を 0〜10 で評価
3. yes_no:  p=0.87 で「はい」

⑥なぜエージェントに効くのか

エージェントの本業選択の連続
  • エージェントの作業のほとんどは、実は書くことではなく「選ぶこと」。「次はどのツール？」「再試行する？」「この実行は安全？」の連続です
  • AstraはOpenAIのフラッグシップで、DataCampの比較では実ソフトウェアをクリックして進むエージェント向きの強い選択肢。Claude Fable 5.1はAnthropicのフラッグシップです
  • どちらも文章・コーディング・深い思考には抜群ですが、些細な選択に1日中答えさせるのは「トップシェフにエレベーターのボタンを押させる」ようなもの。Jevがその役割を引き受けます

⑦制約こそ安全装置

リスト外は回答不可はみ出せない
  • Jevは渡されたリストの中からしか回答できません。4つのツールから選ぶエージェントが、勝手に5番目のツールを発明するようなことはないのです
  • とはいえ選び間違えることはあります。そのためにこそ、すべての回答に信頼度の数字が付いているのです
  • つまりJevは、暴走を構造的に抑えた判断専門の部品。エージェントの運用に組み込みやすい設計になっています

「選べる選択肢」をこちらで決められるのが、安心ポイントです。

⑧精度はどこまで届くか

TypeSafe独自テスト約68%一致
  • TypeSafeの独自テストでは、JevはAstraとFableの平均回答と約68%一致。この水準はGPT 5.6 TerraやClaude Sonnet 5と同等です
  • しかも、その精度に達するまでの速さはTerraの約25倍。小さな判断の処理としては十分すぎる性能です
  • ただし最大級のモデルの方がまだ高精度。だからJevは置き換えではなくパートナーとして使いましょう。書く・考えるは大型モデル、選ぶはJevです

代替ではなく「分担」。この言葉がこのコンボの核心です。

⑩AI Gatewayとは: 1つの鍵で全部へ

1つのドア1つのキー
  • AI Gatewayとは、あなたのアプリと多数のAIモデルの間にある1つのドア。キーは1つで、OpenAI・Anthropic・Googleなどのモデルにアクセスできます
  • だからこそこのコンボのホームに最適。速い判断はJevへ、重い思考は大型モデルへ、と1か所で切り替えられます。Gateway上での名前はTypeSafeAI/Jevです
  • VercelのAI SDKには、Jev向けの実験的なevaluate関数も用意済み。状態と質問を渡すと型付きの回答が返ります
  • 呼び出しはGatewayのログに記録され、ゼロデータ保持や学習に使わない設定もONにできます。Claude CodeやCodexをGatewayへ接続する公式ガイドもあります
// AI SDK の evaluate イメージ
const result = await evaluate({
  state: 状態,
  questions: [質問…]  // 型付きで回答
});

⑪APIキー取得: 5ステップ

1分で発行取り扱い注意
  • Vercelにログインして AI Gateway を開きます
  • API keys へ進み、「Create key」をクリックして名前を付けます
  • キーはすぐその場でコピーして安全な場所へ保管。この一手を忘ずと二度と見られません
  • そして絶対にチャットへ貼らないこと。キーは環境変数に入れます。これはあなたのPCだけの非公開設定で、ツールだけが読み取れます
# 環境変数に入れる（チャットに貼らない）
export VERCEL_API_KEY="（安全な場所から読み込む）"

「コピーはその場で、保存は環境変数へ」。この2つが鉄則です。

⑬Jevが輝く4つの場所

小さな判断の連続Vercel公式リスト
  • 1つ目は次に使うツールやヘルパーエージェントの選定。分岐のたびに最適な1手を選びます
  • 2つ目は続行・再試行・ユーザーへの質問・停止の判定。エージェントの進退をミリ秒で決めます
  • 3つ目は行動前の緊急度・リスクのスコアリング。やばそうな処理には先に点数を付けられます
  • 4つ目は別モデルの出力をルールと照らしてチェック。大型モデルの作業検査員として働きます

「何度も繰り返す小さな判断」こそ、Jevの主戦場です。

⑭信頼度の使い方: 3段階の線引き

TypeSafe公式の3パス0〜1で運用
  • 信頼度が高いときはエージェントにそのまま実行させます
  • 中間ならレビューを挟み、低ければ人間へエスカレーション。この3パス運用がTypeSafeの提案です
  • 線の引き方は「間違えたときの損害の大きさ」で決めます。Vercelの助言は、自分でラベル付けした実例と突き合わせて線を決めること
  • ただしJevが返すのは数字だけで理由は付いてきません。理由の説明が必要な判断は、ClaudeやAstraの担当のままにします
// 信頼度しきい値のイメージ
if (conf >= 0.8)  実行する
else if (conf >= 0.5)  レビューへ
else          人間に確認

⑯バッチング: 1回で10の判断を

7〜10質問を同時約400ms
  • 1回のJevリクエストには多数の質問を詰め込めます。Pippaの構築では7〜10個を一度に投げ、回答が返るのは約400ミリ秒。1回分の重さで10個の判断が手に入ります
  • 3つの質問タイプも同じ状況について1リクエストに混在可能です
  • Forbesの助言は、エージェントの1ステップにつきバッチ1回、行動のあとは新しい状態を読み直すこと。1問ずつ聞くのは速さを捨てる行いです
  • さらに実測では、JevをFableやAstraの下に置くと大型モデルが信号機のような質問を処理しなくなり、トークン消費が減りました
// バッチリクエストのイメージ
questions: [
  次のツールは?,        // choices
  リスクは 0〜10?,     // score
  続行してよい?        // yes_no
]  // → 約400ms で一括回答

⑰独立テストと正直な注意点

Dan Shipper氏のテスト約25倍速
  • Forbesが伝えた外部テストでは、Dan Shipper氏がわざと間違いを仕込んだ12の文章を用意。Jevの回答時間の中央値は約3分の1秒で、高 effort設定のClaude Fable 5.1は約9秒。およそ25倍の差です
  • 検出率はJevが7つの間違いのうち6つ、Fableは7つすべて。1つの見逃しと引き換えに、圧倒的な速さを得る取引です
  • 正直に言うと、TypeSafeの「最大193.6倍速い」という主張は自社ワークフローのハイエンドの数値。テストの答え合わせも正解ではなく他モデルの回答が基準でした
  • そしてJevは登場からまだ数日のモデル。だからこそ、小さく始めるのが正解です

速さの数字は条件次第。手元の仕事で確かめるのが一番です。

⑱今週の始め方と、ブランドの教訓

小さく始める1週間の並走
  • まず繰り返し起こっている退屈な判断を1つ選び、平易な言葉で記述します
  • 選択肢には「いつ当てはまるか」を1行で書いた明確な基準を付けます。誤動作の直し方は、たいていコードを増やすことではなく基準を明確にすることです
  • 現行の仕組みと並走させ、Gatewayのログを見ながら1週間選択を比較し、信頼できてから任せます
  • 最後にブランドの教訓。Jevが機能するのはすべてが明確で、ラベル付けされ、確認しやすいから。あなたのブランドも同じで、AI検索が理解できなければ推薦されません
