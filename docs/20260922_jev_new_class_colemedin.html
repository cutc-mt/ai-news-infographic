第1章: Jevは、全く新しいモデルです

CARD 01 - 04

①: Jevとは何か

  • 今週リリースされた全く新しいAIモデルです。
  • 従来のLLMではなく、System 1モデルという新しいクラスを提唱します。
  • その役割は、優れた意思決定者であることです。
  • Cole氏は「久しぶりに本気でワクワクした」と語っています。
新LLMのラッシュに疲れていた人にこそ、
見てほしい動画です！

②: LLMとは、全く違う

  • ChatGPTやClaudeのような会話はできません。
  • そもそも、文章を生成しないのです。
  • 状況を受け取り、判断だけを返します。
  • 「1文も書けないのに、役に立つ」のがポイントです。
チャット画面は無いと
思ってくださいね。

③: 新しい学習手法「RLCD」

  • 学習にはRLCDを使います。
  • 正式名称は、Calibrated Decisions向けの強化学習です。
  • 生成AIが使うRLHFとは、仕組みが異なります。
  • 判断場面での、ハルシネーションや信頼性の問題を大きく減らせるとされています。
「正しいタスクを最適化すれば、
不公平なほどの優位性を得られる」
—— 開発元の言葉です。

④: 入力と出力の形

  • 入力①: 分析する状況を渡します。
  • 入力②: 答えが選択式の質問のリストです。
  • 出力: 各質問への選択と信頼度が返ります。
  • 見た目はLLMの構造化出力に似ていますが、常に判断のみです。
# 入力のイメージ
{
  "situation": "状況の説明…",
  "questions": [
    { "q": "担当は?",
      "options": ["課金", "技術"] }
  ]
}

第2章: 圧倒的な3つの強み

CARD 05 - 08

⑤: 具体例で見る動作

  • 例: カスタマーサポートへの組み込みです。
  • 顧客は「Stripeの接続に失敗して、売上が止まっている」と困っています。
  • 結果: 担当は課金部門と判断し、信頼度は64%でした。
  • 感情の点数は1。つまり「イライラしているが、丁寧」と読み取りました。
# 出力のイメージ
{
  "routing": "billing",
  "confidence": 0.64,
  "sentiment": 1
}
振り分けと感情分析を、
1回で同時にこなします。

⑥: 完璧な3点セット

  • 速い — 判断が素早く返ります。
  • 安い — コストがとても低いです。
  • 信頼できる — 出力が壊れません。
  • LLMでも同じことは可能ですが、この3つで大きく差がつくとCole氏は言います。
Trifecta
3つ揃ってこそ、本物です。

⑦: 圧倒的な低コスト

  • 最良のLLMと比べて、40〜1,000倍も安いとされます。
  • 公開グラフは対数軸で、差はケタ違いです。
  • GPT-6 AstraやClaude Fable 5.1と比べても、トークン単価は圧倒的です。
  • 時間を十分にかけたLLMの方が、精度が上回る場面もあると正直に紹介しています。
数百〜数千の判断を
並列で出しても、ペニー単位です。

⑧: 圧倒的な速さと信頼性

  • 判断までの速さは、20〜200倍です。
  • 1つの判断が、およそ200ミリ秒で返ります。
  • 構造化出力の失敗率は0%。壊れたJSONで後段が止まる事故がありません。
  • 速さと安さが合わさり、大量の並列判断が現実になります。
ワークフローの分岐を、
もう正規表現や遅いLLM呼び出しに
任せなくてよくなります。

第3章: 実際に作って、試してみた

CARD 09 - 12

⑨: Jevがゲームを遊ぶ

  • localhostで動く自作のインディーゲームを、Jevが実際にプレイしました。
  • Cole氏はキーボードから手を離し、画面を見守るだけです。
  • 攻撃や移動、回避などを、信頼度付きで毎秒3回判断し続けます。
  • LLMでは処理が追いつかず、費用も高すぎて実現できなかったそうです。
ゲームを作るのは苦手ですが、
遊ぶのは得意という不思議な
組み合わせです。

⑩: PRレビューの仕分け

  • オープンソースのArkon上で、ワークフローを組みました。
  • まずJevが、プルリクエストの分類と振り分けを行います。
  • その結果に応じて、LLMがレビューの深さを変えて実行します。
  • すべてのPRに重いレビューは不要なので、費用を最適化できます。
# Arkonからの呼び出しイメージ
import jev_triage
result = jev_triage.classify(pr)
# => 軽い確認 / 通常 / 徹底レビュー

⑪: LLMルーターとして使う

  • リクエストを、strong / coding / open / fastの4モデルへ振り分けます。
  • 深い推論が必要な問いはstrongへ、信頼度100%で送りました。
  • 「bashをPowerShellへ変換」はcodingへ、信頼度は98%です。
  • 「72°Fを摂氏へ」のような軽い質問は、安いfastモデルへ振られました。
  • 数十件の試行の費用は0.4セント、平均0.2秒 / 判断でした。
# ルーティングのイメージ
route = jev.decide(
    situation="ユーザーの質問文",
    choices=["strong", "coding",
             "open", "fast"])
# => {"choice": "fast", "p": 0.99}
振り分け役をLLMに
任せていた時代は、
もう終わりかもしれません。

⑫: 今すぐ試す方法

  • OpenRouter経由が手軽です。他のLLMと同じ要領で呼べます。
  • 開発元のTypeSafe（typesafe.ai）を直接使う道もあります。
  • 直近はウェイトリスト制ですが、1日ほどで通ったそうです。
  • 公式のプレイグラウンドで、動きを確かめることもできます。
今回の動画はTypeSafeの提供ではありません。

第4章: コミュニティの挑戦と、広がる使い道

CARD 13 - 16

⑬: コミュニティのデモ

  • X上で、古典ゲームDoomをJevが遊ぶ投稿が話題です。
  • 画面の片側に、判断の中身と信頼度がリアルタイム表示されます。
  • Pongの比較デモでは、Jevは人間並みの速度でラケットを動かせました。
  • 一方のLLM（3.8 FlashやHaiku 4.5）は、大幅に減速しないと処理が追いつきません。
選べる行動が多いゲームは苦手ですが、
それでも十分すごいです。

⑭: ブラウザの自動操作

  • 状況は「今の画面のレイアウト」、選択肢は「次の操作」です。
  • ボタンを押す、入力欄に記入する、といった操作を判断します。
  • 従来のPlaywrightやブラウザ操作CLIはLLM駆動で、遅いのが弱点でした。
  • browser-use / jev-ultrafastなど、関連リポジトリが続々と登場しています。
Webアプリの検証が、
開発の律速段階から一転、
高速な検査工程になります。

⑮: 公開中の使い道一覧

  • 分類と振り分け — 最も基本的な用途です。
  • エージェントの判断 — 次の一手を選びます。
  • 検証とガードレール — 出力の安全性を守ります。
  • 較正と研究 — 信頼度の分析にも使えます。
  • ゲームとシミュレーション
  • 金融と取引 — 高速な判断が効く分野です。
これらはGitHubの

⑯: LLMと組わせて使う

  • すべてのLLMをJevへ置き換えるのは、得策ではありません。
  • 自動化の中の分岐や仕分けの場所に、Jevを置きます。
  • 文章や推論はLLM、判断はJevと、役割で使い分けるのが理想です。
  • 「道具箱にまた一つ、強い道具が増えた」と表現しています。

第5章: 批判への答えと、まとめ

CARD 17 - 18

⑰: 「ただの分類では?」への答え

  • 最大の批判は、「分類モデルの焼き直しにすぎない」という指摘です。
  • ある程度は事実で、Cole氏も率直に認めています。
  • しかし従来の分類は、TensorFlowやPyTorchで特定の課題専用に作る物でした。
  • 課題が変われば全く使えなくなる、汎用性のなさが弱点です。
  • Jevはどんな状況でも扱える、汎用の分類です。
「最も建物がかっこいい国は?」と聞くと、
何度試しても同じ国を
答えるそうです。
