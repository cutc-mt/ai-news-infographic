ロンチの衝撃: タイムラインを席巻した一週間

LAUNCH
01

①感情的には最悪、精神的には最高

ロンチ直後の心境素の本音
  • 「感情的には人生で最悪です。今はボロ切れのような人間です」と笑うDiogo。テクニカルCEOとして消火したい火事が絶えない毎日だそうです
  • しかし精神的には別世界。AI業界は長らく「お化け屋敷の鏡の部屋」に見えていたけれど、この一週間だけは現実と噛み合った気分なのだとか
  • AIによる経済革命が現実の選択肢に戻ってきた。開発者がその本質を理解してくれたことに、深い感謝を示していました
  • 重要投資家との面談よりもDiscordのタウンホールを優先。「理想の世界では、ずっとコミュニティと話していたいんです」と語ります

「会社の最重要の時期に開発者と話さないなんて、私には汚いことに思えた」。だから髪を染めて、町頭会議の場に立ちました。

02

②数字で見る爆発的な一週間

1兆トークン/日無広告で拡散
  • Discordの参加者が10万人を突破。Xではトレンド3位までを話題が独占しました（「それは君個人のフィードでは」と冗談で返されたとか）
  • ロンチ動画は3800万再生に到達。Navier-Stokesデモの7400万、Fable 5の5700万に並ぶ、2026年の新ラボとしては頂点クラスの数字です
  • 1日のトークン処理量が1兆を突破。「夜中もずっと回っている。機械が呼んでいるのであって、お試しの人ではありません」
  • 登録者数は重要ではない（大半は開発者すらなく、試して去る）。本当の怖さはレート制限の要求。プラットフォームチームの稼働率はAnthropic以上です

マーケターは一人もいない。「ただ素のまま、ふざけて過ごしていただけ」なのに、マーケティングの天才と呼ばれました。

03

③Jevとは何か

システムワンモデルコードが消費者
  • 必要なのは新しいモデルのクラス。社内での呼び名は「システムワンモデル」、正式にはマシンネイティブな大規模プログラマブルモデルです
  • 事前学習LLMはインターネットの自動補完、RLHFモデルはチャットボット向け。Jevの目標はただ一つ、コードが消費する側になること。社名TypeSafeの由来もここにあります
  • 名前はJevonsのパラドックスから。効率が上がると消費が増えるというあの法則です。1ドルあたりの知能のフロンティアに全振りします
  • 「これは本命ロンチではありません。まだ玉手箱が社内に眠っています」と、続々と新モデルを予告していました
04

④システムワンという賭け

直感系の知能ノーススター整理
  • 実証的な判断として、事前学習で凝縮された知能は本質的にシステムワン（直感系）の思考者。そこから最大限の知能を掘り起こす方向で設計しています
  • RLVRはシステム2（熟考系）に驚異的な成果を出したが、その能力は脆弱でギザギザ。数学はフラクタルのように尖った難しさを持つのだとか
  • ホストが実測した感想: シングルホップ推論は状態最強。しかしホップ数が増えると単調に劣化していきます
  • 3つのノーススターを鮮やかに整理。LLMの歴史を動かしたタスク転換は、これまで2.2回しか起きていないと言います
RLHF人を喜ばす RLVRベンチマーク最適化 RLCDプログラム利用への信頼

設計思想: なぜ文字列モデルでは駄目なのか

PHILOSOPHY
05

⑤RLHFが生んだモード崩壊

モードドロップキャリブレーション
  • Yann LeCunの有名なスライド「系列が長くなると誤り確率は発散する」。Diogoいわく「数学的には自明だが、経験的には誤り」なのだとか
  • 分布を覆う古い生成器はぼやけた画像を作った。GANはモードを落とし、少数クラスを切り捨てて多用な模様だけを描きました
  • 長い文字列を誤りなく出すには極端に保守的になるしかない。このモード崩壊が確率分布に毒を注入し、キャリブレーションを壊します
  • だから文字列モデルに意思決定を任せるのは悪手。この違和感こそがTypeSafe創業の出発点でした

「RLHFの望まない副作用としてのモード崩壊。この話は、できるだけ多くの人に伝えたいんです」

06

⑥拒否は型エラーである

拒否の型エラーAPIの信念
  • コーディング中に「DNA.pyは読めません」と拒否されるのは人間なら我慢できる。しかし依存の裏で動くソフトが、変わった入力ひとつで確率的に壊れるのは正気の沙汰ではありません
  • 安全性アライメントはChatGPTやClaudeのような一人あたりの製品なら合理的。でもAPIでは完全に受け入れられない。開発者はその回り込みをプログラムできません
  • 知能は同僚ではなくデータベースのようなもの。DBは自分の使い方の善悪を検査しません。求めるのは、必要な時に just そこにある知能です
  • 「うちはAPI、あなたは開発者。下流で何をしているか知るべきではない」。理想の使い方に傾ける仕組みはあっても、技術レイヤーでは親指を乗せないと固く誓います
07

⑦決定論よりロバスト性

似た入力→似た出力バージョン不変
  • 信頼性は包括語。型安全性、決定論、ギザギザさ。AIが作業を自動化できない原因は、すべて何らかの信頼性不足に帰着します
  • 決定論（同じ入力→同じ出力）は間違った北極星。本当に欲しいのはロバスト性。プロンプトにUUIDの乱数を入れて、意味的に同じ問いに似た答えが返るかを試します
  • 決定論的なモデルも作れるが、それは1ドルあたり知能と交換になる。フロンティアに居座るため、常識破りの工夫（「正直言えないほどのこと」）を重ねています
  • デプロイ済みのモデルは一切書き換えない「それは正気じゃない」。多くの人に使われるJev 1.13.0のLTS化も検討中で、長期支援の「最高に開発者思いな方法」を研究中です
08

⑧データこそが知能である

データ.first無限に採用
  • モデル能力とはデータのこと。9の桁（ナイン）を積み上げるのはデータです。だからデータの人を「無限に」採用したいとアピールしていました
  • Suttonの苦い教訓を深読みする: アルゴリズムは計算に勝つ。しかし最重要は正しいタスク（北極星）。RLHFは指示追従へ、RLVRは小さな修正、そしてRLCDが新タスクです
  • ユーザーデータでは訓練しない。依頼がどれだけ有利でも。べき法則の偏りで現在に過学習し、数年後の想像もつかない用途を壊してしまうからです
  • データチームは認知コアを研究する芸術家。ギザギザを見つけ、あらゆる次元で外科的に治します。比喩すればLLMはUDP、TypeSafeのモデルはTCP。その上に何層も積める基盤です

「データがどれほどすべてを変えられるか、言葉では強調しきれないほどです」

APIデザイン: 3つのプリミティブと分解の美学

API DESIGN
09

⑨3つのプリミティブ: bool・score・choice

新概念の型Bernoulli由来
  • APIの中核はbool・score・choiceの3つ。既存のプログラミング型にわざと一致させない、意図的に新しい概念です
  • 風変わりな綴りのboolはBernoulli（ベルヌーイ確率）から。「pool party」と名付けたかったのに却下された過去も明かしました
  • scoreは判定・並べ替えへ。choiceはswitch文とenumへ。プログラミングの基本要素に素直に対応するのが思想です
  • Jevという名前は社内で総スカンだったそう。今も謝っていない人が一人。親しい友人は「Meow（ニャー）」を推していたとか
// プリミティブと対応する基本要素
choice → switch文 / enum（分岐）
bool   → if文（真偽の確率）
score  → ソート / 閾値（連続値）
10

⑩システムメッセージはグローバル変数

構造化JSON入力AI関数
  • 入力のstate・instructions・criteriaはすべて構造化JSONオブジェクト。プログラムが正しい位置に埋め込めて、テンプレートへの流し込みは不要です
  • システムメッセージは「最低なグローバル変数」。指示を全部ぶち込んで、全部守られることを祈る仕組み。古い考え方だと斬ります
  • 発想はAI関数。手持ちの変数（状態）のうち、どの部分集合をこの問いに渡すのかを、プログラマが明示的に選びます
  • 数字を全部文字列にして渡す言語は存在しない。意味的なネスト構造のまま渡すべきで、ネストの各段の推論を徹底的に最適化しています

「人間が読む時にだけ文字列化する。コンピュータ同士のやり取りなら、構造のまま渡すのが自然でしょう」

11

⑪分解すれば永遠に解決する

小さく・並列に評価可能に
  • 質問は大量に・小さく・並列に分解する。単純な決定の一つ一つは極めて評価しやすく、AIコードベースそのものが劇的に良くなります
  • 「ここで拒否すべき？」の1問より、拒否したい状況ごとの独立した問いを並べる方が遠くまで届く。タスクを明示できるからです
  • 不具合を見つけたら質問と閾値を1つ追加するだけ。テストケースとして永久に固定され、コンテキストが腐っても忘れません。「それがソフトウェア工学です」
  • これを「MLなしのML」と表現。一方で自動トレードのような高次タスクは専門家に任せ、モデルの得意領域を測ってから段階的に展開すべきと戒めます
// 分解の実例: 拒否を1問にしない
NG: 「この入力は拒否すべき?」
OK: 個人情報を含む? / 危険物の設計? / ...
# それぞれ閾値を指定して段階的に制御
12

⑫ベンチマークを信じない

反・公開ベンチバイブと信頼
  • 公開ベンチマークには極めて反対。ゲーム化が簡単すぎる。昔は各ラボがMMLU似のデータを集める班を抱えていた、それ自体が段違いの基準偽装だと回想します
  • 長期の信頼はバイブと信頼から始まり、自分のワークフローに組み込んで測った数字で固める。その繰り返しだけが本物です
  • 内部評価は当然ある。ただし自分自身を欺かないことが最優先で、そこだけは鉄の拳で統治していると明かします
  • 「1年半前にも出せました。ただバカになりたくなかった」。調達の際も基準値を出せと迫られて断り、信念を貫いたと言います

知能には「良いモデルの香り」がある。ロンチ2時間後の「これは実際に使える」の声こそ、本物の基準でした。

ユースケース: 何に使われているのか

USE CASES
13

⑬5大ユースケース族

第一原理から設計大金づち
  • ダークデータ: 高すぎてLLMを当てられなかった社内データの山。大企業が熱狂する「データサイエンティストの夢」で、コーディングエージェントと並ぶ二大ボリューム源です
  • リアルタイム: 100ミリ秒〜1秒の魔法の予算。ECでは10ミリ秒を削るごとに商品が良くなると、すべてのCEOが知っていると言います
  • ゲーム: 知能あるオートバトラーをプレイしたいと目を輝かせる。Stardew Valley的な静かな世界にも、物語が動く未来を描きます
  • 検証と観測: すべてのAI呼び出しを検証する文化。stateは1回だけ支払って、ID付きで何度でも問いかけられます
  • スマートソフトウェア: プログラミング言語そのものとしてJevを使う試みも誕生。「我々のデモよりクールなものが出てくる」と喜びます
14

⑭予想外のコンピュータユース

音声でPC操作想定外の方向
  • 音声でPC全体を操作するデモが急涌した: メモの作成、Arcでの検索、Xの閲覧、写真を開く。Jevを決定モデルにして画面の全操作を声で完結します
  • 「デモには基本的に反対です。でもこれは見たい。弱点を見つけて、解決したい」。確実に動くものだけを世に出す主義の裏返しです
  • コンピュータユースはまったくの想定外からやってきた方向。この用途向けにモデルをさらに良くできる手応えもあるとか
  • 「手首が痛い日には、ささやきだけで全部済ませたい」。開発者らしい素直な願いも覗かせました

コミュニティの Cookbooks には本物の知見が詰まっている。「AI生成の掃き溜めではなく、愛を込めて書きました」

15

⑮KVキャッシュの専制と解放

単一モデル前提の崩壊エージェントの未来
  • Claude CodeとCodexは単一モデル世界を前提に構築されている。一方、オープン系のコーディングエージェントは今やほぼ互角の横並びです
  • 誰かがキラーとなる使い方を1つ見つければ、全員がそこへ殺到し、オープン系ならたちまち模倣される。ゲームの構図が一変すると予想します
  • 記事「KV cache rules everything around me」: なぜルーティングは難しく、サブエージェントは動かず、文脈圧縮は困難なのか。すべてKVキャッシュの専制に帰着します
  • 解放された先の未来: サブタスクツリーを検索して必要な文脈だけ引く、履歴を安く参照する（継続学習とはメモリ管理の問題）、エージェント群の読み書きロックをJevに調停させる

履歴参照  が安価に → 継続学習が成立

⑯OpenAI時代の問い

InstructGPT配備哲学の転換
  • InstructGPTの配備に死闘を挑んだ一人。公開すると即座に当時のLLM市場の50%のシェアを獲得しました
  • しかし行き着いた先はコピーライティングのスロップ。「ネットを悪くしたのではないか」と悩み、原点に戻って何が欠けているかを探します
  • 辿り着いた問い: AI経済革命が起きた時、AIを呼ぶのは人間か、コードか? 答えは9割9分コード。なのに最適化はすべて人間向けでした
  • その問いをSamに見せたら「最高だ、やれば」。感謝祭の休暇にGPUを総動員した英雄ランは、社内の混乱と時を同じくした「歴史の分岐点」だったと振り返ります

「AIの冬が来て、全力を尽くさなかった自分を、私は個人として責任を負うことになる」——退職の決断は、ここから始まりました。

17

⑰創業2年の物語

1週間のはずが数年ステルス2年
  • 最初は「1週間で終わる計画」だった。実は数年の旅になったと、OpenAIの皆さんに冗談で謝罪します
  • 既存企業に相談すると「スタートアップの方が速い」。まずEricに電話し、Sashaは「今すぐ自分の会社をたたむ」と即断で合流しました
  • 2週間で資金が決まり、初期メンバーは彼の部屋に転がり込んだ。潔癖症の本人には「最悪の時期」だったとか
  • ステルス2年の末、ロンチ前の評価は散々。半数以上の体験者が魅力を理解できず「ビタミン剤であって鎮痛剤ではない」と言われ、収益はほぼありませんでした
  • それでも市場は開発者と決めた。「私が態度を変えたらピッチフォークを持ってきてください」。開発者が企業より得をするロンチを約束します
18

⑱業界への提言と未来

知能のAWSへ0%起業家
  • ほとんどの新興ラボは価値を毀損していると率直に言う。重用するのは研究者の肩書きではなく「正しいタスク」を見つけられる人です
  • 「ペース・ザ・フロンティア」議論は全員がRLVRを積み増す前提に立ち、狭い。TypeSafeにとって最適なRLVR量はゼロだと断言します
  • 目指す先はTFP成長率3%を5年で。SaaSは知能で超充電される「逆・SaaSの黙示録」が来る。大量失業ではなく、AIが背景に溶け込む世界です
  • 未来像は「知能のAWS」。LLMはTCPのような土台に過ぎず、あと7層ある。採用はデータ（最高位の地位に）、平台（光速が距離の制約。欧州は3倍速にとどまり申し訳ないと）
  • 本人は「起業家気質は0%」。CEOになりたくなかったのに使命を見つけてしまった、と笑います。チームが遠慮なく彼をからかう文化が自慢です

「Jev for president？ ずいぶんですね。私は自分の決断よりJevの決断を信頼しますよ」——次の大型ロンチは、思っているより早く来るそうです。
