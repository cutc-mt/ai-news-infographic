02

②FounderMatchとは何か

今回の題材共通アイデア
  • FounderMatchは、スタートアップ創業者がスキル・興味・稼働状況に基づいて相性の良い共同創業者（コファウンダー）を発見できるサービス
  • 創業者自身がプロフィールを公開し、互いに互換性のあるパートナーとつながる設計。SNSというより「マッチングに特化したプラットフォーム」です
  • Danielはこの1つの構想を、Web・モバイル・ブラウザ拡張・エージェントという4つの異なる形式で表現することを思い立ちました

「1つのつながったアイデアを思いついて、その周りにいくつものプロダクトを建ててみることにした」——検証の設計思想がここに表れています。

03

③検証のルール: 共有DBには接続しない

検証設計独立ビルド
  • 重要な前提: 今回の4つのビルドは1つの共有データベースには接続しない設計です。あくまで同じFounderMatchアイデアを巡る別々の独立プロジェクト
  • なぜこの形にするのか。それはBlinkが異なるプロダクト形式をそれぞれどう処理するかを純粋に見るため。形式ごとの生成力の比較検証です
  • 「Webでさえ作れればモバイルも拡張も作れるはず」というノーコードツールの大口が、本当に叩けるのかを試すフェアな設定と言えます

04

④文章の指示が動く製品になる

AI開発ワークスペース
  • Blinkは書かれた指示（プロンプト）を実動するデジタルプロダクトに変換するAI開発ワークスペース。コードを書かずにプロンプトだけで開発を進められます
  • コンセプトの核心は「ビジュアルモックアップを超えること」。見た目の画面だけでなく、その裏に本物の技術構造を持った状態までプラットフォームが用意してくれる点です
  • 選んだ形式に応じて、インターフェースとその背後の技術構造の両方を準備可能
05

⑤ホーム画面に並ぶ専用ビルダー群

ビルダー lineup
  • ホーム画面にはフルスタックアプリとモバイルアプリ、そしてWebサイトの専用ビルダーが用意されています
  • Chrome拡張機能は独自の形式で専用ビルダーが存在。他の形式とは異なるフォーマットで生成が行われます
  • エージェントワークスペースはBlink Clawアシスタントのデプロイ専用領域。常時起動のAIエージェントを運用するための区画です
フルスタック モバイル Webサイト Chrome拡張 エージェント
06

⑥見た目だけの画面は本物ではない

なぜ技術構造が必要か
  • 同じワークスペース内で認証（authentication）・ホスティング・初期デプロイまで支援可能。別ツールに持ち出す必要がありません
  • Danielの問題意識: いい感じの画面はリアルなプロダクトの一部に過ぎない。ユーザーにはアカウントも、保存される情報も必要です
  • さらに明確なナビゲーションと、すべての操作の裏にある信頼できる構造があって初めて製品になる——これがBlinkの設計思想と一致する部分です
07

⑦テンプレート・Explore・外部連携

スタートダッシュ機能コネクタ
  • テンプレートとExplore エリアでは既存プロジェクトを閲覧・リミックス可能。すべての詳細を最初から説明したくない人にとって速いスタート地点になります
  • ワークスペースは複数のAIモデルを選択でき、外部サービス用のコネクタも搭載
  • コネクタが特に活きるのは、プロジェクトがメール・ドキュメント・カレンダー・メッセージングツールと連携する必要がある場面です

「この検証では4つのビルドを1つの共有DBにはつながない」——土台の話はここまで。ここからは実際に4つのプロダクトを生成していきます。

ビルド① フルスタックWebアプリ「FounderMatch」

BUILD 1
08

⑧平易な英語のプロンプトでSaaS化を依頼

フルスタックビルダー自然言語開発
  • まずフルスタックアプリビルダーを選び、平易な英語（plain English）で計画を記述。創業者が自分を発信し、互換性のあるパートナーとつながる場、と注文します
  • さらにBlinkへ「このアイデアを保存プロファイルとプレミアムアクセつきダッシュボードを持つリアルなSaaSプロダクトにしてくれ」と依頼
  • プロンプトを送信すると、ツールはインターフェースとその裏の技術構造の両方の準備を開始します
// 依頼のイメージ
FounderMatch を SaaS に:
- 創業者の自己紹介スペース
- 保存されたプロファイル
- プレミアムアクセスつき dashboard
09

⑨初回生成で「完成品サイト」の風格

最初の成果物Stripe連携
  • 最初の結果はすでに完成されたプロダクトサイトに感じられるレベル。サービスの紹介が明瞭で、無料プランと有料プランの料金セクションまで用意されていました
  • Webコンセプトなので、Blinkは決済のためのStripe連携も接続可能。料金ページが絵に描いた餅で終わりません
  • 将来的にプレミアムアクセスを本物のサブスクリプションフローに育てたい場合も、この土台から発展させられます
10

⑩内部ワークスペースと組み込みSEO/AEO

ユーザー体験側SEO/AEO内蔵
  • プラットフォームは実際のユーザー体験のための内部ワークスペースも作成。マッチング領域とメッセージング領域が、アカウント管理・請求設定と並んで配置されます
  • プロジェクトのWebサイトには組み込みのSEOとAEO機能も搭載。検索エンジンやAIアシスタントに対する発見されやすさの改善を、別ツールに持ち出さず同じ場所で行えます
  • レビューの締めに、コード・データベース・バックエンドの各セクションを軽く開いて、画面の裏に何が作られたかを確認しました
11

⑪問題を自動検出して「Fix Issues」

注目機能自動修復
  • プロジェクトをレビュー中、Blinkがあるページの問題（issue）を検出します。自分で探したのではなく、プラットフォーム側が見つけた点がポイントです
  • 「Fix Issues」を選ぶだけで、問題を調査して影響するファイルを自動更新。コードを手作業で検索する必要が一切なしです
  • 修正が完了したら、生成されたビルドへ戻って作業を続行。この「同じワークスペース内で壊れたら直せる」体験が、後の総評でも高く評価されます

「問題を検出 → 調査 → 該当ファイル更新」——ノーコードの弱点だった「壊れた時に詰む」を、Blinkは自動修復でカバーしています。

12

⑫スマホ専用の体験を生成

モバイルビルダー
  • 次はFounderMatchのモバイル版に挑戦。創業者がスマホでプロフィールを閲覧し、より自然に会話を始められる体験を目指します
  • アイデアを記述して生成を放置すると、ワークスペースには主要画面とナビゲーションが準備される進行状況が表示されていきます
  • 生成されたアプリは構造化されたオンボーディングフローから始まります。ユーザーは自分の役割とスキルを選び、マッチングシステムが求める人物像の詳細を追加していく設計です
13

⑬ディスカバリー画面と一貫性のあるUI

初回評価UI一貫性
  • プロフィール完成後に到着するのはディスカバリー画面。各カードには相手の経歴を確認し、相性の良い候補かどうかを判断するのに十分な情報が載っています
  • ビジュアルスタイルはアプリ全体で一貫。ボトムナビゲーションで主要セクション間の移動も簡単です
  • 初回バージョンにしては「整理されていて、スマホで快適に使える」という第一印象。モバイルの使い勝手の最低ラインはしっかりクリアしていました
14

⑭RevenueCat決済と反復改善・公開前チェック

モバイル収益化継続改善
  • モバイル版を収益化したい場合はRevenueCat連携に対応。モバイル特有のサブスクリプションとプレミアムアクセスへの道が用意されています
  • ワークスペースに戻って最初からやり直さずに追加変更を依頼できるのも特徴。初回バージョンは、アイデアの発展とともに少しずつ磨き上げる「基盤」になります
  • ただし公開前には文言の見直しと全画面の入念な確認が依然として必要。準備が整えばBlinkがビルドを用意し、早期テスト・フィードバック用のリンクが渡されます

「初版本はあくまで基盤。公開前に各画面を丁寧に回って確認する」——生成AI時代でも最終チェックは人間の仕事です。

⑮ビルドエラーを乗り越えてブラウザへ

Chrome拡張エラー修正実演
  • 3つ目はChrome拡張機能。公開の創業者ページを分析し、スキャン済みと保存済みのセクションを分けて持つ拡張を依頼します
  • ところが初回ビルドでは技術エラーでダウンロード可能な形式が正しくパッケージされないトラブルが発生。ここでDanielは問題をチャットで記述し、ビルドエラーの調査を依頼しました
  • プラットフォームは必要なファイルを更新して拡張を再ビルド。修正後にポップアップがプレビューで動作することを確認できます
  • zipファイルをダウンロードし、Chromeのデベロッパーモードからインストール。ブラウザに追加しても、Blink内で作ったのと同じシンプルな構造が正しく保たれていました

16

⑯「FounderMatch Ops」— 稼働し続けるアシスタント

最後のビルド常時起動
  • 最後のビルドはBlink Clawエージェント「FounderMatch Ops」。役割はサービスのコミュニケーション側を一日中整理し続けることです
  • 安全面の指示として「承認なしに外部へメッセージを送らない」よう設定。この記述が、編集可能な明確な運用手順つきのエージェントプロファイルに変換されます
  • デプロイ後は専用ワークスペース内でrunning（稼働中）ステータスを獲得。コネクタセクションではコミュニケーションやスケジュール管理サービスを接続先として確認できます
  • デモでは個人のアカウントは接続せず、FounderMatchのコミュニケーション運用をどう管理するか説明を依頼。役割どおりの応答で、問い合わせのレビュー方法や未回答の会話を追跡して日次レポート化する流れを説明してくれました
  • このビルドが示すのはBlinkの別の顔——設定後に動き続けるアシスタントをデプロイできること。単なる画面生成ではなく、運用に残る成果物です

17

⑰一番良かった点: 構造まで作る

高評価ポイント
  • 結果として、1つのFounderMatchアイデアがWeb・モバイル・ブラウザ拡張・エージェントの4形式に展開されました
  • Danielにとって最も有用だったのは、魅力的な画面を生成するだけでなく、技術構造まで準備する点。さらに問題が起きても同じワークスペース内で修正を手伝ってくれることです
  • 認証・ホスティング・Stripe / RevenueCat決済・SEO/AEOと、プロダクトに必要な周辺要素が一式そろう方向性も強み

「見栄えのいい画面を超えて、技術構造の準備と問題修正まで同じワークスペースでできる」——これがこのレビューの核心的な結論です。

18

⑱注意点と最終評価

正直な注意点結論
  • 注意点も明記: 初回バージョンには依然としてレビューが必要。特に本物のユーザー・決済・外部接続を追加する前は入念な確認が欠かせません（Chrome拡張の初回エラーがまさに実例）
  • それでも出発点としての価値は大きい。すべてを手作業で作り直すことなく、複数の形式でアイデアを試せるのは大きな前進です
  • 結論: 技術的なセットアップが障壁になっていた人には、Blinkは一見の価値あり。テストし、改良し、さらに発展させるための実用的なスタート地点をくれる存在です

「技術セットアップが足を引っ張ってきたなら、Blinkは見る価値がある」——Danielからの最後のメッセージでした。
