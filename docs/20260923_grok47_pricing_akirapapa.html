「同じ単価」の意味を正しく読む

PRICING BASICS
01

①「同じ単価」ってどういうこと？

Grok 4.7トークン単価据え置き
  • Grok 4.7はトークン単価が4.6から変わっていない「同じ単価」でのリリースです
  • しかし"同じ単価"と"同じ請求額"はまったくの別物。ここを混同すると請求書を見て驚くことに
  • 請求額は単価×消費トークン数で決まるため、使い方次第で大きく変わります
  • この動画はその料金の読み方の基礎から、実際のコード修正例までを一貫して解説します

「単価が同じ＝今月も同じ請求」ではない！　消費量の変化まで見て初めて料金の話が完結します。

02

②入力・キャッシュ・出力の3建て

入力inputキャッシュ読み取り出力output
  • 入力（input）: プロンプトやコードなど、モデルに送るトークンの料金
  • キャッシュ読み取り（cached）: 一度読んだ内容の再利用は通常入力より安い特別単価
  • 出力（output）: モデルが生成するトークンの料金。3種で最も高いのが一般的
  • 料金計算は「どの桶（バケット）に何トークン落ちたか」を掛けて足すだけ。落ち着けば誰でも計算できます

Cursorでの使い方と利用枠

CURSOR SETTINGS
04

④Cursorの2つの利用枠

Fast枠長文入力枠
  • Cursorには2種類の利用枠があります。1つは高速処理向けのFast
  • もう1つは大量トークンを扱う長文入力用の枠です
  • 「速さを取るか、文脈の長さを取るか」で同じモデルでも消費の仕方が変わる仕組みです
  • 自分の作業スタイルにどちらが合うかを最初に把握しておくと安心です
05

⑤Fastと長文入力の料金差

Fast長文入力
  • Fast: 即答性が高いモード。手軽だが条件に応じた料金の扱いに注意
  • 長文入力: 大きな文脈を丸ごと渡すモード。入力トークンが膨らみやすい分、コスト計算が効いてきます
  • 動画では両者の料金面での違いを丁寧に比較します
  • 「小さな質問はFast、設計全体を見せる時は長文入力」といった使い分けの目安が得られます
06

⑥モデルの変化とベンチマーク

ベンチマーク販売元公表値
  • Grok 4.7ではモデル自体の性能が変化。販売元公表のベンチマーク値が紹介されます
  • ただしモデルごとに推論設定などの条件が異なるため、単純な横比較はできません
  • 動画はベンチ値を「参考値として眺める」姿勢を一貫させています
  • 公式発表: x.ai/news/grok-4-7 で一次情報を当たるのが正攻法です

11

⑪課題：二重計上される料金計算

バグ修正依頼料金計算関数
  • 実例の依頼は「料金計算関数がキャッシュ分を二重に計上している」という修正依頼です
  • 仕様: 入力inputにはキャッシュ済みcachedが含まれる前提の金額計算
  • 要件: 0以上の整数のみ受け付け、cachedがinputを超えたらエラー
  • つまり「input全体に通常単価を付けてしまう」実装はキャッシュ分を二重に請求する誤りになります
12

⑫依頼に使った前提条件

単価の前提100万トークンあたり
  • 未キャッシュ入力: $2 / 1Mトークン
  • キャッシュ読み取り: $0.50 / 1Mトークン（入力の1/4）
  • 出力: $6 / 1Mトークン
  • この3単価を正しい桶に掛けて足す、という単純だが間違えやすい計算が課題の核です

「説明用の計算例」であって実際の請求書ではない、と動画でも注記があります。前提の確認が大事です。

13

⑬Grok 4.7の修正内容

修正の要点未キャッシュ = input - cached
  • 修正の肝は「未キャッシュ入力 = input − cached」として差分に通常単価を付けること
  • キャッシュ分には安い方の単価を充て、二重計上の根源を取り除く実装に置き換えます
  • バリデーション（整数チェック・cached≦input）も要件どおり実装されました
  • Grok Build上でgrok-4.7を指定して実行した応答が字幕映像で紹介されます
# 修正後の計算イメージ
uncached = input - cached          # 二重計上の解消
cost = uncached * IN_PRICE
     + cached   * CACHE_PRICE
     + output   * OUT_PRICE

⑭確認例：計算は合うか

動作確認$0.20 に一致
  • 確認条件: 入力10万・うちキャッシュ8万・出力2万トークン
  • 計算結果は$0.20に一致。修正後の関数が正しく動作しました
  • 動画ではこの検証を制作側で実行したPythonテストとして読みやすく編集して提示
  • 念押し: これは説明用の計算例であり、実際の請求書や今回のモデル実行料金ではありません
# 確認計算（100万トークンあたり単価）
uncached = 100000 - 80000 = 20000
cost = 20000/1M * $2.00      # $0.04
     + 80000/1M * $0.50      # $0.04
     + 20000/1M * $6.00      # $0.12
     = $0.20  ✓
