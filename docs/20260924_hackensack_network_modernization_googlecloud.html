患者ケアを支えるネットワークモダナイゼーション

〜Hackensack Meridian HealthがGoogle Cloudで実現した、ハブアンドスポーク構成とゼロダウンタイム移行の全記録〜

2026年9月23日公開 ｜ Google Cloud Tech ｜ 元動画を見る

背景と課題 — なぜモダナイゼーションが必要だったのか

BACKGROUND
01

①ニュージャージー州が誇る医療機関: HMH

Hackensack Meridian HealthHMH
  • U.S. News & World Reportの2026-2027年評価で臨床優秀性が全国規模で認められています
  • ニュージャージー州で最高位にランクされたがんプログラムを保有
  • 州内No.1の病院であり、ニューヨーク・ニュージャージー都市圏のプレミア医療提供者です

大規模な医療機関だからこそ、ネットワークの安定性はそのまま患者の命に関わる問題なんです！

02

②クラウドエンジニアが語る: 移行の全貌

登壇者: Randy Brokaw
  • HMHのクラウドエンジニア、Randy Brokaw氏が解説を担当
  • オンプレミスのシステムから、シンプルなネットワークインフラへの戦略的な移行の道のりを紹介
  • Google Cloudとのパートナーシップによって進められたモダナイゼーションです

現場のクラウドエンジニアの視点で、「何を課題に感じ、どう解決したか」が語られる貴重な事例紹介です。

03

③ネットワークは患者ケアの生命線

  • 医療機関では、マネージドサービスが常に稼働し続ける常時接続（always-on connectivity）が絶対条件です
  • ネットワークが分断されると、診療そのものと患者データの流通に影響が及びます
  • だからこそHMHは「切り替え中も止めない」移行方針を掲げました

病院のネットワークは「止まらないこと」が使命。この前提がすべての設計判断の出発点になっています。

04

④課題の発端: 分散したランディングゾーン

  • 複数のランディングゾーン（クラウド上の着地環境）が、VPCピアリングで接続されていました
  • 各環境は実質的に互いに分離された孤立した状態だったといいます
  • マネージドサービスをこうした環境横断で動かすには、無理のある構成でした
ランディングゾーンA ランディングゾーンB ランディングゾーンC

環境が増えるほど接続の管理は組み合わせ爆発に。これがモダナイゼーションの直接的なきっかけでした。

05

⑤VPCピアリングの限界: 経由転送ができない

  • VPCピアリングはポイントツーポイントの直接接続のみを提供します
  • あるVPCを経由して別のVPCへ中継するトランジティブルーティング（経由転送）に非対応
  • その結果、HMHは複雑なワークアラウンド（回避策）を迫られていました

「つながってはいるのに、経由して届けられない」。この制限が常に接続を保つうえでの最大の壁でした。

解決アーキテクチャ — Google Cloudが選ばれた理由

SOLUTION
06

⑥Network Connectivity Center: ハブアンドスポークへ

Network Connectivity CenterNCC
  • Google Cloudとのパートナーシップのもと、NCCが提供するハブアンドスポーク構成を採用
  • バラバラだった接続を統一的なモデルにまとめ直しました
// ハブアンドスポークの全体像
ハブ = NCC（中央の接続拠点）
 ├─ スポーク: 各VPC（ランディングゾーン）
 └─ 接続: Dedicated Interconnect ← オンプレミス

「網の目」から「車輪のスポーク」へ。中心を一つにするだけで、経路の見通しが一気に良くなります！

07

⑦オンプレミス接続を1本に集約する

  • オンプレミスからのトラフィックは、単一のDedicated Interconnect（専用相互接続）で受けます
  • この統一モデルを通じて、社内システムの通信がシームレスにクラウドへルーティングされます
  • 回線の乱立を防ぎ、経路の一元管理が可能に
オンプレミス Dedicated Interconnect NCCハブ

入口が一本道になれば、トラフィックの流れも管理もぐっとシンプルになりますね。

08

⑧VPCをスポークとして接続して転送を実現

  • 各VPCをスポークとしてハブにアタッチ
  • これにより集中化されたトランジティブ接続（経由転送）が実現しました
  • ピアリング時代に必要だった複雑なワークアラウンドを排除

「ハブさえ経由すればどこへでも届く」。VPCピアリングで苦労していた経由転送が、標準機能で叶いました。

09

⑨Cloud NGFWでセキュリティを強化する

  • チームはCloud NGFWのインバンドネットワークセキュリティ統合を活用
  • ポイントはアーキテクチャに制約を課すことなく、セキュリティを高められたことです
  • 利便性と安全性を両立する、医療ならではの設計判断が光ります

「安全にするために構成を歪める」ではなく、「構成はそのまま、検査だけ賢く」。次のカードがまさにその仕組みです。

10

⑩深い検査が必要なときだけPalo Altoへ流す

  • このアーキテクチャはトラフィックをインテリジェントにルーティングします
  • 深い検査（ディープインスペクション）が必要な通信のみ、Palo Alto Networksのアプライアンスへ誘導
  • 低リスクのトラフィックはネイティブにそのまま流通し、無駄な負荷を回避します
// インテリジェントな検査ルーティング
if (通信.内容 == 深い検査が必要) {
    経路 → Palo Altoアプライアンス
} else {
    経路 → ネイティブフロー（素通り）
}

全部を検査すると遅く、全部素通りだと危険。「必要なものだけ審査」が最適解でした。

移行の進め方 — 慌てず、検証して、切り替える

MIGRATION
11

⑪まずVPC Flow Logsで通信を丸ごと把握

  • 移行の前に、VLANアタッチメント横断でVPC Flow Logsを収集・活用しました
  • ログからどんなトラフィックがどこへ流れているかをマッピングします
  • 「見えているものは、安全に移せる」。地図作りから始まるのがポイントです

移行の成否は8割が事前調査で決まる——そんな哲学が感じられるステップです。

12

⑫Connectivity Testsで重要経路を特定

Network Intelligence Center
  • Network Intelligence CenterのConnectivity Tests（接続テスト）を活用
  • 移行時に守るべきクリティカルパス（最重要経路）を特定しました
  • テスト結果をもとに、影響範囲を事前に洗い出せます

「全部が大事」では計画が立てられない。絶対に止められない経路からリストアップするのです。

13

⑬Sankeyダイアグラムで流れを見える化

  • 収集した通信の相互作用を、Sankey（サンキー）ダイアグラムで可視化しました
  • 「誰が、どこへ、どれだけ通信しているか」が太さと流れで直感的に把握できます
  • そして変更の前には構成の検証（バリデーション）を実施しました

数字の羅列より、図になった瞬間に「あ、この経路が太いんだな」と腑に落ちる。可視化の力ですね。

14

⑭シームレスな切替: ゼロダウンタイムを達成

移行の成果
  • 事前検証を済ませたうえでカットオーバー（切替）を実施
  • 結果は計画外ダウンタイム ゼロ、そして臨床業務への支障もゼロでした
  • 現場の医療スタッフは移行に気づかないまま、業務を続けられたといいます

病院が営業を続けたままネットワークを作り替える——医療ITの移行として理想的な形です！

成果と次の一歩 — シンプルになった先に見えるもの

RESULTS
15

⑮ランディングゾーンを単一の環境へ統合

  • 今回のモダナイゼーションで、複数あったランディングゾーンを1つの統一された環境に集約しました
  • 管理すべき対象が減り、運用の見通しが大幅に向上
  • 環境ごとにバラバラだった設定やポリシーも、統一的に扱えるように
ゾーンA ゾーンB ゾーンC 単一の統一環境

「たくさんの箱」が「ひとつの箱」に。運用担当者の負担は見る見る減っていったでしょうね。

16

⑯30以上の冗長リソースを廃止できた

削減の実績
  • 統合に伴い、30を超える冗長なネットワークリソースを廃止しました
  • 対象にはレガシーVPNトンネルやCloud Routerなどが含まれます
  • 維持コストと障害の種を、構造ごと取り除いたことになります

「足す」のではなく「引く」ことで強くなる。成熟したインフラ設計のお手本みたいな結果です。

17

⑰次の一手: GeminiでNetOpsエージェント構築

GeminiNetOpsエージェント
  • ネットワークの複雑性が解消したことで、次はGeminiを活用したNetOpsエージェントの構築に着手できます
  • エージェントが担うのは自動トラブルシューティング
  • さらに構成チェックと異常検知も自動化の対象です
// NetOpsエージェントの役割
Gemini → NetOpsエージェント
 ├─ 自動トラブルシューティング
 ├─ 構成チェック
 └─ 異常検知 → プロアクティブな推奨

土台がシンプルになったから、AIによる自動化に挑戦できる。モダナイゼーションの真の狙いはここにあります。

18

⑱先回りの提案が、より良い患者ケアへつながる

  • エージェントは障害が起きてからではなく、事前にプロアクティブ（先回り）な推奨を提供します
  • ネットワークの複雑性を解消することは、患者ケア向上への投資そのものです
  • HMHの事例は、NCC・Dedicated Interconnect・Cloud NGFWを組み合わせた実践的な参考例になります

「止まらないネットワーク」をAIが見守る未来。医療とクラウドの新しい標準形が、ここから始まっています！
