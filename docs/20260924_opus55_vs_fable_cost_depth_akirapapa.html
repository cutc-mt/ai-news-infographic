顔ぶれと値段Claude系列
  • Claude Opus 5.5: 9月22日登場の現行フラッグシップ候補。「0.5」刻みの大きな進化を示す番号です
  • Claude Fable 5.1: Claude家族の最上位（玄人向け）モデル。「ほぼ誰も解けない問題を捌く専門家」と位置づけられてきました

③検証1-B: 値段の差がすべての前提

API単価コスト構造
  • Opus 5.5のAPI単価は入力 $4 / 出力 $20（1Mトークンあたり）。フラッグシップ帯では手頃な方です
  • 対するFable 5.1は最上位モデルらしい高単価。1回のタスクで消費するトークン量も多く、課金レンジが別格です
  • Opus 5.5はさらにキャッシュ利用が約20%値下げ。エージェント運用で効く「キャッシュリード」が安くなるのは大きいです
  • つまりこの対決は「成績がどこまで迫れるか」×「いくら安いか」の掛け算で決まります

「最上位は高い」のは当然。問題は、その差額に見合う成績差があるかどうかです。

⑩「考える深さ」は4段階

Reasoning Effortlow〜max
  • Opus 5.5にはlow / medium / high / maxの「考える深さ（エフォート）」設定があります
  • 深く考えるほど回答の質は上がる反面、消費トークンと所要時間が膨らみ、費用が跳ね上がる仕組みです
  • 公式検証ではOpus 5.5のMediumが前世代Opus 5のMaxを超過。深さ1つ下げても成績を維持できる世代です
  • このグラフが「今日いちばん見てほしいところ」と動画冒頭で強調されます

⑪深さごとの費用カーブ

1タスクあたり費用8倍の壁
  • 出力トークンはlow⇔mediumで約8倍、medium⇔highで約2.7倍に膨らみます。max近くではさらに1.1〜1.4倍上乗せ
  • つまり「少しだけ深く」の代償は大きく、low→mediumの費用段差が最大です
  • グラフでは費用は深さに対して加速度的に立ち上がるカーブを描きます。品質の伸びは緩やかであることもポイントです
  • そのため動画の推奨は基本はmediumかhigh。lowは速さ重視、maxは差を詰める最終手段という使い分けです

maxは「小さい差を埋ける」用。1トークンの価値は徐々に落ちていくので、コスパなら中盤です。

⑫品質の分水嶺はlowとmediumの間

分水嶺LLMジャッジ
  • 生成品質の分水嶺はlowとmediumの間にあります。ここを超えないと成果物のレベルが一段落ちます
  • LLMジャッジによる採点でも、mediumからスコアが立ち上がり、以降は緩やかな上昇という形状です
  • つまり費用対効果のグラフは「mediumで急上昇 → high以降は頭打ち気味」という読み方ができます
  • 3Dゲーム生成の実験などでもmediumが最低ラインという結論が示されます

  • Mediumで前世代のMax超えを達成しているので、「1段浅い設定で同じ点数」が費用削減に直結します
  • Fable 5.1の高単価帯と比べると、1タスクあたりの費用を大幅に抑えられる計算です

⑮検証4: 速さと待ち時間

応答速度Fast Mode
  • Opus 5.5にはファストボード（高速モード）が用意され、通常の2倍の単価で最大2.5倍速の処理が可能です
  • 実測では100 TPS超えの場面もあり、体感でも「速い」と感じるレスポンスです
  • 逆に言えば、深く考えさせる設定ほど待ち時間は伸びるトレードオフがあります
  • Claude Codeなど回転数が命の運用では、この速度面の改善が作業効率に直結します

体感速度は使い心地そのもの。単価2倍・速度2.5倍は、待ち時間が命のタスクでは得です。

⑯検証5-A: 落とし穴を避ける

注意点読みの落とし穴
  • 1つ目の落とし穴: 自社発表ベンチの鵜呑み。外部測定と差がある項目は動画内で併記して判断します
  • 2つ目: 深さ設定の誤用。lowで品質が足りず再試行すれば、かえって費用と時間が膨らむこともあります
  • 3つ目: 全項目でFableに勝ったわけではないこと。Astraが優位な行があるように、得意・不得意は残ります
  • 結論を出す前に、自分の主なタスクがどの行に相当するかを照らし合わせるのが安全です

⑰検証5-B: 判定「Fableはまだ要る」

いちばん深いmax最後の切り札
  • 結論から言うと、答えは「Fable 5.1はまだ要る」です。ただし立ち位置は変わりました
  • Opus 5.5の成績が良いため、Fableの活躍場面は「最後の切り札」に絞られました。普段使いはOpus 5.5で十分です
  • 難しい多段タスクでは式が逆転し、他モデルが到達できない地点へ到達する識別力がFableには残っています
  • つまり「皆が詰まった時」に取っておく専門家がFable 5.1。毎日は雇わない、というのが検証5の判定です

全てをOpusに任せるのではなく、Fableは「ここぞ」で抜く。それが費用面での最適解です。

18

⑱まとめ: 深ければ良い、ではない

動画の結論深さ×費用で選ぶ
  • 動画のまとめは「深ければ良い、ではない」。深さと費用のグラフを読んで選ぶのが新しい世代の使い方です
  • 実践レシピ: 普段はOpus 5.5のmedium/high、速度が欲しい時はlowかFast Mode、詰まった時だけFable 5.1かmax
  • Opus 5.5はコーディング・ナレッジワーク・PC操作でFable 5.1超えを果たし、コスト面でも有利です
  • まずは自分の定番タスクで深さを変えて費用を比べてみることから始めるのがおすすめです

モデル選びは「どれが最強か」ではなく「どの深さで止めるか」の時代です。
