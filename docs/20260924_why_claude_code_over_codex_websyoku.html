推し理由その1：権限とセキュリティ

STEP 1
04

④「あなたのPCで動く」からこそ権限が鍵

講師が常に強調する大前提：Claude Codeは自分のPC上で動くエージェントであり、ファイルの読み書き・コマンド実行・ネット通信まで行えます。

  • 強力さの裏返しがリスク。「何を許すか」をユーザーが制御できるかが初心者向けツールの生命線です。
  • 講座カリキュラムにも「押す前に意味を理解すべきコマンド」や取り消せない操作の教育が明記されています。
$ claude → ファイル読み書き / コマンド実行 / ネット通信
05

⑤allow / ask / deny の権限モデル

Claude Codeはallow（許可）/ ask（確認）/ deny（禁止）の3ルールで操作を制御し、評価順はdeny ＞ ask ＞ allow。設定はsettings.jsonで管理します。

  • 「読み取りは許可、変更は確認、危険な操作は禁止」といった段階的なスターター設定を自分で組めるのが特徴です。
  • 講師は「禁止（deny）だけでは塞ぎきれない落とし穴」も指摘——権限設計の考え方そのものを教えます。
$ /permissions → deny > ask > allow の順で評価
06

⑥隔離の選択肢が実践しやすい

講師のセキュリティ講座は多層防御が柱。Claude CodeにはSandbox（OSレベルの壁）に加え、Docker / Dev Container / VM / GitHub Codespaces での隔離運用という「もう一枚の壁」が用意されています。

  • 「壊れてもいい使い捨て環境」で危険な作業を回す実践手法が講座の中心テーマの一つ。
  • auto承認モードや--dangerously-skip-permissions の罠についても言及される文脈です。

安全は「設定」「隔離」「あなたの確認」の3層で守る——講師の口癖が推奨理由に直結しています。

⑨初心者を支える「考え方」の教育

「何も設定しないで使う」のではなく、最小権限・ゼロトラスト・多層防御といった大原則と一緒に使い始められる文化があります。

  • AIに実行させる前の「これ何するの？習慣」など、確認の作法まで含めた教育が行われています。
  • 便利さと安全のトレードオフを理解した上で使う——非エンジニアがAIを使いこなす前提が整っています。

ツールの性能差よりも「迷わず安全に始められるか」を重視するのがセキュリティ専門家の選び方です。

実践：はじめる前のセキュリティ対策

PRACTICE
13

⑬settings.json で守る

講師の講座カリキュラムに沿うと、最初に取り組むべきはsettings.jsonによる権限設定です。

  • 設定はユーザー／プロジェクト／ローカル／管理者の4階層。Gitで共有すべき設定・してはいけない設定の判別が最初の関門です。
  • 実習の定番は「.env（機密情報）の読み取りをdenyに設定」——顧客データ・会社の情報を守る基本操作です。
$ /permissions で現状確認 → .env を deny に
14

⑭APIキーと課金のガードレール

AIエージェント運用での事故は情報漏洩と課金事故の2本柱。講座では両方の対策が用意されています。

  • APIキーは1Passwordなどシークレットマネージャで管理し、平文で置かない。
  • 利用上限とアラート設定で想定外の課金を防ぐ——実習課題にもなっています。
  • 万一の漏洩時はキーローテーション（使い回さない運用）で被害を封じ込めます。
15

⑮渡していい情報・ダメな情報

「顧客情報・社外秘・契約書をチャット欄に貼らない」——これが講師が繰り返す鉄則です。

  • 業務データを扱うサービス選びではデータ保持・学習設定を必ず確認。
  • どうしても渡す必要がある場合は機密情報のマスク化を先行させます。
  • プロンプト・インジェクションを「防ぎきれない前提」で、被害を封じ込める設計思想へ。

ツール選びより先に「入れていい情報」の線引きを。これがセキュリティ専門家の第一歩です。
