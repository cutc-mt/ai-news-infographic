Runwayの起源 — 創作ツールから動画モデルへ

エピソードの核心

  • ホスト swyxVibhu がRunway共同創業者を直撃
  • 「動画ジェネレーター」の先にある世界シミュレーター構想
  • 動画生成 → 物理シミュレーション → ロボット → OSという拡張路線
  • Gen-1からGen-4.5までの進化の全貌
「動画生成は世界シミュレーションへの道」— これが今回の主張だ!

実験的ツールの出発点

  • 映画・デザイン業界向けの実験的クリエイティブツールから始動
  • 現場のクリエイターのワークフローから機能を発見
  • ツール企業からフロンティアモデル企業へ転身
  • 生成動画への最早期の賭け(Bet)の一つ
「ツールを作りながら、いつかモデルそのものを作る」— 逆順じゃないのが面白い

1,000基のA100という大賭け

  • 動画研究のキックオフに1,000×A100クラスタを先行投入
  • 収益化前に巨大GPU資源を確保したアーリーベット
  • 計算資源の確保が研究の加速装置に
  • 「スケールがすべてを解決する」時代の先回り
売れる前から1,000基…! この度胸が今のRunwayの起点

Stable Diffusionストーリー

  • RunwayはStable Diffusion開発に深く関与したと語る
  • 画像生成の民主化・公開展開を推進
  • 潜在拡散モデル(Latent Diffusion)研究との近さが財産に
  • 画像で得た知見がそのまま動画モデルへ継承
基盤モデル研究の「現場」にいた経験が、Genシリーズの高速開発を支えた
2

Genシリーズの系譜 — 週末ハックからSoraショックへ

text-to-videoだけでは足りない

  • プロの創作では制御性・一貫性が命
  • テキストプロンプトだけでは監督の意図を運べない
  • 参照画像・構図・スタイル・被写体の指定が必須に
  • マルチモーダル入力への時代へ
「美しい動画」より「意図どおりの動画」— プロが求めるのはこちら

Gen-2 — 週末ハックから誕生

  • テキスト・深度(Depth)・動画を組み合わせた週末の実験
  • 画像+深度マップから動く映像を生み出す構成
  • 遊びのハックが製品Gen-2の核に成長
  • 「小さく試して速く世に出す」文化の象徴
週末の実験が看板製品になる…ハックの神様的な誕生秘話!

カメラ操作 → 世界モデルへの道

  • 視点制御(Camera Control)はシーンの3D理解を要求する
  • 「レンズを動かす」=「世界を動かす」ことに等しい
  • Gen-4系のカメラ制御機能へと発展したと報じられている
  • 制御性の追求が自然と世界モデル研究へ接続
カメラを動かすには空間全体を理解しないといけない — ここが分岐点!

Gen-1 → Gen-4.5の進化

  • Gen-1Gen-2Gen-3Gen-4Gen-4.5 の系譜
  • キャラクター・環境の一貫性が世代ごとに向上
  • 物理整合性(光・質感・運動)の質が向上したとされる
  • 映画製作向けの実用機能群が拡大
各世代で「撮れる映像のジャンル」が一段ずつ広がってきた
3

世界モデルという賭け — 物理を学ぶ動画

言語ではなく世界から学ぶ

  • テキストでは捉えられない物理・空間・因果が存在
  • 動画は「世界の観測データ」そのもの
  • 人間は言葉より先に世界との相互作用で学習する
  • テキスト・画像・動画以外のモダリティ学習の可能性
言語モデルが「読んで」学んだように、世界モデルは「見て動いて」学ぶ

スケーリングは物理を教えるか

  • 問い: 動画予測のスケーリングだけで物理法則を学べるか?
  • 物理エンジンを明示的に組み込まないアプローチ
  • Anastasisは楽観的と述べている
  • スケール vs 構造化の論争は業界全体の火種
「規模が十分なら物理は浮かび上がる」— 根拠は画像モデルの前例

Soraショック — 存亡危機

  • OpenAIがSoraを公開、「Runwayは終わった」との宣言が飛び交う
  • チーム内部に走った危機感と緊迫
  • Gen-3を約3ヶ月の突貱いで約10倍にスケール
  • 危機が組織の集中力を極限まで引き上げた
「終わった」と言われて3ヶ月で10倍…実話の逆転劇

リアルタイム生成の必然性

  • レイテンシが下がれば対話的体験が生まれる
  • 推論コスト低下とアーキテクチャ進化が追い風
  • ゲーム・シミュレーションとの融合が見えてくる
  • 「リアルタイムは避けられない」との見解
生成が瞬間に届けば、それはもう「触れる世界」になる
4

Neural OSとRobotics — ピクセルが世界になる

Interface World Models

  • HTMLCSSReactを書かないソフトウェア
  • UIをピクセルとして直接生成
  • 「コードを生成」ではなく「見た目を生成」という反転
  • ソフトウェアのレンダリング概念そのものの再定義
// 従来のUI開発
const App = () => <Button onClick={save} />;

// Interface World Model 発想
render("ボタン付きの設定画面", user_intent)
  → ピクセル列として直接出力
コードを書くAIではなく、画面そのものを描くAI — 発想の転換!

Neural OS — 完全ニューラルなOS

  • アプリ・ウィンドウ・入出力がすべてモデルの生成に
  • 既存のソフトウェアスタックの置き換え構想
  • シェルもファイルも「会話と映像」に溶けていく
  • 実現には数十単位の道程 — しかし方向は定まった
OSの行き着く先は「夢を見る計算機」かもしれない…先の展望カードへ続く

ロボティクスのための世界モデル

  • 世界モデルをロボットのシミュレータとして活用
  • シミュレーション内で操作ポリシーを学習
  • Sim-Judge: 採点モデルが軌道を評価すると報じられている
  • RunwayのGEMA(World Action Models)研究が知られる
// World Action Model の疑似フロー
for episode in simulator:
    traj = policy.observe_and_act()
    score = SimJudge(traj)   // 別モデルが採点
    policy.update(traj, score)
映像モデルがそのままロボットの脳と練習場になる — 大胆な再利用!

第三者視点動画という宝庫

  • インターネット上の第三者視点(三人称)動画は膨大
  • 人の手の操作映像 = ロボット知能の最大の訓練源になりうる
  • 三人称→一人称の視点変換が鍵
  • 動画モデル → World Action Models(ロボットポリシー)へ
YouTubeは人類最大の「お手本動画」データセット、という視点!

未来への視点 — 明晰夢テストとオムニモデル

Lucid Dream Test(明晰夢テスト)

  • 世界モデルの成熟度を測るAnastasisの思考実験
  • 夢の中で「これは夢」と気づけるか?
  • 気づいた上で世界を自在に操作できるか?
  • モデル内世界を操れれば「十分に良い」世界モデル
ベンチマーク点数より詩的なこの判定基準が個人的に一番好き!

Video Agents・Omni Models・そして未来

  • Video Agents: 動画を「読み・操作する」エージェント
  • オーケストレーションはやがてモデル内部へ(omni models)
  • オープンソース世界モデルと中国発モデルのグローバル競争
  • 制御性が上がり、アーティストの反応も変化中
  • Physical AI・科学シミュレーションへの波及
動画・ロボット・OS・科学 — すべてが一つの世界モデルに収束するかもしれない
