CONCEPT

WebMCPとは何か

  • Web + MCP を組み合わせた造語的な概念
  • Webサイトそのものが MCPサーバー として振る舞う
  • サイトが自らの機能をAIに「公開」する発想の転換
  • 公開するもの: 検索・操作・データ取得などの サイト機能
従来は「AIがサイトを使う」だったが、
WebMCPでは「サイトがAIに奉仕する」…ではなく
対等なインターフェースを提供する!
BEFORE

従来の常識: AIは画面を「操作」する

  • AIエージェントは UI自動操作 でクリック・入力を代行
  • スクリーンショット認識や DOM読み取り で画面を推測
  • 課題: 操作が 遅い ・デザイン変更で 壊れやすい
  • 人間向けUIを経由するため 無駄なコスト が発生
「ボタンを探してクリック」の繰り返し…
AIにとっては 遠回りな通信 だった!
SHIFT

パラダイム転換: 直接呼び出し

  • 画面操作 経由 → 機能を 直接call
  • 対象は 表示中のWebページ — その場で完結
  • UI描画を待たないので 高速 かつ 安定
  • Webページが AI向けAPI を内蔵する形に進化
人間用UIとAI用IFの 二重化!
ページが「喋る」時代の幕開け⚡
BASE

前提知識: MCPとは

  • Model Context Protocol の略
  • AIと外部ツールを繋ぐ 共通プロトコル
  • 主な公開対象: Tools Resources Prompts
  • 従来のMCPサーバーはローカルアプリやAPI側に設置
このMCPを Webブラウザ内 に持ち込むのがWebMCP!
USBケーブルではなくWeb標準で接続するイメージ🔌

セクション2: 仕組みを分解

カード 6-10
CORE TECH

中核技術: MCP over window.postMessage

  • WebMCP提案の核心は postMessage によるMCP通信
  • ブラウザ標準APIのみで実現 — 特別な拡張不要
  • AIクライアント ↔ iframe内サーバー間で 双方向メッセージ
  • 既存のオリジン分離モデルを そのまま活用
新しい通信路を作らず、
30年物のWebの土台の上に築くのがミソ!
PROTOCOL

メッセージ形式: JSON-RPC 2.0

  • MCPのメッセージは JSON-RPC 2.0 形式
  • 主要メソッド: initialize → tools/list → tools/call
  • Request / Response / Notification の3種
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "searchProducts",
    "arguments": { "query": "..." }
  }
}
まず initialize で握手してから
ツール一覧を取得 → 呼び出し、という流れ🤝
SERVER SIDE

WebMCPサーバー: iframeで埋め込む

  • サイトはWebMCPサーバー実装ページを 非表示iframe で読み込む
  • サーバーはツール群を定義して 待機
  • 親ページ側は WebMCPクライアント を設置
  • 配布形態: スクリプト埋め込み で既存サイトに追加可能
iframeは 見えないところ で待機。
人間の画面は今まで通り、裏でAI用の窓口が開く🚪
CLIENT SIDE

AIエージェント側: クライアントの役割

  • ページ訪問時に ツール一覧を発見
  • ツール名・説明文を読んで 使い方を推論
  • 必要になったら tools/call で直接実行
  • 結果を受け取り、会話やタスクに 即反映
AIから見るとWeb全体が
巨大な工具箱に見える未来🧰
SECURITY

セキュリティ: 権限と同意

  • ユーザーの同意 なく勝手にツールは実行されない設計
  • postMessageの オリジン検証 が第一防御線
  • iframeの サンドボックス 権限設計と併用
  • 悪意あるツール公開・なりすまし対策が 標準化の論点
「AIが勝手に課金ボタンを押す」を防ぐには
同意フローの設計が鍵🔑

セクション4: 実践と展望

カード 15-18
HANDS-ON

開発者向け: 実装の要点

  • WebMCPサーバーページを用意し iframe で読み込む
  • message イベントでJSON-RPCを受けて応答
  • ツール定義には 説明文 が超重要 — AIが読んで判断
// iframe内サーバーの骨子イメージ
window.addEventListener('message', (e) => {
  const msg = e.data; // JSON-RPC 2.0
  if (msg.method === 'tools/list') {
    e.source.postMessage({
      jsonrpc: '2.0', id: msg.id,
      result: { tools: [/* ... */] }
    }, e.origin);
  }
});
ツールの説明文は AI向けUXライティング!
雑に書くとAIが誤動作します✍️
USE CASES

ユースケース: 何ができる?

  • EC: 検索・絞り込み・カート追加 を会話で完結
  • 予約: 空き状況確認と 予約確定 を直接実行
  • フォーム: 面倒な入力を AIが代行
  • 情報サイト: 記事検索・構造化データ提供
  • 社内ツール: ブラウザ業務の 自動化
「この予約取っといて」の一言で済む世界。
音声×WebMCPとの相性も抜群🎙️
CHALLENGES

課題: 解決すべき山

  • 同意UI の標準化 — どこで・どう許可を取るか
  • 決済など 高リスク操作 の保護レベル
  • 仕様が流動的 — 破壊的変更 の可能性
  • 普及の鶏卵問題: 対応サイト が増えるか
  • ツールの品質 — 説明文誤りによる AIの誤用
今はまだ 登山口 の段階。
