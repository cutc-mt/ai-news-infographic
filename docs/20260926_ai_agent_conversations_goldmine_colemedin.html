気づき — あなたのマシンに「金脈」が眠っている

動画の核心

  • 主張: 最大のエージェント強化はもう手元にある
  • コーディングエージェントとの会話は全てファイルとして保存される
  • しかしほぼ誰も活用していない
  • これこそ時間とともにエージェントを改善する最良の方法
「新しいツールを買う必要はない — 自分との対話履歴こそが教材だ!」

何が保存されているのか

  • 送った全てのプロンプト
  • エージェントの全ツール呼び出しとその結果
  • だから失敗の記録まで丸ごと残る
  • 成功も失敗も含めた完璧な改善データセット
# ~/.claude/projects/ などに蓄積される
2026-09-20 リファクタリング会話 142ターン
2026-09-22 デバッグ会話 87ターン・3失敗

なぜ活用されていないのか

  • 保存先がローカルの隠しディレクトリで見えにくい
  • 会話は巨大なJSONで人間が読むには辛い
  • 検索・集計する仕組みがないと宝の持ち腐れ
  • 本動画はその活用ロードマップを2段階で提示
データは既にある — あとは掘り出す道具だけ
2

第一歩 — たった1プロンプトで始める改善サイクル

シンプルな方法とは

  • 1つのプロンプトで完結する手軽さ
  • 過去の会話をエージェント自身に読み込ませて分析
  • 改善提案の対象はruleshooksskills
  • 公開されているのはopportunity-scan skill
# やること(イメージ)
> 過去の会話を分析して、私の
  rules / hooks / skills への
  改善案トップN を出して

分析で見えてくるもの

  • 何度も繰り返した同じ説明・同じ修正
  • 頻発する失敗パターンとその背景
  • 毎回指示している暗黙のルール
  • これらはrules化・skill化すべき候補
「何度も言ったこと」は1回書けばいい — それがルール

シンプルな方法の限界

  • 会話ファイルを全部読むとコンテキストが圧迫
  • 毎回ゼロから読むのでトークンコストが増大
  • 「昔こうした」のような横断検索・集計は不得手
  • 続けるならデータベースが必要に
最初の一歩には最適 — でもスケールすると痛い
3

フル構築 — Databricksに構造化テーブルを築く

CLIとMCPサーバー導入

  • まずDatabricks CLIをインストール
  • 続けてMCP Serverをセットアップ
  • 全OS向けの手順が公式ドキュメントに公開
  • 今回の構成はFree Editionで完結(無料・クレカ不要)
# インストール(公式ドキュメント参照)
$ brew install databricks  # macOS例
$ databricks auth login
$ databricks mcp add ...

会話をアップロード

  • ローカルの会話ファイルをまとめて取得
  • 機微情報はアップ前にスクラブ(除去)しておく
  • 生データをDatabricksへ投入
  • この作業自体もコーディングエージェントに任せるのが流儀
クラウドに置く前に中身を確認 — 拡張機能の秘匿情報は要注意

Genieがテーブルを構築

  • Databricks Genieが生データを解析
  • 会話・メッセージ・ツール呼び出しを構造化テーブルへ自動整形
  • 以後はSQLでクエリ可能な状態に
  • スキーマ設計もよしなにやってくれるのが強い
# 構造化のイメージ
conversations(会話単位)
  └ messages(発言・ツール呼び出し)
      └ tool_results(実行結果)
4

実戦投入 — Claude CodeからMCP経由で履歴を問う

会話履歴を“語りかける”

  • Claude CodeからMCP経由でDBに接続
  • 「過去にこの機能をどう実装した?」と自然言語で質問
  • エージェントが必要な行だけSQLで取得
  • 判断材料が事実に基づくようになる
「たぶん」が「前回はこうだった」に変わる — これが効く

トークン効率の勝利

  • 生JSONを丸読みと違い必要な部分だけ取得
  • 構造化済みなのでSQLで絞り込みが効く
  • 結果、超トークン効率になると強調
  • 履歴が増えてもコストは爆発しない設計
# トークン消費のイメージ
全ファイル読み込み 500,000+ tokens
SQLで絞り込み   2,000 tokens

データ扱いの注意点

  • 「訓練に不使用」の表明は有料版の規約に基づく
  • Free Editionはサービス改善での利用を許諾
  • だから機密は事前にスクラブが前提
  • その除去作業もエージェントに任せるのが今回の流儀
無料枠の規約はこまめに確認 — 載せる前に読む習慣を
5

実際の成果 — 分析から生まれたAIレイヤーの変更

分析が変えたAIレイヤー

  • 会話分析を踏まえたrulesの更新
  • 定型作業を捕まえたhooksの追加
  • 繰り返し需要のskillsの新設・改善
  • 変更はエージェントの行動原理そのものへの手入れ
「思い付きでいじる」から「証拠で直す」への転換だ

全変更を“本採用”

  • 今回の変更は1つ残らず採用と明言
  • 分析由来の改善は外れが少ない
  • 実際の自分のワークフロー由来だから再現性が高い
  • 「自分用のチューニング」としての価値が大きい

改善は“サイクル”になる

  • 会話が蓄積される
  • 定期的に分析して改善を提案させる
  • rules / hooks / skillsを更新
  • 次の会話がより賢く — 複利で効くループの完成
# 改善ループ
会話 → 分析 → 改善 → より良い会話
  ↑__________________________|
