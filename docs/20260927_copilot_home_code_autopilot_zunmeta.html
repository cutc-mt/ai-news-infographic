Microsoft Copilot刷新
〜会話のあとに残る仕事はどう変わる？ 18のポイント〜

新しいCopilotの「Home・Code・Autopilot」を、会議準備という一つの用事から見る解剖講座！ Office文書の共同編集・小さな業務アプリ・継続する役割の違いを解説します

2026年9月27日  |  ずんめたラボ  |  今知っておきたいAI

なぜ「新しいCopilot」なのか

①

「会話のあとに残る仕事」とは

  • AIに会議メモをまとめてもらっても、まだ準備は終わらない
  • 資料への貼り直しや担当・締め切りの表起こしが毎回残る
  • 欲しかったのは返事ではなく、そのまま使える形だった
  • 次の会議でも、同じ「引っ越し作業」を繰り返すことに
ずんだもん「まとめは終わったのに、仕事が終わっていないのだ……」
②

新しいCopilotの3つの入り口

  • 資料を整える入り口が Copilot Home
  • 小さな仕事の道具を作る入り口が Copilot Code
  • 役割と目標を渡して継続して働くのが Copilot Autopilot
  • HomeとCodeは段階提供、Autopilotは限定試験。全員がすぐ使える発表ではない
めたん「会話の横で資料を直して、その後の作業まで繋がる設計なのね」

Copilot HomeとOffice編集

③

Homeの2つの顔: チャットとコワーク

  • 会話で相談する チャット と、作業を任せる コワーク（Cowork） がHomeに集まる
  • 「メモから決定事項を抜き出して」なら会話が中心。抜けていればその場でもう1度聞ける
  • 資料という完成物まで作りたい場面では、コワークの出番
  • 入り口の得意な使い方として、「質問」と「仕事の移任」を分けて考える
「聞きたい」のか「作ってほしい」のかで、頼み方が変わるのだ
④

コワークは「手順ごと」任せる

  • メモを整理して次回用の説明資料にして、項目をまとめて渡す
  • 資料を作る途中の手順も任せる。複数の手順を進める役割はAIが担う
  • 途中の手順を見て、追加の指示や中断もできる。任せたら黙って待つしかないわけではない
  • 完成したものを見て直すやり取りも、仕事の一部
  • 決まったことと未決のことを分けた仕様を先に伝えると、使うメモの範囲も伝えやすい
完成物をまたワードに貼り直すなら、「引っ越し」は残ってしまうのだ
⑤

Office文書を会話の隣で編集

  • Word・Excel・PowerPoint の文章を、会話の隣で作成・更新
  • チャットの返事に「資料っぽい見た目」がつくだけではない
  • 編集できる本物の文書・表・スライドとして生成（Microsoftの説明）
  • すでにチームが使っているファイルを作業の続きに使える設計
会話の返事をコピーして持っていく、あの往復が減るといいわね
⑥

「完成版その2」からの卒業

  • 完成版・その2・その3・最終版……というファイル名の増殖に悩んでいた
  • 会話の中でファイルを直接更新していく方向
  • どれが正しい版か探す手間が減り、会議準備の見通しが立てやすくなる
ずんだもん「それで何個目の『最終版』なのだ？」
⑦

会話とOffice編集を「同期」

  • 会話とOfficeファイルの編集を同期するという発表
  • 同僚が加えた変更も反映しながら、同じ資料を一緒に仕上げられる
  • 例:「決定事項の文章を短くして」と会話で頼むと、その横で資料自体が更新される
  • 文章を受け取ってから貼る場所を探す往復が減る、という期待
メモを整理している間に、先輩が説明を直せるのは助かるのだ
⑧

見た目が整う≠内容が正しい

  • 修正内容が正しいかどうかは、自分で確認する必要がある
  • 未決だった予算を「決定済み」のように書かれたら困る
  • 元のメモと照らして、決定と提案を取り違えていないか見る
  • 見た目が整ったことと、会議の内容が正確なことは別の話
  • コピーの確認に使っていた手間を、中身の確認に回したい
めたん「整った見た目に安心して、数字を信じないようにするのよ」

Copilot Codeと管理の仕組み

⑨

Code: 道具を言葉で作る

  • アプリ・進捗表・情報をまとめる画面・作業の自動化を、説明して作る入り口
  • 「コード」という名前だが、入ってはいけない部屋ではない
  • 専門の開発者だけに道具作りを限らない考え方。自然な言葉で動きや表示を伝えて形にする
  • 例:「担当と締め切りを一覧にして、未完了だけ見たい」
  • 会議のたびに全員に読んで終わったか聞く手間を見直せそう
必要な項目と操作が見える道具を、お願いして作ってもらうのだ
⑩

「作る前に」考えること

  • 表で十分なら、最初から新しいアプリを増やす必要はない
  • Excelの表で足りるのに立派な道具を作るのは遠回り
  • 同じ絞り込みや集計を繰り返すなら、専用の道具にする意味が出てくる
  • 「何が作れるか」より、毎回どんな操作をしているかを見る
  • 文書に情報を残すことと、情報を何度も操作することを分けて考える
作れるものを増やすより、繰り返す手間を見つける方が先だと思うわ
⑪

GitHub Copilotとの関係

  • Codeは開発者向け GitHub Copilot と同じ基盤技術を使するとされる
  • ただし開発者の道具がそのまま全部自分の画面に来るわけではない
  • 名前が似ていても、操作方法まで同じとは限らない
  • Coworkにもすでに小さなアプリを作る機能はある
  • 今回は「アプリが初めて作れる」より、道具作りの入り口を前に出した話
別の利用場面に向けた入り口だと考えると分かりやすいのね
⑫

会社で使い続けるための管理

  • 会社で使うなら 誰が開けるか・どの情報に繋がるか を決める必要がある
  • 作ったものを動かし続ける場所と、管理の仕組みも必要
  • 会議用の小さな道具でも、置き場所と鍵が要るのだ
自分の画面で動いたからといって、そのまま同僚に渡せるわけではないのだ
⑬

Managed Runtime

  • Microsoftがマネージドランタイムを発表
  • Microsoftがクラウドで運用し、会社の管理ルールの元でアプリを動かす仕組み
  • 会社のパソコンのどれかをずっとつけておく、という話ではない
  • 共有やデータへの接続などを、毎回1から用意しなくて済む狙い
  • 作って終わりではなく、同僚が使うところまで見ている
  • この仕組みも試験提供。使える範囲は会社の設定と合わせて確認を
まずは小さく試して、誰と使うかを決めるのが良さそうなのだ

Copilot Autopilot

⑭

Autopilotとは

  • 継続する役割を任せる入り口。以前はスカウトと呼ばれていた
  • 名前と役割を与えて、話題を追ったり継続する作業を進めたりする
  • 記憶や作業場所を持って、途中から仕事を再開できる（発表の説明）
  • TeamsやOutlookなど、普段の仕事の場所に関わりながら働く想定
  • 公式には取引先の見直し業務で、予定や連絡を進める例
毎回最初から全部の説明を渡す相手とは、違う感じなのだ
⑮

クラウドで動き続ける

  • 自分が画面を閉じたら仕事も全部止まる、というわけではない
  • Autopilotはクラウドで動き、人が離れている間も続ける
  • 戻るたびに仕事を最初からやり直さなくて済む
  • ただし定期実行そのものが初登場ではない。Copilot Studioにも決まった時刻に動かす機能はある
  • 「1回切り」「定期実行」との区別で間違えないように。Autopilotは役割や目標を持つ継続的な相手
新しい名前だけでなく、どんな役割が増えたかを見たいのね

提供条件・料金・選び方

⑯

提供条件の注意点

  • HomeとCodeは、新機能を先に試す フロンティア枠 からの段階提供
  • 会社でCopilotを契約していても、表示されるとは限らない
  • 対象のアカウントや状況、管理者の設定の確認が必要
  • Autopilotは限られた参加者向けの試験を広げる段階
  • 個人向け: Codeはプレミアム／プロにも段階試験提供の予定。企業向けと個人向けは別物なので、無料アカウントで使えると思い込まない
機能名だけでなく、自分の契約と提供対象を見るのだ
⑰

料金は「月額＋使用量」の2本立て

  • 日常の会話や文書作業は、利用者ごとの月額契約が土台
  • ただし月額にも利用上限の扱いがあり、無制限とは言えない
  • コワーク・コード・オートパイロットなどの作業は、使った量に応じる課金
  • その費用を測る単位が Copilot Credits。月額とは別に使用量を見る考え方
  • 企業向けは、管理者が支出の設定をするまで課金対象サービスは無効。設定前には請求されない（Microsoftの説明）
  • 組織・グループの予算や利用者ごとの上限を管理し、使う人が利用量と残りを見られる表示も
「この会議ならいくら」という一律の料金は、ここでは約束できないわね
⑱

選び方の軸は「変えたい仕事」

  • AIにできることの一覧より、自分の仕事のどこを変えたいかが判断の軸
  • 全部の機能を試すより、1番手間のかかる工程から1つ選ぶ。合わなければ待って良い
  • 文章の手直しが負担なら → まず共同編集が役に立つか見る
  • 毎回同じ集計に時間を使うなら → 小さな道具を考える理由がある
  • 次回まで追い続ける仕事なら → 継続する役割（Autopilot）を検討
  • まず会議が終わった後に残る手作業を、1つ書き出してみるのだ
名前が増えたというより、「資料・道具・続く仕事」を見分ける話だったのだ
