『Claude Opus 5.5』で2時間弱 — 自分専用スライドツール「ソダスラ」誕生

パワポは「作る」、ソダスラは「育てる」— いけとも流“さよならPowerPoint”を独自再構築【前編】
2026年9月29日 ・ 動画を見る

①開幕デモ: パワポでも“動く”

  • 冒頭で披露したのはPowerPointで開いたスライド — クリックすると一覧が1本ずつ出て、立方体が回り続けるデモ。
  • AIにHTMLで作らせた動くスライドを自作ツールでパワポに書き出したら、動きごと再生できた。
  • このナレーションはGemini 3.8 Flash TTSで作ったれん学長の声のクローン。
「さよならPowerPoint」の実演から始まり、声まで自分クローン — 冒頭から未来が来ている！

②きっかけ: いけともさんの動画

  • きっかけはいけともさん(池田朋弘さん)の「さよならPowerPoint」実況 — GPT-6で専用スライドツールを自作した話。
  • 「めちゃくちゃ使い勝手良さそう、私もやってみたい」→ Claude Opus 5.5で専用ツール自作に挑戦。
  • ソダスラはれん学長が独自に作ったもので、いけともさんとは関係なく公認も受けていない(概要欄で明記)。
「いけともさんの動画がなかったらソダスラは生まれなかった」— 考え方を土台に感謝を伝える回！

③なぜパワポをやめるのか

  • 理由その1AIと作りにくい — AIが考えた表現をスライドにするまでに操作・調整・仕上げの手間が挟まる。
  • パワポ形式はAIからデータが扱いにくく、動きのある表現も作りにくい。
  • 理由その2判断が残らない — どこをどう直したかファイルに残らない。判断の記録こそ次の資料の質を上げる材料になる。
「完成ファイル」より「判断の履歴」が資産になる — これがさよならPowerPointの核心！

④依頼術: 動画を110要素へ分解

  • 動画2本を2秒ごとに画面で切り出し、映った画面と話した内容の両方から要素を110個拾い出し。
  • 機能の98個を6つのかたまりに整理: 画面23・判断7・話した記録7・AIと操作13・型と表現22・配布と運用26。
  • スクショ撮影→要素整理→設計書→実装までOpus 5.5が実行。「既存HTMLに囚われず、より良い実装があればそちらで」と指示。
参考動画を“仕様書”に変換する発想 — エージェント依頼の教科書的な進め方！

⑤誕生: 名前は「ソダスラ」

  • 名前の由来は「育つAIスライド」 — 育つ(そだつ)+スライドの4音「ソダスラ」。
  • ロゴとキャラそすら君も作成。頭の緑の輪は“育つループ”(無限大)を表現。
  • Opus 5.5のエージェントたちに並行生成させ、依頼から約1時間半・設計書から約1時間20分で初版が動いた。
タイトルの「2時間弱」は嘘じゃない — 設計書ありきなら1時間20分で走り出す！

⑥思想: 使うほど育つループウェア

  • 中心にあるのは「使えば使うほど育つループウェア」という考え方。
  • 作る → 話す → 記録する → 磨く をぐるぐる回す道具のこと。
  • AIが作り、人が採用・却下と理由を記録し、次の指示を良くする。完成ファイルだけでなく作り方と伝え方も残す。
「育つ(そだつ)」の名前はこの思想から — スライドが生き物みたいに進化するのだ！

⑦役割分担: 人は“編集者”

  • 資料を作るのはAIエージェント。人は見て・伝えて・決めるだけ。
  • 管理画面で手直しもできるが、それはあくまで補助の位置付け。
  • 人が画面を操作するよりエージェントに頼むのが基本という作りになっている。
人間は監修者に徹する — AI時代の資料づくりは「指示と判断」の仕事なのだ！

⑧取り入れた6つ(核の再現)

  • いけとも版の核はそのまま採用: 画面の分け方・版と理由の記録・話した記録・その場でのAI修正。
  • 全操作をMCP(Model Context Protocol)化 — 70以上の操作をClaude CodeやCodexから利用可能に。
  • 型と配布: 手間をかけた勝負スライドはテンプレート化、HTMLで動く図や3D、オフラインHTML/PDF出力。
「仕組みそのものが価値」の部分はそっくり吸収 — 再現パートはここまで！

⑨足した6つ(自分専用化)

  • スピーカーノートの編集(発表中でもOK)/却下から学ぶ/要素を選んで頼む・声で頼む。
  • 収録後に実際に話した内容でノートを更新・YouTube制作に活用。
  • PDFとPowerPointへの書き出し / エージェントがファイルを直接直しても履歴が残る。
収録スタイルに合わせた+6 — 汎用より「自分専用」が最强なのだ！

⑩判断ログ: 版と理由が残る

  • スライドごとに版が残り、変更前と変更後を並べて見比べられる(例: 「4日間」→「7日間」の修正)。
  • なぜ変えたかの理由・変更内容・使ったモデルまで一緒に記録される。
  • 自分の意思決定は自分固有のもの — 残しておいてAIに参照させ、次を一発で良いものにさせる。
ハーネスやCodex開発で意識してきた「判断の記録」をスライド作成に応用！

⑪発表の記録も残る

  • いつ・どのスライドを見せて・何を話したかがスライドごとに記録される。
  • いけともさんは録画を忘れた発表も、この記録をClaude Codeに分析させて資料を直させた。
  • 発表するたびにデータが溜まり、次の資料制作に活きる循環に。
「話す」ことまでデータ化 — 発表が終わった瞬間に学習材料が生まれるのだ！

⑫発表中にIキーでAI修正

  • 発表途中にIキーで指示欄が出現 — Claudeに自然言語で修正を依頼(例: 「書き換える」にびっくりマークを追加)。
  • 前と後を切り替えて見比べ、Enterで採用。小さな修正なら5〜8秒で提案が届く。
  • さっと直すのは軽いモデル(Sonnet 5.5)、構成から練り直す「しっかり考え直す」はOpus 5.5のMaxモード指定。
プレゼン中にスライドが書き変わる — “近未来的なAIスライド”の目玉機能！

⑬採用か、却下か — 学ぶ仕組み

  • AIの修正は「提案」として受け取る — 採用するか却下するかを人が選ぶ方式。
  • 却下した理由も付けられ、それが次の指示に引き継がれる。
  • 「ルールにする」を選べば毎回守られる — 同じ指摘の繰り返しが不要に。
却下も学習材料 — ツールが自分の好みをどんどん覚えていくのだ！

⑭設計: 1デッキ=1フォルダ

  • 1つのデッキは1つのフォルダ。スライドは1枚のHTMLファイル、ノートは同名のテキストファイル。
  • 編集画面・発表画面・Claude Codeが全て同じフォルダを読み書き。
  • どこから直しても履歴と判断ログに残る設計になっている。
ファイル構造がそのまま共同作業の土台 — エージェントと人の共用ワークスペース！

⑮編集画面と履歴タブ

  • 左にスライド一覧とノート、右にAIタブ — 直したいことを書くと前後比較の提案が数秒で届く。
  • 変わった部分には「ここ変えました」の表示が出て、差分が一目で分かる。
  • 履歴タブでは版ごとに誰が・何を・なぜ直したかが並ぶ(例: 円の中で文字が折り返したので理由を書いて前の版へ戻す)。
「Claudeが直しました」「私が直しました」も区別して残る — 判断ログが溜まる！

⑯発表者画面と投影ツール

  • 発表者画面には次のスライド・経過時間・目安との差を表示。
  • ノートはその場でダブルクリック編集・自動保存 — 話しながら言い回しを直せる。
  • 投影画面: D=強調ペン・Z=虫眼鏡ズーム・L=レーザーポインタ と全て1キーで呼び出し。
ペン・虫眼鏡・レーザーが1キー — パワポ標準を超える手軽さなのだ！

⑰3つのツールを比較

  • 従来の自作HTMLスライド: ノート編集・AI修正依頼・記録ができなかった。
  • いけとも版: 記録機能は強力だが、PDF書き出しで動く要素が消える課題が残った。
  • ソダスラ: 両方の弱点を埋める — PDFで中身が消えない、パワポには文字のまま、段階表示はアニメーションで書き出し(動画入りは選んだ時だけ短い動画で)。
長所を掛け合わせて“最強の自分専用ツール”に — 比較がそのまま設計指針！

⑱まとめ: その夜、さらに育つ

  • 初版を動かしたその夜、Claude Code(Max 20倍モード)でもう1晩ぶん回してブラッシュアップ。
  • 実現したのはパワポへの段階表示・動く図の書き出し、撮影を楽にする機能、自分の声クローンのナレーションまで。
  • 成長した姿は後編で実際に使いながら披露。ツールはNote「れん学長の資料室」で配布準備中。
2時間弱で生まれ、1晩で育つ — 「育つAIスライド」は本当によく育っていた！
