OPENING「ポチポチ押して確かめる時間」を渡せるか

01
OVERVIEWAgents API に画面操作が加わった00:00
  • サイトを作った後、会員登録の流れを自分でポチポチ押して確かめるあの時間——誰かに任せられたらと思ったことはないか、という導入。
  • OpenAI の開発者イベント DevDay 2026 で、Agents API に画面の操作が加わった。エージェントが自分でブラウザーを開いて流れを確かめてくれる。
  • 今日の問いは「サイトのテストは、借りてきたエージェントに任せていいのか」。公式の資料と他者の一次情報で確かめ、答えは最後に出す構成。
「便利そう」で飛びつく前に借りる範囲と自分で決める範囲を線で区切るのが、この動画の問いの立て方。
02
METAPHOR例え話: 検査ラインのある工場00:35
  • Agents API を例えるなら検査ラインのある工場。コンベアを流れる製品がテストしたいサイト。
  • ラインの横に立つ熟練ロボットはよそから借りてきたもの。ロボットを整備して動かし続けるのは貸主の OpenAI。
  • 自分が用意するのは作業の指示書と工具と材料だけ——この分担が全体の理解の鍵。
「ロボットはレンタル、整備は貸主」——運用の面倒を見なくていい代わりに、どこまで任せるかが問題になる！
03
METHOD確かめ方は5つ、判定は◎〇△01:00
  • 何を借りて、何を自分で決めるのか——レンタルの範囲。
  • 画面の操作はどこまで任せられるか——computer use の実力。
  • いくらで、どこで使えるのか——料金と提供状況。
  • 任せてはいけないことは何か——安全の線引き。
  • 他の選び方と何が違うのか——競合との差分。
各検証に ◎（良い）〇（可）△（注意） の判定を付けていく

04
HARNESS公式の図: 3つの箱で見る構成01:15
  • 左が自分のアプリ、真ん中が Agents API のハーネス（OpenAI が運用）、右が作業場のサンドボックス。
  • ハーネスとはAIに道具を持たせて仕事を最後まで回す仕組みのこと——Dots を動かしているのと同じ技術。

「ハーネス＝Dots と同じ技術」という正体明かしが理解の分かれ目——個人向けの便利機能と開発者向けAPIが同じ基盤。

検証1 判定: ◎（土台は丸ごと借りられる。決めるのは仕事と道具と場所）
06
COMPUTER USE指示は日本語1行で動き出す02:18
  • 基調講演のデモ画面: 道具の欄に computer use と書き、作業でデスクトップを有効にするだけ。
  • 指示は「会員登録の流れをテストして不具合を報告して」——これだけ。
  • するとロボットの腕が動き出す: ブラウザーを開く → 登録のボタンを押す → メールアドレスを入力 → 次の画面へ進む。
  • 目の前の画面を見て、次の一手を自分で決めていく。自分のアプリには作業の記録とスクリーンショットが届く。
「テストして報告して」の1行で登録フローを踏破——コードを書かないテスト自動化の入口！
07
TWO GATESロボットだけでは通れない場所が2つ02:50
  • 新しいサイトの入り口——公開されたサイトでも、開く前に人の許可が必要。
  • ログイン——パスワードや確認の番号はアプリの窓口から渡して、AI のモデルには見せない。SKI など一部の方法にはまだ未対応。
  • 基調講演では Astra がゲームを画面操作で動かすデモも——これは公式デモという前提で見る。
検証2 判定: 〇（流れの確認はやり切る。ただし入り口とログインは人が通す）

VERIFY 3-4料金と、任せてはいけない線

08
PRICING追加料金なし、でも実測は必要03:36
GPT-6 Astra 料金（100万トークンあたり・動画の読み上げ値）
入力 $10
出力 $50
  • Agents API そのものに追加の料金はかからない。払うのはトークン+道具+借りた作業コンテナの3種。
  • 作業場はメモリー4GBの標準サイズで20分あたり12セント程度。
  • ただし正直に——画面操作の仕事が1件いくらになるかは料金ページに載っていない。公式の試験では、画面を操作する長い仕事で Astra は1件あたり$2台から$9台。
検証3 判定: 〇（追加料金なし。ただし1回あたりの費用は試して測る）
09
AVAILABILITY全開発者にベータ公開中04:15
  • Agents API はすべての開発者にパブリックベータで公開中。画面の操作は9月19日に加わった。
  • Amazon のクラウドで動かす道も——Bedrock Managed Agents はハーネスもモデルも AWS の中で動くプレビュー版。
  • 社内規約でデータの境外持ち出しが制限される場合、AWS 内で完結する選択肢は意味が大きい。
「OpenAI 直」と「AWS 経由」の2ルート——データ所在地の要件で使い分けられる体制が既にある。
10
RED LINEここが今日1番大事: 線は自分で引く04:50
  • サイトを開く許可は操作1つ1つの確認ではない。入り口を通した後、中でどのボタンを押すかはロボットの判断になる。
  • 公式はこう書いている——「購入や取り消せない変更を必ず確認したいなら、それができない場所だけを触らせるか、自分で管理するブラウザーを使うこと」。
  • つまり線を引くのは自分。任せる範囲を先に設計する責任は使い手側にある。
「許可」は入口の1回だけ——中での操作はAIの判断。安全の設計は事前に、です！
11
RISKS & SCORE注入リスクと成績73%の現実05:20
  • サイトの文字に悪意のある指示が紛れているかもしれない（プロンプト注入）。公式も「サイトの中身は信用できないものとして扱うよう」と明記。
  • 成績: 画面操作の公式の試験で Astra の正解は73%台——4回に1回ほどはやりきれていない。だから結果は人が確かめる。
  • データにも制限: 保存される場所は今はアメリカだけ。ゼロデータ保持には対応していない。
検証4 判定: △（購入・削除・本番の操作は任せない。結果は人が確かめる）

VERIFY 5他の選び方と何が違うのか

12
CLAUDEAnthropic: 土台はあるが別売り構成06:03
  • Anthropic の Claude にも土台を借りられるマネージドエージェントがある。料金はトークン課金に加えて1時間あたりの課金。
  • 画面の操作は別の道具として一般提供——ただしブラウザーは自分で用意する形。
  • マネージドエージェントでは画面操作はまだ使えないと書かれている。
「土台」と「画面操作」を1つの窓口で借りられるか——ここが OpenAI との差になる。
13
GEMINIGoogle: 確認を求める仕組み06:20
  • Google の Gemini にも土台を借りられる仕組みがある——ただしプレビュー版。
  • 画面操作は別の道具で、支払いなどの操作では自動で確認を求める仕組みがある。
  • 自分で組む道も比較対象——OpenAI の表では手間は Agents API が1番小さい。その代わり、自分で組むほど承認や保存の仕方を細かく決められる。
検証5 判定: 〇（土台と画面操作を1つの窓口で借りられるのが持ち味。ただしまだベータ）

ANSWER答え: 土台は借りて、線は自分で引く

14
ANSWER流れの確認は任せていい07:01
  • 答え: 流れの確認は任せていい。土台は借りて、線は自分で引く。
  • 購入削除本番のログイン——ここは人の手元に残す。
  • まずはテスト用のサイトで小さく試すのが推奨ルート。
「丸投げ」ではなく「範囲を決けて預ける」——自動テスト導入の現実解！

TAKEAWAYポチポチの時間をロボットに渡す07:50
  • ポチポチ押して確かめる時間をロボットに渡す——人が空いた時間で設計と最終確認に回る。
  • 人は線を引いて、最後に確かめる。この2役分担が Agents API 時代のテストの形。
  • 正解率73%台の現実を踏まえ、「任せっきり」ではなく「人機協働」で運用設計する。
単純作業はAI、判断と確認は人——テスト工程の役割分担が入れ替わる転換点！
