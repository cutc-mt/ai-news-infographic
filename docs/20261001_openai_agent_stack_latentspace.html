③ Dotsは「専用Linuxコンピュータ」持ち

04:04 Dots & Personal Cloud Computers
  • 各Dotにはクラウド上の専用Linux仮想コンピュータが割り当てられる
  • 従来はクラウドのブラウザか自分のPCのみ——今回はフルDesktopアプリが動作
  • Webブラウザも使える——人がPCでできることは何でも委任できる
  • 世界中のソフトウェアは人間向け設計——同じUIをエージェントが操作できるのが本質
専用Linux VM Desktop+ブラウザ 全面委任
「ブラウザ貸し」から「丸ごとPC貸し」へ。エージェントの作業場が一気に広がった！

04:58 Use Cases

手作業2時間 CUに委任 15分完了（8倍）

⑥ 最大の差分: 自己デバッグするエージェント

07:16 Self-Debugging Agents
  • 以前: タスクの開始は安定していたが、問題にぶつかると止まってしまった
  • 今: デバッグ・再試行・内省が実に上手くなり自力で回復
  • Codexのツール呼び出しを展開するとJavaScriptを書いて複数操作を一括実行している
  • モデル加速＋ハーネス側の技術多様化（コード生成・マルチモーダル）で速度が桁違いに
agent.write(`js:
  fill("email", ...); click("next");
  select("plan", "pro"); submit();`)
開始はできる 詰まると停止 デバッグで自力回復
1アクションずつポチポチじゃなく、コード書いて一気に処理——これが速度の秘密なんだ…！

⑦ 見方の革命: スクショ＋アクセシビリティ＋DOM

10:36 How CU Sees Software
  • 従来の痛点: スクショ→スクロール→スクショの非効率ループ
  • アクセシビリティ情報とDOMへの直接アクセスでページ全体を一度に把握
  • 全体が見えるので複数ステップをまとめたコードを書ける——速度が段違い
  • スクショ/アクセシビリティ/Playwrightをタスクに応じて使い分けるマルチモーダル設計
1操作ずつ視認 全体を一望 コードで一括実行
「スクロール地獄」からの解放。見え方が変われば速さも変わる、ってのがよく分かる一枚。

⑧ App Shots——スクショの「情報欠落」を潰す

11:35 App Shots
  • コマンドキー2連打で作業中アプリの文脈をCodex/ChatGPTへ高速取り込み
  • 普通のスクショにはリンク先URLや省略された予定タイトルが含まれない
  • App Shotsは生テキスト＋アクセシビリティ表現を丸ごと提供——トークン効率も職人芸
  • 人間向けスクリーンリーダー技術が、LLMのコンピュータ利用にもそのまま有効
スクショ（情報欠落） App Shots（全文脈） 高速な委任
「ただの画像添付」に見えて実は全データ添付だった——地味に凄い機能なんだ…。

⑨ 平均人類超え→「超人類」への残課題

13:21 Superhuman Computer Use
  • 現状: 多くのケースで平均的人間より速い。次は熟練者と同等以上の速度へ
  • 速度が上がるほど律速は「操作そのもの」に——例: DoorDashのページロード待ち
  • ロード完了→次アクション指示の遅延最小化は統計的科学の世界
  • loadイベントでイベント駆動化できる部分と、できない部分（カスタマー応答等）が混在
人間速に到達 律速はロード待ち イベント駆動で圧縮
敵はモデルじゃなくネットワーク待ちになってきた——高速化の主戦場が移ってる！

⑩ DNS設定も請求書支払いも任せる時代

15:31 Trust Milestones
  • 3〜4年前はLLMをWebやデバイスに繋ぐこと自体が怖かった
  • 今はDNS設定や請求書支払い（数万ドル規模）をCUに任せる段階へ
  • カスタマーサポート対応も定番化——完璧な文章で返すので向こうもbotと気づくかも
  • 待ち時間にサブエージェントで調査させる等、人間側の運用ノウハウも進化
接続を恐れた時代 DNS・支払いを委任 bot対botの日常
「数万ドルをYOLOで送る」——信頼の積み上がり速度が怖いくらい早い…！

⑪ Agents API——同一実装のCUを開発者へ

17:15 Agents API
  • 第三者サイト・サービスと連携するアプリに不可欠なCUの汎用性
  • CodexやChatGPTと同じComputer Use実装をAPIで公開
  • モデルは自社ハーネスで訓練——分布内利用は速度・コスト・精度で有利
  • 自前ハーネス構築も可能だが難易度高——公式実装を使うメリットが大きい
自前ハーネズ（難） Agents APIのCU 分布内で有利
「モデルが学んだ環境と同じ環境」をそのまま貸す——分布内だけのアドバンテージ、確かにデカい。

⑫ 信頼を設計で築く——同意・権限・制限

17:58 Trust, Permissions & Safety
  • 信頼は「確実に動く」積み重ねで構築——信頼性の担保が最優先
  • 支払い等の重要操作の前にはユーザーの同意を必ず求める設計
  • タスクに必要なサイト・アプリだけへアクセス制限
  • 安全チェックはタスク性質ごとに設定——製品により構成が異なる
同意 権限の絞り込み 安全チェック 信頼の蓄積
「任せる」と「許可を取る」のバランス設計——魔法ではなく設計で信頼を作るんだね。

⑬ 「作って、テストして」のループ完結

18:43 Coding, Testing & QA
  • 従来: Codexがビルド→人間がテスト——あなたがエージェントのQAになっていた
  • CUでSDLC（開発ライフサイクル）が完結: 構築→テストをエージェントが通しで
  • Ari氏: 「私の手元に来る頃にはもう動いている」——UIプレイテストで設計問題も検出
  • メタな光景: CUエージェントがCUエージェントをテストする入れ子構造
ビルド 自己テスト 動く状態で受け取る
QA作業こそ人間が一番溶かされてた時間——このループを閉じた効果は絶大！

⑭ 非同期ツール呼び出し＋mid-turn steering

20:26 GPT-6 APIs
  • 非同期関数呼び出し: ツール実行中もモデルの推論を停止させない
  • ツール起動→推論継続→結果を後で回収という流れが可能に
  • mid-turn steering: 推論の途中に新しい指示を注入（モデルの訓練とセットで実現）
  • 数ヶ月前に提供のWebSocketsが双方向通信を支え、GPT-6でも利用可能
ツール待ちで停止 推論継続＋途中指示 応答性向上
「ツールを待つ間も考え続ける」——人間と同じ働き方をAPIができるようになったんだね。

⑮ UltraFast——コーディングエージェントで推論を最適化

22:26 UltraFast Inference
  • 推論チームがCodexエージェントを常時走らせ性能を絞り出す「watching them cook」
  • 効率化の成果でLunaの価格を約80%削減——今は速度極大化へギアチェンジ
  • GPT-5.3 Codex Spark（初のWebSocket対象）はCerebras協業が明示——UltraFastは肯定も否定もせず
  • フロンティア知能を極限速度で初めてAPI提供——ユーザー評価も上々
効率化（価格▲80%） 速度極大化 UltraFast API
推論スタックをAI自身に最適化させる時代——再帰的改善がもう日常業務になってる…！

⑰ Decisions APIの中身——Lunaの上に速度を積む

26:44 What Decisions API Is
  • 新モデルではなく既存Lunaのウェイトの上に構築——推論スタックを速度最適化
  • 構造化出力による制約＋複数質問の並列バッチ実行で高速化
  • 推論なし・小型モデルで高速だが長期タスクは苦手——得意領域を選ぶ設計
  • GPT Liveのツール呼び出し高速化やサポート分類の社内利用が進行中
Lunaウェイト 構造化＋並列 超低レイテンシ分類
「速い小モデル」は魔法じゃなく制約と並列の職人技——構造化出力の高速版なんだね。
