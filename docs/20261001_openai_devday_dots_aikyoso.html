① OpenAI DevDay 2026の衝撃

00:01 導入
  • 2026年のDevDayはGPT-6.1 Solだけでなく、Dots（ドット）・ChatGPT Space・MCPプラグインなど大量発表
  • Agents API・Codex・Slack・Teams連携・Sign in with ChatGPT・Marketplace——別々に見えた機能が一気につながり始めた

個別機能の発表 全機能が接続 戦略が見える
バラバラに見えた発表の数々——実は1本の線でつながっていた！

② 結論：出口は「どのAIが賢いか」ではない

01:05 新しい方向性
  • AI競争の入口はこれまで通りモデル——性能がなければユーザーは振り向かない
  • しかしその出口では「どのAIが一番賢いか」ではなく、どのAIが人間とチームの仕事そのものを握るかが勝負
  • つまりワークスペース戦争が始まっている——本動画はこの仮説を検証
入口＝モデル戦争 出口＝ワークスペース戦争
「どのAIが賢い？」の先にある問いは「どのAIと働くか？」だね。

③ 見えている本戦：GPT-6.1 Sol vs Sonnet 5.5

02:08 モデル戦争は入口
  • 現在いちばん分かりやすい競争はGPT-6.1 SolとClaude Sonnet 5.5——同価格帯ビジネスモデル同士の戦い
  • モデルが強くなければユーザーは振り向かない——モデル性能は今後も絶対に重要
  • しかしこれは本戦の入口にすぎない
Sol 参戦 Sonnet 5.5 と激突 それでも入口
実務ビジネスモデル同士のガチンコ勝負——まずはここを通らないと話にならない！

④ モデル性能だけでは勝てない理由

03:12 ユーザーは流動的
  • モデルだけで競争すると今日はGPT、次はClaude、さらにGeminiと、その時に強いモデルへユーザーが移動する
  • 莫大な計算資源と研究開発費を投入し続けても、ユーザーを完全には固定できない
  • そこでOpenAIの次の手——モデルを入口にして、その先で仕事をChatGPTにつなぐ戦略へ
モデル強化 それでも流出 「つなぎ込み」へ
どれだけ金をかけても錨なしでは船は流れていく——錨とは「仕事」のこと！

⑤ OpenAI最大の武器＝巨大ユーザー基盤

04:15 12億ユーザー
  • ChatGPTにはすでに世界規模の巨大ユーザー基盤（約12億ユーザー）が存在
  • このユーザーを単なる「AIを使う人」で終わらせず、仕事・ファイル・外部サービス・AIエージェント・チームをChatGPTに接続
  • 「仕事がChatGPTにつながったユーザー」へ変えていく——解説者はこれをワークユーザーリンク戦略と命名
AIを使う人 仕事をつなぐ人 離れられない人
「使う」から「住む」へ——ユーザーの状態を一段深くするのが狙い！

⑥ 二輪構造：Model Power × Work User Link

04:15 戦略の骨格
  • Model Power＝顧客獲得のエンジン——性能でユーザーを集める
  • Work User Link＝顧客定着のエンジン——仕事環境によって定着させる
  • 獲得と定着の二輪で走るのがOpenAIの戦略構造
性能で獲得 仕事環境で定着 二輪駆動
前輪だけのバイクは転ぶ——獲得と定着、両輪そろって初めて走れる！

⑦ GPT-4o時代の個人向け戦略と「サイコファンシー問題」

05:19 振り返り
  • GPT-4oの時代は個人ユーザー向けの体験が前面だった
  • しかし個人向けの情感・仲良し感を狙う路線はサイコファンシー問題（過度な擬人化・依存の懸念）に直面
  • この経験がのちの仕事側へのシフトを後押ししたと振り返られる
個人向け体験 擬人化の問題 方向転換のターニングポイント
「AIと友達」路線の光と影——この失敗体験が企業向けへの教訓に！

⑧ 個人向けAIとビジネス向けAIの違い

06:22 求められる性能
  • 個人向けは会話の楽しさ・感情・遊び心が重視される
  • ビジネス向けは正確性・再現性・ワークフローの安定が求められる
  • 仕事で使われるAIはビジネス性能で選ばれる——ここに企業向けシフトの理由がある
楽しさ重視 使い勝手 実務性能重視へ
会社に入るAIの条件は「かわいい」じゃなく「間違えない」だね。

⑨ Sora 2——最初の囲い込み実験

07:25 過去の戦略
  • かつてOpenAIはSora 2で動画生成AI×SNSを組み合わせた
  • 個人ユーザーをソーシャルネットワーク側へ囲い込む可能性を模索していた
  • しかしその後Soraは終了——個人SNS囲い込みの第一案は撤退
動画SNS構想 撤退 次の一手へ
SNSで囲う案は頓挫——でもこの実験が「仕事側」への転換を生んだ！

⑩ Gemini 3登場とCode Red→ChatGPT一本化

08:29 転換点
  • Gemini 3登場をきっかけにOpenAI内でCode Red（緊急体制）へ
  • その後はChatGPT本体への集中が強まり、Soraは終了
  • 一方でCodex・Agents・Plugin・Space・Dotsと仕事側の機能は急速に統合
  • Code Red以降、企業向けシフトの方向がさらに収束したと見ると流れが分かりやすい
Gemini 3衝撃 Code Red ChatGPT一本化 仕事機能統合
競合の襲来がOpenAIを「一点集中」の陣形に変えた——危機が戦略を研ぎ澄ます！

⑪ Google Drive・AWS・SlackをChatGPTに集約

09:33 手足の獲得
  • Google Drive・AWS・Slackなど外部サービスがChatGPTに接続可能に
  • MCPによってSlack・Google Drive・CRM・GitHub・Canvaなど多様なサービスへ接続
  • ユーザーは「どのアプリを使えばいいのか」を考えなくてよい——ChatGPTに「これをやって」と頼むだけ
アプリ選び お願いするだけ 出口はChatGPTに集中
ツールの選び方をAIに任せる——入口がひとつになるほど手放せなくなる！

⑫ ChatGPT＝クロスプラットフォーム・アクションゲートウェイ

10:36 新しい姿
  • あらゆるサービスのアクション（実行）がChatGPT経由で完結
  • ChatGPTは会話UIではなくすべての仕事の入り口＝ゲートウェイになりつつある
  • 判断・指示はChatGPT、実行は各サービス——頭脳のポジション掌握がOpenAIの狙い
各サービス個別操作 ChatGPT一括指示 頭脳の中央集権
チャットアプリだと思ってたら、実は巨大な指令塔だった…！

⑬ MCPプラグインを巡る三社競争

11:40 規格を握る者
  • MCPは元々Anthropic発の接続規格——それをOpenAIが本格採用
  • OpenAI・Anthropic・Google三社がプラグイン接続規約を巡り競争
  • どのAIに多くの外部接続が集まるか——規格の覇権争いが始まっている
Anthropic発案 OpenAI採用 三社規格戦争
「接続の規格」を握る者が仕事の流量を握る——次世代のプラットフォーム戦！

⑭ My GPTs廃止→MCPプラグインへ移行

12:43 文化の移行
  • 個人用カスタムAIのMy GPTsは役目を終え廃止へ
  • 後継はMCPプラグイン——単なる外部API接続ではなくUI・Skill・コード・MCPサーバーを組み合わせたAIネイティブなミニアプリ
  • My GPTsで育った「自分専用AIを作る文化」を、「自分たちの仕事専用Pluginを作る文化」へ移そうとしている
個人専用AI チーム仕事専用Plugin 文化のアップデート
「自分のAI」から「チームの道具」へ——文化ごとバージョンアップする移行策！

⑮ GPTs資産の継承とログ・文脈のロックイン

13:49 / 14:54 切り札
  • My GPTsで蓄積した資産をプラグインへ継承できるのがOpenAIの強み
  • 積み上がったGPTsのログと文脈（Context）がそのままChatGPTに残る
  • 履歴・文脈・資産が積もるほどロックインが強化——他社への乗り換えコストが跳ね上がる
資産継承 ログ蓄積 ロックイン強化
会話の履歴こそ最大の資産——それは持ち出せない重さになる！

⑯ Dotsとは？——Astraが裏で動くAIワーカー

15:59 DevDayの主役
  • Dots（ドット）はクラウドで動くAIエージェント——裏ではGPT-6.1 Astraが駆動
  • 単体ではGemini SparkやGrok Botのようなクラウド型AIエージェントと類似
  • 重要なのは単体性能より「AIワーカー」としてチームに参加するという位置づけ
クラウドAI チームの一員 定型業務を担当
「チャット相手」から「同僚」へ——Dotsの正体は新しい職場の仲間だ！

⑰ ChatGPT Space＝AIチームのワークスペース

17:02 Google Workspace対決
  • ChatGPT Spaceに人間のチームが集まり、同じファイル・同じContext・同じPluginを共有
  • そこへDotsというAIワーカーが参加する構造
  • Google Workspaceが「人間×人間×ファイル」の共同作業空間なら、OpenAIは人間×人間×ファイル×Context×Plugin×AIワーカーの空間を狙う
人間＋ファイル Context＋Plugin＋AI AI時代のWorkspace
Google版の共同作業空間を、AI込みで作り直す——これは宣戦布告！

⑱ モデル戦争からワークスペース戦争へ

18:07〜20:16 結論
  • Pluginが共有・標準化され「この仕事はこのPlugin」「この資料はこのSpace」「この定型業務はDots」となれば、ChatGPTは会社の仕事環境になる
  • 他社モデルが少し賢くなっても移れない——乗り換えはWorkflow・Context・権限・AIワーカー・チーム構造そのものの移行になるから
  • GPT・Claude・Geminiのモデル競争は続くが、OpenAIの目指す先は「常に最強でなければ負ける会社」ではなく、トップクラスのモデル＋離れられないプラットフォーム
  • Pluginでつなぐ。Spaceで共有する。Dotsで回す。Teamで固定する。——DevDay 2026は「AIモデル企業」から「AIワークスペース企業」への進化を示した
つなぐ 共有する 回す 固定する ワークスペース企業
AI本戦の出口は「モデル戦争」ではなく「ワークスペース戦争」——2026年DevDayの真のメッセージ！
