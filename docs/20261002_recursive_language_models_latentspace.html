⑩ ハーネスは「構成的汎化器」である

  • 良いハーネスは構成的汎化（compositional generalization）を実現する

⑪ RLM（再帰言語モデル）の核心

00:46:20 RLMs Explained
  • context offloading: 伸び続けるコンテキストを外部へ退避させ、窓をクリアに保つ
  • コード実行を第一級の部品として利用——思考はプログラムで表現
  • 再帰的なサブエージェント呼び出し: LM自身がプログラム的に子エージェントを spawn
  • 共有メモリで親子・兄弟エージェント間の状態を受け渡す
def solve(task):
    plan = lm("計画を立てて", ctx=offload(task))
    for sub in plan:
        result = solve(sub)      # 再帰!
        memory.commit(sub, result)
    return lm("統合して", ctx=memory)
巨大な文脈 分解・委譲 再帰的に解決
「コンテキストが溢れたら、自分自身を呼び出せ」——再帰という古の知恵がLMに降りてきた！

⑫ Prime Agentと永続サブエージェント

00:53:57 Prime Agent & Persistent Subagents
  • Prime Agent: タスクごとに使い捨てず、続けて使う（continual）ハーネスの構想
  • 永続サブエージェント: 子エージェントが経験・記憶を保持し続ける
  • 親子だけでなくエージェント同士の直接通信（agent-to-agent）も視野に
  • 「使い捨ての群れ」から育つ組織へ——組織論的なエージェント設計
spawn→破棄 永続・蓄積・対話 学習する組織
エージェントも「新卒採用より中途育成」——記憶を持つ部下たちという未来の職場！

⑭ OpenAIの1万エージェント実験

  • OpenAIが単一問題に投入した10,000体のエージェントによる大規模実験
  • 総出力は1,300億トークン、コスト換算で約4,000万ドル相当の問題解決

1つの質問 1万エージェント 1つの答え

⑯ Kimi vs OpenAI — 群れの設計思想を比較する

01:17:48 Kimi vs. OpenAI Swarms

⑰ ケイパビリティ・オーバーハングと投機的ツール呼び出し

01:22:02 Capability Overhang
  • 現行のフロンティアモデルには既に大きな能力の余剰が眠っている
  • 引き出せていない原因はモデルではなくハーネスとインターフェースの側
  • 投機的プログラム的ツール呼び出し: ツール実行を生成と並行して先回り実行
  • レイテンシを隠すこの設計はエージェントの体感速度を一変させる可能性
モデルの潜在能力 ハーネス改善 一気に開放
最高のモデルは既に手元にある——足りないのは「使いこなす側」だけ、それが overhang の意味！
