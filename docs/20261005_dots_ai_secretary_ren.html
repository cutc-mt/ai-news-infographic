⑫ 注意1：利用枠はどう数えるのか

10:17 注意1
  • 公式にはdot との会話は利用上限に数えず、dot が始めた Codex や Work のタスクは数えると書かれています
  • X で話題になった「Codex の枠を使わずにサイトを作れた」例もこの説明と合っています。ただし自分の使用量の内訳では34.6%が dot の切り出した作業に関わる項目でした（推測を交えて紹介）
  • 対策は2つ。軽い確認はタスクを作らず dot 自身に済ませてもらうことと、定期チェックの回数を絞ることです
  • なお10月3日の朝に週の枠が0%になりましたが、昼にはリセットなしで戻っており、不具合の可能性が高いと考えています。1週間残量を記録して確かめる予定です
会話は枠外 タスクは枠内 軽い確認はdot自身で チェック回数を絞る
枠の減り方は1週間記録して確かめる——誠実な検証姿勢がこの動画の軸です！

⑬ 注意2：記憶とログの扱い

11:17 注意2
  • dot の中に溜まる記憶は個別に見ることも消すこともできず、消すには dot ごとリセットするしかありません
  • ただし dot に手元のファイルへ書き出させたものは普通のファイルなので、自分で見て、直して、消せます
  • だから覚えて欲しい決まりや好みは手元のファイルに置いて、dot には毎回読ませるのがおすすめです。自作のハレヨミも同じ形にしています
  • 裏で何をしたか見えにくい点は「やったことの記録を手元に書かせる」ことで補えます。仕事のデータを読ませるなら、学習に使われるかの設定と勤務先のルールを先に確かめること
記憶はdotの中 決まりは手元のファイル 毎回読ませる 記録も手元に
消せない記憶に置かず、読ませるファイルに置く——これが安全な型です！

⑭ 注意3：承認が届かないと7時間かかる

⑯ オープンソース版「OpenDots」との比較

13:03 OpenDots との比較
  • OpenDots は CopilotKit が公開した dots のオープンソースの代替で、OpenAI の公式版ではありません
  • 良い点はモデルを自由に選べて、記憶も手元で見て消せることです
  • ただし費用は自分で払い、定期実行の引き金などは未実装です
  • まさおさんの実機レビューでも「API を繋いだだけで、通話から仕事を任せる体験までは作り込まれていない」とのこと。今は本家で使い方の型を固め、OpenDots は部品の候補として見ています
本家dotsで型を固める OpenDotsは部品の候補 様子を見て組み替える

⑰ 私の構成：シエルとハレヨミの連携

13:32 私の構成
  • 分担はきれいに分かれています。「dots は窓口と下書き、ハレヨミは見える化と正本、決めるのは私」です
  • ハレヨミ（仕事用のパソコンで作った AI 秘書）は朝の整理・夜の振り返り・30分ごとの差分チェックの3本を定期実行し、メールやチャットを読んで記録します
  • 定期実行では送信や記録を変える操作はしないと決めていて、画面には会議・空き時間・締め切りがひと目で並びます
  • GTD のタスク管理とも組み合わせます。朝に今日の一歩を決め、夜の EOD で終わったことと残りを整理。その記録が週の振り返り、来週のトップ3、月・四半期・1年のレビューまで繋がります
dots＝窓口と下書き ハレヨミ＝見える化と正本 決めるのは私
