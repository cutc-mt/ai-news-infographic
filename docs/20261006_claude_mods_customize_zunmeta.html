② Claude Modsとは何か

発表の概要
  • 発表したのはAnthropic。対象はターミナルで使うClaude Codeとデスクトップアプリの両方です
  • 一言で言うと、Claude Codeの動き方と画面を、小さなプログラムで作り替えられる仕組み
  • 中身はTypeScript / JavaScriptで書いた短いプログラム。関数とは数学のそれではなく、決まった時に呼ばれて決まった仕事をする部品のこと
  • 新しめのClaude Codeなら設定なしで最初から使える状態になっています
# Claude Mods のひとこと定義
Claude Codeの動き方と画面を
TypeScript / JavaScriptの小さな関数で
作り替えられる仕組み
画面まで変わるのだ。ボタンを出したりもできるのだ。

③ 仕組み: 「合図」に差し込む関数

どうやって動くのか
  • Claude Codeは何かするたびに合図（イベント）を出しています——ファイルを読む、許可を聞く画面を描く、みたいにね
  • Modの正体は、その合図に差し込む小さな関数。合図の前・後、それと代わりに動けるのです
  • 「代わりに動ける」ということは、本来の動きを乗っ取れるということ——Modが強いのはここです
  • 同じ合図に複数のModが差し込まれたら、読み込んだ順番に動く——ゲームのMODとそっくりなルールです
Claude Codeが合図 Modが前/後/代わりに実行 動きと画面が変わる
「今から読むのだ」って毎回言ってるのだ。

④ プラグインの箱と導入方法

入れ方・配り方
  • Modはプラグインという箱に入れて配ります。スキルと同じ箱に入れて配れるのです
  • ブラウザの拡張機能みたいに、入れたり外したりできるのがプラグインの便利なところ
  • 入れる時は、公式のディレクトリ（一覧）か、Claude Codeのプラグイン画面から選びます
  • 別々の人が作ったModも重ねて使える——読み込み順で動きが変わる点は、ゲームのMODと同じです
公式ディレクトリ or プラグイン画面 選んでインストール 外すのも自由
拡張機能と同じ感覚で着脱できるのが嬉しいのだ！

⑤ 使える場所とバージョン

対応環境の確認
  • ターミナルのClaude Codeならバージョン2.1.287以降が対象です
  • デスクトップアプリは、コードタブで使えるアプリ内のClaude Codeが2.1.286以降ならOK
  • VS Code拡張機能のチャット欄やブラウザ版では、画面の追加は表示されないので注意！
  • 料金や使えるプランについては公式の発表に記載なし——Claude Codeを使える契約があることが前提です
環境とバージョンを確認 新しければ設定不要 そのまま試せる
ターミナル派はそのまま試せそうなのだ！

⑥ できること①: 依頼文を書き換える

公式ブログの4機能 その1
  • 公式ブログは関数1つでできることを4つ挙げています。1つ目は依頼文の書き換え
  • あなたが書いた依頼文を、AIに届く前に書き換えることができます
  • たとえば誤字を直してから送るといった使い方——毎日の入力がちょっと賢くなります
  • 「送る前のフィルター」を自分で書けるのが面白いところ。プロンプトの前処理をModに任せる発想です
依頼文を入力 Modが書き換え 整えられた文がAIへ
誤字を直してから送ってくれたら、僕は助かるのだ！

⑦ できること②: 危ない操作を止める

公式ブログの4機能 その2
  • 2つ目は道具（ツール）を使おうとした時に止める機能
  • 止めるだけでなく、書き換える・やり直させることまでできるのです
  • たとえば消しちゃいけないファイルを消そうとしたら、そこで止められる——事故防止のガードレールになります
  • エージェントに任せる作業が増える時代だからこそ、危険操作のブレーキを自作できる価値は大きいです
Claudeが道具を使おうとする Modが判定 止める / 書き換える / やり直す
大事なファイルを守れるのは安心なのだ！

⑧ できること③: 許可に代わりに答える

公式ブログの4機能 その3
  • 3つ目は、「これを実行していいか」の許可確認に、Modが代わりに答える機能
  • 毎回ボタンを押す手間が減って、作業のテンポが上がるメリットがあります
  • でも勝手に許可されるのは少し怖い——その怖さは覚えておきましょう
  • どこまで自動化して、どこで人間が押すかは、自分のルールで線引きするのが正解です
許可の確認 Modがルール判定 自動で応答（線引きは自分で）
便利さと怖さは、いつだって隣り合わせ。

⑨ できること④: 秘密を伏せる

公式ブログの4機能 その4
  • 4つ目は、道具の結果から、パスワードのような秘密の情報を、Claudeが読む前に伏せる機能
  • 見られたくない情報をAIに見せずに済む——社内環境や秘密情報を扱う人には嬉しい仕組みです
  • 「読んだ結果を後で隠す」のではなく、読む前に差し替えるのがミソ。Contextが汚れにくい設計です
  • 依頼文の書き換え・操作の停止・許可の応答と並んで、ガード系のModの柱となる機能です
# 秘密の伏せ字イメージ
道具の結果 → Modが検閲 →
API_KEY="****伏せ字****" → Claudeへ
見られたくない情報をAIに見せずに済むのだ。それは嬉しいのだ！

⑩ さらに: 画面そのものを足せる

UI拡張の可能性
  • 関数4つだけでなく、会話の横に別の窓を出したり、ボタンや入力欄を足したりできます
  • Claudeからの質問や道具の結果の見せ方を、そっくり差し替えることも可能
  • 作業状況を映すダッシュボードを横に置く、といった自分専用のコックピット化ができるのです
  • 見た目の世界じゃなくて中の動きまで改造できる——これがClaude Modsの本領です
会話メイン画面 Mod製サイド窓 自作ボタンや入力欄 専用UIの完成
横に窓を出すのは、Modだけの特技なのだ。

⑪ 前からある「Hooks」との違いは3つ

既存仕組みとの比較
  • 実は似た仕組みは前からありました。名前はHooks——決まったタイミングで外から用意した処理を走らせる仕組みです
  • 画面に描けるのはModだけ——Hooksは窓もボタンも出せません
  • HooksはClaude Codeの外で動くのに対し、Modは中で動く関数——外から指示 vs 中に入り込みの違いです
  • 最初からある機能を丸ごと差し替えられるのはModの方——できることの幅が段違いです
Hooks: 外から・止めるのが得意 Mod: 中から・画面と機能を作り替える
外から指示を出すのと、中に入り込むのとの違いなのだ。

⑫ Hooks・Skills・MCPとの使い分け

役割の住み分け
  • 「じゃあHooksはいらなくなる？」→いなくならない。公式もHooksは今まで通り使えると明記しています
  • 手持ちの処理で止めるだけならHooksで十分——住み分けが基本です
  • SkillsはClaudeが読む指示書——同じお願いを何度も貼っているなら、スキルにまとめます
  • 外のサービスに繋ぎたいならMCP。指示はスキル・接続はMCP・画面や機能を作り替えるならMod——そしてプラグインは全部を入れられる箱です
指示書=Skills 接続=MCP 止める=Hooks 作り替える=Mods 箱=プラグイン
4つの道具は、役割で使い分けるのが正解なのだ。

⑬ /diff とAGENTS.mdもModで作り直し

Anthropic自身の実践例
  • 「機能を丸ごと差し替えるって、例えば何？」への答えがAnthropic自身の実践です
  • 公式は標準機能の/diffとAGENTS.mdの読み込みの対応を、Modで作り直したとのこと
  • さらに今後も本体の機能をModに移していく方針——いらない機能は外せる時代が来ます
  • 本体をスリムに保ち、機能を好きに組み替える——エディタの拡張エコシステムと同じ設計思想です
標準機能 Modとして切り出し 要る人だけ入れる / 要らなければ外す
いらない機能は外せる時代になるのだ！

⑭ ModはClaudeに作らせることも

作り方のハードルを下げる
  • TypeScript / JavaScriptで書くといっても、自分でゼロから書く必要はないのです
  • 作りたいModの内容を伝えれば、Claude CodeにModを作らせることもできる、という話を紹介
  • 公式のサンプルModも公開されており、動きは公式ドキュメントの説明によるもの（動画では実働確認ではなく説明ベース）
  • 「作る」より「作ってもらって中身を読む」ほうが学習としても安全で早いルートです
やりたいことを伝える Claude CodeがModを生成 中身を確認して採用
改造道具を、改造対象自身が作ってくれるのだ！

⑮ 注意: Modは「あなたと同じ鍵」で動く

一番大事な注意点
  • Modはあなたと同じ権限で動き、サンドボックスの中には閉じ込められていない——これが最大の注意点です
  • つまりパソコンの中に全部触れる可能性があるプログラムなのです
  • Modを入れるのは設定を1つ足すことではなく、あなたと同じ鍵を持ったプログラムを家に招き入れること——合鍵を知らない人に渡すのと同じです
  • 止められるのは入れた後。入れた瞬間からもう動いていることも忘れずに
Modを入れる = 合鍵を渡す だから作者と中身を先に見る
家の合鍵を、知らない人に渡すのと同じなのだ……。

⑯ 入れる前のチェックは2つだけ

誰が作ったか・何を触るか
  • 怖がって全部避ける話でもありません。スマホのアプリやブラウザの拡張機能を入れる時と同じ目で見ればいいのです
  • 見るポイントは2つ：誰が作ったかと何を触るか。アプリなら作者とレビューを見てから入れるのと同じです
  • 他人のModは中身を確かめるコマンドでソースを見てから。最初から入っているModをプラグインの画面で覗いてみるのが最初の一歩です
  • 会社のパソコンなら先に会社の方針を確認——組織の設定でModを制限・絞り込む管理にも触れられています
作者を確認 中身を確認 会社PCなら方針確認 初めてインストール
改造の自由と、作者を見る手間はセットなのだ。

⑰ 4行まとめ — 頭の整理

クロージング前の総復習
  • Claude Codeの動き方と画面を作り替える小さなプログラム——見た目の世界ではなく中身の改造です
  • Hooksは外から処理を走らせるのに対し、Modは中から画面や機能まで作り替えられる——止めるだけならHooksで十分
  • 公式も/diff とAGENTS.md対応をModで作り直し、今後も本体の機能をModに移していく方針
  • Modはあなたと同じ権限で動く——作者と中身を見てから入れるのが鉄則です
仕組みを知る Hooks/MCP/Skillsと使い分ける 安全手順で楽しむ
ここまでの話、僕の頭でも整理しておきたいのだ！

⑱ まずは最初から入っているModを覗く

エンディング
  • Claude Codeを毎日使うなら、まず最初から入っているModをプラグインの画面で覗いてみるのがおすすめ
  • 「文字が降ってくるModを作るのだ！」と張り切るずんだもんに、めたんからは動作チェックの1回を忘れずに、のツッコミ
  • 今はClaude Codeを使っていない人も、「改造できる道具は、それと同じだけの権限を持つ」と覚えておけば十分です
  • 改造の楽しさは、確かめる手間の先にある——気になったことはコメントで！チャンネル登録もよろしくなのだ
標準Modを覗く 仕組みに慣れる 自作Modで自分好みに改造
また見に来て欲しいのだ。なのだ。
