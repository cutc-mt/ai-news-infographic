⑤ モデルの役割分担 — 頭と手足

モデル戦略
  • ストーリーは「頭」が必要な作業。ソルなどの上位モデルで構成するのがおすすめです
  • 絵コンテもコマの配置を考えるため、頭の良いモデルで作る方が良いと考えています
  • 画像生成の部分はLunaでも品質はほぼ変わらない。絵コンテで固定すれば、あとはLunaで大量生産するだけ
  • 「頭＝上位モデル、手足＝Luna」という分担が、品質とコストのバランス取れた設計です
ストーリー（上位モデル） 絵コンテ（上位モデル） 画像生成（Luna）
頭の良い仕事と手を動かす仕事を分けるのがコツです

⑥ コスト最優先なら全部Lunaでも可

低コスト運用
  • 絵コンテをLunaで書くことも「かけんことはない」——Lunaも十分に賢いのです
  • とことんコストを下げたい場合は、ストーリーも絵コンテも画像生成も全部Lunaで統一しましょう
  • その場合はエフォート（推論の度合い）を最も高い段階に設定するのがポイントです
  • 品質重視なら頭だけ上位モデル、コスト重視なら全部Luna——使い分けは自由です
全体Luna ＋ エフォート最大、が省コストの鉄板構成！

⑦ エフォート最大は「賢さ」ではなく「粘り」

エフォートの効果
  • エフォートを上げてもモデルが賢くなるわけではありません
  • その代わり長い時間、じゃんじゃん動き続けてくれるようになります
  • 失敗してももう1回やり直す。そういうリトライのループを組ませられます
  • 品質をさらに上げたい場合は、生成画像を見せて確認→フィードバック→再生成のサイクルも組める（時間はかかります）
  • 今回は設定をしっかり固め、ほぼ1発で完成まで到達させました
粘り強く動かして、最後まで仕上げさせましょう！

⑧ サブエージェントの基本仕様

今回の主役

  • 今回は13ページに対して13個のエージェントを作成しました
  • 「3つしか動けないなら速度は変わらないのでは？」→速度は確かに3倍どまりです
  • しかし今回のポイントは速度以外の大きなメリットにあります（次のカードへ）

⑨ 最大のメリットは「コンテキストが汚れない」

品質安定の秘密
  • 3つのエージェントだけで回すと、1ページ目を作ったエージェントが4ページ目を作る際、過去のページを見てしまう
  • するとコンテキストが汚れ、出力に徐々にドロドロ感が出てきます
  • ページごとに別のエージェントが担当すれば、常にフレッシュな状態で描画できます
  • 汚れがなくなることで品質が安定。これが1番重要なメリットです
1エージェントで連続生成 汚れ・ドロドロ感 ページ担当制で解消
速さより「フレッシュな描画」が本命です！

⑩ トレードオフとコスト対策

注意点
  • 速度アップは最大3倍まで。それ以上は速くなりません
  • 各エージェントに絵コンテを渡す分、トークン消費が増える可能性があります
  • 頭の良いエージェントなら「位置だけ渡す」ような簡潔なプロンプトで調整可能。プロンプトエンジニアリングで効率化しましょう
  • 何も指定しないと全文脈を渡してしまい、コストが跳ね上がる恐れも
  • とはいえLunaなので費用はたかが知れている。Proプランなら気にするほどではなく、Plusプランでも十分余裕があります
渡す文脈は最小に——これがコスト削減のコツ！

⑪ 絵コンテ先行の設計手順

エコンテの作成
  • いきなり漫画にせず、まず絵コンテ化するのが手順です
  • 第1話のみを見て絵コンテを書かせ、ページ数とコマの配置を考えさせます
  • 絵コンテは添付フォルダーに書き出し。ここで画の設計を固定します
  • 面倒なら絵コンテなしでも漫画は書けますが、品質を考えるなら絶対にやるべき工程です
# 絵コンテ用プロンプトの例
「第1話のみ見てエコンテを書いて。
   ページ数と構成を考えて、
   エコンテは添付フォルダーに書き出して」
コンテキストの固定が、品質の土台になります！

⑫ 漫画用「スキル」を作って固定化

スキルの自作
  • 漫画のためのスキルを作成して固定化すれば、出力が安定します
  • スキルで固定すれば、これくらいの短いプロンプトで完結します
  • スキルを使わない場合は添付フォルダーにキャラクター画像を置いて参照させる形でもOK
  • 実演では、指示していないのに3面図を勝手に読み込んでくれました
  • 絵コンテとスキルの作り方は過去の動画で解説済み。それを見れば誰でも再現できます
スキル作成 絵コンテ作成 出力が安定
仕込みを一度作れば、あとはずっと楽です！

⑬ 絵のタッチは3パターン同時に比較

タッチ選定
  • 最初に決めるのは絵のタッチ。文章で言えばスタイルとトーンです
  • 3パターンのタッチ案はサブエージェント3つで一気に生成
  • 1案2分かかる場合、直列だと6分。並列なら2分で3案が出揃います
  • 単体で生成すると前の案を見てしまうため、純粋なタッチの比較ができません。文脈がないサブエージェントだからこそ純粋に出せるのです
  • 実演では2番目の案（繊細な線画）を採用しました
# タッチ比較のプロンプト例
「絵のタッチの候補を3パターン書いて」
# → サブエージェント3つが同時に生成
文脈がないことは、比較にはむしろ利点です！

⑭ 実績 — 13ページを29分で完成

今回の結果
  • 13個のサブエージェントで13ページ全てを生成しました
  • 所要時間はわずか29分。1ページあたり3分未満です
  • 思考の過程でキャラクターをきちんと読み込み、3面図を参照しながら描画します
  • 船長「バズ」の顔や体格が全ページで一貫。きちんと資料を見てくれています
  • ここまで固定化すればほぼ間違えません。修正は1ページのみで済みました
13エージェント 29分で13ページ 修正は実質1箇所
早くて品質が良い——この両立が最大の強み！

⑮ キャラ名は画像とファイルの両方に書く

キャラ設定のコツ
  • 小説・絵コンテ・キャラクター画像で名前が一致していないと正しく紐づきません
  • 対策その1：3面図などの画像自体に名前を書く（例: バズホーキンス）
  • 対策その2：参照ファイルの名前にも入れる。どちらか一方で十分ですが、私は両方やっています
  • 2箇所に入れておけばまず間違えることはないでしょう。AIが「このキャラがこう動く」と理解できます
画像に名前を記入 ファイル名にも反映 紐づきミスを防止
名前の一致は地味ですが、超重要な設定です！

⑯ 修正も「レビュー→指摘→再生成」で

修正の実際
  • 不具合を見つけたらLunaに「画像を見て変な点を指摘して」と投げかけます
  • 実際に「右上でステラはすでにフォークで肉を食べている（食事の順序が逆）」と正しく認識してくれました
  • 「左下のスパークとステラを消す」など指示を伝えるだけで反映。不要な2人いるキャラも解消しました
  • 実例: ご飯が届いていないのに肉を持ち、しかもフォークを持っていない矛盾コマなど
  • 絵コンテを修正するよりできた漫画を後から直す方が早い場合が多いです
# 修正時のプロンプト例
「画像を見て変な点を指摘して」
# → レビューさせてから直すのが確実
まずレビューを挟むと、直し忘れが減ります！

⑰ 修正も3案コンペ、仕上げはナンバリング

仕上げの工夫
  • 修正もサブエージェント3つで3パターン同時に出してコンペにします
  • 1案だけだと一発勝負になってしまいます。3案出せばどれか当たりが来ます
  • 何度も修正を重ねるとコンテキストが汚れ、時間もかかる——一気に3案で決めるのが理にかなっています
  • 仕上げはファイル名に連番を振るよう指示。ページ順に並び、投稿も一気にできます
# ナンバリングの指示例
「ファイル名はナンバー付きにして」
# → 01.jpg, 02.jpg ... ページ通りに整列
良い案を1つ選んで、もう1段階磨くのもあり！
