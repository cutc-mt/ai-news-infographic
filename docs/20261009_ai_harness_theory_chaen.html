冒頭30分は「なぜデスクトップ型AIを使うのか」をロジカルに解説します。概念の理解が今日のゴールです！

02AI企業の少人数戦略

「日本そして世界に代表するAI企業を少数精鋭で」という経営目標のもと、全社員がAIをフルで使いこなすことが組織の生産性の源泉だと強調。

  • 少ない人数で利益を作る——これ以外に生産性を上げる方法はない
  • AIを使い込むほど自身の生産性も上がっていく
  • 細かい操作方法（AGENTS.md・スキル等）はAIに聞けばいい。概念・原理原則をインストールするのが講座の目的

03ディスカッション: Webチャットとデスクトップの違いは?

講座はいきなり30秒の隣同士ディスカッションからスタート。「Webのチャットとデスクトップ型の違い、分かりますか?」

  • Web型: Chrome / SafariでChatGPTやClaudeのページを開いて使う
  • デスクトップ型: 専用アプリをPCにインストールして使う（Claude Code / Codex等）
  • 「Webのチャットは終わってる」と営業でも言い続けている代表——終わってはないがデスクトップは10倍便利
同じAIを使っているのに、使い方でかなり差がつく——これが今日のテーマです。

04モデルは「世界平等」

今日の話はClaudeとChatGPTが中心。性能の核となるモデル（Claude Opus 5.5・GPT-6.1等）は誰が使っても同じものです。

  • モデルの中身は共通——私だろうが他社だろうが同じ世界トップのAI
  • 違うのは使う場所がWebかデスクトップ型か、その周りの環境
  • OpenAI内部では少し早いモデルを使っているが、基本的には世界平等
同じモデル 差がつくのは「与える情報」と「使い方」

05AIが知れる情報は4つ

差をつける鍵は「いかに情報を与えるか」の世界。AIがアクセスできる情報源は次の4つに整理されます。

  • ① 学習済み知識——元から学習している情報
  • ② Web検索——最近できるようになった最新情報の取得
  • ③ MCP接続——メール・Slackなど社内サービスの情報を読み込む
  • ④ PC内のファイル——ここがWeb型の弱点、デスクトップ型の独壇場
極論、生まれてから今まで全ての情報を知っていたら精度は高い。でも無理——だから何を渡すかが勝負！

06Web検索の実演: ドジャースの試合結果

「本日のドジャースの試合結果を教えて」と頼むと、AIは検索を実行してから回答。モデルは去年〜今年夏ごろまでの学習で、最新情報は持っていないためです。

  • 学習データには最新のポストシーズン情報が含まれない
  • だから検索してはじめて正答できる——「お勝利しました。良かったですね」
  • Web型でも検索・MCP接続は最近進化——ただし次のカードの弱点が残る

07デスクトップ型の決定的優位: PCの中が読める

Web型は最近の進化で検索もMCPもできるようになった。しかし皆さんのパソコンの中のファイルは読めません。デスクトップ型はここが違う。

  • 普通の人のPCにはデータがいっぱい——それも読ませるほど性能が上がる
  • パソコン全体が「作業環境」と「材料」になる
  • システム設定まで触れる——機内Wi-Fiが遅い時も「全部解決してくれた」実例
情報量 精度 —— 机に材料をそろえるほど仕事がはかどる

08黒い画面が触れて、開発まで一気に

デスクトップ型のもう一つの強みはターミナル（黒い画面）を細かく触れること。開発まで一気通貫でできます。

  • 「私は開発しません」という人でも、ちょこっとアプリを作れる場面が必ず来る
  • 例: 採用担当が各媒体をつなげてダッシュボードでKPI管理——絶対便利
  • Webでも厳密には触れないではないが、デスクトップ型の方が格段に細かい

09宿題: 全員1人1回アプリを作る

講座の最後には宿題も用意。「使えるアプリを1人1回作る」というミッションが全社員に課されました。

  • 「あったらいいな」を自分で作る——業務の課題をアプリで解決
  • 今日終わったらClaude CodeかCodexをインストールしてガチャガチャ使ってみること
  • 今日はハンズオンはしない——まず概念理解に集中
「まだの方いたら、終わったらすぐアプリを入れて使ってみてください」——代表からの宿題でした。

10テーマ2: AIの正体は「文章予測機」

AIの正式名称は大規模言語モデル（LLM）。仕組みを一言でいうと「文章を予測して出すだけ」です。

  • 例: 「我が輩は」→「猫である」と次を予測して答える
  • 大量に学習した文書から次に来るものを予測しているだけ
  • 細かい理論は置いて、この一点だけ覚えて帰る——基礎として全員に知ってほしい

11トークン単位で見る・課金される

AIは文字をそのまま認識せずトークンという単位で処理。このトークンが課金の単位にもなります。

単語ごとだいたい単語で区切る
1〜1.3日本語1文字あたりの目安
課金単位API利用料金の基準
  • 「トークン＝だいたい単語ぐらいで切ってるんだな」程度の感覚でOK
  • 後のコンテキストウィンドウの話でもトークンという言葉が出てくる

12AIエージェントの正体

「AIエージェントって何ぞや?」という2回目のディスカッションから。社員の答えは「AIに詳しい専門家っぽい、勝手に作られたジャンル」——半分正解。

  • 正解は「道具を使うAI」——AIが司令を出してファイル作成や検索をする
  • 検索できるChatGPTも、その意味では全部AIエージェント
  • 今時、文字しか生成しないAIはほぼない——厳密には全部エージェント。マーケや会社によって言い方が違うだけ
「AIエージェント、エージェント、エージェントとうるせえよ」という感想もあるけど、まずは道具を使うAIだと覚えましょう。

13ハーネスとは「馬の馬具」

ここからが本題。ハーネスとは英語で馬の馬具のこと——暴走する馬をまっすぐ進ませる装具です。

  • 馬は暴走する——AIも同じ。周りをちゃんとカチッと固定する仕組みがハーネス
  • ハーネス＝Claude Code＝Codex——モデルの周りの仕組みを指す言葉
  • ハーネスがちゃんとすると性能が上がることは論理的にも客観的にも証明済み——各社も「ハーネス大事」と発信
暴走するAI ハーネスで制御 本来の性能を発揮

14プロンプト全盛期からハーネスへ

代表自身、AI講座を3年やってきて最初は「プロンプト」全盛だったと振り返ります。

  • かつては「チャエン式」という謎のプロンプトを怪しく売っていた時代も
  • 今はClaude Codeの時代——プロンプトは役割のほんの一部と判明
  • 周りの情報を与えるコンテキストとハーネスをカチッと整えると、性能がめちゃくちゃ上がる
ChatGPTのWebチャットは「プロンプト書いて終わり」。デスクトップ型はハーネスを整える作業がセットで付いてくる——やることが10倍ある世界。

15性能の7割は「人の力」

代表の所感として、Claude Code / Codex の成果は7割が人の力、3割がツールの性能。だからこそ使い手で生産性が大きく割れます。

7割人の努力・ハーネス整備
3割ツール（モデル）の性能
10倍デスクトップ型のやること量
  • 極めた人と極めていない人の生産性差はめちゃくちゃに出る
  • 「我々全員、日本・世界でも最高クラスに1度は極めてほしい」——講座の肝

16テーマ3: コンテキストウィンドウ＝机

「情報をたくさん与えればいい」という大原則には例外（限界）があります。それがコンテキストウィンドウ——脳のキャパです。

100万Claude Codeの概算トークン数
20万Codexの通常トークン数
キャパ固定読める頭の容量が決まっている
  • 何でもかんでも放り込むと性能が落ちる
  • トークンは一旦「文字と同じ」と考えてOK

17原理原則: 机を散らかさない

限られたコンテキストウィンドウ＝皆さんの「机」。机が散らかっていたら、基本どんな仕事もできません。

  • 机が散らかると仕事ができない——例外はあるけれど基本は散らかたらダメ
  • 散らかさず、きれいに、圧縮して情報を与える——これがAI活用の全て
  • だからこそAGENTS.md・フォルダ構成・スキル・MCPが生まれた
  • 原理原則さえ分かれば、細かい使い方はAIに聞けば全部わかる
「なるほど」と思った情報だけ、机の上に整頓して置く。それがハーネス整備の第一歩。
