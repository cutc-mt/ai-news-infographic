Google Stitch 2.0 完全解説
〜無料で使えるGoogle製AIデザインワークスペース〜

Google Labsの無料AIデザインワークスペース「Stitch」を、空のプロンプトから実際のアプリ「FrameDesk」を作りながら徹底解説。初回生成、的確な修正、テーマ編集、バリエーション、参照画像、Live Mode、デザインシステムとDESIGN.md、プロトタイプ、コーディングエージェントへのハンドオフ、MCP連携まで、デザインから実装までの全工程を18枚のカードに整理します。

📅 2026年10月9日公開 |  🎬 YouTubeで視聴 |  🔗 stitch.withgoogle.com

① Stitch 2.0とは: 隠れたGoogleの実力製品

動画の冒頭で語られた核心: 「Googleのアプリ開発に最も有用な製品が、実は目の前に隠れている」。それがStitchです。

  • インターフェースを文章で記述するだけでUIデザインを生成
  • 複数のデザインを探索し、画面をつなげてプロトタイプ化
  • 成果物をそのままコーディングツールへ持ち出せる
  • 現在はデイリー制限付きで無料（Google Labs提供）
1枚キレイなダッシュボードが欲しいだけじゃない。「どう直し、どう一貫性を保ち、どう実装につなげるか」がこの動画の主役だよ！

② 始め方: 3ステップでワークスペースへ

ブラウザでStitchを開けば、すぐに作業を開始できます。

  • stitch.withgoogle.comにアクセス（説明欄にリンク）
  • Try Nowをクリックし、Googleアカウントでサインイン
  • ワークスペースに入ったら生成開始

初期画面の構成:

  • プロンプトボックス＋添付ファイルオプション
  • 生成対象の選択: App（モバイル） or Web
  • ダッシュボード・ランディングページ等のテンプレートも用意

③ 生成モードと無料クレジットの仕組み

生成セレクターを開くと、現在のUIでは2つのモードが選べます。今回の例ではBalanced推奨。

Speed＝高速重視
Balanced＝速度と品質のバランス
  • Speed: 素早い協業（クイックコラボレーション）を優先
  • Balanced: スピードと品質の両立を狙う
  • デイリークレジットは毎日UTC深夜0時にリセット
  • 残り回数は設定（Settings）で確認可能

④ 最初のプロンプトの書き方: FrameDeskの例

巨大なプロンプトは不要。ただし「誰が使うのか・何をするのか・視覚的な方向性」の3点は必ず書きます。

  • 誰向け: 単独のYouTubeクリエイター
  • 何を: 次に手を付ける動画の把握、動画ボード（アイデア→台本→収録→公開の4カラム）
  • 視覚方向: 温かみのあるオフホワイト背景＋ダークテキスト＋控えめなオレンジのアクセント
  • リアルなサンプル動画タイトルを使うよう指定
🎬 実際のプロンプト例（意訳）
「FrameDeskという単独クリエイター向けデスクトップWebアプリを設計して。動画・台本・公開予定を管理し、サイドバーに概要・動画・カレンダー・設定を配置。実用的で見やすいレイアウトで、リアルなサンプルタイトルを使って」

⑤ 初回生成の評価: まず構造をチェック

「誰向け・主タスク」の情報が設計の善し悪しを判断する土台になります。生成結果が返ってきたら、装飾より先に構造を見ます。

  • 動画ボードがすぐ見つかるか？
  • 動画を追加する明確な方法があるか？
  • 公開予定パネルが画面を占領せず見えるか？
  • サンプル内容も確認: 3語程度の短いタイトルだけで成立していないか。「Googleの無料デザインツールで完全なアプリを作る」のような長文で破綻しないか試す
動画管理のクリエイターと売上チェックの人とでは、必要な情報が違う。文脈を与えるとデザインの妥当性を評価しやすくなるんだ。

⑥ キャンバス操作: ショートカットと反復のコツ

生成後はキャンバス上で作業。複数のスクリーンと方向性を1箇所にまとめて保持できます。

  • V＝選択、H＝パン（画面移動）
  • ?キーでキーボードショートカットのヘルプを表示
  • 元のスクリーンを表示したまま反復すると、新しいバージョンが想定以上に変わった場合の比較対象になる
生成 比較 修正 また比較

⑦ ターゲット修正: 「もっと良く」をやめる

AIコーディングツールに「見た目を良くして」と頼み、「betterの定義」を1時間説明し続ける羽目になる——そんな経験がある人こそ見どころです。

  • スクリーンを選択 → Edit → チャットに追加 → 具体的な変更を記述
  • 例: 「公開予定パネルをコンパクトにして動画ボードの横幅を広げて。現在の色・タイポグラフィ・ナビは維持」
  • 編集後はボード幅・テキストの収まり・ナビの変更有無を検査
  • 主アクションが埋もれるなら「動画を追加を最も目立つアクションにし、次要ボタンの強調を下げて」と指示
通常の編集は「大きい変更を1つ → 検査 → 継続」がベスト。大転換もできるけど、そこへ至る過程は自分で制御しよう！

⑧ Edit Theme: 会話なしで基本スタイル調整

基本的なスタイリングは、スクリーンを選択してGenerate → Edit Themeから直接調整できます。

  • ライト / ダークの外観切り替え
  • アクセントカラー
  • フォント
  • 角丸（corner radius）

FrameDeskでは暗めのスタジオ風ルックを作り、温かみのあるライト版と比較。両テーマで動画カードとステータスラベルの可読性を必ず確認します。スクリーンショット全体が良さそうに見えても、そこが崩れていては意味がないからです。

⑨ Variations: 複数の方向性を一括生成

Variationsコントロールで複数オプションを一度に生成し、元のデザインからどれだけ離れるか（creative range）を調整できます。

  • 低いレンジ＝小さな改良向き
  • 高いレンジ＝デザインを大胆に再考させる

動画では3案をリクエスト（内容はFrameDeskのまま）:

  • コンパクトなボードレイアウト
  • ゆとりあるエディトリアルレイアウト
  • ダークスタジオレイアウト
  • 全バージョンで次の動画の締め切りが明確であることを要求
選ぶ基準は「豪華な装飾」じゃなくてタイトルと締め切りを読みやすくスキャンできるか。有望な案を選んでから、元のパレットを戻す組合せも明示的に指示できるよ。

⑩ 参照画像: テキスト以外の文脈の与え方

Stitchへの文脈はテキストだけではありません。参照画像（ラフなワイヤーフレームやスクリーンショット）を添付できます。

  • 例: 左にサイドバー・中央に動画ボード・右に公開予定とスケッチして添付し、「この構造を保ちつつタイポグラフィと間隔を改善」と指示
  • スタイル伝達にも有効: 「この参照のタイポグラフィと間隔だけ使って、内容とワークフローはFrameDeskのまま」
  • 既存のコードやデザインファイルを持ち込む経路もあり、新規だけでなく既存改善にも使える

⑪ Live Mode: 声でデザインを操る

Live Modeでは、エージェントが作業中にStitchに話しかけながらデザインを操縦できます。

  • 声の指示例: 「ダッシュボードが混みすぎてる。動画タイトルに余裕を持たせて、締め切りを見つけやすくして」
  • エージェントに階層の批評を頼んだり、ページに必要な要素を一緒に考えることも
  • デザインを見ながら → 変更を話す → 会話を続ける、というごく自然なUI作業が成立

⑫ デザインシステム & DESIGN.md: 一貫性の鍵

残りの画面を生成する前に一貫性への対処を。ここでDesign Systemパネルが本領を発揮します。

  • アクティブな色・フォント・間隔・丸み・コンポーネントパターンを一覧表示
  • チャットで同じパレットを繰り返し説明せず、コア属性を直接編集
  • FrameDeskのルール例: オレンジのアクセントをどこに使うか・動画ステータスの見た目・最も強調するテキスト
  • プロジェクトのデフォルトに設定すれば新画面が同じルールを継承。既存画面にも適用して統一
📄 DESIGN.mdとは
デザインルールの持ち運び可能な版。構造化されたデザイン値と、その使い方を説明した文書ガイダンスを含み、プロジェクトと一緒にエクスポートして別ツールやコーディングエージェントに渡せる。

⑬ ブランドの取り込み: WebサイトURLから抽出

すでにブランドがあるなら、WebサイトのURLや参照画像を渡すだけでデザインルールを抽出してくれます。

  • 自社サイトのURLを指定するだけ
  • あるいは参照画像からルールを抽出
  • 毎回ゼロからブランドを説明し直す手間が不要
ブランドガイドラインを文章で書き出す労力がまるごと省ける。これは既存ビジネス持ちの人にはでかい！

⑭ 画面を増やす: 詳細・カレンダー・空の状態

選んだダッシュボードを文脈に、デザインシステムを適用しながら画面を追加していきます。

  • 動画詳細画面: 編集可能なタイトル、ステータスセレクター、大型の台本エディタ、収録チェックリスト、公開予定日。ボードへ戻る導線とサイドバーの一貫性を明示
  • カレンダー画面: 月間公開カレンダー＋締め切りリスト。動画クリックで詳細画面へ遷移
  • 空の状態（empty state）: まだ動画が1本もない新規ユーザー向けに、説明と「最初の動画を追加」アクションを要求

生成後は共有要素（サイドバー・ボタン・フォント・ステータス色）が同じアプリに見えるかを比較し、ズレたらその差だけを次の編集で狙います。

⑮ モバイル対応: 縮小ではなく再構成

ダッシュボードのスマホ版を依頼します。指定は「同じタスクを保ちつつコンパクトなナビパターンと、動画段階を読みやすく切り替える方法」。

  • 注意: デスクトップの4カラムがそのまま4つの極小カラムになるべきではない
  • レイアウトがどう変化するかを検査するのが要点
  • 同じ情報を快適に閲覧する方法がユーザーに用意されているか確認

⑯ プロトタイプ: ホットスポットで旅程を接続

ダッシュボード・動画詳細・カレンダーが揃ったら、メインフローを接続します。スクリーンを選択してGenerate → Prototype。

  • インタラクションホットスポットで関連画面を接続
  • Playでフローをプレビュー: ダッシュボードの動画カード→詳細、ナビのカレンダー→カレンダー画面、予定動画→詳細へ戻る
  • ユーザーとして歩く: 動画を開く→台本を探す→公開日を確認→ボードに戻る。各ステップで操作とナビが意味をなすかチェック
  • ナビやスクロールの検証、さらには探索中に次のスクリーンを提案・生成してユーザー旅程を拡張できる
クリックして歩いてみないと気づかないギクシャクしたフローって、結構あるんだよね〜。

⑰ コードへのハンドオフ: エクスポートから実装へ

Stitchから仕事を持ち出します。目的のスクリーンを選びDownloadでHTMLと画像のzipを取得。エクスポートにはdesignファイルも同梱され、3点セットで管理します。

  • 画像＝意図した見た目
  • HTML＝開発者への具体的な出発点（CSSはTailwind対応）
  • DESIGN.md＝共有ルールの説明

React / Vueなど框架を使うアプリでも、コーディングエージェントがこの素材から必要なコンポーネントを構築できます。動画の指示例:

「エクスポートされたHTML・画像・design.mdを使い、FrameDeskの画面をReactアプリとして実装して。ナビ・動画カード・ステータスラベル・ボタンを再利用可能にし、ダッシュボード／動画詳細／カレンダーを接続。まずサンプルデータで、見た目は参照を忠実に」
  • 初版ができたらローカルプレビューで同じ旅程を反復し、デスクトップ／スマホ両サイズでStitchの参照と比較・修正
  • 台本の保存や公開日の更新などの動作を追加し、再読み込みで保存が生き残るかテスト
  • その他の出口: Figma（編集可能テキスト・名前付きレイヤー・オートレイアウト）、AI Studio、Antigravityへのエクスポート、Netlifyでの公開

⑱ MCP連携と総評: 設計→実装の連続作業へ

コーディングエージェント利用者にはMCPインテグレーションが有用。エージェントがツール経由でStitchプロジェクトを直接操作できます。

  • 操作: プロジェクト一覧・スクリーン読取・デザイン生成・編集依頼・バリエーション作成
  • 設定: Stitch設定のAPI Keysでキー作成 → コーディングツール（例: AntigravityのMCP Servers設定）に追加。キーはフロントエンドコードの外に保管
  • 接続後はまずプロジェクト一覧を出させ、FrameDeskを指して対象画面を実装前に読み取らせる
  • 公式にはStitch Skills（デザイン・ビルドワークフロー）、CLI・SDKも公開。ブラウザから始めて必要になったら自動化へ

総評: 単独開発者・小チームには早期に設計判断を下せるのが最大の価値。最も大事なコツはリビジョンに時間をかけること。方向を決め、弱い部分を直し、そのデザインシステムを全アプリに貫く——これが単発生成より遥かに多くを引き出す使い方。作りたいアプリの1画面に明確なブリーフを渡し、意図的な修正を重ねて開発ワークフローへ。視覚探索・再利用可能なルール・プロトタイプ・コードハンドオフの組合せは、実際のプロジェクトで試す価値あり！
