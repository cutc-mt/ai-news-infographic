Claude Code 新「Projects」機能徹底解説
〜スキャフォールディング（足場作り）とAIオーケストレーション〜

Claude Codeに待望の新しい「Projects（プロジェクト）」が実装。プロジェクトの中に複数のスレッドを作り、キャラクターに役割を分担させて並列処理／段階的処理を実現。PCを閉じてもクラウドで動き続け、RAGで大量の論文も効率よく読み込める。AIに作業環境を構築させるスキャフォールディング（Scaffolding＝足場作り）まで、初見オペレーションの実録も交えて18枚のカードに整理します。

① Claude Code に「Projects」実装

Claude Codeの新しい「Projects（プロジェクト）」機能が登場。ワンダー佐藤いわく「従来のプロジェクトよりもめちゃくちゃ進化してる」新機能です。

  • プロジェクトの中にスレッドを作り出せる——これが最大の進化点
  • スレッドを組み合わせれば並列処理も段階的（逐次）処理も可能
  • 処理はクラウド実行。ブラウザ版プロジェクトと基本的に同じ感覚で使える
従来のProjects スレッド生成可能な新Projects AIチーム運用へ

② クラウド実行でPCを閉じても動く

最大のメリットは処理がクラウドで行われること。パソコンを閉じてもクラウドで動き続けるので、長時間タスクを放っておけるのです。

  • ロングタスクのワークフローを投げて、あとはPCを閉じて楽できる
  • 手元のマシンが作業に縛られない——リサーチ系の放置作業と好相性
  • 閉じている間の進行も、開き直せば新規・継続が一目で分かる
長いタスクはクラウドに投げて放置——このワークスタイルが実現しました

③ プロジェクト内にスレッドを作る

プロジェクトの中に複数のスレッドを作り出して操作するのが新Projectsの核心。動画では実際にスレッドを生やし、動きを実演しています。

  • 「進行を考えて3つほど」と指示するとスレッドが分岐して3系統が並走
  • こっちのスレッドは進み、こっちには影響しない——系統ごとの独立実行を確認
  • スレッド表示でどのスレッドが何をやっているかを把握・操作できる
複数スレッドプロジェクト内に生成
2方式並列／段階的

④ RAGで大量の論文を効率読み込み

新ProjectsはRAGを活用した情報検索が効くのが嬉しいポイント。研究者にとっては切実な痛点が解消されます。

  • 大量の論文を毎回Claude Codeに読み込ませるのは非常に重いストレスだった
  • プロジェクトに論文をまとめて置けばRAGが効く——消費もいつもより抑えめ
  • 「全ての論文を見て現在の成果を教えて」の一言で全体を総括してくれる
これまではブラウザ版プロジェクトで我慢……でもやっぱりClaude Codeでやりたかった！

⑤ クラウドとローカルの使い分け

何でもクラウドに投げればよいわけではない。処理の重さで使い分けるのがワンダー佐藤の推奨スタイルです。

  • クラウド向き: リサーチ、足場（スキャフォールディング）など軽めの準備作業
  • ローカル向き: ターミナルを使う本作業・Pythonなど重い処理はローカルの方が効率的
  • ローカル実行ではクレジットが消費されないという経済的なメリットも
クラウドで足場作り ローカルで本作業 最強の順番

⑥ スキャフォールディング（足場作り）

動画タイトルにもなった「スキャフォールディング（Scaffolding＝足場作り）」とは、AIに作業環境を構築させること。建築の足場のように、本作業前の準備をAIにやらせる発想です。

  • プロジェクトで一定程度の足場を作る＝下準備をAIに丸投げ
  • 足場が完成した状態でローカルの本作業へ移行するのが推奨フロー
  • 軽めの準備作業はクラウドに任せて手元のリソースとクレジットを温存
「ヘリタン、足場を作れ」——たった一言でAIが作業環境を組み始めます

⑦ AIチーム編成: しより＆ヘリタン

動画の実演では、プロジェクト内に2つのキャラクター（役割）のスレッドを作成。AIオーケストレーションの実例です。

  • しより: 外部論文をリサーチさせるキャラクター
  • ヘリタン: 足場（スキャフォールディング）を作るキャラクター
  • 新規スレッドを作らずとも既存スレッドの役割を認識——しより／ヘリタンを正しく区別
しより＝リサーチ担当 ヘリタン＝足場担当 役割分担のAIチーム

⑧ AIオーケストレーションとモデル最適化

複数のAIに役割を分担させるAIオーケストレーション。スレッドごとに使うモデルを変えられる点がコスト管理の鍵です。

  • オーケストレーター（指揮役）はOpusで回すのが推奨
  • 足場作り・サーチ程度のワーカーはSonnetに変更して消費を抑制
  • スレッドごとにモデルを切り替え可能——役割に応じたコスト最適化
Opus指揮・統制役
Sonnetリサーチ・足場

⑨ 実測: セッション消費はいつもより少ない

全論文を読ませる重い処理でも、RAGが効いているため消費はいつもより少なめ。実際の数値を画面で確認しています。

  • 全論文リサーチ時点でセッション上限は7%しか消費
  • 週次（ウィークリー）は59%に収まる
  • プロジェクトに未登録のファイルも引き継ぎ（継続利用）が楽
セッション上限7%
週次上限59%

⑩ 実演: 宇宙論リサーチを総括

プロジェクトに投げ込んだのは研究中の宇宙論関連の大量の論文。「全ての論文を見て現在の成果を教えて」とプロンプト一発で整理させます。

  • 暗黒セクター／光のセクター／形のセクターと領域別に整理して報告
  • 理論の欠けている部分と次の研究の方向性を即座に提示
  • 「前回の未確認文献」も踏まえてリサーチ→レポート取得まで自動で実行
毎回の読み込みストレスが解消——研究の全体像をすぐ俯瞰できます

⑪ デフォルトは並列処理

複数スレッドに指示を出すと、基本は並列で同時進行します。しよりとヘリタンがほぼ同時に動き出したのが実演の初手でした。

  • 独立した複数リサーチなどは並列のままでOK——むしろ高速
  • しかし順番が重要なタスクでは事故る——後工程が前工程の途中結果を読みに行ってしまう
  • 実際に同時動作してしまったため手動ストップで制御する場面も
独立タスク 並列でOK ／ 依存タスク 制御が必要

⑫ 失敗から学ぶ逐次処理の必需性

最初の試行は「これは失敗ですね」と素直に認める結果に。逐次処理の難しさを浮き彫りにした貴重な実録です。

  • ヘリタンがしよりの不完全なリサーチ途中を読んでしまった——逐次の意味がない
  • リサーチが完了していないのにヘリタンがぐるぐる回って先走り
  • 一旦止めて同じプロンプトを条件付きで再投入——「リサーチが終わるまでヘリタンは動かないで」
同時に動かしたくなければ「動かないで」と明示する——感覚で使うしかない部分です

⑬ 待機指示で逐次制御に成功

条件付きプロンプトで再挑戦。今度はしより完了→ヘリタン開始の順番がきちんと通り、目論見どおりの逐次処理になりました。

  • ヘリタンは「しよりが終わるまで待機、終わり次第動く」と理解
  • オーケストレーター側にはしよりのスレッドだけが動いている状態を確認
  • しより完了を待ってヘリタンが起動——「これをやって欲しかったんだよね」と成功を実感
しよりリサーチ完了 ヘリタンが足場作り開始 逐次成功

⑭ 段階的処理を「スキル化」する

順番制御を毎回プロンプトで書くのは非効率。ワンダー佐藤は段階的処理のパターンを「スキル」化して再利用する道を選びました。

  • 並列がデフォなので並列をブロックする形のスキルを作るのが方針
  • 基本は段階的（逐次）処理だけをスキル化していく
  • 多段階的にプロンプトなしでじゃんじゃん自動実行される状態を目指す
  • 「並列処理」と判断させたい文脈作りは今後の課題

⑮ 成果物の保存先を指定する

スレッドに作らせたMDファイル等の成果物。保存先のデフォルトと変更方法も重要な実用ポイントです。

  • 何も指定しないとクラウドに保存されるのがデフォルト
  • ローカルのフォルダを指定すれば、成果物をローカルに落とし込める
  • 一度指示すれば次からも同じ場所に保存してくれることを再試行で確認
  • 両方に保存の指示や、後から手動で保存する運用もOK
クラウド保存（デフォルト） ローカル指定 書き出し先は明示が吉

⑯ 推奨ワークフロー全体像

動画全体から浮かび上がるのが、「クラウドで準備 → ローカルで本番」の二段構えワークフローです。

  • プロジェクトに資料（論文など）を集約しRAGを効かせる
  • クラウドのスレッドでリサーチ＋足場作りをAIチームに分担（PCを閉じてもOK）
  • 完成した足場・成果物をローカルに書き出し
  • ローカルのClaude Code（ターミナル）で本作業＝クレジット消費なし
準備は雲の上、仕上げは手の中——役割を分けるのがClaude Code新Projectsの極意

⑰ 初見オペレーションの学び

動画はワンダー佐藤が当日初めて機能を使う実録。たどたどしくも、生の試行錯誤だからこそ見える学びが詰まっています。

  • 見どころは逐次処理のさせ方とスレッドの作り方
  • 初回は並列暴走→停止→条件付き再実行という試行錯誤のプロセスをそのまま公開
  • 制御のコツはスキル化で再利用可能にすると次回から楽
  • 使い込んで良い使い方を見つけたら続編で紹介予定

⑱ まとめ: 進化したProjectsを使いこなす

新Projectsは従来版より大幅進化＋プロジェクト内スレッド生成が最大の武器。ただし使いこなすコツがいくつかあります。

  • 並列で回すならデフォルト投入でOK、逐次処理は明示的な制御が必須
  • 書き出し先（クラウド/ローカル）は指示で指定した方が安心
  • クラウド＝リサーチ・足場、ローカル＝本作業で効率とクレジットを両立
  • Opus＋Sonnetのモデル使い分けでオーケストレーションを最適化
