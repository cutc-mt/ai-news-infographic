第1部：Muse Wonderとは何か
CARD 01

Metaが初めて「最上位」と並べて比較

2026年10月12日、Metaが公開したMuse Wonder。Metaが初めて、ClaudeやGPTの一番上のモデルと並べて比べてきたモデルです。

  • Meta自身の成績表で、長い開発と記憶は Opus 5.5 の上
  • 逆に短いコーディングと画面操作では負ける
  • Xでは「ベンチマーク向けに仕上げただけ」という声も
エレン結局、ベンチマーク向けだったの？
まさお全部をよく見せた表ではなかった。上と下がはっきり分かれてたんですよ。
CARD 02

2つの版：APIで使えるのは「無印」

Muse Wonderには2つの版があり、使える場所が分かれています。

  • 無印 Muse Wonder：MetaのモデルAPIとMuse Codeの両方で呼べる
  • Muse Wonder Full：コーディングエージェントMuse Codeの上位プラン（Power Up／Maximum Up）だけで利用可
  • 無印の考える量（エフォート）を最大にしてもFull は選ばれない――モデルIDも別々で、別モデル
Opus 5.5 を上回った数字の多くは、APIで使える無印の方でも出てるのだ！
CARD 03

どこから呼べる？ ローカル不可

今日から試せる経路と、できないことのまとめです。

  • MetaモデルAPI＋ターミナルのMuse Code
  • OpenAI互換のツールは接続先のURLとキーを変えるだけで動く
  • OpenRouter経由でも呼べる
  • モデルの中身のファイルは非公開。自分のPCでは動かせない
日本からMetaモデルAPIに登録できるかは、公式ページに書かれていないのだ。
CARD 04

Muse Sparkの土台から最前線へ

このモデルの始まりは、MetaがAIの取り組みを全面的に作り直したことでした。

AI開発を作り直し

（小さく早い）

  • 公式発表でMuse Sparkの土台の上に作ったと明記
  • Meta研究ブログ：「作り直しを終え、最前線で戦う側に移った」
  • 米国のパーソナルエージェントアプリMuse（アプリ）とは別物。近いうちにアプリ内でも利用予定
「最前線に移った」のはメタ自身の主張。ここから外の測定で確かめるのだ！
第2部：外の測定と Active Focus
CARD 05

Artificial Analysis 総合点は52

自社測定ではなく、Artificial Analysis が同じ条件で測った総合点がここからの物差しです。

Opus 5.5581番上
Muse Wonder52上位勢と並ぶ
  • 前モデルのMuseより上で、GPT-6やGeminiの上位モデルとほぼ並ぶまで到達
  • でもグラフの1番上はOpus 5.5（58）のまま
  • 総合点は複数テストを1つにまとめた点。Fマックス（エフォート最大）で測定
CARD 06

売りその1：Active Focus

Active Focusとは、作業が難しくなってもゴールに向かって働き続ける力です。

  • 行き詰まったら別のやり方を試して壁を超える
  • 公式動画：「諦めないよう訓練した」。途中で新情報が出れば進め方を立て直す
  • 必要なら聞き返し、重要な操作の前には確認を取る――勝手にファイルを消さない
  • Metaはこの力を何時間もかかる大きなソフト開発で測定
粘る力を「諦めない」と言い切るところが今回の肝なのだ！
CARD 07

実演：opencodeで七角形ボール

AI開発ツールopencodeで「七角形の中をボールが跳ねる画面」を依頼した実演です。

  • 考え終わるとまずファイルを丸ごと書き上げる
  • 書き上げた直後に頼んでいない検証を自分で実行
  • ボールの挙動の式を探して手を入れ、もう一度確かめてから仕上げる
  • 壁抜けも重なりもないと自分で確認――まさにActive Focusの動き
頼んでいない品質確認まで自分でやるのがこのモデルの癖なのだ。
CARD 08

長い開発ベンチは外部測定でも勝つ

長い開発を見る2つのベンチ、DeepSWE（複数リポジトリ由来の長期課題）とSWE Marathon（超長期プロジェクト）。

Muse Wonder75.8%1回で通過

  • Artificial Analysis も同じDeepSWEを自社測定――こちらでも無印が Opus 5.5 の上
  • SWE Marathonはメタの表だけ（同じツールでの比較ではない可能性をモデルカード自身が明記）
  • 注意：ベンチの点はハーネス（作業させる周囲の仕組み）が変わると同じモデルでも動く。モデル単体の点ではない
第3部：業務・記憶と苦手なもの
CARD 09

業務の長い仕事は Full の強み

保険の請求処理や賃貸契約書の読み込みなど、手順の多い仕事の切り抜きです。

  • 保険請求なら書類を開き→抜けを確認→記入→送り返すまで完遂するのが仕事
  • 社内総合点Personal Superintelligence Index：1位はFull の59.1、無印54.3で Opus 5.5 のわずか下
  • 業務の流れを最後までこなしたかを見るAutomation Bench A（社外測定）も1位はFull
  • 例外：Harvey Legal AA（法律書類。手上げげ混じりは減点方式）では無印も Opus 5.5 の上
  • ただしVals AIの指数（金融・開発・法律・税を米経済比で平均）では1位Gemini、Full・無印はClaude勢の下
CARD 10

売りその2：Active Memory

Active Memoryは、会話をまたいで大切な文脈を持ち続け、必要な細部を自分から取り出す力です。

エレン前に出た「一度にたくさん読める」話と違うの？
まさお一度に読める量はコンテキスト（1回の会話内）。Active Memory は会話が終わっても覚える方です。
Muse Wonder（無印）85.6メモリーベンチ
Opus 5.581.5
  • 社内ベンチメモリーベンチ：無関係な会話や後から書き変わる情報を混ぜても正しく思い出せるかを測定
  • 例：「走る」を後から日曜に変更したら、古い土曜ではなく新しい日曜を拾えるか
  • TechCrunchは「メタ自身の測定で未検証」と指摘。会話をまたぐ記憶の社外測定はまだ見つかっていない
CARD 11

短いコーディングは Opus 5.5

「長い開発が得意なら短い修正も？」――そこは逆で、Terminal-Bench（ターミナルで課題を解く）は苦戦。

Opus 5.559.6この表で1位
Muse Wonder（無印）52.0
  • この成績表はメタが自分の表で負けを認めた数値。実はArtificial Analysis 測定値をそのまま掲載
  • 別測定（Muse Code利用）でもOpus 5.5 が上
  • 同じ七角形を同じ指示で Opus 5.5・Sonnet 5.5 にも作らせて並べると仕上がりに差が見えた
ちょっとした直しなら Opus 5.5 のまま、なのだ。
CARD 12

画面操作と3Dは苦手

Metaはブラウザやアプリの操作も得意と書きますが、OSWorld（PC画面の実作業ベンチ）では逆の結果に。

Opus 5.581.8部分点1位
Muse Wonder（無印）72.6並びで最低
  • OSWorldは点の数え方が2つ：部分点（途中までの進捗も加点）と完遂のみ（途中で止めたら0点）。完遂は Opus 5.5 の数字がなく部分点で比較
  • Artificial Analysis・Vals AI には画面操作の数字がまだない
  • 3Dはモデル説明書に「形や位置関係を考えるのは弱点」とメタ自身が明記
  • 実際に「夜の商店街を3Dで」を3モデルに依頼：Museは白い中央線の広い道だけの単純な画面。Opus 5.5 はレンガの細い道に自動販売機・看板・シャッターの店を並べ、Sonnet 5.5 タイルの道で店を構える精緻さ
第4部：正直さ・料金・今日から試す
CARD 13

物知りではないが、嘘つきではない

海外記事「Muse Wonder は知識が弱点」の元は、Artificial Analysis の知識ベンチAA Omnisienceです。

  • 正解率（無回答も含む全問中の正答）は比較モデル中で最低
  • ところが知らないのに間違える作り話の割合は低い方――低いほど知らない時に正直
Muse Wonder26.5%作り話が少ない
Opus 5.558.6%それっぽく答えがち
  • 問い合わせメール返信で社内規定にないことを聞かれた場合、作り話しやすいモデルはない規定をそれらしく返信
  • Muse なら「分かりません。確認します」と返しやすい――顧客に嘘の規定を送るより安全
CARD 14

値段は同じ、でも作業1回は安い

Xでは「Opus 5.5 と同じ値段なら使う理由がない」という声も。実際、トークン単価は入出力ともAnthropicと全く同じ数字です。

Muse Wonder$4.52テスト1問あたり
Opus 5.5$5.98
  • 作業1回の費用を決めるのはモデルがどれだけ喋るか。知能テスト1問の出力トークン量はMuseの方がずっと少ない
  • 出力は入力より高単価――喋る量が減れば支払いが大きく変わる
  • Artificial Analysis の実測：開発作業1件あたり、Muse Code のMuseはClaude Code＋Opus 5.5 より早くて安い
  • ただし最安は別：VentureBeat はテスト1問の費用は GPT-6 の上位モデルの方が安いと報道
乗り換え前は値段表より「自分の作業1回いくら」を比べるのだ！
CARD 15

実際に試した：OpenRouter 経由

動画では OpenRouter から実際に呼び、天気調査と通知の機能を持たせて検証しています。

  • 「雨なら傘の通知を入れて」と頼むと、まず翌日の東京の天気を調査
  • 雨と判断すると日本時間で傘の通知を登録してくれた
  • 一方で開発元を聞くと「メタ」と言わず「開発したチーム」とぼかす返答
  • 問い合わせ窓口に置くなら何と名乗るかを最初の指示に書くべき
接続先を変えるだけで試せる手軽さが今回の売りなのだ！
CARD 16

注意：コントリビューターモード

Muse Code を会社の仕事で使うなら最初に確認したい設定です。

  • コントリビューターモード＝送った中身の学習利用を許可する代わりに、使える量が増える設定
  • 学習に回るのはプロンプト・コード・ファイル・返ってきた答えも全部
  • しかも契約した最初からオンになっている
  • オフは Settings から。オフにした後の中身は学習に使われない――会社のコードでは最初に切るのが安全
エレン遊びならともかく、会社のコードだと話が変わるね。
まさおそうなんです。開始前にSettingsで切っておくのが安全です。

CARD 18

まとめ：仕事で選ぶモデル

結論はシンプル。得意な仕事で使い分けることです。

  • 持ち帰り①長い開発（数時間規模）はMuse Wonder を試す価値あり。社外測定でも Opus 5.5 の上
  • 持ち帰り②短いコーディングと画面操作はOpus 5.5 のまま。メタ自身の表でも負けを認めている
  • 持ち帰り③記憶は社内ベンチで1位だが社外検証はまだ
  • 持ち帰り④単価は同じでも喋る量が少なく作業ごとに安く済む
  • 持ち帰り⑤導入時はコントリビューターモードを確認。会社のコードでは最初にオフに
「Opus 5.5 超え」は一面の真実。仕事の種類で選ぶのが正解なのだ！
