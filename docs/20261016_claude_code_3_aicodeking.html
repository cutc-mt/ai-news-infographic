01

今回のアップデートの要点：目的はただ一つ

Anthropicが Claude Code デスクトップアプリの大型アップデート をリリース。狙いは「複数セッションの同時実行を簡単にすること」の一点に集約される。

  • Claude Devs 公式アカウントが公式スレッドで発表
  • スレッドには短いデモ動画も付属
「セッション開始の高速化・作業の分割の容易化・各セッション状況の常時確認」の3本柱
02

背景：4月の再構築から今へ

今回の更新は突然のものではない。2026年4月、Anthropicは並列セッション対応のためデスクトップアプリを一旦再構築している。

  • 4月版：全セッションを一元管理するサイドバーを導入
  • ただし当時はセッションをリスト表示するだけ
  • 今回の更新はその機能を大きく拡張するもの
2026年4月 再構築10月 大型アップデート
03

新セッション画面：最近のフォルダー

新しいセッションを開始すると、画面に最近使ったフォルダーが表示されるようになった。クリックだけでその場所でセッションが始まる。

  • デモでは storefront-web / payments API / infra の3フォルダーが表示
  • 毎回フォルダーを探す手間がなくなる
「どこで作業するか」の選択がワンクリックに——セッション開始の摩擦がほぼゼロに
04

環境（Environments）：保存されたセットアップ

環境とは「保存されたセットアップ」。複数フォルダーのまとまり、SSHホスト、クラウド環境なども指定できる。

  • 例：フロントエンド＋バックエンドのリポジトリを1つの環境として保存
  • 「環境を選択」メニューから選ぶだけで即セッション開始
  • 一度保存すれば何度でも再利用可能
複数フォルダーSSHホストクラウド環境
05

フォルダーごとのワークツリー

各フォルダーに専用のワークツリー（git worktree）を持たせられる。ワークツリーとはセッションごとにリポジトリを個別コピーしたもの。

  • 同じフォルダー内の2つのセッションが同じファイルを変更しないで済む
  • 並列作業によるコンフリクトが原理的に起きない
動画主の評価：「これは素晴らしい改善」——並列開発の土台がここで完成
06

最大の目玉：ネストされたセッション

Claudeに複数タスクを並行依頼すると、タスクごとに個別セッションが自動生成。これが「ネストされたセッション」で、それぞれ独立して動作する。

  • 完了するとメインセッションに結果が返る
  • 以前は並列作業の出力がメインチャットを埋め尽くし読みにくかった
  • メインには結果だけ表示、詳細は個別セッションを開いて確認
07

ネストデモ：「製品グリッドのレイアウトずれ修正」

公式デモでは、メインセッション「製品グリッドのレイアウトずれを修正」の下に2つのネストされたセッションがぶら下がる。

1画像をスクロール時に読み込むよう修正
2サイドバーのカード画像に幅・高さを指定
3完了後、結果をメインセッションへ返却

メインチャットが散らからず、詳細はいつでも子セッションで確認できる

08

フォローアップの提案：次タスクをワンクリック

作業中、Claudeがあなたのために次のタスクを提案するように。クリックすれば個別セッションとして始まり、現在のタスクは中断されない。

  • デモ：レイアウト修正完了後、「修正しきれなかった3項目」をClaudeが検知
  • カート内画像サイズ・スクロール下の遅延読み込み・チェックアウトフォームのラベル
  • 「チェックアウトフォームにラベルを付ける」タスクを提案→サイドバーに作業セッション追加
09

/btw コマンド：サイド質問タブ

セッション中に別の質問が浮かんだら /btw に続けて質問を入力。質問は新しいタブで開かれる。

  • メインセッションはそのまま動き続ける
  • Claudeを止めない・メインの文脈を混乱させない
  • 動画主：「これも非常に素晴らしい機能」
「ちょっと聞きたい」を本流から切り離す——コンテキスト汚染を防ぐ仕組み
10

サイドバーのステータスグループ

セッションがサイドバー上で3つのグループに自動整理される。「入力待ち」「実行中」「完了」の分類で、一目で自分を必要とするセッションが分かる。

  • 「入力待ち」へ移動したセッションには警告アイコンが表示
  • 完了セッションには実行場所アイコン（コンピューター or クラウド）
入力待ち実行中完了
11

セッション内新機能①：ライブToDoリスト

Claudeの計画が表示され、作業の進行に合わせてリアルタイム更新される。完了ステップにはチェックマークが付く。

  • ズレの再現とテスト実行
  • 商品カードへの画像サイズ追加
  • グリッド内のスペース確保
  • プレビューでのグリッド確認
  • レイアウトズレのテスト追加

デモの計画は5ステップ——進捗が可視化され「今どこをやっているか」が明確

12

②要約カード＆③サイドレール

Claudeがあなたを必要とするとき、要約（リキャップ）カードがそのターンの作業内容を要約。質問を探してスクロールバックする必要がない。

  • サイドレール：セッションの実行場所・使用中のコンテキスト量・変更したファイルを表示
セッション内部にも「見える化」が浸透——計画・要約・状態の3層で把握
13

試し方：今日から使える

導入手順はシンプル。既存ユーザーはアップデートするだけ。

1Claude デスクトップアプリをアップデート
2新しいセッションを開始（未経験者はアプリをインストール）
3コードタブを開き、プロジェクトフォルダーでセッション開始

動画主の総評：「全体としてかなりクール。正しい方向性だが完璧ではない」

14

反応はまちまち：賛否両論

公式投稿へのリプライは好評一色ではない。多くのユーザーがeffort（努力レベル）スライダーの復活を求めている。

  • リニューアルで削除または隠された模様
  • GitHubのPRボタンが見つけにくくなったという声
  • 「前のサイドバーの方が良かった」派も
  • セッションがリスト内で勝手に移動するのが不満——位置を把握したい
15

最大の壁は利用制限（Rate Limit）

多くの返信が指摘する本当の障壁は利用制限。動画主も「彼らの言う通り」と率直に認める。

  • 並行セッションが増えれば利用量もその分増加
  • ネストされたセッションはさらに負荷をかける
  • Proプランではすぐ制限到達→実質 最大プラン向けの機能
  • Anthropicは今回の更新で制限変更を表明していない
10個もセッションを開く前に、自分のプランの制限を思い出して
16

アイドル時圧縮（Idle Compaction）

Anthropicの Lydia Hallie が発表した新機能。長いセッションがアイドル状態になると、Claude Codeがキャッシュ期限切れ直前にセッションを圧縮する。

  • 「圧縮」＝会話を短い要約にまとめること
  • 戻ってきたとき、会話全体ではなく要約のみを処理すれば済む
  • ターミナルに「プロンプトキャッシュが期限切れになる前にアイドル時に圧縮されました」と表示
17

なぜ効くのか：プロンプトキャッシュの仕組み

メッセージを送るたび、Claudeは会話全体を処理し直す必要がある。プロンプトキャッシュはその作業を一時保存し、次のメッセージを安くする。

1キャッシュの寿命は約1時間
22時間放置するとキャッシュ消失→会話全体の再処理で制限を大量消費
3アイドル時圧縮なら要約だけ処理→利用量を節約

節約量は未公表だが、多セッション運用では一部が必ずアイドルになるため理にかなう

18

動画主の総評と今後の要望

ベストは「ネストされたセッション」と「/btw タブ」。長いセッションの散らかりという実際の問題を解決してくれる。

  • サイドバーのステータスグループも良い
  • 要望：effortスライダー復活・制限への対応・プロジェクト単位グループ化・複数アカウント・スマホからのセッション一覧
  • 使い込んだらハンズオン動画を予定
方向性は正しい。だが制限が変わらなければ、多く人は活かしきれない
