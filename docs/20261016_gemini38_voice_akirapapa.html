準備編：材料とルール

この動画で分かること

  • Gemini 3.8 Flash TTSに自分の声を登録し、日本語の文章を読ませるまでの実体験
  • 画面の操作では途中で止まった…しかし公式APIで本人確認（同意の確認）を通せば最後まで作れた
  • 必要なもの・手順・つまずきポイント・聴き比べまで全文公開
「いまの声は、私ではない」— 冒頭から、もう生成音声で語り出す導入です。

必要な材料は録音2本

  • 自然な話し声の録音 — 普段のトーンで読み上げた音声
  • 決められた同意の文の録音 — 公式が指定する同意文言を読んだ音声
  • この2本をそろえるのがスタートライン。特別な機材の話はなし
「話し声」＋「同意文」の2本だけ。材料のハードルは低めです。

使えるのは「大人の自分の声」だけ

  • 対象は大人の本人の声のみ
  • 他人の声での複製は禁止
  • 合成した同意の音声も使わない
  • APIキーと声のIDは人に見せない
ルールを守って使うのが大前提。同意文はそのための仕組みです。

全体の流れ（2経路）

  • 画面操作で進める → 今回は途中で止まった
  • 公式APIに切り替え → 本人確認（同意の確認）を通過
  • 日本語のナレーション生成まで完走
画面で止まっても諦めない。APIという別ルートが用意されている、というのが本動画の核心。
実践編：つまずきと突破

画面の操作で止まった

  • 画面上のフローでは途中で停止して先に進めない事態
  • 止まったときに試したことを逐一記録・公開
  • この体験を「日本語はできない」と一般化しない、と明確に断り書き
1回の失敗で全体を判断しない。実体験ベースの冷静な姿勢が特徴的。

録り直しで登録が通った

  • 音声を録り直すことで登録が受理
  • 止まった → 試す → 直す → 通る、の実践ループをそのまま共有
  • 同じ箇所で止まる人へのヒントになる失敗談
「録り直したら通った」— 地道なリトライがAPI本体への扉を開きます。

APIは2段階構成

  • まず声を一度登録する（Voices API）
  • 同じ声のIDを使って音声を生成する
  • 登録と生成が同じIDで紐づくのがポイント
// イメージ（2段階）
// 1) 声を登録 → voice_id を取得
voice = register_voice(録音2本)
// 2) 同じIDでテキストから音声生成
audio = generate(text="原稿",
                 voice=voice.id)

原稿と話し方は別々の欄

  • 読み上げる原稿（text）は専用欄
  • 話し方の指定はstyle欄で別渡し
  • 原稿に命令を混ぜず役割分離できるのがAPIの利点
// イメージ：text と style を分けて渡す
generate(
  text  = "今日は良い天気です。",
  style = "落ち着いた丁寧な語り口で"
)
