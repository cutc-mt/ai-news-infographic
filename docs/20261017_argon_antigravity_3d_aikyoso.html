01

なぜ「Antigravity×Argon」なのか

前回は本家GeminiでArgonを使用し、エラーが頻発して操作性が悪かった。今回はAntigravity（エージェント専用アーキテクチャ）でArgonを動かし、どこまで変わるかを検証。

  • 本家Gemini → エラー多発・操作しづらい
  • Antigravity → エラーがほとんど起こらない
  • よりエージェンティックにタスク実行できるようになる
02

Opus 5.5と比べる理由は「API料金」

なぜClaude Opus 5.5と対決させるのか。それは将来的にArgonのAPI料金がOpusと同じ水準になる想定だから。

  • 現在はSonnet・GPTソル相当の料金帯
  • 将来的にOpusとArgonが本気の価格勝負に
  • その未来を先取りして実力比較
03

ベンチマークの歪み：自前 vs 外部

公開ベンチマークだけでは実態が見えない、というのが出発点。

  • Google自前のベンチマークではArgonがほぼ全勝
  • Opus 5.5はターミナルベンチなどワークフロー系に強み
  • AIアリーナ等の外部ベンチではOpusが優勢な場面も
  • だからこそ自作ワークフローでの実測スコアリングが必要
04

3D対決：ブレンダー不使用の名古屋城

前回はArgonでドラフトを作りOpusで拡張した名古屋城3Dが完成。今回はその全工程をArgon単独で挑む。

  • Blenderなどの3Dツールは不使用
  • それでも立体構造をここまで組めるのがArgonの強み
  • 資格的（視覚的）には分かりやすいが、3Dだけで能力測定はやや不完全
  • だからコーディング系ワークフローでも採点
05

本家Gemini編：設計図→Opusレビューで飛躍

本家での手順は「まず図面・設計図を作り、そこから3D化する」方式。

  • 設計図を先に作ると構造的に正確になりやすい
  • 最初の1作目はあっさり目 → 石垣の石や屋根の質感を拡張
  • さらにOpusがレビュー → 指示 → 再生成で質が激変
  • レビュー前後で「全然違う」＝生成AIのレビュー力の重要性
06

Antigravityの秘密：.mdファイル自動読込

AntigravityでArgonが最初にやったのは、エージェント構築用のMDファイル群を指示なしで大量読込。

  • CORE.md（エージェント構築）→ 言わなくてもじゃんじゃん読み込む
  • RULES.md（禁止事項）・THINKING.md（考え方）も自動で
  • エモーション・ストラクチャー・コーディング・リサーチ・エージェントループまで
  • 私の意図通りのエージェント挙動を再現
07

改造テクニック：GEMINI.mdの1行ハック

解説者の常套手段——GEMINI.mdに「CORE.mdを見て」の1行だけを書く運用。

  • 毎回の大量読込が不要になり挙動が軽くトークン効率UP
  • 1番最初だけ読み込んで後は読まない設計
  • すっきりした生成が可能に
08

三面図の差：本家 vs Antigravity

設計図の質で明暗。本家の図面は「そこまで複雑でない」ミトリ図だった。

  • Antigravity版はいろんな方向からミトリ図を描画
  • かなり複雑で詳細な図面を生成
  • 自作MDファイル読込 × Antigravityアーキテクチャの相乗効果
  • 本家Argonよりかなり拡張された印象

3D成果：光の演出と率直な評価

立体化された名古屋城は光源演出が特に秀逸。ただし完璧ではない。

  • 1発でこの精度 → そこからブラッシュアップしていく戦い方

Antigravityが生む「ファイルの厚み」

Argonの魂：新規性と突破力

常に高かったのが新規性。Gemini 3.0以前から続く「尖った答え」の系譜。

  • 非常に独自的な答えを出してくる＝相手出し（相棒）として優秀
  • OpusやGPTソル・Astraが付かなかった穴を1発で突いた実績
  • 行き詰まった時のワンポイント起用に最適
  • 数学の力も高い

  • 数学能力は高いので計算自体は正確

  • 未検証の答えを断言してしまう・大げさに言いすぎる
  • 出すべきでない段階で「完成しました」と宣言
