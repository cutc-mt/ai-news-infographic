セクション1：Cua Space SDKとは？
1
Cua Space SDK がついに登場

コンピュータユース製品で知られる Cua の仮想環境サービス「Space」に、待望のSDKが登場しました。

  • Linux や macOS のVM（仮想マシン）を手軽に作れる
  • 作った環境をそのままエージェントに操作してもらう
  • 従来はMCP＋アプリ経由だったのが、コードから直接生成・操作可能に
「エージェントに1台まるごと専用PCを渡せちゃう時代」って感じですね〜！
2
Cua Driver との関係

Cua には Cua Driver というコンピュータユースのドライバー部分があり、ヘルメスの裏側などでも使われていると動画で言及されています。

  • Cua Driver ＝ 画面を見てカーソル操作するコンピュータユースの中核
  • Space ＝ その「操作される側」の仮想PCを用意する新レイヤー
  • Driver ＋ Space ＋ SDK で一気通貫のエージェント環境に
つまりこういう構図ドライバー（操作する側）× スペース（操作される専用PC）をSDKでコードから組み立てる
3
従来ルートと新ルートの違い

Space の登場時は「MCPサーバー ＋ アプリ」で使うのが基本でした。今回のSDK追加で、扱い方が大きく変わります。

従来: MCP ＋ アプリ 新: SDKでコード生成
  • GUI操作が中心 → スクリプト・プログラムに組み込める
  • 自作ハーネスへの統合が一気に容易に
  • MCPも引き続き提供されている（ツール数は多めなので注意）
「アプリでポチポチ」から「コードでシュッと」へ。地味にでかい進化です。
4
作れるのは Linux / macOS のVM

Space 内に作成できる仮想環境は、Linux のデスクトップと macOS のVM の2系統。実際に動画内では MacBook Pro 上で Space が動かされていました。

  • Linux VM：クラウド系の用途ならコスパ良さそう
  • macOS VM：Apple 系環境が必要な検証に（料金は高め）
  • 作ったスペースはコードから何個でも列挙・管理できる
「今スペース何個あるっけ？」も get でサクッと確認できるらしい。
5
Space のときから変わらぬ強み

リソース設計も従来どおり。CPUやストレージ容量などを指定して、用途に合わせた空間を作り分けられます。

  • ストレージ量などのスペックを指定可能
  • 不要になったら削除して綺麗に保てる
  • 「1つの環境に詰め込む」より「役割ごとに分ける」設計向き
設計のヒント開発用・確認用・調査用…と分けると、その分スペックも要求されるので、分割は計画的に。
セクション2：SDKで何ができる？
6
スペースの作成・削除をコードで

SDK 経由で Create Space のようなコードベースの操作が可能。VMの立ち上げから片付けまで自動化できます。

# イメージ
space = client.create_space(os="linux", storage="...")
spaces = client.list() # 今何個あるか取得
space.delete() # 使い終わったら削除
作って・使って・消す。このサイクルが全部コードで回るのが強い…！
7
コードからターミナルを開く

自分の Mac で作ったスペースに対して、コードからターミナルを開いてコマンドを打ち込むこともできるようになりました。

  • シェルコマンドの実行をプログラムに任せられる
  • セットアップ作業（パッケージ導入など）を自動化
  • GUI 操作と CLI 操作を1つのSDKで使い分け
「エージェントにターミナルを渡す」か「自分のコードから叩く」か、両方いけます。
8
カーソル操作までそのままに

実際の操作画面では、カーソルで「ここをクリックして」という指示から、スペース一覧の取得まで、コンピュータごと自由に扱える様子が披露されました。

  • デスクトップを画面ごとエージェントに操作させる
  • ブラウザ・アプリなどGUIツールもそのまま利用
  • Cua Driver 由来の操作感をSDKから呼び出せる
人間がやる「ポチッ」を、そのままエージェントに代行してもらえる感じですね。
9
人間の介入もOK

エージェント任せにしつつ、必要な場面では人間が介入できます。完全放置ではなく、見守りながら微修正する運用が可能です。

  • 危なそうな操作は人間が差し込みで確認
  • 認証入力や判断が要る場面を人間側で担当
  • エージェントと人間の協働ワークフローを組める
運用イメージ基本は自動、要所は人間。介入ポイントを設けておくと安心。
10
ピクチャーインピクチャー表示

コードベースでもピクチャーインピクチャーが使えます。手元の MacBook 画面の右下に、スペースの様子を小窓で表示させられるとのこと。

  • 作業しながらエージェントの動きを常時チェック
  • 監視用ウィンドウをわざわざ用意しなくてOK
  • 複数スペースの様子を並べて見る運用にも
画面のすみっこにエージェント専用PCがちょこん。これだけで未来感ある…。
11
チームでの共有も可能

作ったスペースはチームで共有できます。個人の検証環境にとどまらず、チーム開発のインフラとしても使える設計です。

  • 共有スペースを複数人・複数エージェントで利用
  • 環境の共有により属人化を回避
  • 検証環境の再現性がチーム内で担保される
「俺の環境では動く」問題も、スペース共有で説消しできるかも？

12
Claude Code に専用PCを

動画タイトルの核でもある使い方。Claude Code などのCLIエージェントに仮想環境を1台提供し、その中で自由に振る舞ってもらう構成が取れます。

Cua Space でVM作成 Claude Code に接続 専用PC内で作業
メイン環境を汚さず、エージェント专用の「遊び場」を渡せるのが嬉しい。
13
役割ごとにリソースを分ける

「開発係」「確認係」「調べるもの係」のようにエージェントの役割でスペースを分ける設計が有力。ただし分けた分だけスペックが必要になる点はトレードオフです。

  • Space A：開発用 / Space B：確認用 / Space C：調査用…
  • 役割分離で干渉を防ぎ、再現性も向上
  • 増やしすぎるとコスト・管理が膨らむのでバランス重要
「エージェント1人に1台」が当たり前になる日、意外と近いかも。
14
Grokボットとの比較

勢いのある Grok ボットは、契約すると 1アカウントに1台の Linux VM が提供され、複数のボットで共有する形式。Cua Space はここに「追加」の選択肢を足せます。

観点GrokボットCua Space
VM提供1アカウント1台（Linux）Space A/B/C…と追加可能
OSLinux VMLinux / macOS
管理方法提供されるがままSDKでコード管理
Grokボットの共有VMも便利だけど、「スペースを足せる」のが Cua の強みですね。

16
MCP利用時の注意点

SDK だけでなく MCP も提供されていますが、登録されるツールの数が「激しめ」。そのまま繋ぐとコンテキストを圧迫しかねません。

  • ツール数が多いので必要なものだけ有効化
  • コンテキスト消費を意識した設計を
  • SDK直使いなら自分で API を絞って制御できる
MCP 便利だけど「全部盛り」は禁物。選んで使うのが大事そうです。
17
「エージェントOS」が来る

動画では エージェントOS がこれから流行るという予測も。ブラウザユースならエージェントブラウザ、コンピュータユースなら Cua Driver ＋ Space というように、道具を選ぶ時代へ。

  • ブラウザ操作 → エージェントブラウザー系
  • コンピュータ操作 → Cua Driver / Space
  • 自作エージェントOS・自作ハーネスの基盤に最適
「自作エージェントOS、次のハーネス作るなら Cua Space でしょ」という着地。納得です。
