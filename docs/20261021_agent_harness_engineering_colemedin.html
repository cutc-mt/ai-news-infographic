どんな本番エージェントにも必要なのが、稼働中に教訓を学べる仕組み。ユーザーとの対話でエージェントが苦戦したら、それを検知して不確実な状況を人間へエスカレーションできるようにする。そのための「チームの受信箱（インボックス）」を用意し、人間が正しい答えを与えると、エージェントがそれを教訓として確実に記録する。記録はLangChainの呼ぶところのContext Hubに蓄積され、後からいつでも取り出せる——「この状況は前も対応したな。人間チームはこう修正してくれた。だから今回はこう答えよう」という推論ができるようになる。

1. 不確実性の検知エージェントが迷ったら完全停止せずサポートを継続しつつ表面化
→
2. チーム受信箱へ修正を待つ案件として人間にエスカレーション
→
3. 教訓を記録人間の修正をメモリーに保存し次回に活用

CARD 14

LOOP 2（ハーネス改善）: LangSmith Engineが失敗から修正案を作る本番トレースという「無視できない最大の情報の宝庫」

CORE LOOP 2

メモリはContext Hubの重要部分だが、ハーネスの本体はコアとなるワークフローと指示。ループ2では、LangSmithが本番実行のトレースデータをすべて取得し、Engineがそれを収集して実際のデータで発生した失敗に基づく改善提案を自動生成する。提案には失敗の詳細説明が付き、必要ならLangSmithのトレースで証拠を確認できる——問題発生時にモデルが何をしていたかを会話単位で追跡可能。そしてお気に入りの部分というのが一番下の修正案: 「instructions.mdをこのように変更すべき」という具体的な差分を提示してくれる。コーディングエージェントの「システム進化」と同じで、ハーネス全体（ルール・ガードレール・指示）を調査し「この問題が二度と起きないように何を調整すべきか」を見つけ出す。提案は簡潔——文脈を詰め込んでルールを肥大化させないため。

1. トレース収集LangSmithが本番実行をすべて記録
→
2. 失敗分析Engineが実データの失敗を検出・説明
→
3. 修正案生成instructions.mdなどへの変更案を提案
→
4. 承認して適用人間が承認すれば即座に本番反映
