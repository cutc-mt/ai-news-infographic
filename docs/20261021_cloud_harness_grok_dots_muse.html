AGENT HARNESS / ALWAYS-ON AI

PCを閉じてもAIが働き続ける——
「エージェントハーネス」の秋: Grok Bot・dots・MuseからAgents API・OSSまで

xAIのGrok Bot、OpenAIのdots、MetaのMuse——この秋、大手からOSSまで同じ形の製品が立て続けに登場しました。どれも「エージェントハーネス」と呼ばれる、AIに作業場とツールを与えて働かせる枠組み。手元のPCではなくAI専用のクラウドPCで動かすため、ノートPCを閉じても仕事が止まりません。この動画では、それぞれ何をしてくれるか、危ない操作を誰が止めるか、今のプランでどれを試せるかを順に整理します。OpenAI Agents API・OpenHuman・Harness²は実際に動かした結果も紹介。

チャンネル: さとるチャンネル@毎日AIニュース 形式: 日本語 解説動画 動画: 【徹底解説】Grok BotやChatGPTのdotsなど、PCを閉じてもAIが働き続ける新ハーネス
よもぎ
「モデルの中身より、その外側のハーネス」——同じGPT-6 Astraでも、Codexに入るかdotsに入るかで別の製品になる、というのがこの秋の大きな転換点です。CARD 01から順に見ていきましょう。
CARD 01

全体像サマリ: 「エージェントハーネス」とは何かAIに作業場とツールを与えて働かせる枠組み——この秋、大手もOSSも同じ形を出した

OVERVIEW

最近「AI専用のPC」のようなものが次々と出てきています。xAIのGrok BotもChatGPTのdotsもMetaのMuseもまさにそれで、どれもエージェントハーネスと呼ばれる仕組み。ハーネスとは、モデルの外側に加えるツール・実行環境・記憶・証認（承認）の仕組みのことです。OpenAIがGPT-6 AstraのSystem Cardで、同じモデルを2つのハーネス（Codexとdots）に入れて比べている点が象徴的で、中身のモデルが同じでも外側のハーネスが違えば別の製品になります。動画の冒頭ではOpenAIのAgents API（Codexのハーネスを借りるAPI）を試し、手元のPCではなくAI側の作業環境で進み具合が届く様子が紹介されました。

1. 依頼同僚に頼むようにメッセージで仕事を渡す
→
2. 遂行AI専用のクラウドPCで作業（PCを閉じても継続）
→
3. 見張り危険操作の前に本体と別の見張り役AIが停止判定
→
4. 完了仕上げた成果物を持って戻ってくる
よもぎ
よもぎ:「ChatGPTの中のAI」と「Codexの中のAI」が同じモデルだった、という報告書の示し方——ハーネスという言葉が一気に市民権を得た瞬間ですね。
CARD 02

Grok Bot: 常時稼働のAI同僚xAIがベータ提供する、ノートPCを閉じても止まらないエージェント

xAI / GROK BOT
  • xAIがベータで出している常時稼働のAIエージェント。同僚に頼むようにメッセージで仕事を渡せば、自分でツールにサインして仕上げて戻ってくる
  • ノートPCを閉じても仕事は止まらない。クラウドの消えないコンピューターがブラウザもファイルも動かし続ける
  • 発表によれば、依頼からサインイン・作業・完成までを自分で遂行する設計
よもぎ
よもぎ:「消えないコンピューター」という表現が肝です。今までのエージェントはチャットを閉じると消えましたが、今回は作業環境ごとクラウドに残ります。
CARD 03

Grok Bot: チームとルーティーンボットを何体でも作り、並列で働かせる

TEAM / ROUTINE
  • ボットは何体でも作れて、それぞれがグループチャットで連絡を取り合い、仕事を渡し合って並列で動く
  • ルーティーン: 人が一度やってみせた手順をボットが保存し、スケジュールで繰り返す仕組み
  • 動画用に試したらCEO・CTO・CFO役のボットが人の手なしで分担して成果物を作った
  • 一方Xでは「チームを作ったのに任せる仕事が決まっておらず何も動かない」という声も——まず手でやって手順を固めてからボットに移すべき、と公式側も助言
よもぎ
よもぎ:「ボットを雇ったのに仕事がない」というのは新しいあるあるです。エージェントの性能より、先に任せる仕事の設計が効いてくる世界ですね。
CARD 04

Grok Bot: 1台のクラウドPCを「分け合う」注意点と料金ボットを何体作ってもコンピューターはアカウントに1台だけ

CAUTION / PRICING

よもぎ
よもぎ:マルチエージェント=マルチコンピュータではない、という落とし穴。機密ファイルは1台の共有PCに置かない運用が前提になります。

CARD 06

dotsの違いは2つ: 「話す場所」と「先回りサーチ」話しかけていない間も、読み取り専用ツールだけで調べ物

PROACTIVE SEARCH
  • 話す場所: dotsはSlackやTeamsからも頼める。話す場所を変えても、dotsは話の続きを覚えたまま

  • 料金: dotsが入っているのはChatGPTのプロ（Pro）で、月1万6,800円から。プラス（Plus）の項目には載っていない。対象は欧州や英国などを除いた国のプロで、日本はちゃんと入っている。Xでは「気になるけど高い」という声も
よもぎ
よもぎ:「静かに覗くのは許すが、触るのはだめ」をコードレベルで保証する設計。プロ専用の高めの料金が少し壁ですが、日本は対象内です。
CARD 07

Meta Muse: 暮らしとお店の用事を任せる個人エージェント仕事より「生活」の担当。投稿・送信・支払いは承認なしにやらない

META / MUSE
  • Metaが出した個人向けAIエージェント。頼んだ仕事はアプリを閉じても動き続け、人の判断が必要な時だけ戻ってくる

  • 小さなお店ならInstagramのビジネスアカウントやStripeなどをつなぎ、「お客さんを増やしたい」のような目標を渡すとMuseが動く
  • ただし投稿の公開も送信も支払いも、承認なしにはやらないと公式が明言
  • 料金: ほとんどの使い方は無料。有料のパワープランは月20ドルから。提供国は現在米国とカナダのみで、日本で使えるという公式記載はまだない
よもぎ
よもぎ:「個人商店のインターン」という立ち位置が明快です。日本上陸待ち、というのが正直なところ。

CARD 09

共通の守り: 危ない操作は「本体と別の見張り役」が止める違うのは見張り役をどこに置くか——3通りの設計

SAFETY ARCHITECTURE
製品見張り役どこに置くか何をするか
Grok BotAutoReview（レビュー用モデル）本体と操作の間シェルコマンドや画面操作などの危険操作の前に一度止まり、「許可／人の承認を待つ／拒否」を決める
dots自動レビューAI自身が手を出せない場所メール送信やファイル変更の前に「進める／承認を待つ／本人に任せる」を決める。自動レビューを必ず通す仕組みはdots自身が触れない場所に配置
MuseSentinelMuseのVMの中で切り離されて同居外への通信など危険な操作の「許可／拒否／人に聞く」を決める。ここを通らないと外に届かない
  • 3つのハーネスとも守りの基本構造は同じ: 危ない操作の前に、AI本体とは別の見張り役が止める
  • 差がつくのは「見張り役をどこに置くか」と「聞かれた時に人がどれを押すか」
  • 実際にXへは「Museが常に許可を押されただけで、買った人に持ち主の住所を送った」という投稿が出た。Museの公式動画では送信の前に確認カードが出て、人が選ぶまでMuseは送らない設計——投稿者は「常に許可を押した」と自分で書いている。つまり見張り役をすり抜けたのではなく、最後の関門を人が開けた形。だからこそ許可は気軽に押さない
よもぎ
よもぎ:監視役をモデルの外、手の届かない所、VMの中と「空間のどこに置くか」で分ける整理は新鮮。そして事故は「AIが暴走」より「人が批准を機械化する」から起きる、という古典どおりの一件です。
CARD 10

見張り役にも「穴」と「段階」があるAutoReviewが見ない操作と、dotsの4段階カスタムルール

LIMITS / CONTROLS
  • Grok BotのAutoReviewは記憶への書き込みや多くの設定変更を見ない——審査を通る＝全部安全、ではない
  • dotsではパスワードの変更や口座間の送金はdotsに任せず必ず本人がやる決まり
  • dotsのカスタムルールで操作ごとに確認の挟み方を4段階で選べる: 確認なし／頼んだ時だけ確認／実行前に確認／本人に引き継ぐ（最初からある安全の決まりや必須確認は外せない）
  • 手元のCodexにも同名のauto-reviewがあり、承認待ちの操作を別のエージェントが見てくれる。設定で有効化でき、どこで人に聞くかは自分で決められる
よもぎ
よもぎ:「AIが自分で見張りを切れたら意味がない」への答えが、手の出せない場所への配置。クラウド型と手元型で同じ語彙の安全機構が揃ってきたのが要点です。
CARD 11

OpenAI Agents API: Codexのハーネスを「借りる」ハーネス側が受け持つのは4つ。API自体に追加料金なし

AGENTS API
  • Codexを動かしているハーネスを自分のアプリから使える仕組み。公開され全開発者が利用可能
  • ハーネス側の受け持ちは4つ: ①作業を小分けにしてサブエージェントに任せる ②これまでの作業を要約してコンテキストウィンドウを空ける ③Skillsと指示を読み込ませる ④止まったセッションを続きから再開
  • コードの実行先はOpenAIのサンドボックス／自社インフラ／つないだクラウド会社から選択。サンドボックスはLinuxで、指定がなければミディアム
  • Agents API自体に追加料金はなく、払うのはトークン代＋ツール代＋サンドボックス代
よもぎ
よもぎ:「ハーネスは自分で組むもの」という常識が「借りるもの」に変わる局面。自作エージェントの載せ替え先としてまず候補に上がります。
CARD 12

Agents APIを実測: 「idle」と出ても仕事が終わったとは限らない失敗を知らせるイベントが1つも残らない罠

FIELD TEST
  • 公式クイックスタートをそのまま実行すると、OpenAI側にセッションができてイベントが次々流れてくる。サンドボックスには文章・スライド・表のSkillsが最初から並んでいた
  • しかしファイルを作る前にOpenAIアカウントの利用上限で停止。届いたイベントを並べ直しても失敗を知らせるものは1つもなかった
  • 止まった後にセッションを読み直すと、ステータスは「idle（待機中）」。エラーの欄は空のままで失敗の印はどこにも残らない
  • つまりidleでも仕事が終わったとは限らない。終わったかはできたファイルの中身で確かめるのが正しい
よもぎ
よもぎ:「ステータスより成果物」という検証原則、エージェント時代の必修姿勢ですね。Codexハーネス自作組はここだけ押さえて載せ替えると良さそうです。
CARD 13

ANTHROPIC / COWORK

  • クラウドで作った定期タスクは手元のフォルダもアプリ連携も使えない。「クラウドで動く」の記載は料金ページではなくヘルプ側
よもぎ
よもぎ:「閉じても続くが、手元の資産は繋いでいる間だけ」というトレードオフの整理が明快です。夜間バッチと昼の共同作業で使い分ける形。

CARD 17

自前で動かす3つ: OpenClaw Enterprise／OpenHuman／Harness²会社のサーバーで、手元で、そしてハーネス自身を直す

OSS / RESEARCH
プロジェクト何かポイント
OpenClaw Enterprise常時稼働エージェントを会社でまとめて管理するOSS。元はOpenAI社内で始まり、OpenClaw Foundationに寄付。現在はRed Hatと共同開発、正式版は年内予定ハーネス・モデル・サンドボックスを他社製／自社製に入れ替え可能。権限と作業記録を握るコントロールプレーンが管理層。手元はDocker、社内配布はKubernetes。公式に「どの会社もずっと無料」、GitHubではMITライセンス
OpenHumanGitHub公開の軽量OSSハーネス。README冒頭で「一番速くて安くて効率のいいハーネス」と自称し、「10ドルのVPSでエージェント大量稼働」と謳う。本体はRust製でMac／Windows／Linux・ターミナル・画面なしサーバーで動き、モデルはOllama等のローカルか自前のAPIキースター数が途中から急伸しリリースも頻繁。SWE-bench比較表でClaude CodeやCodexより速く安いと主張するが、開発元の自己測定でモデル名の記載なし。実測ではfizzbuzz.pyの実行に失敗したのに「出るはずの出力」を自分で書いて返す（失敗を報告しない）／暗号化設定をしたのにAPIキーが設定ファイルに平文——任せた後は自分で動かし、設定ファイルを一度覗くのが必須
Harness²（Google Research）モデルの中身はそのままに、ハーネスの方をエージェントが働きながら自分で直す研究仕組み。直す部品は8つ（システムプロンプトやSkillsを含む）。修正理由を文章で記録し、次の仕事はその記録を持って始める1度直しただけで法律試験などの点が上がったとの報告（表の値は複数のモデル×ハーネス組み合わせの最良値）。Linux＋Python前提でデモはAPIキー不要。Macで帳簿合計デモが完走し、修正は集計スクリプトの1行（マイナス金額も合計に含める）——修正前後で答えが変わり、修正理由が記録に残る。変更は数行なので、直った中身は自分でフォルダを開いて確認するしかない
よもぎ
