全体像サマリ: 全コーディングエージェントを1ウィンドウへ統合「ターミナル乱立問題」を解決する無料OSSのデスクトップアプリ

動画製作者は日頃から Claude Code・Codex・Kimi Code・OpenCode・GLM・Mimo・Grok Build・Antigravity など多数のコーディングエージェントを使っているが、各エージェントがそれぞれ別のターミナルで動くため「5個もターミナルを開く」「承認待ちに気づかない」「10分前に完了したのに放置」「どのエージェントがどのファイルを変えたか分からない」といった問題が常態化していた。Panda Code はすべてのコーディングエージェントを1つのウィンドウで実行するデスクトップアプリ。プロジェクト管理・Git・ターミナル・ブラウザ・タスクボード・エージェントチーム・ボットまで同じウィンドウに統合し、無料・オープンソースで公開されている。

CARD 02

無料・完全OSS・モデルを売らないアカウント登録不要・データ収集なし・追加課金ゼロ

LICENSE
  • 無料でオープンソース（MITライセンス）。アカウント登録もライセンスキーも不要
  • ユーザーのデータを一切収集しない設計
  • Panda Code 自身はモデルもプランも売らない——既にインストールしたコーディングツールを、ユーザー自身のログインでそのまま利用
  • Claude・ChatGPT・Kimi・GLM などの支払済みコーディングプランをそのまま使えるので追加費用ゼロ
  • 再配布には1つだけルール: コピーを共有する場合は「Panda Code のコピーである」ことを明記
よもぎ

CARD 03

なぜ12MB・最速なのか: OSのWebViewを使う設計Chrome同梱もバックグラウンドのnodeサーバーもなし

LIGHTWEIGHT
  • アプリサイズはわずか12MB。動画タイトルの「4X FASTER」通り動作も高速
  • コンピュータが元々持っているWebViewを利用——Chromeのコピーを同梱せず、バックグラウンドでnodeサーバーも起動しない
  • セルフアップデート機能を内蔵。エージェントが動いていないタイミングでのみ新バージョンを自動インストール（1回ダウンロードすれば良い）
よもぎ
よもぎ:「Electronのようにブラウザを丸ごと積まない」選択が12MBという軽さの正体。ダウンロードと起動のストレスが根本的に違います。

CARD 05

プライバシー設計: すべてローカル、自動通信は3種のみプロンプトは選んだエージェント／サービスにだけ送信

PRIVACY
  • すべてのデータは自分のコンピュータ内のローカルデータベースに保存
  • プロンプトはユーザーが選んだエージェントやサービスにのみ送信される
  • アカウントなし・トラッキングなし。自動通信は①エージェントの新版確認 ②コスト見積用の公開モデル価格リスト取得 ③自身のアップデート確認（無効化可能）の3つだけ
  • APIキーはコンピュータのキーチェーンに保存され、各キーはその提供元にだけ送られる
よもぎ
よもぎ:「何と通信するか」を3つに絞り切った明快さが信頼の源泉。OSSなのでコードを読んで自分で確認できるのも強みです。

CARD 07

画面構成とモデルピッカーアニメ壁紙21種・エージェント×モデルをタスク毎に選択

UI / MODELS
  • 左サイドバーにプロジェクトとスレッド、中央にチャット、下部にプロンプトボックス。「Open Project」→「New Task（Command+N）」で「何を作る？」ページを開始
  • アニメ壁紙を21種内蔵——7日×朝・昼・夜のシーンで日替わり、アプリのメインカラーが壁紙に合わせて変化。設定でオフにしたりVS Codeのカラーテーマをインポートしたりも可能
  • モデルピッカーでエージェントとモデルを組み合わせて選択: Claude Code（Opus / Sonnet）、Codex（GPT系）、Kimi Code、OpenCode、GLM、Mimo、Grok Build、Antigravity など。コンテキスト量と思考レベルも設定でき、タスクごとに記憶される
  • GLM・Mimo は設定でAPIキーを貼るだけ——Panda Code がそのキーで Claude Code を実行。安価なGLMコーディングプランとの相性が特に良い
よもぎ
よもぎ:「タスク単位でモデルを覚えている」のが地味に便利。高いモデルと安いモデルをタスクの重要度で使い分けやすくなります。

CARD 09

チャット体験: @でファイル参照、スラッシュでスキル呼び出し回答はライブ表示、作業ステップは1行に折りたたみ

CHAT
  • 例えば「設定ページにダークモードスイッチを追加して」と入力。回答はきれいなフォーマットでライブ表示される
  • @（アットマーク）を打つとプロジェクト内ファイルを検索——矢印キーで選んでEnterで添付
  • 先頭にスラッシュを打つとエージェントのスラッシュコマンドとスキルを出せる。Claude Codeのスキルがそのまま動く
  • ファイル読取・編集・コマンド実行などのステップは小さな1行バーに折りたたまれ、チャットが散らからない。クリックで全ステップ展開
よもぎ
よもぎ:「ログの洪水」を必要な時だけ開く折りたたみにしたのは、ターミナルGUIとして最も効く改善点です。
CARD 10

承認は見逃さない・入力は止まらない承認バー・メッセージキュー・リアルタイムステアリング

APPROVAL
  • エージェントの承認要求はプロンプトボックス直上の細いバーに1行表示（deny / approve）。要求が多いときは「approve all」で一括承認——ターミナル時代の最大の問題を解決
  • エージェント動作中でも入力可。Enterで送信するとメッセージはキューに入り、エージェントの完了後に自動送信。キュー内は編集・削除も可能
  • Command+Enter でステアリング: 実行中のランに割り込み、停止せずに方向修正（Claude Code と Codex が対応。他はキュー行き）
  • エージェントからの質問は選択肢カードで表示され、クリック1つで回答
よもぎ
よもぎ:「承認待ちで止まっていた」を可視化し、「待つ間に指示を書き溜める」を可能にした。エージェント並行運用の生産性の核心です。
CARD 11

変更管理: ターン単位の差分と内蔵Git「どのターンが何を変えたか」が正確に分かる

GIT
  • 毎ターンの変更を自動保存——各回答の下にそのターンで変わったファイル一覧が表示され、クリックでdiffを開く（左右比較 or 色付き1列表示）
  • ブランチ全体の合計ではなく、ターン単位で何が変わったかを正確に把握できる
  • 変更パネルはGitステータスを表示: diff確認・コミットするファイル選択・コミット実行までその場で完結
  • Command+J でタスクフォルダの本物のターミナルを開ける。回答中のファイル名はクリックで開く
よもぎ
よもぎ:「どのエージェントがどのファイルを変えたか分からない」という最初の悩みにターン単位のdiffで正面から答えた機能です。
CARD 12

内蔵ブラウザ・Runボタン・スマホシミュレータ表示確認・要素指定修正・実機風テストをウィンドウ内で

BROWSER
  • HTML・SVG・画像・PDFをクリックすると内蔵ブラウザ（チャット横に表示）で開く。最初のページはローカルサーバーとポート番号の一覧を表示——port 3000 のアプリもすぐ見つかる
  • ページ上の要素を選んでメッセージに追加可能。スクリーンショットを撮ってエージェントに送ることも——「このボタンが変」を選択して「直して」と言える
  • pandacode run.sh を置くとRunボタンが登場: アプリを専用ターミナルで起動しブラウザで開く。このファイルはエージェントに書かせて最新に保たせる仕組み
  • iOSシミュレータとAndroidエミュレータに対応——スマホ画面がチャット右に表示され、タップ操作も可能。エージェント自身がスマホを操作して動作確認できる
よもぎ
よもぎ:「エージェントが自分でビルド→自分でタップして確認」のループが1ウィンドウで回るのは、モバイル開発での価値が特に大きいです。

CARD 14

Worktree: 同一プロジェクトでエージェント並行実行独立ブランチのコピーで作業し、約2クリックでmainにマージ

WORKTREE
  • Git Worktree（独立ブランチ上のプロジェクトコピー）を利用——プロンプトボックス上のバーでプロジェクト・フォルダ・ブランチを確認
  • ブランチ名をクリックしてタスクを新しいWorktreeへ移動すると、エージェントは自分のコピー・自分のブランチで作業し、他のエージェントの仕事を壊さない
  • 完了後、同じメニューから「merge into main」で保存済みコミットをmainブランチにマージ。未コミット変更やコンフリクトがある場合は何も変更せず停止する安全設計
  • マージ後はWorktreeの削除提案、メニューからのブランチ切替（mainへ戻る等）にも対応
よもぎ
よもぎ:複数エージェントの同時走行を現実にする機能。「壊れそうなら何もしないで止まる」という慎重さもポイントです。
CARD 15

GitHub統合とタスクボードPR・Issueをワンクリック、全プロジェクトの状況を一目で

GITHUB / BOARD
  • GitHub の gh ツールを利用したGitHubビュー——リポジトリ・プルリクエスト・Issueを一覧表示。PRレビュー・失敗チェック修正・マージ・Issue対応がすべてワンクリックで、各アクションはサイドのスレッドとして開く
  • タスク内でエージェントがPRを開くとそのタスクに自動リンク——タスクのPRタブから確認・マージ可能
  • 「Board」で4列タスクボード（Pending / In Progress / Review / Completed）。Start で選んだエージェントが開始し、完了は Review へ→良ければ Completed へ。完了タスクは7日後に自動アーカイブ
  • サイドバーは各スレッドが1行表示で実行中・要対応・完了が一目で分かり、ピン留めとドラッグ並べ替えが可能。Command+F で会話の全文検索も
よもぎ
よもぎ:「Issueを見る→直させる→PRを出す→マージする」の流れがアプリから離れず一周します。
CARD 16

エージェントチーム: Architect＋最大3 Worker の並列分担エージェント混成もOK・名前付きチーム保存・Codex Goals

TEAMS
  • プロンプトボックスのTeamボタンでArchitect（設計役）＋最大3つのWorkerを起動——Architect が計画を立て作業を分割し、各Workerに割り当て。Worker は同時並列実行される
  • エージェントの混成が可能: Architect を Claude Opus、Worker に Codex・Kimi・GLM など。各Workerはチャット内の1行表示で、クリックすると右上に詳細が出る
  • Worker 完了後、Architect が成果を検証しサマリーと変更ファイル一覧を提示
  • 設定に名前付きチームを保存可能（例: GLM Worker の「安いチーム」、Opus＋Codex の「強いチーム」）→ モデルピッカーから選択
  • Codex はGoals（/goal）対応: 目標とトークン予算を書くと、バナーで進捗を示しながらターンをまたいで継続作業する
よもぎ
よもぎ:「強いモデルに設計させ、安いモデルに実装させる」というコスト最適化の編成がGUIで簡単に組めるのは大きいです。
CARD 17

Bots・VM・クラウドサンドボックス・デプロイスマホから指示し、隔離環境で動かし、そのまま公開

EXTEND
  • Bots: エージェントを Telegram・Slack・Discord・WhatsApp・ローカルWebチャットに接続——スマホからメッセージを送ると、自分のコンピュータ上のプロジェクトで作業。Bot毎にプロフィール・メモリ・スケジュール・チャンネル・ルールを設定可能（例: 毎朝リポジトリのサマリーを送るBot）。Bot チャットは通常タスクとして開いて続きの会話ができる

  • デプロイメニュー: Vercel・Cloudflare・AWS 向けのデプロイタスクを開始。エージェントは各CLIをユーザーのログインで使い、コマンドはすべて事前承認・キーは出力上でマスクされる

よもぎ:「スマホで頼む→自宅MacのVMで検証→クラウドへ公開」という在宅エージェントの運用形態まで視野に入った作りです。
CARD 18

まとめ: コスト最適化と正直な注意点「5つのターミナル」から「1ウィンドウ管理」への移行

SUMMARY

コスト面でも工夫が詰まる。使用量ダッシュボードは全エージェントの上限（Claude の5時間／週次上限など）とリセット時刻を表示し、API料金換算の推定コストを週・月・年＋モデル別でグラフ化。タスク途中で上限に達したら「resume at reset」を選ぶだけで、リセット時に自動でタスクを再開してくれる。トークンセイバーは短文スタイル（caveman・lean code・quiet tools）で回答を短くし、この指示は変更時のみ1度だけ送信されるので節約機能自体がムダにならない。ターン終了時に次プロセスをバックグラウンド起動するため、実測でフォローアップの最初の語が約8秒→約4秒に短縮された。Command+Shift+Space のクイックオーバーレイでアプリを開かずタスク投入でき、任意アドオン「Jev」（成果物レビュー・アプリテスト、デフォルトOFF）も用意される。
