  • 国家サイバー統括室も「修正版を早く当ててください」と呼びかけ

  • 「この機会にWordPressをやめよう」という意見も登場
よもぎ

CARD 03

対象は「PHPで動くサイト」すべてWordPressだけの話ではない

SCOPE
  • PHPで動いているサイトならWordPressも含めてすべて対象
  • ログインしていない第三者から、外からの操作でサーバーを乗っ取られるおそれがある
  • 自分でPHPを書いていなくても、CMS・ブログツール経由で該当し得る
よもぎ
よもぎ:「うちCMSだから関係ない」が通らないのが今回の怖さ。動いている実態ベースで確認が必要です。
CARD 04

バージョン別の対応状況: 8.2〜8.5は修正版、8.1以前はEOL「7.4のまま」だったことが何を意味するか

VERSION MAP
バージョン今回の対応どうすべきか
PHP 8.2〜8.5各版に公式の修正版がリリース済みサーバー事業者がパッチを当てているか確認
PHP 8.1以前公式サポート終了（EOL）のため修正版のリリースなし8.2以上へのバージョンアップが前提に
PHP 7.4 / 8.0 / 8.1最小限の修正コードのみ用意本来は速やかな上位版への切り替えが望ましい
よもぎ
よもぎ:れん学長のブログはまさに「EOLの7.4」——パッチを待つことすらできない状態だった、というのが今回の出発点です。

  • Claudeはまず問題の解説と、手元環境の洗い出しから着手

CARD 06

調査結果: PHPが動くのはConoHa WINGだけその上に昔のWordPressブログが載っていた

FINDING
  • 環境を洗い出した結果、PHPが動いていたのはレンタルサーバー ConoHa WINGのみ
  • そこに昔のWordPressブログが載ったままだった
  • ブログのPHPは公式サポートが終了した7.4のまま——放置がその直撃だった
よもぎ
よもぎ:「動いているから気づかない」——更新をやめたサイトほど古いバージョンのまま残りやすい、典型パターンです。

DIVISION OF LABOR

Claudeが管理画面を順に進むサイト管理 → 応用設定 → PHP設定

CARD 09

判明した設定: サーバー共通が「7.4」ドメインごとの設定は「サーバー共通に準拠」

ROOT CAUSE
  • サーバー全体で使うPHPのバージョンが7.4になっていた
  • ドメインごとの設定は「サーバー共通に準拠」——つまりブログはずっと7.4で動いていた
  • 鉛筆マークを押すと、7.4から8.5までのバージョンが選択可能
よもぎ
よもぎ:「共通設定に準拠」は便利だけど、共通側が古いと全サイトまとめて古いまま。配置構成まで含めた点検の重要性が出ます。
CARD 10

選ばれたのは8.5ではなく8.3「長く更新していないテーマ」への配慮

WHY 8.3

Claudeが選んだのは8.3。新旧の差が大きい最新版ではなく、あえて一つ前の系統です。

  • 昔のブログのテーマは長く更新していない可能性がある
  • 8.4以降より変更点の少ない8.3のほうが表示が崩れにくいとClaudeが判断
  • 「最新」より「壊さない」を優先した保守的な選択
よもぎ
よもぎ:無闇に最新版へ飛ばさない——放置サイトほど「最小変更で安全側へ」が正解。AIが出す判断としても筋が良いです。
CARD 11

切り替え実行: 小さなトラブルも自己修正欄の表示が7.4のまま変わらず…

EXECUTION
  • 途中、選ぶ欄の表示が7.4のまま変わらない場面が発生
  • Claudeは欄を押して選び直すことで自力で解決
  • 保存を押すと画面左下に「成功しました」——欄の表示も8.3に変わった
よもぎ
よもぎ:UIの不調で人が諦めがちな場面を、AIは淡々とリトライする。地味ですが、自動化の大きな強みです。
CARD 12

切替後の動作検証もClaudeが実施表示確認で終わらせない二段構え

VERIFICATION

  • 切り替え後は記事ページ・検索結果ページも開いて確認
  • どのページも正常に返り、エラーの文字も出ていないことを確認
  • さらにブラウザで開き、表示が崩れていないことを目視でも確かめた
よもぎ
よもぎ:「切り替えた」で終わらず、前後比較まで取ってくる。エンジニアリングの作法がそのまま組み込まれています。
CARD 13

ここが最重要: 8.3にしただけでは「まだ安全」ではない今回の修正が入るのは8.3.36——パッチはサーバー会社が当てる

CRITICAL CAVEAT
項目内容
修正が入った版PHP 8.3.36（8.2〜8.5の各版にリリース）
レンタルサーバーの場合修正を当てるのはサーバー会社側——自分では当てられない
ConoHaのお知らせ一部サーバーで21日19時〜22日10時の緊急メンテナンスを告知していたが、今回の修正かどうかは記載なし
利用者がすべきこと使っているサーバー会社のお知らせで修正適用済みかを確認
