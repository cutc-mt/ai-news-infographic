HARNESS² / AIがAIを直す

正解がない仕事で、AIはどう自分を良くする？
頭は変えずに、周りの仕組み（ハーネス）を直す研究

Googleの研究チームなどが10月に論文とともに公開した「Harness²」を、ずんめたラボらしい対話形式で解剖する動画です。AIエージェントは「考える頭（モデル）」と「頭の周りの仕組み（ハーネス）」の2つでできており、モデルの重みは固定したまま、ハーネスのファイルをAIが自動で書き換えるのが本手法。実際の仕事（日程・名簿・予算ファイルからの資料作成）で43.1点→77.8点に改善した事例の内訳、直し方の2段階構造、そして「チャット利用者には無関係・対象は開発者と研究者」という正直な適用範囲までを18枚で整理します。

CARD 01

全体像サマリ: AIの頭はそのままで、点数が43.1→77.8に何を変えたのか? → 「周りの仕組み」だった

OVERVIEW

冒頭の寸劇がすべてを要約します。お客さんへの案内資料をAIに作らせたら持ち物の記載が資料と食い違っていた。AIが資料を確かめずに書いたのが原因。そこで「書いたら資料と見比べてね」という決まりを書いておくともう一度頼んだだけで直る。「同じAIでも周り次第で変わる」——この観察を研究にしたのがHarness²です。モデルの中身（頭）には一切手を出さず、指示書・決まり・記憶・道具といった周りの仕組み（ハーネス）をAIが自動で直す。本稿は概念→仕組み→実例→適用範囲の順に18枚で追います。

CARD 02

前提知識: AIエージェントは「2つ」でできている考える頭＝モデル／頭の周りの仕組み＝ハーネス

CONCEPT
  • 1つ目: 考える頭——GPTやClaude、Geminiのようなモデル部分
  • 2つ目: 頭の周りの仕組み——指示書・道具・記憶・仕事の進め方。これがハーネス
  • 例えは「料理人と台所」：腕が良くても台所次第で味が変わる
  • つまりAIの出来は モデル×ハーネス の掛け算で決まる
よもぎ
よもぎ:「頭が良い＝仕事ができる」ではない。環境の影響を数値で見せたのがこの研究です。
CARD 03

身近な例: CodexもClaude Codeも「モデル＋ハーネス」製品名の正体を分解すると見えてくる

EXAMPLES
  • Codex: 頭はGPT、周りの仕組みがCodex
  • Claude Code: 頭はClaude、周りがClaude Code
  • どちらもモデルとハーネスのセットとして設計されている
  • 「いい台所にすればいい」——しかし整えるのは通常人手で手間がかかる
よもぎ
よもぎ:CLAUDE.mdやAGENTS.mdを手書きで育てている人なら、その手間を実感済みのはず。
CARD 04

Harness²の8部品: ハーネスを部品分解するレシピ・包丁の使い方に相当するもの

8 PARTS
  • 話の土台になる指示書（CodexならAGENTS.md、Claude CodeならCLAUDE.mdに相当）
  • 守る決まり（ルール）
  • 記憶
  • 道具の使い方を教える説明とスクリプト
  • 仕事を手分けする分担（エージェント割り当て）
  • 途中に入るプラグイン
  • スキルや道具の使い方もみんなファイルとして存在
  • ファイルなら書き換えられる——ここが次のカードの鍵
よもぎ
よもぎ:「ハーネス＝設計図」ではなく「ハーネス＝書き換え可能なファイル群」と捉えるのがポイントです。
CARD 05

核心の設計: モデルの重みは固定、直すのはファイルだけAIの頭の中身の数字には手を出さない

KEY IDEA
  • 直す役のAIがハーネスのファイルを書き換える
  • モデルの中身（重み＝AIの頭の中の数字）は変えない——GitHubの説明にも明記
  • 「料理人はそのまま、台所を整える」のをAIが自動でやる
  • ファインチューニング不要なので誰でも・すぐ・安く試せる
よもぎ
よもぎ:重みを触らない＝壊しようがない。安全性と再現性の面で理にかなっています。
CARD 06

直し方は2段階: その場で直す＋次の仕事に生かす「今の課題」と「将来の糧」の2本立て

2 PHASES
  • 段階1: その場で直す——1つの仕事の中でハーネスを改善して再挑戦
  • 段階2: 次の仕事に生かす——仕事を順に渡すと、前の仕事の教訓を次に活用
  • コマンドで動かすと同じ課題をエージェントに何度も解かせる
  • 最後に「直した設定」と「得た教訓」を返して止まる設計
よもぎ
よもぎ:「直して終わり」ではなく、教訓を資産として持ち越すのが研究の眼目です。
CARD 07

動かし方: 常駐エージェントではない研究に課題を渡して試し比べる「実験」の仕組み

HOW TO RUN
  • 入れておけばいつものClaude Codeを直してくれる、ではない
  • 会話の裏で勝手にCLAUDE.mdやスキルを直すものでもない
  • 上駄（オーバーレイ）して見張っているものでもない
  • あくまで「研究に課題を渡して試し比べる」実験として回すもの——勝手に動かない
よもぎ
よもぎ:誤解されやすい点を動画が先回りして潰しているのが誠実です。
CARD 08

公開形態: GitHubでコード公開、Apache 2.0ただし「Google公式サポート製品ではない」

LICENSE
  • コードはGitHubで公開、使い方の決まりはApache 2.0ライセンス
  • README末尾に明記: 「Googleが公式にサポートする製品ではない」
  • 困ってもGoogleに聞けるわけではない——自分で面倒を見る前提
  • 研究成果物としての公開、という位置づけを理解して使う
よもぎ
よもぎ:「無料の魔法」ではなく「自己責任の研究ツール」。前提の確認が大事です。
CARD 09

誰の道具か: 対象はかなり限られる3つの「違う」で切り分ける

WHO IT'S FOR
ユーザー像対象?理由
ChatGPT等でチャットする人対象外チャット画面に入れて使うものではない
Codex / Claude Code でコードを書く人そのまま足す道具ではないいつもの環境に直接追加するプラグインではない（Harness²内の仕事を解く役としてCodexが使われることはある）
AIエージェントを作る・研究する人一番の対象開発者・研究者のための実験ツール

現時点の実行環境はOpenCodeとCodex。Claude Codeは今は使えない点も明言されています。

よもぎ
よもぎ:「すごい→入れてみよう」ではなく「自分は対象か?」を最初に判定する——本動画の態度が良いです。
CARD 10

一番の疑問: 正解がないのにどうやって直すのか答えは「仕組みの賞」で出す

OPEN-ENDED
  • 正解が1つに決まらない仕事では通常の採点ができない
  • Harness²の答え: 何を・誰向けに・どの仕組みで行うかを見て評価する
  • 出てくる案は2種類——どの仕事でも効く直し方とその仕事・分野だけの直し方
  • 「いつもの癖を直す案」＋「その仕事向けの案」の組み合わせ
よもぎ
よもぎ:模範解答がない世界での「良くなった」の判定方法が、この研究の工夫の核心です。
CARD 11

手順の詳細: 1課題の中での改善ループやる→案を出す→比べる→組み合わせる

LOOP
  • ① 最初に普通に1度やってみる
  • ② そのやり方を見て、直す案を2つ出す（汎用案＋特化案）
  • ③ それぞれの案で同じ仕事をやり直す——答え合わせはせず、やり方の違いを比較
  • ④ 良かったところを組み合わせる（味見していいところだけ合わせる）
  • このループをAIが自動で回す。人は準備と結果の確認を担う
よもぎ
よもぎ:人の仕事は「準備」と「確かめ」だけ——改善のループ自体はAIに任せる分担です。
CARD 12

実例: 43.1点 → 77.8点の劇的改善仕事は「日程・名簿・予算ファイルから資料を作る」こと

CASE 43.1→77.8
観点改善前（43.1点）改善後（77.8点）
数字の扱いファイル同士の数字を突き合わせていなかった元のファイルと照らし合わせてから書く
出来上がりの確認作ったファイルを開き直して確かめていなかった終わる前に作ったファイルを開き直して確認
スキル（なし）突き合わせ方＋食い違い時の正誤判定の基準を追加
スクリプト（なし）作ったファイルを開き直して調べる確認スクリプトを追加
よもぎ
よもぎ:改善の中身は「知識」ではなく「手順」の追加。地味なようでいて点数を倍近くした犯人です。
CARD 13

何が足りなかったのか: 知識ではなく手順頭の良さは十分、足りなかったのは所作

INSIGHT
  • 改善前のAIに欠けていたのは知識ではなかった
  • 欠けていたのは「確認する」「照らし合わせる」という手順
  • 冒頭寸劇の「資料を確かめずに書いた」と同じ失敗構造
  • 手順はハーネス（決まり・スキル）として後から足せる
よもぎ
よもぎ:人間の新入社員教育と同じ構図——育てるのは知識でなく習慣です。
CARD 14

注意: 1つの課題の例であり、汎用の点数ではない仕事が終わったら直した分は捨てる

CAVEAT
  • 43.1→77.8はあくまで1つの課題での例と強調
  • 1課題内の改善分は仕事が終わったら捨てる設計
  • 「毎回の決まりを人が考えるのは大変」という課題への自動化の方向性を示す研究成果
  • 万人のAgentがすぐ点数アップする道具、と読まないこと
よもぎ
よもぎ:誇張せず範囲を限定して伝える——信頼できる解説の証拠です。
CARD 15

得た教訓の使い道: 次の仕事に持ち越す順番に仕事を渡すと前の教訓を生かす

LESSONS
  • 仕事を順に渡すと、前の仕事で得た教訓を次に生かす
  • 直した設定と教訓が返り値として得られる
  • 教訓を自分のCLAUDE.md等に手動反映する運用も考えられる
  • 「ハーネス育成の自動化」の萌芽として注目度が高い
よもぎ
よもぎ:教訓の貯金が利くようになると、エージェントは「経験を積む」ようになります。
CARD 16

自分のワークフローへの示唆: 今日からできる「手順足し」研究を使わなくても活かせる考え方

TAKEAWAY
  • AIのミスは「知識不足」と決めつけない——手順不足の可能性を疑う
  • 指示書（CLAUDE.md等）に「書いたら元資料と見比べる」系の決まりを足すだけで冒頭の失敗は防げる
  • 「終わる前に自分の出力を開き直して確認」も即効性のある追加手順
  • 失敗のたびに「何の決まりが足りなかったか」をメモする習慣が自分のハーネスを育てる
よもぎ
よもぎ:Harness²を使わない人にも「周りを直す」発想は今日から使えます。
CARD 17

導入を考えている人への判定フロー3問で「触るべきか」が決まる

DECISION
  • Q1: 自分はエージェントの開発・研究に携わっているか? → Noなら様子見
  • Q2: 実行環境（OpenCode / Codex）を普段から扱えるか? → Noなら学習コストが先
  • Q3: 自己責任・自己面倒で運用する覚えはあるか? → Noなら公式サポートのある製品を
  • 3つともYesならGitHubの公開コードと論文を最初から読むのが最短
よもぎ
よもぎ:「触るかどうか」より「自分の課題に合っているか」で判断しましょう。
CARD 18

まとめ: 頭を変えずに、部屋を整える時代よもぎチェックリスト付き

SUMMARY
  • AIエージェント＝モデル（頭）×ハーネス（周り）。改善の余地は後者に大きい
  • Harness²は重み固定のままファイルを自動改善する研究実験ツール
  • 実例は43.1→77.8点——足したのは手順（決まり・スキル・確認）
  • 対象は開発者・研究者。チャット利用者は「手順足し」の考え方だけ持ち帰る
  • □ 自分の指示書に「見比べる・開き直す」の2手順を足してみよう
よもぎ
よもぎ:「AIを育てる」の新しい答えは、頭ではなく周りを整えることかもしれません。
