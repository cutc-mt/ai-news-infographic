全体像サマリ: 1行コマンドでClaudeを「部品」にするclaude -pとは何か、何ができて何に注意すべきか

OVERVIEW

claude -pはClaude Codeの非対話モード。コマンドラインにプロンプトを渡すと対話UIを起動せずに結果だけを返すため、シェルスクリプトや自作プログラムからClaudeを呼び出せます。にゃんた氏はこの性質を利用して、動画編集ワークフローの自動化・PDF読解質問アプリ・スライド資料のAI編集・Excel/CSVの分類要約という4つの実例を紹介。大きな利点はAPIの従量課金を気にせずサブスク（プロプラン等）の範囲内で利用できること。注意点は他者提供サービスへの組み込み禁止（利用規約）と通常のClaude Codeより利用枠消費が早い（約1.7倍問題）ことの2点です。

CARD 02

claude -pとは: 非対話モードの基本結果だけ返して終わる「1回こっきり」の呼び出し

BASIC

通常のClaude Codeはターミалで対話を始めますが、-p（print / pipe モード）を付けるとプロンプトを渡して回答を標準出力で受け取り即終了します。

# 基本形：対話UIなしで1回だけ質問 claude -p "このCSVの1列目の意味を推測して"
  • 対話セッションを開かないのでスクリプトに組み込みやすい
  • 出力はテキストとして受け取れる＝他のプログラムで加工可能
  • ファイル参照や権限オプションなど通常版の機能も併用可
よもぎ
よもぎ:「AIとおしゃべりする」から「AIに仕事を頼んで結果だけ受け取る」へ。UNIX哲学のパイプに馴染む設計なので、シェルに詳しい人はすぐ飲み込めるはずです。
CARD 03

仕組み: アプリの中でClaudeを「呼ぶ」自作プログラム→claude -p→回答を利用

ARCHITECTURE

自作アプリの流れはシンプルです。アプリ側でコマンドを組み立て→サブプロセスで claude -p を実行→標準出力の回答を受け取る。APIキーも従量課金も不要で、サブスク契約のClaude Codeをそのままエンジンにできます。

  • Pythonやシェルからsubprocess的に呼び出すだけの簡素な構成
  • ファイルパスを渡せばPDF・Excel・スライドを読ませることも
  • 結果はテキストで返るのでUI表示や後続処理が自由
  • 自分専用なら複雑な認証実装も不要
よもぎ
よもぎ:「AIアプリを作る＝API契約・課金管理・キー管理」という壁が、サブスク1本で乗り越えられる。個人開発のハードルが一気に下がる構図です。

料金の比較: claude -p と API「サブスクの範囲内」が最大の魅力

COST
観点API（従量課金）claude -p（サブスク）
課金トークン量に応じ都度課金プロプラン等の定額内で消費
試行錯誤リトライがそのまま費用に何回実行しても追加請求なし
管理APIキー・上限設定の管理が必要既契約のClaude Codeをそのまま利用
向き不向き不特定多数向けサービス向き自分・社内向けツール向き
よもぎ
よもぎ:「APIの従量課金を気にせずサブスクの範囲内で利用できる」というのが説明欄の売り文句。個人には金銭的な心理ハードルの低下が何より大きいです。

CARD 10

注意点①: 利用規約 — 他者提供サービスには組み込めない「自分用・社内用」のラインを守る

TOC ⚠
  • claude -pで作ったアプリを他の人に提供するサービスには組み込めない（利用規約）
  • OK: 自分用ツール、社内業務での利用
  • NG: 顧客向けアプリ・外部販売SaaSのエンジンとして利用
  • 線引きは「提供先が自分（組織内）か、外部か」
よもぎ
よもぎ:サブスク運用の裁量を広げる代わりに、商用の外提供は禁止という釣り合いの規約。個人開発の範囲で遊ぶ分には自由、という境界線を最初に確認しておきましょう。
CARD 11

注意点②: 利用枠の消費が早い — 「1.7倍問題」対話モードより枠を食うのに注意

QUOTA ⚠
  • 通常のClaude Code（対話利用）より利用枠の消費が早い
  • 動画では「約1.7倍」という消費係数の話として詳しく解説
  • がんがん回すスクリプトにするとあっという間に枠上限にも
  • バッチ処理の回数・頻度の設計が大切
よもぎ
よもぎ:「追加課金なし」でも「無限」ではない、というのがここでの教訓。1.7倍という数字を頭に置いて、実行回数にブレーキを設計しておくのが大人の使い方です。

Monthly API Creditsと外部アプリ利用条件条件を満たせばAPIクレジットでも運用可

CREDITS
  • サブスク利用とは別にMonthly API Creditsという枠の話を解説
  • 一定の条件（API利用実績など）を満たすと月次APIクレジットが付与されうる仕組み
  • その場合、外部アプリでAPIを利用できる条件が関係してくる
  • 自分の契約状況・付与条件は公式ドキュメントで最新を確認するのが鉄則
よもぎ
よもぎ:制度の詳細は提供側の改定で変わりやすい領域。動画の時点での説明として受け取り、実際に契約する前に一次情報を確認する癖をつけたいですね。
