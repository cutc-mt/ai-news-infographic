CLI-ANYTHING / AGENT×DESKTOP APP

GUIアプリをそっくりそのままCLIへ — コーディングエージェントに「本物のソフトウェア」を扱わせる CLI-Anything 完全解説

香港大学のデータインテリジェンス研究室HKUDS（LightRAGなどのエージェントプロジェクトで知られる）が公開したOSS「CLI-Anything」。GIMPやBlender、LibreOfficeなどボタンとメニューで操作する前提のソフトウェアに、AIエージェントが読めるコマンドラインインターフェースを自動生成します。中心思想は「本物のソフトウェアを呼び出す（authentic software integration）」——貧弱な代用品ではなく、LibreOfficeのheadlessモードで本物のPDFを、本物のBlenderでレンダリングを実行します。54,000星超・Apache 2.0の大型プロジェクトについて、既製CLIを入手する「CLI Hub」と、自分のソフト用にCLIを生成する7フェーズのパイプライン、テスト戦術と限界までを18カードに整理しました。

元動画: CLI-Anything: Turn ANY App into a CLI for Claude Code & Codex (GIMP, Blender, LibreOffice & More!)チャンネル: AI Code King公開: 2026年10月
よもぎ
「ほとんどのソフトウェアは人間向けに作られている」——この一見当たり前の指摘が、エージェント時代の接続問題の核心です。スクリーンショットを撮ってピクセルをクリックするGUIエージェントの遅さに別れを告げる話を見ていきましょう。
CARD 01

全体像サマリ: エージェントとデスクトップアプリの「接続問題」をCLIで解くCLI Hubで既製CLIを使う ＋ CLI Generatorで自前ソフトをCLI化

OVERVIEW

CLI-Anythingの提供価値は大きく2つ。1つ目はCLI Hub——Blender・LibreOffice・Inkscapeなど人気アプリのCLIが既に登録されたパッケージマネージャで、pip install cli-anything-hubひとつで使えます。2つ目がCLI Generator——ソフトウェアのソースコードをコーディングエージェントに読み込ませると、analyze→design→implement→test→document→publishの7フェーズで完全なCLIを自動構築します。生成されたCLIはClickライブラリ製で、REPLモード・JSON出力・undo/redoを備え、テストとskill.md（エージェント向けの取り扱い説明書）まで揃います。

STEP ACLI Hubから既製CLIを導入 — meta skillでエージェントが自律探索
→
STEP BHubに無いソフトはGeneratorでCLI化 — 7フェーズの自動パイプライン
→
STEP Crefineで網羅性を拡張 — test/validateで品質を担保
→
RESULTGUI操作不要 — 本物のソフトウェアをコマンドで駆動
よもぎ
よもぎ:「CLIを手で書く」という退屈な作業をエージェントに丸投げできるのが本質。使う側（Hub）だけでも無料で即活用できる設計が大きなポイントです。
CARD 02

問題意識: ソフトウェアは人間向け、エージェントはテキスト向けボタン・メニュー・ウィンドウの先にある機能の壁

PROBLEM

世の中のほとんどのソフトウェアは人間が操作することを前提に設計されています。機能はボタンやメニュー、ウィンドウの奥にあり、それらは人間の目と手を想定したインターフェースです。一方、AIエージェントが得意なのはテキスト。コマンドを渡してテキストを受け取ることに特化しています。この「GUI前提の機能」と「テキスト前提の利用者」のミスマッチが、エージェントにデスクトップアプリの力を引き出せない最大の原因です。

よもぎ
よもぎ:API時代も同じ話が繰り返されました。「人間向けUI」と「プログラム向けインターフェース」の二重構築コスト。今回はその溝をエージェント自身に埋めさせるのが斬新です。
CARD 03

従来手法3種の限界: なぜGUI自動化・API・書き直しだけでは不十分か遅い・無い・足りない、それぞれの壁

COMPARE
手法仕組み弱点
GUI自動化スクリーンショットを撮り、ピクセル座標をクリック動作が遅く、UIの変更ですぐ壊れる
API呼び出しアプリ純正のAPIを叩くAPIを持たないアプリが多い／あっても一部機能のみ
書き直しPythonなどでアプリの機能を模倣実装小さなコピーにしかならず大半の機能が欠落
よもぎ
よもぎ:どの道も「本物のアプリの全力」から遠い。ピクセル叩きは遅い・壊れやすい、模倣実装は機能不足——この2つがエージェント実用化の足かせでした。
CARD 04

なぜCLIなのか: テキストイン・テキストアウトの発見可能性helpページと --json フラグが自己探索を支える

WHY CLI
  • エージェントは端末の操作方法をすでに知っている——追加の教育が不要
  • CLIはテキストを入れ、テキストを出すだけの単純な往復で完結
  • 各コマンドにhelpページが付く → エージェントが自力で「何ができるか」を発見できる
  • 全コマンドに --json フラグがあり、出力がクリーンなJSONで返る——推測なしで正確に読み取れる
よもぎ
よもぎ:「エージェントが道具を自己発見できる」のが決定的。マニュアルを人間が読んで教えなくても、helpを辿って独学できるインターフェースなんです。
CARD 05

核心思想: Authentic Software Integration — 置き換えず、呼び出すLibreOfficeのheadlessモード、Blenderの実レンダラー

CORE IDEA

CLI-Anythingの生成するCLIは、対象ソフトの代用品ではありません。LibreOffice CLIでPDFを作れば、それはLibreOffice本体がheadlessモードで生成した本物のPDFです。Blender CLIでのレンダリングも、実Blenderエンジンが実行します。プロジェクトはこれを authentic software integration（本物のソフトウェア統合）と呼んでいます。つまり「アプリの簡易コピー」ではなく本物のアプリの全力がコマンド経由で使える——速度も品質も、そのソフトの本性能のまま出力されます。

よもぎ
よもぎ:「Pillowで画像処理を誤魔化さない」という思想が後述のharness.mdにも明文化されます。簡易実装への誘惑に打ち勝つ規律がプロジェクトの背骨です。
CARD 06

使い方は2通り: 「もらう」か「作る」かHubにあれば即導入、無ければGeneratorで生成

TWO PATHS
PATH 1: CLI Hub他の人が作ったCLIを使う — pipでhubを入れてlist/search/install。初心者はまずこちら。無料で即効性あり
⇄
PATH 2: CLI Generator自分のソフト／社内ツール用に新規CLIを生成 — ソースコードかGitHub URLを渡すだけ。Claude Code等のプラグインとして動作

PATH 1は「便利なCLIが既にあるなら使う」、PATH 2は「Hubに登録されていないソフトや自社内部ツールをエージェントに使わせたい」場合の逃げ道です。両方とも同じ cli-anything-<name> の命名規則に従うので、エージェント側からはどちらで入手したCLIも区別なく扱えます。

よもぎ
よもぎ:まずHubのmeta skillだけ入れておくのが動画の推奨ルート。コストゼロでエージェントの道具箱が一気に広がり、足りない分だけGeneratorに頼ればいい、という段階的な設計です。
CARD 07

CLI Hub入門: 5つのコマンドで使えるパッケージマネージャPython 3.10以上で動作

QUICKSTART
  • 導入: pip install cli-anything-hub（Python 3.10+）
  • cli-hub list — レジストリの全CLIを一覧表示
  • cli-hub search image — キーワードで絞り込み（例: 画像ツールのみ）
  • cli-hub install gimp → cli-hub info gimp → cli-hub launch gimp
  • 注意: CLIは本体アプリを呼び出すので、GIMP CLIを入れたらGIMP本体のインストールも必要
よもぎ
よもぎ:list／search／install／info／launchの5語形だけ覚えればOK。「CLIを入れたのに動かない」は本体が無いパターンがほとんどなので、この注意は重要です。
CARD 08

レジストリの品揃え: 動画・画像・オフィス・GISまで勢揃い登録済みCLIの代表的な顔ぶれ

LINEUP

Hubにはすでに多数のCLIが登録されています。3D・映像・画像系ではBlender・Inkscape・GIMP・Kdenlive・Shotcut・OBS Studio・Audacity。ドキュメント・ナレッジ系ではLibreOffice・draw.io・Obsidian・Zotero。開発・AI基盤系ではOllama・ComfyUI。CAD・GIS系ではFreeCAD・QGIS。さらにZoomなど通信ツールまで揃います。cli-hub searchで目的別に探せば、思いがけないソフトがCLI化されているのが見つかります。

よもぎ
よもぎ:この顔ぶれが「エージェントに任せたい作業の地図」そのもの。動画編集・CAD・GISのような重い・細かい作業こそ、CLI化の恩恵が大きい分野です。
CARD 09

Meta Skill: 「道具の探し方」自体をエージェントに教えるskills add でClaude Code / Codex等に導入

META SKILL

CLI Hubにはmeta skillと呼ばれる特別なスキルが用意されています。これは個別ツールの使い方ではなく、「Hubから適切なCLIを探してインストールする方法」そのものをエージェントに教えるスキルです。導入は npx skills add hkuds/cli-anything --skill cli-hub-meta-skill -g -y の1行。-g でグローバルインストール、-y で確認をスキップします。Claude Code・Codexをはじめ、OpenClaw・Nanobot・Antigravityなどskills対応の各種エージェントで利用できます。

よもぎ
よもぎ:「魚を与えるのではなく釣り方を教える」構造。一度入れておけば、エージェントがタスクに合わせて自分で道具を調達するようになります。
CARD 10

実演: アーキテクチャ図を「道具選びごと」丸投げ「Find appropriate CLI software in CLI Hub」

DEMO 01

meta skill導入後のデモでは、プロンプトは「Find appropriate CLI software in CLI hub and complete the task（Hubから適切なCLIを見つけてタスクを完了せよ）」＋課題文だけ。依頼された「簡単なアーキテクチャ図の作成」に対し、エージェントはどの道具を使うかすら指定されていないのに、Hubを検索してdraw.io CLIを発見し、インストール。そのCLIのskill.mdを読んで操作方法を学び、図形の追加・接続を経て最後にPNGを書き出します。人間はツール選定に一切関与していません。

よもぎ
よもぎ:「draw.ioを使え」と言っていないのに自分で見つけて導入し、説明書を読んで使いこなす。エージェントの自律性が一段上がる瞬間です。
CARD 11

Generatorの導入: プラグイン2コマンドでClaude Codeに搭載WindowsはGit for Windows か WSL が必須

SETUP
  • マーケットプレイス追加: /plugin marketplace add HKUDS/CLI-anything
  • プラグイン導入: /plugin install cli-anything — これだけで有効化
  • CLI生成は /cli-anything にパスかGitHub URLを渡す（例: BlenderのリポジトリURL）
  • Claude Code以外にもCursor・Codex・OpenCode・GitHub Copilot CLI等で動作
  • WindowsはBash経由でシェルコマンドを実行する都合上、Git for WindowsまたはWSLが必要
よもぎ
よもぎ:marketplace add → install の2段階で終わる手軽さ。動画の実演はClaude Codeですが、主要コーディングCLIの大半に対応しているのも強みです。
CARD 12

7フェーズの生成パイプライン: ソースコードからCLIが生まれるまでanalyze → design → implement → plan tests → write tests → document → publish

PIPELINE
PHASE 1 analyzeソースコードを読み、GUIが行う操作を発見して、各操作と実装コードを対応づけ
→
PHASE 2 designコマンドグループ・状態モデル・出力フォーマットを設計
→
PHASE 3 implementPythonのClickライブラリでCLI本体を実装。REPLモード・JSON出力・undo/redoを全CLIに標準装備
→
PHASE 4-5 teststest.mdにユニット＋E2Eテストの計画を書き、その計画からテストを実際に作成
→
PHASE 6 documentテスト実行結果をtest.mdへ反映し、他エージェントがCLIを発見するためのskill.mdも生成
→
PHASE 7 publishsetup.pyを作成してCLIをパスへインストール（harnessフォルダで pip install -e . ）
よもぎ
よもぎ:「コード解析→設計→実装→テスト→文書→公開」という教科書通りの工程をエージェントが一気通貫で回すのが面白い。特にskill.mdの自動生成は「次のエージェントへの引継ぎ書類」まで含む設計です。
CARD 13

生成されたCLIを使う: 共通命名規則とJSON出力cli-anything-<name> でどこからでも呼べる

USAGE

生成されたCLIはすべて cli-anything-<name> の命名規則に従います。--help を叩けばコマンドグループが一望でき、各コマンドの --json フラグでエージェントが読みやすいクリーンなJSONが出力されます。実演では画像編集CLIで1920×1080のプロジェクトを新規作成し、poster.jsonへの出力とレイヤー追加をJSONで確認。READMEのLibreOffice例では、Writer文書を新規作成→見出し「Q1 report」を追加→4行3列の表を挿入→export renderコマンドでPDFを書き出す——という流れがそのまま本物のPDFとして完成しました。

よもぎ
よもぎ:命名規則の統一が地味に効いています。エージェントは「cli-anything-で始まるコマンドは全部同じ作法」と一度学べば使い回せるわけです。
CARD 14

REPLモード: 引数なしで起動すると対話プロンプトにシーン名と未保存フラグの常時表示でエージェントが迷わない

REPL MODE

CLIをコマンドなしで実行するとREPL（対話）モードが起動します。Blenderの実演では cli-anything blender で対話promptに入り、scene new で「product shot」という名前のシーンを作成、cubeメッシュを追加、render execute をcyclesエンジンで実行——Blenderがバックグラウンドで画像をレンダリングしました。promptは現在のシーン名を常に表示し、未保存の変更があるときはアスタリスク（星）マークを示します。これによりエージェントは「いま何を開いているか・保存済みか」を常に把握できます。

よもぎ
よもぎ:状態の可視化は長時間作業の命綱。バッチ実行だけでなく対話的に少しずつ進める道が用意されているのが、実用性を一段底上げしています。
CARD 15

refine / test / validate: 初回生成を仕上げる3つのコマンドgapを埋め、テストを回し、規約に照合する

ITERATE
  • /cli-anything:refine — ソフトの能力とCLIのカバー範囲を比較し、不足分のコマンド・テスト・文書を追加
  • refineはフォーカス指定可能（例: バッチ処理とフィルタのコマンドを強化）。何度でも実行でき、過去の成果は消さない
  • testコマンド — テストを実行しtest.mdを更新
  • validateコマンド — CLIをプロジェクト規約（harness.md）と照合
よもぎ
よもぎ:初回で完璧なCLIはまず生まれない、という現実を前提にした設計。壊さず足していく反復モデルが、エージェント生成物の信頼を積み上げます。
CARD 16

harness.mdという「職人の掟」: exit code 0 を信用しないテストマジックバイト・ピクセル・音量・長さを実ファイルで検証

QUALITY

各フェーズでエージェントが従うplaybookがharness.mdです。ここには良い教訓が刻まれています。第一に、CLIは必ず本物のソフトウェアを使うこと——Pillow等での代用を許さない。第二に、exit code 0 は書き出し成功の証明にならないこと——だからテストは実出力ファイルを直接検証し、マジックバイト・ファイル構造・ピクセル・音量・再生時間を確認します。その結果、READMEでは約30のharnessで2,400件超のテストが通過。各harnessはフェイクデータのユニットテストと実ソフトを使うE2Eテストの二段構えで、本体ソフトが未インストールならテストはskipではなくfailになります。

よもぎ
よもぎ:「スキップされたテストは壊れたCLIを隠せる」——この一言に尽きます。甘い成功判定を自分に課さない規律が、生成物の信頼性の源泉です。
CARD 17

公式デモと4つの限界: 強力だがタダではないフロンティアモデル必須・ソースコード前提・refine反復・生成物の監査

LIMITS

READMEのデモは多彩です——FreeCADでCuriosity探査車をライブプレビュー付きで段階構築、BlenderでSFドローンを製作、Slay the Spire 2をCLI経由でプレイ、ArcGIS Proのライブセッションを駆動。オフィスツールにとどまらない力強さが示されます。一方で限界も明示されます: ①フロンティア級モデル必須（Claude Opus/SonnetやGPT-5.4クラス。小さなローカルモデルでは不完全・不正確なCLIになりがちで、大きなコードベースではトークン消費も大きい）②ソースコードがあるほど良い（コンパイル済みバイナリだけでは品質・網羅性が大きく低下）③1回の生成では足りない（refineを数回回す前提で）④エージェント製CLIは所詮エージェント製（重要なファイルへのアクセスを与える前に、テストとコマンドを人間が確認を）。

よもぎ
よもぎ:ゲームをCLIで遊ぶデモは衝撃ですが、本題は限界側。「自動生成＝そのまま信頼」ではないという提醒まで含まれる誠実なプロジェクトです。
CARD 18

まとめ: スクリーンショット高速化の次は「インターフェースの交換」へGUIエージェントは遅く高コスト、CLI+JSONは速く安い

SUMMARY

GUI自動化（スクリーンショット＋クリック）は本質的に遅くコストがかさみます。CLI＋JSON出力は高速・低コスト・エージェントにとって読みやすい。CLI-AnythingはそのCLI作成という退屈な仕事をエージェントに代行させ、しかも呼び出し先は本物のソフトウェアに固定します。動画の推奨アクションは明快です——まずCLI Hubのmeta skillを入れる（無料で巨大な道具箱をエージェントに与えられる）。次に、Hubに無いアプリや自社ツールがあればGeneratorでCLI化を試す。GUIエージェントにピクセルを叩かせる時代から、ソフトウェア自体がエージェント向けの顔を持つ時代への移行を先取りするプロジェクトです。

DO NOWpip install cli-anything-hub ＋ meta skillをエージェントに導入
→
DO NEXT足りないソフトをGeneratorでCLI化 — refineで仕上げる
→
MINDSET生成物のテストとコマンドは人間が確認してから本番へ
よもぎ
よもぎ:GUIエージェントにピクセルを叩かせるより、ずっと速く安い。まず無料のHubから——大きな一歩がタダで踏み出せるのが、このプロジェクトの優しい設計です。
