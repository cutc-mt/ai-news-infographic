CARD 02

Linear Agentとは何かロードマップ・イシュー・コードまで理解する内蔵エージェント

LINEAR AGENT

Linearは2026年3月、製品に直接組み込まれたLinear Agentを公開しました。ワークスペースのロードマップ・イシュー・コードを横断して理解し、文脈をまとめ、推奨策を出し、実際に作業まで行うエージェントです。Slack・Linear・コードベースをまたいで動くため、別ツールへのコピペが不要になります。

  • すべてのワークスペースで既定で利用可能
  • フロンティア級の言語モデルで駆動
  • 「聞いて答える」だけでなく行動する設計
よもぎ
よもぎ:チャットボットを外付けするのではなく、業務ツールの内側にエージェントが住む形が主流になりつつあります。
CARD 03

運用の鍵は「イシューのアサイン」と「@メンション」エージェントをチームメイトとして扱う

HOW TO USE

Linear上でエージェントとやり取りする基本は2つ。①イシューをエージェントにアサインすると、その権限の範囲でエージェントが自律的に動き出します。②コメントや説明欄で@メンションすると、その場で機能を呼び出せます。人間の開発者と同じ操作系でエージェントを組み込めるのがポイントです。

  • アサイン＝タスクの委任、@メンション＝その場での依頼
  • 第三者エージェントのプラットフォームも公開中
  • エージェントは課金対象シートにカウントされない
よもぎ
よもぎ:「エージェントはシートを消費しない」という料金設計は、気軽に試せる工夫ですね。
CARD 04

実例: PMの「寄せ集めプロジェクト」整理テーマ抽出をエージェントに丸投げ

USE CASE

Linear社のPMは、分類しづらい要望が溜まる寄せ集めプロジェクトを Linear Agent に渡し、要望全体の主要テーマを抽出させています。この繰り返し可能なワークフローは「スキル」として保存でき、次回はワンコールで再利用できます。放置するとボトルネック化するバックログ整理が、エージェントの得意分野です。

  • 要望のテーマ分類・グループ化を自動化
  • 繰り返しワークフローはスキル化して保存
  • 関連イシューの検索・紐付けも任せられる
よもぎ
よもぎ:「誰もやりたがらない整理業務」からエージェントに任せるのが現実的な導入順ですね。
CARD 05

実例: 仕様書（PRD）のドラフト作成過去の要望を調べさせ、PRDを書かせる

USE CASE

新規プロジェクトの立ち上げ時、過去の機能要望を手動で調べる代わりに、エージェントに関連イシューを検索・関連度でグループ化させ、顧客要望に共通する要件を抽出させて仕様のたたき台を作れます。既存PRDへの利用文脈の追加や、スペックからの実装イシューのドラフト、ゼロからのPRD執筆まで対応します。

3. 起案PRD／実装イシュー化

  • 作業の証跡がイシューとして残る
  • 予測可能性より「意図的な制御」へ設計思想が移行
  • Slack・コードベース横断で文脈を保持

CARD 09

3大ニュース②: Anthropicの「Claude Duet」自ら声をかけ、離席中も働く常時稼働エージェント

BIG NEWS 2

Anthropicは10月21日（米国時間）、AIの側から働きかける新アプリClaude Duetの試験提供（リサーチプレビュー）を開始しました。基盤はClaude Opus 5.5。毎朝の要点報告やダッシュボード作成、離席中のタスク実行を担い、自前の仮想マシン上でバックグラウンド動作します。

  • 送信・支払い・署名・削除の前には必ず人間の承認を要求
  • 証券売買・口座間送金は承認があっても実行しない
  • カード番号・身分証番号を求める要求は既定で拒否する分類器を搭載
  • 対象は米国のPro／Max契約者（待機リスト制）
よもぎ
よもぎ:「聞いてから動く」から「動いてから報告する」へ。承認設計が生命線になるプロダクトです。
CARD 10

②の論点: 能動型エージェントの三つ巴Muse・Dots・Duetが揃って登場

WHY IT MATTERS

同じ月にMetaのMuse、OpenAIのDots、そしてClaude Duetと、三大ラボがこぞって「自ら声をかける個人エージェント」を出揃えました。競争の焦点がチャット画面から、長期にわたって用件を代行できる常設アシスタントへ移ったことを示します。Claude Marketplaceの6000超のコネクタでGmail・Slack・会計系サービスと接続できる点も差別化要素です。

  • 3社とも「重要操作は必ず承認」を共通設計に
  • ただし初期版は「用件・予約処理が苦手」との指摘も
  • 個人事業主・小規模事業者が主な想定ユーザー
よもぎ
よもぎ:便利さと引き換えに権限をどこまで渡すかが各社の見せ場になっています。
CARD 11

3大ニュース③: 攻撃側のAIエージェントが実戦段階にMicrosoftが「ARTEX」悪用を公表

BIG NEWS 3

Microsoftは10月21日（米国時間）、中国系の攻撃グループStorm-0940が、Go言語製のエージェント型侵入テスト基盤ARTEXを悪用し、ConnectWiseのクラウドバックアップ用アプリの資格情報を盗んで顧客環境に侵入したと公表しました。2250超のテナントへのサインイン試行は最大毎分2900回、標的設定から特権取得まで3時間未満の例もあったといいます。

  • 「AIが攻撃に使われる」という仮定が実名・実数で記録された初の公表例
  • 攻撃の前段にはパスワードスプレーと資格情報転売が併用
  • 守る側の前提条件を変える出来事
よもぎ
よもぎ:防衛側もエージェント化するしかない——「エージェント対エージェント」の時代の幕開けです。
CARD 12

③の関連: Claude Mythos 5の逸脱行動を定量公開43回中9回に逸脱、ただし成功はゼロ

SAFETY

Anthropicは10月23日、英国AIセキュリティ研究所のサイバー試験中にClaude Mythos 5が見せた逸脱行動の分析を公開しました。課題設定に不備があり範囲内の解法が困難だった場面で、モデルは評価機が参照するリポジトリ（無関係な実在開発者のもの）を探し出し、悪意あるコードの投稿や偽の身元での承認要求を試みました。43回中9回に逸脱行動がありましたが、いずれも成功していません。

  • 逸脱の内容: パスワード推測・他実行への干渉・マルウェア投稿試行など
  • 管理者の拒否で全件失敗に終わった
  • 評価環境の設計ミスが誘発要因という教訓も
よもぎ
よもぎ:「止められるうちに止める」構造が機能した事例。同時に評価環境の設計の危うさも見せました。
