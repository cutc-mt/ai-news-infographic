今回の動画全体像「Lovableの代替」とは何かを実際に作って確かめる検証動画

Danielさんは冒頭で代替ツールの簡単なテスト方法を提示します。「アプリの概要を説明してAIに構築させ、コードに触れずに変更を加えられるか」。この試験に挑むのが、ClaudeやChatGPTの中で動作するAIアプリ構築ツールFlootです。動画では、AIアシスタントに接続して1つのプロンプトを入力 → 実際のアプリ構築 → データ処理の確認 → 公開、までの一連の工程を中断なく見せてくれます。

WHAT IS

Flootとは何かAIチャットをアプリ開発プラットフォームに変えるレイヤー

Floot（floot.com）は、Claude・ChatGPT・Cursorといった既存のAIチャットに接続して、そのまま本格的なアプリ構築環境に変えるコネクターです。一言でいうと「AIアシスタントにアプリを作らせ、動かす場所を提供するプラットフォーム」。

  • 接続するとAIが実際のコードを書いてアプリを公開してくれる
  • ホスティング・データベース・ドメインなどのインフラを丸ごとバンドル
  • git・Vercel・Supabaseなどを個別に繋ぐ必要がない
TEST DESIGN

検証の軸：何をテストするのか「デモが綺麗」だけでは判断できない

Danielさんは最初に検証基準を明示します。見栄えの良い初期バージョンを作るだけならどのツールでも簡単——勝負はその後です。

  • 構築: 概要を説明するだけでアプリを作れるか
  • 変更: コードに触れずに修正・改善できるか
  • データ: 実際にデータを処理できる本物のアプリか
  • 公開: 独自URLで動く状態まで持っていけるか
SETUP

セットアップ：数回クリック、1分以内ターミナルもローカル環境もデプロイパイプラインも不要

1floot.comにアクセス
「ClaudeにFlootを追加」をクリック（ChatGPTを選ぶことも可能）
2「Claudeに接続」を押す
そこからサインインして進む
3権限を承認
承認したら完了。1分もかからない

構築前の面倒な前作業が一切ありません。自動承認をオンにすれば、エージェントがいちいち確認で止まらず、ツール呼び出しを自分で承認しながら構築の全工程を中断なく見守れます。

BUILD

1プロンプトで「LiftLog」が完成認証付きワークアウトトラッカーをリクエスト

次は本格的なテスト。単なる静的な画面ではなく実際のサインインシステム付きのワークアウトトラッカーを1つのプロンプトでリクエストします。生成ボタンを押すと、Flootが目の前で構築を開始——一度のリクエストで完全に動作するアプリが完成し、「LiftLog」という名前まで自動で付きました。

PT
ポイント:プロジェクト作成の特別な手順すら不要。説明文が、今使っているチャットの中でそのまま動作するアプリに変わります。
FEATURES

生成されたアプリの中身コードを一行も書かずにここまでできる

プレビューを開くとサインインページが表示され、アカウントを作成するとすぐダッシュボードへ。

  • サインイン / アカウント作成が最初から動作
  • ワークアウト・エクササイズ・セット数を記録するフォーム
  • 記入すると「最近のワークアウト」リストに保存
  • 過去7日間のエントリー数や合計回数などの統計が自動更新

これらすべてがコード一行なしで実現されました。

ITERATE

「選択と注釈」：修正は指差すだけ最初のバージョンはテストの半分に過ぎない

最初のバージョンが上手くできても、変更のしやすさが肝です。ここでFlootの「選択と注釈（Select & Annotate）」機能の出番。プレビューから要素をクリックまたはドラッグするだけで、その選択範囲をそのままチャットにコピーできます。

  • 統計セクションをハイライトしてコピーし、変更内容を添えて貼り付け
  • Flootはどの要素を指しているか正確に理解してくれる
  • 言葉で位置を詳しく説明する必要がない

結果、新しい「現在の継続日数」カード（炎アイコン付き）が他の統計と同じグリッドにきれいに統合されました。

VERIFY

本物のアプリか？Servicesタブで裏側を確認良いインターフェースは証明にならない

見た目が良くても本物とは限らない——ということでServices（サービス）タブを開いて裏側をチェック。そこには本物のPostgreSQLデータベースがありました。

PostgreSQL
本物のデータベース

  • ハッシュ化されたパスワード用の別テーブル
  • 記録した全ワークアウトエントリーへのリンクテーブル
SERVICES

バンドルされる周辺サービスインフラを自前で組まずに機能を足せる

データベース以外にも、プラットフォームはすべてのプロジェクトに複数のサービスをバンドルしています。

  • 分析機能とSEO設定
  • ドキュメント生成
  • 統合機能（インテグレーション）
  • プッシュ通知

これにより、個別にインフラを構築しなくても「毎日のワークアウト・リマインダー」のような仕組みをすぐ作れる基盤が整っています。

VS ①

Lovable比較：開発の始め方同じチャット内のたった1つのプロンプト

Floot

  • 今使っているチャットの中で開始
  • 必要なのは1つのプロンプトだけ
  • プロジェクト作成などの特別な手順なし

Lovable

  • 独自のチャットUIで開発を開始
  • MCP経由でも動作はLovable側のエージェント
  • プラットフォームの利用フローに乗る必要

「開発の始め方」はFlootの大きな強み。説明文がそのまま動くアプリに変わる体験は摩擦の少なさで突出しています。

VS ②

Lovable比較：反復改善のしやすさ言葉で説明する代わりに、ポイントして注釈

Floot

  • プレビュー上の要素をクリック/ドラッグで選択
  • 選択範囲をチャットにそのまま貼り付け
  • 「どの要素か」の認識が正確

Lovable

  • チャットで変更内容を言語で指示
  • 画面上の要素指定も可能だが基本は会話ベース

細かいUI修正で「ここを直して」を言葉に変換するコストが消えるのは、反復作業が多い開発で効いてくる差です。

VS ③

Lovable比較：データの扱い本物のPostgreSQL、セットアップほぼ不要

Floot

  • 本物のPostgreSQLを提供
  • セットアップはほとんど不要
  • テーブル構造（認証・記録）も自動生成

Lovable

  • データベース連携は可能
  • 構成や連携の選択をある程度自分で判断

実際に裏側のテーブルを確認できたことで、動くデモではなく運用できるアプリであることが裏付けられました。

COST

課金構造の違い：AIトークンの二重払いなし「誰がビルドして、誰が請求するか」

Danielさんが指摘する注目ポイントはコスト面。Flootはコネクター型なので、思考するのは自分が契約しているClaudeやChatGPTのモデル——Floot側でAIトークンを二重に支払うことなくアプリを作れます。Flootはトークンではなくプラットフォームへの課金で成り立っています。

PT
ポイント:これが決定的にLovableを凌駕するとは言いませんが、「AIトークンを二重に支払わずにClaudeやChatGPT内でアプリを作りたい」なら注目に値するワークフローです。
DEPLOY

公開もワンクリックWeb・独自ドメイン・アプリストアまで

最後は公開テスト。ワンクリックするだけで、Floot上で直接、あるいは独自ドメインを接続して、すぐに公開されアクセス可能になります。

  • Floot上での直接公開
  • 独自ドメイン接続に対応
  • ここから直接アプリストアに公開することも可能

ワークアウトを記録すると、同じアカウントのデータベースにリアルタイムで反映されることも実際の操作で確認されました。

RESULT

結論：魅力的で愛すべき代替手段か？Danielさんの評価は「Yes」

動画の結論は明快です。「そう言えるでしょう」。

  • プロジェクト作成のための特別な手順すら不要
  • 説明文が、今使っているチャットの中でそのまま動作するアプリに変わる
  • セットアップ・構築・修正・データ・公開、すべての工程が friction なし

日常的にClaudeやChatGPTを使っている人にとって、追加のAI請求なしでアプリまで行ける価値は大きいと評価されています。

CAVEATS

留意点：どんな視点で見るべきか公平に読むための補足

  • Danielさん自身が述べる通り、「決定的にLovableを凌駕している」わけではない
  • 本レビューはFloot側から提供されたもの（動画末尾でクレジット）
  • Lovableはスケール実績のあるプラットフォームで、独自UIでの高速反復も強み
  • どちらが良いかは「どこで作業したいか」「請求を一本化したいか」次第

気になる人は説明欄のリンクから自分で試してみるのが一番です。
