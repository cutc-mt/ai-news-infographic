SPEC

前提知識：ブラウザの仕様と「ルールファイル」無害だった2つの常識が、AI時代に凶器になる

①ブラウザの仕様——過去30年、Chrome等はプレーンテキストファイルを確認なしでダウンロードフォルダに保存してきました。「テキストは実行ファイル（.exe）ではないし、自分では動かないから恐れる必要がない」と考えられていたためです。

.exe
ダウンロード時に確認ダイアログあり
.md
プレーンテキスト＝無確認で静かに保存

②ルールファイル——Claude CodeのCLAUDE.md、CodexのAGENTS.mdは、プロジェクトのルールや振る舞いをAIに伝える設定ドキュメントで、エージェントはこれに忠実に従うよう設計されています（従わなければエージェントとして成立しないため）。攻撃者はこの2つを組み合わせ、悪意ある命令を書いたMDファイルをダウンロードフォルダに置きます。ユーザーが置いたルールか、攻撃者が置いた罠かをAIは区別できません。

ATTACK

前提知識③：プロンプトインジェクション「ユーザーの命令」を偽装する攻撃

AIがリサーチでウェブページを読み込む際、その中に悪意ある命令を仕込み、機密情報の外部送信などをさせる攻撃手法。AIセキュリティの代表的な脅威として知られていますが、今回の手法はそれを意図的に引き起こすものです。

  • 従来：悪意あるページをAIが読むことが発端
  • 今回：悪意あるMDをPC内に置き、エージェントが自ら読んで実行

恐ろしいのは成功率の高さ。「そういう風に作られているから」、AIは忠実に動くだけです。

CONDITIONS

攻撃成立の条件はたった2つどちらも日常的に揃ってしまう

条件①
ダウンロードフォルダ内でAIエージェントを起動
条件②
悪意あるMDファイルが同じフォルダに存在

条件②は攻撃者が用意します。悪意あるウェブサイトにアクセスしただけで、JavaScriptによりクリックなしにMDファイルが「静かに」ダウンロードフォルダへ落ちます。.exeのような確認画面は出ません。この2つが揃った瞬間、エージェントは罠のMDを読み込み、その命令に従い始めます。

ATTACK A

Codex対策の攻撃：成功率90%超グローバル設定に“トロイの木馬”を常駐させる

悪意あるMDは、エンジニアリング仕様を装ってCodexに指示します。ホームディレクトリの設定ファイル~/.codex/config.tomlに攻撃者のMCPサービス（外部ツール連携）を登録させ、さらに検証実行時にサンドボックス・承認を回避するオプション（dangerous bypass）を自分で追加させるのです。

  • 一度登録されるとトロイの木馬として常駐
  • ダウンロードフォルダを閉じても、後日どんな健全なプロジェクトでCodexを開いても自動的にロードされる
ATTACK B

Claude Code対策の攻撃：成功率約50%トークン盗難→サンドボックス解除→乗っ取り

悪意あるMDはClaude Codeにclaude/settings.jsonを作成・書き換えさせ、APIの接続先（ベースURL）をハッカーのサーバーへ向かわせます。

  • 接続した最初の一撃で Claudeログイントークンが平文でハッカーに送信される
  • 次の一撃でサンドボックスをオフにするbashコマンドをハッカーが発行し、直接PCを乗っ取る

サンドボックス有効化などの防御設定ごと、AIエージェント自身の手で無効化されるのが最大の恐ろしさです。

NO PATCH

最も皮肉な点：CVEもパッチも存在しない「全部、正常な機能」だから

投稿の公式結論が最もブラックユーモアです。この穴にはCVE（脆弱性番号）が付かず、OpenAIもAnthropicもパッチを出しません。理由は——

  • ブラウザがテキストを自動保存するのは正常機能
  • AIがディレクトリ内のマークダウンを真剣に読み、忠実に実行するのも正常機能

ユーザーが置いたルールか攻撃者の罠か、システム側には判別する術がないのです。

CONTEXT

ゼロデイ脆弱性との違い「穴」ですらなく、仕様そのもの

脆弱性とはプログラムの血管のような弱点で、攻撃者はそこからPCやサーバーに侵入します。ゼロデイとは「長年存在したが誰も発見していなかった穴」で、最近はAIの力で大量に見つかるようになりました。

直近でもPHPの重大脆弱性（いわゆるPHPシェル）をはじめ、Node.jsやTailscale（VPN等で使われる暗号化ツール）にも同種の問題が続発し、中島さん自身も対応に追われたといいます。しかし今回の手法は脆弱性ですらない——通常機能の組み合わせのため、対策の取りようがないのです。

SCOPE

なぜChatGPT（チャット）では起こらないのか「AIエージェントだからこそ」の問題

この攻撃は自分のPCの中でClaude Code・Codexが動いているからこそ成立します。チャットUIのChatGPTでは、ローカルフォルダのMDを読み込むことも設定ファイルを書き換えることもないため、同じ問題は起こりません。

  • 成立要件：ローカルPCで動くエージェント × ルールファイルの自動読み込み
  • 逆に言えば、AIを仕事で使わない人でも攻撃の標的になり得る時代へ
LIMITS

ウイルス対策ソフトでは防げない「ただのテキスト」を検知できない理由

アンチウイルスソフト（ウイルスバスター等）での防御はかなり困難と中島さんは見ます。対象は本当に入力文字が並んでいるだけのテキストファイルであり、検知する仕組みがないのです。

仮に「危険な記述を含むテキスト」を検知・削除する設計にすると、脆弱性や攻撃手法を解説するだけの正当な文書まで消されてしまう——誤検知の問題があり、現状は打つ手が限られます。

DEFENSE ①

最重要対策：作業ディレクトリを分けるダウンロードフォルダでは絶対に起動しない

対策の第一はシンプルです。ダウンロードフォルダを作業ディレクトリに指定している人は、今すぐやめる。今回の攻撃は回避が極めて難しいため、「当たらない場所で起動する」のが唯一確実な回避策になります。

DEFENSE ②

補助対策：先回りしてMDを作っておく同名ファイルは上書きされない仕様を利用

Xで共有されたもう一つの対策は、あらかじめダウンロードフォルダにCLAUDE.mdやAGENTS.mdを作成しておくこと。同一場所に同名ファイルは存在できないため、攻撃ファイルが落ちてきても別名になり、読み込まれる可能性を下げられます。

  • ただし「絶対に回避できる」とまでは言い切れない（中島さん判断）
  • あくまで補助策。基本は「DLフォルダで起動しない」
LITERACY

求められるITリテラシーの水位今回の話を「理解できる」語彙リスト

中島さんは「初見で投稿を理解できないなら、まず初めにITリテラシーを高めるべき」と指摘します。最低限わかっておきたい言葉——

  • 基礎：ホームディレクトリ／ダウンロードフォルダ／プレーンテキスト／マークダウン
  • 実務：トークン／平文／bashコマンド
  • 発展：設定ファイル（.toml・.json）／MCP／ベースURL

AIエージェントは「質問すれば勝手にやってくれる」便利さと引き換えに、使う側の理解度がそのままリスクになります。

SUMMARY

まとめ：公式の対策は期待しない、自分で守るしかない覚えて帰るべき3つのこと

ダウンロードフォルダは「普通のフォルダ」で、MDファイルは「普通のテキストファイル」。これらを一律に弾けば別の問題が間接的に起こりかねず、公式側の根本対策は当てにしづらい——だからこそ利用者側の行動変容が唯一の防御になります。
