「個人情報をAIに入れないほうがいい」の本当の理由 —— 送った瞬間に情報流出は始まっている

「ChatGPTに個人情報や機密情報を入力するな」とよく言われるけれど、なぜ危ないのかを正しく説明できる人は少ない。20年のプログラミング経験とセキュリティ実務を持つ中島さんが、「たぶん大丈夫」という個人の勘がなぜ通用しないのか、送信の仕組みから学習・ログ・アカウント乗っ取りまで、具体的な実事故とともに読み解きます。本動画（21分25秒）の内容を18枚のカードに整理しました。

CONCLUSION

結論：AIに入れるリスクはある個人の勘（「たぶん大丈夫」）は全く当てにならない

冒頭で提示される結論はシンプル。個人・機密情報をAIに入力することは、非常に高いリスクを伴う。特に会社員は、明確な利用ルールや研修がないまま自己判断でAIを使っており、それが情報漏洩につながりうるといいます。

  • 今回は「なぜ危ないか」の理由に絞った解説（対策ノウハウは次回以降）
  • 対象はChatGPT / Claude / Gemini / Claude Code / Codex などのクラウドAI
  • ローカルLLMはデータが外部に出ないため別の話
BASICS

そもそも「AIを使う」とは？プロンプトはあなたのPCから外部サーバーへ送られている

ChatGPTに文字を打ってボタンを押す——その裏では、入力データがOpenAIのサーバーへインターネット経由で送信され、そこで動く言語モデル（GPT-4oなど）が処理して、結果が返ってくるだけです。いわゆるフロントエンド／バックエンドの構造です。

1プロンプト入力自分のPC（フロントエンド）で入力
2外部サーバーへ送信OpenAI / Anthropic / Google のサーバーにデータが渡る
3結果が返却モデルが処理した応答が手元に戻る

「自分のPCで完結しているように見える」のが最大の落とし穴。システム開発に馴染みのない人こそ、この実態を知る必要があります。

LEAK

公開されなくても情報流出になる「表面化しなかった」は「漏れなかった」ではない

「送ったからって、ネットに公開されるわけじゃないでしょ？」——この反論に対する回答が核心です。問題は表面化するかどうかではなく、送ってはいけないデータを送ったという事実そのもの。それだけで情報流出（情報漏えい）に当たります。

  • 情報漏洩というと「ハッカーが盗んでダークウェブで売る」イメージがあるが、それだけが漏洩ではない
  • 送信先はOpenAI・Anthropic・Googleなど他社の管理するサーバー
  • 一度送ったデータの行方は、自分ではコントロールできない
CASE 1

実例①：Samsung（2023年頃）社内機密を入力してAI利用が全面禁止に

2023年頃、Samsungの社員が内部の人間しか知らないはずの情報をAIに入力してしまった事故が実際に起きました。この件でSamsungは長期間にわたってAIの利用を全面的に禁止。最近になって制限が緩和され使えるようになったものの、一度の入力が会社全体のAI活用を止めたのです。

MEMO
読み解き:「外部に漏れて騒ぎになった」のではなく、機密データを送ったことが発覚しただけでも事故になる、という良い例です。
CASE 2

実例②：RIZAPより最近に起きた同種の謝罪事例

Samsungと似た状況が、より最近にRIZAPでも報じられました。入力すべきでない機密データがAIに送られていたことが発覚し、会社が謝罪に追い込まれたという事例です。

  • データがインターネット上に公開されたケースではない
  • 「送ってはいけないものを送った」こと自体が事故として扱われた
  • 大企業でも起きる＝個人ならなおさら油断できない
TRAINING

学習に使われるから危ない「モデル改善に貢献」スイッチの正体

AIが人間らしく対話できるのは、膨大なテキストデータで「次にどの単語が来やすいか」というパターンを学習（機械学習）しているからです。学習はAIにとって命そのもの。設定にある「モデル改善に貢献する／しない」のオン・オフが、送ったデータが学習に使われるかどうかを左右します。

ON
送信データが学習に使われる可能性
OFF
学習には使われない（≠完全に安全）

学習に使われた場合、個人情報・機密情報が他者の出力に現れる可能性がゼロではなくなります。あくまで「可能性」ですが、その可能性自体がリスクです。

MYTH

「学習に使われなければ大丈夫」ではないAPI利用・ログの残り方の話

知識のある人ほど「学習オフにしてるからOK」「APIは学習に使われないからOK」と考えがち。しかし学習に使われない＝完全に安全、ではありません。

  • ChatGPT等の対話ではログが生成され、相手のサーバーに保存される
  • 削除や保持期間の仕組みはあるが、「記録が残る」事実は変わらない
  • API利用ならチャット履歴のような形では残らない（会社の規定次第で利用可）

残ったログの行く末を、利用者は完全には制御できない——これが次のカードの伏線になります。

CASE 3

実例③：OpenAIのチャット履歴漏れ（2023年）巨大テックでも事故は起きる

「OpenAIやAnthropicは時価数十兆円規模の巨大企業だから事故らない」——その思い込みを覆す実例です。2023年、OpenAIで一部ユーザーのチャット履歴のタイトル等が他人に見えてしまう事故が実際に発生しました。

  • 一部とはいえ、他人の会話の断片が流出
  • 運営側の不具合で起きたもので、利用者に落ち度はない
  • 巨大企業＝安全、は成立しないという教訓
CASE 4

実例④：Twitterの非公開リスト流出「100%安全」なんて存在しない

AI関連ではありませんが、数年前、Twitterの「リスト」機能で非公開設定のリストが誤って公開されてしまったことがありました。「苦手な人リスト」を作っていたユーザーが思わぬ騒動に巻き込まれたのです。

  • 利用者は非公開に設定しており、何も悪くない
  • バグか設定ミスかは不明のまま暴露
  • 教訓：見えるはずのないものが見える事故は、どのサービスでも起こりうる

OpenAI・Anthropic・Googleに送ったデータにも、常に露出の可能性が残ると著者は警告します。

THREAT

「万が一」より怖いアカウント乗っ取り確率が低い事故より、今頻発している脅威

「そんな滅多なこと起きない」という声に対して、著者は最近多発しているアカウント乗っ取りこそ直視すべきだと指摘します。実際の情報漏洩の相当部分は、ハッキングというよりアカウント乗っ取りが原因だからです。

1Googleアカウントが乗っ取られる今まさに頻発している
2連携サービスが全て連鎖「Googleでログイン」している全サービスが危険に
3ChatGPTの履歴も丸見え乗っ取った本人としてログインされるのと同じ

Gmailの閲覧・なりすまし送信・Googleドライブへのアクセスに加え、Googleログインで登録したSNSもAIツールも全部乗っ取られる——その連鎖の恐ろしさが強調されます。「使うな」ではなく、便利だからこそ対策が必須です。

HISTORY

ChatGPTの履歴も全部見られる漏れるのは名前や住所だけとは限らない

GoogleアカウントでChatGPTにログインしている人が乗っ取られたら？ 過去のチャット履歴が他人に全て閲覧されます。仕事の機密情報を貼り付けた会話かもしれず、場合によっては家族にも親友にも見せられない私的な会話かもしれない。

  • 内容は人それぞれ——名前や住所の漏洩より深刻な場合すらある
  • 「普通のデータ漏洩よりリスクが高い」とも言える
  • 履歴サイドバーに残っているものが全部対象
DEFENSE

パスキーを設定しようID＋パスワードのみのログインは今すぐやめる

アカウント乗っ取りへの対策として著者が勧めるのがパスキーです。近年普及が急拡大しており、多くのサービスが対応しています。

体感100倍
パスキー導入での安全度（著者比喩）
フィッシング耐性
偽サイトにパスワードを入力する構造自体がない
  • 使い勝手は保存済みパスワードとほぼ同じ（登録すれば後は使うだけ）
  • 「パスキーが何か分からないからパスワードでいい」は危険側の選択
  • セキュリティ意識の高まりで対応サービスは急増中
Q&A

「Googleドライブならいいの？」結論：同じ外部送信なので本質は変わらない

「AIはダメでGoogleドライブに機密ファイルを置くのはOKなのか？」という疑問にも言及。GoogleドライブもデータをGoogleの外部サーバーに送る点では同じであり、他社のクラウドサービスも同様に送信先としては考え直すべき、とされます。

  • 「Googleドライブはセーフ、AI送信はアウト」という単純な話ではない
  • どこに何を送るのかを一つひとつ検討する視点が必要
  • 本動画の主旨は「AIだけが特別危険」ではなく送信の意味を理解して使うこと
MINDSET

「大丈夫」と思っていてもセキュリティは確率ではなく行為で判断する

著者は約20年のプログラミング経験とセキュリティ実務の経験から、「漏れる確率が100万分の1だから大丈夫」という確率論そのものが間違いだと指摘します。問題は送るという行為自体であり、意識の高い人はその前提で仕事をしています。

ACTION

「使うな」ではなく「ルールで正しく使う」企業には利用ガイドラインの整備が必要

著者の主張はAI排斥ではありません。これからAIを使わない選択肢は現実的でなく、ルールに従って正しく使うべき、ということです。その上で——

  • 大企業でもAI利用ルールがまだ無いケースは多い
  • 特に中小企業では個人の裁量に任されているのが実態で、これは本当に危険
  • 社内ルール／ガイドラインの整備と研修こそが次の課題
  • ChatGPT・Claude・Gemini・Claude Code・Codex など全てのAI利用に共通の心構え

著者自身も企業向けにそうした整備の支援を行っていると紹介しています。
