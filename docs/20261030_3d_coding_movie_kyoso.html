01

「3Dコーディングムービー」とは何かOverview

今回の主題は、以前作った3D世界を素材にして、AIで「番組」を生成すること。人間が自分で操作して撮影するのではなく、AIエージェントが台本どおりに3D世界を動き回り、音声まで入れて動画を完成させる手法です。解説者を務めるのは「ワンダー佐藤」氏。前回の「3D世界の作り方」動画の応用編として、番組自動生成に挑戦します。

コーディング自体もAIが担うため、「AIを中心にして作れる自由度」が最大の売りです。

02

土台となる3D世界「不思議世界ワンディアナ 観察ツアー編」The 3D World

素材となるのは前回作った3D世界です。クリックや十字キーで操作でき、草がモフモフ動くといった物理的な反応も再現。扉に入ると江戸の町へワープする仕掛けなど、複数の世界を行き来できる構造になっています。

  • クリック・十字キーでの直接操作が可能
  • 草が靡くなど、物理空間の挙動を再現
  • 扉をくぐると別の世界（江戸の町など）へワープ

舞台は「花の江戸ソゾロ歩き」— 資料に基づく建物の再現Edo Town

江戸の町を歩くモードでは、建物自体は資料に基づいて再現されています。米屋・そば屋・ご服屋（呉服屋）・おもちゃ屋・茶屋など、実在した業種の建物が並び、スペースボタンでスタンプを収集できる探索システムが用意されています。街の配置自体は架空ですが、一つひとつの建物には歴史的な裏付けがある作りです。

世界観の作り方そのものは前回動画で解説済み。概要欄にリンクが貼られています。

04

従来の動画生成より「自由度が高い」Why 3D Coding

既存の動画生成AIでも似たことはできますが、3Dコーディングムービーの利点は「ここをこう動いてほしい」「このシーンを追加してほしい」という指示が通りやすいこと。コードで世界を拡張できるため、撮影中に足りなくなったらその場でコーディングしてシーンを追加できます。さらに資料を読み込ませれば、その資料の通りに再現してくれるため、歴史解説のような正確性が求められる番組にも強い手法です。

05

制作フロー全体像：5ステップで番組が完成Pipeline

動画内で整理された制作手順は次のとおりです。

① 3D世界を作る（ゲーム感覚・前回動画参照） ② AIと一緒にシナリオ・台本を作る ③ AI（Codex / Claude Code）にコンピューターを操作させ台本どおりに動かす ④ VOICEVOXで音声を入れる ⑤ Pythonで動画化して完成

音声入れもVOICEVOXの自動立ち上げで対応。最終的な動画へのエンコードはPythonが担います。

06

使用するAIエージェント：Codex でも Claude Code でも可CLI Agents

3D世界の操作を任せるのはCLI型AIエージェントです。今回はCodexを使用しましたが、Claude Codeでも同じことができます。ポイントは右側の内部ブラウザ。普段の画面からボタン一つで開け、アプリをブラウザ上に表示させられます。

Codex（今回使用） Claude Code コンピューター操作（画面録画）でも可
07

内部ブラウザ運用のコツ：ローカルで開くLocal Server Tip

3D世界のHTMLファイルを直接開くと操作ができなかったというトラップがあります。解決策はローカルサーバーで立ち上げること。内部ブラウザでアプリを開き、正常に動くようならそのまま利用できます。ブラウザで動くアプリを作っておけば、AIエージェントが内部ブラウザ越しに操作・撮影できる体制が整います。

08

最初の一歩は「5秒だけ撮影」テストFirst Shoot

まずは小さく始めるのがおすすめ。実際に「5秒だけ撮影してみよう」と指示したところ、問題なく動画が撮れました。ここで成功体験を積んだ上で、本番の長尺撮影に進みます。

  • 「5秒だけ撮って」→ 自然言語の指示だけで動作確認できる
  • 「内部ブラウザで花の江戸を立ち上げて」→ アプリを自動起動
  • 「動画を撮るスキルを起動して」→ スキル化した撮影処理を実行
09

「スキル化」が作業を再利用可能にするSkillification

一連の操作はスキルとして保存して再利用できます。実際に「内部ブラウザで花の江戸を立ち上げるスキル」「動画を撮るスキル」を作成。以降は「動画を撮るスキルを起動して」の一言で撮影が完結します。撮影方法は自由で、プロンプト＝自然言語で指示できるレベルの話なので、難しく考えなくてよいと強調されています。

10

実践：居酒屋シナリオで3分の解説動画を生成Hands-on

動作確認ができたところで本番です。「居酒屋のシナリオを作って、3分の動画にまとめて」と依頼すると、AIが台本を起こし、3D江戸の町を台本どおりに自動移動。歩行シーンは約3分間続き、AIが自ら気になる建物をクリックしてズームインする場面も見られました。登場キャラクターも「2人の会話キャラが出る動画スキル」として実装済みで、「キャラいらない」なら省略も自在です。

11

完成映像①：江戸の居酒屋のルーツは「酒屋」Izakaya Origins

完成した番組では、江戸の街を歩く2人のキャラクター（ワンダッ君とつ木さん）が対話形式で解説します。居酒屋のルーツの1つは酒を買う店。買って帰るだけでなくその場に立ち寄って飲む文化が育ち、酒屋と飲食の場所が今よりずっと近かったといいます。神田の「年屋」は酒屋と一杯飲みの店を兼ねた間取りを伝える例として紹介されます。

12

完成映像②：なぜ江戸で外食が発達したかWhy Eating Out Grew

江戸には武家や奉公人など、働きに来た人たちが集まり、独身男性が多かったため、日々の食事を支える商売が発達しました。魚や野菜を調理して売る店、江戸沖の屋台船のように食事や酒を出す様々な店が見られたといいます。毎日忙しく働く人にとって、すぐ食べられる料理は大きな助けでした。

13

完成映像③：おつまみと店の造りEdo Menu & Interior

当時のおつまみの人気メニューには、味噌を塗って焼いた「豆腐田楽」がありました。身近な食材も香りと焼き方ひとつで立派な酒の肴になる好例です。店内には今のような椅子やテーブルではなく、「将棋」（将棋盤のような長い腰掛け）に座り、座面に酒や料理を置く姿が絵に残されています。酒を温める「チロリ」という容器も使われ、道具から暮らしを想像する楽しさが語られます。

14

完成映像④：下り酒と地域を結ぶ流通Sake Distribution

江戸で飲まれた酒には関西から運ばれた「下り酒」がありました。町の一杯飲みの向こうには地域を結ぶ流通が存在し、一つの店を見ても食べ物を作る人・運ぶ人・売る人が繋がっていることがわかります。店の景色に働く人や食材の道筋を重ねると、街の見え方が変わる——これがこの番組の核心的な視点です。

15

歴史解説の姿勢：「資料で確かめた話」と分けるHistorical Rigor

この番組の歴史解説は、アプリ作成時に実際に資料を調査し、その内容を読み込ませて音声化している点が特徴です。冒頭では「この映像はゲームの街です。建物の配置は歴史を証明するものではありません。資料で確かめた話と分けてみていきましょう」と明確に断った上で解説が進行します。

  • 今の居酒屋をそのまま江戸に当てはめない
  • 値段を現代の円に単純置換しない
  • 「どの店も同じ」と考えず、資料ごとの違いを大事にする
16

音声とナレーションも自動：VOICEVOX連携Automated Voice

撮影した映像に音声が必要な場合は、「音声を入れて」と指示するだけで音声アプリ（VOICEVOX）が自動で立ち上がる仕組み。好きな音声・キャラクターを指定すれば、ナレーション付きの動画に仕上がります。今回の完成映像でも、2人のキャラクターによる掛け合いナレーションが自動で挿入されていました。

3Dコーディングムービーの本質は、「世界を作るコーディング」と「番組を演じるAI」を組み合わせられることです。映像をイメージしたら、コーディングで建物や説明を追加し、足りなくなったらさらに拡張する——このループが回る限り、表現は際限なく広がります。コーディングもAIが行い、操作も音声もAIが担うため、人間は「何を撮りたいか」だけを考えればよい時代が来ています。まずは前回動画の3D世界作りから始めて、自分だけの番組自動生成に挑戦してみてはいかがでしょうか。
