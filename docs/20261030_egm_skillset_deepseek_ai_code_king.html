01

EGMとは何かElephant-Goldfish Model

Googleがオープンソースとして公開した「Elephant-Goldfish Model（EGM）」は、コーディングエージェントが機能を実装する前に設計を適切に練り上げるよう支援するプラグインです。GitHubのgoogle組織下で公開され、ライセンスはApache 2.0。誰でも無料で利用できます。

公開約6週間で、すでにスターは約2,600個を獲得しています。

02

対応環境の広さ：自社Antigravityだけでなく競合ツールにも対応Supported Harnesses

EGMはGoogle自社のエージェント「Antigravity」で動くだけでなく、READMEの2番目のインストールコマンドがClaude Code向けであるなど、Claude Code、Codex、Claude Cowork、ChatGPTワークに対してファーストクラスのインストール手順が用意されています。専用のClaude Codeフォルダ（サブエージェントアダプター付き）や、独立したCodexマニフェストも用意され、駆け足な移植ではありません。

Googleの正直な姿勢：数千人の社内利用と「非公式」の明記Inside Google

  • READMEには「数千人のGoogleエンジニアが社内で利用」と記載。Gemini系ツールだけを使っているわけではないことをGoogle自身が公言している形です
  • 一方で「公式サポート対象のGoogle製品ではない」とも明記。大企業の正式リリースではなく、Googleチームのプロジェクトとして位置づけられます
04

起源：Dave RensinのエッセイOrigin Essay

EGMの考え方は、GoogleのDave Rensinによるエッセイ「Elephants, Goldfish, and the New Golden Age of Software Engineering（ゾウ、キンギョ、そしてソフトウェア工学の新たな黄金時代）」が基になっています。発想はシンプルですが、長時間のエージェントセッションで誰もがぶつかる実際の問題に正面から答えるものです。

05

2種類のエージェント：ElephantとGoldfishTwo Agent Roles

🐘 Elephant（ゾウ）＝記憶する側

プロジェクトの文脈・要件・会話で行ったすべての決定を記憶し、設計ドキュメントを執筆するエージェント。長い対話の前提をすべて保持します。

🐟 Goldfish（キンギョ）＝忘れる側

会話の記憶が完全にゼロの状態で起動するサブエージェント。設計ドキュメントと、そこから参照されたファイルだけを受け取り、レビューを担当します。

06

なぜGoldfishが効くのか：共有前提の罠Why It Works

1時間かけてエージェントと機能について話すと、あなたとエージェントの双方に大量の「共有前提」ができます。その状態で書かれた設計書は、両者には完璧に読めるのに、初めて読む人には抜け落ちた部分が見えません。Goldfishが「このwebhookが失敗したらどうなる？」「この用語は何を意味する？」と指摘する箇所こそ、実装段階で実際に事故になる箇所なのです。

07

3つ目の役割は「あなた」：トレードオフの決定と設計の承認は人間Human in the Loop

EGMにおける3つ目の役割はユーザー自身です。何を構築するかを決める権限はエージェントに委ねられず、トレードオフの判断と設計の承認は必ず人間が行う設計になっています。AI任せにしないこの線引きが、実務に即した妥当な判断だと評価されています。

08

インストール方法と重要な注意点Install

  • Claude Code：claude plugin marketplace add google/elephant-goldfish-model → claude plugin install egm@egm
  • Codex：同様に codex plugin marketplace add … → codex plugin add egm@egm
  • Antigravity：agy plugin install にGitHubのURLを指定
  • skillsフォルダだけコピーするのは禁止。スキルは実行時にレビュアーのペルソナとドキュメント標準を読み込むため、壊れます
  • インストール後は新しいセッションを開始してから利用します
09

ワークフロー①：/egm:egm-brainstorm で6つのレンズが並列突撃Brainstorm

「このプロジェクトにwebhook配信を追加したい」のように機能を渡すと、エージェントが質問で曖昧さを潰した上で、6つのGoldfishレビュアーが並列で起動し、それぞれ別の視点からアイデアを検証します。例えば「コントリリアン（反対役）」は「そもそもこの機能は必要か？既存ライブラリで9割解決しないか？」を問い、別の1体はコスト・クォータ・トークン経済を検討します。合意した方向は concepts_brief.md に保存されます。

10

ワークフロー②：/egm:egm-draft でセクション単位の設計書執筆Draft

次に /egm:egm-draft を実行すると、ブリーフが正式な設計ドキュメントに変換されます。ポイントは一気に全文を吐き出さず、セクションごとに執筆しては各セクション後に停止してチャットでフィードバックを求める方式。設計書とは本来この順序で書かれるべきものだと、動画では評価されています。

11

ワークフロー③：/egm:egm-review の5段階レビューFive-Stage Review

  • ズームアウトレビュー：懐疑的なアーキテクトとして「複雑すぎる・不要なもの」を探す
  • 理解度レビュー：素朴な読者として、説明のない用語や略語をすべて指摘する
  • 敵対的デザイン批評：アーキテクチャ・スケーリング・リスクを厳しく検証する
  • 再びズームアウトのパスを実施
  • 実装準備チェック：実務的なTech Leadとして、実装者に設計判断を残さないか確認する

設計上フィードバックが大量に出ます。公式にも「関連するものだけ採用し、残りは無視してよい」と明記されています。

12

/egm:egm-resolve と「お世辞禁止」ルールResolve & No Flattery

/egm:egm-resolve はレビューの指摘を順に処理し、変更内容の合意形成を支援するコマンドです。レビュアーにはお世辞が全面禁止という厳しいルールが課されており、「素晴らしい」「brilliant」といった評価は禁止。まず何が間違いか・リスクかを指摘し、提案に対する最強の反論を提示するよう指示されます。明らかに壊れた計画を「優れたアプローチです」と褒めるエージェントに悩まされた人には、このルールの価値が分かるはずです。

13

最も重要なハードルール：フレッシュサブエージェント強制Fresh Subagents Only

利用中のエージェントが新しいサブエージェントを生成できない場合、EGMはレビューを停止します。同じ文脈（コンテキスト）内でレビューの代行は一切せず、同じ文脈でのレビューはGoldfishレビューではないという原理原則を貫きます。各レビュアーには読み取り専用ツールと独立したコンテキストが与えられ、Goldfishが本当にGoldfishであり続けることが担保されています。この原則的な割り切りが、Claude Code版に専用アダプターが用意されている理由でもあります。

14

追加スキル：egm-bootstrap と egm-drift-reportExtra Skills

egm-bootstrap

既存のコードベースをボトムアップから走査し、各フォルダのREADMEを作成してルートまで要約。Elephantがプロジェクト全体の地図を持てるようにします。

egm-drift-report

設計ドキュメントと現在のコードを比較し、食い違っている箇所を報告します。週1回の実行が推奨されており、マージと同時にドキュメントが古くなる悩みへの対策になります。

15

向き不向きとトークンコスト：小さなバグ修正には不要Trade-offs

  • README自身が明記：小さくて明確なバグ修正には通常のワークフローを使うべき
  • FAQも「設計とレビューには時間がかかり、小さな変更では元が取れない可能性がある」と正直に認めています
  • 前提となるのは「先に意思決定が必要な機能」。フレッシュなサブエージェント群はトークンを大量消費し、1回のレビューで5〜6体がそれぞれ設計書と参照コードを最初から読みます
  • 月20ドルのClaude CodeやCodexのプランではあっという間に利用上限に到達します

解決策：ClinePass 月9.99ドルでオープンモデル使い放題ClinePass $9.99

トークン大量消費の課題にぴったりなのが、Clineチームの定額プラン「ClinePass」（月9.99ドル）です。AI各社から大量割引でモデルを調達しており、5時間・週次・月次の利用枠が価格の割に非常に潤沢です。ラインナップも強化されました。

Kimi K3.1 Pro（デフォルト） DeepSeek V4.1 Flash（新追加） MiniMax M3.1 Flash GLM 5.3 GLM 5.3 Flash Qwen3 Max

Goldfishレビューは本来トークンを大量に使うワークフロー。定額プランなら「レビュアーがファイルを開くたびにお金が燃える」感覚なしに、ブレインストーム→ドラフト→2〜3回のレビューを実行できます。

17

実践：ElephantとGoldfishでモデルを混ぜる＋Cline/PandaCodeで実行Model Mixing

  • ElephantにはKimi K3.1 Pro：長く丁寧な対話と設計書の執筆が得意
  • 敵対的批評と実装準備チェックにはGLM 5.3：実際のコードを読むのが非常に得意
  • 理解度レビューなどの軽いパスにはDeepSeek V4.1 Flash／MiniMax M3.1 Flash：高速で十分な品質
  • Goldfishが別モデルなら、Elephantの習慣や盲点すら共有しないという利点があります
  • ClineはSKILL.mdスキルとサブエージェントに対応。リポジトリ全体をクローンすればEGMが動作します（公式リスト未掲載）
  • PandaCode（アーキテクト＋ワーカー構成）はまさにElephant/Goldfish構造。読み取り専用のClineワーカーが並列でGoldfishレビューを実行できます
18

総評：ハーネスではなく「プロセス」に価値が移った時代Final Verdict

Googleが自社のGeminiエージェントではなくClaude CodeやCodex向けにEGMを提供するのは、エージェントのハーネス（外枠）の差はもう重要ではなく、モデルの周りのプロセスこそが価値を持つことの裏返しです。スキルとサブエージェントさえあれば、一度書いたワークフローはどこでも動く。EGMはアイデアがシンプルで実装が丁寧、無料・Apache 2.0で、長時間セッション特有の実問題を解決します。重要な機能開発でブレインストームとレビューを試し、月10ドルで上限を気にせず回したいなら、Cline＋ClinePass（Kimi K3.1 ProをElephantに、GLM 5.3やDeepSeek V4.1 FlashをGoldfishに）が推奨の組み合わせです。
