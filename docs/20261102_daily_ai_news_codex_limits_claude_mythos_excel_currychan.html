TODAY 02

計量はトークン単位・Instantチャットは対象外「Instantチャットは利用枠を消費しない」

共通化後の利用量はトークン（モデルが処理・生成する情報の単位）で計量されます。

  • 高度なモデル・複雑なタスクほど多くの枠を消費。モデル選択と作業の大きさで消費が変わる
  • Instantのチャットは利用枠から引かれない——例外として明記
  • プランごとの具体的なトークン数・5時間/週の枠が残るかは今回のヘルプには未記載

「同じ質問1回でも、消費量はその時のモデルとタスク次第」という、これまでより細かい課金の考え方への移行です。

TODAY 11

リストの使い方: 挿入→リスト、ショートカットはCtrl+J「1つの文字列」ではなく「値の集まり」として処理

リストは「挿入 → リスト」または Ctrl + J で作成し、カンマ/セミコロン区切りで項目を入力します。

  • 1セルに収まったまま、フィルターや計算では個別の値として扱える
  • 「プロジェクトのオーナー3人」「希望時間帯の複数回答」などのユースケースが公式例
  • 現在の制限：リストからドロップダウン（データ検証）にはまだ接続できない

「複数値を書いたら足し算できないのでは?」という配信の第一声にもある通り、集計への影響が気になる機能です。

TODAY 12

セル内配列・ネスト配列と新関数4種FLATTEN / HAS / HASANY / HASALL

配列まわりも大きく変わります。従来スピルしていた={1;2;3}のような式も、波括弧で括れば1セル内に収まるようになります。

  • FLATTEN(array,[pad_value],[levels])：ネストを解いてグリッドにスピル
  • HAS(array,value)：値が配列内のどこかにあるか
  • HASANY / HASALL：いずれか/すべてが含まれるか
  • ネスト配列は従来#CALC!エラーだったケースも完全な結果を返すように

「これ、ヘッドワーク（頭の整理）が要るな」「ディープラーニング（みたいな構造）できるんじゃない?」と、配信では夢が広がる反応も。

TODAY 13

互換性リスク: Compatibility Version 3 を前に本番運用は非推奨「重要なブックでは使わないで」とMicrosoft

Microsoftは同時に、本番環境では使わないことを明確に求めています。

  • ネスト配列の多くの計算にはCompatibility Version 3 が必要（ブック単位で「数式→計算オプション」から選択）
  • Version 3では既存の一部の数式が違う結果を返す可能性。問題がある場合はV1/V2に留まれる
  • プレビュー機能のため一般提供まで仕様が変わる恐れもある

「既存システム（の数式）を壊していけない人の懸念もある」——配信でも触れた、移行コストの問題です。
