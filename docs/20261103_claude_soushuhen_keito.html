① スキルをObsidianに自動メモKNOWLEDGE・作った瞬間に使い方を残す

ナレッジ管理

スキルが増え続けると「このスキルどう使うんだっけ？」が起きがち。KEITOさんはスキルを作った瞬間、その内容をObsidianに自動でメモさせる仕組みを構築済み。

  • 例「ルマイベント」スキル: イベント概要文をテンプレートから生成し、サムネイルをSVGでローカル生成（外部画像生成API不使用）
  • メモには使いどころ・呼び出し方・スキルの中身（ステップ・ルール）・フォルダ構造まで記録
  • スキル一覧を見返すだけで「あったな・こう使うんだ」と振り返れる
よ
Claude Codeを導入したら、すぐObsidianを接続するのがおすすめって言ってたよ。スキル資産が増えるほど効いてくる仕組みだね！

② 執筆ナレッジと表現リストWRITING・本・記事・言葉遣いを貯める

執筆効率化

約250ページ・6章の書籍執筆では、章ごと・トピックごとにメモをObsidianへ。第1章の内容が第6章で生きるような呼応や、全編を通じた統一された言葉遣いをナレッジとして蓄積し、それを見ながら次のページを書くスタイル。

  • ノート（スキル販売）の記事も同様に、書き方の流れを同じ型で再利用。売れた記事の型を残して踏襲
  • NG表現リスト: 「この言い回しはしてほしくない」を気づいた瞬間に追記
  • いい表現リスト: 採用したい表現を登録 → Claudeの言葉遣いがどんどんセンスアップ
よ
NG/いい表現リストを作っておくと、Claude Codeがすっと言うことを聞くようになるんだって。表現の好みは先に教えちゃうのがコツだよ！

③ メモ保存を「自動」にする2パターンAUTOMATION・フックス vs スキル内蔵

自動化の要

毎回自分でメモ保存を意識するのは忘れがち。そこで自動化を2パターン用意。

  • パターンA: フックス（Hooks） — スキル作成を検知したら自動でメモ保存スキルが発火。「スキルを作成したらその内容をObsidianに保存するフックを作って」と自然言語だけで作成可能
  • パターンB: スキル内蔵 — 本執筆や記事執筆スキルのワークフロー自体に「完了時にObsidianへメモ」を組み込む
  • KEITOさんはスキル作成に公式スキルクリエイターを使うためフックス式、執筆系はスキル内蔵式と使い分け
1スキルを作成スキルクリエイターで新規作成
2フックが検知skillsへの書き込みをイベント検知
3自動メモObsidianに使い方メモが完成
MEMO
音声入力の誤変換が多くても、自然な日本語に直す「音声入力エンジニアリング」用スキルを入れておけば指示が通るんだって。地味に大事な下支えだよ！

④ Record機能でWeb作業を記録RECORD・Notta目次作成を実演

記録→再現

「スキルを記録」で作業手順を音声で喋りながら記録し、そのままスキル化する機能。実演はNotta（文字起こしサービス）の目次作成。

  • 喋った内容: BraveでNottaを開く → 最新アーカイブを開く → 目次を生成 → 公開共有オン・パスワード保護オン → リンクとパスワードをメモ → 目次を整形して提出
  • テキストだけの簡素なスキルに「本当に再現できるの？」と半信半疑で実行 → Claude in Chromeが起動し約2分で作業のほぼ全部を完了
  • 目次の整形はプロンプト次第で改善可能。地味なWeb作業の自動化に効くアプローチ
よ
「こういう単純作業、うちにもあるかも…」と思ったら記録してみるのがおすすめ。思ったより再現度が高くてビックリするみたいだよ！

⑥ Claude Designのリアルタイム編集CLAUDE DESIGN・その場で直せる

⑬ 動画編集スキル＋検証エージェントループEDIT-SHORT-VIDEO・品質を自動でねじ上げる

動画機能②

読み上げ動画を投げるだけでカット合わせ・テロップ・タイトル・Bロール挿入までやる編集スキル。カンの目は「完成品をすぐ見せない」こと。

  • 完成したらウィスパーで再文字起こし → テロップと音声のずれが0.2秒以内か、テロップが顔に被ってないか、BGM・効果音の音量、カット間の黒フラッシュ・ブツ音まで検証
  • 不合格なら再レンダリング→再検証を合格点まで永遠にループ（エージェントループ）
  • 仕上げは3択: エディターで最終調整 / 実画面Bロール挿入→調整 / BGM追加で完成
  • エディターはlocalhost上で起動し、テロップ位置や画像配置を手動微調整。修正指示はスマホのDiscordからご飯を食べながらでも出せる

⑮ 権限モードとリスク設計SECURITY・何を任せ、何を守るか

安全側の設定

Claude Codeは「機密ファイルも読め、通信もできる新人社員」のようなもの。善悪の判断はできない超優秀なスタッフだから、権限設計が事故防止の鍵。

モード内容利便性/リスク
バイパスパーミッション全許可の全開モード利便性MAX／リスク100%
自動判定（Auto）別AIが分類機として危険操作を停止。初期値ほぼMAX／やや減
編集だけ自動作業範囲内のファイル編集は自動、コマンド・通信は確認中／低め
全て確認言葉どおりすべて確認低／低い
  • ルール単位では deny（必ず拒否・最強）／ ask（必ず確認）／ allow（無確認で通過）。askをAPIキー利用や送信手前に置けば全開モードでもそこだけ止まる
  • 診断ツール: 設定をチェックすると残リスクと利便性のトレードオフを数値・グラフ化（プロジェクトルートで開く、秘密を置かない、denyルール追加、MCPサンドボックス等）
  • XでバズっているGitHubツールも、まずWeb版Claudeに読ませて「安全？」と確認してから導入
よ
リスクばかり気にして全部オフにするならAIエージェントを使わなければいい。どちらを取るか「選択できる状態」にしておくのが大事だって！
