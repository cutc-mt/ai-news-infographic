課題: AIのページはなぜみんな同じ？PROBLEM・THE DEFAULT LOOK

問題提起

AIエージェントにデザインを「発明」させると、モデルはカテゴリーのデフォルトを選んでしまう——何も間違っていないが、何も意図的に決めてもいない、という状態に。

  • 中央揃えの見出し＋その上の小さなラベル
  • 横並びの3つのアイコンカード
  • 背景のソフトなグラデーション、ときどきお客様の声
よ
「間違いじゃないけど、選んでない」がポイント。デフォルトに流れる決定権をモデルから取り上げるのが、このスキルの核心だよ！

研究に基づく20の方向性RESEARCH・247 SITES → 20 DIRECTIONS

設計思想

Taste Skill はOnePageLove と Awwwards「Site of the Day」から厳選された247サイトの分析を土台に、20のデザイン方向性を導き出した。

  • 名前をモニュメントのように扱う「Name as a Monument」
  • 章ごとに色が変わる「Color Chapters」
  • 暗室のような「Dark Room」、標本カタログ風「Specimen Catalog」
  • 製品の性能を全面に出す「Product Performs」など
よ
ビルド時はこの中から3つが配られ（deal）、エージェントがクライアントに合う1つを選ぶ仕組み。トランプのような言い方が面白いよね！

ビルドは6ステップで進行PIPELINE・SIX STEPS OF A BUILD

プロセス
STEP 1ブリーフを読み、そのクライアントにしかない要素を8〜12個リストアップ（通りの名前・素材・営業時間・数値など）
STEP 220方向性からスクリプトが3つを提示し、エージェントが最適な1つを選択
STEP 3クライアントの素材と方向性を結ぶコンセプトを1文で書き出す
STEP 4実写真を使ってページを構築
STEP 5実ブラウザで3つの画面幅でチェックし、雑な箇所は不合格
STEP 6自らのスクリーンショットを確認し、上位3つの問題を最大3ラウンドで修正
FLOW
「調べる→選ぶ→一言でまとめる→作る→測る→直す」。人間のデザイナーの仕事の手順を、そのままエージェントに書けてあるのがすごいところ！

実写真戦略: グレーボックスにさよならREAL PICTURES・OPEN ARCHIVES

素材調達

ありきたりなストックフォトの代わりに、オープンなコレクションから実写真を検索する。

  • 検索先: Wikimedia Commons / Openverse / メトロポリタン美術館（The Met）
  • 利用はパブリックドメイン・CC0・CC BY・CC BY-SAのみ
  • クレジットをページ上に直接記載
  • コーヒーショップの例: その店が実際にある通りのアーカイブ写真を見つけられる
よ
「その店にしかない写真」が勝手に集まるの、めちゃくちゃいいよね。ライセンスも最初から安全なものだけっていうのが大事！

Inspect: 本物のChromeで「測る」検査INSPECTOR・MEASURED, NOT VIBED

品質チェック

動画内で最も評価された機能。検査スクリプト「Inspect」が実Chromeでページを開いて実際に計測する。

  • v2.1の新チェック: 初画面に明確なタイトルがない・余白が揃っていない・セクションが片寄りで画面半分が空き・長い空白 → 不合格
  • しきい値も研究から導出: 優れたページは余白が数ピクセル以内に収まっている
  • 「感覚（vibe）チェック」ではなく実際の測定である点が優れている
よ
「なんかダサい」じゃなくて「余白が6pxズレてる」で機械的に落とせるの、エージェント相手だと特に強いんだよね！

実ビルド: リスボンの自転車修理店「Spoke & Chain」REAL BUILD・ONE BRIEF IN CLINE CLI

実演

Cline CLI で Kimi K3.1 Pro（ClinePass経由）を使用し、単一のブリーフを投入。リスボンの小さな通りにある2人で営む自転車修理店のページを作らせた。

  • スクリプトが配った方向性は「The Printed Annual（印刷された年鑑）」
  • モデルの独自アイデア: 「店の修理タグをページそのものにする」という適応
  • その店にしかない品目リストを作成し、Wikimedia Commons で実写真を検索・クレジットを保存
  • 検査ラウンド: 1回目は見出しの折り返し過多で2回落ち、2回目は見出し上の小さなラベルで1回落ち、3回目でエラーゼロで合格
  • 合間に自らのスクリーンショットで確認・修正し、2人の新しいレビュアーまで派遣してチェック
  • 全体の実行時間は約58分。ClinePass利用のため追加費用ゼロ
LOG
落ちる→直す→合格、まで全部自動。3ラウンド制の自己修復ループがきちんと機能してるの、見てて気持ちいいんだって！

ただし完璧ではない: 残った問題CAVEATS・HUMAN REVIEW STILL REQUIRED

注意点
  • デスクトップで写真ストリップが予約フォームに重なるバグが残存—しかもインスペクターは合格と判定
  • レビュアーの1人がその点を指摘したが、モデルは却下してしまった
  • 写真の多くはリスボンのものではなく、住所や価格は捏造
  • 結論: 最終確認は人間が行う必要がある。ただしスキルなしの場合より圧倒的に良い
よ
検査をすり抜けるバグもあるし、事実確認はまだ人間の仕事。「 automate して丸投げ」はだめだよ！

Cline Desktop: Import と ScheduleCLINE DESKTOP・BETA

インターフェース

ターミナルが苦手な人向けのスタンドアロンアプリ版Clineエージェント（ベータ版）。ワークスペースを開くだけでエディタ不要で作業できる。

  • 拡張機能・CLIと同じハーネスを使用。ClinePassのオープンモデル、プロバイダー経由の300以上のモデル、独自APIキーに対応
  • CLI・拡張機能・デスクトップアプリでセッション共有、履歴は一箇所に集約
  • Import: Claude Code で始めたデザインを制限到達時にインポートし、ClinePass の Kimi K3.1 Pro で継続
  • Schedule: 名前・頻度・プロンプト・モデル・ワークスペースを設定してジョブを自動実行。例: 毎週インスペクターを走らせ、安いモデルで落ちた箇所を修正
よ
「週次で品質検査を回す」運用、サイトを長期メンテしていくなら本当に便利そう。放置しても品質が落ちないのいいね！

PandaCode と TasteCodeMODEL COMPARISON & TEAM'S OWN APP

周辺ツール
  • PandaCode: スキルを読み込めるエージェントなら何でも動く。Cline・Claude Code・Codexなど複数エージェントを実行可能
  • アーキテクトが複数ワーカーに同じブリーフを渡し、異なるモデルで実行→全ページを並べて比較。どのモデルにデザインのセンスがあるかを簡単に検証
  • TasteCode: Taste Skill チーム自作のデスクトップアプリ（初期ベータ）。Codex・Claude Code・Grok を自分のサブスクリプションで実行
  • 設計モード内蔵で、指示出しから確認までエージェントが行い、ブラウザタブでページを開く。無料・オープンソース
よ
「モデルのセンス比べ」を同じお題でできるの、面白い！PandaCode はAI Code King 自身が公開してるツールなんだって！
