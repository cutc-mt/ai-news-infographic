AI Code King｜2026.11.05

Claude Code OS Setup：月20ドルで組む「AIコーディングOS」の全体像

何も入っていないMacから、Claude Code＋Zed＋T3 Codeで最初のアプリを動かし、ブラウザで検証するまでを一気通貫で解説。サブスクの選び方からDeltaの落とし穴まで、動画「Claude Code OS Setup: The $20 AI Coding OS」を18枚のカードにまとめました。

1

今日のゴール：まっさらなMacからAIアプリ完成まで

「Macにほとんど何も入れていない状態から、AIで何かを作りたい」。どのサブスクを買うべきか、有料エディタは必要か、ターミナルのClaude CodeかT3 CodeかDeltaか。この動画はその全部に順番に答えます。結論から言うと、コーディングエージェントはClaude Code、エディタはZed、タスク専用UIが欲しければT3 Code。そして月20ドルのClaude Proで始められるのがこの構成の出発点です。

👑
200ドルプランに慌てて課金して、さらに3つもコーディングツールを契約する必要はありませんよ。まずはProで始めて、使い方がわかってから増やせばいいんです。
2

サブスクの入口：FreeにはClaude Codeがない

まず混乱しやすい点から。Claudeの無料プランにはClaude Codeが含まれません。チャットボットにコードを聞くのと、自分のPC上のプロジェクトをClaude Codeに触らせるのは別物です。

  • Pro $20/月Claude Code込み。年払い$200で実質月$16.67
  • Max 5x $100/月・Max 20x $200/月

学習中・副業プロジェクト中・使用量を探っている段階なら、Proが第一候補です。

3

「5倍・20倍」の正体：無制限ではない

Max 5x / 20xの数字はPro比のセッションあたり使用量の目安で、無制限コーディングを意味しません。週次制限が同倍率で伸びる保証もありません。

  • ProもMaxも「5時間セッション制限＋週間制限」あり
  • チャットとClaude Codeの使用量は同じプランから減る
  • 別ターミナルを開いても、T3 Codeに切り替えても枠は増えない

目安として、Proの制限が実務を頻繁に邪魔するようになったらMax 5x、それでも重い使い方ならMax 20xを検討。

4

チーム向け：StandardとPremiumシート

実際にチームメイトと管理・課金を共有したい場合向けのプランです。

  • Standard $25/人・月（年払い$20）
  • Premium $125/人・月（年払い$100）主に使用量が増える
  • 両方とも現在Claude Codeを含む。チームは2人から

Enterpriseは別枠：シート$20/人・月（年払い）＋API単価の従量課金で、セルフサービスは20シート、営業経由は50シートから。$20シートは無制限プランではない点に注意。学校や勤務先でアクセスが提供されているなら、自分で買う前にまずそのアカウントを確認。

5

使い切ったとき：UsageクレジットとAPIクレジット

有料プランには従量のUsageクレジットがあり、月次の支出上限を設定して追加利用を買えます。サブスク全体を上げるべきか、たまの追加課金で済むかは比べて判断を。

さらにMaxとTeamの月次プランにはAPIクレジット特典が展開中。Max 5xは$100、Max 20xは$200、Teamはシートベースのプール。対象プランで7日後にコンソール組織をリンクして受け取ります。ただしこの特典は対話型Claude Codeの利用や上限超過分には使えず、Proには付かないこと。今回の入門セットアップではサブスクサインイン一本でいきます。

6

Macの下準備①：コマンドラインツールとHomebrew

Apple Silicon Macで解説。Spotlightからターミナルを開けば、macOS同梱のターミナルで十分です。

  1. xcode-select --installでAppleのCLIツールを導入（Xcode本体は不要）
  2. 公式サイトのHomebrewインストールコマンドを実行
  3. 表示される「Next steps」のPATH追加コマンドも忘れずに実行
  4. 新しいターミナルでbrew -vを確認
🍎
PATH追加を飛ばして「brewが見つからない」になるのが、新品Macで一番よくあるつまずきポイントですね。
7

Macの下準備②：gitとghの接続

brew install git ghでgitとGitHub CLIを導入。Claudeはgh経由でリポジトリやプルリクエストを扱えます。

  • gitのユーザー名・メールを設定（コミット履歴に個人メールを載せたくないならGitHub設定のプライベートメールを使う）
  • gh auth login→GitHub→HTTPS→ブラウザ認証
  • gh auth setup-gitでgit認証も接続し、gh statusで確認
8

Macの下準備③：Node.js LTSとプロジェクト準備

Web開発向けに公式サイトからLTS版のNodeをインストール（収録時点でNode 24）。npmも同梱されます。ネイティブClaude Code自体にNodeは不要ですが、Webアプリと各種連携に必要なので入れておきます。

  • 新ターミナルでnode -vとnpm -vを確認
  • ホーム下にprojectsフォルダ＋アプリ用フォルダを作成（スペースのないシンプルな名前で。ここではai-starter）
  • 小さなREADMEを作り、git initして最初のコミット
9

Claude Code本体：ネイティブインストール

公式セットアップページのmacOSネイティブ用コマンドを実行。PATH指示に従い、新ターミナルでclaude -v→claude loginでサブスクを持つ同じClaudeアカウントでサインインします。

  • プロジェクトでclaudeを起動し、/statusでアカウントと認証を確認
  • 過去にAPIキーを設定していたら要注意。API課金に寄ってしまうことがある
  • 挙動がおかしければclaude doctor。ネイティブ版は自動更新

まず「このフォルダのファイルを説明して」と依頼し、READMEを見つけられれば導入成功です。

10

エディタはZed：無料でClaudeを載せる

動画のおすすめはZed。公式サイトからDLしてApplicationsへ。Claudeに大きなタスクを任せつつ、ファイルを眺めて小修正を直接入れる「ちゃんとある場所」が欲しい——単語2語の直しのたびに会話を増やさなくて済みます。

  • エディタ自体は無料。有料はホスト型AI機能のみで選択制
  • 使い方A：Zed内蔵ターミナルでそのままclaude
  • 使い方B：コマンドパレット（⌘⇧P）→zed: copilot registry→Claudeエージェント統合をインストール

ACP（Agent Client Protocol）でエディタが外部エージェントと対話を表示。「外部Claudeエージェント」を選ぶこと。Zed自身のエージェントにAnthropicモデルを選ぶのは別の課金経路で、「モデル名にClaudeと見える＝Proのサブスクから払われる」ではない点が重要です。

11

T3 Code：無料OSSのタスク管理UI

複数タスクの専用インターフェースが欲しいならT3 Code。無料・OSSで、エージェント会話・プロジェクトファイル・変更・Git操作を1つのワークスペースにまとめ、裏側のツールとアカウントをそのまま使います。

  • インストール：公式DLまたはbrew install --cask t3-code（npx t3@latestのブラウザ版も）
  • 設定→ProvidersでClaudeを有効化。claude login済みならそのログインを流用可能（CLIが見つからなければバイナリパスを指定）
  • 初回はsupervised（承認制）パーミッションを明示的に選ぶ
12

worktreeで並行タスク、でも枠は共有

T3 Codeでタスクを作るとき「new worktree」を選べると、そのタスク専用のブランチと作業フォルダが割り当てられます。あるタスクが機能追加中に、別タスクが別の変更を試しても同じチェックアウトを取り合いません。

便利なレビューフロー：ターン中の変更点の検査、ブランチとベースの差分比較、そしてコミット・プッシュ・PR作成。エージェントのworktreeをZedで見たいならworktreeフォルダ側を開くこと。元のプロジェクトフォルダには未マージの変更は現れません。

🌿
並列エージェントもClaudeの使用枠はみんなでシェアです。まずは1タスクから慣れて、役割が明確に分かれた2つ目を足すのが初心者向け。
13

Bamboo：タスクボード型のエージェントワークスペース

もう一つの界面、Bamboo。Claude CodeのほかCodex・OpenCode・Kimi Code・AntiGravityなども束ねるネイティブデスクトップアプリです。Claude Codeの導入・サインインを済ませてから、Bambooでプロジェクトを開きタスクを作成、Claude Codeを選んでモデルを指定するだけ。

  • タスクボード：pending→作業中→レビュー→完了が追える
  • ファイル差分、ブラウザ、スクリーンショット等のビジュアル参照でUI指示が正確に伝わる
  • Architect＋最大3 Workerの分担。モデルやツールを混在させてチームプロファイルとして保存可能

価格は$20/月（個人2台）＋Claudeサブスクで、Pro月払いなら実質$40/月。まだアルファ版なのでバグと変化は覚悟を。無料枠のT3 Codeと比べて、タスクボード・ビジュアルワークフロー・チーム連携を本当に使うかで判断します。

14

Deltaは面白いが、今回の構成には要注意

Zedチーム製のDeltaは、会話とその成果のコード変更を一緒に置き、Delta DBというバージョン履歴の上で「変更から会話をたどる」レビュー・協働ができるツール。現在パブリックベータで、MacはApple Silicon＋macOS 13以降。Zedアカウントでサインインし、Gitリポジトリを追加、隔離worktreeとプロバイダを設定して使います。

  • Personal無料・Pro $10/月（ホストモデル$5分＋従量）。既存Zedサブスクでも利用可
  • 重要：非公開プロジェクトを取り込むと、追跡対象ファイルをDeltaのサーバーへアップロード。隔離worktreeはサンドボックスではない

そして最大の落とし穴。Claudeサブスクの直接サインインは現時点で「近日対応」で、ACP経由の外部エージェント取り込みも「進行中」。Anthropic APIキーは接続できるけれ別課金。買ったばかりのサブスクを使いたい今は、T3 CodeかZedの外部Claudeエージェントが正解です。

15

CLAUDE.md：プロジェクトの説明書を渡す

プロジェクトの初期化が済んだら小さなCLAUDE.mdを作り、アプリのコードが生まれてきたら/initで生成→内容を確認。毎回Claudeが知るべきことを書きます。

  • アプリの内容・実行方法・テスト方法・プロジェクト固有のルール
  • 自分で読み切れる短さを保つ
  • Starter向け：TypeScriptを使う／初版はデータをブラウザのローカルに保存／変更はビルドとテストで確認
  • .gitignoreも依存・ビルド成果物・ローカルシークレットが入らないようClaudeに設定させる
16

拡張：Context7・デザインプラグイン・Superpowers

Context7：npx context7 setup --claudeでエージェントに最新のライブラリ公式ドキュメントを引かせられます。「プロジェクトの実際のバージョンのドキュメントを確認して」と指示するのがコツ。APIが最近変わった場合は特に有効。

フロントエンドデザイン：公式マーケットから。ただし「綺麗にして」より、参考スクリーンショット・希望色・レイアウトの明確な説明の方がずっと効きます。Superpowers：要件の明確化・計画・テスト・レビューのワークフローを追加。大きめの機能構築で試す価値あり。プロジェクト限定か全体かを選んでインストール。

17

Claude in Chrome：実ブラウザでの動作確認

Webアプリには実ブラウザでの検証を。Chromeと公式拡張「Claude in Chrome」をインストールし、サインイン。ターミナルのClaude Codeをclaude --chromeで起動、/chromeで接続確認、ローカル開発サイトへのアクセスを承認すれば、第三者製UIに同等機能がなくても公式のブラウザテスト経路が確保できます。隣にZedを開き、CLIでこの部分だけ担当させる運用が現実的。

18

実演：読書リストアプリを1サイクル回す

最初のプロジェクトは「読書リスト」が最適。本の追加・読了の記録・フィルター・リロード後のデータ保持——ワークフロー全体を試すのに十分で、アカウントや決済の設定に午後を潰しません。

  • プロジェクトでスレッドを開き、実装前にプランを要求（CLIではShift+Tabでプランモードへ）
  • プロンプト例：React＋TypeScript＋Viteで読書リスト。追加・編集・削除・フィルタ、ブラウザ保存、温かみのある背景と読みやすいタイポ、スマホで横向きスクロール不要のコンパクト配置
  • 検証条件を明示：空タイトル拒否・編集で複製されない・リロードで消えない・電話幅で横スクロールなし
  • 雛形ができたら/initでCLAUDE.mdを精査し、npm run devで開発サーバー起動（worktreeならそこからも）
  • 2つ目のターミナルでclaude --chrome：本を2冊追加→1冊編集→1冊読了→リロードで保存確認→モバイルレイアウト点検
  • 失敗したら再現手順を渡してその箇所だけ修正させ、同じ操作で再確認。自分でも空状態・長いタイトル・削除を手でクリック
  • ZedやT3 Codeの差分で変更を理解し、動く版をコミット。GitHubにprivateリポジトリを作ってpushも

次の機能（例：評価の追加）は新しい会話で明確な依頼から。これが日々のワークフローです。/modelで利用可能モデル、/usageで残量を確認し、推奨デフォルトから始めて評価できるタスクで実験を。一番高いモデルにちまちました修正を任せる必要はなく、Python環境やDockerは必要になったときに足せばいい。

🏁
まとめ：Claude Code＋Zed＋git、ブラウザ検証、必要になったらT3 Code。基本のランニングコストはClaude Pro月20ドルだけ。容量も連携も、プロジェクトが実際に必要としたときに足していく——それが良いスタート地点です。
