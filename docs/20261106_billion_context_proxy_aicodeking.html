02 課題

コンテキストウィンドウが埋まると何が起きるか長期タスクで誰もが直面する問題

AIコーディングエージェントを長期のタスクで使うと、セッションが肥大化し続ける。ウィンドウが埋まったエージェントは次のどちらかに陥る。

  • すべてを曖昧な要約に圧縮して詳細を失う
  • 機能不全に陥り、やり取りのたびに履歴全体を再送

つまり同じトークンの料金を何度も支払っている状態。キャッシュされたトークンは安価なだけに、履歴再送はコスト面で重大な損失になる。

!
定額プランでも5時間枠・週間・月間制限があるため、履歴再送が続くとすぐ制限に達してしまう。
03 仕組み

エージェントとモデルAPIの「間」に置く小さなプロキシベースURLを向けるだけで全リクエストが経由

① エージェントClaude Code / Cline / OpenCode など。ベースURLをプロキシに変更するだけ
② billion-context会話を読み取り、完了した部分を圧縮してから転送
③ モデルAPIAnthropic / OpenAI形式に対応。圧縮済みの履歴だけが届く

エージェント側の設定変更は最小限。プロキシが会話を読み取り、完了した部分を圧縮してから実際のモデルへ転送するという構造で、モデルから見れば常にコンパクトな履歴に見える。単に上限で履歴を切り捨てる方式とは異なり、失われた情報は後から復元できる。

04 中核機能

モデルに与えられる4つのツールいつ・何を圧縮するかはモデル自身が判断

  • compress — メッセージ範囲を詳細な要約にまとめる
  • decompress — 詳細が必要になった際にその範囲を元に戻す
  • search context — 圧縮されたすべての中身をキーワード検索
  • ACP status — コンテキストの充填状況と圧縮可能な範囲を表示

モデル自身がツールを呼び出して圧縮を制御する点が、エージェントに組み込まれた従来の要約機能との決定的な違い。

05 圧縮方式

インクリメンタル・可逆・キャッシュ維持切り捨てではなく小さな範囲ごとに要約

圧縮は増分式。全体を一気にまとめるのではなく、小さな範囲ごとに要約する。そして可逆的で、いつでも展開可能。

10 魔法ではない

「針を探す」テストでの低下要約は意味を保つが、正確な単語は保たない

圧縮の正確な一文を抽出する必要がある「ニードル（針探し）」テストでは、69%→27%へとリコールが低下。要約は意味を保持するが、すべての正確な単語を保持するわけではない。

⚠
過去の特定の行を逐語的に必要とする場合、モデルはdecompressでその範囲を展開する必要がある。コーディングエージェントにとっては通常適切なトレードオフだが、この点は理解しておこう。
11 セットアップ 1/3

インストールは「billy」コマンドnpmで一発、3つの使い方

ローカルフォルダに--prefixを指定してインストールすると、billyコマンドが使えるようになる。

INSTALLnpm install -g billion-context
  • billy plugin install [クライアント名] — Cursor、OpenCode、Continue などネイティブプラグインとして動作
  • billy [クライアント名]（例: billy claude）— 設定変更なしでプロキシ経由起動
  • ベースURLの前置き — 起動中のbillyのアドレスをプロキシとして設定（Clineでの使い方）

13 セットアップ 3/3

Cline / Cline Desktop の設定手順ベースURLにプロキシを前置きするだけ

① プロバイダーClineで「OpenAI Compatible」を選択
② ベースURLlocalhost:8787/v1 + ClineのAPIアドレスを続けて入力
③ キー＆モデルClineのAPIキーを貼り付け、モデルに「ClinePass/DeepSeek V4.1 Flash」を指定

これでClineからのすべてのリクエストがbillion-context経由で圧縮され、ClinePassへ送られる。billion-contextのリポジトリにはOpenAI互換ベースURL経由のClineが検証済みクライアントとして記載されており、Cline Desktopでも同様に動作する（プロバイダーリストのOpenAI互換項目で同じURL・キー・モデルを設定）。

14 相性の理由

なぜClinePass × billion-contextなのか定額制の制限を履歴短縮で回避

ClinePassは定額制だが、5時間枠・週間制限・月間制限が存在する。長時間セッションではやり取りのたびに履歴を再送信するため、すぐに制限へ達してしまう。

  • billion-contextが履歴を短縮 → 同じプランでもっと長く使える
  • DeepSeek V4.1 Flashはベンチマークと同じモデルファミリー
  • Cline Desktopは長期タスクに最適なスタンドアロンアプリで、並行セッション実行・ジョブスケジュール・Claude Code／Codex会話のインポート継続にも対応

実際にコストが削減できているかの検証に非常に便利。

16 オーケストレーション

PandaCodeとの組み合わせアーキテクト×ワーカー構成で圧縮が最も効く

GUIでのオーケストレーションが必要ならPandaCodeがおすすめ。タスク全体を管理するアーキテクトが個別のワーカーへ作業を割り振る構成で、Clineはそのハーネスの一つ。

  • アーキテクトのセッションが最も長く続き、コンテキストも最も肥大化 → 圧縮機能が最も威力を発揮
  • ワーカーはPi、OpenCode、Kimi Codeなどで実行可能。すべてBillyのネイティブプラグインを保有
17 注意点

導入前に知っておくべき4つの制限急速に進化するプロジェクト特有のリスク

  • 進化が非常に速い — 現在はバージョン0.121。デフォルトで自動更新されるが、マスターブランチはいつ壊れてもおかしくない。NPMからリリース版をインストールすること
  • --hostでのネットワーク実行は認証ゼロ — 信頼できるネットワーク上でのみ運用すること
  • Claudeデスクトップアプリのコードタブはプロキシをバイパス — 圧縮は適用されない
  • 逐語リコールの低下 — 過去の特定の行を正確に必要とする場合はdecompressが必要。ドキュメントも巨大で専門的なため、セットアップには読み込みが必要
18 まとめ

安いオープンモデル×途切れないセッション長期エージェント運用の現実解

billion-contextは、モデルがキャッシュを維持したまま履歴を小さな範囲でツールにより圧縮・復元できるプロキシ。DeepSeek V4.1 Flashのベンチマークではフルコンテキストより安価で、コーディング性能はわずかに上回った。

  • Cline／Cline Desktopの前に置けば、安価なオープンモデルと継続的なセッションが手に入る
  • 長時間のエージェントセッションが頻繁に終了したりコストがかさむ場合の有力な解
  • 全体としてかなり優れたツールとの評価
