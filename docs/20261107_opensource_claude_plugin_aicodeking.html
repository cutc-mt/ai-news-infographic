Claude Codeで一番イライラするのはレート制限じゃなくて「毎朝ゼロからやり直し」だと思うんだ。今回はそれを治すOSS「Claude Mem」を、仕組みから実際のデモ、そして知っておくべきプライバシー問題まで全部見ていくよ。
01 今日のテーマ

Claude Code最大のストレスは「セッションの健忘症」レート制限ではなく、記憶が引き継がれないこと

Claude Codeで一番つらいのはレート制限ではない。新しいセッションが毎回記憶ゼロで始まることだ。1時間かけてバグを直し、判断理由を説明し、ターミナルを閉じる。翌朝、Claudeは何も覚えていない。同じ説明をし、同じファイルを読み直し、同じトークン代をもう一度払うことになる。

あるある「昨日なんでその実装にしたんだっけ？」→全部説明し直し……このループ、地味に一番コストが高い。
02 主役の登場

それを解決する「Claude Mem」もはや小さな実験プロジェクトではない規模に成長

Claude Memはコーディングエージェント向けのメモリシステム。エージェントがセッション中にやったことを監視して短いメモに圧縮し、将来のセッションで関連するメモを渡してくれる。コマンドを覚える必要も呼び出す必要もなく、バックグラウンドで動く。

112,000+GitHubスター数
約10,000フォーク数
Apache 2.0ライセンス
v15.92日前にリリース

ただし導入前に知るべきプライバシー問題もある（後述）。

03 仕組み① 観測

Claude Codeのライフサイクルフックを活用すべてのツール実行をフックでキャッチ

Claude MemはClaude Codeのライフサイクルフックを使う。セッション開始、プロンプト送信、各ツール呼び出しの前後、停止、セッション終了――それぞれにフックがあり、Claudeがファイルを読み、編集し、コマンドを実行するたびにClaude Memがそれを捉える。

①フックツール実行を検知
②ワーカーローカルで常駐実行
③observerHaikuが解析
④保存SQLite＋Chromaへ

イベントはローカルで動く小さなワーカーサービスに送られ、バックグラウンドで動くもうひとつのモデル（Haiku）に渡される。

04 仕組み② 記録

ツール実行を「オブザベーション」に変換して保存タイトル・種別・ナラティブ・事実・対象ファイル

observerと呼ばれるモデルが、生のツール呼び出しをオブザベーション（観察記録）に変換する。各記録にはタイトル、種別（バグ修正・意思決定など）、短いナラティブ、事実、関係するファイルが含まれる。保存先は自分のマシン上のSQLiteデータベースと、意味検索用のChromaベクトルDB。

  • セッション終了時には「何を依頼し・何を調査し・何が分かり・次は何をすべきか」のサマリーも生成
  • すべての記録は自分のマシン上で管理
05 仕組み③ 読み出し

「漸進的開示」でトークンを節約履歴を全部突っ込むのは最悪の設計

単純なメモリ実装は履歴を全部コンテキストに流し込む。しかしそれは無関係な情報に何千ものトークンを燃やすだけ。Claude Memはプログレッシブ・ディスクロージャー（漸進的開示）という方式を採る。

流れ新セッション開始時に、直近のオブザベーション（デフォルト50件）の「索引」だけを注入。含まれるのはタイトル・種別・読み込む場合のトークンコストのみ。エージェントは何が存在するかを見て、開く価値があるものを自分で判断する。

必要になれば3つの検索ツールで詳細を取りに行く設計だ。

06 検索ツール

「search」はID一覧だけ返す超軽量設計取得前にフィルタして約10倍のトークン削減を主張

検索ツールのひとつsearchは、コンパクトなIDのリストを返すだけ。1件あたりのコストは約50〜100トークンで、エージェントが選んだID分だけ課金される。「取得前に絞り込む」ことで約10倍のトークン削減を主張している。

⚠️
ただし公式サイト自身が「トークン使用量への影響はワークロードとプロバイダ次第」と注意書きしている。10倍という数字は鵜呑みにしすぎないのが正直なところ。
07 インストール

インストールは npx ひとつnpm install -g はNGなので注意

インストールは npx claude-mem install を実行するだけ。npm install -g は使わないこと――ライブラリが入るだけで、フックもワーカーもセットアップされない。

  • インストーラはまずランタイム（BunとUV）を準備してくれる
  • 続けてサインインとメモリプロバイダの選択へ進む
08 プロバイダ選択

ホスト版に登録しなくても使える--provider フラグで自前のプランで動かす

セットアップ中にホスト版「CMem Pro」（30日間の無料トライアル付き）が事前選択されているが、選ぶ必要はない。--provider claude フラグを渡せばサインインをスキップし、自分のAnthropicプランの枠内でメモリが動く。

  • 自分の OpenRouter や Gemini のキーも使用可能
  • OpenAI互換エンドポイントなら何でもOK
動画ではClaudeプロバイダを指定してセットアップ完了。追加料金ゼロで始められる。
09 実演① バグ修正

請求書APIのタイムゾーンバグを修正「月末締めの請求書が1日早く表示される」問題

小さな請求書APIを題材に実演。一部の顧客で月末が期限の請求書が1日早く表示されるバグをClaudeに調査・修正させる。

  • Claudeが日付処理のコードを読んで原因を特定
  • 期日がローカルタイムとしてパースされており、タイムゾーンによって日付がズレることが判明
  • UTCへの変換に修正し、テストはすべて合格

この一連の作業中、Claude Memはすべてを録画していた。

10 実演② 記憶の確認

ワーカーのビューアで録画内容を確認メモリタイムラインとオブザベーション

ブラウザでワーカーのURLを開くとビューアが表示される。メモリタイムラインには、先ほどのセッションで生成されたオブザベーションが並ぶ。バグ修正の記録にはタイトル・事実・触れたファイルが整理され、セッションサマリーには「何を学んだか」「次のステップ」まで記録されていた。

ここまで自動何もコマンドを打たなくても、セッション中の作業がそっとメモになっている。
11 実演③ 真価

真っ新しいセッションが前のバグを「知っている」索引はわずか425トークン

セッションを閉じて完全に新規セッションを開始。冒頭には注入されたコンテキストがあり、直近3オブザベーションのタイムライン・種別・読取コストは合計425トークンのみ。

  • 「期日の3日前にリマインダーメールを追加して」と依頼→日付バグを一度も説明していないのに、期日はUTCで扱うことを既に知っており、同じヘルパーを使い回す（新規セッションなら書き間違える典型的なミス）
  • 「なぜ期日のパース方法を変えたの？」と質問→searchでIDを絞り、get observationsで詳細を取得し、前セッションのタイムゾーン問題という本当の理由を回答
感想何も説明し直さなくていいのは、本当にすごい。
12 新機能 My Work

「My Work」ページでエージェントの作業を一覧管理多数のエージェントを同時実行する人に便利

新しいMy Workページは同じローカルURLのデフォルト画面になった。記録されたリクエストから「作業中」「あなたの待ち」「完了だが未確認」を可視化する。

  • 確認したら「mark checked」を押せばOK。その確認状態はローカルに保存
  • 従来のメモリタイムラインは「classic viewer」リンクから利用可能
  • たくさんのエージェントを並走させている人には特に役立つ
13 対応範囲

Claude Code以外のエージェントにも対応v15.9ではDevinが追加

名前に反してClaude Code専用ではない。--id フラグでCodex、Cursor、OpenCode、Windsurf、Copilot、Kimi、Devin、Hermes、PI、DeepSeek Coderなどに対応（v15.9でDevinが追加）。

  • メモリの書き出し言語は約30言語から設定可能
  • 記録を減らして「再発見が痛いもの」だけ残すchillモードも搭載
14 注意① プライバシー

最大の問題：過去30日分のプロンプトを無断アップロードしていたv15.8.3（11月2日）で修正済み――必ず最新版を

v15.2で追加されたブラウザセットアップが、数日前までClaude Code・Codex・Gemini CLIなどのローカル履歴をスキャンし、過去30日分のプロンプト全文をプロジェクト名・フォルダパス・タイムスタンプとともにcmem.aiへアップロードしていた。ページを読み込んだ瞬間に、確認なしで実行される。

  • ユーザーがIssueで報告。報告によればcmem.aiは「プロンプトが保持・学習する可能性のあるプロバイダをブロックせずOpenRouter経由で処理した」ことを認めた
  • しかもプライバシーポリシーには「Cloud Syncを有効にしない限りデバイス外に出ない」と書かれていた
  • v15.8.3からは明示的に確認を求め、「すべてローカルに保持」する選択肢も明確に表示される
  • ただし既にアップロードされたプロンプトはアップデートでは削除されない。旧バージョンのブラウザセットアップを使った人は要注意
🛡️
今日インストールするなら、必ずv15.8.3以降を使うこと。動画の結論としては「アップロードにはNoと言う」が推奨。
15 注意② テレメトリ

テレメトリはデフォルトでON匿名・ドキュメント済みだがオプトアウト制

テレメトリは匿名で仕様も公開されており、インストーラが一度だけ尋ねてくれるが、基本的にONがデフォルト。

  • npx claude-mem telemetry disable で無効化できる
  • Do Not Track環境変数の設定も有効
16 注意③ 機密保護

privateタグと自動リダクションリダクションはデフォルトONにすべきと指摘

プライバシー対策の道具自体は悪くない。

  • 任意のテキストをprivateタグで囲むと、そのセッションではClaudeが使えるが、メモリには保存されない
  • 自動リダクションはAPIキーなどの機密パターン30種類を内蔵。ただしオプトインなので、動画では初日に redact enabled 設定でONにするのがおすすめ
17 注意④ コスト

エンジンは無料でもobserverはモデル隠れた実行でクォータを食う報告も

エンジン自体は無料・OSSだが、observerはモデルであり実行コストがある。

  • Claudeプロバイダ指定時は自分のプランの使用量を共有。既に上限に達している枠から消費される
  • Issueで「My Workのリフレッシュにより4日間で約230回の隠れたCodex実行が発生し、Codexのクォータを使い切った」という報告
  • ホスト版はトライアル後$30/月、Heavy $70、Max $100
  • デフォルトONのファイル読み込みゲートは、履歴のある大きなファイルの読込をブロックしてアウトラインを代わりに渡す。トークン節約になるが、大ファイル周りでClaudeの挙動がおかしい時はここを疑う
18 結論

使うべき人は「同じプロジェクトを長く続ける人」約2分のセットアップで良いとこ取りする手順

  • ◎同じプロジェクトに数週間取り組み、同じ判断を何度も説明し直している人には本当に有用。索引アプローチはこの問題の賢い解き方
  • △小さな単発タスクしかしない人には不要。良い CLAUDE.md ファイルで大半の仕事は無料で済む
