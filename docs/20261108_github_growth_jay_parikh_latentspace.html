ホストインフラ、セキュリティ、そしてソーシャルメディア——まさにアベンジャーズのような経歴です。開発者のソーシャルネットワークが集まり、私たち全員が頼るサービスを維持している。

03 エージェント化の現在地

PRの約40%はエージェントが作っているエージェント総数はわずか6ヶ月で6倍

GitHub上で作られるプルリクエストの約40%がエージェントベース。エージェントの総数は6ヶ月で6倍に急増し、プラットフォームの構成は大きく変化しつつある。

注目点エージェント利用の爆発にもかかわらず、人間による利用も同時に増加している。「エージェントが来て人間が去る」ではなく、両方が一緒に伸びるという珍しいパターンです。
04 信頼性とスケール

ダウンタイム批判の裏で進む「毎秒」の戦い今年初めて信頼性スコア9点を達成

多くの人がGitHubのダウンタイムを批判するが、このサービスは今年初めて信頼性で9点を達成。同時に、エージェントのニーズだけでなく人間のニーズにも適合するための極端な規模の進化が続いている。

  • 1年間で毎秒1人の開発者追加——途方もない持続的成長
  • 成長と並行してAzureへの移行も進行中
ホスト順風満帆な道のりではありませんでしたが、障害やダウンタイムについて石を投げられる人はいるでしょうか。GitHubは常にGitHubです。
05 コードのソーシャルネットワーク

熟練エンジニアでなくてもGitHubを使える時代NingとFacebookで学んだパターンの再適用

かつてGitHubは「私はソフトウェアエンジニア・PM・デザイナーだから使える」ものだった。しかしAIのコーディングエージェントにより、熟練エンジニアでなくてもアイデアを共有できるプラットフォームへと開かれつつある。

Jay先日ある記者が「リポジトリを作って人々と共有し、フィードバックが欲しい」と試していました。世界がAIを採用して、一緒に何かを構築するために学んでいる、もう一つの方法だと思います。
06 限界を使うユーザー

OpenClawのPete Steinbergerと「プルリクエストの終焉」上位0.001%のパワーユーザーが問い続ける前提

Podcast推薦ゲストでもあるOpenClawのPete Steinberger氏は、おそらく上位0.001%のユーザーの一人で、GitHubを限界まで押し進める存在。彼の問いの一つが「プルリクエストの終了」——エージェントによってPRという概念自体が変化するのか、という議論だ。

Jayピーターとチームは本当に素晴らしく、私たちを常により良くしようと後押ししてくれます。テクノロジーは急速に進歩しているので、私たちは反復を続け、プラットフォームを進化させ続けます。
07 コンポーザブルな未来

「概念は必須ではなく構成可能になる」Jay自身、PRを作らないリポジトリを持つ

新しいパラダイムが出現すれば、プラットフォームは適応し続ける。役に立たなくなった概念は構成可能（コンポーザブル）な選択肢になり、必須ではなくなる。

  • 2億2500万人の開発者、大企業、中小企業、学生——多様な層に多くの概念を備えたプラットフォームを提供する必要がある
  • Jay自身もプルリクエストを作らないリポジトリを持つ——ただアイデアを出し続けて構築し続けるスタイル
  • 作業方法に応じて概念を組み合わせられる柔軟性が鍵
08 リポジトリとは何か

Matt Pocockの「ただのマークダウン」が76% Rust問題コードは実行可能ソフトウェアの上の抽象化か

基調講演で大きく取り上げられたリポジトリの一つが、最終スピーカーのMatt Pocockによるマークダウンフォルダ。中身はただのマークダウンなのに、GitHubの言語内訳表示では「76%がRust」——リポジトリとは何か、コードとは何か、何を保存しているのかを考えさせる。

Jay実行ファイルだけでは足りません。まだたくさんのコードが存在します。今日の大規模ビジネスを支えるJavaや.NETのコード、数十年前のものが今も本番環境で動いているのですから。
09 レガシーコードの現実

数十年前のコードが「今も」本番で修正されているセキュリティ修正・近代化・最適化・バグ修正

ビジネス上重要な大規模システムの多くはJavaや.NETで書かれ、なかには数十年前のものもある。そしてインタビュー中にも、それらの一部が本番環境でバックコーディング（揃えて修正）されている。

  • ツールは多様なコンテキストにまたがって柔軟である必要がある
  • 開発者には選択肢が必要——こだわりや性格のようなものをツールで表現するから
10 ハーネスの解剖

Copilotは最初の「ハーネス」だった —— モデルルーティングとSDK公開ハーネスの根本的な仕事は「モデルの機能を最大限に活用すること」

5〜6年前にリリースされたオリジナルのコーディングアシスタントCopilotは、約4年をかけてハーネスへと進化した。GitHub UniverseではこのCopilotハーネスの詳細が公開され、SDKを使えば誰もが独自のアプリケーションを構築できる。

マルチモデル単一モデルに固定せず複数モデルをサポート
接続先の選択ハーネスのどこに接続するかを選択可能
MCP対応コーディングに必要なツール群と接続
インテリジェンステスト実施・プロンプト取得・成果単位の取り出し
Jay価格も性能も異なるさまざまなモデルを抱えるエンジニアの認知負荷を軽減し、「これを最適化できます」と言えるようにする。最高品質のものを、非常に迅速に、はるかに安価に提供する——改良はこれからも続けます。
11 Fusionとの関係

ハーネスとFusionは「潮の満ち引きのように」流れる開発者の仕事とは、作業方法のオーケストレーション

インタビュアーにとってFusionはハーネスとは何かというメタ抽象化。モデルの選択肢が爆発的に増えた今、どのモデルを選ぶべきかの判断はFusionが担う。

  • ハーネスとFusionは潮の満ち引きのように一緒に流れていく——Jayの整理
  • 開発者の仕事の本質は、すべてのツール・作業方法のオーケストレーション
12 あらゆるサーフェスのCopilot

スマホで始めてデスクトップで続ける —— コンテキストは1か所に集約UI革新かモデル層か？「どちらも必要」

Copilotアプリ、VS Code、github.com——現在はすべて同じハーネスで接続されている。モデルが違っても、リポジトリ・課題・PR・セキュリティ検出結果・メモリ・設定・インテリジェンスエンジンが一か所に集約される。

GitHubのアプローチ

  • スマホで開始→PCで継続、またスマホへ——全コンテキストが追従
  • 別プロバイダーのツール間ではインテリジェンスが統合されない課題を、まさに解決する

イノベーションの全体像

  • ストレージ・コンピューティング・ネットワーク・セキュリティの低レイヤー
  • Git・Actions・AIゲートウェイのプラットフォーム層、ワークフローとサーフェス層——全レイヤーでの進化
13 セキュリティ製品

Code Review Maxと、シークレットを「押す前に」ブロックするAIスキャンコード生成量が増えても品質基準を下げない

より多くのコードを生成する時代だからこそ、品質基準の維持が重要になる。

  • Code Review Max: より深刻度が高く分かりにくいバグの発見を支援
  • AIスキャン: 基調講演のデモでDamienが誤ってシークレットをプッシュした際、リポジトリへの入力すらブロックされた
  • ディープスキャン: 表面的な脆弱性だけでなく高度な脆弱性も検出。ワークフローへの組み込みも可能
14 サプライチェーン防衛

Microsoftセキュリティチーム×GitHubセキュリティチームの連携オープンソースメンテナーとの協働が日常に

  • npmなどパッケージマネージャーの脆弱性制限
  • 侵害されたリポジトリの削除や時間遅延の導入
  • オープンソースのメンテナーとの連携を日々改善——Microsoft全体が投資する最優先事項
Jay多くの作業が進められています。まだやるべきこともたくさんありますが、コミュニティやオープンソースプロジェクト、メンテナーと協力しながら日々改善していきます。
15 OSS議論の核心

「コードが安価になった今、オープンソース依存は20個に減らすべきか？」ホストの挑発的問いに対するJayの答え

ホストの整理: GitHubとOSSサプライチェーンは「コードが高価」という考えの上に成り立っている。しかし今コードは安価になりつつあり、セキュリティレビューも安価かもしれない。ならばすべてをベンダー化するか、すべて書き換えるのが最善では？「私の依存関係は2,000個。全部が脆弱性の表層だ。20個に減らせばいいのでは？」

Jay突飛ではない、よく聞かれる質問です。でも万能薬ではない。2,000個のうち使うのは20個でも、残りの1,980個は維持管理しなければならない——どこにお金・人・時間を投資するかの選択です。オープンソースの価値は企業・開発者・クリエイターにとって今後さらに高まる一方。囲い込まれたガーデンではなく、オープンソースを安全にするという問題を解決しましょう。

17 2027年予測 ②

数千のエージェントと、トークン支出のガバナンスFortune 500が求める「制限を設定する権限」

ソフトウェアの構築・デプロイ・最適化の考え方は1年後にはかなり違って見えるはず。数十・数百ではなく数千のエージェントを管理する日々が来るのかは「わからない」が、適切なプリミティブでプラットフォームを構築し続ける。

  • 支出の可視化: 今週トークンに1,000ドル使った結果、どの機能がリリースされ、どんなROI（コスト削減・エンゲージメント・リテンション・CSAT）に繋がったかを語れるように
  • Fortune 500企業はガバナンスを求める——制限設定のための管理機能を提供
  • 製品内で「このユースケースは別モデルの方が良い」といった推奨を継続提供
