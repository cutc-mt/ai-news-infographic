Claudeのメモ、Dreamingで見比べて直す？

お月見山で迷子になったAI｜Anthropicの「AIの記憶」研究

📅 2026年11月11日　ずんめたラボ

①ポケモン赤でAIが迷子になった

  • ポケモン赤を遊ぶAIがお月見山で迷子に。
  • 原因は自分のメモに目印を書き間違えたこと。
  • メモを直す／直さないを比べると、直した方だけ次の街に到着。
メモを直したら行き先が変わったのだ

②今回のテーマはAIの「記憶」

  • Anthropicが出したAIエージェント記憶の研究を解説。
  • 対象はAIが次の会話のために自分で書いておくメモ。
  • メモを記録と見比べて直す手順Dreamingも登場。
僕のメモも賢くするのだ

③AIの記憶は3種類ある

  • 1つ目：会話の中だけの記憶。会話を閉じたら消える。
  • 2つ目：長い会話の古い部分を短くまとめて置き換える。
  • 3つ目：次の会話まで残して後で読めるメモ。研究で「記憶」と呼ぶのはこれだけ。
残るメモだけが記憶なの

④身近な例はClaude Code

  • パソコンの作業を任せる道具Claude Codeにメモ機能がある。
  • CLAUDE.md：人が書いておく指示のファイル。
  • オートメモリー：Claude Codeが自分で書くメモ。
AIが自分でメモを取るのだ

⑤オートメモリーに書く4つ

  • 使う人の役割。
  • 直された点・進行中の仕事。
  • 作業の場所（ディレクトリ）など4つの項目を書く。
次に開いたときに仕事を思い出すためね

⑥メモは未来への予想

  • AIがメモを書くのはまた役に立つと思うから。つまり予想。
  • 間違えたら→なぜか仮説を立てる→確かめる。
  • 分かったことを次の答え方のルールにして書く。
間違いが次のルールになるのだな

⑦モデルによる書き方の違い

  • Sonnet 4.6：確かめていない推測のメモが散らばる。
  • Opus 4.7：1つの資料にまとめ、確認済みと未確認を分ける。
  • Opus 5：ルールとその根拠も書き、日付も自動で入る。
新しいモデルほど賢く書くのよ

⑧ポケモン赤で見たメモの量

  • Sonnet 3.7（2025年2月）：所持金までメモし225フォルダ・413ファイル。
  • 2026年6月のモデル：9ファイルほど。選んで書くようになった。
  • 所持金や今いる場所は画面を見れば分かる＝メモに不要。
僕ならお金も全部メモするのだ

⑨メモの効果は新しいモデルほど大きい

  • ベンチマーク比較：Sonnet 4.6は0.33→0.36とわずかな伸び。
  • Opus 4.7は0.38→0.70まで大きく伸びる。
  • メモの書き方・読み方が上手くなった効果が数字に。
そのままだとあまり伸びないのだな

⑩メモすべきは「見つけたこと」

  • 書くのは作戦・次の目標・確かめたルールなど自分で見つけたこと。
  • 例：コイキング捕獲で7回連続で外れたあとに書いたメモ。
  • 「3回続けて失敗したらタイミングを変える」。
画面で分かることは書かないのだ

⑪指示は細かく決めない

  • 「メモのフォルダがある」とだけ伝えただけで点が上がった。
  • 書くものを決めすぎ（失敗だけ記録）すると、伸びた分の多くを失う。
  • 何のためのメモかは伝えて、書き方は任せるのが良い。
目的だけ伝えるのがコツよ

⑫メモを読むかもモデルで違う

  • Sonnet 4.6：答える前にメモを読んだのは半分より少ない。
  • 「読んでから」と指示するとほぼ倍に。
  • 新しいSonnet 5は言われなくても10回中9回先に読む。
古いモデルには手順を、新しいモデルには目的だけなのだ

⑬目次＋詳細の2層構造

  • メモは目次と詳しいメモに分かれる。目次がMEMORY.md。
  • 会話の初めに毎回読むのは先頭の200行か25KBまで。その先は読まれない。
  • 目次は1行に1つ。詳細は別メモに分けて必要な時だけ読む。CLAUDE.mdも200行以内が目安。
長い指示ほど守られにくいそうよ

⑭Dreaming（ドリーミング）とは

  • 作業中に書いたメモには間違い・重複・古い情報が混ざる。
  • 作業後にAIにメモと会話記録を見比べさせて直す手順。
  • するのは4つ：①間違い直し②重複まとめとリンク③毎回読むメモを短く④繰り返す間違い探し。人は頼むか時刻を決めて動かす。
AIが夢を見るのだ。僕と同じなのだ

⑮お月見山での結果

  • Claudeはポケモンセンターを目印にしたが、「山を抜けた先」と書き間違えた。
  • 直さない方：センターが先だと思い込み、段差から3回落ちて手前の街まで戻った。
  • Dreamingで直した方：入り口と分かり洞窟を抜けて次の街に到着。
メモを直したら着く街が変わったのだな

⑯WikiづくりにもDreaming

  • 約35万ファイルの社内資料からOpus 5がWikiを作成。
  • Dreamingを2回で正答13%→128回で48%。検索と併用で61%。
  • 合併を題材にした24問では資料をまたぐ判断でWikiが87% vs 検索のみ73%。ただしまとめが元より大きくなることも→定期整理が良い。
回すほどWikiが詳しくなるのだ

⑰公式の見本と簡易版

  • 公式見本：分析役が記録と見比べてメモを直し、印を付けて小さく分ける。
  • 整理役が重複をまとめて目次を仕上げる。記録10件・約12MBで約8ドル・約10分。
  • 簡易版はチャットで頼む：読んでもらう→食い違いを直す→重複をまとめて短い目次に。消す前の一覧を見せてもらう。
元のメモは残しておくのよ

⑱注意点と今日からやる5か条

  • 自動化の注意：記録に仕込まれた指示のリスク→分析役にはメモ編集以外を許可しない。直す前のコピーを残す。回す間隔は用途に合わせる。
  • 5か条：①見て分かることは書かない②目的を1行で、書き方は任せる③日付と確認済みの印を付ける④定期的に見直す⑤毎回読むメモは短く。
  • 見つけたことを書き、書きっぱなしにしない。AIも人も時々の見直しが大事。
確かめたルールだけを書く。身についているじゃない
