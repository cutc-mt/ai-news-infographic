【公式の結論】Claudeモデル使い分け指南

Opus・Fable・Sonnet・Haikuの4種はどこで使うべき？effortの選び方まで

📅 2026年11月11日 / まさおAIじっくり解説ch

①公式ブログの結論: 迷ったらOpus 5.5

  • Anthropic公式ブログ「Which Claude model should you build with?」が使い分けを指南。
  • 推奨の基本は「迷ったらOpus 5.5のeffortミディアムから」。
  • 何も決めていない場合でもまずOpusミディアムで始めて様子を見るのが公式の考え方。
まずOpusミディアム、これが基準ライン

②現行ラインナップ: 一般提供は4モデル

  • 一般提供はHaikuSonnetOpusFableの4種。
  • プラス1つ、プレビュー段階のモデルはプログラム参加者が利用可能。
  • 4モデルとも最近登場したばかりで、Claude環境ではこの4択で選ぶ時代に。
4種類から場面で選ぶのが基本

③Haiku: 大量の単純作業を速く安く

  • 得意分野は分類・ルーティング・タグ付けなどの定型処理。
  • 大量抽出・ファイル検索・ログ読みなどサブエージェント向きの作業にも。
  • 単純で大量のチャット対応など、コストと速度重視の場面で活躍。
安くて速い、量こなす係

④Sonnet: 仕様が決まった作業の主力

  • 仕様通り（仕様通り）の機能実装など範囲の決まったコーディングに十分。
  • 日常の文章作成や繰り返すエージェント作業、資料・スライド作成にも。
  • チャット対話ならロー/ミディアムの低effortでも実用になる速さ。
ゴールを言語化できるなら十分強い

⑤Opus 5.5: 日常開発の基準モデル

  • 複数PRにまたがる複雑な開発もOpus 5.5で対応するのが公式推奨。
  • コンピュータユースも強力ポイント。まずミディアムから試すのが定石。
  • 簡単なパフォーマンス最適化でもOpusが欲しくなる場面がSonnetにはある。
コスパのいい頼れる主力

⑥Fable 5.2: 最難関と長時間無人実行

  • Opusで足りない時、最難関の技術プロダクト開発でFableへ。
  • 長時間の無人実行（ロングラン）はFable 5.2が公式推奨。
  • 大規模リファクタ・移行、アーキテクチャ設計、ディープリサーチにも。
未知に向き合う最上位モデル

⑦effortとは: 考え方の量を調整

  • 同じモデルでもロー/ミディアム/ハイ/マックスで頑張り具合が変わる。
  • effortを上げるとより長く考え、ツールが増え、自己検証も増える。
  • その分時間とトークンは消費。マックスはコストもしっかりかかる。
細かく調整できる今、意識したい設定

⑧鉄則: モデルより先にeffortを動かす

  • 公式の方針は「いきなりモデルを変えず、まずeffortを動かして試す」。
  • 低いeffort（ロー/ミディアム）で試して、足りなければ上げる。
  • 実例: OpusハイでダメならFableミディアム→ハイへ段階的に移行。
まずeffort、次にモデル

⑨effortの限界: 能力の天井は超えない

  • effortを上げてもそのモデルの知識・能力の限界を超えるわけではない。
  • 限界を感じたらモデルを上げる:Sonnet→Opus→Fableの順。
  • ミディアムとハイの間に壁を感じる、という体感の声も。
頑張りと賢さは別物

⑩単価の感覚: 段階的に約2倍ずつ

  • Haikuを基準にするとSonnet→Opus、Opus→Fableでそれぞれ約2倍ずつ上昇。
  • OpusはFable比で入出力トークン単価が約半分。Claude CodeではOpusのコスパが良いと評判。
  • Fableは単価が高く、Claude Codeで使うと枠が想定より早く溶ける場面も。
最上位はコストも最上位

⑪共通スペック: 1Mコンテキスト・画像入力

  • 全モデル1Mコンテキスト・最大出力128Kで統一。
  • 画像入力にも対応し、マルチモーダルな作業を投入可能。
  • キャッシュリードは100Kまでは安価。OpusとFableのキャッシュ単価は同水準。
スペックより中身で選ぶ時代

⑫既定effort: APIとClaude Codeで違う

  • API既定: Haiku=ミディアム、Sonnet=ハイ、Opus=ミディアム、Fable=ハイ。
  • Claude Code上ではSonnetとFableはミディアム既定に変化。
  • OpusとFableにはファストモード（約2.5倍速）も存在。トークン単価は高め。
既定値を知っておくだけでも得

⑬長時間無人実行ほどFableの差が出る

  • 10分で終わるループならモデル差は広がりにくいが、1時間・3時間と長くなると判断質の差が累積。
  • 察しの良さやメタ認知の深さが、ロングランのドリフト加減を左右。
  • OS自作やPython→Rust移行のような大きい移行ほど、上質な判断が効いてくる。
放っておく時間ほどモデル選択が効く

⑭タスク別使い分け早見表

  • 日常チャット・簡単な質問→Sonnet低effortやHaikuミディアム。
  • 資料・スライド作成、繰り返し作業→Sonnetミディアム中心、不足ならハイ。
  • 複雑開発・コンピュータユース→Opus 5.5ミディアムから。
  • 大規模移行・無人長時間実行→Fable 5.2。
タスクの形でモデルを選ぶ

⑮モデルは混ぜて使うのが当たり前

  • 作業の区切りでモデルを切り替えるのが基本の運用。
  • サブエージェント設定の中でモデルを個別指定し、下位モデルに安く任せる。
  • 1日にできる決定の数は有限。じっくり考える場面には上位モデルを集中させる戦略も。
使い分けてこそコスパ最大化

⑯/advisorとopusplanで相談する

  • Claude Codeの/advisor: Opusで作業しつつ、気になるところだけFableに相談。
  • /opusplanでは逆方向の相談も可能。
  • 主力は安いモデル、相談役に最上位、という賢い組み合わせ。
高いモデルは顧問として使う

⑰切替とコストのコツ

  • モデルを切り替えた直後のターンは会話全体の書き直しが入り高くつく。
  • /compactで会話を小さくしてから切替ると節約。
  • コストは1タスクあたりで考える。100K超の大量処理では単価感覚が変わるので注意。
切替のタイミングもお金に関わる

⑱まとめ: 公式結論に従って使い倒そう

  • 基本はOpus 5.5+effortミディアム。まずeffortを動かし、限界ならモデルを上げる。
  • 決まった作業はSonnet、大量の単純作業はHaiku、最難関・無人長時間はFable 5.2。
  • 単価・既定effort・タスク別推奨の詳細は元動画と公式ブログで確認を。
