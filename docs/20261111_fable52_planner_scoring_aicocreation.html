Claude Fable 5.2 徹底検証 / AI共創イノベーション

Claude Fable 5.2に難問を解かせてスコアリング！ 使い方はプランナー、そしてコンテキストの重要性を解説

ワンダー佐藤（佐藤源彦）が科学的タスクの難問をFable 5.2に多数解かせ、Opus 5.5のレビューAIでスコア化。1つの作用から4つの穴を見抜く「構想力」の一方で、安定性・厳密性の弱さも浮き彫りに。Seam=Opus 5.5、Faro=Fable 5.2、Chordum=GPT-6.1 Solの3AI比較から「Fableで計画、Opus/Sonnetで実行」のサイクルとプロンプト＆コンテキストエンジニアリングの重要性まで図解します。

01
今回の検証

1日かけて難問を解かせてスコア化科学的タスクを何問も解かせて違いを見る

最近のAIはどれも強くなっているため、1〜2問では差が見えません。そこで科学的なタスクの難問を何問もFable 5.2に解かせ、その結果をスコア化。改めて「文脈が大事」という結論と、Fable 5.2の役割を探ります。

  • 出題は科学的タスク中心、とにかく数をこなして差を可視化
  • 評価はOpus 5.5のレビューAIに依頼
  • 分かった最大の特徴はスケールのでかさ＝構想力
何問も解かないと差が出ない、ってホントだね。1問だけじゃ「みんな正解」で終わっちゃうもんね！
02
OpusレビューAIの評価

「全体を見る力」が突出何も指定していない場所から4つの穴を発見

OpusのレビューAIに「Fable 5.2をどう評価する?」と聞いたところ、全体を見る力が抜けている（突出している）との評価。何も指定していない部分から4つの穴を見つけ、1つの作用からそれらを塞ぐでかい構想を打ち出しました。

  • 指示していない領域から穴を4つつきとめ、塞ぐ構想まで提示
  • 探索力も強いが、探索させるとスコアはやや落ちる
  • 結論: プランニングの力が最強 — 頭（ヘッド）として使うのが最適
03
構想力

チームの誰も描かなかった「1枚の地図」精鋭揃いのチームで、この地図を描けたのはFableだけ

「この構想力は、チームの誰もこの1枚の地図は描いていませんでした」— 精鋭揃いのメンバーでも、でかい地図を描くのはFable 5.2の得意分野。手足（実行）も強いが、全体を見る頭脳としての起用がベストという評価に。

精鋭ぞろいのチームでも描けなかった地図を描いちゃうって、ちょっとロマンチックだね〜！
04
弱み

安定性と厳密性はいまいちSol・Astraほどの精度は出ない

一方で弱さも明らかに。安定性がなく、GPT-AstraやSolのような精度の高さはないのが従来のFable/Opus系と同じ傾向。細かく深く掘るのは得意ではなく、厳密性が足りず最終的な解への収束が苦手です。

  • SolやAストラに指摘されて間違いを直させる運用が現実的
  • だからこそ「でっかく描く」仕事に投げるのが正解
05
Gemini 4 Argon との比較

穴のつき方が違う: Argonは「マニアックな1つ」、Fableは「ど真ん中の4つ」着眼点の違いと、圧倒的なスケール差

同じく穴をつくのが得意なGemini 4 Argonと比較すると、Argonも穴をつくのがうまいものの1つにとどまるのに対し、Fableは4つの穴をつき、さらにその穴を塞ぐ構想まで持っています。

視点Gemini 4 ArgonClaude Fable 5.2
穴の数1つ（深い）4つ（広い）
着眼点結構マニアックなところを「え、こんなところ見るの?」とついてくるどちらかというとど真ん中の要点をつく
構想のスケールFableには全然叶わない圧倒的に大きい — 穴を塞ぐ構想まで出せる
Argonは「誰も気づかない穴」、Fableは「みんなが見てるはずなのに取りこぼした穴」って感じかな？
06
パラメータ考察

API料金2倍 → パラメータはMythos系が大きいはず知識量＝視野の広さ＝プランニング力

Fableの方がAPI料金は2倍高い。比例するとは限らないものの、Mythos系のFableはパラメータが大きいだろうと推測されます。穴をつく力は元々Mythosが強かった証拠で、コーディング能力を上げたらサイバーセキュリティ能力も上がり、穴をつくのが強くなったと分析。

  • パラメータの大きさ ≒ 知識の量 ≒ 視野の広さ
  • そこがプランニング力に直結しているはず
07
能力の正体

問題定義能力 × 問題解決能力穴を見つけ、塞ぐ構想を出せる

ここで言えるのは問題定義能力。さらにその穴を塞ぐ構想も出せる、つまり問題解決能力まで備えているのがFable 5.2の強さの本質です。

08
役割分担

探索と実務はOpus / Solの領域現実的な部分は実務向けに訓練されている

探索を進めるとOpusの強いところが出てきます。Opusは実務的・現実的な部分を想定して訓練されており、ハーネス的な強さも。Fableも手足（実行）はベンチマーク上強いものの、実務はOpusやSonnetに任せるのが現実的です。

  • 実務・実行 → Opus 5.5 / Sonnet
  • 正確さを足したい → Solを噛ませる
  • Fableは大きな構想・計画・抽象的領域を担当
09
ベストプラクティス

「Fableで計画 → Opus/Sonnetで実行 → 成果をFableへ戻す」サイクルリーダー（頭）としてFableを据える使い方

Fable 5.2をリーダー・抽象的領域の担当とし、具体的な実行をOpus/Sonnetが担い、その成果をもう一度Fableに戻して構想に反映する。このサイクルを繰り返すのが最良の使い方だと結論づけています。

1
Fable 5.2 が計画 — 全体像・大きな構想・リーダー役で方向を示す
2
Opus 5.5 / Sonnet が実行 — 実務的・具体的なタスクを担当
3
成果をFableへ戻す — 計画にフィードバックして構想を更新、サイクルを繰り返す
頭でっかちじゃなくて、「頭がでっかいチーム」って感じ？ Fableが地図を持ってて、久しぶりに全員で同じ地図を見れるんだね！

公平な条件

エフォートは全て「ミドル」で揃えてスコアリングExtra High → ミドルでも結果はほぼ不変

最初はGPT-6.1 SolだけエフォートExtra Highで運用していましたが、条件を揃えるために全てミドルに統一。何回か試してもスコアはほぼ変わらず、条件は大体同じという公正な比較になりました。

  • Fable・Opus・Sol 全てエフォート＝ミドルで統一
  • Solの得点はミドルに下げても落ちない（底堅い）
  • Fableは文脈がない分、スコアが落ちる場面も

同じ課題・同じコンテキストで3者が提出した回答を、パラメータを設定して合計点を出し、表形式で見やすく比較。結果の要点は以下のとおりです。

逆転現象

「新しい発見」でレビュー役Solが1位Fable・Opusが低いという逆転が発生

本来なら探索担当のはずのFable/Opusが低く、レビュー役のChordum（Sol）が新しい発見で1位という逆転現象が発生。Solは他のAIよりなぜか探索が強く、文脈の与え方や設計の差が効いていると分析されます。

採点する先生が、生徒より発見しちゃうってどういうこと!? …あ、これが「コンテキストの力」なんだね。
14
核心

ベンチマーク最強なのに、なぜスコアが違う？答えは「文脈が乗っていない」

外部ベンチマークではFable 5.2が圧倒的に高いのに、今回の合計点ではOpusとSolが圧倒。この違いはコンテキストの量です。Fableにも文脈は与えているものの、OpusやSolほどではなく、そこまでの深さが出ないのがスコアに現れました。

  • モデルがいくら強くてもコンテキストとプロンプト次第で結果が激変
  • 今回は探索前提。構想（プランナー）ならFableが最強のはず

AIの育て方

名前をつけると履歴が乗って強くなるラベル付けとコンテキストの集中

Seam・Faro・Chordumのように名前をつけると会話履歴として文脈が乗り、強くなる体验を繰り返しています。AIは「設計する」ことと「育成する」こと — ラベルをつけてコンテキストを集中させる作業が大切。誰がやったか後から分かる利点も。

  • 名前・ラベル → 履歴と役割が定着
  • コンテキストを集中 → 性能が伸びる
17
実用プロンプト

「差分をスコアリングして」が超便利違いだけを抽出して採点させる

検証で重宝したのが「差分をスコアリングして」というプロンプト。3者の回答の違い（差分）だけを抽出して採点してくれるため、比較検証の記録づくりに欠かせません。

  • 3者の記録をレビューAIに戻して差分のみ採点
  • パラメータを設定して合計点を表形式で自動整列
「差分だけ採点して」って言うだけで、先生が見やすい成績表を作ってくれるんだね。覚えておこ〜！
18
結論

Fable 5.2は「プランナー」として使え構想力No.1、探索の不安定さは他AIで補完

最終結論: Fable 5.2は不安定さはあるものの構想力が最強。探索だけだと不安定な部分を補う必要があり、実務はOpus、正確性はSolを噛ませる分担がベスト。次回からはFableをリーダーに据えるだけでなく、高い探索力も試していく予定です。

  • 構想・計画 → Fable 5.2（でっかく描く）
  • 実務・実行 → Opus / Sonnet
  • 正確さ・深さ → GPT-6.1 Sol
