Agent GUI「Rex」はかなりの完成度

Mitchell Hashimoto氏の新会社Superlogicalが初製品のターミナル「Rex」をβ公開。ターミナルとマルチプレクサを一体化し、コーディングエージェントが“住める”設計が注目を集めています。18カードでまとめて読めます。

CARD 01

作者はMitchell Hashimoto氏

Ghosttyの生みの親。その前にはVagrantやTerraformなど、開発者の多くが一度は使ったことのあるツールを世に出してきた人物です。

CARD 02

新会社Superlogicalと初製品

同氏が立ち上げた新会社Superlogical。そのファーストプロダクトがターミナル「Rex」です。動画では実際にMacにインストールして使い込んだ印象が語られています。

CARD 03

RexはGhosttyの改名ではない

Ghosttyは非営利プロジェクトとしてそのまま継続。Rexはまったく別の商用製品です。「Ghosttyの有料版」と混同しないよう、まずここを押さえるのが大事だと強調されています。

CARD 04

共通エンジン libghosty

RexはGhosttyの描画とターミナルエミュレーションを支えるMITライセンスのライブラリ「libghosty」を共有。だから文字描画やターミナルの挙動はGhostty使いならすぐ馴染む感覚です。

CARD 05

ターミナル＋マルチプレクサ一体型

tmuxのようなマルチプレクサ機能をアプリ自体に内蔵。他のターミナルの中で動かすのではなく、それ単体で完結するのが設計のポイントです。

CARD 06

サーバ／クライアント構造

バックグラウンドのサーバがシェルとプロセスをすべて管理し、Rexアプリはそのクライアント。アプリを完全に終了してもプログラムは動き続け、再び開けば再アタッチできます。

CARD 07

用語整理：session / window / block

  • session ＝ プロジェクト単位
  • window ＝ いわゆるタブ
  • block ＝ ペイン（現状はターミナル）

CLIで操作する際、この呼び方が至るところに出てきます。Warpの「blocks」とは別物です。

CARD 08

βは招待制・macOS限定

superlogical.comのウェイトリストに参加すると招待が届きます。アプリは「Rex beta」v0.1.0としてインストール。サーバはLinux／Windows版も存在し、他プラットフォームのクライアントも準備中です。

CARD 09

ブラウザのようなUI

  • タブバーを上部 or 左右サイドバーに配置可能
  • コマンドパレットは Ctrl+Shift+P 風のショートカット
  • ダーク／ライト約40テーマを内蔵
  • GhosttyとiTermの配色をテーマとしてインポート可能
CARD 10

設定はLuaファイルひとつ

設定は ~/.config/rex/init.lua。初回起動時に自動生成され、コメントには既存環境のキーバインド移行は不要だったと記録されていました。rex.bindでtmux風のコード（B → C など）も登録できます。

編集後は config check で検証し rex config reload で反映。ファイル監視はされないのでリロードは手動ですが、デフォルトのままでも不自由しなかったとのこと。

CARD 11

CLIが主役：rex ls / new / split

同梱の rex コマンドでアプリ全体を操作できます。rex new で新規セッション、rex split --split=right＋比率＋コマンドでペイン分割。分割は体感0.1秒ほどで一瞬でした。

CARD 12

他のペインを操る

  • rex send … 任意のターミナルに文字を入力
  • rex send-key … Enterなどのキーを送信
  • rex capture … 画面とスクロールバックを出力
  • --format=html なら色付きHTMLで取得
CARD 13

rex run --wait が便利

コマンドを新しいタブで実行し、終了を待って終了コードを返してくれるモード。exit 3を返すコマンドで試したら正しく「exit status 3」が戻りました。Rexのターミナルをスクリプトから“ジョブ”として扱えます。

CARD 14

自動化も：events / do

rex events --json はサーバ上で起きるすべての出来事をストリーミング。rex do はアクションやLuaスクリプトの実行まで可能。ほぼ全コマンドがJSON出力に対応しており、スクリプトとの相性が抜群です。

CARD 15

AIは内蔵しない——代わりにエージェントが“住める”

RexにはAIアシスタントが入っていません。代わりに、同氏が考案したプロトコルOSC7501で、プログラムはidle／working／done／blocked／erroredの状態をターミナルに伝えられます。blockedのときは権限待ち・質問待ち・ログイン待ちのどれかまで通知され、Claude Codeはすでに対応済み。どのセッションが自分を必要としているか、タブを行き来しなくても分かります。状態は rex events や rex block call program status でも読み取り可能です。

CARD 16

rex skill setup ワンコマンド

実行1回でエージェント側にスキルとスタートフックをインストール。Claude Code、Codex、Open Code、piに対応しています。セットアップ後、エージェントは自分のセッションとペインを認識し、diffを新タブで開いたり、devサーバーを分割して立ち上げ、テスト結果を読み戻したりできます。

CARD 17

リモート接続：Tailscale内蔵

サーバにTailscaleが組み込まれており、rex server tailscale on で有効化すると、同じテールネット上の他デバイスから自分のセッションにアクセスできます。デフォルトはオフ＆ローカルのみという設計は適切と評価。同氏自身も自分のサーバでSSHの代わりに使っているそうです。ただし両端にRexが必要なので、SSHを全面的に置き換えるものではありません。

CARD 18 / VERDICT

結論：年内最注目のターミナル、でも急がなくていい

永続セッションCLIが最高に使いやすい軽快でネイティブ現在全機能が無料招待制・macOS限定βオープンソースか未確定tmux設定の移行なし・コピー機能も未実装再起動でプロセス消失

「1日中ターミナルで過ごし、コーディングエージェントを走らせ、セッションを失った苦い経験がある人」には今年最も面白いターミナル。永続セッションとCLI＋スキルの設計はまさにMitchell流の硬派なエンジニアリング。ただしライセンスも料金も未確定の超早期βなので、今すぐ全ワークフローを移すのは時期尚早。提案はこうです——招待が来たらGhosttyの隣に置き、エージェント用セッション専用として使う。tmuxや既存環境に満足しているなら、急ぐ必要はありません。
