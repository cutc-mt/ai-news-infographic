META ASTERIX OPEN SOURCE

MetaがOSS化した「Asterix」——コーディングエージェントと人間が共有するデザインシステムでUIの質を変える

動画：「Meta just opensourced a 100-File Skill Library for Better UI Designs!」
チャンネル：AI Code King（公開：2026-11-13）／ YouTubeで視聴する
Metaが8年かけて育て、社内13,000アプリを支えるデザインシステム「Asterix」をMITライセンスで公開。ポイントは「あなたのコーディングエージェントが、あなたと同じドキュメントを同じように使う」設計です。150以上のReactコンポーネント、テンプレート、CLI is the docsという思想まで、主要18トピックをカード形式で整理します。
01 概要

Asterixとは —— エージェントと人間が「同じシステム」を使う

Metaがオープンソース化したデザインシステムAsterix。売りは見栄えの良いReactコンポーネント集ではなく、あなたとコーディングエージェントが同じドキュメントから同じ方法で使えるよう設計されている点です。AIにUIを作らせると毎回バラバラな結果になる問題への一つの答えとなっています。

エージェントに「当て推量」ではなく「調べ方」を与える設計
02 経歴

新規プロジェクトではない —— 8年・13,000アプリの実績

AsterixはMeta社内で8年かけて成長し、同社で最大のデザインシステムとなりました。13,000以上の社内アプリを支えており、2026年6月にベータ公開、現在GitHubで約18,700スターを獲得。ライセンスはMITで自由に利用できます。

実験ではなく、巨大企業の実働システムがそのまま公開された
03 問題意識

エージェント製UIの宿病 —— divとランダムhexの山

今日エージェントにUIを作らせると、大体いつも同じものが返ってきます。divの塊、ランダムな16進カラーコード、適当なTailwindクラス、そして「一応動くが何にも属していない」レイアウト。Asterixはエージェントに本物のシステムと検索手段を与えることで、この問題を解決します。

「それっぽいUI」から「システムに属するUI」へ
04 コンポーネント

150以上の型付きReactコンポーネント

READMEによると150以上、実際にインストールしたCLIでは174個のコンポーネントがリストされます。いずれもアクセシビリティ対応済みで完全なTypeScript型付き。アプリシェル、ダイアログ、テーブル、フォーム、デートピッカーなど定番が揃っています。

型情報があるので、エージェントが存在しないpropsを発明しない
05 テンプレート

ページ＆ブロックテンプレート —— 完成レイアウトをそのまま落とす

コンポーネントに加え、ダッシュボード・ログイン・設定ページ・AIチャット画面などのフルレイアウトであるページテンプレートとブロックテンプレートを同梱。そのままアプリにドロップすれば、一発で整った画面が手に入ります。

「積み木から組む」より「完成図を置いて削る」方が速い
06 内部技術

Stylex製なのにStylexを触らなくていい

内部はMeta製CSS-in-JSのStylexで書かれていますが、利用者は触る必要なし。ビルド済みCSSファイルを2つimportするだけで、ビルドプラグインもPostCSS設定もBabel設定も不要です。

導入コストを最小化した設計がうれしい
07 カスタマイズ

見た目の変更は className で —— Tailwindとも共存

見た目を変えたいときはclassNameを渡すだけ。中身はTailwind、CSS Modules、素のCSSなどプロジェクトが既に使っているもの何でもOK。システムと既存のスタイリング手法を無理なく併用できます。

ラッパーやフォークをしなくても自分のブランドに寄せられる
08 テーマ

テーマはCSS変数の集合 —— 7テーマ＋ダークモード

テーマはCSS変数のセットとして定義されるため、コンポーネントをフォーク・ラップせずにシステム全体を自社ブランド風にできます。現在neutral・butter・chocolate・stone・gothic・Y2Kなど7テーマを用意し、ダークモードも組み込み済み。

変数を差し替えるだけで全コンポーネントが追従
09 フルコントロール

Swizzle —— 必要な部品だけソースを引き取る

コンポーネントを完全に制御したいときはSwizzleコマンドでそのソースをプロジェクト内にコピーし、以降は自分のものに。shadcn方式に似ていますが、変えたい部品だけ引き取り、残りはupstreamの修正を受け取り続けられるのが特徴です。

全部取り込むか、一部だけ取り込むか選べる
10 中核思想

「CLI is the docs」—— ドキュメントが同期崩れしない仕組み

Asterixの根幹はCLIこそがドキュメントという思想。ドキュメントサイトはCLIから読み込む（逆ではない）ため、ドキュメントのコピーは1つだけでずれようがありません。ブログ記事「The Best CLI is One You Never Run（最高のCLIは自分で走らせないもの）」が方針を物語ります。

CLIを走らせるのはエージェント、人間はその成果を見るだけ
11 セットアップ

initコマンド —— エージェントのルールファイルに直接書き込む

最初のコマンドはinit。Claude・Cursor・Codexなど使用エージェントを指定すると、その指示ファイル（ClaudeならCLAUDE.md）に管理ブロックを書き込みます。「各ページはテンプレートから始める」「生のdivを書かない」「hexやピクセル値を直書きしない」「コンポーネントは使用前に調べる」「終えたらdoctorを実行」というルールです。

注意：CLI導入前のnpx asterixは別パッケージ。正式名で実行すること
12 buildコマンド

平文の要望 → コード生成ではなく「テンプレート選択」

buildコマンドに「SaaSアプリの設定ページが欲しい」など平文で伝えると、コードを生成する代わりに最も近いページテンプレートを選び、埋めるブロックと残りのコンポーネントを提案します。Metaの理屈は「AIは模倣物なので、模倣する良いお手本を与えた」——納得の考え方です。

生成の当たり外れではなく、選択の確度で品質を作る
13 実演

新規Viteアプリで数分で設定ページが完成

動画ではVite + Reactの新規アプリにAsterix本体・neutralテーマ・Stylex・CLIを導入。theme add neutralでテーマを追加し、メインファイルに15行ほど書いてdevサーバーを起動すると、サイドバー・フォーム・トグル・適切な余白を持つフルの設定ページが完成。所要時間は数分、その大半はnpm installだったとのこと。

templateコマンドで設定画面テンプレートをそのままコピー
14 検索・参照

search / props / manifest —— エージェントのための参照コマンド

コンポーネント・フック・ドキュメント・テンプレート・テーマを1つのランキング付きリストで横断検索でき、個別コンポーネントのprops（正確な型・バリアント・デフォルト値）も参照可能。全コマンドは安定したエラーコード付きのJSON出力と、トークンを削減するdense modeに対応し、CLI全体を記述するmanifestコマンド（「CLI向けのOpenAPI spec」）もあります。

出力が機械向けに設計されているのがエージェント前提の証拠
15 MCP連携

ホスト型MCPサーバー ＆ llms.txt ＆ スキル配布

CLIを使わない場合はホスト型MCPサーバーを利用可能。Claude Codeに1コマンドで追加すると、同じドキュメントを引くsearch と get の2ツールがエージェントに与えられます。サイトにはllms.txtも用意され、CLIをグローバルに入れてinit userを実行れば、Asterixスキルがホームフォルダに書き込まれ各エージェントへリンク。開くすべてのプロジェクトがAsterixを知っている状態になります。

プロジェクトごとの設定不要にできるのが強い
16 検証

vibe tests —— 毎晩エージェントにビルドさせて採点する

リポジトリにはvibe testsというフォルダがあります。毎晩同じUIプロンプトをエージェントに与え、Asterix単体／Asterix＋Tailwind／shadcn＋Tailwind／素のHTMLの4方式でビルドし、別のjudgeエージェントが採点。調子の良い夜はAsterix 98点、shadcn 95点、素HTML 82点。悪い夜にはAsterixが77点に落ちた記録も公開し、全記録ではshadcnが最多勝と正直に明かしています。

悪いチャートまで出す誠実さが unpopular で逆に信頼できる
17 注意点

β版の制約 —— バージョン・Node・バンドルサイズ

まだベータ（v0.7）でほぼ毎日リリースがあり、React 19以降・Node 22.13以降が必要（React 18アプリは対象外）。メンテ宣言済みはneutralテーマのみで他テーマは別パッケージ。chartsはCanaryチャネルのみ、Swizzle後はビルドにStylexコンパイラが必要。エージェントルール（div禁止・hex直書き禁止）はTailwind全盛チームには厳しい場合があり、デモ1ページでgzip前およそ600KBのJSが出ました。

採用前に要件とトレードオフを確認
18 結論

使うべきか —— React 19新規＋エージェント大量開発なら「試す価値あり」

React 19の新規アプリでエージェントにUIを大量に書かせるなら、テンプレート・buildコマンド・CLI is the docsの思想は1ページ目から効果を実感できるとの評価。一方、shadcnやMUIで成熟したアプリを持つなら、ベータ脱出まで待ち、まずサイドプロジェクトで試すのが現実的。総評は「かなりイケてる」でした。

まず小さな新規プロジェクトで手触りを確かめるのがおすすめ
