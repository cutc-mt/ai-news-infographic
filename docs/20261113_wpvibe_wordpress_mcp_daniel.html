【WPVibe検証】WordPressをダッシュボード開かずAIに任せる

WordPress MCPプラグイン「WPVibe」をChatGPTとClaudeの両方に接続／ヘッダー色の変更・復元から記事下書き作成まで実機テスト／危ない操作の前の承認プロセスも確認

📅 2026年11月13日 / Daniel | Tech & Data / スポンサー提供レビュー

①WPVibeとは：WordPress×AIの架け橋

  • WordPressのダッシュボードを開かずにサイト全体を管理する——AIアシスタントに頼むだけで、インターフェースの変更やプラグイン管理・修正ができるプラグインがWPVibe。
  • 普段使っているChatGPTやClaudeとWordPressサイトを連携させる仕組み。「設定はどれくらい簡単か？ 本当にサイトを更新できるのか？」を動画で検証。
  • もう一つの焦点は変更を反映させる前の承認プロセス。AIに何を許して、何には確認を挟むのか。
「お願い」だけでサイトが直る未来が、もう普通に動く

②仕組み：MCPでAIがWordPressを操作

  • MCP（Model Context Protocol）を通じて、AIアシスタントがWordPressサイトを操作できるようにするのが基本的な構成。
  • WPVibeはサイトとChatGPT／Claudeをつなぐ架け橋。接続すれば、対話を通じてアシスタントが情報の取得と対応可能なタスクの実行ができる。
  • 今回のテスト計画はシンプル：①サイトから情報取得 → ②実際に変更を加える → ③元に戻す → ④取り返しのつかない操作の挙動。設定に時間はかけず、準備後の動きに注目。
面白いのは「準備が整った後」——設定自体は数分で終わる

③ChatGPTへの接続手順

  • まずプラグインディレクトリを開いてWPVibeを追加。追加したらサインインし、自分のサイトに接続するよう指示。
  • これで接続完了。プラグイン側が接続の詳細を返してくれるので、ちゃんとつながったことをその場で確認可能。
  • 注意点が一つ：ChatGPTは会話（チャット）ごとに個別に接続する必要がある。新しいチャットを始めるたびに再度追加し直すこと。
「チャット毎に再接続」だけは唯一の面倒ポイント

④接続テスト：プラグイン一覧を取得

  • すべてが正しく機能しているか確認するため、サイトにインストールされているプラグインを表示してとWPVibeに依頼。
  • 結果、AIがWordPressから実際の情報を取得できていることを確認。読み取り（取得）系の操作はこの時点で問題なし。
  • 接続が確認できたので、次は実際にサイトへ変更を加えるテストへ進む。
プラグイン名とバージョンのリストがそのまま返ってくる

⑤テスト1：ヘッダー背景色を変更

  • 最初は簡単なタスクから。ヘッダーの背景色を変えてとChatGPTにリクエスト。まず現在のデザインを確認してから依頼。
  • アシスタントが編集を適用すると、メニューの文字色も自動で更新。見た目の整合性まで気を回してくれる。
  • ウェブサイトを更新して結果を確認すると——サイトのヘッダーがきちんと更新されている。会話だけでデザイン変更が完結。
「反映して」の一言で、数秒後に本番サイトが変わる

⑥テスト2：変更を元に戻す

  • 次に、さきほどの変更を元に戻すテスト。簡単なプロンプトを入力して、数秒待つだけ。
  • アシスタントがリクエストを適用した後、ページを再更新すればヘッダーが元の見た目に復元されていた。
  • 「調整 → 会話で元に戻す」まで一通り通せたので、これは良い最初のテストだった、とDanielさん。
やり直しも会話完結——CSSを手で書き直す必要なし

⑦間に挟まる一言：高評価のお願い

  • Danielさんより：「私は退屈ではない楽しいコンテンツ作りを心がけています」——楽しんでもらえたら高評価とチャンネル登録を、とのこと。
  • 動画の概要欄に役立つリンクを掲載。プラグインのインストールリンクもそこから。
  • さて本題再開——続いて同じWordPressサイトにClaudeを接続して、同じことができるか見ていく。
紹介リンク経由のスポンサー提供レビューである点も明示

⑧Claudeへの接続手順

  • 手順はほぼ同じ。コネクタ（Connectors）ディレクトリを開き、WPVibeを見つけてアカウントに追加。
  • あとはAIに「サイトとの接続を確立して」と依頼するだけ。接続完了後、ChatGPT同様にインストール済みプラグインの一覧を確認。
  • プラグイン名とバージョンが記載されたリストが表示され、問題なく接続完了。両アシスタントの準備が整った。
ディレクトリから追加 → 接続指示、の2ステップ

⑨ChatGPTとClaudeの決定的な違い

  • ChatGPT：チャットごとにWPVibeを追加し直す必要がある（会話単位の接続）。
  • Claude：コネクタがアカウントに追加されるため、会話をまたいで使い回せる。
  • 頻繁にWordPressをAIで操作したいなら、この接続の持続性の差は地味に大きい使い勝手の分かれ目。
「毎回つなぐ」か「一度つなぎっぱなし」か——Claudeに軍配

⑩Claudeでも同じテストを実行

  • 同じタスクをClaudeで実行。ヘッダーのスタイルを特定し、リクエストされた更新を適用してくれる。
  • サイトを確認するとヘッダーとメニューの色が変更済み。そして「戻して」の指示ではわずか数秒で元に復元。
  • ChatGPT／Claudeのどちらも、サイトへの変更と復元を問題なくこなすことが確認できた。
2大アシスタントで同じ操作が同じように通る

⑪テスト3：ランディングページを作らせる

  • もっと大きなことに挑戦。「AIInsight Newsletters」というランディングページを作成するようAIに依頼する。
  • Claudeはサイトのテーマに合わせて作業し、下書きとして保存。つまり勝手に公開されることはない。
  • 完成後、アシスタントが結果をプレビューするためのリンクを提供。既存の色やテーマ要素を使ったページが生成されていた。
エディタを開いて手作業で組む必要がまるでなかった

⑫テスト4：画像3枚から記事下書きを作成

  • 次は実用的なケース。3枚の画像を渡して投稿を作成するようClaudeに依頼。
  • ここで判明した制約：AIはチャットから直接ファイルをアップロードできない。代わりに画像を追加できるパネルを開いてくれるので、そこ経由で追加して作業を継続。
  • Claudeが画像をメディアライブラリへ移動し、下書き記事を作成。各記事に対応する画像が含まれていた。
アップロードだけ人間、執筆と組み立てはAI——いい分担

⑬出来上がった下書きのクオリティ

  • 生成された記事はサイトの既存スタイルや色に沿った見た目。テーマと乖離したデザインにはならない。
  • 各記事にはカテゴリーも自動で割り当て済み。投稿の仕分け作業も丸ごとスキップできる。
  • 自分で手動で投稿を作る代わりに、下書きを確認して、準備ができたら公開するだけの運用に変わる。
「コンテンツの準備」までAIが担うようになった

⑭テスト5：取り返しのつかない操作はどうなる？

  • いよいよ本番の見せ場。ChatGPTにテストページを作成させ、それをゴミ箱へ移動させる。
  • ゴミ箱移動は復元可能なため承認は不要——そのまま素直に実行された。
  • そこでAIにこのページを「完全に削除」するよう指示してみる。さあ、どうなるか。
「戻せる操作」と「戻せない操作」で挙動が変わる設計

⑮承認プロセスが作動した瞬間

  • 完全削除の指示に対し、WPVibeが動作を停止し、続行前に確認を求めてきた——これが見たかった光景。
  • 操作を承認すると初めて実行。リストを更新して確認すると、ページは確かに削除されていた。
  • 元に戻せない操作の前には許可を求めてくることが実証された。これがWPVibeの安全装置。
危ない一手はAIが勝手に打たず、人間の指先待ち

⑯検証結果のまとめ

  • ①情報取得：インストール済みプラグインの一覧をAIが取得。
  • ②デザイン編集と復元：ヘッダー色の変更・メニュー文字色の更新・元に戻すまで会話で完結。
  • ③コンテンツ作成：ランディングページの下書き生成、画像3枚からのカテゴリー付き下書き記事を作成。
  • ④安全装置：完全削除などの不可逆な操作では実行前に承認を要求。
情報取得・デザイン・コンテンツ・安全性、全部クリア

⑰コントロール権は人間に残る

  • WPVibeは単なる情報の取得や簡単なデザイン調整以上のことができる。コンテンツ作成やWordPressタスク全般を支援する。
  • それでいて、何を公開し、何を完全に削除するかというコントロール権はあなたに残る——これが設計思想の核。
  • プラグインは動画説明欄のリンクからインストール可能。スポンサー提供のレビューとのこと。
AIに任せきりにせず、最後の鍵は自分が握る

⑱結論：WordPress運用は「対話」で変わる

  • ダッシュボードを開かず、「お願い」だけでサイトの情報取得・デザイン変更・記事の下書きまで行える時代に突入。
  • ChatGPT（会話ごとに接続）とClaude（アカウント単位で持続）の接続スタイルの違いだけ押さえておけば、あとは好みで選べる。
  • 「いいね」とチャンネル登録のお願い〆。それではまた次回──。
