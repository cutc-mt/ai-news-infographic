オントロジーとは「意味の設計図」——現場の暗黙知をAIに受け継がせる方法

AIエージェント活用はまだ1割未満／点と線で世界を記述する／専門職“FDE”の正体／予期せぬ問題に強いAIの作り方／社内導入は“足元の地図”から

📅 2026年11月14日 / PIVOT TECH ／ MC: 野島卓也（PIVOT） ／ ゲスト: 萩野達弘（カンリ CIO・元ビズリーチAI研究開発）

①なぜ今、オントロジーなのか

  • 2026年5〜6月以降、オントロジーという言葉がニュースに急増。AI関連イベントやAI業務に携わる人との会話にも頻出するように。
  • マイクロソフトがオントロジーベースの「ファブリックIQ」の提供を開始したことがトレンドの起点のひとつ。
  • パランティアのAIプラットフォーム「AIP」におけるファウンデーションオントロジーは同社最大の競争力と言われる。
AIエージェントが企業で正確・安全に動くための「ガードレール」——それがオントロジー

②AI活用は4〜6割、エージェントは1割未満

  • 「AIを使い始めた」企業は4割・5割・6割と増え続ける一方、AIエージェントを使いこなせている会社は昨年末3%から増えても1割に満たない。
  • 「AIエージェント元年」と言われながら、多くはPOC（概念実証）で止まったままというのが現状。
  • 理由はシンプル。AIは間違いを起こすが、企業では個人情報漏洩や意図しない発注が信用問題に直結し、個人のように「後でキャンセルすればいい」では済まない。
個人なら「まあいいか」で済む失敗も、企業では命取り——ハードルが段違い

③オントロジー＝「意味の設計図」

  • オントロジーはもともと哲学用語（存在論）だが、AI文脈では人間が使う言葉の意味をコンピュータに伝える技術として長年研究されてきた。
  • 定義するなら「AIと人間が同じ現実世界の情報を“意味”として共有するための設計図」。
  • 萩野氏の出身領域である求人×職務経歴書のマッチングでも、キーワードの裏の意図を読めないと合わない——という同じ問題が20年前から存在した。
「オントロジー＝意味付け」。まずはこの一言から始まる

④基本構造は「トリプレット」（SVO）

  • 概念（オブジェクト）を点として定義し、概念同士を線で結ぶ——例えば「萩野達弘」は「オープンクロー解説回」に出演する、で「出演者」という新しい概念が生まれる。
  • これは英語の主語・述語・目的語（SVO）の構造と同じ。3つの関係をトリプレットと呼ぶ。
  • 番組には放映日・視聴者数といった属性も持たせられる。点と線と属性で現実世界をそのままデータ構造に映す——だから「デジタルツイン」とも呼ばれる。
「誰が・何を・どうする」を点と線にするだけで、世界が記述できる

⑤「パイソン」問題——言葉は文脈で変わる

  • 爬虫類の話をしている時に「パイソン知ってます？」と言えば蛇。AIの話ならプログラミング言語。
  • つまり「その世界の中で、この言葉はどういう意味か」を記述しないとAIは誤解する。
  • 現実世界の定義は本来曖昧で、曖昧な定義のままではAIも曖昧に動き、意図に合わない行動をとってしまう。曖昧さを減らす役割もオントロジーの仕事。
人間は文脈で自動的に切り替える——その切り替えをデータ化するのが一番むずかしい

⑥「グラフ＝点と線」という再発見

  • 野島氏「グラフ＝XY軸のグラフのイメージ」——しかし算数の「この点を通りますか？」も、点と点を線で結んだもの。グラフの正体は点と線。
  • オントロジー（意味の設計図）に基づいて点と線を結んでできたものがナレッジグラフ（知識グラフ）。
  • 米田さん・富山さん・萩野氏のPIVOT出演回は別番組でも「人物→出演する→番組→扱う→テーマ」という同じ構造で記述できる。
オントロジー自体はグラフではなく、グラフを作るための「設計図」

⑦Excelでも書ける。でも動かせない

  • 極論すればExcelでもオントロジーは表現できる。だが意味付けのデータだけでは、AIの行動までは保証できない。
  • 例：経費精算。社内規定や法律を読んで都度判断する人間と違い、AIにはプログラムで検証（バリデーション）される仕組みが必要。
  • データの意味付け＋行動の制御が揃って初めて企業業務に使える——だからこそ「どのプラットフォームを使うか」で各社は悩む。
意味の設計図だけでなく「動いていい・ダメ」の検証装置までセットで

⑧「AIの記憶」ではない。契約書だ

  • 「オントロジー＝AIの記憶」と書く記事もあるが、萩野氏は「記憶という言葉は間違い」と指摘。
  • 記憶は曖昧。一方で契約書は「書かれてることが正」として進む。オントロジーによるAI制御は後者。
  • たとえるならAIとの業務委託契約書。内部規定や法律に相当するルール——「いくら以上は部長決裁、さらに上は取締役会決議」——を概念ごとあらかじめプログラミングしておく。
曖昧な「思い出」ではなく、決済権限まで書いた「委託契約書」の世界

⑨専門職「FDE」とは何か

  • FDE（Forward Deployed Engineer／フォワードデプロイドエンジニア）。企業に入り込んで業務を観察・構造化・抽象化し、オントロジーの形に変換する専門職。
  • 「どこまで概念を分けるか」「どこを分けないか」の線引きは人間の仕事。この地図作りができる人材としてFDEが生まれている。
  • パランティアはオントロジーが競争力になると分かっていたから自社にFDEという職種を作った——業務の世界をAIに伝えるための地図を作ってきた。
AI時代の地図描き。ガバナンスを握る職種として今、注目が集まる

⑩ゲスト萩野氏のバックグラウンド

  • 萩野達弘氏はAI研究開発の畑出身で10年以上。ビズリーチでHRテックの研究開発に従事。
  • 求人と職務経歴書のマッチングで「死ぬほど凝って書いた文章」の裏にある意図をどう機械に伝えるかに苦闘。「毎日放送のアナウンサーでした」だけでは同期の2人も区別できない、と。
  • 現在は店舗インフラ「カンリ」のCIOとしてAIエージェント化を推進。かつてはD2Cブランドの立ち上げ（企画〜製造〜発送〜請求〜CS）も経験。
「経歴書の中身を読めない機械」の問題に10年向き合った人が解説者

⑪なぜ現場業務の自動化は進まないのか

  • D2Cの実体験：販売システムと倉庫システムは別システム・別担当。注文キャンセル1つにも関係者全員への連携が必要。
  • 「それキャンセル？ 返品？」という判断すら、システム間・担当者間の調整が要る。
  • 定型業務ならワークフローで組める。しかし在庫が突然半分になる・入荷が間に合わないといった予期せぬ事態は事前に組みようがない。
「戦争が起きたらこうしてください」——どこまでワークフローを書けばいいのか、という話になる

⑫臨機応変の正体＝“勘”の世界地図

  • 優秀な担当者はどんな状況でも過去の知識と経験から勘を働かせ、「このシステムを見る」「この取引先に連絡する」「お客様に事前連絡する」を瞬時に判断する。
  • この臨機応変性をプログラムで定義するのは土台無理——そこが人間の凄さだった。
  • しかし人間と同じ「世界地図」を頭に持てばAIにも見える：この状況ではどの情報にアクセスし、どんなリスクが起き、誰に連絡すべきかがルールとして見えてくる。
ベテランの勘は「言語化されていないオントロジーの引き出し」だった

⑬暗黙知を形式知に：キャンセルと返品の例

  • 注文取り消しのルール：「すでに出荷済みの注文は取り消せない」。ここで臨機応変な対応が必要になる。
  • オントロジーに「返品処理」という概念が定義済みなら、AIは“キャンセルではなく返品をすればいい”と判断できる。
  • 人間は言語化していなくても引き出しを持っていて、起きた時に自分で開けている。それを言語化すればAIでも同じことができる——日本のAI導入の壁とされた「現場の暗黙知」のデータ化が、本当の意味で可能になる。
職人の勘を「契約書の言葉」に翻訳する——それが暗黙知の継承

⑭実演：出演者キャンセル→代打探し

  • PIVOTの番組制作を題材に実演。出演者の1名が急遽出演不可に——グラフ上では「出演する」の線が切れるだけで、後続の対応が必要なことが分かる。
  • AIがグラフを辿り、過去に同テーマへ出演し出演許可と出演料（ダミーデータで22万円）の情報がある人物を代打候補として推論。
  • 人が承認すると、企画データ・概要欄・サムネ素材確認・台本・出演予約など関連システムへ一括連携。従来はSlackで一人ずつ確認していた作業が全て自動化。
「白石さんお願いします」の一言の背後にあった数十分の調整を、グラフが肩代わりする

⑮承認を入れるか、自律させるか

  • デモでは要所に人間の承認ステップを挟む設計。承認なしで「そこまでやっていいよ」にすれば、AIエージェントは自律的に最後まで動く。
  • 自律動作時も参照する情報が新演者に切り替わっているため、古い出演者への誤連絡は起きない。
  • イレギュラー発生時に「どのシステムに・何を・漏れなく」連携するかを定義しておくのは、従来のアプリ開発では至難の業。APIだけでやるのは現時点では無理、と萩野氏。
グラフを作ったのは誰か、AI任せにして責任は取れるか——監査の設計が鍵

⑯社内導入のコツ：足元の地図から

  • 第一歩は「身の回りの地図」を作ること。負担が大きい・時間がかかる・判断に時間が要る・人とシステムを巻き込む煩雑な業務を1つ選ぶ。
  • その業務を紐解くと見えてくる4点：①ルール②概念＝データ③そのデータが入っているシステム④操作に必要な権限。
  • 地道に定義してAIエージェントに1業務任せ、複数業務のオントロジーがつながり始めると大きな地図になる——地域地図を組み合わせて世界地図を作るように。
明日から「うちもやります」は無理。でも1業務の地図なら今日から描ける

⑰プラットフォーム争いとロックイン

  • 小組織なら手元ツールや全エージェントが参照するファイル1つでも済む。だが大企業ではそうはいかない。
  • 2026年、オントロジー中心のAIエージェント・プラットフォームの競争が激化。マイクロソフト・パランティア・Databricksらが企業ナレッジベースのインフラを取り合っている。
  • 1社へのロックインリスクはあるが、それ以上に世界地図の保有がAI活用の重要ピース——「掲載権」を握られると出られなくなる、と野島氏。
パランティアは高すぎる——代わりはどこか、と各社が模索する段階

⑱まとめ：意味の設計図がAI時代の常識に

  • オントロジーとは点と線で現実の意味を記述する「設計図」。AIエージェントが企業で安全に動くガードレールになる。
  • 業務を構造化してオントロジーに変える専門職がFDE。萩野氏は「今後どれくらいの複雑さにどれほどのオントロジーが要るか」の形式化に期待を示す。
  • 企業の明日からの一歩は足元の業務を1つ紐解いて地図を描くこと。地図がつながれば、現場の暗黙知もAIに受け継がれる。
