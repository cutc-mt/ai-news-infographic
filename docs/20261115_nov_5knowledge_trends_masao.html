②結論：メインモデルをOpus 5.5→Fable 5.2へ

  • 11月前半、まさお氏のメインモデルはClaude Opus 5.5からFable 5.2へ移行。
  • ただし日常タスクで長時間の難題を扱わないならOpusで十分足りる場面も多い。
  • ゴリゴリと深掘りしたい場合には「もうFableしか考えられない」レベル——外部指標Artificial Analysisでも頭一つ抜けた。
ズバ抜けたモデルが登場した2週間だったの

③Fable 5.2の実力：オーケストレーション

  • 複数セッション（Claude Codeプロジェクト等）を束ねるオーケストレーションのうまさが極まっている。
  • 自作ハーネスでもFableが中心で活躍し、公式事例でも大規模なコード修正の共有があった。
  • コスト低下・出力最大30%高速化・読みやすさ改善——「資料作成はとりあえずFableに任せろ」。
複数の関心ごとを守りながら働く注意力が違うの

④effort設定の使い分け

  • 設定はMedium／High／Max・XHigh。基本はHigh、より念入りな検証を求めるときはMax・XHigh。
  • MediumとHighの間にはトークン使用量の壁のようなものを体感——切り替えでコスト感覚が変わる。
  • 5.1と5.2で挙動が変わるという声も。モデルの「癖」の把握までが使いこなし。
「頑張って」はダイヤルで調整する時代なのだ

⑤タスク難易度でモデルを選ぶ

  • 難易度10のタスクならOpus 5.5で十分——仕組み化されたものはSonnetでも回る。
  • 難易度20〜30、注意力を要する大きな仕事、さらには100・1000級（MMORPGのシミュレーション級）はFableの出番。
  • 「オセロを組む授業課題」と「壮大なシミュレーション」のたとえで、難易度とモデルの対応を直感的に解説。
高いモデルほど大事、ではなく「仕事の規模で選ぶ」の

⑥「サブエージェント分割」はもう古い？

  • 昔のモデルは注意力が有限で関心ごとの分離（サブエージェント分割）が必須だった。
  • 今のモデルは分離せず複数の関心ごとを同時に保持できる——「あえてサブエージェントを切らない」流れ。
  • 帰結：5.1時代と5.2時代で書くべきプロンプトやCLAUDE.mdが変わる。ベストプラクティスの更新が重要。
モデルが進化すれば、指示の設計も組み直すべきなの

⑦Gemini 4の位置づけ：CarbonとHydrogen

  • イメージはCarbon＝Opus/Fable級、Hydrogen＝Sonnet級。Argon→Carbon→Hydrogenのラッシュで一気に戦力化。
  • Carbonはサイバー防御や長文ベンチマークに強い一方、最近のトレンドであるコンピューターユースではOpus 5.5に見劣りする場面も。
  • 現在は限定で安いが、12月1日ごろから正規価格へ値上げ——使いやすい今がチャンス。
Geminiが再び最前線に返ってきたの

⑧Hydrogenが「やばい」理由

  • 無料枠がありコストも安いのに、Gemini APIではTPS 200〜300と高速。
  • 入力は動画・音声・画像OK、コンテキスト100万——検証手段として「あるだけいい」。
  • 実例：鼻をすすった音の場所や、ページをめくる映像の文字まで鋭く拾ってくる——その精度に「めちゃくちゃすげえ」。
無料枠でここまで拾えるのは反則級なのだ

⑨音声・動画インプットの活用筋

  • この特性を活かしたエージェンティックな動画編集アプリ／ハーネス構築が今後の面白いところ。
  • 動画生成の検証にも活用可能——検証ツールはあるだけ良いのがまさお流。
  • 競合はSonnet 5.5やGPT-6.1級——実は両者もコスパ・能力とも高評価で、選択肢が厚くなった。
コスト的にできることはHydrogenで、が鉄則なの

⑩日本語はどう扱う？

  • Geminiの文章は長めでくどい面はあるものの、日本語の綺麗さには定評。
  • お勧めフロー：Fableで一度作らせ→日本語を整えたい部分だけデリゲートGeminiでdiffを取る。
  • 「Gemini単体に文章を作らせるのは好みではない」と正直に——AIスロップ対策の分工として活用。
作るのはFable、磨くのはGemini——夢の分工なの

⑪Claude Duetとプロジェクト機能

  • Claude Codeのプロジェクト機能は「部長」的な構図——フロント開発・リサーチ・検証など3本のスレッドを束ねる。
  • メインセッションで話していると裏側で3スレッドが進行し、進捗を教えてくれる——使用感も良好。
  • Claude Duetは「ManusのClaude版」的ポジションで大注目。DuetからCodeを操作でき、エージェントがエージェントを操作する構図に。
窓口1つで部下AI軍団を動かす時代が来たの

⑫AIがセッションを束ねる時代

  • 進化の系譜：人がセッションを並べる→人が束ねる→AIが束ねる。
  • 各ハーネス企業も「窓口1つ」の構成に力を入れている。
  • Duet・プロジェクト機能の登場で、この流れが一気に現実化——ハーネスレイヤーの主戦場に。
操縦席はまだ人間、でも束ねるのはAIなのだ

⑬GeminiのDecision API

  • 文章を書かず「答えの確率だけ」を返すDecision APIがGeminiに登場。
  • 特徴は音声・動画・画像入力に対応——リアルタイム系の予想・判定に使いやすい。
  • コストも手頃で「手札として持っておきたい」一着。OpenAI系の判断系APIとの併用も視野に。
確率だけ返す軽量API、地味に万能なのだ

⑭GPT Image 2.6とOpenAIクレジット

  • 11月4日にGPT Image 2.6が登場——着実に「0.1」を刻む進化。
  • 新機能はGIF作成とSVG出力。日常使いで嬉しいアップデートと、画像自体の変化は体感少なめという正直な評価。
  • 画像生成はCodexで使うことが多い昨今。加えてOpenAIがクレジットを配ってくれるようになったのも追い風。
リアルタイム・画像・モデル、どこから使ってもいい時代なの

⑮「任せる」と「明け渡す」は違う

  • 任せる＝結果を自分が引き受けること。明け渡す＝確かめる気がなくなるまで任せること。
  • AIが賢くなるほど「全部オッケー」連打になりがち——赤ペンでポンポン承認するだけも明け渡している可能性。
  • 対策はAIにクイズを出してもらうなど、認識のずれを限りなく減らす仕組みづくり。
権限は渡しても、理解は手放さないのが原則なの
