攻撃者はもうあなたのコーディングエージェント経由で入ってくる——直近数週間の実攻撃と、今すぐできる対策、設定を丸ごと監査する無料スキル (Cole Medin)

Cole Medin の動画「Hackers Are Coming for Your AI Coding Agent (Lock It Down Now)」を1枚にまとめたインフォグラフィック。AIを使って脆弱性を探し・突く攻撃者の速度が上がるいま、標的は私たちのコーディングエージェントそのもの。設定ファイルがバックドアを落とす実例、パッケージ経由のキー窃取、会話履歴・許可リストに残る資格情報、盗んだAIキーを転売する LLMjacking まで、直近数週間の実攻撃を確認し、「エージェントの実行内容を確認する」「APIキーに上限を付ける」「秘密をエージェントから離す」という基本3つと、設定全体を監査する無料の agent-config-audit スキルを導入します。

攻撃は「機械速度」で起きているTHREAT・Google GTIG レポートの要点

脅威の地殻変動
  • Google 脅威インテリジェンス・グループ（GTIG）と Mandiant は 2026-11-16、「エージェント的脅威活動が重大な閾値を超えた」と報告
  • 攻撃者はプロンプト入力から自律的なマルチエージェント攻撃フレームワーク（ARTEX・CAIRN・CyberStrikeAI・PentAGI など）へ移行——多段侵入を機械速度で連結
  • LLM でパッチの差分解析を自動化し n-day 脆弱性を即武器化——人の手を介さず、インターネット向きのサーバーへスケールする悪用パイプライン
  • 諜報系グループは自律型コーディングアシスタントの設定を操作してバックドアを落とす新種のサプライチェーン攻撃も確認されている
⚠
「攻撃の仕組みは昔どおり（脆弱なシステム・盗まれた資格情報）でも、速度と規模が桁違いになった」——これが防御側の新しい課題なんだ。

実攻撃①：設定ファイルがバックドアを落とすATTACK 1・A Settings File That Downloads a Backdoor

1:48〜
  • 共有・移植されたエージェントの設定ファイルを開くだけで外部からコードを取ってくる実例——「便利な設定をコピペ」が攻撃入口になる
  • GTIG も「コーディングアシスタントの設定操作→ローカル実行時にバックドアをドロップ」という攻撃ベクトルを実際に観測
  • 自分の環境に持ち込む設定は中身を読んでから——「動くからよい」では済まない時代に

実攻撃②：パッケージがキーを盗むATTACK 2・A Package That Steals Your Keys

3:09〜
  • エージェントに「このパッケージを入れて」と言わせる・入れたくなる悪意あるパッケージが流通——インストールの裏でキーを窃取
  • タイポスクワッティングや人気ライブラリの偽物など、サプライチェーン経由の攻撃は AI による偽装の質上がりで見分けが難化
  • コーディングエージェントは依存関係の追加を自動で通しがち——ここを人が止める設計が重要

実攻撃③：会話履歴に残る資格情報ATTACK 3・Credentials in Your Conversation History

5:00〜
  • エージェントとの会話に貼り付けたパスワードやトークンが履歴に保存され続ける——履歴がそのまま「秘密の倉庫」になる
  • 設定攻撃やキー窃取と組み合わせると、履歴漁りだけで資格情報の一括収穫が可能になる
  • 対処は文化側にもある: 秘密は会話に貼らない、どうしても必要なら環境変数・シークレット管理ツールで間接参照させる
⚠
「ちょっとこれで動かして」と貼り付けた API キー、何ヶ月も前のセッションに残っていない? エージェント利用歴が長い人ほど見直しが効く項目だよ。

実攻撃④：許可リストに保存されたパスワードATTACK 4・Passwords Saved to Your Allow List

5:35〜
  • 「毎回聞かれないように」と許可リスト（allow list）に強い権限やパスワードを保存してしまう運用のリスクを解剖
  • once で許可した強いコマンドが、プロンプトインジェクション等で乗っ取られたエージェントに再利用されうる
  • 利便性のための allow list が、攻撃者にとっての「事前承認済みパス」にならないか一行ずつ点検する習慣を

実攻撃⑤：盗まれたAIキーの転売（LLMjacking）ATTACK 5・Stolen AI Keys

7:01〜
  • 盗んだ LLM の資格情報とクラウドリソースを地下のプロキシサービス（LLM ミキサー等）で転売する金銭動機の攻撃が定着
  • 被害側は自分が払った分で他人の高性能モデル利用が回される——気づいた時には請求額が跳ねている
  • GTIG は LLMjacking を継続的な収益化の主要パターンとして挙げる——キー管理は「コーディングの衛生」ではなく「金銭リスク管理」

なぜ「いま」ロックダウンなのかWHY NOW・防御側が追いつく猶予

締切は今日
  • 攻撃側は AI で偽装・偵察・悪用を自動化——防御側の手作業では速度が合わない
  • コーディングエージェントはファイル読み書き・シェル実行・ネット通信という強権限を普通に持つ——侵入口として魅力的
  • 直近数週間の実例が示す通り、「自分は大丈夫」の根拠が消える速度が上がっている
  • Cole の結論: 完璧なセキュリティより、今日から効く基本——次の3カードがその中身
視点
攻めは「機械速度」、守りは「人間の確認」。この非対称を埋めるのが、実行内容の可視化とキーの上限設定と秘密の分離なんだ。

基本①：エージェントが実行するものを確認BASIC 1・Check What Your Agent Runs（8:12〜）

まず見る
  • エージェントが走らせたコマンド・触ったファイル・外部通信を毎回確認する——自動承認の網羅拡大をやめる
  • 特に 設定ファイルの読み込み・リモート取得・権限変更を伴う操作は、速さより正確性優先で人間が目を通す
  • 共有された設定・ルール・スキルを導入するときは内容を読む——実攻撃①の対策はまさにここ

基本②：すべてのAPIキーに上限を付けるBASIC 2・Put a Limit on Every API Key（9:54〜）

被害の天井
  • 開発用のキーにも利用上限（spending limit / quota）を必ず設定——漏れたときの被害に天井を付ける
  • LLMjacking は「盗んで使い倒す」攻撃——上限なしキーは無限の請求リスクと同義
  • プロジェクトごとにキーを分け、使わなくなったら即失効——1キー全能の状態を避ける
💡
「キーが漏れても上限100ドルなら、被害は100ドル」。地味だけど、効果が保証された数少ない対策のひとつだよ。

基本③：秘密をエージェントから離すBASIC 3・Keep Secrets Away From Your Agent（12:28〜）

分離の原則
  • パスワード・トークンは会話にも設定ファイルにも置かず、シークレット管理・環境変数で間接参照させる
  • エージェントには「必要な時だけ・必要な権限だけ」——秘密への常時アクセスを与えない設計
  • 実攻撃③④への直接対策: 履歴と許可リストに秘密を貯めない運用に切り替える

agent-config-audit スキルとはTOOL・設定全体を丸ごと監査（10:55〜）

無料・公開中

  • secrets guard フック同梱: 秘密がエージェント経由で漏れないよう守るフック付き

  • 「何を確認すればいいか分からない」人向けに、監査のチェックリストをスキル化したもの

MCP時代の設定ハイジーンHYGIENE・便利さと危険のトレードオフ

日々の習慣
  • MCP サーバー・スキル・ルールファイルなど、エージェントの構成部品が増えるほど監査面積も増える
  • 「全部乗せ」から使うものだけ・読んだものだけへ——設定の最小主義がそのまま防御力
  • 定期的に allow list / MCP 連携 / キーの棚卸しをする日を作る（監査スキルに任せるのが楽）
  • 攻撃者が AI で速くなる以上、防御も自動化された確認で回すのが現実的
🧹
設定ファイルは「一度書いたら終わり」じゃなくて、生き物。追加するたびに「これ攻撃者に使われない?」と一言聞く習慣をつくろう。
