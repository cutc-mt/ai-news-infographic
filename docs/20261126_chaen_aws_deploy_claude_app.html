公開前に知っておきたいAWSの基本6:02 リージョン・リソース・課金の考え方

いきなり実演に入る前に、AWSの基本を押さえます。AWSは世界中に「リージョン」というデータセンター拠点があり、そこに「リソース」（サーバーやストレージなど）を作って使う従量課金の仕組み。使った分だけ料金が発生するので、何を作って・いつ削除するかを意識するのが安全に使うコツです。動画ではこの基本を「公開の前」に理解しておくべきこととして丁寧に解説します。

DEMO 03

［作る］今日のおすすめAIツールページ乱数で変わるシンプルなWebアプリ

次に送るプロンプトは「ボタンを押すと今日のおすすめAIツールがランダムに出るWebページを作って。個人情報の入力や外部APIは使わず、まず手元で動かせるようにして。」。ポイントは2つ。「個人情報の入力や外部APIを使わない」で安全面のリスクを先に外していること、「まず手元で動かせるように」で公開前にローカルで動作確認する段階を挟んでいることです。Claude Codeがページを生成し、手元で動くことを確認します。

SAFETY

［確認］公開前にリソースと費用を確認「聞いてから進める」がクセになる

いきなり公開せず、一度 Claude Code に立ち止まってもらうのがこのプロンプト。「このデモをAWSで公開する前に、作成するリソースと費用が発生しうる条件を説明して。確認したあとに公開したい。」。すると、どんなリソースを作るのか・どんな条件で費用が発生しうるのかが説明され、内容を確認してから公開に進めます。クラウドが怖い人に特に刺さるステップで、AI任せにしつつも財布の紐は自分で握る形です。

ここ大事
「作る前に説明させて、納得してから進める」——これをプロンプト1行で実現できるのがエージェント時代の安全運転なんだ。従量課金のクラウドでは特に価値がある習慣だよ。

DEMO 04

［公開］AWSに載せてURLを取得説明を確認したら公開へ

内容に問題なければ送るのは「説明を確認しました。この内容でAWSに公開して、公開したURLを教えて。」。これだけでClaude CodeがAWS側の作業を進め、アプリが公開され、アクセス用のURLが返ってきます。スマホでも開けるそのURLを人に渡せば、作ったアプリを誰でも見られる状態の完成です。「作ったアプリ、どうやって公開する？」という冒頭の問いへの答えがここで提示されます。

CLEANUP

［一覧］［片付け］使ったものを削除9:27 実演を通しで見る：最後の工程

公開まで終わって満足して終わり…ではないのがこの動画の良い所。まず「このデモのために作ったものだけ一覧にして」でリソースを洗い出し、続く「一覧のものを削除して、ほかに残っているリソースがないか確認して。」で実際に削除します。従量課金のクラウドでは「消し忘れ」がそのまま課金につながるので、この「一覧→削除→残っていないか確認」の3拍子がそのまま安全な使い方のお手本になります。

  • 📋 一覧：デモのために作ったリソースだけを抽出
  • 🗑️ 削除：一覧のものを削除
  • 🔍 確認：ほかに残っているリソースがないか最終チェック
