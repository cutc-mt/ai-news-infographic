TELEMETRY 01

「opt-in」の公約は35日間だけ存在したホームページ上の約束の行方

「同意してから送る」というopt-inの明記は、5月14日の追加から6月18日の削除まで、ちょうど35日間だけホームページに存在していました。テレメトリ自体は3月6日から一度もデフォルトOFFになっていないため、「opt-in公約」と「デフォルトONの実装」が並走していた期間があったことになります。動画はこのズレを「悪意」と断定せず、事実として提示します。

TELEMETRY 02

無塩SHA-256ハッシュの問題「匿名」ではなく「仮名」だった

11月24日のパッチまで、T3 CodeのアナリティクスコードはCodexとClaudeのサインインファイルを読み取り、CodexワークスペースID・OpenAIユーザーID・ClaudeアカウントUUIDを無塩（ソルトなし）のSHA-256でハッシュ化していました。ソルトなしハッシュは推測や総当たりで元に戻せる可能性があり、「匿名」ではなく「仮名識別」。さらにPR 21506が、これらのハッシュ化IDを同一インストールに紐付けていました。

サインインファイルを読む→ 無塩SHA-256でIDをハッシュ化→ 同一インストールに紐付け

AUDIT 01

カナリアテスト：個人情報は送られていなかった偽データを仕込んで見張る監視手法

投稿者の監査は「カナリアテスト」方式。偽のメールアドレス・ユーザー名・トークンを仕込んだ環境でT3 Codeを動かし、外部通信にそれらが現れるかを監視しました。結果、偽メール・偽ユーザー名・トークンの送信はゼロ。プロンプト本文やファイル内容も送信されていませんでした。「盗んでいる」という言葉の重さに対して、監査で確認できた事実はここで一旦区切られます。

  • 偽メール・ユーザー名・トークン：送信されず
  • プロンプト本文・ファイル内容：送信されず
  • ただし「何も送らない」ではない（次のカードへ）

FIX 01

安定版0.1.12に収まった修正PR 42119の会話履歴パージ

動画が評価するのが、安定版0.1.12に shipped したPR 42119。削除済みの会話履歴をパージ（完全消去）し、tombstone（削除痕跡）と一部メタデータのみを残す設計です。ソーススレッドの履歴は、生きたforkがそれを表示し続ける限り保持される仕様も説明されます。「削除したのに残っている」問題への正面からの修正でした。

  • PR 42119：削除済み会話履歴を完全パージ
  • tombstone＋一部メタデータのみ保持
  • 生きたforkが表示する限りソース履歴は保持

FIX 02

モバイルのトレーススイッチは別経由のOTAスマホに届いたPR 42415

Send接続のトレーススイッチ（PR 42415）はデスクトップと同じソースツリーに存在しながら、スマホには別個のover-the-air（無線配信）アップデートとして届きました。デスクトップの修正を確認しても「モバイルは別」——こうした配信経路の分離があるため、動画は「ソースを読んだだけでは実配信が見えない」注意点としてこの話を扱います。プライバシー検証は配信経路ごとに必要、という教訓です。

PANDA 01

PandaCode：デフォルトでテレメトリゼロ対抗馬の設計思想

投稿者が開発に関わるPandaCodeは、デフォルトでテレメトリがゼロ。さらに、サポートされているopt-outフラグを、新しく起動するハーネス（CLIセッション）へ自動的に適用します。「自分で切る」ではなく「最初から切れていて、切れないものにも配慮する」スタンスがT3 Codeとの最大の設計差として示されます。

ナビ
スタート地点が違うんだ。T3 Codeは「ONが前提で議論する」、PandaCodeは「OFFが前提で例外を管理する」。テレメトリの議論って、どちらをゼロ地点に置くかで難易度が激変するんだよね。

CONNECT 01

PandaCode Connect：承認制の端末間連携最大10台・E2E暗号化

PandaCode Connectは明示的にopt-inするまでオフ。有効化すると最大10台のマシンを接続でき、X25519鍵交換＋HKDF-SHA256＋XChaCha20-Poly1305のエンドツーエンド暗号化で通信を保護します。新しいデバイスはすべて「保留」状態になり、ローカルであなたが承認するまで接続できません。端末間同期のプライバシー設計として動画が誇る部分です。

opt-inまでオフ→ 最大10台をE2E暗号化→ 新デバイスはローカル承認必須

CONNECT 02

スレッド削除は「本当の」SQL DELETESQLiteでの完全削除

PandaCodeのスレッド（会話）削除は、SQLite上で実際のSQL DELETEを実行します。フラグを立てて見えなくする論理削除ではなく、行そのものを消す物理削除。「削除した」という操作に、利用者が期待する通りの意味を持たせる設計です。T3 Code側の「削除済みでも履歴が残る」問題（PR 42119で修正済み）との対比として紹介されます。

ナビ
「削除」ボタンの裏で何が起きているか、普段は誰も気にしないけど、テレメトリ騒動を経た今は違うよね。SQL DELETEで消すのか、フラグで隠すのか。その一言の差が信頼の差になるんだ。

BENCH 02

勝てなかった項目：初分のCPUCLIバージョンチェックのコスト

すべてで優位というわけではありません。起動1分の合計CPU時間はPandaCodeが10.3秒に対しT3 Codeは7.4秒と、PandaCodeの方が重かった。理由は起動時のCLIバージョンチェックで、PandaCode自身のプロセスだけを見れば3.2秒対7.0秒と軽いものの、チェック対象のCLI起動がコストを上乗せしています。動画は不利な数字も隠さず載せる構成です。

NOTE 01

配信まわりの注意点署名・SmartScreen・HTTP

公平性のため、PandaCode側の留意点も明記されます。macOSビルドは署名・公証済みですが、WindowsインストーラはSmartScreenの警告が出ることがある。PandaCodeはあなたがインストールしたCLIに依存し、起動時にそのバージョンを確認します。さらにバージョン0.3.146のオプション機能「ブラウザアクセス」は、ローカルマシン上でプレーンなHTTPを使うとのこと。利便性と引き換えの部分は利用者各自の判断です。

  • macOS：署名・公証済み
  • Windows：SmartScreen警告が出る場合あり
  • 0.3.146のブラウザアクセスはローカルHTTP
