KEY IDEA

「inferred」と「seen」の違いコードを読むだけの限界という問題提起

動画の中心的な問題意識がここ。ソースコードだけを読んで「このアプリはこう動くはず」と結論づけた場合、その主張はあくまで推測（inferred）としてマークされたままになります。本当にそのAPIコールが飛ぶのか、そのデータが含まれるのかは、実際にアプリを動かして見る（seen）まで確定できません。読んだコードと実行時の挙動はしばしば食い違う——テレメトリがランタイムで組み立てられるようなケースは、まさにその典型です。

よもぎちゃん
「『コードを眺めて分かった気になる』のと、『実際に動かして確認する』のとじゃ、確かさが全然違うの。このギャップを埋めるのがこの動画のテーマだよ。」
NEW TOOL

Vercel Labsの「agent-browser」ネイティブRust製CLIでブラウザを駆動

「inferredをseenに変える」ための新しい道具として紹介されるのが、Vercel Labsが公開するagent-browserです。Rustで書かれたネイティブCLIで、Webページを実際に操作・観察できます。「LLMに読み込ませるためのページ駆動」が主用途で、セットアップ手順ではdshと並んでインストールして両立させる構成になります。

  • 開発元：Vercel Labs
  • 実装：Rust製のネイティブCLI
  • 機能：Webページの駆動と観察
TECH

Electronアプリへの接続リモートデバッグポート経由という手法

agent-browserの注目ポイントは、Electron製デスクトップアプリにも接続できること。Electronは内部にChromiumを持つため、リモートデバッグポートを開けばagent-browserから内部のレンダリングプロセスへアクセスできます。つまり「見た目はローカルアプリ、中身はブラウザ」というElectronの性質を逆手に取り、Webページと同じ要領で内部の通信やDOMを観察できるわけです。

Electronアプリ→リモートデバッグポート→agent-browser接続→内部を観察

DEMO 1

実演：Electronのノートアプリ検証対象として選ばれたサンプル

環境が整ったところで、実例としてElectron製のノートアプリを取り上げます。一見シンプルなローカルアプリですが、内部では同期処理やテレメトリ送信といった通信が発生しており、「コードを読むだけでは分からない実挙動」の観察対象として恰好の題材です。agent-browserをデバッグポートに接続し、実際のリクエストを覗いていきます。

ノートアプリ起動→agent-browser接続→同期リクエスト観察
DEMO 2

検証1：削除されたフィールドは同期外かstripされたデータの実挙動確認

デモ前半の検証テーマは「取り除いた（stripped）フィールドが、本当に同期リクエストから除外されているか」。コード上でフィールドを削除・除去したつもりでも、実行時にそれが守られているかは別問題です。agent-browserで実際のsyncリクエストを観察することで、「除外されているはず」という推測を「除外されているのを見た」という事実に格上げできます。

よもぎちゃん
「『はず』が『確認した』に変わる瞬間がこのデモの山場だよ。プライバシー系の処理では特に大事な確認なの。」
DEMO 3

検証2：ランタイム生成のテレメトリ静的読み取りでは見えない送信を捕捉

もうひとつの検証は、実行時に組み立てられるテレメトリ呼び出しの捕捉。ソースコード上に固定の文字列として現れないこうした呼び出しは、コードをいくら丁寧に読んでも見逃す可能性があります。agent-browserで実際の通信を観察することで、ランタイムで生成・送信されるテレメトリを直接捉えられます。「inferred vs seen」の問題意識が最も具体的に効くシーンです。

  • 静的解析：コードに見える呼び出しのみ
  • 実行観察：ランタイム生成の呼び出しも捕捉
